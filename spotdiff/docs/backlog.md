# spotdiff 拡張候補（backlog）

公開済みの spotdiff に次に足せる要素の候補。上ほど優先（先頭が次の候補）。spec ではない。採用するときは `game-extend` で 1 件を選んで詰め、`game-spec` で spec に書く。

- 規模: S = 小さな追加（既存の仕組みの範囲） / M = 新しい種類・仕組みを 1 つ / L = 複数の仕組みにまたがる（`game-extend` で 1 PR 分に切り出してから採用）
- 「自動プレイ」の数字の条件: 日付 20300000〜20300299 の 300 セット（セット番号 1、各 5 ステージ）の中央値・割合。ゲームのロジックだけを動かした数字で、人が見て見つけやすいかは分からない。差分の種類の割合は、形の差分を足したあとに、シード 1〜300 の各 5 ステージで測り直した（色 21%・移動 17%・大きさ 20%・消失 21%・形 21%）
- どの候補も、差分を選ぶルール（いまは 5 種類を等確率）を変える。採用するときは、ステージごとにどの種類を出すか（早いステージは易しい種類だけ、など）も `game-extend` で決める

### 右にだけ増える図形（`added-shape`）

- 狙い: 消失は「左にあって右にない」の一方向だけなので、「右に足りないものを探す」習慣だけで済んでしまう。根拠: spec 「差分の内容」の「消失: 右の絵からその図形を描かない」。消失は全差分の約 21%（自動プレイ。形の差分を足したあと）
- 何を足すか: 右の絵にだけ、左に無い図形が 1 つ増えている差分
- コアループへの効き方: 広げる — 左右どちらにあるかを意識して見比べる必要が出る
- 種別: gameplay
- 規模: S
- 出どころ: spec 分析 / ユーザー
- メモ: 増やす図形は他の図形と判定円が重ならない位置に置く（差分どうしの円が重ならない規則を守る）。左右の図形をインデックスで対応させる作りなので、左の図形数より右が増える扱いを `game-extend` で決める

### 横持ちスマホで大きく表示（`phone-landscape`）

- 狙い: スマホを横にすると、パネルが小さくなって見づらい。根拠: QA で 844x390（スマホの横向き）に切り替えた画面で、パネルが約 203 CSS px、最小の図形が直径で約 20 CSS px、最小の判定円が直径で約 35 CSS px（44 CSS px 未満）になった。縦持ちには拡大レイアウトがある（spec 「画面・Scene構成」の向きの判定は「縦長か、それ以外」の 2 通り）が、横長のスマホは PC の横長（1024x768）と同じ扱い
- 何を足すか: 横長で低い画面（スマホの横向き）用に、キャンバスの縦横比を画面に合わせ、2 枚のパネルを画面の高さいっぱいに拡大して描く
- コアループへの効き方: 広げる — 横持ちのスマホでも、小さな差分を見つけて押せる
- 種別: presentation-only
- 規模: M
- 出どころ: spec 分析
- メモ: 縦持ちと同じく、論理座標・ルール・数値は変えず、表示倍率だけを変える。ただし表示が大きくなる分、体感の難易度は変わるので、足したあとに `game-balance` で見る。PC の横長ウィンドウ（4:3 に近い）と横長スマホ（約 2.2:1）を、どの比率で切り替えるかを `game-extend` で決める

### 図形の種類を増やす（`more-shapes`）

- 狙い: 全ステージの絵が円・四角・三角の 3 種類だけで、後半の 36 個も似た見た目になる。根拠: 自動プレイで図形の種類は円 34%・四角 33%・三角 34%。ユーザーの声（形状のバリエーションを増やしたい）
- 何を足すか: 星・リング・十字・六角形など、図形の種類を増やす。ステージが進むと新しい種類が混ざる
- コアループへの効き方: 広げる — 絵の見た目が多彩になり、同じ形が並ぶ単調さが減る。後半に新しい形が出る発見がある
- 種別: gameplay
- 規模: M
- 出どころ: ユーザー / 自動プレイ
- メモ: 同じ日・同じセット番号で同じ絵になる、という保証は保つが、追加の前後では同じ日付でも別の絵になる。図形ごとに外接の正方形（一辺 `2*size`）に収める規則を守る。模様・縁取りのある図形（縞・水玉）を足す案もあるが、塗り方の差分まで増える（規模 M〜L）ので、先に図形の種類だけを増やす

### 遊び方の説明（`how-to-play`）

- 狙い: 初めて遊ぶ人に伝わるのは、ステージ1の最初の 1 行（"Tap where the pictures differ"）だけで、誤クリックで時間が減ること、5 ステージで 1 セットであること、画面を離れると止まることを知る手段が README だけ。根拠: spec 「演出・UI」（初回ヒントはステージ1・セット1・最初の当たりまで）と、Title の説明が 1 行（"Find the differences"）であること。ユーザーの声（遊び方の説明を足したい）
- 何を足すか: 違う所をタップする・外すと 5 秒減る・5 ステージで 1 セット・画面を離れると一時停止、を短く伝える説明
- コアループへの効き方: 広げる — 初めての人が、ルールを知らないまま遊び始めて損をしない
- 種別: presentation-only
- 規模: S
- 出どころ: ユーザー / spec 分析
- メモ: 毎回出ると邪魔なので、Title に「遊び方」のボタンを置く（押すと開く）か、Title の説明を数行に増やす。「初回だけ表示」は、遊んだかどうかを覚える永続化が要る（いまの spec は永続化なし）ので、`records` と同時に決めるなら別だが、単独では採らない

### ヒント（`hint`）

- 狙い: 残り 1 個が見つからないまま時間切れになると、セット全体が最初のステージからのやり直しになり、助けがない。根拠: spec 「勝利・失敗・スコア」（時間切れは常にセットの先頭から再開）と非MVP範囲（ヒント機能）。自動プレイで、差分 1 個あたりの持ち時間はステージ 5 で 5.7 秒（20.0 / 13.8 / 10.0 / 7.5 / 5.7 秒）
- 何を足すか: ボタンを押すと、未発見の差分の 1 つを、判定円より広い範囲の円で一定時間だけ示す
- コアループへの効き方: 広げる — 「探す」だけだった遊びに、助けを借りる代わりに何かを払う判断が加わる
- 種別: gameplay
- 規模: M
- 出どころ: spec 分析 / ユーザー
- メモ: 使うと残り時間が減る、またはセットごとに回数が限られる、といった代償は `game-extend` で決める（代償がないと、押せば必ず見つかるので探す遊びが成り立たない）。ステージ単位のやり直し（コンティニュー）は、1 ステージずつ再挑戦して答えを覚えてしまうため、採らない。spec の非MVP範囲から「ヒント機能」を外すことになる

### 拡大表示（`zoom-view`）

- 狙い: スマホでは後半の小さな差分が見づらい。根拠: 縦持ちの 390x844 の画面でパネルが約 355 CSS px、最小の図形（半径 20）は直径で約 36 CSS px。後半は色相のずれ 30°・移動 18px・大きさの変化 22% まで小さくなる（spec のパラメータ表）
- 何を足すか: 2 枚のパネルを同じ位置で拡大して見られる（ピンチ操作またはボタン）。拡大中も、当たり判定は論理座標のまま
- コアループへの効き方: 広げる — 答えは教えずに、小さな違いを見分ける手段を渡す
- 種別: gameplay
- 規模: M
- 出どころ: spec 分析 / 自動プレイ
- メモ: 拡大中のタップをパネル内座標へ変換する規則（拡大率・移動量）と、拡大中の誤クリック・赤丸・× の表示位置を決める。拡大すると差分が見つけやすくなるので、後半の難しさの感触は `game-balance` で見直す

### 色覚への配慮（`color-safe`）

- 狙い: 色の差分は色相のずれだけで、後半は 30° まで小さくなる。赤と緑のように見分けにくい色の組み合わせでは、見えない違いになりうる。根拠: spec 「差分の内容」（色: 色相を `hueShift[s]` 度ずらす）とパラメータ表（120 / 80 / 55 / 40 / 30°）、図形の色の範囲（彩度 0.55〜0.9・明度 0.4〜0.6）。実際に見分けにくい人のデータはまだない
- 何を足すか: 色の差分で、見分けにくい色の組み合わせを避けるか、明るさも同時に変えて、色だけに頼らずに違いが分かるようにする
- コアループへの効き方: 広げる — 色覚の違いで、差分が「見えない」ことがなくなる
- 種別: gameplay
- 規模: M
- 出どころ: spec 分析
- メモ: 採用前に、色覚シミュレーションで見え方を確認し、見えにくくなる色差分の割合を測る。`tone-shift`（明るさだけの差分）と関係が深いので、一緒に考える

### 回転の差分（`rotate`）

- 狙い: 図形に角度の概念がなく、三角も頂点が上向きだけ。向きが変わる違いがない。根拠: spec 「絵の描画」（図形は頂点が上の二等辺三角形、四角は軸に平行）
- 何を足すか: 図形に角度を持たせ、右の絵で一定の角度だけ回転している差分
- コアループへの効き方: 広げる — 「同じ位置・同じ形・同じ色に見えて向きが違う」という見分けが加わる
- 種別: gameplay
- 規模: M
- 出どころ: ユーザー / spec 分析
- メモ: 円は回しても変わらないので、対象は四角・三角（`more-shapes` の図形があればそれも）。回した後も外接の正方形に収まる範囲（回転で四隅が飛び出さない大きさの扱い）を決める

### 明るさだけの差分（`tone-shift`）

- 狙い: 色の差分は色相の変化だけで、明るさ・彩度だけが変わる違いがない。根拠: spec 「差分の内容」（色: 色相を `hueShift[s]` 度ずらす）。後半は 30° まで小さくなる
- 何を足すか: 色相は同じで、明るさ（または彩度）だけが変わる差分
- コアループへの効き方: 広げる — 色相の違いより気づきにくい、静かな差分が加わる
- 種別: gameplay
- 規模: S
- 出どころ: spec 分析
- メモ: 気づきにくい差分なので、ステージ後半に限る・変化量の初期値は小さすぎないようにする。難しさに強く効くため、足したあとは `game-balance` で見る

### 背景の差分（`background-diff`）

- 狙い: 全差分が図形に結びついていて、背景の装飾の円は差分にならない。図形の外を見る必要がない。根拠: spec 非MVP範囲（背景の差分）と「背景」の規則（装飾は左右同一で、差分にしない）
- 何を足すか: 背景の装飾の円が、右の絵で消える・動く・大きさが変わる差分
- コアループへの効き方: 広げる — 探す範囲が図形の外の背景にも広がる
- 種別: gameplay
- 規模: M
- 出どころ: spec 分析
- メモ: 装飾の円はパネルの端で切れて描かれる（矩形でクリップする）ので、判定円の扱いと端のときの見え方を決める。spec の非MVP範囲から「背景の差分」を外すことになる
