# 明るさの差分

`docs/spec.md` の一部。7 種類目の差分「明るさ」と、色差分に足す明度のずれを、独立して書いたもの。`docs/spec.md` と合わせて 1 つの spec である。

## 概要

図形の色相・彩度はそのままで、**明度だけ**が変わる差分「明るさ」（`tone`）を、ステージ 3〜5 に足す。あわせて、既存の色差分は、色相のずれ（`hueShift`）に加えて明度も同時にずらす。色相のずれだけでは、後半（30° まで小さくなる）や色の見分けにくい人に「見えない違い」になりうるので、色相とは別の手がかり（明るさ）を足して見落としを減らす。コアループは広げる（見分けの軸が 1 つ増える）。操作の追加・変更はなく、ルール・持ち時間・図形数・差分数・スコアは変えない。

## 操作仕様

なし（操作は `docs/spec.md` の操作仕様のとおり）。

## 画面・Scene構成

- 画面・レイアウト・演出・UI の変更はない。図形は、これまでどおり `shape.hue`・`shape.sat`・`shape.light` で塗る（右の図形の明度が変わるだけ）。
- **出るステージ**: 明るさの差分はステージ `toneFromStage`（3）以降だけ。ステージ 1・2 の絵・差分の種類の抽選、`Title` のデモ（ステージ 1・2）には出ない。
- **プレイヤー向けの説明**: `Help` の図（違いの 6 種類）は変えない。明るさの差分は、プレイヤーには「色の違い」の一種として説明する（`README.md` は色に「色合いと明るさ」を含めて書く）。

## ルール

**明るさの差分**（絵と差分の生成の「差分の内容」に加わる。差分の種類の抽選は `docs/spec.md` の「差分の選択」）

- 右の図形の明度 `light'` を、元の明度 `light` から `toneDelta[s]` だけ、ランダムに ± どちらかへずらした値にする。符号は乱数で決める。ずらした値が `[toneLightMin, toneLightMax]`（0.2〜0.8）の外なら、逆向きにする（誤差 1e-9 は範囲内として扱う）。図形の明度は 0.4〜0.6、`toneDelta[s]` は最大 0.22 なので、どちらか一方の向きは必ず範囲内になる（`light` が 0.42 以上なら下げられ、0.58 以下なら上げられる。0.4〜0.6 のすべてがどちらかを満たす）。
- 色相・彩度・位置・大きさ・種類は変えない。右の絵だけに反映し（色差分と同じ）、左の絵は元のまま。
- 判定円は色差分と同じ: 中心は図形の中心、半径は `size + hitMargin`。
- 候補の種類の抽選: ステージ 1・2 は 6 種類（色・移動・サイズ・消失・増加・形）を各 1/6、ステージ 3〜5 は明るさを加えた 7 種類を各 1/7（`docs/spec.md`）。乱数はシード付きで決定的に使う（同じバージョンの中では、同じ `(日付, セット番号, ステージ)` は何度生成しても同じ絵）。

**色差分の明度**（`docs/spec.md` の「色」）

- 色差分は、色相を `hueShift[s]` 度、明度を `colorLightShift`（0.12）、それぞれランダムに ± どちらかへずらす（符号は独立）。彩度は変えない。ずらした後の明度は 0.28〜0.72 に収まるので、範囲の調整はしない。
- `hueShift[s]` の値・ステージごとの小ささは変えない。

## パラメータ表

| 名前 | 初期値 | 意味 |
|---|---|---|
| `toneFromStage` | 3 | 明るさの差分が出始めるステージ（ステージ 1・2 は 6 種類のまま） |
| `toneDelta` | ステージ 3 / 4 / 5 = 0.22 / 0.18 / 0.15 | 明るさ差分の明度のずれ。ステージが進むほど小さくする。下の参考値のとおり、後半の色相のずれより輝度の差が大きい初期値（遊んでからの調整は `game-balance`） |
| `toneLightMin` / `toneLightMax` | 0.2 / 0.8 | ずらした後の明度の範囲（外なら逆向き）。`toneDelta` は 0.3 以下でなければならない（図形の明度 0.4〜0.6 のどれでも、どちらかの向きが範囲に収まる条件。初期値がこれを満たすことをテストで確かめる） |
| `colorLightShift` | 0.12（`docs/spec.md` のパラメータ表） | 色差分の明度のずれ（全ステージ共通） |

**参考値（測定済み。仕様を決める値ではなく、実装・QA で食い違いを見つけるための目安）**

- 左右の図形の輝度コントラスト比（WCAG の相対輝度の比。彩度 0.55〜0.9・明度 0.4〜0.6 の図形 2 万個、乱数、シード 1）の中央値:

  | 差分 | ステージ 3 | ステージ 4 | ステージ 5 |
  |---|---|---|---|
  | 色相のみ（`hueShift` 55 / 40 / 30°。これまでの色差分） | 1.39 | 1.25 | 1.18 |
  | 色相＋明度 0.12（これからの色差分） | 1.57 | 1.51 | 1.46 |
  | 明るさのみ（`toneDelta` 0.22 / 0.18 / 0.15） | 2.02 | 1.77 | 1.60 |

  ステージ 1・2（色相 120° / 80°）の色差分は、明度を足しても中央値がほぼ変わらない（2.18→1.96、1.60→1.70）。
- 差分の種類の割合（現行のジェネレーター、300 セット、ステージ別）: 色 16.5〜19.3%・移動 12.4〜15.4%・サイズ 15.9〜17.2%・消失 15.4〜18.6%・増加 16.4〜18.3%・形 15.7〜18.1%。明るさは色差分と同じ判定円なので、ステージ 3〜5 で 7 種類に増えると、各種類が約 1/7（14%）に下がり、明るさは約 14〜16% と見込む（見込みであって測定値ではない。実装後の実測で確かめる）。

## テスト観点

- **明るさ差分の内容**（手計算）: 元の明度 0.5、`toneDelta` 0.22 → 右の図形の明度は 0.72 か 0.28。元 0.41・符号が下げる向き（0.41−0.22=0.19 < 0.2）→ 逆向きの 0.63。元 0.59・上げる向き（0.81 > 0.8）→ 逆向きの 0.37。元 0.42・下げる向き → 0.20（範囲内。誤差 1e-9 を許す）。元 0.4・`toneDelta` 0.15 で下げる向き → 0.25。この確認は、符号を引数に取る純粋関数（例: `toneLight(light, delta, sign)` → 右の明度。符号 −1 が下げる向き、+1 が上げる向き。範囲外なら逆向きにして返す）で、2 つの向きと逆向きへの切り替えをそれぞれ行う。生成器は、性質（範囲・変化量・多数のシードで両方の符号が出る）だけで確かめ、乱数を引く回数と順は縛らない。色差分の明度も同様に、色相の符号と明度の符号を引数に取る純粋関数で確かめ、多数のシードで 4 通りの組み合わせがすべて出ることを確かめる。
- 右の図形で、色相・彩度・位置・大きさ・種類が元と同じ。左の図形は元のまま。他の図形は左右とも同じ。判定円の中心が図形の中心、半径が `size + hitMargin`。判定円どうしが重ならない選び方は変わらない（差分数が `diffCounts[s]`）。
- **ずれた明度の範囲**: 多数のシードのステージ 3〜5 のすべての明るさ差分で、右の明度が `[toneLightMin, toneLightMax]` に収まり、元との差の絶対値が `toneDelta[s]` に等しい（誤差 1e-9）。
- **出るステージ**: ステージ 1・2 に明るさの差分は出ない（多数のシードで 0 件）。ステージ 3〜5 には出る。ステージの範囲外の入力のクランプは変わらない（0 はステージ 1、9 はステージ 5 として扱う）。
- **割合**（多数のシード。300 セット×5 ステージ以上）: ステージ 3〜5 の差分のうち、明るさが各ステージで 8〜25%。全ステージ・全差分のうち、7 種類すべてが出て、各種類が 8〜25%（`docs/spec.md` のテスト観点の「形の差分」の確認。明るさは約 1 割と見込み、実測で下限を割る種類があれば、範囲ではなく根拠を見直す）。
- **色差分の明度**（手計算）: 元の明度 0.5 → 0.62 か 0.38、色相も `hueShift[s]` だけ変わる。元 0.4 → 0.28 か 0.52。元 0.6 → 0.48 か 0.72。彩度・位置・大きさ・種類は変わらない。色相と明度の符号は独立（4 通りがすべて出る）。範囲外にならない（全ステージ・多数のシード）。
- **ステージ難度の単調性**: `toneDelta` がステージ 3→5 で 0.22 > 0.18 > 0.15。
- **回帰条件（明るさの差分の追加で変えないもの）**: 操作と入力のルール（`Game` のパネルの入力は [zoom.md](zoom.md) の規則（タップは `pointerup` で判定）・パネル外は無反応・判定円の境界は当たり）、`hueShift`・移動・サイズ・消失・増加・形の差分の中身（ずらし方・変化量・判定円）、判定円の定義と判定円どうしが重ならない選び方、図形数・差分数・持ち時間・ステージごとの変化量、誤クリックの罰（5 秒）、HINT、スコア、一時停止、演出・UI、縦・横・横長のレイアウト、ステージ 1・2 の差分の種類（6 種類）、`Title` のデモ（仕組み・手順・タイミング・レイアウト）、`Help`、`(日付, セット番号, ステージ)` のシードの仕組み（同じバージョンの中では同じ絵）。既存のテストのうち、絵の生成の固定の期待値を置いたもの（乱数の使い方が変わる）と、色差分の「色相だけが変わる」を確かめたものは、新しい仕様から求め直す。それ以外は無変更で通る。同じ日付・セット番号でも、旧バージョンとは別の絵になってよい。
- **検証の数値（QA で報告）**: 実際の絵（300 セット×ステージ 3〜5 など、テスト観点と同じシード）から、色差分と明るさ差分の左右の図形の輝度コントラスト比（上の参考値と同じ定義）の中央値をステージ別に出し、QA の報告に書く。上の参考値から大きく外れる（目安: 中央値が 0.15 以上違う）なら、理由を報告に書く。値の良し悪しだけで QA を落とさない（見え方の調整は `game-balance`）。

## 完了条件

- ステージ 3〜5 に明るさの差分が出る（右の図形の明度だけが、`toneDelta[s]` だけ違う）。ステージ 1・2 と `Title` のデモには出ない。判定円は色差分と同じ。
- 色差分は、色相と明度が同時に違う。
- 上のテスト観点（手計算の境界値・割合）と、回帰条件のすべて（操作と入力のルール、`hueShift` と移動・サイズ・消失・増加・形の差分の中身、判定円と重ならない選び方、図形数・差分数・持ち時間・ステージごとの変化量、誤クリックの罰、HINT、スコア、一時停止、演出・UI、レイアウト、ステージ 1・2 の 6 種類、`Title` のデモ、`Help`、シードの仕組み）を満たし、`npm run lint`・`npm run test`・`npm run test:coverage`（90% 以上）・`npm run build` と共有ビルドの起動が通る。
- QA（実ブラウザ）で、ステージ 3〜5 の絵に明るさの差分が見え、左右を見比べて違いが分かる（明度の差が小さい `toneDelta` 0.15 でも、拡大したスクリーンショットで確認し、結果を報告に書く）。輝度コントラスト比の中央値（上の「検証の数値」）を報告に書く。
- `README.md` の違いの説明に、色には色合いと明るさの違いが含まれ、明るさだけが変わる違いが後半のステージで出ることが書かれている。
- 意図した変更（レビューで確認する）: ステージ 3〜5 の差分の種類の割合が下がる（7 種類）、色差分が全ステージで少し易しくなる、同じ日付・セット番号でも旧バージョンと別の絵になる。持ち時間・図形数・差分数などの数値は変えない。バランス（初期値の良し悪し）はテストプレイで確かめる（polish・balance は行わない）。

## 実装裁量

- 符号を決める乱数の使い方（何回引くか・色差分で色相と明度のどちらを先に引くか。シード付きで決定的であること）、明るさの抽選を 7 種類の配列にするか別の方法にするか。
- 図形の色の計算の内部表現（既存の `shape.light` を使う前提。描画のコードは変えない）。
- 輝度コントラスト比の測定スクリプトの置き場所と形式（QA の補助。リポジトリに残してもよいし、報告に数値だけ書いてもよい）。
- `Help` の説明の文言は変えない（変える必要が出たら、`Help` の spec の改訂として別に行う）。
