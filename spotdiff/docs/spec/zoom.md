# 拡大表示（ズーム）

`docs/spec.md` の一部。`Game` のパネルを拡大して見る機能を、独立して書いたもの。`docs/spec.md` と合わせて 1 つの spec である。

## 概要

`Game` の 2 枚のパネルを、同じ倍率・同じ位置で連動して拡大して見られる（スマホはピンチとドラッグ、PC はホイールとドラッグ）。後半の小さな差分（色相のずれ 30°・移動 18px・大きさの変化 22%）を、答えを教えずに見分けやすくする。当たり判定・判定円・ルールは論理座標のままで変わらない。拡大すると人が見つけやすくなるが、絵の生成と差分は変えないので、シード付きの bot で旧版と比べても数字は変わらない（難しさの感触の調整は、遊んでから行う）。

## 操作仕様

- **ピンチ（タッチ）**: 2 本の指の間隔の比で拡大・縮小する。
- **ドラッグ（タッチ・マウス）**: 拡大中に指（マウスなら左ボタン）を動かすと、絵が指に付いてくるように移動する。
- **ホイール（マウス）**: カーソルがパネルの上にあるとき、ホイール 1 ノッチごとに、カーソルの位置を中心に拡大・縮小する。
- **RESET ボタン**: 拡大中（倍率が 1.0 を超えている間）だけ、HUD の行の左端に出る。押すと倍率 1.0（絵全体が見える状態）に戻る。
- どちらのパネルを操作しても、2 枚に同じ倍率・同じ位置で反映する。
- **タップ（当たり・誤クリックの判定）の規則を変える**: `Game` のパネルへの入力は `pointerup`（指を離した時）で判定する。次をすべて満たす入力だけがタップとして判定される。
  - 同じ `Game` の中で、`play` のときに、パネルの矩形の中に `pointerdown` を受けている（`Title`／`Result` で遷移のきっかけになった指の `pointerup` は、対応する `pointerdown` が `Game` に届いていないので無視する。`clear`／`won`／`over`／`paused` の間に押した指は、`play` に戻ってから離してもタップにならない）。
  - `pointerdown` から `pointerup` までの間、押した位置からのユークリッド距離が一度も `tapSlop`（表示上の px）を超えていない（ちょうど `tapSlop` はタップ。一度超えたら、戻ってもタップにならない）。
  - その間に、ジェスチャーに加わる 2 本目の指が触れていない（`ignored` の指、受け付けられなかった HINT・RESET を押した指は数えない）。パネルの上で有効にホイールが回されていない（パネルの外・`play` 以外でのホイールは、何も変えない）。
  - パネルへの入力として判定やジェスチャーの対象になるのは、タッチとマウスの左ボタンだけ（マウスの右・中ボタンは、パネルでは判定にもジェスチャーにもならない。HINT・RESET・一時停止の再開は、今までどおりボタンを問わない）。
  - `pointerup` の時点で `play` であり、`pointerup` の位置がパネルの矩形の中にある。
  - ドラッグ・ピンチ・ホイールは、当たりにも誤クリックにもならない（時間は減らない）。倍率 1.0 でのドラッグも同様。
- HINT・RESET・一時停止画面の再開タップ・`Title`・`Help`・`Result` の入力は、今までどおり `pointerdown` で処理する。HINT・RESET・一時停止画面の再開で押した指は、離すまでパネルへの入力にしない（`pointerup` もタップにならない）。HINT と RESET の矩形は、パネルへの入力より先に判定する（何本目の指でも同じ）。HINT・RESET が受け付けられて倍率が 1.0 に戻ったときは、進行中のジェスチャー（`pending`／`dragging`／`pinching`）をすべて捨てる（判定せず、離すまで `ignored`）。受け付けられなかった押下（HINT の使用済み、RESET が出ていないとき）は、進行中のジェスチャーに影響しない。
- 拡大・移動・RESET が効くのは `play` の間だけ（`clear`／`won`／`over`／`paused` では、ピンチ・ドラッグ・ホイールは無視し、RESET は出さない）。

## 画面・Scene構成

### ビュー（倍率と見ている範囲）

パネル内座標（0〜`panelSize` = 400。レイアウトによらない）で、見ている範囲の左上 `(viewX, viewY)` と倍率 `zoom`（`zoomMin`〜`zoomMax`）を持つ。見ている範囲は一辺 `panelSize / zoom` の正方形で、パネルの矩形いっぱいに表示する。

- パネル内座標 `p` → キャンバス座標: `panelOrigin + (p - view) * zoom * panelScale`。逆は `p = view + (キャンバス座標 - panelOrigin) / (zoom * panelScale)`。`zoom = 1`・`view = (0, 0)` のとき、今までの `Game` の座標変換と同じ（絵・判定・赤丸が変わらない）。
- `view` は常に `0 <= viewX, viewY <= panelSize - panelSize / zoom`（見ている範囲がパネルの外へはみ出さない）に収める。
- **ビューの更新（アンカーの規則）**: ジェスチャーの開始時に、指の中点の下にあるパネル内座標 `a` を決め、以降は「`a` が指の中点の下にある」ように `view` を求める（`view = a - (中点 - panelOrigin) / (zoom * panelScale)` を収め直す）。ピンチでは `zoom = 開始時の zoom × 現在の指の間隔 ÷ 開始時の間隔`（`zoomMin`〜`zoomMax` に収める。中点は 2 本の指の中点）。ドラッグ（指 1 本）では `zoom` は変わらない。ホイールでは `zoom` に係数を掛け、アンカーはカーソルの下の点にする。ジェスチャーの指の数が変わる（2 本目が触れる、1 本が離れる）たびに、現在のビューと指の位置から開始し直す。
- ホイールの係数: `wheelStep ^ (-clamp(deltaY, -wheelDeltaMax, wheelDeltaMax) / 100)`（`deltaY` が負で拡大。1 ノッチ = 100 で `wheelStep` 倍）。`deltaMode` が行単位（Firefox など）のときは、`deltaY` に `wheelLinePx`（16）を掛けてピクセル相当にしてから使う。倍率は `zoomMin`〜`zoomMax` に収める。カーソルがどちらのパネルの矩形の外にあるときは何もしない。ホイールを回すと、進行中の `pending` は `dragging` になり（タップにならない）、`dragging` はホイール後のビューとカーソル位置からアンカーを取り直す。
- ピンチの開始時の指の間隔が 1 CSS px 未満のときは、倍率の比を 1 として扱う（ゼロ割りを避ける）。
- ジェスチャーで使う座標変換は、そのジェスチャーの最初の `pointerdown` が入ったパネルの `panelOrigin` を使う（指がパネルの外へ出ても、同じ線形の変換で続ける）。

### ジェスチャーの状態

1 回のジェスチャー（最初の指が触れてから、すべての指が離れるまで）の状態:

| 状態 | 内容 | 遷移 |
|---|---|---|
| `ignored` | パネルの外・HINT・RESET・一時停止画面を押した指。離すまで何も起こさない | すべての指が離れたら終了 |
| `pending` | パネルの中に触れた指 1 本。タップの候補 | `tapSlop` を超えて動いたら `dragging`（動いた位置から開始し、`tapSlop` 分の飛びは起きない）。2 本目が触れたら `pinching`。離れたらタップとして判定して終了 |
| `dragging` | 指 1 本でビューを動かしている。タップにならない | 2 本目が触れたら `pinching`。離れたら終了（判定しない） |
| `pinching` | 2 本の指で拡大・移動している。タップにならない | 1 本が離れたら `dragging`（残りの 1 本から開始し直す）。判定しない。3 本目以降は無視する |

- パネルの外から始まった指、`play` 以外で押した指は `ignored`。ジェスチャーの最初の指が `ignored` のとき、後から触れた指もすべて `ignored`（`pending` にならない）。最初の指が `pending`／`dragging` のとき、2 本目の指は、位置によらず（パネルの外でも）ジェスチャーに加わる（HINT・RESET の矩形を押した指を除く。上の「操作仕様」）。3 本目以降の指は `ignored`。
- `pointercancel`（OS やブラウザのジェスチャーで指が取り消された）は、判定せず、その指を終わらせる（残りの指は、指の数が変わったときの規則で続ける）。
- ブラウザ既定のピンチ拡大・スクロール・ホイールによるページのスクロールは、`Game` では抑止する（`touch-action: none` 相当と、ホイールの `preventDefault`）。
- ジェスチャー中に `play` でなくなった（`clear`／`won`／`over`／`paused`）・レイアウトが変わった・Scene が終了したときは、そのジェスチャーを捨てる（判定せず、離すまで `ignored` と同じ）。`pointerupoutside`（キャンバスの外で離れた）は判定しない。
- 同時に見るのはマウスとタッチのどちらか 1 つのジェスチャーだけでよい（混在は考えない）。

### 状態遷移との関係

- `Game` の `create` とステージの開始（次のステージ・時間切れからの再開）で、`zoom = 1`・`view = (0, 0)`。
- `play` から `clear`／`won`／`over` に入った瞬間（同じフレーム）に `zoom = 1`・`view = (0, 0)` に戻す。最後の差分を見つけた当たりの赤丸の広がり、時間切れの黄色い開示は、倍率 1.0 で描く。
- `paused` では倍率と位置を保つ（再開後に続きから。一時停止画面は絵を覆うので、見えない）。
- レイアウトの変更（縦・横・横長）では、`zoom` と `view` はパネル内座標なのでそのまま引き継ぐ（新しい配置で、同じ範囲を見る）。
- **HINT**: HINT が受け付けられたとき（使えるとき）は、押した瞬間に `zoom = 1`・`view = (0, 0)` に戻してから、ヒントの円を今までどおりに示す。使えないときの押下は、何も起こさない（倍率も変えない）。ヒントの円を示している 1.5 秒の間に拡大した場合は、円も絵と一緒に拡大して描く（円の位置・大きさはパネル内座標のまま）。

### 描画

- 倍率が 1.0 のときは、今までと同じ描画（赤丸はパネルの矩形の外へはみ出してよい）。
- 倍率が 1.0 を超えている間は、パネルの背景・装飾・図形・赤丸・ヒントの円を、すべてそのパネルの矩形でクリップする（拡大した赤丸がもう 1 枚のパネルや HUD にかからない）。クリップの方法は実装裁量。
- 図形・赤丸・ヒントの円の位置と大きさは、ビューの変換（上の式）で拡大・移動する。赤丸の線幅 4px は拡大しても 4px のまま（今までどおり）。
- 誤クリックの×と「-5」は、「パネル番号とパネル内座標」で保持し、描画のたびにビューの変換でキャンバス座標を求める（絵に付いてくる）。×と「-5」の大きさ・線幅は拡大しない（`docs/spec/effects.md` どおり）。描くかどうかは、変換後の位置（「-5」は上昇前の中心で、x を収め込む前の位置）がそのパネルの矩形の中にあるかで決める（外なら描かない。時間は進める）。倍率 1.0 では、パネル内のタップに出るので常に「中」で、今までと同じように描く。「-5」の x を `[40, キャンバス幅-40]` に収める規則は、変換後の位置に適用する。
- 描画順（`docs/spec.md` の「レイアウト方針」）は変わらない。
- **RESET ボタン**: 文字は "RESET"。HUD の行で、HINT とキャンバスの水平中央に対して左右対称の位置・同じ大きさの矩形（押せる範囲は実寸 44 CSS px 以上。HUD の行の外へ透明に広げてよいが、パネルの矩形とは重ならない）。倍率が 1.0 を超えていて `play` のときだけ表示し、それ以外では何も描かず、押しても何も起こらない（`Game` の他の入力にもならない）。HUD の最大幅は、RESET が出ているかによらず常に「キャンバス幅 − 2 ×（HINT と RESET のうち幅の大きい文字の幅 ＋ 16 px）」とする（拡大に入った瞬間に HUD の大きさが変わらないように。`docs/spec.md` の HUD の規定を、この値で置き換える）。倍率 1.0 でも、HUD の文字が今までより縮んでよい（意図した変更。縮小後もキャンバス上で 32 px 以上）。HUD の文字はキャンバス上で 32 px 以上のまま。

## ルール

- 当たり判定・判定円・当たりと誤クリックの結果（時間の減算・カメラシェイク・赤丸）は `docs/spec.md` のとおり。変わるのは、入力をパネル内座標へ変換する式（ビューを通す）と、判定を行う時点（`pointerup`）だけ。
- 拡大しても、時間は止まらない（ズームやドラッグの間も `play` の時間は減る）。ヒントの代金・ステージの持ち時間・スコアの規則は変わらない。
- 倍率・位置はセーブしない（Scene と一緒に捨てる）。

### 純粋ロジックとして分けるもの（Phaser 非依存・時間と座標は引数で渡す）

- ビューの計算（パネル内座標⇄キャンバス座標、収め直し、アンカーを保った拡大、ホイールの係数）。
- ジェスチャーの状態機械（指の押下・移動・離れ・キャンセルを渡すと、状態・ビューの更新・「タップとして判定する位置」を返す）。`tapSlop` はキャンバス座標への換算係数と一緒に引数で渡す。
- RESET ボタンの矩形と表示条件（レイアウト・倍率・状態 → 矩形／非表示）、HUD の最大幅。
- `Scene` は、Phaser の入力イベント（複数の指を扱うため `input.addPointer` で指の数を増やす）とビューの描画・クリップをつなぐだけにする。

## パラメータ表

| 名前 | 初期値 | 意味 |
|---|---|---|
| `zoomMin` | 1.0 | 最小の倍率（絵全体が見える） |
| `zoomMax` | 3.0 | 最大の倍率（縦 390x844 で最小の図形が約 36 → 約 107 CSS px、見ている範囲はパネルの 1/3 四方） |
| `wheelStep` | 1.1 | ホイール 1 ノッチ（`deltaY` = 100）あたりの倍率の係数 |
| `wheelDeltaMax` | 300 | 1 回のホイールで使う `deltaY` の絶対値の上限（トラックパッドの急な入力を抑える） |
| `wheelLinePx` | 16 | `deltaMode` が行単位のときの 1 行あたりのピクセル換算 |
| `tapSlop` | 10 | タップとみなす移動量の上限（表示上の px。`Scale.FIT` の縮小率でキャンバス座標に換算する。ちょうど 10 はタップ、超えたらドラッグ） |
| RESET の位置・大きさ | HINT と水平中央に対して対称・HINT と同じ大きさ | 拡大中だけ表示 |

## テスト観点

- **座標変換**（手計算）: 縦レイアウト（panelScale 1.75、1 枚目の原点 (34, 210)）で、`zoom = 2`・`view = (100, 50)` のとき、キャンバス座標 (34, 210) はパネル内 (100, 50)、そこから (70, 35) 右下は (120, 60)。`zoom = 1`・`view = (0, 0)` では今までの変換（(35, 35) 右下は (20, 20)）と一致する。往復（パネル内→キャンバス→パネル内）で元に戻る。横・横長のパネル原点でも同様。
- **収め直し**: `zoom = 2` で `view` の最大は (200, 200)、`zoom = 3` で約 266.67、`zoom = 1` で (0, 0)。範囲外の `view` は最寄りの端になる。
- **アンカーを保つ拡大**: `zoom` 1→2、`view = (0, 0)`、アンカーのパネル内座標 (300, 100) なら新しい `view = (150, 50)`。アンカー (390, 390) なら (195, 195)、(400, 400) なら (200, 200)。拡大後も、アンカーが指（カーソル）の下にある。縮小で `view` が範囲外にならない。
- **ホイール**: `deltaY = -100` を `zoom = 1` から 2 回で 1.1、1.21。`deltaY = +100` を `zoom = 1` で受けても 1.0 のまま。`deltaY = -300` で 1.1³ = 1.331、`deltaY = -1000` も 300 に丸めて 1.331。パネルの矩形の外では何も起こらない。`zoomMax` で止まる。
- **ピンチ**: 開始の間隔 100・`zoom = 1` で、間隔 250 → 2.5、400 → `zoomMax`（3.0）、30 → 1.0。指の中点が動けば、アンカーの点が中点の下に付いてくる。
- **ジェスチャー（タップとドラッグ）**: 移動 9px・10px で離すとタップ（判定する）、10.01px では `dragging` になり離しても判定しない。`pending` から 2 本目が触れて 1 本離しても判定しない（`dragging` を経て終了）。パネルの外・HINT・RESET・一時停止画面を押した指は、離しても判定しない。`pointerdown` を受けていない `pointerup`（`Title`／`Result` から遷移した指）は判定しない。倍率 1.0 でのドラッグは誤クリックにならず、時間も減らない。ドラッグが `tapSlop` を超えた瞬間に `view` が飛ばない（超えた位置から始まる）。`dragging` の移動量: `zoom = 2`・縦（panelScale 1.75）で指を (+40, +20) 動かすと `view` は (-40/3.5, -20/3.5)（≒ (-11.43, -5.71)）だけ変わり、収め直される。
- **ジェスチャーの穴（状態機械の全ケース）**: 1 本目が `pending`／`dragging` のときに 2 本目で HINT（使える）を押すと、HINT が受け付けられ、倍率が 1.0 に戻り、進行中のジェスチャーが捨てられ、離しても判定しない（誤クリックにならない）。HINT が使用済み・RESET が出ていないときの押下は、進行中のジェスチャーに影響しない（`pinching` になるのではなく、その指だけが `ignored`。1 本目はそのまま `pending` で、離すとタップとして判定される）。1 本目が `ignored`（パネルの外・HINT・RESET・`play` 以外）のとき、2 本目がパネルに触れても `ignored` のまま（離しても判定しない）。`clear` 中に押して `play` で離した指は判定しない。3 本目の指は無視する。`pointercancel` は判定せずその指を終わらせる。マウスの右・中ボタンは判定にもジェスチャーにもならない。マウスで左ボタンを押している間（`pending`）にホイールを回すと `dragging` になり、離しても判定しない。ホイールの `deltaMode` が行単位のとき、`deltaY = -3` は -48（`wheelLinePx` = 16）として扱い 1.1^0.48 倍になる。ピンチ開始の間隔が 1 CSS px 未満のときは比 1（倍率が変わらない）。押した位置から一度でも `tapSlop` を超えて動いたら、押した位置に戻って離してもタップにならない。
- **判定の時点**: 指を離した位置で判定し、`pointerup` の時点で `play` でなければ判定しない（`clear`／`won`／`over`／`paused`）。同じフレームで最後の差分を見つける `pointerup` は、`update` より先に処理される。倍率 2.0 でも、拡大した画面上の位置を `pointerup` すると、論理座標の同じ判定円で当たる（境界ちょうどは当たり）。パネルの矩形の外で離しても何も起こらない。
- **状態遷移**: `play` 以外ではピンチ・ドラッグ・ホイールで `zoom` が変わらない。`clear`／`won`／`over` に入ると `zoom = 1`・`view = (0, 0)`、`paused` では保たれ、再開後も同じ値。次のステージ・時間切れからの再開で 1.0 に戻る。レイアウトが変わっても `zoom`・`view` が変わらない。ジェスチャー中に `play` でなくなったら捨てられ、離しても判定しない。
- **HINT**: 拡大中に HINT を押すと、`zoom = 1`・`view = (0, 0)` になり、ヒントの円が今までの位置・大きさで出る（使用済みなら何も起こらず、倍率も変わらない）。HINT の押下は誤クリックにならない。HINT を押した指の `pointerup` はタップにならない。
- **RESET**: 倍率 1.0 では矩形が無効（押しても何も起こらない）、1.0 を超えて `play` のときだけ有効。押すと `zoom = 1`・`view = (0, 0)`。誤クリックにならない。矩形が HINT と水平中央に対して左右対称で、HUD・パネルと重ならず、キャンバスに収まる（縦 768 幅・横 1024 幅・横長 1664 幅）。実寸 44 CSS px 以上（縦 390x844・横長 844x390）。HUD の最大幅の計算が、HINT と RESET のうち大きい方の文字幅を使う。縦キャンバス幅 768・セット番号 3 桁・残り時間警告の拡縮（`1 + lowTimePulse`）でも、HUD が RESET・HINT と重ならない。
- **×と「-5」**: 描くかどうかの判定は、変換後の位置（「-5」は上昇前・x の収め込み前）で行う。倍率 1.0 では、パネルの上端付近のタップでも「-5」が上昇の途中で消えない。誤クリックの位置が、ビューの変換後のキャンバス座標に出る。ビューを動かすと絵に付いてくる。変換後にパネルの矩形の外なら描かれない。「-5」の x の収め込みは変換後の位置に適用される。
- **回帰条件（拡大表示の追加で変えないもの）**: 倍率 1.0 のとき、絵・判定・赤丸・×・「-5」・ヒントの円の座標と描画が今までと同じ（赤丸のはみ出しも含む。HUD は、最大幅が RESET の文字幅ぶん小さくなって文字が縮む場合があることだけが意図した変更で、位置・内容・32px 以上の規定は変わらない）。判定円の論理座標と半径・当たりと誤クリックの結果（5 秒の減算・カメラシェイク・赤丸）・HINT の規則（1 ステージ 1 回・5 秒・最小インデックス・1.5 秒）・絵と差分の生成とシード・図形数・差分数・持ち時間・スコア・一時停止の挙動・`Title` のデモ・`Help`・`Result`（入力ロックを含む）・演出の内容と時間・縦／横／横長のレイアウトが変わらない。既存のテストは、パネルへの入力を `pointerdown` で行うものだけ `pointerup` のタップに直し、期待値は変えない。

- `npm run lint`・`npm run test`・`npm run test:coverage`（90% 以上）・`npm run build` が成功し、共有ビルド（`task build`）でも起動する。
- 倍率 1.0 を超える間、ピンチ・ドラッグ（タッチ）、ホイール・ドラッグ（マウス）で 2 枚のパネルが同じ倍率・同じ位置で連動して拡大・移動する。倍率は `zoomMin`〜`zoomMax`、見ている範囲がパネルの外へはみ出さない。

- RESET が拡大中だけ HUD の左端に出て、押すと 1.0 に戻る。縦 390x844・横長 844x390 で HUD・HINT と重ならず、実寸 44 CSS px 以上で押せる。
