# SpotDiff（間違い探し・仮称）

## コンセプト

図形で描いた左右（縦持ちでは上下）2枚の絵から、違う箇所を制限時間内にクリック／タップして見つける短時間パズル。5ステージを1セットとし、絵と差分はシード付き乱数で自動生成する。シードは「日付」と「セット番号」で決まり、同じ日・同じ番号のセットは何度遊んでも同じ5ステージ、日付や番号が違えば別の構成になる（1ステージずつ再挑戦して答えを覚えてしまうのを防ぐため、遊びはセット単位）。ステージが進むほど図形が増え、差分は小さく多くなる。

## ターゲットプレイヤー

カジュアル全般。PC（マウス）でもスマホ（タッチ、縦持ち・横持ち）でも、1ステージ約30〜60秒・全体で数分の空き時間に遊べる。

## コアループ

違うと思う箇所をクリック／タップする。当たりなら発見済みになり赤丸が付く。外れなら残り時間が減る。全差分を見つけたらステージクリアで次のステージへ。時間が尽きたらゲームオーバー。

## 操作仕様

- 入力はクリック／タップのみ（マウスとタッチで同じ。ホバー・ドラッグ・長押し・キーボードは使わない）。すべての Scene で `pointerdown` で処理する（Scene 遷移のきっかけになった入力の `pointerdown` は新しい Scene には届かないので、誤クリックにならない）。
- 2枚のパネルのどちらを押してもよい。押した位置を、そのパネルの左上を原点としたパネル内座標（表示倍率 `panelScale` で割った値）に変換して判定する。
- パネルの外を押しても何も起こらない（時間も減らない）。
- 入力を受け付けない期間は「画面・Scene構成」の各状態を参照。

## 画面・Scene構成

Scene は `Title` → `Game` → `Result` の3つ。画面の向きは次のとおり切り替える（全 Scene 共通）。

- **レイアウトの判定**: ウィンドウが縦長（高さ > 幅）なら縦レイアウト、そうでなく幅÷高さ ≧ `wideAspectMin`（1.6）なら横長レイアウト（横持ちのスマホ向け）、それ以外（4:3 の PC など）は横レイアウト。幅÷高さがちょうど 1.6 なら横長。Scene 開始時と、ウィンドウのリサイズ時に判定する。レイアウトが変わったらキャンバスサイズを切り替えて再配置する（Game 中なら絵は再生成せず、同じシード・同じ図形・同じ差分を新しい配置で描き直す。日付 `d`、セット番号 `n`、スコアの累計、ステージ、発見済み、残り時間、一時停止の状態（入る前の状態・再開ロックの残り）、`clear`／`won`／`over` のタイマーとメッセージ、開示済みの赤丸もそのまま引き継ぐ）。
- キャンバスは Phaser の `Scale.FIT`・中央寄せ。

### Title

- 表示: ゲーム名「SpotDiff」、遊び方の一行説明（"Find the differences"）、今日の日付（`Title` の `create` 時に取得した端末のローカル日付、`YYYY-MM-DD`）、"TAP TO START"。
- 画面のどこをクリック／タップしても `Game` へ遷移する。表示した日付をそのまま `Game` に渡し（タップ時に取り直さない。以降そのプレイでは固定で、日付をまたいでも変えない）、セット番号 1 で開始する。

### Game

**レイアウト方針**（座標はパラメータ表）

- 横: 上部中央に HUD（1行）、その下にメッセージ行、画面中央付近に2枚のパネルを左右に並べる。
- 縦: 上部中央に HUD、その下にメッセージ行、2枚のパネルを上下に並べる。パネルは表示倍率 `panelScale`（縦のみ 1.75）で拡大して描き、スマホの縦長の画面で画面幅いっぱいに近づける（判定円・赤丸・当たり判定は、パネル内座標のまま同じ倍率で拡大される。図形の大きさ・差分の論理座標・ルールは変わらない）。
- 横長: 横と同じく2枚のパネルを左右に並べ、表示倍率 `panelScale`（横長のみ 1.6）で拡大して画面の高さいっぱいに近づける（横持ちのスマホ 844x390 でパネルが高さの約 8 割になる）。上部中央に HUD（1行）、その下にメッセージ行、その下にパネル。判定円・赤丸・当たり判定は縦と同様、パネル内座標のまま同じ倍率で拡大される（図形の大きさ・差分の論理座標・ルールは変わらない）。
- 背面に画面全体の背景、その上にパネル（背景＋装飾＋図形）、その上に赤丸マーク、その上に誤クリックの×、その上に HUD とメッセージ、その上に誤クリックの「-5」、最前面に一時停止画面。

**HUD**: `SET <セット番号>   STAGE <n>/5   <発見数>/<差分数>   TIME <残り秒>`。縦キャンバス幅 768px・セット番号3桁でも1行に収まること（必要なら文字を縮小してよい。縮小後もキャンバス上で 32px 以上）。`play` 中のメッセージ行は空。`clear`／`won`／`over` の間は、その状態に入った時点の値で HUD を固定する（`over` の TIME は 0）。残り秒は切り上げ整数（`ceil`）。

**絵の描画**

- パネル背景は淡色の矩形、その上に装飾の円（左右同一。差分にならない）、その上に図形をインデックス順（若い順が下）に描く。
- 2枚の絵は同じ図形の集合から作り、差分の図形だけが違う。左右の図形はインデックスで対応し、どちらの絵も同じ描画順を保つ（移動・サイズ変更・形の変更をされた図形も自分のインデックスの順位で描く。消失した図形は右の絵に、増加した図形は左の絵に、描かない）。
- 図形は円・四角・三角（頂点が上の二等辺三角形）。いずれも、中心を中心とする一辺 `2*size` の正方形（バウンディングボックス）に収まる（円は半径 `size`、四角は一辺 `2*size`、三角は底辺 `2*size`・高さ `2*size`）。
- 赤丸マーク: 発見済み差分の判定円（下記）を、両パネルに同じパネル内座標で、線幅 4px の赤い輪として描く。輪の線幅は表示倍率に関わらず 4px（拡大しても太くしない）。輪はパネルの矩形でクリップせず、パネルの外へはみ出してよい（HUD・メッセージより背面）。

**状態遷移**（Game 内部の状態）

| 状態 | 内容 | 次の状態への遷移 |
|---|---|---|
| `play` | 入力を受け付け、時間が減る | 全差分発見 → `clear`（最終ステージなら `won`）／残り時間が 0 → `over` |
| `clear` | メッセージ "CLEAR!"。入力は無視、時間は止まる。`stageClearPauseMs` 続く | 経過後に次のステージを生成して `play` へ（HUD・メッセージを更新） |
| `won` | 最終ステージをクリアした直後。メッセージ "ALL CLEAR!"。入力は無視 | `stageClearPauseMs` 経過後に `Result` へ |
| `over` | 残り時間 0。未発見の差分の判定円を赤丸で表示（正解の開示）。メッセージ "TIME UP"。入力は無視 | `resultRevealMs` 経過後に `Result` へ |
| `paused` | ページ非表示で入る（`play`／`clear`／`won`／`over` のどれからでも）。時間は止まり、入力は一時停止画面へのタップ以外無視。詳細は下の「一時停止」 | 再開タップで、入る前の状態へ戻る |

- **一時停止（`paused`）**: `Game` が動いている間に、ページが非表示になった（ブラウザのタブ切り替え、別アプリへの切り替え、スマホの画面消灯。Phaser の `hidden` イベント／`document.visibilityState` が `hidden`）ら、その時点の状態（`play`／`clear`／`won`／`over` のいずれか）を覚えて `paused` に入る。
  - **時間の数え方**: 残り時間と、`clear`／`won`／`over` の待ち時間は、`update` の経過時間（delta）で自前のカウンタを減らして数える（Phaser の `delayedCall` やタイマーイベントは使わない）。`paused` の間はカウンタを一切減らさない。非表示だった時間・一時停止画面を見ていた時間は数えない。再開タップの後の最初の `update` からは、そのフレームの通常の delta だけで進める。
  - **進行中のカメラシェイク**: `paused` に入る時にカメラシェイクを止め（残りの揺れは再開しない）、再開後は揺れない。
  - **優先順位**: 非表示になったら `paused` への遷移を最優先とし、`paused` に入った後は、状態遷移（`clear`→次のステージ、`won`／`over`→`Result`、時間切れ）を一切行わない。待ち時間のカウンタが 0 以下になっていても、再開後の最初の `update` で遷移する。非表示と同じフレームに最後の差分を見つける入力があった場合は、入力が先に処理される（その入力で `clear`／`won` になってから、`paused` に入る）。
  - `Game` の `create` の時点で、すでにページが非表示なら、`play`（ステージ1）の初期状態で `paused` から始める（復帰したときに一時停止画面を見せる）。
  - ページが再び表示されたら、一時停止画面を表示する（非表示の間に一時停止画面を用意しておき、復帰した瞬間に見えること）。一時停止画面は画面全体を覆い、絵・HUD・赤丸が読み取れない不透明度（`pauseOverlayAlpha` = 1.0）で、中央に "PAUSED" と "TAP TO RESUME" を出す（一時停止中に絵を眺められないようにするため）。描画順は最前面（HUD・メッセージ・赤丸より前）。
  - 復帰（直近の `visible`。`visible` になるたびにやり直す）から `resumeInputLockMs` の間は一時停止画面へのタップを無視する（復帰操作の余波で誤って再開しないため）。以降、画面のどこをタップしても、覚えていた状態に戻って時間が動き出す。この再開タップは誤クリックにも当たりにもならない（パネルへの入力として扱わない）。
  - 再開後は、`play` なら残り時間は一時停止直前の値から、`clear`／`won`／`over` なら待ち時間は一時停止直前の残りから続く。見た目（発見済み・開示済みの赤丸、メッセージ、HUD）も一時停止直前と同じに戻る。
  - 非表示と表示が繰り返されても、再開タップを受けるまでは `paused` のまま。`paused` 中にウィンドウの向きが変わったら、一時停止画面も新しいサイズで描き直す。
  - ウィンドウのフォーカスが外れただけ（ページは表示されたまま。デスクトップで別ウィンドウを操作した場合など）では一時停止しない。
  - `Title`／`Result` では一時停止しない（時間が進まないため）。
- 同一フレームの競合: 入力イベントは `update` より先に処理される。最後の差分を見つけた入力で `clear`／`won` になり、その後の `update` では時間を減らさない（`play` でないため）。外れ入力で残り時間が 0 になったら即 `over`。`play` 以外の状態に入ったら、以降の入力・時間経過は無視する。
- 誤クリック（どの判定円にも入らない、パネル内の入力）: 残り時間を `missPenalty` 秒減らす（0 未満にはしない）。カメラを揺らす（`missShakeMs`・`missShakeIntensity`、Phaser のカメラシェイクを使う）。入力は揺れ中も受け付ける。
- 当たり（未発見の判定円の内側）: その差分を発見済みにして赤丸を付ける。時間は減らさない。既に発見済みの差分の円内の入力は、他の未発見の判定円に入っていなければ誤クリック扱い。
- 進行中（`play`）に Scene が終了・再開されたとき、入力リスナー・リサイズリスナー・タイマーは後始末する。

### 演出・UI

プレイヤーの操作や出来事への反応と、読みやすさのための表示。**どの演出も入力を止めない**（仕様が入力を無視する状態を除く）。描画は Phaser の Graphics とテキストだけで行い、画像・音声は使わない。オブジェクトは作り直さず再利用し、`update` で生成しない。時間はすべて「出来事のフレームを t=0 として、ちょうど D で消える」に統一し、`update` の経過時間で数える（`delayedCall` は使わない）。

**共通ルール**

- **一時停止**: `paused` に入る時、×と「-5」はその場で消す。赤丸の広がりとメッセージのポップは最終値（拡大率 1.0）に確定する（再開後に続きはやらない）。状態で決まる表示（残り時間の警告色、時間切れの黄色い開示、初回ヒント）は再開後も条件を満たす限り続く。残り時間の警告の拡縮は、`paused` の間は時間 t を止め、再開後にその続きから進める。
- **Scene 再開・遷移**: 演出の状態は Scene と一緒に捨て、次の Scene に持ち越さない。新しいステージが始まる時は、残っている×・「-5」・広がりをすべて消す。
- **レイアウトの変更**（縦・横・横長のどれの間でも）: 演出は新しいレイアウトで描き直し、経過時間は引き継ぐ。×と「-5」は「パネル番号（上下／左右のどちらか）とパネル内座標」で保持し、描画のたびに現在のレイアウトのパネル位置と表示倍率から画面位置を求め直す。
- **画面外**: ×はパネル内のタップにしか出ないので収める必要はない。「-5」は、上昇前の中心の x だけを `[40, キャンバス幅-40]` に収める（縦の拡大したパネルの端をタップしても文字が切れないように。y は収めない。上昇しても画面外に出ない位置にしかタップできない）。
- **文字の大きさ**: 縦レイアウトと横長レイアウトでは、HUD・メッセージ行・Title・Result・一時停止画面・「-5」の文字は、キャンバス上で 32px 以上にする（縦は幅 390 CSS px、横長は 844x390 のスマホで 16 CSS px 以上に見える）。HUD は、32px のときの幅に `1 + lowTimePulse` を掛けても縦キャンバス幅 768 以下になるフォントを選ぶ（文字が等幅のフォントは避ける。横長のキャンバスは幅 1664 なので収まる）。
- **押しやすさ**: 縦レイアウトの 390x844 の画面（`Scale.FIT` で幅に合う）で、最小の判定円（直径 `2*(shapeSizeMin + hitMargin)` = 68px）が 44 CSS px 以上になる（表示倍率 1.75 × 縮小 約 0.51 で約 60 CSS px）。横長レイアウトの 844x390 の画面（`Scale.FIT` で幅と高さがほぼ同率に合う。縮小 約 0.507）でも同じく 44 CSS px 以上になる（表示倍率 1.6 × 約 0.507 で約 55 CSS px）。文字（16 CSS px 以上）と判定円（44 CSS px 以上）の条件は、横長では 844x390 以上の画面で守る（これより小さい画面では、縮小に応じて小さくなってよい）。

**Game**

| 演出 | きっかけ・内容 | 時間 | 描画順・競合 |
|---|---|---|---|
| 誤クリックの×と「-5」 | 誤クリック（パネル内で外れた入力）のたびに、タップ位置へ赤い × を出す（線幅 5px、一辺 `missMarkSize`。どちらもキャンバス上の px で、表示倍率では拡大しない）。同時に「-5」（常に `-` + `missPenalty`。残り時間が足りず実際の減算が少ない時もこの表示）を同じ位置に出し、`missPopupRise` px 上へ動かしながら消す | ×は `missMarkMs` で透明度が 1→0（直線）。「-5」は `missPopupMs` で透明度 1→0、上昇は 0→`missPopupRise`（直線） | ×は赤丸の上・HUD の下、「-5」は HUD の上・一時停止画面の下。同時に出せる数は `missMarkMax` 個ずつで、超えたら最も古いものを再利用する。同一フレームの誤クリックはそれぞれ独立に出す。誤クリックで時間切れになった場合も同じフレームで出し、`over` の間も時間どおり進める |
| 当たりの赤丸の広がり | 当たり（発見）のたびに、その差分の赤丸（両パネル同時）の半径だけを中心から広げて出す（線幅 4px は固定）。時間切れの黄色い開示は広げず、すぐ全体を出す | `hitPopMs` で半径の拡大率が `hitPopFrom`（0.6）→1.0（イーズアウト: `from + (1-from)*(1-(1-p)^3)`、p は 0〜1 の進み具合）。透明度は常に 1 | 最後の差分の当たりでも広がる（`clear`／`won` 中も進める）。他の赤丸には影響しない |
| 時間切れの開示の色 | `over` で未発見の差分の判定円を、発見済みの赤と区別して黄色（`revealMarkColor`）で描く | `over` の間ずっと（状態で決まる） | 発見済みの赤丸はそのまま赤 |
| 残り時間の警告 | `displaySeconds` が `lowTimeSec`（10）以下の間、HUD の文字色を赤系（`lowTimeColor`）にする。`play` の間は、さらに HUD を拡縮する（拡大率 `1 + lowTimePulse*(1-cos(2π*t/lowTimePulseMs))/2`、t は警告に入ってからの経過ms。範囲 1.0〜`1+lowTimePulse`） | 色: 状態で決まる（`clear`／`won`／`over` でも ≤10 なら赤のまま）。拡縮: `play` のみ、周期 `lowTimePulseMs`。t=0 は、`play` 中に `displaySeconds` が `lowTimeSec` 以下になった（初めて、または誤クリックで一気に下がった）フレームで、そこから数える。`clear`／`won`／`over` に入ったら拡大率は即 1.0 に戻る。拡縮は HUD の中心を基準にする | 新しいステージで残り時間が `lowTimeSec` を超えれば元の色・拡大率 1 に戻る。HUD の幅に収める縮小と掛け合わせ、拡縮で一時的に幅を超えてもキャンバス幅内に収まる程度（`lowTimePulse` ≦ 0.12）。色だけでなく動きでも知らせる |
| 初回ヒント | ステージ1・セット番号1・`play`・発見数 0 の間、メッセージ行に "Tap where the pictures differ" を出す。最初の当たりで消える（誤クリックでは消えない） | 状態で決まる | メッセージ行を使う。`clear`／`won`／`over` のメッセージが出る時は、そちらが優先（ヒントが出ている間に発見数 0 のまま時間切れになったら、その瞬間に "TIME UP" に置き換わる）。ヒントの文字は縦・横長でも 32px 以上 |
| メッセージのポップ | "CLEAR!"・"ALL CLEAR!"・"TIME UP" が出る瞬間（メッセージが出たフレームが t=0）に、文字を拡縮する | `msgPopMs`。拡大率は 0→0.6D で `msgPopFrom`（0.8）→`msgPopPeak`（1.15）、0.6D→D で `msgPopPeak`→1.0（それぞれ直線）。D 以降は 1.0 | 初回ヒントのメッセージにはかけない |

**Title・Result**

- 「TAP TO START」「TAP FOR NEXT SET」「TAP TO RETRY」: 透明度を `promptPulseMin + (1 - promptPulseMin) * (1 + cos(2π * t / promptPulseMs)) / 2` で往復させる（t は Scene が始まってからの経過ms。t=0 で 1.0、`promptPulseMs/2` で `promptPulseMin`、`promptPulseMs` で 1.0）。`Result` では入力ロック中も動かす。
- Result の見出し・SET・STAGE・TIME・促し文: 表示した瞬間から `resultFadeMs` で透明度が 0→1（直線）。促し文の透明度は、このフェード係数と上の点滅の値の積。入力ロック（`resultInputLockMs`）には影響しない。

### Result

- 入力: 表示してから `resultInputLockMs` の間は入力を無視する（直前の連打で誤って再開しないため）。以降、画面のどこをクリック／タップしても `Title` を経由せず `Game` を開始する（ステージ1から）。クリアの Result では**次のセット番号**（日付は同じ）、ゲームオーバーの Result では**同じセット番号**（同じ絵のやり直し）で開始する。
- 表示:
  - 見出し: クリア時は "ALL CLEAR!"、ゲームオーバー時は "TIME UP"。
  - "SET <セット番号>"（直前にプレイしたセットの番号。クリア時も +1 しない）。
  - "STAGE <到達ステージ>/5"（クリア時は 5、ゲームオーバー時は時間切れになったステージ番号）。
  - "TIME <残り時間の合計>"（スコア。単位は秒。ゲームオーバー時も、クリア済みステージ分の合計を表示する）。
  - クリア時は "TAP FOR NEXT SET"、ゲームオーバー時は "TAP TO RETRY"。
- 永続化: なし（ハイスコアは保存しない）。

## ルール

### セットとシード

- **セット**: 5ステージ（ステージ1〜5）の組。`Game` は日付 `d` とセット番号 `n`（1以上の整数）を受け取って開始する。
- **日付 `d`**: `Title` から開始した時点の端末のローカル日付を整数 `YYYYMMDD` にしたもの。テストのため外から注入できること。
- **セット番号 `n`**: `Title` から開始すると 1。クリアの Result からの再開で +1。ゲームオーバーの Result からの再開では変わらない。永続化しないので、ページを開き直すと 1 に戻る。
- **シード**: ステージ `s` の絵は、`(d, n, s)` の組だけで決まる（時刻などに依存しない）。3つ組が異なれば別のシードになること（`d + n + s` のように和で衝突させない）。したがって同じ `(d, n)` のセットは、何度遊んでも（時間切れでやり直しても）5ステージとも同じ図形・同じ差分になり、`d` か `n` が違えば別の構成になる。
- 1ステージ単位のやり直しはない。時間切れは常にセットの先頭（ステージ1）から再開する。

### 絵と差分の生成

ステージ `s`（1〜5）の絵は、上記のシードから作った乱数で次の手順で作る。同じシードなら必ず同じ絵になること。乱数はテスト・再現のため外から注入できること。

0. **ステージ番号**: `s` は 1〜5 にクランプする（範囲外の入力は最寄りの端として扱う）。
1. **図形配置**: 図形数 `shapeCounts[s]` 個を作る。各図形は種類（円／四角／三角を等確率）、半径（`shapeSizeMin` 〜 `shapeSizeMax[s]` の一様分布）、位置、色（色相 0〜359 の一様、彩度 0.55〜0.9、明度 0.4〜0.6）を持つ。位置はパネル内で四辺から `shapeSizeMax[s] + 20` px 以上内側。既に置いた図形との中心間距離が `(r1 + r2) * overlapFactor` を超えること（超えない候補は捨てて再抽選）。重なりは許可する。再抽選は最大 4000 回まで。到達しなければ置けた分で打ち切ってよい。
2. **背景**: 背景色相 `bgHue`（0〜359）と、パネル内に `bgDots` 個の装飾の円（半径 8〜26、中心はパネル内。端で切れてよい。パネルの矩形でクリップする）を作る。装飾は左右の絵で同一で、差分の対象にならない。
3. **差分の選択**: 差分数 `diffCounts[s]` 個を、図形を乱順にした候補から順に決める。候補ごとに差分の種類（色・移動・サイズ・消失・増加・形を等確率。各 1/6、全ステージ共通でステージごとの重みはない）を決め（確率は候補ごとの値。判定円の大きい種類ほど、あとの重なりの判定で落ちやすいので、最終的に採用された差分の割合は 1/6 からずれる。ずれを補う重みは付けない）、その判定円（下記）を求め、既に決めた差分の判定円すべてと重ならない（中心間距離 > 半径の和）場合だけ採用する。重なる候補は捨てる。これにより、1つの丸の中に2つの差分が入らない。採用した差分数が足りなければ、絵全体の生成をやり直す（最大 50 回。それでも足りなければ得られた数で進める。HUD の差分数は実際の数を表示する）。
4. **差分の内容**（色・移動・サイズ・形は右の絵に反映する。消失は右の絵から、増加は左の絵から図形を除く）:
   - 色: 色相を `hueShift[s]` 度、ランダムに±どちらかへずらす。
   - 移動: 位置を `moveDist[s]` px、ランダムな向きにずらす。ずらした後も図形全体がパネル内に収まる向きだけを選ぶ（図形の配置余白により、収まる向きは必ず存在する）。
   - サイズ: 半径を `size * (1 ± scaleDelta[s])`（符号はランダム）にする。拡大でパネルからはみ出す場合は縮小側にする。
   - 消失: 右の絵からその図形を描かない（左の絵にだけある）。
   - 増加: 左の絵からその図形を描かない（右の絵にだけある）。図形の数・位置・大きさ・色は変えず、他の図形の配置にも影響しない。
   - 形: 図形の種類（円／四角／三角）を、元の種類以外の2種類から等確率で選んだものに変える。位置・半径・色は変えない。外接の正方形（一辺 `2*size`）は同じなので、パネル内に収まる配置は変わらない。

**判定円**（クリック判定とマーク表示に使う円。パネル内座標）:

| 種類 | 中心 | 半径 |
|---|---|---|
| 色・消失・増加・形 | 図形の中心 | `size + hitMargin` |
| 移動 | 元の中心と移動後の中心の中点 | `size + hitMargin + moveDist[s] / 2` |
| サイズ | 元の図形の中心 | `max(元のsize, 変更後のsize) + hitMargin` |

### 勝利・失敗・スコア

- **ステージクリア**: そのステージの差分をすべて発見する。
- **ゲーム勝利**: ステージ5をクリアする → `Result`（クリア）。
- **失敗**: いずれかのステージで残り時間が 0 になる → `Result`（ゲームオーバー）。ライフの概念はない。
- **ステージの持ち時間**: ステージごとに `timeLimits[s]` 秒から開始し、繰り越さない。プレイ中（`play`）のみ減る。何もしなければ時間切れになる。
- **スコア**: セット内でステージクリア時の残り秒（切り上げ整数）の合計。クリアしたステージだけが加算され、時間切れのステージは加算されない。セットごとに 0 から数え直す（セットをまたいで加算しない）。ステージクリア画面中に個別の表示はなく、`Result` で合計を表示する。

## MVP範囲

- 図形（円・四角・三角）で描く、シード付き乱数のランダム生成の絵（画像素材なし）。重なりを許可。
- 6種類の差分（色・移動・サイズ・消失・増加・形）と、判定円が重ならない選び方。
- 全5ステージ、ステージ別の持ち時間・図形数・差分数・差分の大きさ。
- 誤クリックの時間減算とカメラシェイク。
- 横／縦／横長レイアウトの切り替え（縦と横長はスマホ向けにパネルを拡大）。
- 操作への反応の演出（誤クリックの×と「-5」、当たりの広がり、時間切れの黄色い開示、残り時間の警告、初回ヒント、メッセージのポップ、「TAP …」の点滅、Result のフェードイン）。
- 日付とセット番号で決まる、固定シードの5ステージのセット（クリアで次のセット、時間切れで同じセットのやり直し）。
- Title・Game・Result の3 Scene。スコア（クリア時の残り時間の合計）の表示。
- 背景（画面とパネル）。
- ページ非表示（画面消灯・別アプリ・タブ切り替え）での自動一時停止と、復帰時の一時停止画面（タップで再開）。

## 技術要件

- Phaser 4 + Vite + TypeScript。描画は Phaser の Graphics とテキストのみ（画像・音声アセットを使わない。スキャフォールドの未使用アセットは残さない）。
- 静的サイトとして `npm run build` と共有ビルドの両方で動作すること（AGENTS.md 4.3）。
- ESLint エラー 0、Vitest のカバレッジは文・分岐・関数・行すべて 90% 以上。
- Scene は `Title` / `Game` / `Result`。`preload`・`create`・`update` の責務を混在させない。`update` ではオブジェクトを生成しない。入力・リサイズのリスナーは Scene 終了時に後始末する。誤クリックの揺れは Phaser のカメラシェイクを使う（自前実装しない）。
- **純粋ロジック（Phaser 非依存で単体テスト可能にする）**:
  - 乱数（シード付き。注入可能）。
  - 絵の生成（図形配置・背景・差分の選択と内容・判定円・再生成）。
  - クリック判定（パネル内座標 → 当たった差分のインデックス or なし）。
  - 色変換（HSL → 数値色）。
  - レイアウトの判定と計算（ウィンドウの幅・高さ → 縦／横／横長、レイアウト → キャンバスサイズ・パネル位置・表示倍率・HUD 位置）と、キャンバス座標→パネル内座標の変換（表示倍率で割る）。
  - 演出の時間計算（赤丸の広がりの拡大率、×・「-5」の透明度と上昇量、警告の拡縮、メッセージのポップの拡大率、点滅の透明度、残り時間の警告・初回ヒントを出すかの判定）。時間は引数で渡せること。
  - ステージ進行（持ち時間、誤クリック減算、時間切れ・クリア判定、スコア加算）。
  - 一時停止の状態機械（入る前の状態の記憶、時間カウンタの凍結、復帰時刻からのロック判定、再開）。時間・イベントは引数で渡せること。
- レイアウトの種類は縦／横／横長の3値で、判定の結果が変わった時だけ再配置する（1.6 付近でリサイズを繰り返すと切り替わるが、状態は引き継がれる）。
- 時刻・乱数は注入する。Scene は描画・入力・タイマーの接続だけを担う。

## テスト観点

- **乱数**: 同じシードで同じ絵、異なるシードで異なる絵。
- **セットとシード**: 同じ `(d, n)` で5ステージすべてが何度生成しても完全に同一（図形・差分・背景）。`d` が違う、または `n` が違うと別の構成になる。`(d, n, s)` の入れ替え（例: `n=1,s=2` と `n=2,s=1`）で同じシードにならない。
- **セット進行**: クリアの再開で `n` が +1 で `d` は不変、時間切れの再開で `n` は不変。Title からの開始は `n=1`。スコアはセットごとに 0 から。
- **図形配置**: 図形数が `shapeCounts[s]`（打ち切りを除く）、すべてパネル内（四辺から `shapeSizeMax[s] + 20` 以上内側）、任意の2図形の中心間距離が `(r1+r2)*overlapFactor` を超える、半径が `shapeSizeMin`〜`shapeSizeMax[s]`。
- **差分**: 全ステージで差分数が `diffCounts[s]`（複数シードで）。判定円どうしが重ならない。右の絵と左の絵の差が、差分と一致する（色・位置・サイズ・消失・増加・形の6種類それぞれで、差分でない図形は変化しない）。移動・サイズ変更後も図形全体がパネル内に収まる。背景の装飾は左右で同一。ステージ範囲外（0 や 6）の入力でも落ちない／クランプされる。
- **判定円**: 6種類それぞれの中心・半径が表のとおり（増加と形の差分は色・消失と同じ）。
- **増加の差分**: 増加の差分では、左の絵にその図形が描かれず、右の絵には位置・半径・色・種類がそのまま描かれる。消失の差分はその逆（右の絵に描かれない）。差分でない図形は、左右とも同じ。左に描かれる図形の数は、全図形の数から増加の差分の数を引いたもの、右は消失の差分の数を引いたものになる。多数のシードで、増加の差分も消失の差分も出る。
- **形の差分**: 形の差分では、右の図形の種類だけが左と違い、位置・半径・色は左と同じ。変更先は元の種類以外の2種類のどちらかで、元と同じ種類にはならない。多数のシードで、円→四角・円→三角・四角→円・四角→三角・三角→円・三角→四角の6通りがすべて出る。差分の種類は多数のシード（300セット×5ステージ程度）で、6種類すべてが出て、各種類が全体の 8〜25% に収まる（候補ごとの確率は 1/6 だが、判定円が大きい移動は重なりで落ちやすく、最終の割合は少し下がる。この範囲は、重なりによるずれを許す確認で、仕様が決めるのは候補ごとの 1/6 である。移動の判定円が最も大きく、重なりで落ちる割合が最も高いため、下限はその分の余裕を見た値で、実測で下限を割る種類があれば、範囲ではなく根拠を見直す）。6通りの確認も、同じ多数のシードの全差分で行う。形が変わった図形も、描画順はインデックスのまま。
- **クリック判定**: 円内で当たり、円の境界ぎりぎり（距離＝半径）は当たり、境界を超えると外れ。発見済みの差分は当たらない。差分が無い位置は外れ。
- **一時停止**: 非表示で `paused` に入り、復帰直後 `resumeInputLockMs` 未満の再開タップは無視、以降のタップで元の状態に戻る。`paused` 中に任意の時間が経過しても、残り時間と `clear`／`won`／`over` の待ち時間は変わらない（`play`・`clear`・`won`・`over` それぞれで、一時停止直前と再開直後で同じ値）。再開タップが誤クリック（時間減算）・当たりにならない。`paused` 中の非表示・表示の繰り返しで状態が壊れない（`resumeInputLockMs` は直近の `visible` から数える）。`paused` に入った時にカメラシェイクが止まる。非表示と同フレームで待ち時間が 0 以下になっても、`paused` 中は遷移せず再開後の最初の `update` で遷移する。`create` 時点で非表示なら `paused` から始まる。フォーカス喪失だけでは一時停止しない。
- **ステージ進行**: 誤クリックで `missPenalty` 秒減り、0 で下限、減算で 0 になれば時間切れ。最後の差分発見でクリア。時間が尽きたステージのスコアは加算されない。スコアはクリア時の残り秒（切り上げ）の合計。ステージ5クリアで勝利。
- **レイアウト**: 横・縦それぞれのキャンバスサイズ・パネル位置・表示倍率・パネルが画面内に収まる（縦は 2枚目の下端 1650 ≦ 1664）。縦のキャンバス座標→パネル内座標の変換が表示倍率で割った値になる（例: 1枚目の左上＝(34,210) は (0,0)、そこから (35, 35) 右下は (20, 20)）。縦のパネルの端（表示サイズ 700）の境界。
- **レイアウトの判定**: 高さ > 幅は縦（例 390x844）。それ以外で幅÷高さが 1.6 以上は横長（例 844x390 は約 2.16、1280x800 は 1.6 ちょうどで横長、1920x1080 は 1.78 で横長）、1.6 未満は横（例 1024x768 は 1.33、1279x800 は 1.599 で横）。幅＝高さは横。横長の計算: キャンバス 1664x768、パネルは x=160 と x=864・y=104・表示倍率 1.6・表示サイズ 640、下端 744 ≦ 768、右端 1504 ≦ 1664、2枚が重ならない。横長のキャンバス座標→パネル内座標の変換が表示倍率で割った値になる（例: 1枚目の左上＝(160,104) は (0,0)、そこから (32, 32) 右下は (20, 20)。2枚目の左上＝(864,104) は (0,0)）。横長のパネルの端（表示サイズ 640）の境界。判定の結果が変わる境界（1.599 → 1.6）でだけ再配置が起きる。最小の判定円（直径 68）に表示倍率 1.6 を掛け、844x390 の縮小（390/768）を掛けると 44 CSS px 以上。
- **色変換**: 代表値（赤・緑・青・無彩色）の HSL → 数値色。
- **演出の時間計算**（手計算の境界値）: 赤丸の広がりは t=0 で 0.6、t=75ms で 0.6+0.4*(1-0.5^3)=0.95、t=150ms 以降で 1.0。×の透明度は t=0 で 1、t=200ms で 0.5、t=400ms 以降で 0。「-5」は t=300ms で透明度 0.5・上昇 20px、t=600ms 以降で 0・40px。警告の拡縮は t=0 で 1.0、t=500ms で 1.10、t=1000ms で 1.0。メッセージのポップは t=0 で 0.8、t=150ms で 1.15、t=250ms 以降で 1.0。点滅の透明度は 0.5〜1.0 の範囲。警告は `displaySeconds`=10 で入り、11 では入らない。初回ヒントはステージ1・セット1・発見数 0 の `play` でだけ出て、誤クリックでは消えず、最初の当たりで消える（時間切れ後の同じセットのやり直しでも再び出る）。点滅の透明度は t=0 で 1.0、t=800ms で 0.5、t=1600ms で 1.0。Result の促し文は t=150ms（フェード 0.5）かつ点滅の値との積になる。警告の拡縮の t は、誤クリックで 13 秒から 8 秒に落ちたフレームを 0 とする。「-5」は、残り時間が 3 秒の時の誤クリックでも「-5」。「-5」の中心 x は端から 40px 未満なら 40 に、幅-40 を超えるなら幅-40 に収まる。×・「-5」の同時数が `missMarkMax`（4）を超えると最も古いものが再利用される。`paused` に入ると×・「-5」は消え、赤丸の広がり・ポップは 1.0 に確定する。向きが変わっても×・「-5」はパネル番号とパネル内座標で保たれ、新しいステージの開始で全部消える。
- **回帰条件（演出追加で変えないもの）**: 演出を足しても、当たり判定・ルール・スコア・シード・一時停止の挙動・Result の入力ロック（`resultInputLockMs`）は変わらない（既存のテストがそのまま通る）。縦の判定は、表示倍率を掛けた画面上の位置を押しても、論理座標では横と同じ判定円で当たる。
- **回帰条件（差分の種類の追加で変えないもの）**: 操作と入力のルール（クリック／タップのみ、パネル外は無反応、判定円の境界は当たり）、色・移動・サイズ・消失・形の中身（ずらし方・変化量・判定円）、図形数・差分数・持ち時間・ステージごとの変化量、誤クリックの罰（5秒）と判定円どうしが重ならない選び方、スコア、`(日付, セット番号, ステージ)` のシードの仕組み、一時停止、演出・UI、縦横レイアウトは変わらない。同じバージョンの中では、同じ日・同じセット番号は何度生成しても同じ絵になる（絵の生成の結果に固定の期待値を置いている既存のテストは、差分の選び方が変わるので、期待値を新しい仕様から求め直す）。
- **回帰条件（横長レイアウトの追加で変えないもの）**: 操作と入力のルール、誤クリックの罰（5秒）、図形数・差分数・持ち時間・ステージごとの変化量、スコア、シード、一時停止、絵の生成（同じ `(日付, セット番号, ステージ)` はどのレイアウトでも同じ図形・同じ差分）、演出・UI の内容、縦レイアウト、横レイアウト（幅÷高さ < 1.6 のとき、キャンバス 1024x768・パネル位置・表示倍率 1.0・HUD 位置は変わらない）は変わらない。判定円の論理座標と大きさは変わらず、横長でも表示倍率を掛けた画面上の位置を押すと横と同じ判定円で当たる。レイアウトが（縦・横・横長のどれの間でも）変わってもプレイ中の状態が失われない。
- **ステージ難度の単調性**: 各ステージの差分割合が `diffCounts[s] / shapeCounts[s]` で単調に下がる（25%→19%）。ステージが進むと `hueShift`・`moveDist`・`scaleDelta` が単調に小さくなる。

- 絵は `(日付, セット番号, ステージ)` ごとに違い、左右（上下）で差分を見つけられる。差分は色・位置・大きさ・消えている・増えている（右の絵にだけ図形がある）・形（円／四角／三角が別の種類に変わる）の6種類で、どのステージでも6種類のどれも出うる（テスト観点と同じ多数のシードで、各ステージに各種類が出る）。当たりで赤丸が両パネルに付く。誤クリックで残り時間が 5 秒減り、画面が揺れる（揺れはカメラシェイクが呼ばれることをテストで確認し、体感は目視で確認する）。

- 縦持ち（高さ > 幅）では2枚が上下に並び、横持ちでは左右に並ぶ。縦では 390x844 の画面でもパネルが画面幅の約 9 割になり、最小の判定円が 44 CSS px 以上に見える。向きを変えてもプレイ中の状態が失われない。
- 幅÷高さが 1.6 以上の横長の画面（横持ちのスマホ 844x390 など）では、2枚が左右に並んで拡大され、パネルが画面の高さの約 8 割になる。最小の判定円が 44 CSS px 以上に見え、HUD・メッセージ・Title・Result・一時停止画面の文字が 16 CSS px 以上に見える。幅÷高さが 1.6 未満（1024x768 など）は従来の横レイアウトのまま。縦・横・横長のどの間で切り替えても、プレイ中の状態が失われない。
