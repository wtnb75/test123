# SpotDiff（間違い探し・仮称）

## コンセプト

図形で描いた左右（縦持ちでは上下）2枚の絵から、違う箇所を制限時間内にクリック／タップして見つける短時間パズル。5ステージを1セットとし、絵と差分はシード付き乱数で自動生成する。シードは「日付」と「セット番号」で決まり、同じ日・同じ番号のセットは何度遊んでも同じ5ステージ、日付や番号が違えば別の構成になる（1ステージずつ再挑戦して答えを覚えてしまうのを防ぐため、遊びはセット単位）。ステージが進むほど図形が増え、差分は小さく多くなる。

## ターゲットプレイヤー

カジュアル全般。PC（マウス）でもスマホ（タッチ、縦持ち）でも、1ステージ約30〜60秒・全体で数分の空き時間に遊べる。

## コアループ

違うと思う箇所をクリック／タップする。当たりなら発見済みになり赤丸が付く。外れなら残り時間が減る。全差分を見つけたらステージクリアで次のステージへ。時間が尽きたらゲームオーバー。

## 操作仕様

- 入力はクリック／タップのみ（マウスとタッチで同じ。ホバー・ドラッグ・長押し・キーボードは使わない）。すべての Scene で `pointerdown` で処理する（Scene 遷移のきっかけになった入力の `pointerdown` は新しい Scene には届かないので、誤クリックにならない）。
- 2枚のパネルのどちらを押してもよい。押した位置を、そのパネルの左上を原点としたパネル内座標に変換して判定する。
- パネルの外を押しても何も起こらない（時間も減らない）。
- 入力を受け付けない期間は「画面・Scene構成」の各状態を参照。

## 画面・Scene構成

Scene は `Title` → `Game` → `Result` の3つ。画面の向きは次のとおり切り替える（全 Scene 共通）。

- **向きの判定**: ウィンドウが縦長（高さ > 幅）なら縦レイアウト、それ以外は横レイアウト。Scene 開始時と、ウィンドウのリサイズ時に判定する。向きが変わったらキャンバスサイズを切り替えて再配置する（Game 中なら絵は再生成せず、同じシード・同じ図形・同じ差分を新しい配置で描き直す。日付 `d`、セット番号 `n`、スコアの累計、ステージ、発見済み、残り時間、一時停止の状態（入る前の状態・再開ロックの残り）、`clear`／`won`／`over` のタイマーとメッセージ、開示済みの赤丸もそのまま引き継ぐ）。
- キャンバスは Phaser の `Scale.FIT`・中央寄せ。

### Title

- 表示: ゲーム名「SpotDiff」、遊び方の一行説明（"Find the differences"）、今日の日付（`Title` の `create` 時に取得した端末のローカル日付、`YYYY-MM-DD`）、"TAP TO START"。
- 画面のどこをクリック／タップしても `Game` へ遷移する。表示した日付をそのまま `Game` に渡し（タップ時に取り直さない。以降そのプレイでは固定で、日付をまたいでも変えない）、セット番号 1 で開始する。

### Game

**レイアウト方針**（座標はパラメータ表）

- 横: 上部中央に HUD（1行）、その下にメッセージ行、画面中央付近に2枚のパネルを左右に並べる。
- 縦: 上部中央に HUD、その下にメッセージ行、2枚のパネルを上下に並べる。
- 背面に画面全体の背景、その上にパネル（背景＋装飾＋図形）、その上に赤丸マーク、最前面に HUD とメッセージ。

**HUD**: `SET <セット番号>   STAGE <n>/5   <発見数>/<差分数>   TIME <残り秒>`。縦キャンバス幅 768px・セット番号3桁でも1行に収まること（必要なら文字を縮小してよい）。`play` 中のメッセージ行は空。`clear`／`won`／`over` の間は、その状態に入った時点の値で HUD を固定する（`over` の TIME は 0）。残り秒は切り上げ整数（`ceil`）。

**絵の描画**

- パネル背景は淡色の矩形、その上に装飾の円（左右同一。差分にならない）、その上に図形をインデックス順（若い順が下）に描く。
- 左パネル（または上）が元の絵、右パネル（または下）が差分入りの絵。左右の図形はインデックスで対応し、右の絵は同じ描画順を保つ（移動・サイズ変更された図形も自分のインデックスの順位で描く。消失した図形は描かない）。
- 図形は円・四角・三角（頂点が上の二等辺三角形）。いずれも、中心を中心とする一辺 `2*size` の正方形（バウンディングボックス）に収まる（円は半径 `size`、四角は一辺 `2*size`、三角は底辺 `2*size`・高さ `2*size`）。
- 赤丸マーク: 発見済み差分の判定円（下記）を、両パネルに同じパネル内座標で、線幅 4px の赤い輪として描く。輪はパネルの矩形でクリップせず、パネルの外へはみ出してよい（HUD・メッセージより背面）。

**状態遷移**（Game 内部の状態）

| 状態 | 内容 | 次の状態への遷移 |
|---|---|---|
| `play` | 入力を受け付け、時間が減る | 全差分発見 → `clear`（最終ステージなら `won`）／残り時間が 0 → `over` |
| `clear` | メッセージ "CLEAR!"。入力は無視、時間は止まる。`stageClearPauseMs` 続く | 経過後に次のステージを生成して `play` へ（HUD・メッセージを更新） |
| `won` | 最終ステージをクリアした直後。メッセージ "ALL CLEAR!"。入力は無視 | `stageClearPauseMs` 経過後に `Result` へ |
| `over` | 残り時間 0。未発見の差分の判定円を赤丸で表示（正解の開示）。メッセージ "TIME UP"。入力は無視 | `resultRevealMs` 経過後に `Result` へ |
| `paused` | ページ非表示で入る（`play`／`clear`／`won`／`over` のどれからでも）。時間は止まり、入力は一時停止画面へのタップ以外無視。詳細は下の「一時停止」 | 再開タップで、入る前の状態へ戻る |

- **一時停止（`paused`）**: `Game` が動いている間に、ページが非表示になった（ブラウザのタブ切り替え、別アプリへの切り替え、スマホの画面消灯。Phaser の `hidden` イベント／`document.visibilityState` が `hidden`）ら、その時点の状態（`play`／`clear`／`won`／`over` のいずれか）を覚えて `paused` に入る。
  - **時間の数え方**: 残り時間と、`clear`／`won`／`over` の待ち時間は、`update` の経過時間（delta）で自前のカウンタを減らして数える（Phaser の `delayedCall` やタイマーイベントは使わない）。`paused` の間はカウンタを一切減らさない。非表示だった時間・一時停止画面を見ていた時間は数えない。再開タップの後の最初の `update` からは、そのフレームの通常の delta だけで進める。
  - **進行中のカメラシェイク**: `paused` に入る時にカメラシェイクを止め（残りの揺れは再開しない）、再開後は揺れない。
  - **優先順位**: 非表示になったら `paused` への遷移を最優先とし、`paused` に入った後は、状態遷移（`clear`→次のステージ、`won`／`over`→`Result`、時間切れ）を一切行わない。待ち時間のカウンタが 0 以下になっていても、再開後の最初の `update` で遷移する。非表示と同じフレームに最後の差分を見つける入力があった場合は、入力が先に処理される（その入力で `clear`／`won` になってから、`paused` に入る）。
  - `Game` の `create` の時点で、すでにページが非表示なら、`play`（ステージ1）の初期状態で `paused` から始める（復帰したときに一時停止画面を見せる）。
  - ページが再び表示されたら、一時停止画面を表示する（非表示の間に一時停止画面を用意しておき、復帰した瞬間に見えること）。一時停止画面は画面全体を覆い、絵・HUD・赤丸が読み取れない不透明度（`pauseOverlayAlpha` = 1.0）で、中央に "PAUSED" と "TAP TO RESUME" を出す（一時停止中に絵を眺められないようにするため）。描画順は最前面（HUD・メッセージ・赤丸より前）。
  - 復帰（直近の `visible`。`visible` になるたびにやり直す）から `resumeInputLockMs` の間は一時停止画面へのタップを無視する（復帰操作の余波で誤って再開しないため）。以降、画面のどこをタップしても、覚えていた状態に戻って時間が動き出す。この再開タップは誤クリックにも当たりにもならない（パネルへの入力として扱わない）。
  - 再開後は、`play` なら残り時間は一時停止直前の値から、`clear`／`won`／`over` なら待ち時間は一時停止直前の残りから続く。見た目（発見済み・開示済みの赤丸、メッセージ、HUD）も一時停止直前と同じに戻る。
  - 非表示と表示が繰り返されても、再開タップを受けるまでは `paused` のまま。`paused` 中にウィンドウの向きが変わったら、一時停止画面も新しいサイズで描き直す。
  - ウィンドウのフォーカスが外れただけ（ページは表示されたまま。デスクトップで別ウィンドウを操作した場合など）では一時停止しない。
  - `Title`／`Result` では一時停止しない（時間が進まないため）。
- 同一フレームの競合: 入力イベントは `update` より先に処理される。最後の差分を見つけた入力で `clear`／`won` になり、その後の `update` では時間を減らさない（`play` でないため）。外れ入力で残り時間が 0 になったら即 `over`。`play` 以外の状態に入ったら、以降の入力・時間経過は無視する。
- 誤クリック（どの判定円にも入らない、パネル内の入力）: 残り時間を `missPenalty` 秒減らす（0 未満にはしない）。カメラを揺らす（`missShakeMs`・`missShakeIntensity`、Phaser のカメラシェイクを使う）。入力は揺れ中も受け付ける。
- 当たり（未発見の判定円の内側）: その差分を発見済みにして赤丸を付ける。時間は減らさない。既に発見済みの差分の円内の入力は、他の未発見の判定円に入っていなければ誤クリック扱い。
- 進行中（`play`）に Scene が終了・再開されたとき、入力リスナー・リサイズリスナー・タイマーは後始末する。

### Result

- 入力: 表示してから `resultInputLockMs` の間は入力を無視する（直前の連打で誤って再開しないため）。以降、画面のどこをクリック／タップしても `Title` を経由せず `Game` を開始する（ステージ1から）。クリアの Result では**次のセット番号**（日付は同じ）、ゲームオーバーの Result では**同じセット番号**（同じ絵のやり直し）で開始する。
- 表示:
  - 見出し: クリア時は "ALL CLEAR!"、ゲームオーバー時は "TIME UP"。
  - "SET <セット番号>"（直前にプレイしたセットの番号。クリア時も +1 しない）。
  - "STAGE <到達ステージ>/5"（クリア時は 5、ゲームオーバー時は時間切れになったステージ番号）。
  - "TIME <残り時間の合計>"（スコア。単位は秒。ゲームオーバー時も、クリア済みステージ分の合計を表示する）。
  - クリア時は "TAP FOR NEXT SET"、ゲームオーバー時は "TAP TO RETRY"。
- 永続化: なし（ハイスコアは保存しない）。

## ルール

### セットとシード

- **セット**: 5ステージ（ステージ1〜5）の組。`Game` は日付 `d` とセット番号 `n`（1以上の整数）を受け取って開始する。
- **日付 `d`**: `Title` から開始した時点の端末のローカル日付を整数 `YYYYMMDD` にしたもの。テストのため外から注入できること。
- **セット番号 `n`**: `Title` から開始すると 1。クリアの Result からの再開で +1。ゲームオーバーの Result からの再開では変わらない。永続化しないので、ページを開き直すと 1 に戻る。
- **シード**: ステージ `s` の絵は、`(d, n, s)` の組だけで決まる（時刻などに依存しない）。3つ組が異なれば別のシードになること（`d + n + s` のように和で衝突させない）。したがって同じ `(d, n)` のセットは、何度遊んでも（時間切れでやり直しても）5ステージとも同じ図形・同じ差分になり、`d` か `n` が違えば別の構成になる。
- 1ステージ単位のやり直しはない。時間切れは常にセットの先頭（ステージ1）から再開する。

### 絵と差分の生成

ステージ `s`（1〜5）の絵は、上記のシードから作った乱数で次の手順で作る。同じシードなら必ず同じ絵になること。乱数はテスト・再現のため外から注入できること。

0. **ステージ番号**: `s` は 1〜5 にクランプする（範囲外の入力は最寄りの端として扱う）。
1. **図形配置**: 図形数 `shapeCounts[s]` 個を作る。各図形は種類（円／四角／三角を等確率）、半径（`shapeSizeMin` 〜 `shapeSizeMax[s]` の一様分布）、位置、色（色相 0〜359 の一様、彩度 0.55〜0.9、明度 0.4〜0.6）を持つ。位置はパネル内で四辺から `shapeSizeMax[s] + 20` px 以上内側。既に置いた図形との中心間距離が `(r1 + r2) * overlapFactor` を超えること（超えない候補は捨てて再抽選）。重なりは許可する。再抽選は最大 4000 回まで。到達しなければ置けた分で打ち切ってよい。
2. **背景**: 背景色相 `bgHue`（0〜359）と、パネル内に `bgDots` 個の装飾の円（半径 8〜26、中心はパネル内。端で切れてよい。パネルの矩形でクリップする）を作る。装飾は左右の絵で同一で、差分の対象にならない。
3. **差分の選択**: 差分数 `diffCounts[s]` 個を、図形を乱順にした候補から順に決める。候補ごとに差分の種類（色・移動・サイズ・消失を等確率）を決め、その判定円（下記）を求め、既に決めた差分の判定円すべてと重ならない（中心間距離 > 半径の和）場合だけ採用する。重なる候補は捨てる。これにより、1つの丸の中に2つの差分が入らない。採用した差分数が足りなければ、絵全体の生成をやり直す（最大 50 回。それでも足りなければ得られた数で進める。HUD の差分数は実際の数を表示する）。
4. **差分の内容**（右の絵に反映）:
   - 色: 色相を `hueShift[s]` 度、ランダムに±どちらかへずらす。
   - 移動: 位置を `moveDist[s]` px、ランダムな向きにずらす。ずらした後も図形全体がパネル内に収まる向きだけを選ぶ（図形の配置余白により、収まる向きは必ず存在する）。
   - サイズ: 半径を `size * (1 ± scaleDelta[s])`（符号はランダム）にする。拡大でパネルからはみ出す場合は縮小側にする。
   - 消失: 右の絵からその図形を描かない。

**判定円**（クリック判定とマーク表示に使う円。パネル内座標）:

| 種類 | 中心 | 半径 |
|---|---|---|
| 色・消失 | 元の図形の中心 | `size + hitMargin` |
| 移動 | 元の中心と移動後の中心の中点 | `size + hitMargin + moveDist[s] / 2` |
| サイズ | 元の図形の中心 | `max(元のsize, 変更後のsize) + hitMargin` |

### 勝利・失敗・スコア

- **ステージクリア**: そのステージの差分をすべて発見する。
- **ゲーム勝利**: ステージ5をクリアする → `Result`（クリア）。
- **失敗**: いずれかのステージで残り時間が 0 になる → `Result`（ゲームオーバー）。ライフの概念はない。
- **ステージの持ち時間**: ステージごとに `timeLimits[s]` 秒から開始し、繰り越さない。プレイ中（`play`）のみ減る。何もしなければ時間切れになる。
- **スコア**: セット内でステージクリア時の残り秒（切り上げ整数）の合計。クリアしたステージだけが加算され、時間切れのステージは加算されない。セットごとに 0 から数え直す（セットをまたいで加算しない）。ステージクリア画面中に個別の表示はなく、`Result` で合計を表示する。

## MVP範囲

- 図形（円・四角・三角）で描く、シード付き乱数のランダム生成の絵（画像素材なし）。重なりを許可。
- 4種類の差分（色・移動・サイズ・消失）と、判定円が重ならない選び方。
- 全5ステージ、ステージ別の持ち時間・図形数・差分数・差分の大きさ。
- 誤クリックの時間減算とカメラシェイク。
- 横／縦レイアウトの切り替え。
- 日付とセット番号で決まる、固定シードの5ステージのセット（クリアで次のセット、時間切れで同じセットのやり直し）。
- Title・Game・Result の3 Scene。スコア（クリア時の残り時間の合計）の表示。
- 背景（画面とパネル）。
- ページ非表示（画面消灯・別アプリ・タブ切り替え）での自動一時停止と、復帰時の一時停止画面（タップで再開）。

## 非MVP範囲

ヒント機能、セット番号や日付をプレイヤーが選ぶ UI、ハイスコア・ランキング・クリア履歴などの永続化、サウンド、画像素材、エンドレスモード、レベルエディタ、手書きの固定ステージ、背景の差分（背景は差分にしない）、難易度選択、手動のポーズボタン・ポーズメニュー（ページ非表示時の自動一時停止は MVP に含む）、ステージごとのテーマ。

## 技術要件

- Phaser 4 + Vite + TypeScript。描画は Phaser の Graphics とテキストのみ（画像・音声アセットを使わない。スキャフォールドの未使用アセットは残さない）。
- 静的サイトとして `npm run build` と共有ビルドの両方で動作すること（AGENTS.md 4.3）。
- ESLint エラー 0、Vitest のカバレッジは文・分岐・関数・行すべて 90% 以上。
- Scene は `Title` / `Game` / `Result`。`preload`・`create`・`update` の責務を混在させない。`update` ではオブジェクトを生成しない。入力・リサイズのリスナーは Scene 終了時に後始末する。誤クリックの揺れは Phaser のカメラシェイクを使う（自前実装しない）。
- **純粋ロジック（Phaser 非依存で単体テスト可能にする）**:
  - 乱数（シード付き。注入可能）。
  - 絵の生成（図形配置・背景・差分の選択と内容・判定円・再生成）。
  - クリック判定（パネル内座標 → 当たった差分のインデックス or なし）。
  - 色変換（HSL → 数値色）。
  - 縦横レイアウトの計算（向き → キャンバスサイズ・パネル位置・HUD 位置）。
  - ステージ進行（持ち時間、誤クリック減算、時間切れ・クリア判定、スコア加算）。
  - 一時停止の状態機械（入る前の状態の記憶、時間カウンタの凍結、復帰時刻からのロック判定、再開）。時間・イベントは引数で渡せること。
- 時刻・乱数は注入する。Scene は描画・入力・タイマーの接続だけを担う。

## テスト観点

- **乱数**: 同じシードで同じ絵、異なるシードで異なる絵。
- **セットとシード**: 同じ `(d, n)` で5ステージすべてが何度生成しても完全に同一（図形・差分・背景）。`d` が違う、または `n` が違うと別の構成になる。`(d, n, s)` の入れ替え（例: `n=1,s=2` と `n=2,s=1`）で同じシードにならない。
- **セット進行**: クリアの再開で `n` が +1 で `d` は不変、時間切れの再開で `n` は不変。Title からの開始は `n=1`。スコアはセットごとに 0 から。
- **図形配置**: 図形数が `shapeCounts[s]`（打ち切りを除く）、すべてパネル内（四辺から `shapeSizeMax[s] + 20` 以上内側）、任意の2図形の中心間距離が `(r1+r2)*overlapFactor` を超える、半径が `shapeSizeMin`〜`shapeSizeMax[s]`。
- **差分**: 全ステージで差分数が `diffCounts[s]`（複数シードで）。判定円どうしが重ならない。右の絵と左の絵の差が、差分と一致する（色・位置・サイズ・消失の4種類それぞれで、差分でない図形は変化しない）。移動・サイズ変更後も図形全体がパネル内に収まる。背景の装飾は左右で同一。ステージ範囲外（0 や 6）の入力でも落ちない／クランプされる。
- **判定円**: 4種類それぞれの中心・半径が表のとおり。
- **クリック判定**: 円内で当たり、円の境界ぎりぎり（距離＝半径）は当たり、境界を超えると外れ。発見済みの差分は当たらない。差分が無い位置は外れ。
- **一時停止**: 非表示で `paused` に入り、復帰直後 `resumeInputLockMs` 未満の再開タップは無視、以降のタップで元の状態に戻る。`paused` 中に任意の時間が経過しても、残り時間と `clear`／`won`／`over` の待ち時間は変わらない（`play`・`clear`・`won`・`over` それぞれで、一時停止直前と再開直後で同じ値）。再開タップが誤クリック（時間減算）・当たりにならない。`paused` 中の非表示・表示の繰り返しで状態が壊れない（`resumeInputLockMs` は直近の `visible` から数える）。`paused` に入った時にカメラシェイクが止まる。非表示と同フレームで待ち時間が 0 以下になっても、`paused` 中は遷移せず再開後の最初の `update` で遷移する。`create` 時点で非表示なら `paused` から始まる。フォーカス喪失だけでは一時停止しない。
- **ステージ進行**: 誤クリックで `missPenalty` 秒減り、0 で下限、減算で 0 になれば時間切れ。最後の差分発見でクリア。時間が尽きたステージのスコアは加算されない。スコアはクリア時の残り秒（切り上げ）の合計。ステージ5クリアで勝利。
- **レイアウト**: 横・縦それぞれのキャンバスサイズ・パネル位置・パネルが画面内に収まる。向きの判定（幅＝高さは横）。
- **色変換**: 代表値（赤・緑・青・無彩色）の HSL → 数値色。
- **ステージ難度の単調性**: 各ステージの差分割合が `diffCounts[s] / shapeCounts[s]` で単調に下がる（25%→19%）。ステージが進むと `hueShift`・`moveDist`・`scaleDelta` が単調に小さくなる。

## 完了条件

- `npm run lint`・`npm run test`・`npm run test:coverage`（90% 以上）・`npm run build` がすべて成功する。共有ビルド（`task build`）でも起動する。
- Title → Game（5ステージ）→ Result → 再開、の流れを、クリア・ゲームオーバーの両方でブラウザ上で確認できる。
- 同じ日・同じセット番号は、ゲームオーバーからのやり直しやページの開き直しでも同じ絵になる。クリア後は次のセット番号で別の絵になる。
- 絵は `(日付, セット番号, ステージ)` ごとに違い、左右（上下）で差分を見つけられる。当たりで赤丸が両パネルに付く。誤クリックで残り時間が 5 秒減り、画面が揺れる（揺れはカメラシェイクが呼ばれることをテストで確認し、体感は目視で確認する）。
- 差分が重なる絵柄（図形の重なり）でも、1回の丸の中に差分が2つ入らない。
- 縦持ち（高さ > 幅）では2枚が上下に並び、横持ちでは左右に並ぶ。向きを変えてもプレイ中の状態が失われない。
- ステージが進むと、図形が増え、差分が小さく多くなる。ステージ進行のテンポ（クリア表示 900ms で次へ）が保たれている。
- ブラウザのタブ切り替え（スマホでは画面消灯・別アプリへの切り替え）で時間が止まり、戻ると一時停止画面（絵は見えない）が出て、タップで元の状態から再開する。止まっていた間は残り時間が減らない。`clear`／`over` の最中に一時停止しても、待ち時間が止まって再開後に続きから進む。
- 時間切れ時、未発見の差分が赤丸で開示され、1.5 秒後に Result へ進む。Result は表示直後の 0.5 秒は入力を受けない。
- `README.md` に目的・ルール・操作方法がある。`<title>` と favicon がこのゲーム固有のもの。
