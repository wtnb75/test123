# spotdiff: コードレビューで見送った指摘

`game-codereview` が、見送った指摘を理由つきで残すファイル（spec ではない）。レビュアーに渡して、同じ指摘を繰り返さないために使う。コードが無くなった行は削除する。

- `src/game/scenes/*`（Title・Result・Game のテキストのスタイル）: 3つの Scene で文字スタイルの組み立てが重複している — 理由: 各3行の記述で、共通化しても得が小さい（見た目の細部は実装裁量）
- `src/game/scenes/Game.ts`（誤クリック中のカメラシェイクと当たり判定）: シェイク中は描画が最大約4pxずれるのに、判定は元の座標で行う — 理由: 判定の余白（`hitMargin` 14px）に収まり、シェイクは120msだけ。判定は仕様どおり
- `src/game/logic/run.ts`（差分が0個のステージ）: 差分が0個だと、クリアできず詰む — 理由: 図形が1つでも置ければ最初の候補は必ず採用されるので、到達しない
- `src/game/logic/generate.ts`（図形が足りない時の再生成の目標数）: 図形が目標より少ないと、再生成を最大回数まで回す — 理由: 現行の数値では図形数が表どおりになる（テストで確認済み）。起きても、足りた分で進めるのが仕様
- `src/game/logic/generate.ts`（移動後の図形が別の図形の下に隠れる）: 見つけにくい移動の差分ができうる — 理由: 仕様は「パネル内に収まること」までで、バグではない。難しさの調整は `game-balance` の話
- `src/game/logic/generate.ts`（形の変更の見分けやすさ）: 最小サイズでは円・四角・三角の違いが小さい — 理由: 見え方とバランスの問題で、バグではない
- `src/game/scenes/Game.ts`（`onHidden`）: `hide()` が false でも一時停止画面を再表示する — 理由: false になるのは、すでに `paused` のときだけで、再表示は無害
- `src/game/logic/layout.ts`（`toPanelLocal` / `toCanvas`）: 本番コードが使っていない — 理由: 座標変換の仕様を表す小さな関数で、テストが使っている。削るとテストを組み替えるだけで、得が小さい
- `src/game/scenes/Game.ts`（`frames` と `layout` の二重管理）: パネルの位置情報が二重になっている — 理由: 更新するのは `relayout` の1か所だけで、食い違う経路はない
- `src/game/scenes/Game.ts`（演出の状態がシーンの中にある）: 一時停止での演出の取り消しがテストできない — 理由: Phaser 側の部品で、QA で画面を確認している（古いフラグは害がなく、取り消しで消している）
- `src/game/scenes/Title.ts` / `Result.ts` ほか（位置や 0.6 などの数字の直書き）: 数字がコードに直書き — 理由: 0.6 は仕様の式（0.6D）、Title と Result の位置は見た目の細部で実装裁量
- `src/game/logic/generate.ts`（形の変更の候補の配列）: 形の差分の候補ごとに小さな配列を作る — 理由: 毎フレームではなくステージ生成時だけで、2要素。影響なし
- `src/game/logic/generate.test.ts`（同じ300セットを複数のテストで生成）: 同じコーパスを何度も作る — 理由: テスト全体が約1秒で、各テストの独立性と読みやすさを取る
- `docs/spec.md`（frontmatter の `status_*` の巻き戻し）: 公開済みなのに下流の段階が戻っている — 理由: 拡張のたびに下流を戻すのがワークフローの決まりで、公開の段階で `done` に戻る
- `src/game/logic/generate.ts`（乱数の流れの変化）: 差分の種類を足すと、同じ日・同じセット番号でも更新前後で絵が変わる — 理由: spec に明記した意図した変更。同じバージョンの中では同じ絵になる
- `docs/spec.md`（回帰条件の書き方）: 変えない種類の一覧に「消失」が無いように読める — 理由: テスト観点の回帰条件にも、完了条件にも、「消失（消えている）」は含まれている
- `src/game/logic/generate.ts`（`Proposal.hideLeft`、`Stage` の `shapes`・`left`・`right` の3つの配列）: 左を隠すフラグの形と、並行する配列の重複 — 理由: 差分の種類が1つのうちは動作に問題がなく、`left` が空になりうることは spec に書いてある。左だけを変える差分が増えたときに整理する
- `src/game/logic/generate.test.ts`（参照の同一性）: 増加の右の図形や、左の図形が `shapes` の参照そのものか確かめていない — 理由: 内容の同一性を確かめれば足り、参照の共有を禁じるのは実装の細部に縛りすぎ
- `src/game/logic/generate.test.ts`（種類の割合の範囲 8〜25%）: 実測（14〜18%）より緩い — 理由: 範囲は spec で合意した値。厳しくするなら先に spec を改訂する
- `src/game/logic/generate.test.ts`（空になる位置の直接確認）: 増加・消失の位置にだけ空があることを、描かれた数とは別に確かめていない — 理由: 差分でない図形の左右が元と同じことを、1つずつ確かめるテストがあり、違う位置を空にすると、そこで検出される（変異で確認済み）
- `src/game/logic/generate.test.ts`（シード300）: テストが約2.5倍になる — 理由: テスト全体が約1秒で、稀なケース（拡大がパネルをはみ出す場合など）の網羅が優先
- `docs/backlog.md`（実測値の丸め）: 合計が99%で、内訳が分からない — 理由: 目安の数字。範囲を厳しくする時に測り直す
