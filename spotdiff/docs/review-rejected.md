# spotdiff: コードレビューで見送った指摘

`game-codereview` が、見送った指摘を理由つきで残すファイル（spec ではない）。レビュアーに渡して、同じ指摘を繰り返さないために使う。コードが無くなった行は削除する。

- `src/game/scenes/*`（Title・Result・Game のテキストのスタイル）: 3つの Scene で文字スタイルの組み立てが重複している — 理由: 各3行の記述で、共通化しても得が小さい（見た目の細部は実装裁量）
- `src/game/scenes/Game.ts`（誤クリック中のカメラシェイクと当たり判定）: シェイク中は描画が最大約4pxずれるのに、判定は元の座標で行う — 理由: 判定の余白（`hitMargin` 14px）に収まり、シェイクは120msだけ。判定は仕様どおり
- `src/game/logic/run.ts`（差分が0個のステージ）: 差分が0個だと、クリアできず詰む — 理由: 図形が1つでも置ければ最初の候補は必ず採用されるので、到達しない
- `src/game/logic/generate.ts`（図形が足りない時の再生成の目標数）: 図形が目標より少ないと、再生成を最大回数まで回す — 理由: 現行の数値では図形数が表どおりになる（テストで確認済み）。起きても、足りた分で進めるのが仕様
- `src/game/logic/generate.ts`（移動後の図形が別の図形の下に隠れる）: 見つけにくい移動の差分ができうる — 理由: 仕様は「パネル内に収まること」までで、バグではない。難しさの調整は `game-balance` の話
- `src/game/logic/generate.ts`（形の変更の見分けやすさ）: 最小サイズでは円・四角・三角の違いが小さい — 理由: 見え方とバランスの問題で、バグではない
- `src/game/scenes/Game.ts`（`onHidden`）: `hide()` が false でも一時停止画面を再表示する — 理由: false になるのは、すでに `paused` のときだけで、再表示は無害
- `src/game/logic/layout.ts`（`toPanelLocal` / `toCanvas`）: 本番コードが使っていない — 理由: 座標変換の仕様を表す小さな関数で、テストが使っている。削るとテストを組み替えるだけで、得が小さい
- `src/game/scenes/Game.ts`（`frames` と `layout` の二重管理）: パネルの位置情報が二重になっている — 理由: 更新するのは `relayout` の1か所だけで、食い違う経路はない
- `src/game/scenes/Game.ts`（演出の状態がシーンの中にある）: 一時停止での演出の取り消しがテストできない — 理由: Phaser 側の部品で、QA で画面を確認している（古いフラグは害がなく、取り消しで消している）
- `src/game/scenes/Title.ts` / `Result.ts` ほか（位置や 0.6 などの数字の直書き）: 数字がコードに直書き — 理由: 0.6 は仕様の式（0.6D）、Title と Result の位置は見た目の細部で実装裁量
- `src/game/logic/generate.ts`（形の変更の候補の配列）: 形の差分の候補ごとに小さな配列を作る — 理由: 毎フレームではなくステージ生成時だけで、2要素。影響なし
- `src/game/logic/generate.test.ts`（同じ300セットを複数のテストで生成）: 同じコーパスを何度も作る — 理由: テスト全体が約1秒で、各テストの独立性と読みやすさを取る
- `docs/spec.md`（frontmatter の `status_*` の巻き戻し）: 公開済みなのに下流の段階が戻っている — 理由: 拡張のたびに下流を戻すのがワークフローの決まりで、公開の段階で `done` に戻る
- `src/game/logic/generate.ts`（乱数の流れの変化）: 差分の種類を足すと、同じ日・同じセット番号でも更新前後で絵が変わる — 理由: spec に明記した意図した変更。同じバージョンの中では同じ絵になる
- `docs/spec.md`（回帰条件の書き方）: 変えない種類の一覧に「消失」が無いように読める — 理由: テスト観点の回帰条件にも、完了条件にも、「消失（消えている）」は含まれている
- `src/game/logic/generate.ts`（`Proposal.hideLeft`、`Stage` の `shapes`・`left`・`right` の3つの配列）: 左を隠すフラグの形と、並行する配列の重複 — 理由: 差分の種類が1つのうちは動作に問題がなく、`left` が空になりうることは spec に書いてある。左だけを変える差分が増えたときに整理する
- `src/game/logic/generate.test.ts`（参照の同一性）: 増加の右の図形や、左の図形が `shapes` の参照そのものか確かめていない — 理由: 内容の同一性を確かめれば足り、参照の共有を禁じるのは実装の細部に縛りすぎ
- `src/game/logic/generate.test.ts`（種類の割合の範囲 8〜25%）: 実測（14〜18%）より緩い — 理由: 範囲は spec で合意した値。厳しくするなら先に spec を改訂する
- `src/game/logic/generate.test.ts`（空になる位置の直接確認）: 増加・消失の位置にだけ空があることを、描かれた数とは別に確かめていない — 理由: 差分でない図形の左右が元と同じことを、1つずつ確かめるテストがあり、違う位置を空にすると、そこで検出される（変異で確認済み）
- `src/game/logic/generate.test.ts`（シード300）: テストが約2.5倍になる — 理由: テスト全体が約1秒で、稀なケース（拡大がパネルをはみ出す場合など）の網羅が優先
- `docs/backlog.md`（実測値の丸め）: 合計が99%で、内訳が分からない — 理由: 目安の数字。範囲を厳しくする時に測り直す
- `src/game/scenes/Game.ts`（横長で上端付近の誤クリックの「-5」が、初回ヒントの行に重なる）: パネル上端と行の間が狭い — 理由: 初回ヒントが出ている間にパネル上端を外した場合だけで、縦レイアウトでも同程度。「-5」は手前に描かれ読める
- `src/game/logic/layout.ts`（`sideBySide` の `wide` 分岐、`bigText` が `kind` から導ける）: 重複した分岐 — 理由: 種類が3つのうちは今の書き方のほうが読みやすく、動作に問題はない
- `src/game/scenes/orientation.ts`（3値の切り替えのテストとヒステリシス）: 1.6 付近のリサイズで切り替わりが続く — 理由: spec が「切り替わるが状態は引き継ぐ」と明記。Scene は単体テスト対象外で、QA で向きを変えて確認する
- `src/game/logic/layout.ts`（16:9 の PC も横長になる）: スマホ向けレイアウトが PC に出る — 理由: 意図した変更で、spec に明記しユーザーが確認済み
- `src/game/scenes/orientation.ts`（JSDoc の長さ、`kind` の名前）: 見た目だけの指摘 — 理由: 動作に影響しない
- `src/game/scenes/Title.ts`（ボットのタップのフレームで、印と輪を 2 回描き直す）: 出力が同じ描画が 2 回走る — 理由: 700 ms に 1 回の 1 フレームだけ。直すと「どこで描くか」が暗黙になる
- `shared/title-demo/src/director.ts`（`state`・`phase`・`rounds` が外から代入できる。README は `readonly`）: 契約と実装の食い違い — 理由: Scene は代入しない。内部で更新するので `readonly` には getter と private への作り直しが要る。README は契約の記述
- `src/game/logic/titleLayout.ts`（Game のレイアウトを作り直して 3 つの値だけ使い、中央寄せの式を重複している）: — 理由: 向きの変更のときだけ呼ばれる純粋関数で、式は 1 行。共通化の見返りが小さい
- リポジトリ（1 PR に spotdiff・pushline・共有パッケージ・AGENTS.md・Taskfile が混ざる）: 1 ゲーム 1 PR に反する — 理由: 共有パッケージを同時に作る方針をユーザーが選んで合意済み。完了条件にも pushline のテストを通すことを書いている
- `src/game/logic/titleDemo.ts`（判定円が重なるとボットの手順が古くなり、再計画が続く恐れ）: 重なる判定円では手順が崩れる — 理由: spec が「判定円どうしが重ならない」と定め、生成のテストで確認済み。差分の中心は必ず自分の円の中にある
- `src/game/storage.test.ts`（共有パッケージを含む glob が長い 1 行で、`../../../` に依存する）: — 理由: 取りこぼすと `toContain` の検査が大きな声で失敗する。lint・型は通っている
- `shared/title-demo/src/director.ts`（`fadeMs` が NaN のときの扱い）: 検証が無い — 理由: 設定値の書き間違いだけで起き、揃った動き（すぐ終わる）になる
- `pushline/src/game/logic/demo.ts`（アダプタが `advance` を null にする）: 将来 `advance` を足すと再描画されない — 理由: pushline に `advance` は無い。コメントで明記している
- `src/game/scenes/draw.ts`（星・十字の凹多角形を `fillPath` で塗る）: 描画器によって塗りが崩れる恐れ — 理由: コードの誤りの指摘ではなく実描画の確認の話。QA で実ブラウザの星・十字を確認する（完了条件にある）
- `src/game/logic/generate.ts`（`SHAPE_KIND_ORDER` が PARAMS の外にある、種類の列が複数箇所）: spec の `shapeKindOrder` との置き場所のずれ — 理由: 動作に問題なし。種類の数・並びは `kindsAt` のテストで固定している
- `src/game/logic/generate.ts`（`kindsAt` を何度も呼んで小さな配列を作る）: 同じ配列の作り直し — 理由: 生成時だけの小さな配列で、同種の指摘は見送り済み
- `src/game/scenes/draw.ts`（多角形の再描画のたびに頂点の配列とクロージャを作る）: 割り当て — 理由: 再描画は状態変化のときだけで、最大 72 図形。既存の描画の作りと同じで実害なし
- `src/game/logic/titleDemo.ts`（`botPlan` の既定の `Set` を毎回作る）: 無駄な割り当て — 理由: 本番の呼び出しは常に `found` を渡す。無視できる量
- `src/game/scenes/Help.ts`（作成時の文字サイズのリテラル、促し文の 36）: params と二重 — 理由: 見出し・説明・種類名は `place()` が上書きする。促し文の 36 は Title の "TAP TO START" と同じ書き方
- `src/game/scenes/Help.ts`（`shutdown` での `input.off` が冗長）: Phaser が後始末する — 理由: `Result.ts` と同じパターンで無害。早い入力を無視するため `input.once` は使えない
- `src/game/scenes/Help.ts`（開発ビルドの `__qa` の形が Title 用の QA スクリプトと違う）: — 理由: 開発ビルド専用で本番に含まれない。Help 用のシナリオは `scene: 'Help'` を見て読める
- `src/game/scenes/Game.ts`（HUD の文字が、縦の狭い画面（SE 縦）で CSS 14 px を下回る）: 主な情報の 14 px の規則に届かない — 理由: HUD の文字は既存の規定（キャンバス上で 32 px 以上）のまま、横長の 16 CSS px 規定だけ HUD を例外とすると、ユーザーが決めた（HINT の拡張の承認時）。HUD の大きさを変えるなら spec で決める
