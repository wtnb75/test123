# shoot1 ゲーム仕様

## ゲーム名

**shoot1** ― 弾幕回避シューティング（仮称）

## コンセプト

画面下部の自機を操作し、上から降り注ぐ敵弾を避け続ける。
地雷を設置して敵機が地雷に当たると、敵機と敵弾を爆破で巻き込める。ただし自分が踏んでも爆発する。どれだけ長く生き残れるかを競う。

## ターゲットプレイヤー

- ブラウザゲームを手軽に遊びたいプレイヤー
- 弾幕系シューティングに親しみのあるプレイヤー

## コアループ

1. 自機をキーボードで上下左右に動かす
2. 敵弾が当たる前に避け続ける
3. 地雷を設置して、敵機が触れるか時間経過で爆発・周囲の弾を巻き込んで消去
4. 地雷に自分が触れる、または爆風範囲に入るとゲームオーバー（扱い注意）
5. 被弾またはミス踏みでゲームオーバー → スコア表示 → リスタート

## 操作仕様

### キーボード（PC）

| 操作 | 方法 |
|------|------|
| 移動 | 矢印キー（上下左右）または WASD |
| 地雷設置 | スペースキー／Z キー（自機の現在位置に設置） |
| リスタート | ゲームオーバー画面で R キーまたはクリック |

### 仮想コントローラ（スマートフォン・タッチデバイス）

| 操作 | 方法 |
|------|------|
| 移動 | 画面左下に表示される仮想スティック（8方向） |
| 地雷設置 | 画面右下に表示される仮想ボタン（BOMB） |
| リスタート | ゲームオーバー画面をタップ |

- 仮想コントローラはタッチデバイス検出時に自動表示する
- PC ではデフォルト非表示（キーボード操作優先）
- 仮想スティックはマルチタッチ対応（スティック操作中にボタンタップ可能）

| Scene | 役割 |
|-------|------|
| `Boot` | アセット読み込み |
| `Game` | メインゲームプレイ |
| `GameOver` | スコア表示・リスタート |

### 背景・機体の見た目（レトロ調）

見た目だけの仕様。ルール・当たり判定・難易度の時間割は変えない。描画は `Graphics` と図形から作ったテクスチャで行い、外部画像は使わない。

- **背景の層**: 下地（全面の単色）→ 走査線（横線）→ 流れる星、の順。3 つとも、敵機・敵弾・地雷・自機・HUD より下に描く（depth −10 と −9）
- **下地色の段階**: 難易度の時間割と同じ 6 段階の境界で、下地色を切り替える（色はパラメータ表）。切り替えはなめらかにせず、その瞬間に変える
- **走査線**: `BG_SCANLINE_GAP` ごとに、画面の全幅へ細い横線を `BG_SCANLINE_ALPHA` の透明度で引く。1 回だけ描いてテクスチャを使い回し、毎フレームは描き直さない
- **流れる星**: `BG_STAR_COUNT` 個の小さな点を、それぞれ `BG_STAR_SPEED_MIN`〜`BG_STAR_SPEED_MAX` の速さで下へ流す。画面の下端を越えた星は上端の外から出し直す。星の数と初期位置は起動時に作り、毎フレームは位置の更新だけ行う（オブジェクトを生成しない）。リスタートでは配置を作り直してよい
- **自機**: 頂点が上の三角形。頂点は、中心から当たり半径 `PLAYER_RADIUS`（12）以内の距離に収める。色は従来の水色。当たり判定は従来どおり半径 12 の円
- **敵機**: 頂点が上下左右の菱形。頂点は、中心から当たり半径 `ENEMY_RADIUS`（14）の距離にする。色は従来の赤。当たり判定は従来どおり半径 14 の円
- **形と判定の差（許容）**: 当たり判定は円のまま。菱形の角と三角形の頂点より外側の円の部分に当たっても、見た目は当たっていない。これは仕様として許容する
- 自機と敵機の形・色は、段階によらず全段階で同じ

## 敵機パターン

編隊型を中心に構成する。時間経過でパターンが切り替わり難易度が上がる。

下の表の「弾種」列は編隊の代表的な弾の目安で、実際に撃つ弾は編隊の形に結びつかない。1 発ごとに、その時点の段階の弾種から選ぶ（「弾パターンの難易度スケール」が正）。

| パターン名 | 動き | 弾種 | 出現タイミング |
|-----------|------|------|--------------|
| **横一列編隊** | 3〜5機（機数は下のパラメータ表の時間割に従う）が横並びで直下降下 | 直下弾 | 0秒から（常時） |
| **V字編隊** | V字フォーメーションで降下 | 自機狙い弾 | 10秒以降（序盤の2段階目から） |
| **くの字編隊** | 斜めに整列して斜め降下 | 直下弾 + N-way弾 | 中盤 |
| **波状編隊** | 横一列がsin波で揺れながら降下 | 全方位弾 | 中盤〜終盤 |
| **包囲編隊** | 画面両サイドから挟み込む形で進入 | 自機狙い弾 | 終盤 |

単体で出る敵（突進する敵・停止して撃つ敵）は、この表の編隊とは別に、30 秒以降に出る。詳細は [敵の種類](spec/enemy-kinds.md) を参照。

### 敵機の共通仕様

- 編隊は画面上部から出現する。**最初の編隊はゲーム開始と同時（経過 0 秒の最初の更新フレーム）に出る**。以降の間隔は経過時間の段階で決まる（`FORMATION_INTERVAL_EARLY_SEC` / `FORMATION_INTERVAL_SEC`、パラメータ表）
- 編隊の形は出現の瞬間の経過時間で決まる（0〜10秒は横一列のみ、10秒以降は横一列・V字を 1/2 ずつ。中心 x の決め方は従来どおり）
- 編隊内の各機は一定間隔で弾を撃ち、画面外に出ると消える
- 難易度は時間経過で段階的に上昇（弾速・弾数・編隊サイズを増加）
- 自機の弾による撃破は MVP 外（地雷での撃破のみ）

## 敵弾パターン

| パターン名 | 内容 | 登場タイミング |
|-----------|------|--------------|
| **直下弾** | 真下に一定速度で落下 | 0秒から |
| **自機狙い弾** | 発射時点の自機方向へ飛ぶ | 10秒から |
| **3-way弾** | 自機狙い方向を中心に3方向扇形 | 20秒から |
| **5-way弾** | 自機狙い方向を中心に5方向扇形 | 終盤から |
| **全方位弾** | 360度均等に8方向拡散 | 中盤から |
| **渦巻き弾** | 時間差で角度をずらしながら連射（渦巻き状） | 終盤から |
| **高速弾** | 2〜3倍速の直下弾（少量） | 中盤から |

### 弾パターンの難易度スケール

- **0〜10秒**: 直下弾のみ、低速。横一列編隊のみ
- **10〜20秒**: 直下弾・自機狙い弾、低速。V字編隊が加わる
- **20〜30秒**: 直下弾・自機狙い弾・3-way弾、低速
- **30〜60秒**: 3-way弾・全方位弾が混入、やや高速化
- **60〜120秒**: 5-way弾・渦巻き弾・高速弾が出現
- **120秒以降**: 全パターンが混在、弾速・密度が最大

段階の境界は「経過時間 ≧ 境界」で次の段階（10秒ちょうどは 2 段階目）。敵 1 機が 1 発撃つたびに、その瞬間の段階の弾種から 1 つを等確率で選ぶ（編隊の形が弾種を決めるわけではない）。撃つ間隔は、撃った瞬間の段階の `fireIntervalSec` に 0〜0.3 秒のランダムを足したもの。各段階の値は下のパラメータ表。上の表の「登場タイミング」とこの節が食い違うときは、この節とパラメータ表の時間割が正。

従来の実装値を維持するもの（今回は変えない）:

- 自機狙い弾・N-way 弾・全方位弾の速度はその段階の弾速、高速弾は弾速の 2 倍の直下弾。
- 3-way / 5-way の扇の総角度は π/5 ラジアン（自機狙い方向を中心に等間隔）。
- 敵の最初の発射までの時間は、出現から 0.5〜1.0 秒のランダム。画面上端の外（y < 0）にいる間も撃つ。
- 弾は画面の外 20 px を超えたら消える。敵機は画面下端の外 40 px を超えたら消える。

## ルール

- **失敗条件**: 敵弾が自機に当たる、自機が地雷に触れる／爆風範囲に入る、または突進する敵が自機に触れる（いずれも1回でゲームオーバー。突進する敵は [敵の種類](spec/enemy-kinds.md) を参照。バリアを持っているときは、これらを 1 回だけ防げる。[アイテム](spec/power-ups.md) を参照）
- **スコア条件**: 生存時間をスコア（秒×10）とする
- **地雷**:（以降の「ゲームオーバー」は、バリアを持っていないときの規則。バリアがあるときは [アイテム](spec/power-ups.md) の規則が優先する）
  - ゲーム開始時に 3 発所持（残弾数を HUD 表示）
  - スペース／Z キーで自機の現在位置に設置
  - **当たり判定の対象は敵機のみ**（敵弾には反応しない）
  - 敵機が地雷に触れると爆発し、爆発半径内の全敵機・全敵弾を消去する
  - 自機が爆発半径内にいる場合はゲームオーバー
  - 自機が地雷に触れると即ゲームオーバー
  - **設置直後は自機との当たり判定を一定時間（0.5秒）無効化**し、置いた瞬間に自爆しないようにする
  - 敵機が来なくても、設置から一定時間（10秒）後に自動で爆発する（巻き込み効果あり）
  - **連鎖爆発**: 爆発半径内に別の地雷がある場合、その地雷も誘爆する
    - 誘爆した地雷の爆発半径は **1.5倍**（連鎖回数が増えるたびにさらに 1.5倍ずつ累積）
    - 連鎖爆発も通常爆発と同様に敵機・敵弾を消去し、自機が爆風内ならゲームオーバー
    - 連鎖爆発は再帰的に処理する（誘爆した爆発がさらに別の地雷を誘爆できる）
    - 無限ループ防止のため、すでに爆発処理済みの地雷は再処理しない

## 技術要件

- フレームワーク: Phaser 4.x（TypeScript）
- ビルド: Vite
- lint: ESLint（エラー0件）
- テスト: Vitest（カバレッジ90%以上）
- アセット: 図形描画（`Graphics`）で代替し、外部画像なしで動作させる
- アイテム（落とす判定・落下・取る判定・地雷 +1 の残弾・バリアの状態遷移・HUD の MINE の文字列・猶予の点滅）は純関数として切り出してテストする（[アイテム](spec/power-ups.md)）
- 純関数として切り出してテストするもの（Phaser 非依存）: 弾種 → 見た目の形の対応と描く向きの角度、縮むカウントダウン輪の半径（経過秒 → 半径または非表示）、爆風の警告輪を出すかの判定（`circlesOverlap` と同じ式）。描画（`Graphics`・テクスチャ・tween）は Scene の接着部分
- 背景の段階色・星の位置の更新・機体の頂点の距離は、純関数として切り出してテストする（描画は Scene の接着部分）
- 敵機と敵弾の状態と更新は、Phaser に依存しない純粋なモジュール（`src/game/core/`）に切り出してテストする。挙動は変えない。範囲は、編隊と単体の敵の出現（位置・初速・最初の発射までの時間）、撃つ間隔の進行と弾種の選択、弾種ごとの発射（弾の位置と速度）、敵機と弾の移動、停止する敵の降下・停止・上昇、画面外での削除
  - core の状態は描画物（`Graphics`・`Image`）を持たず、敵機と弾のそれぞれに id を振る。1 回の更新は、出現した敵機・弾と消えた敵機・弾の id を返す。Scene は返された id に従って描画物を作る・壊す・位置を合わせるだけにする（出現と削除の計算を Scene に持たない）
  - 爆発で敵機・弾を消すときは、core の削除関数（地雷の core が呼ぶ。次の「地雷の core」）で消す。残った敵機・弾の並び順は変えない。アイテム・敵弾と自機の当たり判定・バリアは Scene に残す（範囲外）
  - 乱数は `rand: () => number`（`[0, 1)`）を注入する。`Math.random` を呼ぶ順番と回数は従来と同じにする（次の項）
  - 乱数の呼び出し順（従来のまま）: 編隊の出現は、形の選択に 1 回（経過 0〜10 秒でも呼ぶ）→ 中心 x に 1 回（`floor(r × (GAME_WIDTH − 160 + 1)) + 80`。従来の `Phaser.Math.Between(80, GAME_WIDTH - 80)` と同じ）→ 機ごとに最初の発射までの時間に 1 回（`0.5 + r × 0.5`。編隊の機の並び順）。単体の敵の出現は x に 1 回。停止する敵が停止に入った更新は、最初の発射までの時間に 1 回（`r × 0.3`）。撃つときは、次の間隔に 1 回（`fireIntervalSec + r × 0.3`）→ 弾種の選択に 1 回（`floor(r × その段階の弾種の数)`）の順。弾の発射では乱数を呼ばない
  - 1 回の更新の順（従来のまま）: 段階の決定 → 編隊の出現 → 単体の敵の出現 → 敵機ごとの移動と発射（敵機の並び順。この更新で撃った弾も、同じ更新の弾の移動に含む）→ 画面外の敵機の削除 → 弾の移動 → 画面外の弾の削除。突進する敵が自機に触れる判定は、その敵機の移動の直後に Scene が行う。それでゲームオーバーになった更新では、並びが後ろの敵機は動かず・撃たず、弾も動かない（従来のまま）。そのため core は、敵機ごとの移動の直後に Scene へ処理を渡せる形にする。中断した更新でも、そこまでに出現した敵機・弾（この更新で先に撃った弾を含む）は Scene に通知し、描画物を作る（弾は出現位置のまま、ゲームオーバーの演出の間、画面に残る）。中断した更新では、画面外の削除と弾の移動は走らず、削除の通知も出ない
  - core の 1 回の更新は、`dt`・経過秒（段階の決定に使う）・その更新で移動したあとの自機位置を受け取る（突進の向きと狙い弾・N-way 弾の向きは、この自機位置から決める）。編隊の出現と単体の敵の出現は、1 回の更新につき各 1 回まで。この更新で出た敵機も、同じ更新の「敵機ごとの移動と発射」に含む
  - 開発用の `window.__qa` の形（`enemies` は kind・x・y、`bullets` は数）は変えない（`game-qa` のシナリオが読む。`scene` 経由で敵機・弾の内部の形を読むものは保証しない）。編隊タイマーと単体の出現数は core が持ち、リスタートで初期に戻す
- 地雷の更新と爆発の解決は、Phaser に依存しない純粋なモジュール（`src/game/core/`。「地雷の core」）に切り出してテストする。挙動は変えない（ルールの節の地雷の規則・[アイテム](spec/power-ups.md) の規則・数値のとおり。以下は、その規則を「どの順で解くか」を従来の `Game.ts` のとおりに固定するもの）
  - 状態: 地雷のリスト（地雷ごとに id・x・y・経過秒 `age`。描画物は持たない）。id は重複しない。リスタートで空に戻し、id も初期に戻す。地雷の残弾数（`MineState`）は従来どおり別（Scene が持つ）。`window.__qa` の `mines`（x・y・age）の形は変えない
  - 1 回の更新は、`dt`・その更新で移動したあとの自機位置・敵機と敵弾の core の状態（`stepField` のあと）を受け取り、次の順で解く。**地雷の更新で乱数は呼ばない**
    1. 更新の最初の地雷リストの並びで、1 つずつ見る。すでにこの更新の爆発で除かれた地雷は飛ばし、`age` も進めない
    2. `age` に `dt` を足す。`age` が `MINE_TIMEOUT_SEC` 以上なら「爆発予定」に加え、その地雷についてはこれ以上調べない（3・4 を飛ばす。ちょうど 10 秒で爆発）
    3. そうでなければ、敵機のどれか（その時点の敵機リスト。1 機でも）が、地雷と `circlesOverlap`（地雷 `MINE_RADIUS`・敵機 `ENEMY_RADIUS`。中心間距離が 26 未満で重なる）なら「爆発予定」に加える（1 つの地雷につき 1 回）。この判定のあとも 4 を続ける
    4. `age` が `MINE_PLACE_GRACE_SEC` を**超え**（ちょうど 0.5 秒は無効）、Scene が「自機の接触は有効」と答え（バリアの猶予中は無効。地雷ごとに、その時点の状態で問い合わせる）、地雷と自機が `circlesOverlap`（`MINE_RADIUS`・`PLAYER_RADIUS`）なら、その地雷から**接触の爆発**をただちに解く（下記。**新しい処理済み集合**・連鎖回数 0。他の地雷の爆発予定とは集合を共有しない）。結果を Scene に渡し、Scene が「ゲームオーバー（中断）」と答えたらこの更新をここで止める（残りの地雷は `age` を進めず、爆発予定も解かない）。そうでなければ（バリアが防いだ）次の地雷へ続ける。接触の爆発の「自機への爆風」の結果は、ここでは見ない（接触の失敗として Scene が扱う）
    5. すべての地雷を見たら、「爆発予定」を加えた順に、**1 つの処理済み集合を共有して**解く。すでに除かれた地雷（4 の接触の爆発やその連鎖で除かれたもの）と処理済みの地雷は飛ばす。まとめた結果を Scene に渡し、その中に自機への爆風が 1 つでもあれば、Scene が失敗の原因を「爆風」として扱う（バリアで防ぐ規則は従来どおり Scene と [アイテム](spec/power-ups.md)）
  - 1 つの爆発の解き方（地雷・処理済み集合・連鎖回数）:
    1. 処理済みなら何もしない。そうでなければ処理済みに加える
    2. 半径 = `MINE_EXPLODE_RADIUS` × `MINE_CHAIN_RADIUS_MULTIPLIER`^連鎖回数（0 回で 120、1 回で 180、2 回で 270、3 回で 405）
    3. その地雷をリストから除く
    4. 連鎖の対象を、**このあとの掃き出しより先に**集める。リストに残る、処理済みでない地雷のうち、爆心からの中心間距離が半径**以下**のもの（ちょうど半径は誘爆する）をリストの並びで
    5. 敵機のうち、中心間距離が半径**以下**のものを、敵機リストの並びで消す。消えた敵機の id と座標を、その並びで結果に含める（Scene が、この並びでアイテムを抽選する）。敵弾も同じ（弾の id）。残りの並びは変えない
    6. 自機への爆風: 爆心と自機が `circlesOverlap`（爆風の半径・`PLAYER_RADIUS`。中心間距離が半径 + 12 **未満**）なら「自機に当たる」
    7. 4 で集めた対象を、集めた並びで、連鎖回数 + 1 で順に解く（深さ優先）。解く直前に処理済みになっていた地雷は飛ばす（先の連鎖が先に誘爆したもの。例: 爆心 A の対象に B と C がいて、B の連鎖が C を誘爆したら、C は連鎖回数 2 で 1 回だけ爆発する）
    8. 結果は、この爆発 → その連鎖（深さ優先、前順）の順に並べて返す。1 つの結果は、地雷の id・位置・半径・連鎖回数・消えた敵機（id と座標）・消えた弾の id・自機に当たったか
  - Scene は、結果を受け取った順に次の処理だけを行う: 地雷の描画物と輪の破棄、地雷の残弾の補充（爆発した地雷 1 つにつき 1）、消えた敵機・弾の描画物の破棄、消えた敵機ごとのアイテムの抽選（`Math.random` の呼び出しの順と回数は従来のまま。結果の並び・敵機の並びの順）、爆発の円とカメラシェイク（色・遅れ・強度は連鎖回数で決まる従来のまま）。そのあとで失敗の扱い（バリア・ゲームオーバー）を行う。地雷の点滅・輪・設置の描画物は Scene が id で持つ。爆発で除かれなかった地雷の点滅と輪の更新は、core の更新のあとに Scene が行う（ゲームオーバーで中断した更新では行わない。時間切れで爆発予定になった地雷は、その更新では点滅・輪を更新しない）
  - 地雷の設置の規則（残弾・重ね置きの禁止）は変えない。地雷のリストへの追加は core の関数で行う（置き場所は実装裁量）
- ゲーム状態はシーン内のプロパティで管理し、グローバル汚染しない
- 物理エンジン: Phaser 4 の Arcade Physics（利用可能であることを確認済み）
- 仮想コントローラ: **VirtualJoystick プラグインは Phaser 4 非対応のため使用しない**
  - `Phaser.GameObjects.Ellipse` + `Phaser.Geom.Circle` + `Pointer` イベントで自前実装する（first-game の実装を参照）
  - 独立した UI Scene として重ねる
- レイアウト: `Scale.FIT` + `CENTER_BOTH` でスマートフォン縦横両対応

## ゲーム画面内の地雷ビジュアル仕様

- 地雷は黄色の円で表示（`Graphics`）
- 設置後7秒まで: 通常表示
- 残り3秒から: 点滅（点滅スピードが上がり緊迫感を表現）
- 同じ座標への重ね置きは禁止（地雷がすでにある場合は設置操作を無視）

地雷には、本体のほかに次の 3 つの輪（`Graphics` / 円。外部画像なし）を付ける。当たり判定・爆発の規則は変えない（見た目だけ）。

| 輪 | 出る条件 | 見た目 |
|----|----------|--------|
| 設置の波紋 | 地雷の設置に成功した瞬間（重ね置きで無視された操作では出さない） | 地雷の位置に、半径 `MINE_RIPPLE_START_RADIUS` から `MINE_RIPPLE_END_RADIUS` まで `MINE_RIPPLE_SEC` 秒で広がりながら、透明度 `MINE_RIPPLE_ALPHA` から 0 へ消える輪（線のみ・黄色系）。半径と透明度は直線的に変える。更新の経過時間で動かす（tween は使わない）。`MINE_RIPPLE_SEC` 経つか、その地雷が爆発で除かれた瞬間に破棄 |
| 縮むカウントダウン輪 | その地雷の残り時間（`MINE_TIMEOUT_SEC` − 経過）が `MINE_BLINK_SEC` 以下の間（点滅の開始と同じ瞬間から） | 地雷の位置に、半径が `MINE_EXPLODE_RADIUS` から `MINE_RADIUS` へ、残り時間に比例して直線的に縮む輪（線のみ・淡い黄色系）。この輪自体は点滅しない |
| 爆風の警告輪 | 自機が、その地雷の爆風範囲に入っている間 | 地雷の位置に、半径 `MINE_EXPLODE_RADIUS` の輪（線のみ・赤）。自機が範囲から出たフレームで消える |

- **縮む輪の半径**: 残り時間 r（秒）に対して `MINE_RADIUS + (MINE_EXPLODE_RADIUS − MINE_RADIUS) × r / MINE_BLINK_SEC`。経過 7 秒（r = 3）ちょうどで半径 120、経過 8.5 秒（r = 1.5）で 66、爆発の瞬間（r = 0）で 12。経過 7 秒より前は出さない（経過 6.99 秒では輪なし、7 秒では出る）。点滅（本体）は従来どおり
- **警告輪の範囲の判定**: 爆風が自機に当たる判定（`circlesOverlap`、地雷の爆風半径 `MINE_EXPLODE_RADIUS` と自機の `PLAYER_RADIUS`）と同じ式を、毎フレーム、自機の移動のあとの座標で評価する。つまり地雷の中心から自機の中心までの距離が `MINE_EXPLODE_RADIUS + PLAYER_RADIUS`（132 px）より小さい間、警告輪を出す（距離 100 px では出る、140 px では出ない）。設置直後の 0.5 秒間（自機との接触が無効な間）も、範囲に入っていれば出す（接触の猶予は地雷本体の接触だけで、爆風には猶予が無い）
- 連鎖で広がる爆風範囲（`MINE_CHAIN_RADIUS_MULTIPLIER` 倍）は予告しない。警告輪は常に半径 `MINE_EXPLODE_RADIUS` の輪で、複数の地雷があれば地雷ごとに独立して出す
- **消える時**: 地雷が爆発（通常・連鎖・自爆の判定）でリストから除かれる瞬間に、その地雷の 3 つの輪もすべて破棄する。連鎖で誘爆する地雷の輪も、誘爆した瞬間に消える（爆発の円の演出が 100ms ずつ遅れて出るのは従来どおり）
- **描画順**: 地雷本体（depth 5）の下、敵機（depth 4）の上（depth 4.5）。敵弾（depth 3）・敵機より前に出る。自機は従来どおり（depth は変えない。depth 0 で、輪より下になる）で、輪は線のみで塗らないので自機の見え方を損なわない。HUD・爆発の円（depth 6）・仮想コントローラは輪より前のまま。同じ地雷の縮むカウントダウン輪と警告輪が重なるときは、警告輪を上に描く
- **入力と他の演出との関係**: 輪の表示中も入力は止めない。爆発の円・カメラシェイクとは独立に動く。ゲームオーバーの演出中（約 800ms）は、更新を止めるので輪もその時点の状態のまま残り、Game シーンの終了とともに消える。リスタート後に前回の輪は残らない
- 画面の端の近くに置いた地雷の輪は、画面の外にはみ出してよい（切り詰めない）

## 敵弾ビジュアル仕様

敵弾は、弾種（`BulletType`）ごとに形と色を変えて描く。当たり判定は従来どおり、すべての弾が半径 `BULLET_RADIUS`（5）の円（見た目だけ変える）。外部画像は使わず、図形から作る。

| 弾種 | 形 | 色（初期値） |
|------|----|--------------|
| 直下弾 `straight` | 円（半径 5）。従来のまま | 橙 `0xff8800`（従来のまま） |
| 自機狙い弾 `aimed` | ひし形（進む向きに頂点を向ける） | マゼンタ `0xff44ff` |
| 3-way 弾 `nway3`・5-way 弾 `nway5` | 三角形（進む向きに頂点を向ける）。3-way と 5-way は同じ見た目 | 黄緑 `0xaaff00` |
| 全方位弾 `spread8` | 円（半径 5） | 淡い紫 `0xc9b8ff` |
| 高速弾 `fast` | 先頭の円（半径 5）と、弾の中心から後ろへ `BULLET_TAIL_LENGTH` まで伸びる尾（細い三角形で、中心側から先端へ薄れる） | 先頭は白 `0xffffff`、尾は橙 `0xff8800` から透明へ |

- **大きさ**: 先頭の形（尾を除く）は、弾の中心から半径 `BULLET_VISUAL_RADIUS_MAX`（6）の円に収まる大きさにする（当たり判定の半径 5 より外へ大きく出さない）。尾は弾の進む向きの反対側にだけ伸びる
- **向き**: ひし形・三角形・尾は、発射の時点の速度の向き（`atan2(vy, vx)`）に合わせて向けて、弾が消えるまで変えない（弾の速度は途中で変わらない）。直下弾・全方位弾・先頭の円は回転しても見た目が変わらない
- **色**: 自機（水色）・地雷（黄色）・敵機（赤）・爆発の円と、弾が見分けられる色にする。上の初期値は、見分けられる範囲で調整してよい（実装裁量）
- **描画**: 弾は起動後に一度だけ図形から作ったテクスチャを使い回す（弾 1 発ごとに `Graphics` を作らない。リスタートでは作り直さなくてよい）。描画順は従来どおり（depth 3）
- **爆風・消去**: 弾の消去（爆発の巻き込み、画面外）は従来どおり。見た目の弾種の違いは、消去・当たり判定に影響しない

## 連鎖爆発ビジュアル仕様

- 連鎖爆発の爆発円は通常より大きく描画する（半径が係数に応じて拡大）
- 爆発円の色は爆発段階に応じて変化させる（例: 元の爆発はオレンジ、1連鎖目は赤系、2連鎖目以降は紫）
- 各連鎖の爆発は少し時間差（100ms）を置いて順に表示することで演出を強調する
- カメラシェイクの強度も連鎖回数に応じて増加する

## 爆発ビジュアル仕様

- 爆発半径を円で描画し、数フレームでフェードアウト（`Graphics` + `alpha`減算）
- 爆発時にカメラを軽くシェイク（`cameras.main.shake`）
- 爆発ビジュアルが完了する前に巻き込み対象の消去処理を先に実行する

## リスタートフロー

- GameOver → Game シーンを直接再起動（Boot を経由しない）
- `this.scene.start('Game')` でシーン内ステートを完全リセット
- アセット（Graphics のみ）は再読み込み不要

## 編隊挙動詳細

- 編隊内の一部が地雷で倒された場合、残りの敵機はそのまま降下し続ける（フォーメーションは崩れても継続）
- 編隊は個別ステータスを持たず各機が独立して動く

| `BULLET_VISUAL_RADIUS_MAX` / `BULLET_TAIL_LENGTH` | 6 / 14 px | 敵弾の先頭の形の最大半径・高速弾の尾の長さ（見た目のみ。当たり判定は `BULLET_RADIUS`） |
| 背景の下地色（段階 1〜6） | `0x0a0a1a` / `0x100a1e` / `0x160a22` / `0x1c0a26` / `0x220a2a` / `0x280a2e` | 難易度の時間割の段階と同じ境界で切り替える。見た目のみ |

| `FORMATION_INTERVAL_EARLY_SEC` | 4 秒 | 経過 0〜30 秒の編隊の出現間隔 |
| `FORMATION_INTERVAL_SEC` | 6 秒 | 経過 30 秒以降の編隊の出現間隔（従来どおり） |

編隊の出現間隔は、編隊が出た瞬間にタイマーを 0 に戻し、タイマーが「その時点の経過時間の段階の間隔」以上になったら次を出す。最初の編隊は経過 0 秒（開始直後の更新）に出る。例: 0, 4, 8, …, 28 秒に出て、次は 28 秒の編隊から 6 秒後の 34 秒（30 秒を過ぎてから間隔が 6 秒になるため、32 秒ではない）。タイマーは出現のたびに超過分を捨てて 0 に戻し、開始時は間隔以上の値から始める（最初の更新で必ず 1 回出る）。

難易度の時間割（経過秒 → 段階）:

| 経過 | 弾速 | 弾種 | 編隊の形 | 編隊の機数 | 撃つ間隔（`fireIntervalSec`） |
|------|------|------|----------|------------|------------------------------|
| 0〜10 秒 | 基準 × 1.0 | 直下 | 横一列 | 3 | 2.0 秒 |
| 10〜20 秒 | 基準 × 1.0 | 直下・自機狙い | 横一列・V字 | 3 | 1.8 秒 |
| 20〜30 秒 | 基準 × 1.0 | 直下・自機狙い・3-way | 横一列・V字 | 3 | 1.6 秒 |
| 30〜60 秒 | 基準 × 1.3 | 直下・自機狙い・3-way・全方位 | 横一列・V字 | 4 | 1.4 秒 |
| 60〜120 秒 | 基準 × 1.6 | 上 + 5-way・高速 | 横一列・V字 | 5 | 1.1 秒 |
| 120 秒以降 | 基準 × 2.0 | 60〜120 秒と同じ | 横一列・V字 | 5 | 0.8 秒 |

- 30 秒以降の行は従来から変えていない。
- 概算（撃破なしの定常状態、敵弾の発射数 弾/秒）: 0〜10 秒 3.4、10〜20 秒 3.8、20〜30 秒 7.0、30〜60 秒 13.6。実際に遊んだ手応えは未確認（初期値）。

## テスト観点

- スコア計算ロジック（時間 × 係数）
- 地雷残弾数管理（初期値・設置で減少・0のとき設置不可。アイテムで増える分は [アイテム](spec/power-ups.md) のテスト観点）
- 自機の移動ロジック（境界クランプ）
- 敵弾生成ロジック（座標範囲、速度範囲）
- 当たり判定ロジック（円同士の重なり判定）
- 爆発の巻き込み判定（爆発半径内の敵機・敵弾を消去、範囲外は残る。自機が半径内ならゲームオーバー）
- 連鎖爆発ロジック（爆発半径内の地雷を誘爆、半径を 1.5 倍に拡大して再帰処理。処理済み地雷を追跡して無限ループ防止）
- 地雷タイムアウト爆発（10秒後に自動爆発）
- 自機が地雷に触れた場合のゲームオーバー判定
- 設置直後の自機判定無効化（0.5秒の猶予時間）
- 仮想スティック入力のベクトル変換（8方向 → 移動速度）
- タッチデバイス検出フラグの切り替え
- 難易度スケール（経過時間 → 弾速・弾種・編隊の形・機数・撃つ間隔・編隊の出現間隔の段階変化。純関数としてテストする）
  - 境界: 9.99 秒は 1 段階目（直下弾のみ・横一列のみ・2.0 秒・間隔 4 秒）、10 秒は 2 段階目（自機狙い・V字が加わる・1.8 秒）、19.99 / 20 秒（3-way が加わる・1.6 秒）、29.99 秒は間隔 4 秒、30 秒は間隔 6 秒
  - 0〜30 秒の弾速は `BULLET_BASE_SPEED`、機数は 3
  - 30 秒以降の各段階（30 / 60 / 120 秒）の弾速・弾種・機数・撃つ間隔は従来と同じ
- 編隊の出現タイミング（純関数。タイマー進行 → 出現するか）: 経過 0 秒の最初の更新で出る、4 秒ごとに出る（0〜30 秒）、28 秒の次は 34 秒、30 秒以降は 6 秒間隔
- 編隊の形の選択: 0〜10 秒は常に横一列、10 秒以降は乱数で横一列・V字（乱数は注入）
- 編隊生成ロジック（横一列・V字の座標計算）
- N-way弾の角度計算（自機狙い方向を中心に扇形展開）
- 回帰（変えないもの）: 自機の移動速度・地雷の設置／爆発／連鎖／自爆の規則と数値・スコア式・敵機の降下速度・各当たり半径・30 秒以降の時間割・リスタートでタイマーと経過時間が 0 に戻ること、仮想スティックのベクトル変換と地雷ボタンが従来どおりであること
- 敵弾の見た目の選択（純関数）: 弾種 → 見た目（形 + 色）の対応（色の初期値は敵弾ビジュアル仕様の表）。`straight`・`aimed`・`nway3`/`nway5`・`spread8`・`fast` がすべて対応を持ち、`nway3` と `nway5` は同じ見た目、それ以外は互いに形か色が違うこと（`straight` と `spread8` は同じ円で、色が違う）。弾の速度の向きから描く向きの角度を求める計算（下向き `(0, v)` は π/2、右向き `(v, 0)` は 0）
- 縮むカウントダウン輪の半径（純関数。地雷の経過秒 → 半径または「出さない」）: 6.99 秒は出さない、7 秒は 120、8.5 秒は 66、9.99 秒は 12.36（= 12 + 108 × 0.01 / 3）、10 秒は 12（10 秒を超えても 12 を下回らない）
- 爆風の警告輪の判定（純関数。地雷の位置・自機の位置 → 出すか）: 距離 100 は出る、距離 131.99 は出る、距離 132 ちょうどは出ない、距離 140 は出ない、境界は爆風が自機に当たる判定（`circlesOverlap`）と一致する（`MINE_EXPLODE_RADIUS + PLAYER_RADIUS` ちょうどの扱いも同じ）。地雷が複数あれば地雷ごとに独立に判定する
- 背景の段階色（純関数。経過秒 → 下地色）: 9.99 秒は段階 1 の色、10 秒は段階 2、119.99 秒は段階 5、120 秒は段階 6 の色（境界は難易度の時間割と同じ）
- 星の更新（純関数。星の位置・経過 → 次の位置）: 下へ流れ、画面の下端を越えた星は上端の外へ戻る
- 機体の形（純関数。形の頂点 → 中心からの距離）: 自機の三角形の頂点は当たり半径 12 以内、敵機の菱形の頂点は当たり半径 14 以内にある
- 回帰（見た目の変更で変えないもの）: 敵弾の当たり半径（5）・地雷の当たり半径（12）・爆風半径（120）・連鎖の倍率・弾の速度と向き（弾種ごとの発射方向の計算）・弾の消去の規則が従来どおりであること
- 敵機・敵弾の core（固定の乱数列と手計算の期待値でテストする。期待値は実装の式の再計算でなく、この spec の数値から手で出す）:
  - 編隊の出現: 乱数列 `[形, 中心 x, 機 1, 機 2, …]` から、形（0〜10 秒は乱数が何でも横一列。10 秒以降は r = 0.499… で横一列、r = 0.5 で V 字）・各機の位置（間隔 52、中心 x は上の式。横一列は全機 y = −20 で、3 機なら (c − 52, −20)・(c, −20)・(c + 52, −20)。V 字は従来の `calcVFormation` どおり、奇数機数なら中央の機が y = −20 で先頭、続いて 1 段ごとに「左 → 右」の順で、i 段目は x = 中心 ∓ i × 52、y = −20 + i × 52 × 0.6。偶数機数は、左右の対を i = 1 … 機数/2 の順に並べたあと、最後に半段（i = 機数/2 − 0.5）の左 → 右の対が加わる。このため偶数機数の V 字は `機数 + 2` 機になる（従来の `calcVFormation` の挙動。今回は変えない。実際に出るのは時間割の機数 4 のとき = 6 機）。例: 3 機 = 中央 (c, −20)・左 (c − 52, 11.2)・右 (c + 52, 11.2)。4 機 = 左 (c − 52, 11.2)・右 (c + 52, 11.2)・左 (c − 104, 42.4)・右 (c + 104, 42.4)・左 (c − 78, 26.8)・右 (c + 78, 26.8)（計 6 機）。機ごとの乱数と敵機の配列は、この返却順）・初速（vx 0、vy `ENEMY_SPEED`）・最初の発射までの時間（`0.5 + r × 0.5`、r = 0 で 0.5、r = 0.999… で 1.0 未満）・初期の弾種（横一列は `straight`、V 字は `aimed`）を確かめる。乱数の呼び出し回数は 2 + 出た機数（V 字の偶数機数は上のとおり `機数 + 2` 機）
  - 単体の敵の出現: x が `ENEMY_RADIUS + r × (GAME_WIDTH − 2 × ENEMY_RADIUS)`（r = 0 と r → 1 の両端が画面内）、y = −`ENEMY_RADIUS`。突進は自機位置へ向かう速さ `RUSH_SPEED` の速度、停止は出現時の vx・vy が 0 で降下から始まる（降下は `advanceStopper` が `ENEMY_SPEED` で y を動かす）。乱数は 1 回
  - 撃つ間隔: 撃つ間隔の残りが 0 を超える間は撃たず、乱数も呼ばない。0 以下になった更新で、次の間隔（`fireIntervalSec + r × 0.3`）と弾種（`floor(r × 弾種の数)`、r → 1 でも範囲内）を、この順に 2 回の乱数で決めて撃つ。停止する敵は、停止中（phase が hold）だけ撃つ（降下中・上昇中は撃たず、残りも進めない）。降下から停止に入った更新だけ、最初の発射までの時間を `r × 0.3` に決める（乱数 1 回）。その更新は phase がすでに hold なので、同じ更新のうちに `dt` を引いて 0 以下なら撃つ（r × 0.3 ≤ dt なら入った更新で撃ち、その更新の乱数は 3 回続く）。停止の残り秒はその更新では減らさない。停止の残りが 0 以下になった更新は phase が上昇に変わるので撃たない。テストに、`dt` を固定して r = 0 で入った更新に撃つ場合と、r = 0.999… で入った更新に撃たない場合を入れる
  - 弾種ごとの発射（乱数なし）: `straight` は真下に 1 発、`aimed` は自機方向に 1 発、`nway3` / `nway5` は自機方向を中心に総角 π/5 を等間隔に 3 / 5 発、`spread8` は 8 方向（0, π/4, …）、`fast` は弾速 2 倍の真下に 1 発。弾速はその段階の弾速。境界: 自機が敵のちょうど真下（角度 π/2）・真上（−π/2）・同じ位置（`atan2(0, 0)` = 0、右向き）
  - 移動と削除: 編隊は直下に `ENEMY_SPEED`、突進は初速のまま直進、停止は降下 → 停止（`SOLO_STOP_Y`、`SOLO_STOP_SEC`）→ 上昇。削除の境界は、編隊は y > `GAME_HEIGHT` + 40 で消え（ちょうど 40 は残る）、突進・停止は [敵の種類](spec/enemy-kinds.md) のとおり。弾は x < −20、x > `GAME_WIDTH` + 20、y < −20、y > `GAME_HEIGHT` + 20 で消える（ちょうど −20 などは残る）
  - 更新の順: 同じ更新で撃った弾が、その更新のうちに 1 回分 dt だけ動くこと。更新の途中で Scene が処理を止めたとき、後ろの敵機が動かず・撃たず・乱数を呼ばず、弾も動かないこと。中断前に出現した敵機と、中断前に撃った弾の id が通知され、その弾の位置が出現位置のままであること、削除の通知が出ないこと
  - id と削除: 出現した敵機・弾に重複しない id が付き、消えた id が返ること。爆発による削除は、渡した対象だけを消し、残りの順序を保つ。リスタートで状態を作り直すと、敵機・弾・タイマー・id が初期に戻ること
  - 回帰（挙動を変えない移動）: 上の各値が、移動前の `Game.ts` の式と同じ数値になること（敵機の降下速度 `ENEMY_SPEED`・弾の発射方向・乱数の呼び出し順と回数）
- 地雷の core（手計算の期待値でテストする。特に断らない限り、座標は例に書いたとおりで、自機は爆風から遠くに置く。地雷のリストの並びは例に書いた順（A・B・C …）。期待値は実装の式の再計算でなく、この spec の数値から手で出す）:
  - 連鎖の半径: 連鎖回数 0・1・2・3 で 120・180・270・405
  - 誘爆の境界: 地雷 A (200, 300) と B (200, 420)（距離 120）は B が誘爆する（ちょうど半径は含む）。B が (200, 420.01) なら誘爆しない
  - 連鎖の深さ: A (200, 300)・B (200, 400)・C (200, 500) で、A が爆発すると A（連鎖 0、半径 120）→ B（連鎖 1、半径 180）→ C（連鎖 2、半径 270）の順になる（A の対象は B だけ。C は A から 200 離れている）
  - 先の連鎖が誘爆した地雷: A (200, 300)・B (260, 300)・C (140, 300) で A が爆発すると、順は A（0）→ B（1）→ C（2）で、C は 1 回だけ（連鎖回数 2。連鎖回数 1 ではない）
  - 巻き込み: 爆心 (200, 300) 半径 120 で、敵機・弾は距離 120 ちょうどは消え、120.01 は残る。残った敵機・弾の並びは変わらない。消えた敵機の座標は敵機リストの並びで返る。同じ更新で先に消えた敵機は、後の爆発の対象にならない
  - 自機への爆風: 半径 120 で距離 131.99 は当たり、132 ちょうどは当たらない（連鎖で半径 180 なら 191.99 は当たり、192 は当たらない）。連鎖のどれかが当たれば、その結果に自機に当たったが入る
  - 起点: `age` 9.99 に `dt` 0.02 を足すと爆発予定（10 秒ちょうども）。9.98 に 0.01 を足した 9.99 は予定に入らない。敵機との距離 25.99 は予定に入り、26 ちょうどは入らない。時間切れの地雷は敵機・自機の判定をしない
  - 自機の接触: `age` ちょうど 0.5 は無効、0.51 は有効。Scene が「無効」と答えている間は接触しても爆発しない（問い合わせは地雷ごとに、その時点の状態で）
  - 更新の途中: 接触の爆発で Scene が中断と答えると、後ろの地雷は `age` が進まず、爆発予定も解かれない。バリアが防いだ（続ける）と、後ろの地雷は続けて調べられ（その間は Scene が無効と答える）、接触の爆発で消えた敵機・誘爆した地雷は、後ろの地雷の敵機との判定・爆発予定に反映される（誘爆で除かれた爆発予定の地雷は、まとめて解くときに飛ばす）。接触の爆発と爆発予定では処理済みの集合が別
  - 爆発予定のまとめ: 爆発予定の地雷の連鎖が、後ろの爆発予定の地雷を誘爆したら、その地雷はまとめの中で 2 度は爆発しない。結果は爆発予定の順・各連鎖の深さ優先の順
  - 乱数: 地雷の更新は乱数を呼ばない
  - リスタート: 状態を作り直すと、地雷のリストが空で id が初期に戻る
  - 新旧の比較: 移す前の `Game.ts` の再帰（`triggerExplosion`・地雷の更新ループ・爆発予定のまとめ）を、テストの中に基準の実装として写し、固定のシードの乱数で作った地雷（3〜8 個、位置・`age` はばらつかせる）・敵機・弾・自機の配置の多数のケースで、新しい core と基準実装を比べる。比べるもの: 爆発の順・連鎖回数・半径・消える敵機（id と座標の並び）と弾の id・自機に当たったか・更新後に残る地雷（id と `age`）・敵機と弾の並び。接触の有効・中断の答えも、いくつかのパターン（常に有効／常に無効／最初の接触で中断／最初の接触でバリアが防ぎ以後は無効）で比べる。ケースの数のうち、連鎖が 2 回以上、自機に爆風が当たる、接触の爆発が起きる、爆発予定が複数あるものが、それぞれ 1 件以上あることも確かめる（比べるだけで通る空の配置にしない）
  - Scene の接着の確認（単体テストの対象外。コードの確認と QA で確かめる）: アイテムの抽選が、結果の消えた敵機 1 機につき 1 回、結果の並び（爆発の順 → 敵機リストの並び）で `Math.random` を呼ぶこと（コードの確認。並び自体は上の新旧の比較で確かめる）。`window.__qa` の `mines` が x・y・age だけの配列であること（QA で読む）
- 描画の細部（輪・波紋・弾の形の見え方）・HUD は単体テストの対象外。ブラウザでの目視確認（QA）で、弾種の見分け・輪の出る／消える・縮む様子を確かめ、爆発と連鎖の演出・HUD が従来どおりであることも確かめる。背景・自機・敵機の見た目は「背景・機体の見た目（レトロ調）」を満たすことを確かめる
