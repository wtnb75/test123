# cjump ゲーム仕様

## ゲーム名

**cjump** ― 拡大する円を避けるワンボタン・ジャンプゲーム（仮称）

## コンセプト

キャラクターがあらかじめ決まったカーブを含むルートを等速で自動的に進み続ける中、画面内のランダムな地点から発生して広がり続ける円の縁（輪郭線）にタイミングよくジャンプして接触を避け、ルートを走り切ることを目指す。

## ターゲットプレイヤー

- ブラウザで気軽に遊べるワンボタンゲームを求めるプレイヤー
- タイミング型・反射神経系のシンプルなゲームを好むプレイヤー

## コアループ

1. キャラクターはルートに沿って自動的に等速で進み続ける
2. 画面内のランダムな地点から円が発生し、時間経過で半径が広がり続ける
3. 円の縁（輪郭線）がキャラクターの現在地に重なるタイミングで、ワンボタン入力してジャンプする
4. ジャンプ中はキャラクターの移動が停止し、着地後に移動を再開する
5. 円の縁に接触せずルートの終点まで到達するとステージクリア
6. 円の縁に接触すると即座にゲームオーバー

## 操作仕様

| 操作 | 方法 |
|------|------|
| ジャンプ | スペースキーなどのキーボード入力、または画面全体のタップ／クリック |

- PC・スマートフォンいずれも同一の操作感になるよう、キーボードとタッチ/クリックの両方を常時受け付ける
- 仮想コントローラ等の追加UIは不要（ワンボタンのため画面タップで代替）

## 画面・Scene 構成

| Scene | 役割 |
|-------|------|
| `Boot` | アセット読み込み（Graphics主体のため軽量） |
| `StageSelect` | ステージ選択。セッション内で解放済みのステージのみ選択可能 |
| `Game` | メインゲームプレイ（ルート移動・円回避・ジャンプ） |
| `StageClear` | クリア表示。次ステージへ進む、またはステージ選択に戻る選択肢を表示 |
| `GameOver` | 失敗表示。ステージ選択に戻る |

### 進行状況の扱い

- 進行状況（解放済みステージ）はセッション内メモリのみで管理する
- `localStorage` 等の永続化は行わない（ブラウザを閉じる／リロードすると常にステージ1のみ解放された状態に戻る）

## ルート生成の仕様

- ステージ番号をシードとしたシード付き疑似乱数でルートを決定的に生成する（同じステージ番号なら常に同じルートになる）
- ルートはいくつかのウェイポイント（制御点）をランダム生成し、`Phaser.Curves.Spline`（`Phaser.Curves.Path` 経由）で滑らかな曲線として構築する
- 制御点は常に一定方向（例: 左から右）へ進む形で生成し、直前の区間の進行方向に対する次区間の方向変化量（進行方向の角度差）に上限 `θ_max` を設けることで、ルートが自己交差しないようにする
  - `θ_max` はステージ番号に応じて広がる（`θ_max(stage) = min(30 + 10 × (stage - 1), 90)` 度）。難易度スケールで言う「カーブの角度変化が増える」はこの `θ_max` の増加で表現する
  - 各制御点間の距離は、画面のプレイ可能幅（左右マージンを除いた幅）をウェイポイント数で等分した目標区間距離をもとに算出する（角度がついた分だけ実距離は目標区間距離より長くなる）。これにより、ステージの複雑さ（角度・ウェイポイント数）によらず、ルートは常に画面のほぼ全幅を使って左端から右端まで到達する
- キャラクターはパス上のt値を一定速度で進めることで等速移動を実現する（ジャンプ中はt値の更新を停止）

## 円（障害物）の仕様

- 円は画面内のランダムな座標を中心として発生する
- 発生直後は一定時間（発生予告時間）、当たり判定を持たない「予告状態」とし、発生予定地点に予告表示（例: 小さな印や薄い輪）のみを行う
  - 予告状態の間は半径0のまま拡大しない。プレイヤーが接触を避ける準備をするための猶予時間として機能する
- 発生予告時間の経過後、時間経過とともに一定速度で半径が拡大し始める（当たり判定もこの時点から有効になる）
- 半径の上限や消滅条件はなく、画面外に完全に出るまで拡大を続ける（画面外に出た円は描画・判定コストを避けるため破棄する）
- 危険なのは円の縁（輪郭線）のみで、円の内側・外側の領域は安全

### 当たり判定

- 予告状態の円は当たり判定の対象外とする
- 予告状態を終えた円については、キャラクター座標と円中心との距離を計算し、`|距離 - 現在の半径| < 縁の許容誤差` を満たす場合を接触とみなす
- 許容誤差は描画する縁の線の太さと一致させ、見た目と判定を一致させる

## キャラクターの見た目

- `Graphics` で描く単純な円とし、進行方向が視認できるよう円の縁に小さな三角形（矢印）を進行方向側に添える
- ジャンプ中は「浮いている」ことを演出するため、円をわずかに拡大表示し、足元に薄い影（進行方向に固定した小さな楕円）を縮小表示する
- これらは見た目上の演出のみであり、当たり判定（円中心・パス上のt値）には影響しない

## ジャンプの仕様

- ワンボタン入力で固定時間・固定モーションのジャンプを行う
- ジャンプ中はルート上の移動（t値の更新）を停止する
- ジャンプ中は円の縁との当たり判定を無効化する（ジャンプで回避する、という仕様のコア）
- ジャンプ中の追加入力は無視する（連続ジャンプ・二段ジャンプは不可）
- 着地と同時にルート移動を再開する

## 難易度スケール（ステージが進むにつれて変化する要素）

- **円の発生頻度**: ステージが進むほど円の発生間隔が短くなる
- **円の拡大速度**: ステージが進むほど円の半径が広がる速度が上がる
- **ルートの長さ・複雑さ**: ステージが進むほどルートが長くなり（ウェイポイント数が増える）、カーブの角度変化上限 `θ_max` が広がる（「ルート生成の仕様」参照）
- キャラクターの移動速度・ジャンプの固定時間は全ステージ共通で変化させない
- **ステージ数**: 全10ステージの固定構成とする。ステージ10をクリアすると `StageClear` 画面は「全ステージクリア」表示とし、「次のステージへ」は表示せず「ステージ選択に戻る」のみを表示する

## ルール

- **勝利条件（ステージクリア）**: ルートの終点まで、円の縁に一度も接触せずに到達する
- **失敗条件**: 円の縁にキャラクターが接触する（1回で即ゲームオーバー）
- **スコア条件**: なし。クリアの有無のみを判定し、クリアしたステージの次のステージがセッション内で解放される

## リスタート・進行フロー

- `GameOver` → `StageSelect`（挑戦していたステージより先は解放されない）
- `StageClear` → `StageClear` 画面から「次のステージへ」または「ステージ選択に戻る」を選択
- `Game` シーンはステージ番号をパラメータとして毎回リセットして起動する（`this.scene.start('Game', { stage })`）

## MVP 範囲（初版で作る範囲）

- ステージ番号をシードとしたルートの決定的なプロシージャル生成（`Phaser.Curves.Spline` による曲線ルート）
- キャラクターのルート上の等速自動移動
- 円のランダム発生・発生予告時間・時間経過による拡大
- 円の縁とキャラクターの当たり判定（許容誤差つき距離判定、予告状態の円は判定対象外）
- ワンボタン（キーボード＋タップ/クリック）による固定時間ジャンプ、ジャンプ中の移動停止・当たり判定無効化
- ステージクリア判定（ルート終点到達）・ゲームオーバー判定（円の縁への接触）
- ステージが進むごとの難易度上昇（円の発生頻度・拡大速度・ルートの長さと複雑さ）
- `StageSelect` / `Game` / `StageClear` / `GameOver` の画面遷移
- セッション内メモリでのステージ解放状況管理

## 非MVP範囲（今回は作らない範囲）

- 進行状況の永続保存（`localStorage` 等）
- スコア・タイムアタック要素
- BGM・効果音
- 難易度設定（イージー／ハードなどのモード選択）
- 複数ライフ・被弾猶予
- 二段ジャンプ・ジャンプの高さ／時間の可変制御
- 仮想コントローラ等の追加UI（画面タップのみで代替するため不要）

## 技術要件

- フレームワーク: Phaser 4.x（TypeScript）
- ビルド: Vite
- lint: ESLint（エラー0件）
- テスト: Vitest（カバレッジ90%以上）
- アセット: 図形描画（`Graphics`）で代替し、外部画像なしで動作させる
- ルート表現: `Phaser.Curves.Path` + `Phaser.Curves.Spline`
- 乱数: シード付き疑似乱数（軽量PRNGを自前実装し、ステージ番号から決定的にルート・難易度パラメータを導出する）
- ゲーム状態はシーン内のプロパティで管理し、グローバル汚染しない
- レイアウト: `Scale.FIT` + `CENTER_BOTH` でスマートフォン縦横両対応

## テスト観点

- シード付き疑似乱数の再現性（同じシードから同じ値列が得られること）
- ルート生成ロジック（ウェイポイント生成、`θ_max` によるルートの自己交差防止、`θ_max` がステージ番号に応じて 30〜90 度の範囲で変化すること、区間距離が目標区間距離をもとに算出されルートが画面のプレイ可能幅をほぼ使い切ること）
- キャラクターのルート上移動ロジック（t値の進行、ジャンプ中は停止すること）
- 円の生成・拡大ロジック（発生予告時間中は半径が0のまま拡大しないこと、予告時間経過後に時間経過とともに半径が増加すること、画面外判定による破棄）
- 円とキャラクターの当たり判定ロジック（境界値: 許容誤差の内側／外側／境界上、予告状態の円には接触しないこと）
- ジャンプ中の当たり判定無効化ロジック
- ジャンプの固定時間・入力無視（ジャンプ中の追加入力が無視されること）
- ステージクリア判定（ルート終点到達）
- ゲームオーバー判定（円の縁への接触）
- 難易度スケールのステージ番号依存ロジック（発生頻度・拡大速度・ルート複雑さがステージ番号に応じて変化すること）
- 最終ステージ（10）クリア時の分岐ロジック（「次のステージへ」を出さないこと）
- ステージ解放状況の管理ロジック（セッション内メモリでの解放・GameOver時に解放範囲が広がらないこと）
