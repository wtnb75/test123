# ベスト記録の保存

`docs/spec.md` の一部。セッションをまたいで保存するベスト記録（最高のライン数）の保存形式・読み込みの検査・「ベスト」の行の決め方と、そのテスト観点・完了条件を、独立して書いたもの。パラメータ名と節名は `docs/spec.md` のものを指す。`docs/spec.md` と合わせて 1 つの spec である。

## 概要

最高のライン数を `localStorage` に保存し、プレイ中の HUD と Result に「ベスト」の行として出す。

## 操作仕様

なし。

## 画面・Scene構成

なし（HUD と Result の配置は `docs/spec.md` の「画面・Scene 構成」とパラメータ表のとおり）。

## ルール

### 保存するもの

- セッションをまたいで保存するのは、ベスト記録（最高のライン数）だけ。設定やほかの記録は持たない。ブラウザの `localStorage` に、キー `ベスト記録のキー` で、共有パッケージ `shared/best-store` の約束の形（JSON `{"score": N, "label": "ライン N"}`。`score` は 1 以上の整数のライン数、`label` は一覧にそのまま出す文字列。約束は `shared/best-store/README.md`）で保存する。形式とキーだけを約束に合わせ、読み書きの回数・失敗時の扱いは下のとおりこのゲーム固有のまま（`best-store` の `BestStore` は使わない。ストレージ API は、このゲームのベスト記録のモジュールだけが呼ぶ）。`bestKey` / `parseBest` / `Best` 型は `best-store` のものを使ってよい。
- ストレージを呼ぶのは、Game のベスト記録だけ。(1) Game に入るとき `getItem` を 1 回（その回の基準 B。「もう一度」で Game に入るたびに読み直す）。(2) その回のライン数 N が基準 B と、その回にすでに保存した値の両方を上回るたび（一列を消したとき）に `setItem` を 1 回（N を保存する）。同じ N は 1 度しか書かない（描画のたびには呼ばない）。Title・デモ・Result・盤面のロジックと、向きの変更による配置し直しでは呼ばない。

#### ベスト記録

Game に入るとき、保存されている値 B を読む。B は、`best-store` の約束どおりに読める値（JSON で、`score` が有限の数、`label` が文字列）で、かつ `score` が 1 以上の安全に扱える整数（`Number.isSafeInteger`）のものだけを有効とし、それ以外（無い・空・壊れた JSON・`score` が 0・負・小数・数でない・桁が大きすぎる・`label` が文字列でない）は「保存なし」として扱う。ライン数だけの 10 進の文字列（例 `7`）も、この形ではないので「保存なし」になる。以前のバージョンは、その形の値を別のキー `pushlineBest` に保存していた。新しいバージョンはそのキーを読まず、書かず、消さない（記録を読み替えない）ので、以前の記録があったプレイヤーは、新しいキーが空の状態から始まる。更新後の最初のプレイは「ベスト 1」から出直しになり、「更新!」は付かない（古いキーの値はブラウザに残るが、使われない）。その後、そのときのライン数 N（スコア。0 から増え、減らない）について、次のとおり決める。行は HUD の 2 行目と Result の「ベスト」の行に同じ内容を出す。

| 条件 | 保存 | 「ベスト」の行 |
|---|---|---|
| B が保存なしで N = 0 | しない | 出さない |
| B が保存なしで N ≥ 1 | N を保存する（N が増えるたび） | 「ベスト N」（「更新!」は付けない。比べる前回が無い） |
| N > B | N を保存する（N が増えるたび） | 「ベスト N 更新!」 |
| N ≤ B（B がある） | しない | 「ベスト B」 |

- ストレージが使えない（`getItem` で例外が出る・ストレージが存在しない）、または保存が必要なのに書けなかったときは、「ベスト」の行を出さない（HUD も Result も）。以後その回はストレージを呼ばない。例外はゲームの進行・Result のほかの表示に影響しない（Result は通常どおり出て、「もう一度」「タイトルへ」も動く）。
- 保存するのはライン数だけ。「最短 M 回」は保存せず、ベストの行にも並べない。
- 保存は一列を消した時点で行うので、「Quit」やブラウザを閉じる場合も、それまでの最高は残る。ゲームオーバーまで遊ばなくても、記録は更新される。
- Result の行は、手数切れの時点の N で決まった行をそのまま出す（Result で読み直しも書き直しもしない。入力無効時間の経過や向きの変更でも変わらない）。

## テスト観点

- ベスト記録（ストレージを注入して確認する。書き込みの回数と値も見る。N は入場後に 0 から増やしていく）
  - 保存なし・N = 0 のまま: 書かない。行は出さない。保存なしで N が 0 → 1 → 2 と増える: `{"score":1,"label":"ライン 1"}`・`{"score":2,"label":"ライン 2"}` を順に 1 回ずつ書く。行は「ベスト 1」→「ベスト 2」で、どちらも「更新!」なし
  - B = 5（保存値 `{"score":5,"label":"ライン 5"}`）: N が 0〜5 のあいだは書かない。行は「ベスト 5」で「更新!」なし（N = 5 でも書かない）。N = 6 で `{"score":6,"label":"ライン 6"}` を書き、「ベスト 6 更新!」。N = 7 で `{"score":7,"label":"ライン 7"}` を書き、「ベスト 7 更新!」。N が同じまま何度呼んでも、書き込みは増えない。`label` は読むときに使わない: 保存値が `{"score":5,"label":"WAVE 5"}` でも B = 5 として読まれ、行は「ベスト 5」
  - 保存された値が `""`・`"{"`・`"null"`・`"7"`（以前の形式の 10 進の文字列）・`{"score":0,"label":"ライン 0"}`・`{"score":-3,"label":"x"}`・`{"score":2.5,"label":"x"}`・`{"score":"5","label":"x"}`・`{"score":5}`（`label` なし）・`{"score":5,"label":7}`・`{"score":99999999999999999999,"label":"x"}` のときは「保存なし」として扱う（N = 4 まで増やすと 1〜4 を 1 回ずつ書き、行は「ベスト 4」で「更新!」なし。N = 0 のままなら書かず、行も出さない）。書く値の `label` は `ライン <N>`
  - `getItem` が例外を投げる・`setItem` が例外を投げる・ストレージが存在しないとき: 例外を外へ出さず、行を出さない（以後その回はストレージを呼ばない。Result のほかの表示と遷移は変わらない）
  - Title とデモの進行、Result、向きの変更の配置し直しでは、`getItem` も `setItem` も呼ばれない（呼び出し回数 0）
  - 「もう一度」で次の回に入るとき、`getItem` が 1 回呼ばれ、前の回の書き込み後の値が B になる。「Quit」の前に更新していれば、その値が残る
  - ベストの行（HUD）の配置データ: 縦画面 (240, 625)・横画面 (140, 340) で、既存の HUD（手数・ライン）・盤面（縦 110〜590、横 280〜680）・操作ボタンと重ならず、キャンバスの内側に収まる（行全体「ベスト 123 更新!」を、`ベストHUDの文字の大きさ` の幅で見積もっても、横画面の左の余白 0〜280 に収まる）。既存の HUD の座標は変わらない
  - Result の配置データ: 「ベスト N」の中心が「最短 M 回」の中心から `ベストの間隔`（45 px）下にあり、縦画面 (240, 365)・横画面 (480, 255) で、「ライン N」・「最短 M 回」・ボタンと重ならず、キャンバスの内側に収まる。「更新!」を添えた行は、行全体（「ベスト 7 更新!」）の中心を同じ座標に置く。ベストの行の有無によらず、既存の 5 要素の座標は表の値のまま（縦 190 / 260 / 320 / 480 / 600、横 80 / 150 / 210 / 330 / 440）
  - 入力無効時間（時計を注入して確認する）: Result に入って `結果画面の入力無効時間`（400 ms）未満は、「もう一度」「タイトルへ」・Space / Enter を無視する。400 ms 以降は受け付ける。ベストの行の有無で変わらない

## 完了条件

- ベスト記録: プレイ中の HUD の 2 行目と Result の「ベスト」の行に、保存されている最高のライン数を出す。今回のライン数が上回ったら、一列を消した時点で HUD が「ベスト N 更新!」に変わり、その値が保存される（ゲームオーバーを待たない。「Quit」やページの読み込み直しの後も残る）。今回が下回るあいだは保存の値のまま。保存が無いときは、最初の一列を消すまで行を出さない。Title とデモ・Result はストレージを呼ばない。ストレージが使えない環境では行が出ず（HUD も Result も）、プレイと Result とそこからの遷移は普通に動く。HUD の行は縦画面・横画面とも既存の HUD・盤面・ボタンと重ならず、画面に収まり、実寸 11 px 以上で読める。Result の行は「ライン N」・「最短 M 回」・ボタンと重ならず、画面に収まり、実寸 11 px 以上で読める（375 × 550 と 667 × 310 を含む。QA のスクリーンショットで、保存なし・更新・更新なしの 3 状態を、プレイ中の HUD と Result の両方で確認する）。ストレージ API を呼ぶ箇所は、ベスト記録のモジュール 1 つだけ（コードの検索で確認する）。保存は `shared/best-store` の約束の形になっている（ブラウザで確認: 一列を消すと `localStorage` の `pushline.best` が `{"score":N,"label":"ライン N"}` になる。以前の形式を再現して、古いキー `pushlineBest` に `7` を入れておくと、HUD に行は出ず、最初に一列を消したときに「ベスト 1」が新しいキーに保存され、古いキーの値は変わらない。新しいキー `pushline.best` に `7` を手で入れても、同じく「保存なし」として扱われ、「ベスト 1」で上書きされる）。表示の文字（「ベスト N」「更新!」）・保存の回数・失敗時の扱いは移行前と同じ。`pushline/package.json` に `"best-store": "workspace:*"` を宣言する。
