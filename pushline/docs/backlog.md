# pushline 拡張候補（backlog）

公開済みの pushline に、次に足せるものの候補を、上から順に並べたものです。上のカードが「次の候補」です。仕様（`spec.md`）ではありません。`game-extend` が上から順に 1 件を選び、目的・コアループへの効き方・変えないものを固めてから、仕様に書きます。

- 規模: S = 1 画面と数値の追加程度、M = 複数の画面や仕組みにまたがる追加、L = 大きいので、`game-extend` で 1 PR 分に切り出してから採用する。

### タイトルのデモ再生を共通部品にする（`title-demo-shared`）

- 狙い: 他のゲームのタイトルも、ゲーム名と開始ボタンだけ、または説明文だけで、遊びの見本がない。根拠: ユーザー（pushline で試作した Title のデモを、他のゲームにも展開したい）
- 何を足すか: pushline の Title のデモで使った、盤面描画・演出の再生・デモの進行の枠組みを、共有のワークスペースパッケージに切り出し、2 本目のゲームで採用して形を確かめる。
- コアループへの効き方: 広げる — ゲームの中身は変えず、タイトルの見せ方を共通にする。
- 種別: presentation-only
- 規模: L（共有パッケージの新設と、2 本目のゲームの改修にまたがる。`game-extend` で 1 PR 分に切り出してから採用する）
- 出どころ: ユーザー
- メモ: pushline の試作（`feat/pushline-title-demo`）の後に、2 本目のゲームで同じ形になる部分を見極めてから抽出する。Phaser は import map で外出しにしているので、共有パッケージでは Phaser を `peerDependency` にし、バンドルに混ぜない。構成の変更（`pnpm-workspace.yaml` への追加）は、事前に方針の合意が要る（AGENTS.md 7 節）。
