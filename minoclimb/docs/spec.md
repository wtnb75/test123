# minoclimb（仮称。画面表示名は MINOCLIMB）

## コンセプト

普通のテトリスの盤面（10×20）にミノが 1 個ずつ降ってくる。プレイヤーは小さなキャラを操作し、落ちてくるミノを避けながら、積もったミノを登って上端近くのゴールラインに足を届かせるアクション。一列揃うとその行は消え、上の積み重ねが下がる（プレイヤーはその場に残り、重力で自然に落ちる）。ミノは足場であり脅威でもある。

## ターゲットプレイヤー

数十秒〜数分で 1 回遊べるカジュアルなアクションが好きな人。テトリスのミノの形を知っている人。PC（キーボード）とスマホ（タッチ）の両方で遊ぶ。

## コアループ

1. 上に現れたミノが回りながら止まり（回らないミノもある）、着地位置の枠もミノに合わせて動いて、最後の着地位置で止まる。止まった枠を見て、落ちてくる列から逃げる。
2. 予告が終わるとミノが一気に落ちて積もる。積もった段差にジャンプで乗り、高さを稼ぐ。
3. 行が揃って消えると足場が下がる。足場を保ちつつ登り、ゴールラインに足を届かせる。

## 操作仕様

プレイヤーが操作するのはキャラだけ。ミノは操作できない。

| 操作 | キーボード | タッチ |
|---|---|---|
| 左へ移動 | ← / A | 画面のどこかに触れ、触れた点（スティックの起点）から左へ STICK_DEADZONE を超えてドラッグ |
| 右へ移動 | → / D | 画面のどこかに触れ、スティックの起点から右へ STICK_DEADZONE を超えてドラッグ |
| ジャンプ | ↑ / W / スペース | 画面のどこかを①タップする（TAP_MAX_TIME 以内に、TAP_SLOP を超えて動かさずに離す）、②ドラッグ中の指を起点から上へ STICK_JUMP_FLICK を超えて弾く、③ドラッグ中に 2 本目の指で画面のどこかに触れる（触れている間ジャンプ） |
| 開始（Title） | スペース / Enter | 画面のどこかをタップ（START ボタン以外でもよい） |
| リトライ（結果画面） | R / スペース | 画面をタップ |

- 入力の合成、タッチ（スティックの指・ジャンプの指・タップ）、「新しく押した」、「ゲーム入力として有効になる入力」、開始・リトライの受け付け、マウスの扱い、無視される指の規則は、[入力とタッチ操作の詳細](spec/touch-input.md) に書く。
- 一時停止は無い。ブラウザのタブが非表示の間は進行しない（Phaser の既定）。

## 画面・Scene 構成

| Scene | 役割 |
|---|---|
| `Title` | 最初の Scene。ゲーム名・START と、縮小したデモの小窓（[Title とデモプレイ](spec/title-demo.md)）。開始で `Game` を始める |
| `Game` | 盤面・プレイヤー・ミノ・HUD を描画し、ゲームを進行する。始まるとすぐ `playing` の局面 |
| `Demo` | `Title` の小窓の中で、ボットが `Game` と同じルールで遊ぶ（[Title とデモプレイ](spec/title-demo.md)） |
| `Result` | クリア／ゲームオーバーの表示とリトライ。`Game` の上に重ねて起動する。`Game` はそのまま動かし続けるが、ラウンドの進行は止まり（盤面・プレイヤー・ミノは結果の瞬間のまま）、画面の揺れなどの演出だけが動く。最後の盤面が背後に残る |

起動後は `Title` が始まる（アセットの読み込みは無い）。`Title` で開始すると、`Game` が `playing` から始まる。リトライ（`Result` から）は `Title` に戻らず、`Game` を直接始める。

### 論理サイズとレイアウト

- 論理サイズは `COLS × CELL` = 360 px 幅、`ROWS × CELL` = 720 px 高さ。Phaser の Scale `FIT`＋中央寄せで、ウィンドウに収まるよう拡大縮小する。背景色は暗色（実装裁量）。
- 盤面が画面全体を占める。座標は盤面のセル単位（列 x、行 y。左上が (0, 0)、y は下向きに増える）で扱い、描画時に `CELL` 倍する。
- 盤面の上端 `TOP_OUT_ROW` 行分（行 0〜1）は「積み上がりすぎ」の危険域として、他と違う色の帯で示す。
- ゴールラインは行 `GOAL_ROW` の上端に、盤面幅いっぱいの太さ 4px の黄色い線で描く。
- HUD（高さ）は盤面の左上に重ねて表示する。黒い縁取り（太さ 3px）を付けて、ミノと重なっても読めるようにする。
- ゴールラインの右端に「GOAL」、危険域の帯の下端付近に中央揃えで「ここまで積むと負け」を、小さく薄い文字で常に表示する（見え方は「演出・UI」を参照）。
- 描画順（下から）: 背景・危険域の帯・ゴールライン → 固定されたセル → 崩れの予告（[閉じ込めの崩れ](spec/stuck-crumble.md)） → 固定・行消しの光 → 着地位置の枠 → 予告中／落下中のミノ → プレイヤー → HUD・GOAL・「ここまで積むと負け」の文字 → 操作ヒント → スティックの輪・つまみ → Result の重ね表示。プレイヤーが行 0 より上にいるときは、画面の外にはみ出して描かれず見えなくなってよい（クリア済みの高さなので問題にならない）。
- スティックの指がいる間だけ、いまの起点 (ax, ay)（追従で動いたあとの位置）に輪（半径 STICK_RING_RADIUS px）、(ax + dx, ay + clamp(dy)) につまみ（半径 STICK_KNOB_RADIUS px）を描く。dx は追従のあとなので ±STICK_RING_RADIUS に収まっており、dy は −STICK_RING_RADIUS〜+STICK_RING_RADIUS に収める（上へ弾くとつまみが上へ動く）。ジャンプの指（2 本目以降）には、何も描かない。輪・つまみが画面の端で切れて描かれてもよい。画面に左右の区分の色は付けない。

### 演出・UI

見た目と分かりやすさのための表示で、ルールや数値には影響しない。いずれも入力の受け付けを遅らせない。

| 名前 | きっかけ | 見え方 | 消えるとき |
|---|---|---|---|
| GOAL ラベル | 常時（Game Scene のどの局面でも） | ゴールラインの右端に「GOAL」。ライン（黄色）と同じ色、線のすぐ上、右端から 6px 内側 | 消えない |
| 危険域ラベル | 常時 | 危険域の帯の下端のすぐ上に中央揃えで「ここまで積むと負け」。白の薄い文字（透過度 0.35 程度）、小さい文字 | 消えない |
| 操作ヒント | `playing` の開始（リトライの `playing` も含む） | 画面の下端近くに、画面の幅の中央へ 3 行「ドラッグ: 移動」「タップ / 上へ弾く: ジャンプ」「ドラッグ中に 2 本目の指: ジャンプ」（この順に上から）を薄く表示する。キーボードで遊んでいる場合も同じ | `playing` の経過時間が HINT_TIME に達するまで出し、最後の HINT_FADE 秒で直線的に透明にして消す。クリアまたはゲームオーバーで、残りに関わらず消える |
| 固定の光 | ミノが固定されたとき | 固定されたミノの 4 セルを白い光で覆い、LOCK_FLASH_TIME 秒かけて透明にする。同じフレームに行消しがあったときは、行消し後の位置に出す（消える行にあったセルは出さない） | 光が透明になったら。クリアまたはゲームオーバーで切る |
| 行消しの光 | 行が消えたとき | 消えた行（消える瞬間の行の位置）を白い帯で覆い、CLEAR_FLASH_TIME 秒かけて透明にする。2 行以上のときは行ごとに 1 つの帯 | 光が透明になったら。クリアまたはゲームオーバーで切る |
| 結果の揺れ | ゲームオーバー（潰された／積み上がりすぎ）で `Result` が出るとき。クリアでは揺らさない | 盤面（`Game` の画面）を RESULT_SHAKE_TIME 秒、RESULT_SHAKE_INTENSITY の強さで揺らす（Phaser のカメラの揺れ）。`Result` の暗幕と文字は揺らさない | RESULT_SHAKE_TIME 経過で止まる。リトライで `Game` を作り直したとき切れる |

- **時間の数え方**: 光と操作ヒントは、きっかけのフレームを 0 とし、ちょうど決められた時間で消える。時間はラウンドの時計と同じ数え方（1 フレームの経過時間は MAX_DT で頭打ちにして足す）で、長いフレームがあってもラウンドと食い違わない。同じ種類のきっかけがもう一度来たときは、前の光はそのまま続け、新しい光を別に出す（1 つにまとめない）。
- **同じフレームの扱い**: 固定と行消しが同じフレームに起きたときは「固定の光」（行消し後の位置）と「行消しの光」を両方出す。潰れ・積み上がりすぎ・クリアのフレームでは光を出さない（そのフレームから光は描かない）。
- **局面**: リトライ後は光・ヒント・揺れをすべて作り直す（前の run のものは残らない）。
- **結果の間の見え方**: 結果の局面（`Result` の間）は、ラウンドの進行が止まった瞬間のまま。着地位置の枠は向き・列・行も点滅の濃さも、その瞬間のまま止め、スティックの輪・つまみは描かない（`Result` の間に指が触れていても出さない）。
- **重なり**: 光はプレイヤー・ミノより下に描かれる。揺れは `Game` の画面全体（盤面・HUD・ラベル・結果の瞬間に残っているもの）を動かす。揺れの間は盤面の端が動いて背景色が見えてよい。
- **画面の端**: GOAL の右端は盤面の右端から 6px 内側に収める。操作ヒントは、盤面の下端から 3 セル上の高さの中央（3 行の塊が最下 2 行（行 ROWS − 2・ROWS − 1）に掛からない。最下段の着地位置の枠・プレイヤーと重ならない）に、画面の幅（COLS × CELL）の中央で中央揃えにし、幅に収まる大きさの文字にする（論理 16 px 以上。最長の行が幅 360 px に収まる範囲で、これ以上に決める。AGENTS.md 4.6 の補助の文字（実寸 11 px 以上）は、縦の 375 × 550 で満たす。横の 667 × 310 は縮小率が小さく届かないが、ヒントは HINT_TIME で消える補助の表示で、遊ぶのに必要な情報ではないので許容する）。3 行は、1 つの文字の塊として、その高さに縦の中央を合わせる（3 行とも画面の中に収まり、行どうしが重ならない。長い行は折り返さず、文字の大きさで収める。行間・文字の大きさは実装裁量）。HUD の「高さ」と「ここまで積むと負け」は重ならない大きさにする。

## ルール

### 盤面と座標

- 盤面は `COLS × ROWS` のセル格子。行 0 が最上段、行 `ROWS − 1` が最下段。
- 盤面の左右の外側と最下段の下は壁／床（固体）。行 0 より上は何も無い（天井は無く、空間として自由）。
- セルは「空」か「ミノの種類（1〜7）」。空でないセルは固体として扱う。

### プレイヤー

- 大きさは PLAYER_W × PLAYER_H（セル単位）の長方形。座標 (x, y) は左上で、初期位置は盤面の中央・床の上（x = COLS / 2 − PLAYER_W / 2、足が最下段の下端に接する）。
- 1 フレームの経過時間 dt は MAX_DT 秒で頭打ちにする。
- 毎フレーム、先に水平、次に垂直の順に動き、固体セルにめり込んだら手前に押し戻す。
  - 水平: 入力方向 × WALK_SPEED × dt だけ動く。壁・固体セルに当たったらその面に接する位置で止まる。
  - 垂直: 重力 GRAVITY で vy を更新し、vy × dt だけ動く。この移動は SUBSTEP_MAX セル以下の小刻みに分けて判定する（落下が速くても 1 セル厚の固体をすり抜けない）。下向きに当たったら着地（足が固体の上に接する、vy = 0、`onGround`）。上向きに当たったら天井にぶつかったとみなし vy = 0。
  - ジャンプ: ジャンプ入力があり、かつ前フレームの垂直移動の結果が `onGround` なら、そのフレームの重力を足す前に vy = −JUMP_V にする。
- ジャンプで届く高さは約 2.3 セル（JUMP_V² / (2 × GRAVITY)）。段差 2 までは自力で登れるが、3 以上は、ジャンプだけでは登れない（壁蹴りで、向かい合う壁の間なら登れる。壁が片側だけの段差は、壁蹴りを使っても、蹴った壁へは戻れないので 3 以上は登れない）。段差 2 でも、壁際で空中でジャンプを押し直す（連打）と蹴りになり、蹴った壁へ戻れないので、登れないことがある。押しっぱなしなら（壁蹴りにならないので）登れる。
- プレイヤーはミノを押せず、すり抜けもできない。固定されたミノは壁のように扱う。落下中のミノは固体でなく危険物（下記）。
- 穴に落ちて出られなくなったとき、向かい合う壁の間に蹴りで届く穴は、壁蹴りで出られる。蹴りで向かいの壁に届かない穴（幅が広い穴、片側だけが壁の穴）には救済は無い（そのままミノが来て潰されるか、積み上がりすぎで終わる）。ただし、ミノのふたで上下左右が固体に閉じた空間に入ったときだけは、壁が崩れて出口ができる（[閉じ込めの崩れ](spec/stuck-crumble.md)）。手計算の目安（蹴りのあとの入力で歩くことを含む。実測ではない）: 幅 1〜3 の穴（壁の間の隙間 0.3〜2.3）は蹴りと入力で向かいの壁に届き、幅 4 以上（隙間 3.3）は、空中の約 0.54 秒では届かない。

#### 壁蹴り

- **壁に接している**: プレイヤーの長方形の左端から左へ WALL_TOUCH_TOL 以内に、体の縦の範囲（y 〜 y + PLAYER_H）と重なる固体セル（盤面の左右の外側の壁・固定されたミノのセル。縦の重なりは厳密な不等号で、足の下端がセルの上端にちょうど接するだけ、頭の上端がセルの下端にちょうど接するだけでは重ならない）があれば「左の壁に接している」。右端から右へ WALL_TOUCH_TOL 以内なら「右の壁に接している」。「以内」は、体の端と壁の面の間隔 ≤ WALL_TOUCH_TOL + 1e-9（浮動小数点の誤差を許す。境界のテストは、厳密に表せる値か、この許容を含めた値で書く）。体の幅 PLAYER_W と壁の間の隙間の合計は、1 セル幅の穴でも 1 − PLAYER_W = 0.3 > 2 × WALL_TOUCH_TOL なので、左右の壁に同時に接することは無い。
- **蹴れる条件**（すべて成立）: ①前フレームの垂直移動の結果が接地していない（`onGround` でない）、②そのフレームでジャンプを「新しく押した」（操作仕様）、③壁に接している（左か右。上のとおり同時には 1 側だけ）、④その側が「直前に蹴った壁の側」と違う（まだ蹴っていないときは、どちら側でもよい）。判定は、そのフレームの水平移動の前の位置（前フレームまでの結果）で行う。接地しているときは、これまでどおり通常のジャンプ（壁際でも通常のジャンプ。蹴りにはならない）。
- **蹴ったとき**: そのフレームの重力を足す前に vy = −WALL_KICK_VY にする（通常のジャンプの −JUMP_V の代わり）。水平は、壁と反対向き（左の壁なら右、右の壁なら左）の速度 WALL_KICK_VX で動く。「直前に蹴った壁の側」をこの側にする。
- **蹴りの間の水平移動**: 蹴ったフレームを 0 とし、蹴りのあとの n フレーム目（蹴ったフレーム自身は n = 0）の水平移動は、それ以前の n フレームの dt（MAX_DT で頭打ちにしたもの）の合計 t に対して、t + 1e-9 < WALL_KICK_LOCK である間、入力を無視して壁と反対向きの WALL_KICK_VX で動く（60fps で 9 フレーム、動く距離は約 0.6 セル）。t + 1e-9 ≥ WALL_KICK_LOCK 以降は入力どおりに戻る。蹴りの速度で壁に当たったら、通常の衝突と同じく、その面で止まる（蹴りは成立したままで、時間が過ぎるまで入力は無視される）。着地（そのフレームの垂直移動の結果が `onGround`）したときは、そのフレームの垂直移動の終わりに、蹴りの経過時間と「直前に蹴った壁の側」を消す。そのフレーム自身の水平移動（水平が先）は、蹴りの途中なら蹴りの速度のまま。次のフレームの水平移動から入力どおりに戻る（次に空中で接した壁は、どちら側でも蹴れる）。
- **蹴りの間のジャンプ入力**: 蹴りの間も、上の条件を満たせば、また蹴れる（反対側の壁に接したとき）。蹴るたびに、蹴りの経過時間は 0 から数え直す。蹴ったあとに入力を押しっぱなしにしても、「新しく押した」でなければ蹴らない。通常のジャンプのあと、空中で押し直して壁に接していれば、蹴れる。
- **蹴った壁へは戻れない**: 蹴ったあとは、蹴った壁の側（左の壁を蹴ったなら左、右なら右）を「戻れない側」にする。戻れない側があるあいだ、その側への水平入力は、押されていない扱いにする（反対向きの入力はそのまま効く。蹴りの間の水平移動は入力を見ないので変わらない）。ジャンプで届く 2.3 セルの頂点で壁を蹴ると、さらに約 1.5 セル上がって合計約 3.8 セルになり、壁へ歩いて戻ると 3 段の段差に乗れてしまう。それを防ぐ（向かい合う壁の間の登りは変わらない）。戻れない側は、各フレームの垂直移動まで済んだ時点で次の順に決める: ①着地した（`onGround`）なら、なし（蹴りの記憶を消すのと同時）。②そのフレームで蹴ったなら、その壁の側。③そうでなく戻れない側があり、そのフレームの水平・垂直の移動が済んだ位置で反対側の壁に接している（「壁に接している」の判定）なら、なし。④どれでもなければ変わらない。次のフレームの水平入力から効く（蹴ったフレーム自身の水平移動は蹴りの速度）。水平入力の合成は、戻れない側の入力を外してから、左右同時の打ち消しを行う（左を戻れない側にして左右とも押していれば、右だけが残って右へ動く）。③の判定は、そのフレームの固定・行消しの前の位置で行う。戻れない側は「直前に蹴った壁の側」（④）とは別の状態で、③で戻れない側が消えても「直前に蹴った壁の側」は消えない（着地か次の蹴りまで残る。反対側の壁に接すると蹴れるようになるのは、その壁が「直前に蹴った壁の側」と違うからで、同じ側の壁は、反対側の壁を蹴るか着地するまで蹴れない）。蹴りは上向きに跳ぶので、蹴ったフレームに着地することは実質無いが、起きたら①（着地）が先。ラウンドの開始時、戻れない側は無い。空中でミノを避けるとき、戻れない側へは動けない（蹴ったあとに壁の方へ避けられない）。
- **ほかの規則との関係**: 蹴りの上昇・水平移動は、通常の衝突（天井で vy = 0、壁で止まる）に従う。潰れ・固定・行消しの規則は変わらない。行消しによる位置の移動（下げる）は、「直前に蹴った壁の側」・戻れない側・蹴りの経過時間を変えない。壁蹴りには、専用の演出・音・ヒントは無い。

### ミノ

- 7 種類（I・O・T・S・Z・J・L）。各形は 4 セル。回転は 90 度刻みの 4 状態で、回転後は外接矩形の左上を原点に詰めた形として扱う。回転 0 の形:

  | 種類 | 回転 0 のセル（列, 行） |
  |---|---|
  | I | (0,0) (1,0) (2,0) (3,0) |
  | O | (0,0) (1,0) (0,1) (1,1) |
  | T | (0,0) (1,0) (2,0) (1,1) |
  | S | (1,0) (2,0) (0,1) (1,1) |
  | Z | (0,0) (1,0) (1,1) (2,1) |
  | J | (0,0) (0,1) (1,1) (2,1) |
  | L | (2,0) (0,1) (1,1) (2,1) |

  回転 k は (列, 行) → (−行, 列) を k 回適用してから、最小の列・行を 0 に揃えたもの。
- ミノは常に 1 個だけ。固定されてから SPAWN_DELAY 秒後に次の予告が始まる。`playing` の開始からも SPAWN_DELAY 秒後に最初の予告が始まる。
- 種類は 7 種から一様ランダム。着地位置（向きと列）は「着地 AI」が決める。

### 着地 AI

予告の開始時に、盤面と種類から (向き 0〜3, 左端の列) の全候補を評価し、評価点の高い順に並べる。通常は上位 AI_TOP_K 件から一様ランダムに 1 件を選ぶ。確率 AI_MISTAKE_RATE で「ミス」をして、上位 AI_MISTAKE_K 件から選ぶ（完璧な AI だと壁が平らに上がるだけで、足場に段差や隙間ができずクリアしにくいため、意図的に下手に積む）。

- 候補: 向き 0〜3 のすべて（同じ形になる向き、例えば O の 4 向きも別の候補として数える）× 左端の列 0〜「COLS − ミノの幅」。
- 着地行: ミノを盤面の上（外接矩形の上端が行 −4）から真下に動かし、固体にぶつかる直前の行。これでミノの外接矩形の上端行が決まる。行 0 より上のセルは盤面に書き込まない（その候補は、上端が `TOP_OUT_ROW` より上になるので積み上がりすぎの扱い）。
- 着地行の外接矩形の上端が `TOP_OUT_ROW` より上になる候補（積み上がりすぎ）は、評価点を −1,000,000 にする。
- それ以外は、そのミノを置いた盤面（行は消さない）について次で評価する。
  - 評価点 = AI_LINES_W × 揃う行の数 − AI_HOLES_W × 穴の数 − AI_BUMP_W × 凸凹 − AI_WELL_W × 空け列に置くセル数
  - 穴: 各列で、その上にセルがある空セルの数
  - 凸凹: 隣り合う列の高さ（最も上のセルから底までのセル数）の差の絶対値の和。空け列を含む組は数えない
  - 空け列: ゲーム開始時に左端（列 0）か右端（列 COLS − 1）のどちらかを 50% ずつで決め、そのゲームの間は変えない
- 評価点の降順に並べる。同点の候補は、生成順（向き 0→3、各向きで列の昇順）を保つ（安定ソート）。「積み上がりすぎ」でない候補（評価点 > −1,000,000）がある場合、1 個目の乱数 u1（0 以上 1 未満）が AI_MISTAKE_RATE 未満ならミス、そうでなければ通常とする。選ぶ件数 k は、通常なら min(AI_TOP_K, 積み上がりすぎでない候補数)、ミスなら min(AI_MISTAKE_K, 積み上がりすぎでない候補数)（積み上がりすぎでない候補が 1 つも無いときは、全候補を対象に通常の k）。2 個目の乱数 u2 で、並べた候補のうち floor(u2 × k) 番目（0 始まり）を選ぶ。積み上がりすぎでない候補が 1 つも無いときは、ミス判定をせず、通常の選び方で選ぶ（その候補は固定されると積み上がりすぎになる）。
- 着地 AI はプレイヤーの位置を考慮しない。

### 1 個のミノの流れ（進行）

1. **予告**（TELEGRAPH_TIME 秒）: 盤面の最上部（外接矩形の上端が行 0）に、選ばれた種類のミノが現れる。ミノは、最終の向きに向かって、ミノごとに決まる回数（回転数 n = 0〜3）だけ 90 度ずつ回って止まる。
   - **回転数** n = (3 × 種類の番号 + 5 × 選ばれた向き + 7 × 選ばれた列) mod 4。種類の番号は「ミノ」の表の並び（I = 0, O = 1, T = 2, S = 3, Z = 4, J = 5, L = 6）、選ばれた向きは 0〜3、選ばれた列は着地 AI が選んだ左端の列（下記の「寄せる」前の値）。乱数は使わない（着地 AI と `Round` の乱数の並びを変えないため）。同じ予告は同じ回し方になる。手計算の例: Z（4）・向き 2・列 1 → 12 + 10 + 7 = 29 → n = 1。T（2）・向き 1・列 4 → 6 + 5 + 28 = 39 → n = 3。I（0）・向き 0・列 0 → n = 0（回らず、最初から最終の向き）。O（1）・向き 2・列 5 → 3 + 10 + 35 = 48 → n = 0。L（6）・向き 3・列 2 → 18 + 15 + 14 = 47 → n = 3。
   - **回る時刻**: 予告の開始からの経過時間 t（秒）で、n 回の回転が起きる時刻をパラメータ表の `ROTATE_TIMES`（n = 1: 0.30、n = 2: 0.20・0.45、n = 3: 0.14・0.34・0.60）で決める（後ろの回転ほど間隔が長く、止まる前に減速して見える）。回転は、t が回る時刻以上になった瞬間に起きる（浮動小数点の誤差で、ちょうどの時刻の回転が遅れないよう 1e-9 の余裕を持たせる）。どの n でも最後の回転は 0.6 秒（予告の開始から）までに終わる。回転は、向きが瞬間に 90 度切り替わる（補間しない）。
   - 残りの回転数 = n − （t までに起きた回転の数）。表示する向きは「選ばれた向き − 残りの回転数」（4 を法とする）。t = 0 では「選ばれた向き − n」で、最後の回転の後は最終の向きになり、予告が終わるまでその形で止まる。n = 0 のミノは、最初から最終の向きで止まっている。見た目が変わらない回転（O の回転など）は、見た目の変化が無いだけで、時刻は同じ。表示する列は、その向きの幅で盤面からはみ出すときは、はみ出さない最も右の列に寄せる。着地位置を示す、ミノと同じ形の点滅する枠を表示する。**予告の間、枠は表示中のミノに追従する**: 枠の形と列は、その時刻の表示の向きと表示する列で、行は、その形をその列の盤面の上（外接矩形の上端が行 −4）から真下に落としたときに止まる行（着地 AI が候補の評価に使う着地行と同じ計算。盤面は、そのフレームの現在の盤面。t < 0.6 の間だけこの計算を使い、t ≥ 0.6 は予告中に[閉じ込めの崩れ](spec/stuck-crumble.md)で盤面が変わっても、着地 AI が選んだ着地行（`plan.row`）をそのまま使う）。回転のたびに、枠の形・列・行がミノと同時に切り替わる（補間しない）。どの n でも t = 0.6 以降の枠は、最終の向き・選ばれた列・着地行（着地 AI が選んだ位置）で、落下中も固定されるまでそのまま。n = 0 は最初から最終の位置。途中の形が盤面の上で止まれない（着地行が行 0 より上になる）ときは、画面の外にある行のセルは描かない。この枠は予告の開始から、ミノが固定される（または潰れで終わる）まで出し続け、SPAWN_DELAY の間は出さない。枠は予告中の表示の向きが変わるまで最終の位置を教えないので、最終の着地位置が分かるまでの猶予は、n = 0 が 0.9 秒、n = 1 が 0.6 秒、n = 2 が 0.45 秒、n = 3 が 0.30 秒（最後の回転の時刻から TELEGRAPH_TIME まで。平均 0.5625 秒。枠が最終に固定の仕様より短い）。予告中のミノは何にも当たらない（プレイヤーは潰れない）。
2. **落下**: 予告が終わると、最終の向き・選ばれた列で外接矩形の上端が行 0 から、DROP_SPEED セル/秒で落ちる。1 フレームの移動は SUBSTEP_MAX セル以下の小刻みに分けて判定する（すり抜けない）。落下中のミノの各セルとプレイヤーの長方形が（辺が接するだけでなく）重なったら、その時点で「潰された」。
3. **固定**: 下に固体があって進めなくなったら、最後の小刻みな移動を着地行（整数の行）に揃え、その位置でも潰れの判定をしてから（重なれば「潰された」）、その位置で固定してセルを盤面に書き込む。固定された外接矩形の上端が `TOP_OUT_ROW` より上なら「積み上がりすぎ」。同じ固定で潰れと積み上がりすぎが両方成立したら「潰された」を優先する。
4. **行消し**: 固定後に、横一列が埋まった行をすべて消し、その上の行を（消えた行数ぶん）下げる。プレイヤーは、足場に立っていても空中にいても、**瞬間移動させない**（位置・速度を保ち、積み重ねだけが下がる。足場が下がったぶんは、重力で自然に落ちる）。ただし、動かさないと、下がってきた積み重ねのセルとプレイヤーの長方形が重なる場合（頭上の張り出しが降りてくるとき）だけは、プレイヤーを下へ動かす（重なって埋まるのを防ぐ）。
   - 重なりの判定は、行消しのあとの盤面に対して、プレイヤーの長方形を現在の位置のまま、1 回だけ行う（複数行が同時に消えたときも、全行を消したあとの盤面で 1 回）。重なりは厳密な不等号で、許容値（GOAL_TOL）は使わない（辺が接するだけなら、頭・足・横のどれでも重ならない）。浮動小数点の誤差を吸収する 1e-6 程度の内部の微小値だけは使ってよい。
   - 動かす量は、足の下端 ≤ 消えた行の上端 + GOAL_TOL を満たす消えた行の数（足より下にある行だけを数える）だけのセル。プレイヤーより上にある消えた行は数えない。数が 0 なら動かさない。重なりを解く最小量ではなく、この数ちょうど。
   - 動かすのは位置だけ。速度（vy）と `onGround` は変えない（上昇中のジャンプはそのまま続く）。
5. SPAWN_DELAY 秒後に次の予告へ。

同じフレームでの処理順: プレイヤーの更新（このあとゴール到達を判定して覚えておく）→ ミノの進行（潰れ・固定・積み上がりすぎ・行消し）→ クリア判定（プレイヤーの更新で覚えた到達だけで決まる。行消しでプレイヤーが下へ動かされても取り消されない。行消しでプレイヤーが上へ動くことは無い）→ 崩れの進行（ラウンドが続いているときだけ。[閉じ込めの崩れ](spec/stuck-crumble.md)）。ミノの進行でゲームオーバーの条件が成立したら、クリア条件が同時に成立していてもゲームオーバー。

### クリア・ゲームオーバー・スコア

- **クリア**: プレイヤーの足の下端（y + PLAYER_H）が、ゴール行の上端（`GOAL_ROW`）以上の高さに達する（y + PLAYER_H ≤ GOAL_ROW + GOAL_TOL）。ジャンプの頂点でもよい（足場の高さ 13 段にジャンプが加われば届く）。
- **ゲームオーバー**: ①落下中のミノに潰される、②ミノの固定位置が「積み上がりすぎ」になる。
- **スコア**: 無し。クリアしたか、しなかったか（しなかったときは敗因と到達した最大の高さを表示するだけ）。時間・ベストタイム・記録の保存はしない（着地 AI の積み方に左右されるので、腕前の指標にならない）。

### HUD

- 左上に「高さ 7 / 15」（n / (ROWS − GOAL_ROW)）を表示する。時間は表示しない。
- 高さ n は、floor((ROWS − プレイヤーの足の下端) + GOAL_TOL) を 0 以上にしたもの。床に立っていれば 0。ゴール行に足が届いた（クリアした）ときだけ ROWS − GOAL_ROW になる。空中（ジャンプの頂点など）も、その瞬間の足の位置で計算する。ゲームオーバーで表示する「到達した最大の高さ」は、`playing` 中の全フレームの n の最大値。

| STICK_KNOB_RADIUS | 18 | スティックのつまみの半径（論理 px） |
| TAP_MAX_TIME | 0.25 | タップとみなす、触れてから離すまでの最長時間（秒）。これを超える長押しは何も入力しない |
| TAP_SLOP | 10 | タップとみなす、触れた位置からの最大の動き（論理 px の直線距離）。STICK_DEADZONE と同じ値（移動の入力が出ない範囲＝タップの範囲）。制約: TAP_SLOP ≤ STICK_DEADZONE（動かないタップが移動入力にならないため） |
| TAP_JUMP_HOLD | 0.1 | タップの離れたあと、ジャンプ入力が入っている時間（秒）。1 フレームの長さより長く、通常のジャンプの空中時間より十分短い長さ。着地の 0.1 秒以内に空中でタップすると、パルスが着地をまたいで再ジャンプする（押しっぱなしと同じ。許容する） |

| CLEAR_FLASH_TIME | 0.2 | 行消しの光の時間（秒） |
| RESULT_SHAKE_TIME | 0.2 | ゲームオーバー時の揺れの時間（秒） |

AI の重み・ミスの確率（`AI_*`）は、プレイヤーがいない場合の模擬（各 200 回）で「約 43 個目で高さ 15 に届き、約 70 個目で積み上がりすぎ、行消しが約 13 行」になる値として決めた。ミス 0 では約 56 個目・約 98 個目・約 24 行（段差・隙間が少なく壁が平らに上がる）。ミス 0.1 / K=∞（どの候補でも）だと約 34 個目・約 54 個目・約 7 行で、登れる時間の余裕が短すぎた。登れる時間の余裕と、行消しの起きやすさを左右する。

## テスト観点

純粋ロジックの単体テスト（境界値を含む）:

- ミノの形: 7 種 × 回転 0〜3 のセルが外接矩形の左上 (0,0) に詰まり、4 セルで、回転 4 回で元に戻る。O は全回転で同形。
- 盤面の固体判定: 左右の外・最下段の下は固体、行 0 より上は空。
- 着地行: 何も無い盤面で床に接する。固体の上で止まる。ミノの幅いっぱい／壁際の列でも正しい。
- ミノの落下: DROP_SPEED × MAX_DT（2 セル）の 1 回の移動で、1 セル厚の固体を飛び越えない。固体の直前で固定される。プレイヤーが落下途中の経路上にいれば、途中のセルで潰れが成立する。辺が接するだけなら潰れない。
- 固定: 書き込まれるセルが正しい。外接矩形の上端行が `TOP_OUT_ROW − 1` なら積み上がりすぎ、`TOP_OUT_ROW` なら正常。
- 行消し: 1 行・複数行（離れた行／連続した行）が消えて上が詰まる。何も揃わなければ変化しない。
- 行消しとプレイヤー（瞬間移動しない）: 足場に立っていて足が消えた行の上にいても、積み重ねが下がって体が重ならないなら、位置も速度も変わらない（その後の重力で落ちる）。空中でも同じ。
- 行消しと張り出し: 頭上の張り出し（消えた行より上のセル）が下がると体に重なるときだけ、消えた行数ぶん下がる。ちょうど接するだけ（重ならない）ときは動かない。複数行が同時に消えたときも同じ。足が消えた行より下にいるときは、重ならないので動かない。足の下端が「消えた行の上端 + GOAL_TOL」ちょうどでも、重ならなければ動かない。
- 足場が下がったあとの落下: 立っていたプレイヤーは次の更新から重力で落ち、足場の上に着地する。
- 行消しと張り出しの手計算例（PLAYER_H = 0.9、行消し後の盤面で、プレイヤーは x = 4.65 で列 4・5 の範囲）: ①行 10 の列 4 にセルがあり、プレイヤーが y = 9.6（体は 9.6〜10.5）、消えた行が行 16 のとき、体が行 10 のセルと重なるので 1 セル下の y = 10.6 へ動く。②同じ盤面で足の下端がちょうど 10.0（y = 9.1）のときは、接するだけなので動かない。③消えた行が行 16 と 17 のときは 2 セル下の y = 11.6。④消えた行が行 5 と行 16 で、足の下端 10.5 のとき、足より下にあるのは行 16 だけなので 1 セル（行 5 はプレイヤーより上）。⑤同じフレームに、プレイヤーの更新でゴールに届いていて、張り出しで下へ動かされても、クリアのまま。
- スティック: dx = −STICK_DEADZONE ちょうどと +STICK_DEADZONE ちょうどは入力なし、その外側 1px で左／右。画面のどこ（左端・中央・右端）に触れた 1 本目の指も、同じ規則でスティックになる。2 本の指があるときは先に触れた方だけがスティック、後の指はジャンプの指。
- スティックの追従（起点 (100, 600)、STICK_RING_RADIUS = 28、STICK_DEADZONE = 10 の手計算例）: ①指が x = 128 なら起点は動かず dx = 28（右）。x = 129 なら起点は ax = 101 に動き dx = 28。②x = 200 まで動かすと ax = 172（dx = 28）。そこから x = 162 まで戻すと dx = −10 で入力なし（38 px 戻した）、x = 161 で dx = −11 で左（39 px）。③左側も同じ: 起点 (100, 600) で x = 72 なら起点は動かず dx = −28、x = 71 なら ax = 99 で dx = −28。④縦は、y = 628 なら ay は動かず dy = 28、y = 629 なら ay = 601 で dy = 28。上は、y = 560 まで動かしても ay は動かず dy = −40（上には追従しない）。⑤追従で起点が動いても（画面の端でも）、その指はスティックのまま。⑥1 回のフレームで指が大きく飛んだ（x = 100 → 300 など）ときも、追従したあとの dx = 28 で判定され、右になる。
- スティックの上への弾き（起点 (100, 600)、STICK_JUMP_FLICK = 28、STICK_JUMP_RELEASE = 14。ジャンプ状態は触れた時点で「入っていない」）: ①y = 572（dy = −28）ではまだ入らない、y = 571（dy = −29）で「入っている」。②「入っている」の途中で y = 585（dy = −15）は「入っている」のまま、y = 586（dy = −14）で「入っていない」に戻る。③戻したあとに y = 571 へ弾き直すと、また「入っている」（壁蹴りの「新しく押した」になる）。上に出したままの間は、合成後のジャンプ入力は入ったまま（着地ごとの再ジャンプ）。④横の移動と同時: dx = 20、dy = −30 なら、右とジャンプが同時に入る。dx = 5、dy = −30 は移動なしでジャンプのみ。⑤縦に追従したあと（y = 629 で ay = 601）は、新しい起点から −28 を超えて（y < 573）弾いたときだけ入る。⑥指を離すと状態が消え、次に触れた指は「入っていない」から始まる。⑦ジャンプの指でジャンプが入っているときにスティックを弾いても、合成後のジャンプは入ったままで「新しく押した」にならない（蹴りにならない）。ジャンプの指を離してもスティックが「入っている」なら、ジャンプ入力は途切れない。キーのジャンプも同じ（OR）。⑧「離すまで無効」の指（開始・リトライに使った指、結果画面の間に触れた指）は、上に弾いてもジャンプにならない。
- タップ（TAP_MAX_TIME = 0.25、TAP_SLOP = 10、TAP_JUMP_HOLD = 0.1。触れた位置 (100, 600)）: ①0.25 秒ちょうどで離すとタップ、0.26 秒では何も入らない。②離すときの位置が (110, 600)（距離 10 ちょうど）ならタップ、(111, 600) や (100, 589) なら対象外。途中で (130, 600) まで動いて (100, 600) へ戻してから離しても対象外。③タップのジャンプは離れたフレームで入り、0.1 秒ちょうどで切れる（離れたフレーム 0 のとき、0.09 秒までは入り、0.1 秒で切れる）。入った瞬間は「新しく押した」になり、壁に接した空中なら蹴れる。④2 本目の指が触れたことのある 1 本目の指は、離してもタップにならない（2 本目の指がジャンプを入れている）。⑤長押し（触れたまま 1 秒など）は何も入力しない。⑥1 フレームより短いタップ（押下と解放の間に読み取りが無い）も、離れたあとの最初の読み取りで、タップとして入る。⑦弾き（ジャンプ状態が「入っている」になった指）は、離してもタップのジャンプを足さない（離れる前から入っていたジャンプが、離れて切れるだけ）。⑧開始・リトライに使った指（離すまで無効）のタップはジャンプにならない。タップで Title の START・結果画面のリトライが始まった直後は、その指の離れるタイミングでジャンプが入らない。⑨時間は dt の足し合わせ: 1/60 秒のフレームで 15 回足した 0.25 ± 1e-9 以内はタップ、16 回（約 0.2667）は対象外。⑩パルスの途中（離れて 0.05 秒後）に次のタップが離れたら、そこから 0.1 秒に取り直す（延長でも二重でもない。「新しく押した」にならない）。⑪ジャンプの指が先にいて（スティックの指が離れたあと）新しく触れた指は、その指が触れている間に新しいジャンプの指が触れなければ、タップになる（先にいたジャンプの指は数えない）。⑫キャンセル（指の消失）はタップにならない。マウスの主ボタンのクリックは、タップと同じに入る。
- 2 本目の指: スティックの指がいる間に別の指が触れると、触れている間ジャンプ入力が入る（位置は問わない）。2 本目の指だけが先に離れても、スティックの移動は続く。スティックの指が先に離れても、2 本目の指が離れるまでジャンプは入ったまま（このとき新しく触れた指は、スティックの指がいなければスティックの指になる）。3 本目の指もジャンプの指。4 本目は扱わない。
- タッチの回帰（変えないもの）: ①キー（←/→/A/D、↑/W/スペース）の移動とジャンプは、スティックの有無に関わらず従来どおり。②スティックの左とキーの右を同時に入れると、打ち消し合って止まる。③同時に扱う指は 3 点まで。4 本目は扱わず、無視される指も数に入る。④スティックの指は、追従で起点が動いても、最初に触れた 1 本だけ。⑤触れただけ（動かさず、タップにもならない長押し）では、移動もジャンプも入らない。
- ヒント: 文言が「ドラッグ: 移動」「タップ / 上へ弾く: ジャンプ」「ドラッグ中に 2 本目の指: ジャンプ」の 3 行であること。3 行の塊の縦の中心が、盤面の下端から 3 セル上にあり、塊の下端が最下 2 行の上端（盤面の下端から 2 セル上）より上にあること。論理幅 360 で、3 行とも幅（360 px）に収まり、行どうしが重ならないこと。HINT_TIME・HINT_FADE の消え方は変わらないこと。論理座標の範囲外（x < 0、x > 360 など）へ動いた指も、同じ規則で追従する（pointer の位置は論理座標に直した値を使う）。
- 開始・リトライの入力: 押しっぱなしのまま RETRY_LOCKOUT が過ぎてもリトライしない（押した瞬間だけ受け付ける）。`playing` の開始時に既に押されているキー／指（リトライに使ったもの、結果画面の間に押したもの、押しっぱなしの移動キー）は、離すまで移動・ジャンプ・スティックの起点にならない（スペースを押したままリトライした直後にジャンプしない）。離したあとに押し直せば有効。無視されている指は、あとからスティックにならない。
- プレイヤー: 壁際で止まる。MAX_DT でも落下速度が最大（行 0 の上から落ちるなど）の状態で、1 セル厚の固体の上に着地する（すり抜けない）。段差 2 のセルの上に跳んで乗れる（ジャンプは押しっぱなしにするか 1 回だけ押す。空中で押し直すと壁蹴りになる）。段差 3 には（ジャンプだけでは）乗れない。壁に接していない空中でジャンプを新しく押しても跳べない。押しっぱなしで着地ごとに再ジャンプ。左右同時入力で止まる。天井にぶつかって vy が 0 になる。dt が大きくても MAX_DT で頭打ち。
- 壁蹴り（接触と許可）: 体の端と壁の面の間が WALL_TOUCH_TOL ちょうどなら接している、WALL_TOUCH_TOL + 0.01 なら接していない（左の壁・右の壁・固定されたミノの側面・盤面の外側の壁のそれぞれ）。体の縦の範囲に重ならない（足の下だけ・頭の上だけにある）セルでは接しない。接地中のジャンプは壁際でも通常のジャンプ（vy = −JUMP_V）で、蹴りにはならない。空中で、壁に接していて新しく押したとき蹴れる。押しっぱなし（前フレームも入っている）では蹴れない。別のキーを足しても新しく押したことにならない。
- 壁蹴り（速度と時間）: 蹴ったフレームの vy が −WALL_KICK_VY、水平が壁と反対向きに WALL_KICK_VX。蹴ったフレームの水平入力（左右とも）は無視される。60fps（dt = 1/60）で、蹴ったフレームから 9 フレーム（t = 0〜8/60）は蹴りの速度、10 フレーム目（t = 0.15）から入力どおり。dt が MAX_DT で頭打ちになる大きいフレームがあっても、dt の合計で数える。
- 壁蹴り（制限）: 左の壁を蹴ったあとは、空中のまま左の壁にまた接しても蹴れない。右の壁に接すると蹴れる。右を蹴ったあとは左に接すると蹴れる。着地すると、どちらの側でも蹴れる状態に戻る。蹴りの間に反対側の壁に接した（0.15 秒の間でも）なら、すぐ蹴れる。
- 壁蹴りの手計算例（PLAYER_W = 0.7、1 セル幅の穴。左の壁の面は x = 4、右の壁の面は x = 5。WALL_KICK_VY = 10.88、WALL_KICK_VX = 4、dt = 1/60）: ①体が x = 4 + 1e-6（左の壁に接している）の空中で、ジャンプを新しく押すと、そのフレームの vy は −10.88 + 40/60 = −10.2133…（重力を足したあと）、水平は右へ 4/60 ≈ 0.0667 動く（x ≈ 4.0667）。②右の壁（x = 5）までの隙間は 5 − 0.7 − 4 = 0.3 なので、約 5 フレームで右の壁に接し、そこで止まる（x = 5 − 0.7 − 1e-6）。③その時点で、ジャンプを新しく押す（押し直す）と、今度は右の壁に接しているので、左向きへ蹴れる。押しっぱなしのままなら蹴れない。④蹴ったあとに着地して、また同じ壁に空中で接したときは、どちら側でも蹴れる。
- 壁蹴りの戻れない側: 左の壁を蹴ったフレームの次のフレームから、左入力は押されていない扱い（右入力は効く。左右とも押していれば右だけ）。右の壁を蹴ったときは右入力が無視される。戻れない側は、着地で消える。空中で反対側の壁に接した（そのフレームの移動が済んだ位置で）フレームで消え、次のフレームから、その側への入力が効く。蹴ったフレームでは、反対側の壁に接していても消えない（その側を戻れない側にする）。幅の広い 3 段の段差（右半分が高さ 3 の固体）の左端に立って、ジャンプ→空中で押し直して蹴る→右入力を押し続ける、を、押し直す時刻と蹴ったあとの入力を変えて繰り返しても、段差の上に着地できない。ランダム入力の分布（0 回の検査）: シード固定の乱数で 20,000 回。始まりの x は 1〜4.3 の一様乱数、右半分（x ≥ 5）が高さ 3 の固体。1〜8 フレームごとに入力を引き直す（左 30%・右 70%・ジャンプ 60%、それぞれ独立）。150 フレームで打ち切り、`onGround` で足の下端が段差の上端（行 17 の上端）にあり、体が x = 5 をまたぐ（x + PLAYER_W > 5.05）なら成功。0 回であること（旧の物理では約 33%）。
- 壁蹴りの戻れない側の手計算例（PLAYER_W = 0.7、WALK_SPEED = 5、dt = 1/60。壁が片側だけの空中）: ①左の壁（x = 4 の面）に接した空中で蹴る（フレーム 0）。フレーム 0〜8 は入力を見ず右へ 4/60 ずつ。フレーム 9 から左入力（右は押さない）は無視されて x は変わらない。右入力なら 5/60 ≈ 0.0833 ずつ右へ。②①で左右とも押していれば、フレーム 9 から右へ 0.0833 ずつ（右だけが残る）。③幅 3 の穴（左の壁の面 x = 4、右の壁の面 x = 7）で左を蹴って右へ歩き、フレーム k の末尾に右の壁に接したとする。フレーム k + 1 から左入力は効く（左へ 0.0833）。接する前のフレームでは効かない。④空中で戻れない側が左のまま着地したフレーム f の末尾で消え、フレーム f + 1 から左入力が効く（f 自身の水平移動は蹴りの途中なら蹴りの速度）。幅 1・幅 2・幅 3 の穴（深さ 6）を蹴りで登れることは変わらない。
- 壁蹴りと他の規則: 蹴りの上昇が天井に当たったら vy = 0（蹴りは成立し、記憶は残る）。蹴りの水平が壁に当たったら止まる。行消しでプレイヤーが下に動かされても、直前に蹴った壁の側と蹴りの経過時間は変わらない。
- 壁蹴りの統計（模擬）: `Round` に対して、デモのボット（`demoBot`）の入力に、「囲まれたときだけ次の動きを重ねる」単純なボットを使い、シード 1〜60 の 60 回、1/60 秒刻み、上限 300 秒。囲まれた判定は 6 フレームごと: プレイヤーのいるマス（体の中心のセル）から、歩き（同じ行の隣の空きマスへ。足場が無いマスは足場まで落ちる）と、最大 2 行上へ上がってからの横移動で届く「立てるマス（空きマスで、すぐ下が固体か床）」の数が 3 以下で、かつそのうちもっとも高いマスが、積み重ねのもっとも高い列の高さより 3 段以上低いとき。動き: 囲まれている間は、接地中はジャンプを入れ、横は直前に蹴った壁と反対向き（まだ蹴っていないときは、盤面の近い側の壁へ）。空中では、壁に接していて蹴れる条件（①〜④）を満たすフレームにだけジャンプを入れる（そのフレームの前のフレームでは入れない）。囲まれている時間の割合は、1 走りごとに「囲まれていた判定（6 フレームごと）の数 ÷ 判定の総数（走りの終わりまで）」を出し、60 走りの平均を取る。「囲まれた状態から出られた回数」は、判定が 真 → 偽 に変わった回数の 60 走りの合計。「壁蹴りが成立した」は、プレイヤーの更新の結果から読める（技術要件）。囲まれた状態では、デモのボットの「ミノを避ける」動きより、この動きを優先する。次を満たす（旧の物理 = 壁蹴りが無い物理での値も同じ模擬で測った。「戻れない側」を入れた物理でも、実測値は同じ: 26 回・4.7%・47 走り・60 回。このボットは蹴った壁と反対向きへ動くので影響しない）: 囲まれている時間の割合の平均が 10% 以下（実測 4.7%、旧 23.5%）、クリアが 20 回以上（実測 26、旧 11）。空振りの検査: 壁蹴りが成立した走りが 1 走り以上（実測 47 走り）、囲まれた状態から出られた回数が 1 回以上（実測 60 回）。
- デモのボットは蹴らない: デモのボットが出すジャンプ入力は、接地しているフレームだけである（シード固定の 40 走りで、デモのボットの入力が空中で「新しく押した」にならない。壁蹴りが 1 回も成立しない）。デモの走りの結果（終わるフレーム・到達高さ）は、壁蹴りが無かった物理と同じになる（比べる基準は、テスト専用の「壁蹴りを無効にする」オプションで走らせた結果。同じシードで一致する）。
- 壁蹴りの入力の事例: `playing` の最初のフレームでは、前フレームは入っていない扱いで、空中で壁に接していれば（始まる位置では接地しているので、ほぼ起きないが）新しく押したことになる。ジャンプのキーを押したまま別のジャンプのキー（またはタッチ）を足しても、新しく押したことにならない。離すまで無効のキーを押したままのときは、そのキーはジャンプ入力に入らず、別の有効なキーを新しく押せば蹴れる。着地フレームで蹴りの途中なら、そのフレーム自身の水平移動は蹴りの速度で、次のフレームから入力どおり。蹴りに専用のヒント・演出は無い（ヒントの文言以外は変わらない）。
- 着地 AI: 穴ができる置き方より穴ができない置き方を選ぶ。空け列に置かない（他に選択肢があるとき）。`TOP_OUT_ROW` 未満になる候補は選ばれない（他に候補があるとき）。通常の選び方では、乱数が 0 のとき最上位（同点は生成順で先）、乱数が 1 に近いとき AI_TOP_K 番目を選ぶ。ミス判定の乱数が AI_MISTAKE_RATE 未満ならミス（AI_MISTAKE_K 番目までから選ぶ）、以上なら通常。積み上がりすぎになる候補は、ミスでも選ばれない（他に候補があるとき）。候補数が AI_TOP_K や AI_MISTAKE_K 未満でも落ちない。
- 着地 AI の統計（模擬）: 種類を一様ランダムに選び、プレイヤー無しで、1 個ずつ固定して行消しを毎回行う模擬を、シード 1〜30 の 30 回（空け列は左右半々）、1 回あたり最大 500 個まで行う。高さは「いちばん上のセルから床まで」の行数。平均の「積み上がりすぎまでのミノ数」が 50〜100 個、消えた行の合計の平均が 8 行以上、高さが 15 以上になるまでのミノ数の平均が 60 個以下で、かつ「高さ 15 以上に届く前に積み上がりすぎになる」回が全体の 5% 以下であること（初期値はそれぞれ約 70・約 13・約 43・0%。高さ 15 に届かない回は 500 個として数える。ミス確率 0 の場合との差をテストに含める: ミス 0 のほうが段差の少ない壁になり、行消しの平均が多い）。
- 予告の表示: 回転数 n は (3 × 種類 + 5 × 向き + 7 × 列) mod 4（手計算: Z・向き 2・列 1 → 1、T・向き 1・列 4 → 3、I・向き 0・列 0 → 0、O・向き 2・列 5 → 0、L・向き 3・列 2 → 3。同じ種類・列で向き 0〜3 を変えると、n が 0〜3 の 4 通りすべて出る）。t = 0 で「最終 − n 回転」。n = 3 は、t = 0.14（浮動小数点の誤差を含めてちょうど）で 1 回目、0.34 で 2 回目、0.60（ちょうど）で 3 回目が起きて最終の向き。n = 2 は 0.20・0.45、n = 1 は 0.30、n = 0 は最初から最終の向き。各回転の直前（0.14 − 1e-3 など）はまだ起きていない。どの n でも t = 0.6 以降は最終の向き。回転の間の向きは「最終 − 残りの回転数」。幅がはみ出す向きでは右に寄せる。回転数の決定は乱数を使わず、同じ入力で同じ結果を返す。最終の向き・列、および t ≥ 0.6 の枠の位置は、今までと同じ。
- 予告の枠: 予告の開始から固定までの間だけ表示され、SPAWN_DELAY の間は表示されない。予告中は表示の向き・列に追従する: 枠の形・列は `telegraphView` の結果と同じで、行はその形をその列で行 −4 から真下に落とした着地行。手計算の例（空の盤面、ROWS = 20）: I・最終の向き 0・列 0・n = 0 → 全時刻で枠は横 4 の形・列 0・行 19。I・最終の向き 0・列 3・n = 1（7 × 3 mod 4 = 1）のとき、t = 0.29 は向き 3（最終 − 1 回転。縦の形）で、その形の着地行（縦 4 セルの外接矩形の下端が行 19）、t = 0.30 以降は向き 0（横）で行 19。n = 3 のとき、枠の向きは t = 0.13 が「最終 − 3」、0.14 が「最終 − 2」、0.34 が「最終 − 1」、0.60 が最終の向きで、0.60 以降は最終の向き・選ばれた列・着地行（`plan.row` と一致）。幅がはみ出す向きでは、枠の列もミノと同じく右に寄る。途中の形が着地できない列（上まで積み上がっている）では、画面の外の行のセルを描かない。最終の位置（t ≥ 0.6）では、どの盤面でも（予告中に崩れが起きて盤面が変わっても）枠の位置が着地 AI の選んだ位置（`plan.row` を含む）と一致する。シードを固定した走りで、枠の追従の前後に `flow.plan`・`Round` の乱数の消費・終わるフレームと状態・到達した高さが同じであること、デモのボットが読む位置が最終の位置のままであること（同じ入力でボットの出力が同じ）も確かめる。

- 予告の回し方（追加）: ミノごとの回転数 n（0〜3）と回る時刻 `ROTATE_TIMES` のとおりに回り、どの n でも 0.6 秒までに最終の向きで止まる（テスト観点の手計算例のとおり）。回転数は乱数を使わず、種類・向き・列から決まる。枠が表示の向き・列に追従することで、最終の着地位置が分かるまでの猶予が縮む（n = 0〜3 で 0.9 / 0.6 / 0.45 / 0.30 秒。意図した難しさの変更）。次は変わらない: 最終の向き・選ばれた列・最終の着地行（t ≥ 0.6 の枠の位置）、予告の長さ（TELEGRAPH_TIME 0.9 秒）、ROTATE_TIMES、落下の時機、着地 AI、`Round` の乱数の並び、潰れ・固定・行消し・クリア・積み上がりすぎの判定、操作の感触、Title とデモの走りの結果（デモのボットは予告中の表示の向きを使わず、最終の位置を見る。ボットの品質のしきい値も同じ）、レイアウト・HUD、枠の点滅の周期・濃さ・色・描画順。枠の追従で、`Round` の状態（`flow.plan`）は変わらない（追従は表示の計算だけ）。参考の測定値（デモのボットで 120 シード、DEMO_RUN_MS の走り）: ボットに表示中の位置だけを見せても、最終の位置を見せても、生き残り 93・負け 27・到達した高さの中央値 8 で同じ（ボットは反応が一瞬なので猶予の短縮に影響されない。人の難しさは測れない）。

## 実装裁量

仕様に書かず、実装側で決めてよいもの:

- 色（背景、7 種のミノ、プレイヤー、危険域の帯、点滅する枠、スティックの輪・つまみ）。ミノの種類が区別でき、プレイヤーとミノが見分けられること。
- フォント・文字サイズ・HUD 以外の文字の縁取り・HUD 内の並び順と余白、結果画面の重ね表示の暗さ・透過度。
- ソースコードのモジュール構成・ファイル名・クラス名。
- 描画方法（Graphics の毎フレーム描き直しか、図形オブジェクトの再利用か）。
- 内部の表現（セルの値の型、ミノ内部の座標形式）。
- 予告中の枠の点滅の周期と濃さ。
- 演出の色・文字の大きさ・フォント・透過度の細かい値（GOAL、危険域ラベル、操作ヒント、光）、光が透明になっていくときの曲線（t = 0 で最大、t = D でちょうど 0、その間は単調に減るなら、直線でなくてもよい。操作ヒントの消え方だけは直線に固定）、光の矩形の大きさ（セルより 1〜2px 小さくしてよい）。
- キー入力の捕捉方法（`addKeys` / `createCursorKeys` など）。
- スティックのつまみの縦の見せ方の細部（輪・つまみの色や濃さ）、操作ヒントの 3 行の行間・文字の大きさ。短いタップを取りこぼさないための押下・解放の持ち方（時間の基準は「タップ」の規則で固定）。
- 壁蹴りの内部状態の持ち方（直前に蹴った壁の側・蹴りの経過時間・前フレームのジャンプ入力を、プレイヤーの状態に持つか、別のオブジェクトに持つか）。壁に接している判定の実装方法（隣のセルを調べる、位置をずらして重なりを調べる、など。結果が上の規則と同じなら何でもよい）。
