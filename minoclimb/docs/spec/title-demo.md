# Title とデモプレイ

## 概要

最初の画面に Title（ゲーム名・START と、ボットが本物の `Game` と同じルールで遊ぶデモの小窓）を置く。デモは文字やボタンと重ならない小窓に縮小して表示する。ルール・数値・操作・着地 AI は変えない。これまで `Game` の `ready` 局面が担っていた「ゲーム名・開始の待ち」は Title に移り、`ready` 局面は無くなる（操作の説明はゲームが始まってからのヒントで出す）。

## 操作仕様

- デモは操作を受け付けない（Title の上でのドラッグ・ジャンプのキーはデモを動かさない）。
- 開始: スペース / Enter、または画面のどこかをタップ（クリック）。START ボタンの上でなくてもよい（ボタンは目印）。押した瞬間だけ受け付ける（押しっぱなしで来たキー・指では始まらない）。開始の要求は最初の 1 回だけ有効で、受け付けたあとの入力は無視する。
- 開始に使ったキー／指は、`Game` が始まったあと、離すまでゲーム入力（移動・ジャンプ・スティックの起点）にならない（現在の仕様と同じ。`Game` の「ゲーム入力として有効になる入力」のとおり）。
- Title が使うキー（スペース・Enter）のリスナーは、Title が終わったとき（`shutdown`）に解除する。ページのスクロールを止めるための捕捉（矢印・スペース）はゲーム全体で共有されるので、Title が終わっても残してよい（`Game` が同じ捕捉を使う）。
- Title に何秒いても、開始したあとの `Game` はいつも最初の状態から始まり、持ち時間や経過時間は削られない（`Game` の進行は `delta` で数えていて、`this.time.now` を使わない）。

## 画面・Scene 構成

| Scene | 役割 |
|---|---|
| `Title` | 最初に表示する。ゲーム名と START と、デモの小窓（枠つき・幕つき）を置く。`Demo` を起動して小窓に流す。開始で `Demo` を止めて `Game` を始める |
| `Demo` | `Game` の派生。ボットの入力で `Game` と同じ `Round` を進める。入力のリスナーを持たず、`Result` を出さず、操作ヒントと画面の揺れは出さない。盤面全体を縮小して、Title の小窓に描く |

Scene の並びは `Title`・`Game`・`Result`・`Demo`（先頭が自動で始まる）。

### レイアウト（論理サイズ 360×720）

Title の要素は論理座標で置く（中央揃え）。デモは盤面全体（360×720）を一様に縮小して、小窓に入れる。文字・ボタンはデモと重ならない。拡縮はキャンバスごとに Phaser の `FIT`。

| 要素 | 位置・大きさ（論理 px） |
|---|---|
| ゲーム名「MINOCLIMB」 | x = 180、y = 48、44px（上端 26〜下端 70） |
| デモの小窓 | 左上 (DEMO_VIEW_X, DEMO_VIEW_Y) = (48, 96)、DEMO_VIEW_W × DEMO_VIEW_H = 264 × 528。盤面全体を倍率 264 / 360 = 0.733 に縮小して入れる。外側に細い枠（2px、明るいグレー）を描く |
| START ボタン | 中心 (180, 672)、START_W × START_H = 200 × 64 の角丸の矩形（640〜704）。文字「START」28px |
| 幕（作り直し用） | 小窓と同じ矩形。黒。デモの上、枠の内側 |

名前・小窓・ボタンは縦に並び、重ならない（名前の下端 70 < 小窓の上端 96、小窓の下端 624 < ボタンの上端 640）。説明の文・操作の行・補助の文字は置かない。開始はスペース / Enter / 画面のどこをタップしても（START ボタンは目印）。

手計算の例（`FIT` の倍率 s = min(W / 360, H / 720)、キャンバス = 360s × 720s、小窓 = 264s × 528s、盤面の 1 セル = 36 × 0.733 × s）:

| 画面（CSS px） | s | キャンバス | 名前 | 小窓 | 盤面の 1 セル | START ボタン |
|---|---|---|---|---|---|---|
| 375 × 550（iPhone SE Safari 縦） | 0.764 | 275 × 550 | 33.6px | 201.7 × 403.3px | 20.2px | 152.8 × 48.9px |
| 667 × 310（横向き） | 0.431 | 155 × 310 | 18.9px | 113.7 × 227.3px | 11.4px | 86.1 × 27.6px |
| 390 × 844（スマホ縦） | 1.083 | 390 × 780 | 47.7px | 286.0 × 572.0px | 28.6px | 216.7 × 69.3px |
| 1280 × 720（PC） | 1.000 | 360 × 720 | 44.0px | 264 × 528px | 26.4px | 200 × 64px |

- 横向きのスマホは小窓も文字も小さい（盤面の 1 セルが約 11px）。START ボタンだけでなく画面のどこをタップしても開始でき、スペース / Enter でも開始できるので、操作は成り立つ。横向きは主な対象ではない。
- 最小の対象画面（375 × 550）でも、START ボタンの高さは 44 CSS px 以上（48.9px）。
- 描画順（下から）: Demo の盤面（小窓の中） → 幕 → 枠 → 名前・START ボタン。リサイズでは、デモを作り直さず、今の状態から描き直す。

### デモの流れ

| 局面 | 内容 |
|---|---|
| 走り | `Demo` の `Round` をボットが DEMO_RUN_MS 動かす。`Round` の進行は `Game` と同じ（`dt` は MAX_DT で頭打ち） |
| 終了の見せ方 | `Round` がクリア・潰れ・積み上がりすぎで終わったときは、その状態のまま DEMO_END_HOLD_MS 見せてから幕を閉じる（走りの長さを待たない） |
| 幕が閉じる | DEMO_FADE_MS かけて幕が不透明になる。始まった時点で、再生中の光は捨てる。不透明度は直線的に変える |
| 作り直し | 幕が閉じきった時点（画面が黒の瞬間）で、`Demo` を止めて新しい `Round`（新しい乱数）で起動する。ボットの経過時間と `Round` の時計は、この時点から数える（幕が開く間も進む） |
| 幕が開く | DEMO_FADE_MS かけて幕が透明になる。そのあと次の走り |

- 幕が閉じ始めるのは、最初は走りの始まりから DEMO_RUN_MS 後。2 回目以降は、前の幕が開ききってから DEMO_RUN_MS 後（前に閉じ始めてから DEMO_RUN_MS + 2 × DEMO_FADE_MS）。
- 時刻はすべて、Title の幕の時計（Title を表示してからの経過。最初の走りは 0 から）で数える。この時計は `Round` と同じゲーム内の時間で、1 フレームの経過時間を MAX_DT で頭打ちにして足す（長いフレームでも、幕のフェードが飛ばない）。走りの作り直しのとき、`Round` の時計は 0 から数え直すが、幕の時計は続ける。
- 幕が閉じ始めるのは `min(DEMO_RUN_MS, 走りが終わった時刻 + DEMO_END_HOLD_MS)`（どちらも幕の時計）。走りが終わったのが、すでに幕が閉じ始めたあとなら、待ち直さず、閉じる動きをそのまま続ける。
- 走りの時計（いつ幕を閉じ始め、いつ作り直し、いつ開くか）は、純粋ロジックとして持ち、単体テストする（`TitleDemoRunner` を使っても、走りが終わったときに作り直してもよい）。フェーズ名は `waiting` / `stepping` / `fading-out` / `fading-in` のいずれかで（`shared/title-demo` の名前）、`__qa.demoPhase` にそのまま出す。
- `Demo` は、作り直しのたびに入力のリスナー・タイマーを増やさない。

### `Game` との違い（`Demo` だけ）

- ボットが入力を作る。キーボード・ポインタは読まない。
- `ready` 局面・`Result` の起動・操作ヒント・結果時の画面の揺れ・`window.__qa` の書き込みは無い。HUD の「高さ」と GOAL・危険域のラベル、固定・行消しの光は `Game` と同じに出す。
- 盤面全体（HUD・ラベル・光を含む）を、小窓の大きさまで一様に縮小して描く（カメラの拡大率 DEMO_VIEW_W / 360）。HUD の位置・文字は縮小されるだけで、変えない。

## ルール

- ゲーム本体のルール・スコア・難易度・着地 AI・操作は変えない。デモは何も保存しない（`localStorage` を使わない）。
- ボット（`DemoBot`）は、乱数を使わない純関数: 盤面・プレイヤー・ミノの状態と、走りの経過時間（ms）から、`{ left, right, jump }` を返す。同じ入力なら同じ出力。

### ボットの振る舞い

用語（盤面は `Game` の仕様と同じ）:

- **今の列**: floor(x + PLAYER_W / 2)（体の中心の列）。
- **足場の高さ**: 列の「いちばん上のセルから床まで」の行数（着地 AI が使う高さと同じ。空の列は 0）。
- **ミノの列**: 予告中・落下中のミノの、**最終の着地位置**（最終の向き・選ばれた列。予告の終わりの枠と同じ）の左端の列から右端の列まで。予告中の表示の向き・位置は使わない。
- **体が重なる**: プレイヤーの体の左端 − DEMO_BODY_MARGIN < ミノの列の右端 + 1、かつ 体の右端 + DEMO_BODY_MARGIN > ミノの列の左端（厳密な不等号。接するだけは重ならない）。

規則（上ほど優先）:

1. **避ける**: ミノがあり、体が重なるとき、安全な列へ逃げる。
   - 安全な列: ミノの列の外側にある列で、今の列から左右へ 1 列ずつ進んで着けるもの。途中の各列は、「前の列より 3 以上高くない」かつ「前の列より 3 以上低くない」（段差 2 までは登れる、深さ 2 までは落ちても登れる）。
   - 候補が複数あるときは、距離（列の数）が近いものを選ぶ。距離が同じなら右を選ぶ。（深さ 3 以上の穴には、安全な列の定義の「落ちても深さ 2 まで」により、そもそも入らない。）
   - 逃げる向きへ動き、次の列が今より高く、立っているなら、ジャンプする。安全な列が無ければ動かない。
   - 体の中心がすでにミノの列の外にあって、体の端だけがミノの列に届いているときは、遠い安全な列へ向かって戻らず、ミノから遠ざかる向き（ミノの左側なら左、右側なら右）へ、その列の中で動く（ジャンプはしない）。列の境目で左右に震えないため。
2. **登る**: 避ける必要が無いときは、今の列と左右 2 列ずつ（盤面の内側）の中で、足場がもっとも高く、今の列から段差 2 以内の列へ向かう。ミノの列は選ばない。同じ高さなら、距離が近い列（今の列を含む）、距離が同じなら右。
3. **巡回**: 2. の結果が今の列のまま（今より高い列が無い）のときは、目標の x を `DEMO_ROAM_CENTER + DEMO_ROAM_AMPLITUDE × sin(2π × t / DEMO_ROAM_PERIOD_S)` とし（t は作り直しからの秒。x はセルの境界の座標で、5.0 が盤面の中央）、体の中心がその目標から DEMO_ARRIVE_TOL セル以内なら止まり、それ以外はその向きへ動く。ただし、ミノの列へは入らない。
4. **ジャンプ**: 進む向きの次の列の足場が今より 1 または 2 高く、立っている（`onGround`）ときだけ、ジャンプする（1. の逃げでも同じ）。
5. **穴・壁へ入らない**: 歩いて進む（2. と 3.）先の列の足場が、今より 3 以上低いとき（落ちたら登れない）は、その向きへ動かない（体が今の列の縁を出る前に止まる）。今より 3 以上高いとき（登れない壁）も、その向きへ動かず、ジャンプもしない（壁に向かって跳ね続けない）。1. の逃げは、安全な列の定義（落ちても深さ 2 まで）だけに従う。

（細かい係数は、品質のしきい値を満たす範囲で、実装で調整してよい。ただし、上の優先・同点の決め方・用語の定義は変えない。）

### 品質のしきい値（`DemoBot` の性質テストで確かめる）

シード 1〜40 の 40 走り（走りの長さ DEMO_RUN_MS、60fps、dt は 1/60 秒。`Round` の乱数は、シードから作った mulberry32 を注入する）で、次を満たす。クリアも「生き残った」に数える。**値は初期値。実装時に測って、下げる・上げるときは、測った値と日付を仕様に書く。**

実測（2026-10-12、実装時）: 生き残り 30/40（75%）、到達高さの中央値 8、1 走りあたりのジャンプの平均 19.9 回、通った列の中央値 7。負けた走り 10 回は、床の近くの 3 段の壁と、同じ幅のミノに挟まれて逃げ場が無い（ボットが入る前に壁が 3 になった）ことが主な原因。

| 性質 | しきい値 |
|---|---|
| 生き残る（走りの長さまでに、潰れ・積み上がりすぎにならない。クリアは生き残りに数える） | 40 走りのうち 28 以上（70%） |
| 到達する高さ（`maxHeight`） | 40 走りの中央値が 6 以上 |
| ボットが押したジャンプ（立っているときに `jump` を新しく立てた回数） | 40 走りの平均が 1 走りあたり 8 回以上 |
| プレイヤーの体が通った列の数（足を置いた列の種類） | 40 走りの中央値が 5 列以上 |

## パラメータ表

| 名前 | 初期値 | 意味 |
|---|---|---|
| DEMO_RUN_MS | 30000 | 1 走りの長さ（ms）。幕が閉じ始めるまで |
| DEMO_FADE_MS | 400 | 幕が閉じる・開くのにかかる時間（ms） |
| DEMO_END_HOLD_MS | 1200 | 走りが終わった状態を見せてから幕を閉じ始めるまで（ms） |
| START_W / START_H | 200 / 64 | START ボタンの大きさ（論理 px）。最小の対象画面で 44 CSS px 以上 |
| DEMO_VIEW_X / DEMO_VIEW_Y | 48 / 96 | デモの小窓の左上（論理 px）。名前の下端 70 より下 |
| DEMO_VIEW_W / DEMO_VIEW_H | 264 / 528 | デモの小窓の大きさ（論理 px）。比が 360 : 720 の 1 : 2 で、縮小の倍率は 264 / 360 = 0.733。下端 624 は START ボタンの上端 640 より上 |
| DEMO_ROAM_CENTER | 5 | 巡回の中心の x（セルの境界の座標。盤面の中央） |
| DEMO_ROAM_AMPLITUDE | 3.5 | 巡回の振れ幅（列） |
| DEMO_ROAM_PERIOD_S | 12.6 | 巡回の周期（秒） |
| DEMO_ARRIVE_TOL | 0.15 | 巡回の目標に着いたとみなす差（セル）。これ以内なら止まる（左右に震えない） |
| DEMO_BODY_MARGIN | 0.08 | 避けるときに、体の左右へ足す余裕（セル） |

値同士の制約: DEMO_FADE_MS < DEMO_END_HOLD_MS < DEMO_RUN_MS。

## テスト観点

- **ボット（手計算の例。`DemoBot` を直接呼ぶ）**:
  - 避ける: プレイヤーの今の列が 5、ミノの列が 4〜7 のとき、右の安全な列は 8（距離 3）、左は 3（距離 2）なので、左へ向かう。同距離（例: ミノの列 4〜6 で今の列が 5、列 3 と列 7 が距離 2）のときは右へ向かう。
  - 避ける（列の境目）: ミノの列が 1〜2、プレイヤーの体が x = 0.58〜1.28（中心 0.93 で列 0）のとき、体の右端がミノの列に届いているので、列 3 へ戻らず左へ動く。x = 0.2（体は 0.2〜0.9、余裕を足して 0.98 < 1）なら避けない。
  - 避ける（穴）: 左の安全な列（距離 2）へ向かう途中に、3 低い落ち（深さ 3 の穴）があるとき、その向きは選ばず、距離 3 の右の列を選ぶ。壁際の列でも同じ（壁側の隣は無いものとして、もう一方の隣との差で判定する）。
  - 避ける（壁）: 逃げる向きの途中に 3 高い壁があるとき、その向きは選ばない。左右とも不可なら動かない。
  - 避ける（深い落ち）: 逃げる向きの途中に 3 低い落ちがあるとき、その向きは選ばない（落ちたら登れない）。
  - 避ける（体の余裕）: 体の右端 + DEMO_BODY_MARGIN が、ミノの左端の列の左端にちょうど接する位置では避けない。それより 0.01 セルでも内側なら避ける。
  - 登る: 右の列が 1 高いとき、右へ向かいジャンプする。段差 3 の列へは向かわない。同じ高さの列が左右にあるときは、距離が近いほう、同距離なら右。
  - 巡回: 近くに今より高い列が無いとき、目標 x が、t = 0 で 5.0（中心）、t = 3.15 秒で 8.5（中心 + 振れ幅）、t = 6.3 秒で 5.0、t = 9.45 秒で 1.5（中心 − 振れ幅）。体の中心が目標から 0.15 以内なら動かない。
  - 穴・壁に入らない: 進む先の列が今より 3 低いとき、その向きへ動かない。2 低いときは動く。進む先が今より 3 高い壁のときは動かず、ジャンプもしない。2 高いときは動いてジャンプする。
  - 純関数: `Math.random` を例外を投げる関数に置き換えても動く。同じ入力で同じ出力。
- **性質テスト**: 上の品質のしきい値を、シード固定の走り 40 回で確かめる（空振りの検査つき: 生き残った走りと終わった走りの両方が数えられていること、ボットが押したジャンプだけを数え、`Round` 側の自動の動きを数えない）。
- **走りの時計（時刻列。単体のテスト対象は「走りの時計」の純粋ロジック）**: DEMO_RUN_MS 30000、DEMO_FADE_MS 400 のとき、t = 0 で走り、29999 までは幕が閉じず、30000 で幕が閉じ始め（`fade-out`）、30400 で作り直し（`fade-in`、不透明度 0）、30800 で幕が開ききり、60800 で 2 回目の幕が閉じ始める。走りが終わった時刻 t_end では、`min(30000, t_end + 1200)` で幕が閉じ始める（t_end = 5000 なら 6200、t_end = 29500 なら 30000）。幕が閉じ始めたあとに走りが終わっても、待ち直さない。開始の要求は最初の 1 回だけ `true` で、そのあとは時計も進まない。
- **開始**: 開始の要求は押した瞬間だけ受け付け、押しっぱなしのキーでは始まらない。受け付けたあとの 2 回目の要求は無視する（`Game` が 2 重に始まらない）。
- **開始に使った入力**: Title でスペースを押して（または触れて）`Game` を始めたあと、その入力を離すまで、`Game` の移動・ジャンプ・スティックの起点にならない（離して押し直すと有効）。
- **開始直後の状態**: Title に DEMO_RUN_MS + 5000 ms 以上いたあとに開始しても、`Game` の最初の状態（空の盤面、プレイヤーは中央の床の上、`playing`、高さ 0、最初のミノの予告は SPAWN_DELAY 後）が、すぐ開始したときと同じ。
- **後始末**: `Demo` を 5 回作り直しても、入力のリスナーとタイマーの数が増えない。Title が終わると、Title のキーのリスナーと捕捉が解除される。`Demo` は `localStorage` を読み書きせず、`window.__qa`（`Game` 用）を書かない。
- **Scene / 統合（最小限）**: `Title` から開始すると `Game` が `playing` で始まる（`ready` が無い）。`Result` からのリトライは今までどおり `Game` を直接始める（Title に戻らない）。
- **回帰**: 既存の `Game`・`Round`・着地 AI・操作・結果画面のテストは、変更しない（`ready` 局面のテストだけは、Title の開始に置き換える）。

## 完了条件

- `npm run lint`・`npm run test`・`npm run test:coverage`（90% 以上）・`npm run build` がすべて通り、単体ビルドと共有ビルドの両方で起動する。dev 専用の `__qa` は本番の bundle に残らない。
- スクリーンショット（`scripts/qa/title-viewports.mjs`）: 375 × 550、667 × 310、390 × 844、1280 × 720 の Title で、名前・説明・操作・START が上の配置どおりに出る。デモが背後で動いている（`__qa.demoVisible` が真）。
- `scripts/qa/title-start.mjs`: DEMO_RUN_MS + 5 秒以上（少なくとも 1 回の作り直しを跨ぐ）待ってから、Enter・Space・クリックで開始しても、`Game` が `playing` で、高さ 0、プレイヤーが中央の床の上から始まる（開始のあと 1 秒の `__qa` で確かめる）。幕が閉じて作り直される様子（`__qa.demoPhase` が `fading-out` → `fading-in`）が見える。
- 変えないもの（回帰条件）:
  - `Game` のルール・数値・着地 AI・操作の感触・結果画面とリトライ（Result → Game）・演出・スコア無しは変わらない。
  - 開始した直後の盤面は、Title に何秒いても同じ（空の盤面、プレイヤーは中央の床、最初のミノは SPAWN_DELAY 後）。
  - 開始に使った入力は、離すまでゲーム入力にならない。
- 変わるもの（合意済み）: 最初の Scene が `Title` になる。`Game` の `ready` 局面（名前・操作の説明・開始の待ち）は無くなり、`Title` が担う。
- dev 専用の `window.__qa`（`shared/title-demo/README.md` の「Title の形」）: Title は `{ scene: 'Title', demoVisible, demoPhase, demoRounds }`、`Game` は従来どおり。`Demo` の盤面の値は別の dev 専用のグローバル（`__qaDemo`）にする。いずれも本番の bundle に残らない。
- 実機（スマホ）での確認を案内する（デモの動きは目で判断する）。
