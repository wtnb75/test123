# Result Scene（結果画面）

`docs/spec.md` の一部。`Result` Scene の表示、「タイトルへ」ボタン、結果画面の入力の振り分けと、そのテスト観点・完了条件を、独立して書いたもの。パラメータ名（`RETRY_LOCKOUT`、`RESULT_TITLE_X` など）と節名は `docs/spec.md` のものを指す。`docs/spec.md` と合わせて 1 つの spec である。

## 概要

クリア／ゲームオーバーの結果表示と、リトライ・タイトルへ戻る入力を定める。

なし（キー・タッチの共通の扱いは `docs/spec.md` の「操作仕様」と [入力とタッチ操作の詳細](touch-input.md) のとおり）。

## 画面・Scene構成

### Result Scene

| 結果 | 表示する文言 | 補足 |
|---|---|---|
| クリア | 「クリア！」 | なし |
| 潰された | 「ゲームオーバー」＋「ミノに潰された」 | 到達した最大の高さ（`n / (ROWS − GOAL_ROW)` 段）を添える |
| 積み上がりすぎ | 「ゲームオーバー」＋「積み上がりすぎた」 | 同上 |

- 「タップ / R / スペースでリトライ」を、RETRY_LOCKOUT 経過後に表示する。
- クリアでもゲームオーバーでも、リトライの案内の下に、ボタン「タイトルへ（T）」を、同じく RETRY_LOCKOUT 経過後に出す（それまでは描かない）。中心 (RESULT_TITLE_X, RESULT_TITLE_Y) = (180, 600)、RESULT_TITLE_W × RESULT_TITLE_H = 200 × 64 の角丸の矩形（x 80〜280、y 568〜632。左と上の辺は含み、右と下の辺は含まない）で、文字は 24 px 以上。既存の要素（見出し・詳細・リトライの案内）の位置は変えない。現行の配置は、見出しの中心 y = 720 ÷ 3 = 240、詳細の上端 y = 240 + 56 = 296（2 行で下端は約 346）、リトライの案内の中心 y = 720 × 2 ÷ 3 = 480 で、リトライの案内とボタンの上端 568 の間は 88 px。
- 「タイトルへ」: ボタンの矩形の中で触れ始めた指（クリックを含む）、または `T` キーの押し始め（キーダウン）で、`Game` と `Result` を止め（`Game` に重ねた表示・演出・盤面を残さない）、`Title` を始める。`Title` はいつもどおりの最初の状態から始まる（デモは新しい走りから。[Title とデモプレイ](title-demo.md)）。そのあとの START で、`Game` は今までどおり最初の状態（`playing`）から始まる。受け付ける時間・指の扱い（矩形の中で触れ始めた指はリトライにならない、前に触れた指・押しっぱなしの `T` は受け付けない、使った指・キーは `Title` の START にならない）は [入力とタッチ操作の詳細](touch-input.md) のとおり。リトライの入力（R・スペース・矩形の外のタップ）は今までどおり `Game` を直接始める。同じフレームにリトライと「タイトルへ」の入力が来たら、「タイトルへ」だけが効く（「タイトルへ」はボタン上の指・`T` の明示的な操作なので優先し、リトライの入力は無視する。キーと指のどちらが先に来ても同じ）。同じ種類の入力が同じフレームに複数来ても、`Game` と `Title` を始めるのは 1 回だけ。
- 実寸（FIT のあと、縮小率 s = min(幅 / 360, 高さ / 720)）: 375 × 550（s = 0.764）でボタンは 152.8 × 48.9 px（AGENTS.md 4.6 の的の大きさ 44 px 以上）、文字は約 18 px。390 × 844（s = 1.083）で 216.7 × 69.3 px。1280 × 720（s = 1.0）で 200 × 64 px。横向きの 667 × 310（s = 0.431）は、ボタンが 86.1 × 27.6 px・文字が約 10 px で基準に届かない。論理サイズが 360 × 720 の固定のため（Title の START と同じ理由で、横向きは主な対象ではない）許容する。`T` キーが使えない横向きのタッチ画面では、ページの再読み込みが従来どおりの代わりの手段になる。

## テスト観点

- 結果画面の入力の振り分け（時計を注入して確かめる。ボタンの矩形は x 80〜280・y 568〜632、右と下の辺は含まない）:
  - 矩形の中（例: (180, 600)、左上の角 (80, 568)）で触れ始めた指は「タイトルへ」。矩形の外（例: (79, 600)、(180, 567)、右の辺 (280, 600)、下の辺 (180, 632)、リトライの案内の位置 (180, 480)）で触れ始めた指はリトライ。
  - 経過が RETRY_LOCKOUT 未満（0.49 秒）の入力（ボタンの中・外・R・スペース・`T` のどれも）は何も起こさず、あとから RETRY_LOCKOUT に達しても持ち越されない。ちょうど 0.5 秒の新しい入力から受け付ける。ボタンは 0.5 秒未満では出ない。
  - 矩形の外で触れた指が、動いて矩形の中で離れても、リトライのまま（「タイトルへ」にならない）。矩形の中で触れた指が、動いて外で離れても「タイトルへ」。ボタンの上で触れた指は、リトライにならない。
  - `T` キーの押し始め（キーダウン）で「タイトルへ」。押しっぱなしのまま RETRY_LOCKOUT が過ぎても「タイトルへ」にならない。R・スペースは今までどおりリトライ。`T` はクリアでもゲームオーバーでも効く。遊び中（`playing`）の `T` は何もしない。
  - 同じフレームにリトライと「タイトルへ」の入力が来たら（R と `T`、スペースと `T`、矩形の外のタップと `T`、矩形の外のタップと矩形の中のタップ。どの順に来ても）、「タイトルへ」だけが効き、`Game` と `Title` が両方始まらない。同じ種類の入力が複数来ても 1 回だけ始まる。
  - 「タイトルへ」のあと `Title` が始まり、`Game` と `Result` は動いていない（ミノの予告・落下、操作ヒント、揺れ、光が残らない）。`Title` の START（スペース・Enter・新しいタップ）で `Game` が最初の状態（`playing`、盤面は空）から始まる。「タイトルへ」に使った指と `T` キーは、離すまで `Title` の START にならず、離して押し直せば始まる。
  - リトライの入力（R・スペース・矩形の外のタップ）は今までどおり `Title` を経ずに `Game` を直接始める（リトライの手応えは変わらない）。
  - 回帰（ボタンを足しても変わらない）: 結果画面の既存の要素（見出し y 240・詳細の上端 y 296・リトライの案内 y 480・暗幕・ゲームオーバーの揺れ）の位置と表示、HUD・盤面のレイアウト、遊び中の操作、`Title` の START とデモの走りは変わらない（既存の単体テストが変更なしで通る。位置と表示は QA のスクリーンショットで確かめる）。
  - 「タイトルへ」ボタンの配置データ: 中心 (180, 600)・200 × 64 がキャンバス（360 × 720）の内側に収まり、リトライの案内（y = 480）・見出し（y = 240）・詳細（y = 296〜346）と重ならない。375 × 550 で実寸の高さが 44 px 以上（64 × 0.764 = 48.9）。

## 完了条件

- 結果画面から Title へ戻る入口: クリア・ゲームオーバーの結果画面に、RETRY_LOCKOUT のあと「タイトルへ（T）」ボタンが出て、ボタンのタップ・クリックと `T` キーで `Title`（デモが新しい走りで動く）に戻れ、START で最初から遊べる。ボタンは縦画面（375 × 550・390 × 844）・PC（1280 × 720）で、見出し・詳細・リトライの案内と重ならず、切れず、実寸の高さが 44 px 以上・文字が 14 px 以上で読める（375 × 550 は 48.9 px・約 18 px）。横向き 667 × 310 は上の「Result Scene」の例外（27.6 px・約 10 px）。画面で確かめる（QA のスクリーンショット: クリアとゲームオーバー × 縦と横、ボタンを押したあとの `Title`、その START から始まる `Game`）。リトライ（ボタン以外のタップ・R・スペース）は今までどおり `Game` を直接始め、`Title` を経ない。
- 結果画面の入力の変更の回帰条件（変えないもの）: 遊び中の操作（ジャンプ・移動・スティック・タップ・壁蹴り）、着地 AI、ミノの予告・落下・固定・行消し・潰れ・積み上がりすぎ・クリアの判定と数値、結果画面の既存の要素（見出し・詳細・リトライの案内・暗幕・揺れ）の位置と表示、RETRY_LOCKOUT とリトライの入力（R・スペース・ボタン以外のタップ・「離すまで無効」の扱い）、`Title` の START とデモの仕組み、HUD と盤面のレイアウト。既存の単体テストは、変更なしで通る。
