# ステージ（次のステージへ進む枠組み）

`docs/spec.md` の一部。クリアしたら次のステージへ進む枠組み（ステージ番号の持ち方、HUD の表示、クリア画面の「次のステージへ」）を、独立して書いたもの。パラメータ名と節名は `docs/spec.md` のものを指す。`docs/spec.md` と合わせて 1 つの spec である。結果画面の入力の振り分けの基本は [Result Scene（結果画面）](result-screen.md) のとおり（クリアのときの違いだけをここに書く）。

## 概要

クリアすると、次のステージへ進める。ステージ番号は 1 から始まり、クリアのたびに 1 増える（上限は無い）。ステージ 1 と 2 以降で、遊びの中身の違いは「せり上がり」の有無だけ（ステージ 2 以降は、盤面の下から行がせり上がる。[せり上がり](rising.md)）。ステージ 2 以降はすべて同じ規則で、それ以上のステージごとの違いは別の拡張で足す。コアループの先に「次の挑戦」ができる。

## 操作仕様

クリアの結果画面での操作だけが変わる（結果画面の受け付けの規則は変えない: RETRY_LOCKOUT 秒は受け付けない、押した瞬間だけ、「離すまで無効」）。

| 操作 | クリア | ゲームオーバー |
|---|---|---|
| 次のステージへ | スペース、または画面のタップ（下の「タイトルへ」ボタンの上を除く） | なし |
| 同じステージをもう一度 | R | R・スペース・画面のタップ（今までどおり） |
| タイトルへ | `T`、または「タイトルへ（T）」ボタン | 同じ（今までどおり） |

- 同じフレームに複数の入力が来たときの優先は、「タイトルへ」が最優先。クリアで R と、スペースまたはタップが同じフレームに来たら、R（同じステージをもう一度）を優先する。同じ種類の入力が複数来ても、`Game` と `Title` を始めるのは 1 回だけ。
- Enter は、結果画面の入力に加えない（今までどおり）。
- 「次のステージへ」「同じステージをもう一度」に使ったキー・指は、リトライに使ったものと同じに、離すまで次の `Game` のゲーム入力にならない（[入力とタッチ操作の詳細](touch-input.md) の「ゲーム入力として有効になる入力」）。次の `Game` は、リトライと同じに新しく作る（光・操作ヒント・揺れ・盤面を引き継がない）。

## 画面・Scene構成

### ステージ番号の持ち方

- ステージ番号 `stage`（1 以上の整数）は、`Game` を始めるときに受け取る値として持つ（Scene の起動データなど。置き場所は実装裁量）。進行の保存（ブラウザへの保存）はしない。
- `Title` の START で始める `Game` は、いつも `stage` = 1。
- クリアの結果画面から「次のステージへ」で始める `Game` は、`stage` + 1。Title を挟まない。
- ゲームオーバーのリトライ（R・スペース・タップ）と、クリアでの R は、同じ `stage` で `Game` を始める。
- 「タイトルへ」で `Title` に戻ったら、`stage` の記憶は消える（次の START は 1）。
- `Game` は、`stage` が違っても、同じ初期状態から始める（盤面は空、プレイヤーは中央の床の上、`playing`、最初のミノの予告は SPAWN_DELAY 後、空ける列は 50% ずつで新しく決める）。ステージによって変わる規則は、せり上がりの有無だけ（`stage` ≥ RISE_FROM_STAGE で有効。[せり上がり](rising.md)）。`Game` は、`stage` から「せり上がりが有効か」を決めて `Round` に渡す（`Demo` は渡さない）。表示とこの有効化以外には、`stage` を使わない。
- `Demo`（Title の小窓）は、`stage` を持たない（常に今までのまま。HUD に「ステージ」は出さない）。

### HUD

- `Game` の HUD（盤面の左上）は、1 行で「ステージ {stage}　高さ {n} / {ROWS − GOAL_ROW}」（「ステージ」と数字のあとに全角の空白 1 つ、次に「高さ」）にする。`stage` = 1 のときも出す。文字の大きさ・縁取り・位置（左上 (6, 4)）は今までの HUD と同じ。
- 「ステージ 999　高さ 15 / 15」でも、論理幅 360 px の中に収まり、「ここまで積むと負け」のラベルと重ならない。
- `Demo` の HUD は今までどおり「高さ {n} / {ROWS − GOAL_ROW}」で、「ステージ」は出さない。

### Result Scene（クリアのとき）

- 見出しは「ステージ {stage} クリア！」（`stage` は、そのクリアしたステージの番号）にする。位置は今までの見出しと同じ（中心 y = 240）。文字の大きさは、見出しの幅が論理幅 360 px（左右 10 px の余白を引いた 340 px）以内に収まる最大の大きさにする（上限は今までの 40 px。「ステージ 1 クリア！」でも 40 px では収まらないので下がる。番号の桁数によらず収める）。下限は論理 18.3 px（375 × 550 の実寸で 14 px 以上。AGENTS.md 4.6 の主な情報）で、番号が 3 桁（999）までは下限を割らない。
- y = 480 の案内（RETRY_LOCKOUT 経過後に出す）は、「タップ / スペースで次のステージへ」にする（ゲームオーバーでは今までの「タップ / R / スペースでリトライ」のまま）。位置・文字の大きさ・出る時機は変えない。
- 詳細（敗因と高さ）はクリアでは出ない（今までどおり）。「タイトルへ（T）」ボタンと、暗幕、揺れ（クリアでは揺れない）は変わらない。
- R を押したとき（同じステージをもう一度）は、案内には出さない。

## ルール

- 遊びの規則（クリア・ゲームオーバーの条件、ミノ、着地 AI など）は、せり上がり（[せり上がり](rising.md)）を除いて、ステージによらず `docs/spec.md` のとおり。`stage` は表示と、せり上がりの有効化と、`Game` を始めるときの受け渡しにだけ使う。
- 難易度は、ステージ 1 は今までどおり。ステージ 2 以降は、せり上がりが加わるぶん難しくなる（意図した変更）。ステージ 2 以降のあいだでは変わらない（ステージごとの違いは、別の拡張で足す）。

## パラメータ表

なし（新しい数値は無い。既存の数値は `docs/spec.md` のパラメータ表のとおり）。

## テスト観点

- 結果画面の入力の振り分け（`resultAction` を、クリア／ゲームオーバーの区別を渡して呼ぶ。時間は呼び出し側が渡す）:
  - クリア: スペース、矩形の外のタップ → 「次のステージへ」。R → 「同じステージをもう一度」。`T`、矩形の中のタップ → 「タイトルへ」。Enter は何も起こさない。
  - ゲームオーバー: R・スペース・矩形の外のタップ → 「同じステージをもう一度」（今までどおり）。`T`・矩形の中 → 「タイトルへ」。
  - 同じフレームに、クリアで R とスペース → R（同じステージ）。クリアで R と矩形の外のタップ → R。クリアで R と `T` → 「タイトルへ」。クリアでスペースと矩形の外のタップ → 「次のステージへ」（どちらも同じ結果）。
  - 経過が RETRY_LOCKOUT 未満（0.49 秒）の入力は、クリアでも何も起こさず、0.5 秒ちょうどから受け付ける。
- ステージ番号の遷移（`Game` が受け取る `stage` を返す純粋な関数）: `Title` の START → 1。クリア 1 →「次のステージへ」→ 2、クリア 2 → 3、クリア 998 → 999。クリアで R → 同じ `stage`。ゲームオーバーのリトライ → 同じ `stage`（1 でも 5 でも）。「タイトルへ」のあとの START → 1。
- HUD の文言: `stage` = 1・高さ 0 →「ステージ 1　高さ 0 / 15」、`stage` = 12・高さ 7 →「ステージ 12　高さ 7 / 15」。`Demo` は「高さ 7 / 15」（ステージ無し）。
- 見出しの大きさ（文字の幅を測る関数か、レイアウトのデータで確かめる）: `stage` = 1・99・999 で、見出しの幅が 340 px 以内、大きさが 18.3 px 以上 40 px 以下。
- 「離すまで無効」: 「次のステージへ」「同じステージをもう一度」に使ったスペース・R・指は、離すまで次の `Game` の移動・ジャンプ・スティックの起点にならない（リトライと同じ。離して押し直せば有効）。次の `Game` に、前のステージの光・操作ヒント・揺れ・ミノ・盤面が残らない（作り直す）。
- 純粋ロジックの形: ステージ番号の遷移、結果画面の入力の振り分け、HUD と見出しの文言は、Phaser に依存しない関数として単体テストできる（「技術要件」）。
- クリアの結果画面の文言: 見出し `stage` = 1 →「ステージ 1 クリア！」、`stage` = 12 →「ステージ 12 クリア！」。案内は「タップ / スペースで次のステージへ」。ゲームオーバーは「ゲームオーバー」と「タップ / R / スペースでリトライ」のまま。
- `stage` からせり上がりの有効化への変換（Phaser に依存しない純粋な関数）: `stage` = 1 → 無効、2 → 有効、7 → 有効、999 → 有効。`Demo` は無効（`stage` を持たない）。
- 回帰（せり上がりが無効なら変わらない）: 同じシードの `Round` の走り（盤面・ミノの列・着地 AI の選択・乱数の消費・終わるフレームと状態・到達高さ）が、せり上がりが無効（`stage` = 1 と `Demo`）なら、今までと同じ。`stage` = 2 と `stage` = 7 は、同じシード・同じ入力で同じ走りになる（`stage` の番号の違いでは変わらない）。既存の単体テストは、変更なしで通る（HUD と結果の文言の単体テストがあれば、その文言の変更分だけ更新する）。
- `Title` の START と `Demo` の走り（デモのボットの品質の閾値を含む）は変わらない。

## 完了条件

- クリアすると、結果画面（RETRY_LOCKOUT のあと）に「ステージ n クリア！」と「タップ / スペースで次のステージへ」が出て、スペースまたは（ボタン以外の）タップで、Title を挟まずに `stage` = n + 1 の `Game` が始まる（`playing`、盤面は空、HUD は「ステージ n+1　高さ 0 / 15」）。R は同じステージをもう一度始める。「タイトルへ」で Title に戻り、START で `stage` = 1 から始まる。画面で確かめる（QA のスクリーンショット: ステージ 1 の HUD、クリア画面（縦 375 × 550・390 × 844・PC 1280 × 720）、「次のステージへ」のあとの HUD が「ステージ 2」）。
- 文字は、縦画面（375 × 550・390 × 844）と PC（1280 × 720）で、切れず・重ならず、HUD の文字の大きさは今までのまま（18 px。375 × 550 の実寸で約 13.75 px で、AGENTS.md 4.6 の主な情報の 14 px にわずかに届かない）。この拡張はレイアウト・見た目の不変を合意しているので、HUD の大きさは変えない（届かない点は既存の HUD からの持ち越しで、別の見た目の改善（`game-polish`）で扱う）。ステージ番号を足した 1 行が幅に収まることだけを確かめる（1000 以上でも幅 360 px を超えないこと。超えるときは文字を縮める）。
- ゲームオーバーの結果画面とリトライ（同じステージ）、Title・デモは、今までどおり。
- 変えないもの（回帰条件）: 遊び中の操作の感触（移動・ジャンプ・壁蹴り・スティック・タップ・キー）、ミノの予告・落下・固定・行消し・潰れ・積み上がりすぎ・着地 AI・躊躇・閉じ込めの崩れ・クリア判定とそれぞれの数値、盤面とレイアウト、結果画面の既存の要素（暗幕・見出しの位置 y 240・詳細の位置 y 296・案内の位置 y 480・「タイトルへ」ボタンの位置と大きさ・`T`・ゲームオーバーの揺れ）、RETRY_LOCKOUT と「離すまで無効」の扱い、`Title` の START とデモの仕組み、ステージ 1 の難易度（せり上がりが加わるのはステージ 2 以降だけ。[せり上がり](rising.md)）。
- 保存はしない（ブラウザにステージを残さない。再読み込みで Title から 1）。
- README の操作方法に、クリア後の「次のステージへ」（スペース / タップ）、R（同じステージ）、ステージ番号が増えることが書かれている。

## 実装裁量

- `stage` の受け渡しの方法（Scene の起動データ、registry など）。`Round` には、ステージ番号そのものではなく「せり上がりが有効か」を渡す（渡し方は [せり上がり](rising.md) の実装裁量）。
- 「ステージ n クリア！」の文字の大きさ（収まる範囲で。40 px から下げてよい）。
- 結果画面の「次のステージへ」の案内の、見え方の細部（色・濃さ。位置・文字の大きさ・出る時機は上のとおり）。
- HUD のステージ番号の見せ方の細部（全角の空白の幅など。1 行に収め、縁取りを付けること）。
