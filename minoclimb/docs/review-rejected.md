- `src/game/scenes/**`: Scene glue (ready→playing, retry lockout ordering, landing-frame visibility) has no unit tests — 理由: scenes/** is excluded from coverage by the shared config; the decision logic (PressDetector consumption, `Round.flow.kind`) is unit-tested and the Scene behavior is confirmed with screenshots in game-qa.
- `src/game/main.ts`, `src/game/logic/round.ts`: `activePointers: 3` and the 50% open-column roll are outside params.ts — 理由: the spec states them as fixed rules, not table parameters; moving them needs a spec change first.
- `src/game/logic/input.ts`: a lift and re-touch of the same Phaser pointer slot within one frame is read as the same finger — 理由: touchend and touchstart arrive as separate events with a frame between in practice; the worst case is one dropped tap that the next tap fixes.
- `src/game/scenes/BoardView.ts`: locked cells are redrawn every frame — 理由: at most 200 rectangles per frame is cheap; splitting the layer adds complexity for no measurable gain (revisit in game-polish if a phone shows slowdown).
- `src/game/scenes/KeyTracker.ts`: `addCapture` is never removed — 理由: Phaser's captures are global and not reference-counted, and Game and Result overlap in lifetime, so removing from one Scene could drop the other's; the page contains only the game.
- `src/game/logic/ai.test.ts`: tests build a `Round` just to read `wellCol` and so depend on its constructor's first random draw — 理由: that draw order is part of the spec (the open-column roll comes first); a change would show up in the statistics tests.
- `src/game/scenes/BoardView.ts`: hint `setAlpha` is called every frame even when the value is unchanged — 理由: two property writes per frame are not measurable; tracking the last value adds state for nothing.
- `src/game/scenes/BoardView.ts`: flashes and hint fades are hand-rolled instead of Phaser tweens — 理由: the spec fixes exact timing rules (t = 0 maximum, exactly 0 at D, overlaps counted separately) that are unit-tested as pure functions; tweens would not be unit-testable and need manual cut-off on end/retry anyway. The shake uses the library (`camera.shake`).
- `src/game/scenes/Game.ts`: the first frame after the Game starts steps the Round with the real delta (the old ready-to-playing frame was time 0) — 理由: the delta is capped at MAX_DT (50 ms), the first telegraph is SPAWN_DELAY away, and nothing observable changes.
- `src/game/scenes/Title.ts`: `stop('Demo')` is called on the start path and again in the `shutdown` handler — 理由: both are idempotent; the explicit call keeps the start path readable.
- `src/game/scenes/Title.ts`: `__qa.demoPhase` never shows `stepping` and `demoRounds` is 0/1 — 理由: the spec allows any of the shared phase names and `demoRounds` is "rounds finished in the current run" as in `shared/title-demo`; the shared QA scripts only use `fading-out` and `waiting`.
- `src/game/scenes/Demo.ts`: `dropEffects` uses `this.view?.` and does not redraw — 理由: it is called only on `fade-out` after the run has been playing for DEMO_RUN_MS (or the round ended and the effects were cut already), so the view exists and nothing is left to redraw.
