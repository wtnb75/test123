# absorb ゲーム仕様

## ゲーム名

**absorb** ― 弾を吸って撃ち返すシューティング（仮称）

## コンセプト

敵弾を避けるのではなく「吸い込む」シューティング。吸収フィールドで敵弾を溜め、好きなタイミングで解放すると、溜めた弾が近い敵から順に、倒すのに必要な数ずつ分かれて追尾し、まとめて撃破する。
吸収は常時自動で行われ、プレイヤーが押すボタンは解放だけ。ストックが満タンになると自動で解放されてしまうので、「どこまで溜めるか・いつ撃つか」を見極めるのが面白さの核になる。

## ターゲットプレイヤー

- ブラウザで数分の手軽なアクションを遊びたいプレイヤー
- 弾幕シューティングは好きだが、避け続けるだけの緊張感より攻めの判断を楽しみたいプレイヤー

## コアループ

1. 敵が画面の上・左・右から出現し、自機に向けて弾を撃つ
2. 自機の周囲の吸収フィールドが敵弾を自動で吸い、ストックが溜まる（吸収の操作は不要。弾を吸える位置へ動くだけ）
3. ストックが十分溜まったら解放キーで一斉解放する。溜めた弾は近い敵から順に、倒すのに必要な数ずつ分かれて追尾し、まとめて撃破する
4. 敵は急降下・掃射突撃・包囲突撃・突進で自機の近くに入ってくる。敵弾は吸えるが敵本体は吸えないので、避けるか解放弾で先に倒す。体当たりを受けるとライフが減る（ぶつかった敵は壊れ、救済としてストックが増える）
5. 敵を倒してスコアを稼ぎ、次の敵を迎える
6. ライフが 0 になったらゲームオーバー → スコア表示 → リスタート

## 操作仕様

### キーボード（PC）

| 操作 | 方法 |
|------|------|
| 移動 | 矢印キー または WASD（8方向） |
| 解放 | スペースキー・X キー・Enter キーのいずれか（押した瞬間に発動。押し続けても 1 回だけ） |
| リスタート | ゲームオーバー画面で、解放と同じキー（スペース・X・Enter のいずれか）かクリック。画面が出てから `GAMEOVER_INPUT_LOCK` 秒間は受け付けない（下記「GameOver 画面」） |

### タッチ（スマートフォン・タブレット）

| 操作 | 方法 |
|------|------|
| 移動 | 画面のどこでも（解放ボタンの当たり判定の外。下記）指を置いて滑らせると、指が動いた量と同じだけ自機が動く（相対ドラッグ。指の真下に自機が来るわけではないので、指で自機が隠れない） |
| 解放 | 画面右下の解放ボタンをタップ、またはドラッグ中の別の指で画面のどこかをタップ（どちらも触れた瞬間に発動。下記） |
| リスタート | ゲームオーバー画面をタップ（画面が出てから `GAMEOVER_INPUT_LOCK` 秒間は受け付けない） |

- ドラッグは「自機の目標位置」を動かす。指が動いた量（ゲーム画面の座標に換算）だけ目標位置を動かし、自機はその目標位置へ**キーボードと同じ最大速度 320px/秒**で向かう（キーボードより有利にならないようにする）
  - 目標位置は自機の移動範囲の中に収める（壁の外へ指を動かしても目標は壁で止まり、逆方向に指を戻すとすぐ戻り始める）
  - 自機が目標位置に着いたら止まる。指を素早く大きく動かすと、自機は少し遅れて追いつく
  - 指を離しても、目標位置に着くまで自機は動き続ける
- **指の振り分け**（タッチ端末、つまり解放ボタンを表示する端末のみ。PC（タッチ非対応）ではマウスの操作は従来どおりで、この振り分けもボタンの当たり判定も働かない）: 指が画面に触れた瞬間に、次の順で「解放」「ドラッグ」「無視」のどれかに決める。決めた役割は、その指がなくなるまで変わらない。複数の指のイベントは、届いた順に 1 つずつ振り分ける（同じフレームに複数届いても、前の指の結果を踏まえて次の指を決める）
  1. 一時停止中に触れた指はすべて「無視」（再開に使った指を含む。[一時停止](spec/pause.md)。解放にもドラッグにもならない）
  2. ドラッグ中の指がすでにある間に触れた指は、位置に関係なく「解放」（別の指で画面のどこをタップしてもよい）
  3. ドラッグ中の指がないとき、解放ボタンの当たり判定（中心から `BUTTON_HIT_RADIUS` px 以内。描く円より広い。ボタンの見た目は変えない）の中に触れた指は「解放」
  4. それ以外は「ドラッグ」
- 「解放」の指は、触れた瞬間に 1 回だけ解放を起こす（ストックが 0 なら何も起きない）。その指はドラッグにならず、動かしても離しても何も起きない。「解放」の指が触れたままでも、次に触れた指は上の順で決め直す（ドラッグ中の指がなければドラッグを始められ、あれば解放になる）
- **指の役割の寿命**: 役割は触れた指ごとに記録する。記録のない指（`Game` Scene の開始より前から触れていた指、たとえば `GameOver` 画面のリトライのタップの指や、`Title` の START のタップの指）は「無視」で、離すまで何も起こさない。記録は、その指が離れた・キャンセルされた（`pointercancel` など）・画面の外で離れたときに消す。`Game` Scene の開始時と終了時（`shutdown`）にはすべて消す。一時停止が始まったときは、ドラッグ中の指の役割を「無視」に変える（その指は離すまでドラッグに使わず、ドラッグ中の指がない状態に戻る。[一時停止](spec/pause.md)）
- ドラッグ中の指が離れたあとは、ドラッグ中の指がない状態に戻る（触れたままの「解放」の指がドラッグを引き継ぐことはない）
- 振り分けの規則は `ready`・`playing`・`ending` のどのフェーズでも同じ。`ready` の解放と、`ending` での入力は、従来どおりロジックが受け付けない
- 指が 3 本以上同時に触れた場合も、振り分けの規則はそのまま当てはまる（端末やブラウザが 3 本目のイベントを届けるかは保証しない）。ドラッグと解放の判定はどちらも画面座標（揺れの影響を受けない座標）で行う
- 手のひらや持ち手の指が誤って触れた場合も「解放」になる（上の 2）。誤爆を防ぐための待ち時間や判定は設けない（触れた瞬間の即応を優先する）
- 解放ボタンと自機は重なってもよい（ボタンは半透明で最前面に描く。自機がボタンの位置に来ることは妨げない。ドラッグを始められないのは、ボタンの当たり判定の中に指が触れたときだけ）
- キーボードとタッチは同時に使える。キーボードの移動入力がある間はキーボードを優先し、ドラッグの目標位置は破棄する（キー入力中のドラッグは無視）
- ボタンは解放の 1 つだけ。吸収は自動で行われ、入力を必要としない

## 画面・Scene 構成

| Scene | 役割 |
|-------|------|
| `Title` | 起動時の最初の Scene。名前・START・操作の説明を、背景で流れるデモの上に出し、START で `Game` を始める（[Title とデモ](spec/title-demo.md)） |
| `Demo` | `Title` の背景で、ボットの操作で本物のゲームを流す Scene（`Game` を継承。HUD・一時停止・`GameOver` は無い。[Title とデモ](spec/title-demo.md)） |
| `Game` | プレイ本体（準備カウントダウン、プレイ中、ゲームオーバー遷移を内部フェーズで管理） |
| `GameOver` | 最終スコアとその内訳の表示・リスタート受付 |

`Boot` / `Preloader` は作らない（外部アセットなし、図形描画のみ）。

### レイアウト方針

- **ゲーム画面のサイズは端末の向きに合わせて変える**（縦長の端末では縦長、横長では横長）。`Title` Scene の開始時と、`Game` Scene の開始時（リスタートのたびに）、表示領域（ブラウザのウィンドウ）の縦横比から次の式で決める
  - 短辺は常に 768
  - 長辺 = 768 × (表示領域の長辺 ÷ 短辺)。ただし 1024（4:3）〜 1536（2:1）の範囲に収める（四捨五入して整数）
  - 表示領域が横長または正方形なら 幅 = 長辺・高さ = 768、縦長なら 幅 = 768・高さ = 長辺
  - 例: PC 1920×1080 → 1365×768、iPad 横 → 1024×768、スマホ縦 390×844 → 768×1536（2:1 を超える分は上下に余白）
- 表示は `Scale.FIT` + `CENTER_BOTH`。縦横比が上の範囲に収まる端末では余白が出ない
- プレイ中に端末を回転した場合、そのプレイ中はゲーム画面のサイズを変えない（`Scale.FIT` で縮小表示され、余白が出る）。新しい向きのサイズは次のプレイ（リスタート）から使う
- 位置や範囲の値のうち「画面高さの ○%」「画面幅」など画面サイズを基準に書かれたものは、そのプレイのゲーム画面サイズを基準にする。px で書かれた値（速度・半径・余白など）はサイズによらず同じ
- 敵は画面の上端・左端・右端の外から出現する。自機は HUD の帯（画面上端から 48px）を除く画面全体を上下左右に自由に移動できる（y は下向きに増える。自機の中心は上端 48px + 自機半径 から 下端 − 自機半径 の範囲、左右は 自機半径 から 画面幅 − 自機半径 の範囲）
- 画面上部には敵がいるため、上へ行くほど敵本体に接触しやすくなる（上へ行くのは自由だが危険、というバランス）
- HUD は画面上端に配置する。左にスコア、中央にライフ、右にストックゲージ（残数／上限）。ボスがいる間は HUD の帯のすぐ下にボス HP バーを表示する（[ボス敵](spec/boss.md)）
- 解放ボタンは画面右下（ボタンの中心が右端・下端からそれぞれ 90px）に半径 56px の円で描く。現在のストック数を中に表示する。タッチ操作が可能な端末でのみ表示し、PC（タッチ非対応）では表示しない。触れて解放できる範囲は描く円より広い（`BUTTON_HIT_RADIUS`。「タッチ」の節）。指が触れて解放を起こしたとき、ボタンは押し込まれる（ストック 0 のときは赤く光る）演出をする（[演出・UI](spec/effects.md)の「演出・UI（解放ボタン）」）
- ゲームのページ上でのタッチ操作によってブラウザがスクロール・拡大しないようにする
- 敵弾・解放弾・敵・自機はすべて同一のプレイ領域に描画する。重なったときは、奥から順に「敵弾 → 敵（ボスを含む）→ 解放弾 → 自機（吸収フィールドを含む）」の順に描く（撃った直後の敵弾が敵本体の上に重ならないようにする）。自機の層の中の順序は「演出・UI（吸収）」の描画順に従う。撃破の破片は敵の層の最後（すべての敵より手前、解放弾より奥）に描く（「演出・UI（撃破）」参照）。`splitter` の分裂の輪は破片のさらに後（敵の層の最後）に描く（[分裂する敵](spec/splitter.md)参照）。敵の層の中では、`carrier` をほかのすべての敵より手前（破片・分裂の輪より奥）に描く（[運び屋](spec/carrier.md)参照）。解放の衝撃波の輪は解放弾の層の最後（すべての解放弾より手前、自機より奥）に描く（「演出・UI（解放）」参照）。同時撃破のカウント表示と確定表示は自機より手前、HUD より奥（ボスの撃破演出のスコア表示と同じ層）に描く（「演出・UI（同時撃破）」参照）。被弾の衝撃の輪は自機（`ending` の爆発を含む）の直後に、被弾の赤み・四辺の帯はプレイ領域のすべて（同時撃破の表示、ボスの撃破演出の輪・スコア表示、ボス本体の被弾フラッシュを含む）より手前、HUD（ボス HP バーと「BOSS」の文字を含む）より奥に描く（「演出・UI（被弾）」参照）。カウントダウンの数字と「GO!」の文字は、プレイ領域のすべてより奥（最背面）に描く（自機と吸収フィールドが数字に隠れないようにする。「演出・UI（スタート）」参照）。`ready` の間も吸収フィールドを自機のまわりに描く（見た目だけ。吸収の判定は `playing` から）。HUD はプレイ領域と重なってよいが、最前面に描く

### Game Scene の状態遷移

| フェーズ | 内容 | 次フェーズへの遷移条件 |
|---------|------|-------------------|
| `ready` | 「3 → 2 → 1」を表示。敵は出現せず、自機のみ移動可。数字・輪・吸収フィールドのチャージ・HUD のフェードインの演出は [演出・UI](spec/effects.md) の「演出・UI（スタート）」 | 3 秒（各数字 1 秒）経過で `playing`（その最初のフレームに「GO!」の演出） |
| `playing` | 通常プレイ。敵出現・弾発射・吸収・解放・当たり判定を処理する | ライフが 0 になった瞬間に `ending` |
| `ending` | 自機の爆発演出を 1 秒間再生。新規の敵出現・弾発射・入力・吸収・当たり判定は停止する。すでに画面にある敵・敵弾・解放弾は動き続ける | 1 秒経過で `GameOver` Scene を起動（スコアを引き渡す） |

- どのフェーズでも、画面が隠れた・フォーカスが外れたときは一時停止し、プレイヤーの操作で再開する（[一時停止](spec/pause.md)）。一時停止中はフェーズの経過時間も進まない

- `GameOver` → `Game`: 受け付け開始後のリトライ操作（スペース・X・Enter・クリック・タップ。下記「GameOver 画面」の **入力**）で `scene.start('Game')` を呼び、状態を完全リセットする
- `Game` Scene 終了時（`shutdown`）にキー入力・タイマー・ポインタのリスナー、一時停止のきっかけ（`visibilitychange`・`blur` など）のリスナーをすべて解除する

### GameOver 画面（スコアの内訳）

最終スコアが何から成り立っているかを見せ、次のプレイで何を狙えばよいかの手がかりと、振り返りの満足感を与える。表にはそのプレイで倒した種類の敵だけを出す（まだ出会っていない敵の名前を明かさず、長く生き残るほど行が増えて進んだ感覚が得られるようにするため）。

- **内容**（上から順に）: 「GAME OVER」、内訳の表、合計、案内「Press SPACE or tap to retry」
- **内訳の表**: 次の行をこの順に出す
  - 敵の行: 「GRUNT」「SHOOTER」「HEAVY」「RAMMER」「SPLITTER」「CARRIER」「BOSS」の 7 種類のうち、**そのプレイの撃破数が 1 以上の種類だけ**を、この順に詰めて出す（撃破数 0 の種類は行ごと出さず、空けもしない）。各行は「名前 ×撃破数 点数」（例: 「GRUNT ×12 1200」）。名前はその敵のゲーム中の通常時の本体色（予告の点滅などで変わる色は使わない。ボスはボス本体の描画と同じ色）で書く。数えるのはそのプレイだけで、過去のプレイの記録は使わない（保存もしない）
  - 受け取ったデータで撃破数が無い・0 の種類は、点数も 0 として扱う（行を出さず、ボーナスの計算にも入れない）。ボーナスは「最終スコア − 表に出す敵の行の点数の和」と等しい
  - 撃破数が 1 以上の種類が 1 つも無いときは、敵の行の代わりに「NO KILLS」の 1 行を出す（白。敵の行の名前の列の位置に置く。撃破数と点数の列は空）
  - ボーナスの行: 常に出す。「MULTI-KILL BONUS +ボーナス」（例: 「MULTI-KILL BONUS +2300」。0 なら「MULTI-KILL BONUS +0」）
  - 表の行（敵の行または「NO KILLS」、ボーナスの行）は上から詰めて並べ、その下に合計、さらにその下に案内を置く。表の一番上の行の位置は行の数によらず同じ（行が少ないと、合計と案内が上に寄る）
  - 数字は桁区切りを入れない整数。「×」は U+00D7
  - 色: 名前以外（撃破数・点数・ボーナスの行・合計）は白（#ffffff）。「GAME OVER」の赤（#ff5252）と案内「Press SPACE or tap to retry」の灰色（#aaaaaa）は従来のまま
- **合計**: 「SCORE 最終スコア」を、表の行より大きな文字で出す（従来の「SCORE 最終スコア」の 1 行をこれに置き換える）
- **数え方**
  - 撃破数: 解放弾で倒した通常の敵（6 種。`splitter` は親と子の合計。[分裂する敵](spec/splitter.md)。`carrier` は [運び屋](spec/carrier.md)。carrier が落とした敵はその種類に数える）とボス、および体当たりで倒したボスの数。体当たりで壊れた通常の敵は数えない（スコアに入らないため）。撃破は倒した瞬間に数える（同時撃破の集計が確定するのを待たない）
  - 各行の点数: 倒した敵の撃破スコア（同時撃破ボーナスの倍率を掛ける前）の合計。ボスは倒した各ボスの撃破スコア（最大 HP × `BOSS_SCORE_PER_HP`）の合計
  - ボーナス: 最終スコア − 7 種類の点数の合計（表に出さない種類は点数 0）（同時撃破ボーナスの倍率による上乗せ分。切り捨て後の値）
  - 最終スコアは、`ending` の終わりにまとめて確定した集計の分まで加えた後のスコア（`GameOver` に渡す値）。この最後の確定の分は、`GameOver` への切り替えの直前の 1 フレームだけ HUD のスコアにも反映されるので、最終スコアは常にゲーム中の HUD の最後の値と等しい（その 1 フレームは目では追えないことがある）。7 種類の点数とボーナスの和は常に最終スコアと等しい（倍率は 1 以上で、体当たりで倒したボスは倍率なしなので、ボーナスは 0 以上）
- **出し方**: 「GAME OVER」は画面が始まった瞬間から表示する（案内の出し方は下記 **案内**）。表に出す行（敵の行または「NO KILLS」、ボーナスの行。全部で n 行、2 ≤ n ≤ 8）を上から順に、k 行目（0 から数える）を画面の開始から k × `GAMEOVER_ROW_INTERVAL` 秒後に、合計をそのあと n × `GAMEOVER_ROW_INTERVAL` 秒後に出し始め、それぞれ `GAMEOVER_ROW_FADE` かけて不透明度を 0 から 1 へ直線的に上げ、その後は不透明度 1 のまま表示し続ける（演出の「時間の規約」の、長さを過ぎたら消えるという決まりは当てはめない）。時間は `GameOver` Scene の開始（`create`）から、毎フレームの経過時間で数える
- **入力**: リトライの操作は、解放と同じキー（スペース・X・Enter のいずれか）と、画面のどこかのクリック・タップ。R キーは使わない
  - **受け付けない時間**: 画面の開始から `GAMEOVER_INPUT_LOCK` 秒は、表に出す行の数によらず、リトライの操作をすべて無視する。`GAMEOVER_INPUT_LOCK` は 7 種類すべての敵の行が出る（表が最大の 8 行の）ときに合計が出そろう時間（`8 × GAMEOVER_ROW_INTERVAL + GAMEOVER_ROW_FADE` = 1.16 秒。合計の行は 0.96 秒から出し始める）で固定する。表の行が少ないときは合計がそれより早く出そろい、案内は合計の後、少し間をおいて現れる（例: 敵 1 種類なら合計は 0.44 秒で出そろい、案内は 1.16 秒から）。解放を連打している最中にゲームオーバーになっても、意図せずスコアを見逃さないようにするため。時間は内訳のフェードと同じく `create` からの毎フレームの経過時間で数え、経過時間が `GAMEOVER_INPUT_LOCK` 以上になったフレームから受け付ける（比較は浮動小数の誤差を許す）
  - **押し直しが必要**: 受け付けるのは、受け付け開始後に新しく押し下げた操作だけ。受け付けない時間の間に押し下げたキー、および `Game` Scene（`playing`・`ending`）から押し続けているキーは、受け付け開始後も押し続けている限り反応せず、一度離して押し直したときに反応する。キーの自動リピート（押しっぱなしで繰り返し届くキー入力）は押し直しとみなさない。クリック・タップは、受け付け開始後に押し下げた（触れた）瞬間に反応する（受け付けない時間の間に触れ始めた指を受け付け開始後に離しても反応しない）
  - 同じフレームに複数の操作が届いても `scene.start('Game')` は 1 回だけ
- **案内**: 「Press SPACE or tap to retry」は受け付けない時間の間は出さず（不透明度 0）、受け付けを始めたフレームから `GAMEOVER_HINT_FADE` かけて不透明度 0 → 1 に上げ、その後は 1 のまま表示し続ける。フェードの途中でもリトライは受け付ける。位置・書体・色は従来どおり（合計の下）
- **受け取るデータ**: `GameOver` は `scene.start('GameOver', { score, breakdown })` で、最終スコアと内訳（`grunt` / `shooter` / `heavy` / `rammer` / `splitter` / `carrier` / `boss` それぞれの撃破数と点数）を受け取る。内訳が無い・欠けている種類は撃破数 0・点数 0 として扱う（撃破数が 0 の種類は点数も 0 として扱う。ボーナスは最終スコア − 撃破数 1 以上の種類の点数の和。スコアも無ければ 0）
- **後始末**: `GameOver` Scene の終了時（リトライで `Game` に戻るとき）に、キー入力・ポインタのリスナーとフェードに使ったタイマー等を残さない
- **配置**: 縦長（幅 768）の画面でもすべて画面内に収まり、重ならないこと。書体・文字の大きさ・行間・列の揃え方は実装裁量（下記）

### 演出・UI

吸収・撃破・解放・同時撃破・被弾の演出は [演出・UI](spec/effects.md) を参照。


## ルール

### 自機

- 半径 10px の円。ライフ 3
- 被弾すると 1 ライフ減り、1.5 秒間の無敵（点滅表示）に入る。同時に**救済としてストックが 10 増える**（1 発ずつ吸収したのと同じ扱いで、途中で 50 に達したらその瞬間に自動解放し、残りは解放後のストックに加える。例: 45 で被弾 → 50 で自動解放 → ストック 5）。無敵中は被弾しないが吸収は可能
- 移動速度 320px/秒（一定）
- 初期位置は画面の横中央、下端から画面高さの 15% の位置

### 吸収フィールド

- `playing` フェーズの間は常に、自機を中心とした半径 90px の円として展開している（操作不要）。`ready` の間の見た目のチャージは [演出・UI](spec/effects.md) の「演出・UI（スタート）」（吸収の判定は `playing` から）
- フィールド内に入った敵弾を吸収して消去し、ストックを敵弾 1 発につき 1 増やす。「フィールド内」は、敵弾の中心と自機の中心の距離が 90px 以下であること（ちょうど 90px も吸収する）
- ストック上限は 50（満タンなら `heavy` 6 体分の HP に届く。追尾の外れを見込んでも数体まとめて倒せる量）。吸収でストックが上限に達した瞬間、手動解放と同じ処理で**自動解放**する（ストックは 0 に戻り、フィールドはそのまま吸収を続ける）。自動解放も同時撃破ボーナスの対象
- フィールドが吸収しなくなる状態はない（満タンでも自動解放で空きができる）
- 吸収する弾の種類による差はない（どの敵弾も +1、MVP）
- 吸った弾は自機へ吸い込まれる演出で見せ、フィールドの縁が脈動する（「演出・UI（吸収）」参照。描画のみで判定・ストックには影響しない）
- 設計意図（バランス調整）: 当初の半径 60px・発射間隔（grunt 1.6 秒 / shooter 2.0 秒 / heavy 2.5 秒）では、上手に動いても序盤の吸収ペースが約 0.6 発/秒しかなく、`heavy` 1 体分の 8 発を溜めるのに 10 秒以上かかり、満タンの自動解放は一度も起きなかった。「溜めて一気に倒す」場面を作るため、半径を 90px に広げ、各敵の発射間隔を短くした（調査で吸収ペースはおよそ 2 倍になった）

### 解放

- 解放キーを押した瞬間、ストックが 1 以上あれば、ストック全弾を解放弾として自機位置から放つ。ストックは 0 になる。0 のときは何も起きない
- 解放弾は 1 発ダメージ 1、速度 600px/秒。発射時は自機から放射状にわずかに散らばる（ランダムな初期角度、±30°）
- 解放弾は 1 発ずつ自分の**標的**を持ち、毎フレーム標的へ進行方向を追尾補正する（最大旋回 360°/秒）。標的にできるのは画面内にいる生存中の敵だけ（出現途中や再出現前でまだ画面外にいる敵は対象外）
- **標的の割り振り（解放時）**: 撃破に必要な弾数だけを各敵に割り振り、弾をばらけさせて一度に多くの敵を倒せるようにする
  1. 各敵の「不足数」= 残り HP − すでにその敵を標的にしている解放弾の数（前の解放の弾も含む）。0 未満は 0
  2. 画面内の敵を自機に近い順に並べ、不足数ぶんずつ弾を割り振る
  3. すべての敵の不足数を満たしても弾が余った場合は、余りを自機に近い敵から順に 1 発ずつ巡回して割り振る
  4. 画面内に敵が 1 体もいない場合、弾は標的なしで発射される
- **標的の付け替え（飛行中）**: 標的が撃破された・画面外に出た、または標的を持っていない解放弾は、毎フレーム新しい標的を探す。「不足数が 1 以上の敵」のうちその弾に最も近い敵を選び、いなければ（全員に足りている）その弾に最も近い画面内の敵を選ぶ
- 標的がいない場合、解放弾は直進する
- 解放弾は画面外に出るか、発射から 2.5 秒経過すると消える
- 解放弾が敵に触れると、その敵の HP を 1 減らして解放弾は消える。HP が 0 になった敵は撃破される
- 解放弾は自機・敵弾には当たらない

### 敵

敵の種類（`grunt` / `shooter` / `heavy` / `rammer`）ごとの HP・弾パターン・発射間隔・撃破スコア・当たり半径、出現位置、動き、同時存在の上限は、[敵の種類と動き](spec/enemies.md) に書く。`splitter`・`carrier`・ボスは、それぞれ [分裂する敵](spec/splitter.md)・[運び屋](spec/carrier.md)・[ボス敵](spec/boss.md) に書く。出現の比率・間隔・敵弾の速度は、次の「難易度スケール」に従う。

### 難易度スケール

経過時間（`playing` フェーズ開始からの秒数）で段階的に上げる。

| 経過時間 | 出現比率（`grunt` / `shooter` / `heavy` / `splitter`） | 出現間隔 | 敵弾速度 | `rammer` 出現間隔 | `rammer` 1 回の数 |
|---------|-----------|---------|---------|-----------------|-----------------|
| 0〜30 秒 | 100 / 0 / 0 / 0 | 3.0 秒 | 180px/秒 | 10 秒（初回は 10 秒経過時） | 1 |
| 30〜60 秒 | 50 / 25 / 15 / 10 | 2.5 秒 | 200px/秒 | 8 秒 | 1 |
| 60〜120 秒 | 30 / 30 / 25 / 15 | 2.0 秒 | 230px/秒 | 6 秒 | 2 |
| 120 秒〜 | 20 / 30 / 35 / 15 | 1.6 秒 | 260px/秒 | 4 秒 | 3 |

- 各段階の境界は「その秒数ちょうどから次の段階」（例: 30.0 秒は 30〜60 秒の段階）
- 出現する敵の種類は出現比率に従って乱数で選ぶ
- 敵弾速度は発射時点の段階で決まり、発射後に変わらない
- 設計意図（バランス調整）: 当初の比率（30〜60 秒 70/30/0、60〜120 秒 50/30/20、120 秒〜 35/30/35）では `heavy` が 60 秒を過ぎてから 2 割しか出ず、`heavy` が 2 体以上そろう時間が 1 プレイあたり数秒しかなかった。`heavy` の包囲と一斉突撃を実際に起こすため、30 秒台から出現させ、比率も上げた

### スコア

- 敵の撃破スコア（[敵の種類と動き](spec/enemies.md) の「敵」の表）を加算する
- **同時撃破ボーナス**: 1 回の解放で撃破した敵の数が 2 体以上なら、撃破スコア合計に `(撃破数 − 1) × 50%` の倍率を上乗せする（例: 3 体同時 → 合計 × 2.0）。同時撃破は「1 回の解放によって放たれた解放弾のうち、その解放弾が撃破した敵」の合計で数える。解放弾が全て消滅した時点で集計を確定する
- 前の解放の弾が残っている間に次の解放（自動解放を含む）が起きた場合も、解放ごとに別々に集計する。撃破は「とどめを刺した解放弾が属する解放」に数える
- 倍率を掛けた後の端数は切り捨てる。スコアは整数
- 生存ボーナスなし

### 勝利条件・失敗条件

- 勝利条件はなし（エンドレス、スコアアタック）
- 失敗条件: ライフが 0 になる

## MVP 範囲（初版で作る範囲）

- 自機の移動（矢印キー・WASD、タッチの相対ドラッグ）、タッチ端末での解放ボタン
- 端末の向きに合わせたゲーム画面サイズ（縦長・横長）

- 同時撃破ボーナスを含むスコア計算
- HUD（スコア・ライフ・ストックゲージ）

- 図形描画のみによる表示（外部アセットなし）

## 技術要件

- フレームワーク: Phaser 4.x（TypeScript）、Vite でビルド（静的サイト）
- lint: ESLint（エラー 0 件）
- テスト: Vitest（カバレッジ 90% 以上）
- 表示は `Graphics` などの図形描画のみで、外部画像に依存しない
- 見た目（敵ごとの色・形、吸収フィールド・解放弾・敵弾の描き方、`grunt` の予告の震え・`rammer` の予告点滅の表現、HUD のフォント・ゲージの形）は実装者の裁量とする。ただし敵 6 種（`splitter`・`carrier` を含む）は色か形で見分けられること、吸収フィールドの範囲が見えること
- ゲームロジック（ストック管理、追尾、当たり判定、難易度、スコア、敵出現）は Phaser に依存しない純粋関数／クラスとして `src/game/logic/` 配下に切り出し、単体テスト可能にする。Scene はロジックの呼び出しと描画のみを担当する
- 乱数・時刻は注入可能にし、テストで再現できるようにする
- スコアの内訳のため、ロジック（`World`）は撃破の数と点数を種類ごと（6 種とボス。`splitter` は親と子の合計）に記録し、`GameOver` Scene へ最終スコアと一緒に渡す（`scene.start` のデータとして）。スコアの計算と確定のタイミングは変えない。内訳の集計（ボーナスの算出を含む）、行の文言、行ごとの不透明度の時間変化は `src/game/logic/` の純粋関数にしてテストする
- ゲーム画面のサイズはロジックの定数に固定せず、プレイ開始時に決めたサイズ（幅・高さ）をロジック側へ渡す。サイズを決める計算も純粋関数にしてテストする
- タッチ入力は Phaser の `Pointer` イベントで自前実装する（外部プラグインを使わない）。ロジックへは「そのフレームのドラッグ移動量」（目標位置の管理と速度制限はロジック側で行う）と「解放が押されたか」として渡す。指を「解放」「ドラッグ」「無視」のどれにするかの振り分け（「タッチ」の節の順）は、ドラッグ中の指の有無・触れた位置・再開に使った指かを受け取って役割を返す純粋関数にしてテストする。ボタンに触れたかの判定は `pointer.x` / `pointer.y` とボタンの中心の距離が `BUTTON_HIT_RADIUS` 以下かどうか
- 毎フレーム処理でオブジェクト生成を最小化する（弾はプールまたは配列の再利用を優先）
- Scene 終了時に入力リスナー・タイマーを解除する（重複登録を防ぐ）
- 状態はモジュール／Scene のプロパティで管理し、グローバルを汚染しない

## テスト観点

- ストック管理: 吸収で +1、50 に達した時点で自動解放され 50 を超えない、解放で 0 に戻る、0 のときの解放は no-op
- 吸収判定: フィールド半径内の弾のみ吸収、境界値（ちょうど半径）、上限到達で自動解放してストックが 0 に戻る、自動解放後も吸収を続ける、`playing` 以外のフェーズでは吸収しない
- 被弾判定: 自機と敵本体の半径の重なり判定、敵弾では被弾しない、無敵時間中は被弾せず敵も壊れない、被弾でライフが 1 減る、ライフ 0 で `ending`
- 接触時の処理: 接触した敵 1 体が壊れる（スコア・同時撃破に数えない）、その敵を狙っていた解放弾は付け替える、ストックが 10 増える、途中で 50 に達すると自動解放して残りを持ち越す（45 → 解放 → 5）
- 標的の割り振り: 自機に近い順に不足数（残り HP − 向かっている弾数）ずつ割り振る、前の解放の弾を不足数から差し引く、余りは近い順に巡回、画面外の敵には割り振らない、敵不在なら標的なし
- 追尾ロジック: 標的が撃破・画面外になったら付け替える、付け替えは不足数 1 以上の敵のうち弾に最も近い敵を優先し、いなければ弾に最も近い画面内の敵、標的不在時は直進、旋回速度の上限（360°/秒）、2.5 秒または画面外で消滅
- 同時撃破の集計: 解放が重なったとき、撃破がとどめを刺した弾の解放に数えられる、倍率後の端数切り捨て
- 出現比率: 段階ごとの比率（`splitter` を含む 4 種）に従って種類が選ばれる（乱数を注入して境界を確認。0〜30 秒は `grunt` のみ）、最初の敵が 0 秒で出る
- 解放弾と敵: 命中で HP が 1 減る、HP 0 で撃破、1 発の弾が複数の敵に当たらない
- スコア: 敵種ごとの撃破スコア、同時撃破ボーナスの倍率（1 体 = 等倍、2 体 = ×1.5、3 体 = ×2.0）、解放弾がすべて消えてから集計が確定する
- 難易度スケール: 経過時間から敵種・出現間隔・弾速を引く境界値（30/60/120 秒ちょうど）、`rammer` の初回出現が 10 秒
- 画面サイズの決定: 横長・縦長・正方形の表示領域、4:3 未満・2:1 超の縦横比のクランプ、四捨五入
- 画面サイズ基準の値: 縦長サイズでも定位置の高さ・左右出現の高さと位置・自機の初期位置・移動範囲が画面サイズの割合どおりになる
- タッチ移動: ドラッグ量だけ目標位置が動く、自機は最大 320px/秒で目標へ向かい着いたら止まる、目標位置は移動範囲でクランプされる、キーボード入力があると目標位置を破棄してキーボードで動く
- 指の振り分け（純粋関数）: ドラッグ中の指がなければ、ボタンの中心から `BUTTON_HIT_RADIUS` ちょうど（88px）は解放、88px を超えるとドラッグ（描く円の半径 56px を超えて 88px 以内も解放）。ドラッグ中の指があれば、位置に関係なく（画面の四隅・自機の上・ボタンの上のどれでも）解放。再開に使った指は、ドラッグ中の指の有無にかかわらず無視。解放の指が触れたままでも、次の指はドラッグ中の指の有無で役割が決まる。ドラッグ中の指を離すとドラッグ中の指がない状態に戻り、次の指はドラッグになる（ボタンの範囲の外なら）。解放の指はドラッグ量を動かさない。役割の寿命: 記録のない指（`Game` の開始前から触れていた指）は無視、指が離れる・キャンセルされる・画面の外で離れると記録が消えてドラッグ中の指がない状態に戻る（その直後に触れた指はドラッグ）、一時停止の開始でドラッグ中の指が無視に変わりドラッグ中の指がない状態になる（その指を離す前に別の指が触れるとドラッグ）、一時停止中に触れた指はすべて無視。同じフレームに届く 2 本は届いた順に振り分ける（1 本目がドラッグならば 2 本目は解放、1 本目が解放ならば 2 本目はドラッグ）。PC（タッチ非対応）ではボタンの範囲でもドラッグになり、別の指の解放もない
- 移動: 画面境界のクランプ（上端は HUD の帯 48px + 自機半径、下・左右は自機半径）
- フェーズ遷移: `ready` → `playing` → `ending` → `GameOver`、入力の無効化タイミング
- スコアの内訳: 解放弾で倒した通常の敵が種類ごとに数えられ、点数は倍率前の撃破スコアの合計（grunt 2 体を同時撃破 → GRUNT ×2 200、ボーナス 100、最終スコア 300）。体当たりで壊れた通常の敵は数えない。ボスは解放弾でも体当たりでも倒せば BOSS に数え、点数は各ボスの最大 HP × `BOSS_SCORE_PER_HP` の合計（1 体目と 2 体目で点数が違う）。`ending` の終わりにまとめて確定した集計の撃破も含む。7 種類の点数とボーナスの和が最終スコアと等しい。行の文言は部品（名前・「×12」・「1200」、ボーナスは「MULTI-KILL BONUS」・「+2300」、0 は「+0」）で返し、Scene は部品を列に並べてよい。表に出す敵の行: 撃破数 1 以上の種類だけが決まった順に並ぶ（例: GRUNT 3 体と BOSS 1 体 → GRUNT・BOSS の 2 行、間の種類は出ない。7 種類すべて → 7 行）。撃破 0 のときは「NO KILLS」の 1 行。表の行の数 n（敵 1 種類 → 2、7 種類 → 8、撃破 0 → 2）。行の不透明度（k 行目は k × 0.12 秒まで 0、そこから 0.1 秒で 0.5、0.2 秒で 1、その後もずっと 1（例: 5 秒後も 1）、合計は n × 0.12 秒から（n = 8 なら 0.96 秒、n = 2 なら 0.24 秒で、0.44 秒で出そろう）。境界の比較は浮動小数の誤差を許す）。内訳の無い・欠けたデータ（すべて 0 として扱い、ボーナスは最終スコア − 表に出す行の点数の和。例: スコア 500 と `{ grunt: { count: 0, points: 200 } }` → GRUNT の行は出ず「NO KILLS」、ボーナス +500）
- リトライの受け付け（純粋関数）: 経過時間から受け付け中かを返す（0 秒・1.15 秒は受け付けない、ちょうど 1.16 秒（浮動小数の誤差を許す）・5 秒は受け付ける）。`GAMEOVER_INPUT_LOCK` が行の間隔と表示時間から導かれ、表が最大の 8 行のときに合計の行が不透明度 1 になる時刻と一致する。表の行が少なくても 1.16 秒のまま（敵 1 種類でも 1.15 秒は受け付けない）。案内の不透明度（1.15 秒で 0、1.16 秒で 0、1.26 秒で 0.5、1.36 秒以降は 1（`GAMEOVER_HINT_FADE` = 0.2 秒のとき））
- リトライの入力の判定（純粋関数またはクラス）: 受け付け前に押し下げたキーは受け付け後も押し続けている間は反応せず、離して押し直すと反応する。`Game` から押し続けているキー（押し下げの記録なしで自動リピートだけ届く）は反応しない。受け付け後に新しく押し下げたスペース・X・Enter は反応する。R キーは反応しない。受け付け前のクリック・タップは反応せず、受け付け後は反応する。同じフレームに複数届いても 1 回だけ
- スコアの内訳の回帰（変えないもの）: スコアの計算と最終スコアの値、`ending` の長さと `GameOver` への遷移、ゲーム中の挙動・演出、内訳の行と合計の不透明度（時刻。n = 8 のとき合計は 0.96 秒から）とリトライの受け付け（1.16 秒）を確かめる既存テストが、変更なしですべて通ること。撃破 0 の種類の行（「×0」「0」）が出ることを確かめていた既存テストだけは、表に出す行を詰める・「NO KILLS」を出す新しいテストに置き換える。リトライの操作と画面の見た目はスクリーンショットで確認する（完了条件参照）
- 指の振り分けの回帰（変えないもの）: 解放のルール（押した瞬間の 1 回、ストック 0 では何も起きない、押し続けても 1 回、自動解放）、キーボード操作、ドラッグの操作感（ドラッグ量・最大速度 320px/秒・目標位置のクランプ）、一時停止からの再開の指が解放・ドラッグにならないこと、リトライ、スコア・難易度・敵・ボスの既存のテストが、変更なしですべて通ること
