# 演出・UI

## 概要

敵弾の吸収・撃破・解放・同時撃破・被弾を、その場で感じられるようにする演出。すべて `Game` Scene の描画だけで、ルール（ロジック）には影響しない。コアループ（吸う → 溜める → 撃つ）の各段階の手応えを強める。

本文中の「」で示す節名・パラメータ名のうち、このファイルにないものは [docs/spec.md](../spec.md)（または [ボス敵](boss.md)）の節・パラメータ表を指す。

## 操作仕様（追加・変更分）

なし

## 画面・Scene構成（追加・変更分）

新しい Scene はない。描画順の全体は docs/spec.md の「レイアウト方針」を参照。

### 演出・UI（吸収）

敵弾を吸ったことを自機の周りで感じられるようにする演出。どの演出も `Game` Scene の描画だけで、ルール（ロジック）には影響しない。吸収の判定・ストックの増加・敵弾の消去は従来どおり吸った瞬間に行い、演出の間も吸った弾は当たり判定には存在しない。入力は止めない。

- **時間の規約**: [ボス敵](boss.md) の「時間の規約」と同じ。長さ D の演出は、経過時間 t が 0 ≤ t < D の間だけ描き、t ≥ D で消える。「直線的に変える」値は t = 0 で開始値、t → D で終了値に近づく。以下 u = t / D（0 ≤ u < 1）。きっかけのフレームは t = 0 で描き、以降は毎フレームの経過時間（Scene の delta。ロジックと同じく上限つき）で t を進める
- **きっかけ**: `playing` フェーズでフィールドが敵弾（ボスの弾を含む）を吸収したとき。1 フレームに複数発吸った場合は、吸った弾 1 発ごとに吸い込みを 1 つ、脈動と外側の輪はそれぞれ 1 回だけ始める。被弾時の救済ストック（`HIT_STOCK_BONUS`）は吸った弾がないので、どの演出も出さない。満タンで自動解放されたフレームでも演出は通常どおり出し、自動解放で途中終了させない
- **吸い込み**（吸った弾 1 発ごと）: 長さ `ABSORB_SUCK_DURATION`
  - 開始位置は、吸収と判定されたフレームのその弾の位置（そのフレームの移動を終えた後の位置）。終了位置は毎フレームの**現在の**自機の中心（自機が動けば追いかける）
  - 位置 = 開始位置 + (現在の自機中心 − 開始位置) × u²（最初はゆっくり、自機に近づくほど速い）
  - 半径 = `ENEMY_BULLET_RADIUS` × (1 − u)（0 に向けて直線的に縮む）
  - 色は敵弾の色からフィールドの色へ u に比例して直線的に変える（RGB 各成分の線形補間）。不透明度 1
  - 残像: 本体に加えて `ABSORB_TRAIL_COUNT` 個の残像を描く。k 番目（k = 1, 2, …）の残像は、経過時間 t − k × `ABSORB_TRAIL_INTERVAL` のときの本体と同じ位置・半径・色（位置は現在の自機中心を使って計算する）で、不透明度 1 − k × `ABSORB_TRAIL_ALPHA_STEP`。t − k × `ABSORB_TRAIL_INTERVAL` < 0 の残像はまだ描かない。本体が消える（t ≥ `ABSORB_SUCK_DURATION`）と残像も一緒に消える
  - 同時に再生する吸い込みの数に上限は設けない（吸った弾の数だけ出る）
- **縁の脈動**: 長さ `ABSORB_PULSE_DURATION`
  - ふだんのフィールドの縁（半径 `FIELD_RADIUS` の円周）は太さ `FIELD_EDGE_WIDTH`・不透明度 `FIELD_EDGE_ALPHA`
  - 脈動中は、太さを `ABSORB_PULSE_WIDTH` から `FIELD_EDGE_WIDTH` へ、不透明度を 1 から `FIELD_EDGE_ALPHA` へ、それぞれ直線的に戻す。縁の半径は変えない（吸収範囲を実際より広く見せない）
  - 脈動中に再び吸収したら、その時点から数え直す（同時に 1 つだけ）
- **外側の輪**: 長さ `ABSORB_RING_DURATION`
  - フィールドの色で、太さ `ABSORB_RING_WIDTH` の輪を現在の自機中心のまわりに描く。半径を `FIELD_RADIUS` から `ABSORB_RING_MAX_RADIUS` へ、不透明度を 1 から 0 へ、それぞれ直線的に変える
  - 再生中に再び吸収したら、その時点から数え直す（同時に 1 つだけ）
- **終了**: `playing` を抜けて `ending` に入ったフレームで、再生中の吸収演出（吸い込み・残像・脈動・外側の輪）をすべてその場で消す。同じフレームで弾を吸ってから被弾してライフが 0 になった場合（更新後のフェーズが `ending`）は、そのフレームに吸った弾があっても新しい演出は作らない（演出を作るのは、更新後のフェーズが `playing` のフレームだけ）。リスタート（`Game` Scene の開始）のときも何も残さない
- **描画順**: どれも「自機（吸収フィールドを含む）」の層に描く。層の中では奥から「フィールドの塗り → フィールドの縁（脈動を含む）→ 外側の輪 → 吸い込み（残像が奥、本体が手前）→ 自機本体」。吸い込みは自機本体より奥なので、最後は自機に吸い込まれて見える
- 既存の表現（ストック量に応じてフィールドの塗りが濃くなる）はそのまま残す

### 演出・UI（撃破）

解放弾で通常の敵を倒したことを、その場で感じられるようにする演出。`Game` Scene の描画だけで、ルール（ロジック）には影響しない。破片は当たり判定を持たず、何にも当たらない。撃破された敵は従来どおりそのフレームで当たり判定・標的の対象から外れる。入力は止めない。

- **時間の規約**: 「演出・UI（吸収）」と同じ（[ボス敵](boss.md) の「時間の規約」。きっかけのフレームは t = 0 で描き、以降は毎フレームの経過時間で t を進める）。以下 u = t / `DEBRIS_DURATION`（0 ≤ u < 1）
- **きっかけ**: 解放弾の命中で `grunt` / `shooter` / `heavy` / `rammer` / `splitter`（親と子。[分裂する敵](splitter.md)）/ `carrier`（[運び屋](carrier.md)）の HP が 0 になり撃破されたとき（手動解放・自動解放どちらの弾でも）。1 フレームに複数体を撃破したら、1 体ごとに破片の組を 1 つずつ出す
- **出さないもの**: 体当たりで壊れた敵、画面外へ出て消えた `rammer` と `splitter` の子と `carrier`、ボス（ボスは [ボス敵](boss.md) の撃破演出を使う）
- **破片の組**（撃破 1 体ごと）: 長さ `DEBRIS_DURATION`
  - 撃破されたフレームの敵の位置（そのフレームの移動を終えた後の位置）を中心に、`DEBRIS_COUNT` 個の丸い破片を出す
  - 破片 i（i = 0, 1, …, `DEBRIS_COUNT` − 1）の飛ぶ向きは θ + i × 360° / `DEBRIS_COUNT`。θ はとどめを刺した解放弾（既存の命中処理の順で、その敵の HP を 0 にした弾）の、そのフレームの旋回・移動を終えた後の進行方向（乱数は使わない）。角度は画面座標（x 右向き・y 下向き）で x 軸正の向きを 0 とし、角度が増えると画面上で時計回りに回る（`Math.atan2(dy, dx)` と同じ規約）
  - 各破片の中心からの距離 = `DEBRIS_SPEED` × `DEBRIS_DURATION` × (u − u² / 2)（初速 `DEBRIS_SPEED` から直線的に減速し、t = `DEBRIS_DURATION` で速度 0。最終的な距離は `DEBRIS_SPEED` × `DEBRIS_DURATION` / 2）
  - 半径 = `DEBRIS_RADIUS` × (1 − u)。色は撃破された敵の種類ごとの通常時の本体色（予告の点滅などの状態による色の変化は使わない）。本体色は既存の描画で使っている各種類の通常時の色をそのまま使う（新しい色定数は作らない）。ただし `rammer` だけは、本体色を白へ寄せた明るい色にする: RGB 各成分 c（0–255）を c + (255 − c) × `DEBRIS_RAMMER_WHITEN` とし、整数に四捨五入する（本体の赤が敵弾の赤と近く、破片が敵弾に見えるのを避けるため）。不透明度 1
  - 同時に再生する破片の組の数に上限は設けない
- **終了**: `ending` に入っても再生中の破片の組は最後まで描く（`ending` では当たり判定が止まるので新しい撃破は起きない）。同じフレームで解放弾による撃破のあと被弾してライフが 0 になった（更新後のフェーズが `ending`）場合も、そのフレームの撃破は一覧に入り、破片の組を作る。リスタート（`Game` Scene の開始）のときは何も残さない
- **描画順**: 敵の層の最後（すべての敵より手前、解放弾より奥）

### 演出・UI（解放）

解放（ストック全弾の一斉放出）の重みと、満タンで自動解放されたことを伝える演出。`Game` Scene の描画（とカメラ）だけで、ルール（ロジック）には影響しない。入力は止めない。

- **時間の規約**: 「演出・UI（吸収）」と同じ（きっかけのフレームは t = 0 で描き、以降は毎フレームの経過時間で t を進める）。以下、衝撃波の輪は u = t / `RELEASE_RING_DURATION`（0 ≤ u < 1）
- **きっかけ**: 解放が起きたとき。手動解放・満タンでの自動解放（被弾の救済ストックで `STOCK_MAX` に達した場合を含む）を区別しない。ストックが 0 で何も起きなかった解放キーには出さない。以下 n は、その解放で放った弾数（1〜`STOCK_MAX`）。1 フレームに解放が複数回起きたら、1 回ごとに衝撃波の輪を 1 つずつ出す
- **衝撃波の輪**（解放 1 回ごと）: 長さ `RELEASE_RING_DURATION`
  - 中心は解放した瞬間の自機の中心（その解放の解放弾の発射位置と同じ）。その後自機が動いても輪は動かない
  - 最終半径 R = `RELEASE_RING_MIN_RADIUS` + (`RELEASE_RING_MAX_RADIUS` − `RELEASE_RING_MIN_RADIUS`) × n / `STOCK_MAX`
  - 太さ W = `RELEASE_RING_MIN_WIDTH` + (`RELEASE_RING_MAX_WIDTH` − `RELEASE_RING_MIN_WIDTH`) × n / `STOCK_MAX`（再生中は一定）
  - 半径を `PLAYER_RADIUS` から R へ、不透明度を 1 から 0 へ、それぞれ直線的に変える。色は解放弾の色。線は円周を中心に太さ W で描く（内外に W / 2 ずつ）
  - 同時に再生する輪の数に上限は設けない
- **画面揺れ**: n = `STOCK_MAX`（満タンの解放。手動・自動を問わない）のときだけ、長さ `RELEASE_SHAKE_DURATION`、揺れ幅 `RELEASE_SHAKE_AMPLITUDE` で画面全体（プレイ領域と HUD）を揺らす。n < `STOCK_MAX` では揺らさない
  - 揺れはカメラの表示位置をずらすだけで、ゲーム内の座標・当たり判定・入力（タッチの座標換算を含む）・移動には影響しない
  - 揺れは `Game` Scene のメインカメラ 1 台（プレイ領域と HUD はどちらもこのカメラで描かれる）に、Phaser のカメラ揺れ機能（`camera.shake`）で行う。長さは `RELEASE_SHAKE_DURATION` をミリ秒に換算して渡す（0.2 秒 → 200）。揺れの間は毎フレーム表示位置を上下左右それぞれ −`RELEASE_SHAKE_AMPLITUDE` 〜 +`RELEASE_SHAKE_AMPLITUDE` px の範囲でずらし（強さはゲーム画面の幅・高さに対する割合として、横 `RELEASE_SHAKE_AMPLITUDE` / 幅、縦 `RELEASE_SHAKE_AMPLITUDE` / 高さ を渡す）、終わったら元の位置に戻す。揺れの時間は Phaser の経過時間で数える。ずらし量は整数に丸めない（カメラの `roundPixels` は無効のままにする）
  - 揺れの途中で再び満タンの解放が起きたら、その時点から `RELEASE_SHAKE_DURATION` を数え直す（重ねて大きくはしない。`camera.shake` の `force` を使う）
  - 解放ボタンも HUD の一部として一緒に揺れて描かれる。ボタンの当たり判定とドラッグ量は揺れの影響を受けない画面座標で扱うので、揺れの間は描かれたボタンと当たり判定が最大 `RELEASE_SHAKE_AMPLITUDE` px ずれる（意図した挙動）
- **終了**: `ending` では新しい解放は起きない。再生中の輪と揺れは最後まで再生する。同じフレームで解放が起きてから被弾してライフが 0 になった（更新後のフェーズが `ending`）場合も、そのフレームの解放は一覧に入り、輪と（満タンなら）揺れを出す（撃破演出と同じ扱い）。リスタート（`Game` Scene の開始）のときは何も残さず、カメラの表示位置も元に戻っている
- **描画順**: 解放弾の層の最後（すべての解放弾より手前、自機より奥）

### 演出・UI（同時撃破）

同時撃破ボーナス（「スコア」参照）を目に見えるようにし、まとめて倒すほど倍率が伸びていく手応えと、集計が確定した瞬間のご褒美を見せる演出。`Game` Scene の描画だけで、ルール（スコアの計算・確定のタイミング）には影響しない。入力は止めない。以下「集計」は同時撃破ボーナスの単位（1 回の解放ごと。撃破はとどめを刺した解放弾が属する解放に数える）、k はその集計のその時点の撃破数。

- **時間の規約**: 「演出・UI（吸収）」と同じ（きっかけのフレームは t = 0 で描き、以降は毎フレームの経過時間で t を進める）
- **倍率の表記**: 倍率 = 1 + (k − 1) × `RELEASE_BONUS_STEP`（「スコア」と同じ式）を、小数点以下 1 桁で「×1.5」「×2.0」のように書く
- **大きさと色**（k ごと）: 文字の大きさ S(k) = min(`MULTIKILL_FONT_BASE` + `MULTIKILL_FONT_STEP` × (k − 2), `MULTIKILL_FONT_MAX`) px。色は k = 2 で白（#ffffff）、`MULTIKILL_TIER_YELLOW` ≤ k < `MULTIKILL_TIER_ORANGE` で黄（ボスの色と同じ #ffd54f）、k ≥ `MULTIKILL_TIER_ORANGE` で橙（`shooter` の色と同じ #ffa726）。書体は HUD と同じ
- **カウント表示**（集計ごとに 1 つ）: その集計の撃破数が 2 以上になったフレームに現れ、以後その集計で撃破が起きたフレームごとに更新する
  - 文字は「k HIT ×倍率」（例: 「3 HIT ×2.0」）。大きさ S(k)、色は k の色、不透明度 1
  - 位置: 文字の中心（原点は文字の中央）を、その集計で最後に倒した敵の位置（撃破したフレームの敵の位置）から上へ `MULTIKILL_OFFSET_Y` の点に置く。ただし拡大率 1 のときの文字の幅 W・高さ H（描画した文字の実際の大きさ。縁取りを含む）を使って、中心の x を `MULTIKILL_EDGE_MARGIN` + W / 2 〜 画面幅 − `MULTIKILL_EDGE_MARGIN` − W / 2、y を T + H / 2 〜 画面高さ − H / 2 の範囲に収める（画面の外にも HUD の帯にもはみ出さない）。T は上端の限界で、ボスがいない間は `HUD_HEIGHT`、ボスがいる間（そのフレームにボスが存在するとき）は HUD の帯の下のボス HP バーも避けて `HUD_HEIGHT` + `BOSS_BAR_HEIGHT`。弾みで拡大している間のはみ出しは許容する。W・H は文字が変わるたび（更新のたび）に測り直す。範囲が空になる軸（文字が画面より広い・高いとき）だけ、その軸の中心を画面の中央に置く（もう一方の軸は通常どおり範囲に収める）
  - 更新したときは新しい位置へ即座に移る（補間しない）
  - 弾み: 表示が現れた・更新されたフレームから `MULTIKILL_POP_DURATION` の間、拡大率を `MULTIKILL_POP_SCALE` から 1 へ直線的に戻す（それ以外は 1）。拡大は文字の中心を基準にする。1 フレームに同じ集計で複数体を倒したら、最後の撃破の位置と撃破数で 1 回だけ更新する。フレーム内の「最後」は、当たり判定を処理する順（解放弾を発射した順）で後に起きた撃破とし、確定表示の「最後に倒した敵がボスか」もこの順で決める
  - その集計が確定するまで表示し続ける（撃破がない間も消えない）
- **確定表示**（撃破数 2 以上の集計が確定したとき）: 確定したフレームでカウント表示を消し、代わりに「+」に続けてその集計の獲得点（倍率を掛けて切り捨てた後の値。HUD のスコアに加算される値と同じ）を出す（例: 「+1800」）
  - 大きさ S(k) × `MULTIKILL_RESULT_SCALE`、色は確定時の k の色
  - 開始位置はカウント表示の最後の位置（範囲に収めた後の位置）。ただしその集計で最後に倒した敵がボスのときは、そこからさらに上へ `MULTIKILL_BOSS_OFFSET_Y`（ボスの撃破演出のスコア表示は撃破位置から始まるので、それと重ならないように。カウント表示の段階での重なりは許容する）
  - 開始位置も画面内に収める: 確定表示の拡大率 1 のときの幅 W'・高さ H' を使って、中心の x を `MULTIKILL_EDGE_MARGIN` + W' / 2 〜 画面幅 − `MULTIKILL_EDGE_MARGIN` − W' / 2、y を T + `MULTIKILL_RESULT_RISE` + H' / 2 〜 画面高さ − H' / 2 の範囲に収める（T はカウント表示と同じ。確定したフレームにボスがいるかで決める。W'・H' も縁取りを含む）（上がりきっても HUD の帯に入らない）。ボスの近くでこの範囲に押し戻されてボスのスコア表示と重なるのは許容する。範囲が空になる軸だけ、その軸の中心を画面の中央に置く
  - `MULTIKILL_RESULT_DURATION` かけて `MULTIKILL_RESULT_RISE` だけ直線的に上へ動きながら、不透明度を 1 から 0 へ直線的に下げ、終わったら消える。拡大率は 1
- **撃破数が 1 以下の集計**: カウント表示も確定表示も出さない（撃破 0 も同じ）
- **同じフレームの撃破と確定**: 同じ集計で撃破数の更新と確定が同じフレームに起きたら（最後の弾が最後の敵を倒して消えたときなど）、更新を先に、確定を後に処理する。そのフレームにはカウント表示を描かず、確定表示だけを出す。確定表示の開始位置は、その更新で決まるカウント表示の位置（範囲に収めた後）を基準にする
- **複数の集計**: 解放が重なって集計が同時に複数あるときは、それぞれ別のカウント表示・確定表示を出す（数に上限なし）
- **終了**: `ending` の間も、再生中のカウント表示・確定表示は描き続け、`ending` の間に確定した集計にも確定表示を出す。`ending` の終わりに残りの集計がまとめて確定される（`GameOver` への遷移と同時）ときの確定表示は、遷移で画面ごと消えるので気にしない。リスタート（`Game` Scene の開始）のときは何も残さない
- HUD のスコアは従来どおり、集計が確定したフレームに加算する

### 演出・UI（被弾）

自機が敵本体に接触してライフが減ったこと（被弾）の痛さを伝える演出。`Game` Scene の描画だけで、ルール（被弾・無敵・救済ストック）には影響しない。入力は止めない。被弾後の無敵中の点滅（「自機」参照）はそのまま残す。

- **時間の規約**: 「演出・UI（吸収）」と同じ（きっかけのフレームは t = 0 で描き、以降は毎フレームの経過時間で t を進める）。以下、それぞれの演出の長さを D として u = t / D（0 ≤ u < 1）
- **きっかけ**: 被弾してライフが 1 減ったフレーム（通常の敵・ボスとの接触のどちらも）。無敵中の接触はライフが減らないので出さない。最後のライフでの被弾（そのフレームに `ending` に入る）でも出す。被弾の位置は、そのフレームの移動を終えた後の自機の中心
- **色**: どれも敵弾と同じ赤（#ff5252）
- **画面全体の赤み**: 長さ `HIT_TINT_DURATION`。ゲーム画面全体を赤で塗り、不透明度を `HIT_TINT_ALPHA` から 0 へ直線的に下げる
- **四辺の赤い帯**: 長さ `HIT_EDGE_DURATION`。ゲーム画面の上下左右の端から内側へ幅 `HIT_EDGE_WIDTH` の帯を赤で塗る。画面内の点の不透明度は、最も近い画面の端までの距離を d として `HIT_EDGE_ALPHA` × max(0, 1 − d / `HIT_EDGE_WIDTH`) × (1 − u)（端で最も濃く、内側へ直線的に薄くなり、時間とともに直線的に消える）。角は最も近い端までの距離で決まる（上辺と左辺の帯が重なって濃くはならない）
- **衝撃の輪**: 長さ `HIT_RING_DURATION`。被弾の位置を中心に、太さ `HIT_RING_WIDTH` の輪（線は円周を中心に内外へ半分ずつ）を描く。半径を `PLAYER_RADIUS` から `HIT_RING_MAX_RADIUS` へ、不透明度を 1 から 0 へ、それぞれ直線的に変える。中心は被弾の位置のまま動かない
- **再び被弾したとき**: どの演出もその時点から数え直す（同時に 1 つずつ。無敵時間が演出より長いので通常は重ならない）
- **他の演出との関係**: 救済ストックで `STOCK_MAX` に達して自動解放されたフレームでは、被弾の演出と解放の演出（輪・満タンなら揺れ）の両方を出す。画面揺れの間は、赤みと帯もカメラと一緒に揺れる。揺れで画面の端に塗り残しができないよう、赤みと帯は画面の外側へ上下左右それぞれ `RELEASE_SHAKE_AMPLITUDE` 広げて描く（帯の濃淡の位置が揺れで最大 `RELEASE_SHAKE_AMPLITUDE` px ずれるのは許容する）
- **終了**: `ending` の間も最後まで描き、リスタート（`Game` Scene の開始）のときは何も残さない
- **描画順**: 衝撃の輪は自機（`ending` の爆発を含む）の直後。赤みと帯はプレイ領域のすべて（同時撃破の表示、ボスの撃破演出の輪・スコア表示、ボス本体の被弾フラッシュを含む）より手前、HUD（ボス HP バーと「BOSS」の文字、タッチ端末の解放ボタンとその数字を含む）より奥（HUD の文字と解放ボタンは赤みの上に見える）

## ルール

なし（どの演出も描画のみで、ルールには影響しない）

## 技術要件

- 吸収演出のため、ロジック（`World`）は「そのフレームにフィールドが吸った敵弾の位置の一覧」を Scene が読める形で公開する（毎フレームの更新の最初に空にする。救済ストックでは追加しない）。ルール・ストックの処理は変えない。吸収演出の時間変化（位置・半径・色の補間・残像・脈動・外側の輪）の計算は `src/game/logic/` の純粋関数にしてテストする
- 撃破演出のため、ロジック（`World`）は「そのフレームに解放弾で撃破した通常の敵の一覧（位置・種類・とどめの解放弾の進行方向）」を Scene が読める形（読み取り専用）で公開する（毎フレームの更新の最初に空にする。体当たりで壊れた敵・画面外へ出た敵・ボスは入れない）。ルール・スコアの処理は変えない。破片の組の状態管理と時間変化（位置・半径・消えるまで）の計算は `src/game/logic/` の純粋関数・クラスにしてテストする
- 解放演出のため、ロジック（`World`）は「そのフレームに起きた解放の一覧（解放した瞬間の自機の位置・放った弾数）」を Scene が読める形（読み取り専用）で公開する（毎フレームの更新の最初に空にする。ストック 0 の解放キーでは追加しない）。ルール・ストックの処理は変えない。輪の状態管理と時間変化（半径・太さ・不透明度）と、そのフレームの解放で揺れを始めるかどうかの判定は `src/game/logic/` の純粋関数・クラスにしてテストする。揺れそのもの（長さの管理・表示位置のずらし・終了後の復帰）は Phaser のカメラ揺れ機能に任せ、自前で実装しない。タッチのドラッグ量と解放ボタンの当たり判定は、カメラの揺れの影響を受けない画面座標（Phaser の `pointer.x` / `pointer.y`。`worldX` / `worldY` は使わない）で計算する。解放ボタンの当たり判定は `pointer.x` / `pointer.y` とボタンの中心の距離から自前で計算し、Phaser の `setInteractive` による当たり判定（カメラの揺れの影響を受ける）は使わない
- 同時撃破演出のため、ロジック（`World`）は集計（解放ごとの撃破の記録）に、解放ごとに異なる識別子と、その集計で最後に倒した敵の位置と、その敵がボスかどうかを持たせる。そのうえで「そのフレームに撃破数が増えた集計の一覧（識別子・撃破数・最後に倒した敵の位置）」と「そのフレームに確定した集計の一覧（識別子・撃破数・獲得点・最後に倒した敵の位置・最後に倒した敵がボスか）」を Scene が読める形（読み取り専用）で公開する（毎フレームの更新の最初に空にする）。スコアの計算・確定のタイミング・集計の数え方は変えない。カウント表示・確定表示の状態管理と、表記・大きさ・色・位置（範囲に収める計算を含む）・時間変化の計算は `src/game/logic/` の純粋関数・クラスにしてテストする
- 被弾演出のため、ロジック（`World`）は「そのフレームの被弾の一覧（被弾の位置）」を Scene が読める形（読み取り専用）で公開する（毎フレームの更新の最初に空にする。無敵中の接触では追加しない）。被弾・無敵・救済ストックのルールは変えない。演出の状態管理と時間変化（赤みの不透明度、帯の不透明度、輪の半径・不透明度）は `src/game/logic/` の純粋関数・クラスにしてテストする

## テスト観点

- 吸収位置の公開: 吸った弾の数だけ、移動後の位置がそのフレームの一覧に入る、次のフレームには前の分が残らない、救済ストック（+10）では一覧に入らない、自動解放したフレームでも吸った弾はすべて一覧に入る、`ready` と `ending` の間の更新では吸収しないので空。吸収した後に同じフレームで被弾して `ending` に変わった場合は、吸った分が一覧に入る（演出を作らないのは Scene 側の規則）
- 吸収演出の時間変化（「時間の規約」どおりの境界）: 吸い込みの位置（u = 0 で開始位置、u = 0.5 で開始位置から自機中心までの 1/4、自機中心が動くと終点が追従する）、半径（開始時 `ENEMY_BULLET_RADIUS`、中間で半分）、色の補間（開始時は敵弾の色、中間で RGB の中間値）、ちょうど `ABSORB_SUCK_DURATION` で消えている。残像 k は t < k × `ABSORB_TRAIL_INTERVAL` では出ず、出ているときは t − k × `ABSORB_TRAIL_INTERVAL` の本体と同じ値で不透明度 1 − k × `ABSORB_TRAIL_ALPHA_STEP`、本体が消えると残像も出ない。脈動の太さ・不透明度（開始時 `ABSORB_PULSE_WIDTH`・1、中間で中間値、ちょうど `ABSORB_PULSE_DURATION` でふだんの値）。外側の輪の半径・不透明度（開始時 `FIELD_RADIUS`・1、中間で中間値、ちょうど `ABSORB_RING_DURATION` で消えている）
- 吸収演出の回帰（変えないもの）: 吸収判定の境界（ちょうど `FIELD_RADIUS` で吸う）、吸った瞬間にストック +1 して弾が一覧から消える、上限 `STOCK_MAX` での自動解放とストック 0 への戻り、救済ストックの持ち越し（45 → 解放 → 5）、操作（キー移動、解放は押した瞬間の 1 回、タッチの相対ドラッグ）、スコア計算、難易度スケール、敵とボスの挙動を確かめる既存テストが、変更なしですべて通ること。ストック量に応じたフィールドの塗りの濃さと HUD の表示は Scene の描画なので、単体テストではなくスクリーンショットで確認する（完了条件参照）
- 撃破の一覧の公開: 解放弾で撃破した通常の敵が、撃破したフレームの位置・種類・とどめの弾の進行方向で一覧に入る。1 フレームに 2 体撃破したら 2 件。HP が残った命中では入らない。次のフレームには前の分が残らない。体当たりで壊れた敵・画面外へ出た `rammer` と `splitter` の子・画面外へ去った `carrier`・撃破されたボスは入らない。`ready` と `ending` の間の更新では空。同じフレームで撃破してから体当たりで `ending` に変わった場合は、撃破した分が一覧に入る
- 撃破演出の時間変化（「時間の規約」どおりの境界）: 破片の向き（i = 0 は θ、`DEBRIS_COUNT` = 8 なら i = 2 は θ + 90°）、中心からの距離（u = 0 で 0、u = 0.5 で `DEBRIS_SPEED` × `DEBRIS_DURATION` × 0.375 = 36px、u → 1 で 48px に近づく）、半径（開始時 `DEBRIS_RADIUS`、中間で半分）、ちょうど `DEBRIS_DURATION` で消えている。破片の色: `grunt` / `shooter` / `heavy` / `splitter`（親・子）/ `carrier` は本体色そのまま、`rammer` は各成分 c + (255 − c) × `DEBRIS_RAMMER_WHITEN` を四捨五入した色（白へ寄せる割合を引数で与えられる関数にして、0 で本体色、1 で #ffffff、0.25 で白寄り 1/4 になることも確かめる。既定値 0.5 では各成分が本体色と 255 の中間を四捨五入した値）。破片の組の管理: 撃破 1 体ごとに 1 組、各組は自分の経過時間で消える、`ending` でも進み続けて最後まで描かれる、リスタートで空になる、撃破と同じフレームで `ending` に変わっても破片の組が作られる
- 破片に当たり判定がないこと: 破片の組の状態は `World` の外（Scene が持つ純粋クラス）で管理し、`World` の更新は破片を一切参照しない。`World` のテストで、撃破の直後のフレームも敵・敵弾・解放弾・自機・スコアの更新が撃破前と同じ規則で進む（撃破位置の近くの敵弾が吸収・消滅以外で消えない、近くの敵が破片で HP を減らさない）
- 撃破演出の回帰（変えないもの）: 解放弾の命中で HP が 1 減る・HP 0 で撃破・1 発が複数の敵に当たらない、撃破した敵がそのフレームで標的から外れて付け替えが起きる、標的の割り振り、スコアと同時撃破ボーナス（1 体 = 等倍、2 体 = ×1.5、3 体 = ×2.0、全弾が消えてから確定）、ボスの撃破と撃破演出の判定（`bossEvent`）、吸収と吸収演出、操作、難易度、敵とボスの挙動を確かめる既存テストが、変更なしですべて通ること。HUD とボスの撃破演出・吸収演出の見た目は Scene の描画なので、スクリーンショットで確認する（完了条件参照）
- 解放の一覧の公開: 手動解放で 1 件（位置は解放した瞬間の自機の中心、弾数は解放前のストック）、ストック 0 の解放キーでは入らない、吸収で `STOCK_MAX` に達した自動解放で 1 件（弾数 `STOCK_MAX`）、被弾の救済ストックで `STOCK_MAX` に達した自動解放で 1 件（弾数 `STOCK_MAX`、45 → 解放 → 5 の場合も）、次のフレームには前の分が残らない、`ready` 中・`ending` 中の更新では空（解放キーを押しても入らない）、同じフレームで解放してから体当たりで `ending` に変わった場合は解放した分が入る
- 解放演出の時間変化（「時間の規約」どおりの境界）: 最終半径（n = 50 で 220px、n = 25 で 160px、n = 1 で 102.4px）、太さ（n = 50 で 8px、n = 25 で 5px）、半径の変化（u = 0 で `PLAYER_RADIUS`、n = 50 の u = 0.5 で 115px）、不透明度（開始時 1、中間 0.5）、ちょうど `RELEASE_RING_DURATION` で消えている。輪の管理: 解放 1 回ごとに 1 つ、各輪は自分の経過時間で消える、中心は解放時の位置のまま。揺れの判定: そのフレームの解放に n = `STOCK_MAX` のものがあるときだけ揺れを始める（n = 49 だけなら始めない、解放なしなら始めない、49 と 50 が同じフレームにあれば始める）。揺れの長さ・数え直し・終了後の復帰・リスタート時に残らないことは Phaser のカメラ揺れ機能の責務なので、単体テストではなく完了条件のスクリーンショットで確認する。輪は `ending` の間も進み続ける（フェーズを参照しない）、リスタートで輪が残っていない
- 解放演出の回帰（変えないもの）: 解放のルール（全弾放出してストック 0、ストック 0 では何も起きない、上限での自動解放と救済ストックの持ち越し、標的の割り振り・追尾）、当たり判定、スコアと同時撃破ボーナス、難易度・敵・ボスの挙動、吸収・撃破・ボスの演出の判定、操作（解放は押した瞬間の 1 回）を確かめる既存テストが、変更なしですべて通ること。揺れがゲーム内の座標・入力に影響しないことは、揺れをロジックが一切参照しない構造（揺れは Scene のカメラだけ）で保証し、HUD の内容と各演出の見た目はスクリーンショットで確認する（完了条件参照）
- 同時撃破の一覧の公開: 1 回の解放で 2 体を別のフレームで倒すと、それぞれのフレームで撃破数 1・2 の更新が 1 件ずつ入り、位置はそのフレームに倒した敵の位置。1 フレームで同じ集計の 2 体を倒すと更新は 1 件（撃破数 2、位置は後に倒した敵）。解放が 2 つ重なると識別子の異なる 2 件。全弾が消えたフレームに確定の一覧に 1 件入り、獲得点は HUD のスコアに加算された値と等しい（2 体 = 撃破スコア合計 × 1.5 の切り捨て）。撃破 0 の集計も確定の一覧には入る（撃破数 0）。最後にボスを倒した集計は「最後がボス」、ボスを倒した後に通常の敵を倒した集計は「最後がボス」ではない。次のフレームには前の分が残らない
- 同時撃破演出の計算: 倍率の表記（k = 2 → 「×1.5」、3 → 「×2.0」、4 → 「×2.5」）、文字の大きさ（k = 2 で 24px、3 で 28px、8 で 48px、9 でも 48px）、色（k = 2 白、3・4 黄、5 以上 橙）、位置（最後に倒した敵の 30px 上、文字の幅・高さを与えて左端・右端・上端・下端で範囲に収まる境界。例: 幅 1365・文字幅 120 なら中心 x は 76〜1289。ボスがいる間は上端の限界が 64px になる。範囲が空になった軸だけが画面の中央になる）、同じフレームの撃破と確定（カウント表示は作られず、確定表示の開始位置はその更新の位置）、ボスを最後に倒したときだけ確定表示がさらに 50px 上（ボスを含むが最後ではない集計ではずれない）、確定表示の開始位置の範囲（上がりきっても HUD の帯に入らない）、弾み（更新時 1.4、0.075 秒で 1.2、ちょうど 0.15 秒で 1）、確定表示（大きさ 1.5 倍、開始位置はカウント表示の最後の位置、最後に倒した敵がボスならさらに 50px 上、0.5 秒で 20px 上・不透明度 0.5、ちょうど 1.0 秒で消えている）。表示の管理: 撃破数 1 ではカウント表示を作らず 2 で作る、更新で位置・撃破数が変わり弾みが数え直される、確定でカウント表示が消え撃破数 2 以上なら確定表示ができる、撃破数 1 以下の確定では何も出ない、集計ごとに別の表示、`ending` の間も進み続ける（フェーズを参照しない）、リスタートで空
- 同時撃破演出の回帰（変えないもの）: スコアの計算（撃破スコア、同時撃破ボーナスの倍率、切り捨て）と確定のタイミング（全弾が消えた時点）、解放ごとの集計、とどめの弾の解放に数えること、`ending` の終わりの残りの集計の確定、標的の割り振り、当たり判定、難易度・敵・ボスの挙動、他の演出の判定、操作を確かめる既存テストが、変更なしですべて通ること。HUD の内容と他の演出の見た目は Scene の描画なので、スクリーンショットで確認する（完了条件参照）
- 被弾の一覧の公開: 被弾したフレームに 1 件入り、位置はそのフレームの移動後の自機の中心。無敵中の接触では入らない。最後のライフでの被弾でも入る（そのフレームのフェーズは `ending`）。救済ストックで自動解放されたフレームでは被弾と解放の両方の一覧に入る。次のフレームには前の分が残らない。`ready` 中・`ending` 中の更新では空
- 被弾演出の計算（「時間の規約」どおりの境界）: 赤みの不透明度（開始時 0.25、0.1 秒で 0.125、ちょうど 0.2 秒で消えている）、帯の不透明度（開始時の端で 0.7、端から 32px で 0.35、64px 以上で 0、0.2 秒の端で 0.35、ちょうど 0.4 秒で消えている）、輪（開始時の半径 10px・不透明度 1、0.175 秒で半径 75px・不透明度 0.5、ちょうど 0.35 秒で消えている）。演出の管理: 被弾で 3 つとも t = 0 から始まる、再び被弾すると数え直す、`ending` の間も進み続ける（フェーズを参照しない）、リスタートで空
- 被弾演出の回帰（変えないもの）: 被弾のルール（敵本体との接触、1.5 秒の無敵、ライフの減少、救済ストック +10 と上限での自動解放）、`ending` の長さと `GameOver` への遷移、スコア、難易度・敵・ボスの挙動、他の演出の判定、操作を確かめる既存テストが、変更なしですべて通ること。HUD の内容・無敵中の点滅・他の演出の見た目は Scene の描画なので、スクリーンショットで確認する（完了条件参照）

## 完了条件

- 吸収演出: 敵弾を吸ったとき、弾が残像を引きながら自機へ吸い込まれ、フィールドの縁が太く明るくなり、外側の輪が広がって消えることをスクリーンショット（連続撮影）で確認する。演出は短い（0.25 秒以下）ので、長さ・境界は単体テスト（時間変化の関数）で確認し、見た目は `heavy` の全方位弾などをまとめて吸う場面の連続スクリーンショットで確認する。`ending` に入ったあとのスクリーンショットに吸収演出が残っていないこと
- 吸収演出で変えないもの（回帰条件）: 操作（キーボード・タッチの移動と解放）と操作感、吸収判定（半径 `FIELD_RADIUS`、吸った瞬間にストック +1 して弾は当たり判定から即座に消える）、ストック上限 `STOCK_MAX` と自動解放、救済ストック、スコア計算、難易度・敵・ボスの挙動、ストック量に応じてフィールドの塗りが濃くなる表現、HUD（スコア・ライフ・ストックゲージ・解放ボタン）の表示が、演出の追加前と変わらないこと
- 撃破演出: 解放弾で通常の敵を倒したとき、敵の色の破片が放射状に飛んで減速しながら縮んで消えることを、連続スクリーンショットで確認する（長さ・境界は単体テストで確認する）。複数体をまとめて倒した場面で、1 体ごとに破片が出ること。`rammer` の破片が白寄りの明るい色で、敵弾の赤と見分けられること。体当たりで壊れた敵・画面外へ出た `rammer` と `splitter` の子・ボスには破片が出ないこと（ボスは従来の撃破演出だけ）
- 撃破演出で変えないもの（回帰条件）: 操作と操作感、解放弾の命中・撃破の判定と標的の割り振り、スコアと同時撃破ボーナス、難易度・敵・ボスの挙動、ボスの撃破演出、吸収演出、HUD の表示が、演出の追加前と変わらないこと。破片が敵・敵弾・解放弾・自機のどれにも当たらないこと
- 解放演出: 解放したとき、自機の位置から解放弾の色の輪が広がって消え、弾数が多いほど大きく太いことを連続スクリーンショットで確認する（長さ・境界は単体テストで確認する）。満タン（手動・自動）の解放でだけ画面全体が短く揺れること。揺れの前後を連続スクリーンショットで撮り、ずれが見えるのが解放からおよそ `RELEASE_SHAKE_DURATION` の間だけで、その後は HUD の文字と解放ボタンが解放前のスクリーンショットと同じピクセル位置に戻っていること。リスタート直後のスクリーンショットでも同じ位置にあること。揺れの途中で再び満タンの解放が起きたときの数え直しは `camera.shake` の `force` 指定に任せ、プレイ中に再現しにくいのでスクリーンショットでは確かめない。少ない弾数の解放では揺れないこと。タッチ端末相当のビューポートで、揺れの最中もドラッグ移動と解放ボタンが揺れの前と同じように反応すること
- 解放演出で変えないもの（回帰条件）: 操作と操作感（解放は押した瞬間の 1 回、揺れの間もタッチ・キー入力の位置と反応が変わらない）、解放のルールと自動解放の条件、当たり判定、スコアと同時撃破ボーナス、難易度・敵・ボスの挙動、吸収・撃破・ボスの演出、HUD の内容（揺れで一緒に動くのは意図した変更）が、演出の追加前と変わらないこと
- 同時撃破演出: 1 回の解放で複数体を倒したとき、2 体目から最後に倒した敵の近くに「N HIT ×倍率」が出て、倒すたびに数字・大きさ・色が変わり弾むこと、全弾が消えたら「+獲得点」に変わって上へ動きながら消え、その値がそのフレームの HUD のスコアの増えた分と一致すること（その集計だけが確定したフレームで比べる）を連続スクリーンショットで確認する（長さ・境界は単体テストで確認する）。1 体だけの解放では何も出ないこと。画面の端で倒しても文字が画面の外にはみ出さないこと
- 同時撃破演出で変えないもの（回帰条件）: スコアの計算と確定のタイミング、集計の数え方、`ending` の終わりの残りの集計の確定、標的の割り振り、当たり判定、難易度・敵・ボスの挙動、他の演出（吸収・撃破・解放・ボス）、HUD の内容、操作が、演出の追加前と変わらないこと
- 被弾演出: 被弾した瞬間に画面全体がうっすら赤くなってすぐ消え、四辺が赤く光って消え、自機の位置から赤い輪が広がって消えることを連続スクリーンショットで確認する（長さ・境界は単体テストで確認する）。赤みの間も HUD の文字が読めること。最後のライフでの被弾では爆発と重なって出ること。無敵中の接触では出ないこと。ストックが `STOCK_MAX` − `HIT_STOCK_BONUS` 以上のときに被弾すると、被弾の演出と解放の輪・揺れが同時に出て、揺れの間も画面の端に赤みの塗り残しができないこと（QA ではストックを検証用に操作してよい）
- 被弾演出で変えないもの（回帰条件）: 操作と操作感、被弾のルール（接触判定、無敵 1.5 秒、ライフ、救済ストック +10 と上限での自動解放）、`ending` の長さと `GameOver` への遷移、スコア、難易度・敵・ボスの挙動、他の演出（吸収・撃破・解放・同時撃破・ボス・自機の爆発・無敵中の点滅）、HUD の内容が、演出の追加前と変わらないこと

## 実装裁量

- 吸収演出: 吸い込みの記録（配列・プールの方式）、フィールドの色・敵弾の色の具体値（既存の色を使う）、吸い込みを円で描くこと以外の細部（輪郭の有無など）、縁・外側の輪の線の太さを円周のどちら側に付けるか
- 撃破演出: 破片の組の記録（配列・プールの方式）、破片を円で描くこと以外の細部（輪郭の有無など）。破片の色は本体色（`rammer` のみ白へ寄せる）で固定し、実装裁量ではない
- 解放演出: 輪の記録（配列・プールの方式）、揺れの呼び出し方の細部（Phaser のカメラ揺れ機能に渡す引数の組み立て方）。揺れに Phaser のカメラ揺れ機能を使うこと、揺れの長さと最大幅、輪の大きさ・太さ・色・長さは固定
- 同時撃破演出: 表示の記録（配列・プール・テキストオブジェクトの使い回しの方式）、文字の縁取りや影の有無（読みやすさのため付けてよい）、同じ層の中での表示どうし・ボスのスコア表示との前後。表記・大きさ・色・位置・時間は固定
- 被弾演出: 四辺の帯の濃淡の描き方（段階の数などで近似してよい。ただし端で最も濃く、幅 `HIT_EDGE_WIDTH` で 0 になること）、演出の記録の方式。色・大きさ・長さ・不透明度は固定
