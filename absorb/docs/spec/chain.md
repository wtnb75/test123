# 連続解放ボーナス（chain）

## 概要

撃破のある解放を短い間隔で続けるほど、スコアの倍率が上がっていく。ストックを溜めて 1 回で多数を倒す遊び方（同時撃破ボーナス）と、細かく撃って連続を切らさない遊び方の、2 つがスコアで競うようになる（コアループの「溜める → 撃つ」の判断を深める）。スコアの式だけを変え、ほかのルール（解放・標的・敵・ボス）と操作は変えない。

## 操作仕様（追加・変更分）

なし（操作・操作感は変わらない）。

## 画面・Scene構成（追加・変更分）

### レイアウト方針

- `Game` Scene の HUD に「連鎖の表示」を足す。左端（x = `CHAIN_X`）、HUD のスコアの真下に置く。論理 px で、文字は y = `CHAIN_TEXT_TOP`〜`CHAIN_TEXT_TOP + CHAIN_FONT`（52〜76）の帯、その下の y = `CHAIN_BAR_TOP`（80）から高さ `CHAIN_BAR_H` のバー。文字の左端とバーの左端はどちらも x = `CHAIN_X`。画面サイズ（横長・縦長）によらず同じ位置・大きさ
- 画面中央のボス HP バー（[ボス敵](boss.md)。画面幅の半分の幅）や、そのほかの HUD と重ならない。縦長（幅 768）では HP バーの左の「BOSS」ラベル（`BOSS_LABEL_SIZE` 22px。x は約 125〜190、y は約 45〜67）が文字の位置に重なりうるので、**ボスが存在する間（HP バーが出ている間）は、連鎖の文字とバーをまとめて `CHAIN_BOSS_OFFSET_Y`（24px）だけ下へずらす**（文字は y = 76〜100、バーは y = 104〜108）。ボスが撃破されたフレームで元の位置に戻る。横長・縦長どちらでも同じずらし量にする
- 文字の実寸: 連鎖の文字（22px）とバー（4px）は論理 px 固定で、縦長 768×1536 を 390 幅の画面へ縮める（縮小率 約 0.51）と、文字は実寸で約 11px になる。連鎖の段は補助の情報として扱う（スコアそのものは HUD の主な情報で、連鎖は色とバーでも伝わる）。AGENTS.md 4.6 の補助の文字の下限（実寸 11px 以上）を、この縮小率で満たす大きさとして `CHAIN_FONT` を決めている。縮めた画面でこれを下回らないこと（下げない）
- `Demo`（`Title` の背景）には出さない（`Demo` に HUD は無い）。連鎖の計算（ロジック）は `Demo` でも `Game` と同じに動く

### 状態遷移・表示の規則

連鎖は `World`（ロジック）が持つ次の状態で決まる。表示はそれを読むだけで、ルールには影響しない。

- **連鎖の段**: 撃破のあった解放が続いているかを表す整数（0 = 連鎖なし）
- **最後の撃破の時刻**: 最後に解放弾が敵・ボスを倒した時刻（`World` の経過時間）
- 表示する条件（すべて満たす間だけ）: 連鎖の段が 2 以上、かつ 最後の撃破から `CHAIN_WINDOW` 秒が経っていない（`経過 < CHAIN_WINDOW`）。満たさなくなったフレームで文字とバーを消す（フェードしない）。連鎖が続く判定（ちょうど `CHAIN_WINDOW` 秒も続く。「ルール」）と表示の判定（ちょうど `CHAIN_WINDOW` 秒で消える）の境界が異なるのは意図したもの（ちょうどその瞬間に撃破があれば連鎖は続き、表示はその撃破で戻る）
- 文字: 「CHAIN ×n」（n は連鎖の段。10 以上でもそのまま）。大きさ `CHAIN_FONT`（22px）。色は段 2 が白、段 `CHAIN_TIER_YELLOW`（3）〜4 が黄、段 `CHAIN_TIER_ORANGE`（5）以上が橙（[演出・UI](effects.md)「演出・UI（同時撃破）」の白・黄・橙と同じ色）。最後の撃破で段が変わるたびに文字を更新する
- バー: 幅 `CHAIN_BAR_W`（110px）× 高さ `CHAIN_BAR_H`（4px）。残りの割合 = `(CHAIN_WINDOW − 経過) / CHAIN_WINDOW`（0〜1）の分だけ左から塗り、文字と同じ色にする。下地（全幅）は文字の色の薄い色で出してよい（見た目は実装裁量）。解放弾が敵を 1 体倒すたび（同じ解放の 2 体目以降でも）、最後の撃破の時刻が更新されるのでバーは満タンに戻る
- 演出の規約: 時間は `World` の経過時間で数える（一時停止中は進まない。[一時停止](pause.md)）。HUD と同じ層（最前面。一時停止の暗幕は表示より手前）。`ending` の間も、条件を満たす限り出し続ける。リスタートで空にする。入力は止めない。新しい撃破が同じフレームに何度あっても、表示はそのフレームの最後の状態だけを出す

### GameOver 画面

内訳の表のボーナスの行の名前を「MULTI-KILL BONUS」から「BONUS」に改める（[スコアの内訳](../spec.md)。連鎖の分も同じ行に入る）。行の数（最大 9 行）・出し方・`GAMEOVER_INPUT_LOCK`（1.28 秒）・色は変えない。

## ルール

### 連鎖の段と倍率

- **解放弾による撃破**だけが連鎖に関わる（解放弾が通常の敵・ボスを倒したとき）。体当たりで壊れた通常の敵・体当たりで倒したボス（[ボス敵](boss.md)の接触）は、連鎖の段も最後の撃破の時刻も変えない
- **段の決め方**: 解放（自動解放を含む）ごとに、その解放弾が**最初の撃破をした瞬間**に、その解放の段を次のとおり決める。決めた段は、その解放の確定まで変えない（同じ解放の 2 体目以降の撃破では決め直さない）
  - 直前の解放弾による撃破（どの解放のものでもよい）の時刻から `CHAIN_WINDOW` 秒以内（ちょうど `CHAIN_WINDOW` 秒も窓の中）で、その時点の連鎖の段が 1 以上なら、その解放の段 = 連鎖の段 + 1
  - それ以外（まだ撃破がない、窓の外、連鎖の段が 0）は 1
  - 決めた段が、そのまま「連鎖の段」になる。解放弾が敵を倒すたびに「最後の撃破の時刻」を現在の時刻にする（同じ解放の 2 体目以降も）
  - 同じフレームに 2 つの解放が最初の撃破をした場合は、解放弾の処理の順に 1 つずつ決める（前の解放の結果を踏まえて、あとの解放を決める）
  - 同じフレームの中の順序は、**そのフレームの撃破（段の決定・最後の撃破の時刻の更新）を先に、解放の確定（撃破 0 の解放による連鎖の 0 戻しを含む）を後に**行う（[演出・UI](effects.md) の「更新を先に、確定を後に」と同じ流儀）。例: 同じフレームに、別の解放の最初の撃破と、撃破 0 の解放の確定が重なると、最初の撃破は連鎖が続いたまま段を決め、そのあとで 0 に戻る
- **連鎖が 0 に戻る**: 撃破 0 のまま確定した解放（全弾が敵を倒さずに消えた解放）があるとき、確定した瞬間に連鎖の段を 0 にする。ほかの解放がまだ飛んでいても同じ。窓が過ぎただけでは段は 0 にならない（次の最初の撃破が、窓の外として段 1 になる。表示は窓が過ぎた時点で消える）
- **倍率**（解放の確定のときに掛ける。確定のタイミング＝その解放の全弾が消えた時点、と、解放ごとの集計は変えない）:
  - 倍率 = `1 + (撃破数 − 1) × RELEASE_BONUS_STEP + min(段 − 1, CHAIN_MAX_LEVEL) × CHAIN_STEP`
  - `RELEASE_BONUS_STEP` = 0.5（同時撃破。[スコア](../spec.md)）、`CHAIN_STEP` = 1.0、`CHAIN_MAX_LEVEL` = 4（`CHAIN_MAX_BONUS` = `CHAIN_MAX_LEVEL × CHAIN_STEP` = +4.0。段 5 以上で頭打ち）
  - 獲得点 = `floor(その解放の撃破スコアの合計 × 倍率)`（端数は掛けた後に切り捨て。スコアは整数）。撃破数が 1 のときも連鎖の分は掛かる（段 1 なら倍率 1.0）。撃破数 0 の解放は 0 点
  - 例: 段 3・2 体同時撃破で撃破スコア合計 300 → 倍率 `1 + 0.5 + 2.0` = 3.5 → 1050。段 1・1 体で 100 → 100。段 7・1 体で 100 → 倍率 5.0 → 500
- 撃破数・内訳（GameOver の行の撃破数と点数）は変えない。点数は倍率を掛ける前の撃破スコアの合計のまま、連鎖の分は「BONUS」に入る（`最終スコア − 敵の行の点数の和`）
- 同時撃破の表示（「N HIT ×倍率」）は変えない（倍率の表記は `1 + (N − 1) × 0.5` のまま。連鎖の分は含めない）。解放の確定の表示「+獲得点」は、確定した獲得点（連鎖の分を含む。HUD のスコアの増えた分と一致する）を出す。撃破数 1 の解放では、連鎖があっても何も出さない（従来どおり）

## パラメータ表

| 名前 | 初期値 | 意味 |
|------|--------|------|
| `CHAIN_WINDOW` | 5 秒 | 直前の撃破から次の解放の最初の撃破までに連鎖が続く時間（ちょうど 5 秒も続く） |
| `CHAIN_STEP` | 1.0 | 連鎖の段が 1 上がるごとの倍率の増分 |
| `CHAIN_MAX_LEVEL` | 4 | 倍率に効く段の上限（段 − 1 の上限。段 5 で頭打ち） |
| `CHAIN_MAX_BONUS` | +4.0（`CHAIN_MAX_LEVEL × CHAIN_STEP`。独立に調整しない） | 連鎖の分の倍率の上限 |
| `CHAIN_X` | 16px | 連鎖の表示の左端 x |
| `CHAIN_TEXT_TOP` / `CHAIN_FONT` | 52px / 22px | 文字の帯の上端と文字の大きさ（帯は 52〜76） |
| `CHAIN_BAR_TOP` / `CHAIN_BAR_W` / `CHAIN_BAR_H` | 80px / 110px / 4px | 窓の残りを示すバーの位置と大きさ |
| `CHAIN_BOSS_OFFSET_Y` | 24px | ボスが存在する間、連鎖の文字とバーを下へずらす量（「BOSS」ラベルとの重なりを避ける） |
| `CHAIN_TIER_YELLOW` / `CHAIN_TIER_ORANGE` | 3 / 5 | 文字の色が黄・橙に変わる段 |

参考（出発点の目安。完了条件のしきい値ではない）: ボット（Title のデモのボットの移動に、撃つ条件だけ差し替えたもの）を 50 シード・上限 600 秒で走らせ、連鎖の加算を外から計算した結果。スコアの中央値（横長 1365×768）は、早撃ち（ストック 12 で撃つ）133,100 → 240,950、混合（満タン 45・敵が 140px 以内ならストック 4 でも撃つ）175,475 → 355,900、純粋な溜め（自動解放のみ）393,225（変化なし）。縦長 768×1536 は 124,600 → 225,750、211,550 → 351,450、421,650（変化なし）。刻み 0.25・上限 +1.0 では早撃ちが 155,725 にしかならず、狙いに足りなかった。

## テスト観点

- 段の決め方: 最初の撃破で 1（連鎖なし・窓の外・段 0）。窓の中（直前の撃破の 4.9 秒後・ちょうど 5.0 秒後）で +1、5.01 秒後で 1 に戻る。同じ解放の 2 体目以降では段を変えない。別の解放の最初の撃破で +1（前の撃破が別の解放のものでも）。同じフレームの 2 つの解放の最初の撃破は処理順に 1、2 になる
- 最後の撃破の時刻: 同じ解放の 2 体目以降の撃破でも更新される（その後 5 秒以内の別の解放の最初の撃破が連鎖になる）。体当たりで壊れた通常の敵・体当たりで倒したボスでは更新されず、段も変わらない
- 連鎖が 0 に戻る: 撃破 0 のまま確定した解放で 0（ほかの解放が飛んでいても）。その次の最初の撃破は窓の中でも 1。窓が過ぎただけでは変わらない（表示だけが消える）。撃破のある解放の確定では 0 に戻らない
- 倍率とスコア: 段 1・1 体 = 等倍（既存の値と同じ）、段 2・1 体 = ×2.0、段 5 で ×5.0、段 6・段 7 でも ×5.0（頭打ち）、段 3・2 体 = ×3.5、段 5・4 体 = ×6.5（`1 + 1.5 + 4.0`）、倍率を掛けた後の切り捨て（例: 撃破スコア 150・倍率 2.5 → 375、撃破スコア合計 101・倍率 1.5 → 151）、撃破 0 は 0 点。確定のタイミング（全弾が消えた時点）と、解放ごとの集計（とどめの弾の解放に数える）は変わらない
- ボス: ボスを解放弾で倒すと連鎖に数える（段・最後の撃破の時刻を更新）。体当たりで倒したボスは数えず、倍率も掛けない
- 時間: 一時停止中は窓が進まない（`World` の経過時間で数える）。`ending` の間に確定する集計にも連鎖が掛かる（`ending` の終わりにまとめて確定した集計の分まで最終スコアに入る）
- GameOver の内訳: ボーナスの行の名前が「BONUS」（値は「+ボーナス」で従来どおり）。連鎖の分がボーナスに入り、8 種類の点数とボーナスの和が最終スコアと等しい。行の数・出し方・`GAMEOVER_INPUT_LOCK` は変わらない
- 同じフレームの順序: 別の解放の最初の撃破と、撃破 0 の解放の確定が同じフレームに重なると、最初の撃破は連鎖が続いたまま段を決め（例: 段 2 → 3）、そのあとで連鎖が 0 になる。ボスの存在によるずらし（ボスがいる間は y が 24px 下、撃破されたフレームで元に戻る）
- 表示の計算（純粋関数）: 表示する条件（段 1 では出ない、段 2 で出る、経過 4.99 秒で出る、ちょうど 5.0 秒で消える、段 0 では出ない）。文字（「CHAIN ×2」「CHAIN ×12」）、色（段 2 白、3・4 黄、5 以上 橙）、バーの割合（0 秒で 1、2.5 秒で 0.5、5 秒で 0）。位置と大きさは定数どおり
- 回帰（変えないもの）: 解放のルール（押した瞬間の 1 回、全弾放出、ストック 0 では何も起きない、自動解放と救済ストック）、標的の割り振りと追尾、同時撃破の倍率の式（連鎖が 1 段のとき従来と同じ値）と確定のタイミング、敵・ボス・難易度、ライフ・被弾・ストック上限、GameOver の行数・出し方・入力ロック、「N HIT」演出、操作・操作感、`Demo` に表示が出ないことを確かめる既存のテストが、行の名前（「MULTI-KILL BONUS」→「BONUS」）に関わるもの以外は変更なしですべて通ること

## 完了条件

- lint / test / coverage（90% 以上）/ build が通る
- 連鎖の段が 1 のとき（連鎖を使わない遊び方）のスコアが従来と同じ値になる（既存のスコアのテストが変更なしで通る）
- ブラウザ（`game-qa`。横長 1365×768 と、縦長 390×844 相当）で、連鎖の表示が左上の HUD のスコアの下に出て、スコア・ボス HP バー・そのほかの HUD と重ならず（縦長 390×844 相当でボスがいる間も、「BOSS」ラベルと重ならず、連鎖の文字が実寸で読める）、段 3 で黄・段 5 で橙になり、窓が過ぎるとバーが 0 になって消えること。GameOver のボーナスの行が「BONUS」になっていること。`Title` の背景のデモに表示が出ないこと
- 自動プレイ（ボットの撃つ条件を変えた 3 種。50 シード・上限 600 秒・横長 1365×768 と縦長 768×1536）で、連鎖ありのスコアの中央値を測り、連鎖なしの値と並べて PR の説明に載せる（上の参考の値との大きなずれがないか確かめる。ずれたら理由を書く）
- 変えないもの（回帰条件）: 操作・操作感、解放の標的の割り振りと追尾、同時撃破の倍率の式と確定のタイミング、敵・ボス・難易度、ライフ・被弾・ストック上限、GameOver の行数・入力ロック、「N HIT」演出が、変更前と変わらないこと。意図して変わるもの: 撃破のある解放が続くとスコアが上がる（早撃ち寄りのプレイで約 1.7〜1.8 倍）、GameOver のボーナスの行の名前
