# 元に戻す／やり直す、全消去、サイズ変更で地雷を保持する（undo-history）

## 概要

盤面を変える操作を履歴に残し、元に戻す・やり直すができるようにする。あわせて、地雷をまとめて消す「全消去」を足し、サイズ変更（「反映」）が盤面全体を消さずに、重なる範囲の地雷と開始マスを残すようにする。作った絵を、1 回の操作ミスで失わないための安全網で、編集のコアループ（置く → 確かめる → 直す）は広げない。

## 操作仕様

- 「元に戻す」「やり直す」「全消去」の 3 つのボタンを、サイドバーの「開始マスを指定」「盤面テキストをコピー」の行の直下の 1 行に、この順で置く。文字は「元に戻す」「やり直す」「全消去」。
- 履歴に残す操作（1 回で 1 手）は 4 つ。
  - 爆弾のトグル（置く・外す。開始マス制約で拒否されたものは、盤面が変わらないので手にならない）
  - 開始マスの設定（拒否されたものは手にならない）
  - 全消去
  - サイズ変更（「反映」）
- 盤面が変わらない操作は、手として残さない。盤面が変わらない = 操作の前後で、幅・高さ・各マスの爆弾の有無・開始マスがすべて同じ。例: 今と同じサイズで「反映」、今と同じマスを開始マスにする、爆弾が 1 つもない盤面で全消去。
- 「元に戻す」: 直前の手を取り消し、盤面を、その操作の前の状態（幅・高さ・爆弾・開始マス）に戻す。取り消した手は、やり直しの側に積む。履歴が空なら、ボタンは無効で何も起きない。
- 「やり直す」: 最後に取り消した手をもう一度行い、盤面をその操作の後の状態にする。やり直しの履歴が空なら、ボタンは無効で何も起きない。
- 新しい手を記録したとき、やり直しの履歴はすべて捨てる。盤面が変わらない操作は、手を足さず、やり直しの履歴も捨てない。
- 履歴は `UNDO_LIMIT` 手まで。超えたら、いちばん古い手から捨てる（捨てた手より前の状態には戻れない）。
- 「全消去」: 確認ダイアログ（`window.confirm`。文言は「地雷をすべて消しますか？（「元に戻す」で戻せます）」）を出し、OK なら地雷をすべて消す。キャンセルなら、何も変えない（状態表示も変えない）。開始マスと盤面のサイズはそのまま。爆弾が 1 つもない盤面では、ボタンを無効にする。
- 「反映」（サイズ変更）: 新しい幅・高さ（今までどおり 2〜50 に丸める）の盤面にし、重なる範囲の爆弾を残す。マス (行, 列) の爆弾は、新しい盤面にその (行, 列) があるときだけ残り、その位置のまま。広がった部分には爆弾が無い。開始マスは、(行, 列) が新しい盤面の中に残るなら、その位置のまま保持する。外にはみ出すなら、開始マスを解除する（「未指定」に戻る）。開始マス指定モードは、今までどおり「反映」で終了する（ボタンの強調表示も外す）。「反映」のあとの判定結果は、新しい盤面で、取り消し・やり直しのあとと同じ規則で更新する（開始マスが残れば再評価、解除されたら「未評価」）。
- 開始マスを保持したとき、禁止領域（開始マスと周囲 8 マス。新しい盤面に存在するマスだけ）に爆弾は無い（元の禁止領域は爆弾が無く、新しい盤面の禁止領域は、元の禁止領域の部分と、広がった空の部分だけからなるため）。
- 取り消し・やり直しのあと、次を、戻した盤面にそろえる: マスの表示、数字、判定結果（開始マス未指定なら「未評価」）、幅・高さの入力欄の値（戻した盤面の幅・高さ）。表示倍率・スクロール位置・表示モード・開始マス指定モードは変えない（盤面が小さくなって、スクロール位置が範囲外になる分は、ブラウザの標準で収まる）。
- 状態表示の文言:
  - 元に戻したとき: 「元に戻しました。」
  - やり直したとき: 「やり直しました。」
  - 全消去したとき: 「地雷をすべて消しました。」
  - 「反映」したとき: 「盤面サイズを `W`x`H` に変更しました。」（今までどおり）。開始マスを解除したときは、続けて「開始マスは盤面の外になったため解除しました。」を付ける
- キー: Ctrl（⌘）+Z で元に戻す。Ctrl（⌘）+Shift+Z、または Ctrl（⌘）+Y（Shift の有無は問わない）でやり直す。`z`・`y` の大文字・小文字の両方で効く。次のときは効かせず、何もしない（ブラウザの標準のまま）: W・H の入力欄（など、文字を入力する欄）にフォーカスがあるとき、プレイ中、Alt を押しているとき。上の条件に当たらないときは、履歴が空でも `preventDefault` する（盤面は何も起きない）。キーのリスナーは Scene の終了時に解除する（ズーム・表示モードのキーと同じ）。
- プレイ中（[作った盤面をその場でプレイする](play-test.md)）は、3 つのボタンを無効にし、キーも効かせない。履歴はプレイで変わらず、「編集に戻る」で編集に戻ると、プレイの前の履歴のまま使える。
- ヘルプ文に、元に戻す・やり直すのキーを足す。
- 履歴は保存しない。リロードや Scene の再開始で、履歴は空になる。

## 画面・Scene 構成

- サイドバーに 1 行を足す（「開始マスを指定」「盤面テキストをコピー」の行と、「プレイ」の行の間）。3 つのボタンを横に並べ、狭いときは折り返す。既存のボタン・表示の並びの順番は変えず、この行の分だけ、それより下の表示が下がる。
- ボタンの有効・無効:
  - 「元に戻す」: 元に戻す履歴があり、プレイ中でないとき有効
  - 「やり直す」: やり直す履歴があり、プレイ中でないとき有効
  - 「全消去」: 爆弾が 1 つ以上あり、プレイ中でないとき有効
- 無効のボタンは、既存の無効ボタンと同じ見た目（薄く表示）。ボタンの大きさ・余白は、既存のボタンと同じ範囲。
- 取り消し・やり直し・全消去・「反映」は、盤面を描き直す（爆弾のトグルと同じ。マスのボタンを作り直してよい）。表示倍率と表示モードの値は変えない。

## ルール

- 履歴の 1 手 = 操作の前の盤面の状態（幅・高さ・爆弾・開始マス）。現在の盤面は、履歴とは別に持つ。
- 盤面の状態（`BoardSnapshot`）: 幅、高さ、爆弾の有無の配列（行優先、長さ = 幅 × 高さ）、開始マス（インデックスまたは `null`）。
- 履歴は、取り消しの側とやり直しの側の 2 つ。操作を記録すると、操作の前の状態を取り消しの側の最後に積み、やり直しの側を空にする。取り消しの側が `UNDO_LIMIT` を超えたら、いちばん古いものを捨てる。
- 取り消しは、現在の状態をやり直しの側に積み、取り消しの側の最後を現在にする。やり直しは、現在の状態を取り消しの側に積み、やり直しの側の最後を現在にする（この積みでも、`UNDO_LIMIT` を超えたら、取り消しの側のいちばん古いものを捨てる）。
- サイズ変更の写し方: 新しい盤面のマス (行 `y`, 列 `x`) は、`y` < 元の高さ かつ `x` < 元の幅 のとき、元の (`y`, `x`) の爆弾の有無を引き継ぐ。それ以外は爆弾なし。開始マスは、元のインデックスを元の幅で (`y`, `x`) に直し、`y` < 新しい高さ かつ `x` < 新しい幅 のとき、新しいインデックス `y × 新しい幅 + x` に移す。そうでなければ `null`。
- 開始マスの制約（周囲 8 マスに爆弾を置けない・開始マス設定の拒否）は今までどおり。履歴の操作（元に戻す・やり直す）は、制約を破る状態を作らない（履歴の状態は、すべて制約を満たす盤面だったときのもの）。

## テスト観点

純粋関数（`src/game/logic/` の履歴・サイズ変更・全消去・キー判定。Phaser・DOM に依存せず、引数を破壊的に変更しない。履歴の上限は引数で渡せる）の単体テスト。

- サイズ変更の写し方（手で数えた例。盤面は幅 5 × 高さ 4。インデックス = 行 × 幅 + 列）
  - 爆弾が (0,4)・(3,2)・(2,0)（インデックス 4・17・10）、開始マスが (0,0)（インデックス 0）
  - 3 × 3 にすると、残る爆弾は (2,0) だけ（新しいインデックス 6）。開始マスは 0 のまま
  - 5 × 2 にすると、残る爆弾は (0,4) だけ（インデックス 4）。開始マスは 0 のまま
  - 7 × 5 にすると、爆弾は (0,4)→4、(3,2)→23、(2,0)→14。開始マスは 0。広がった部分に爆弾は無い
  - 別の盤面: 幅 5 × 高さ 4、開始マスが (3,4)（インデックス 19）、爆弾が (0,0) だけ。4 × 4 にすると、開始マスは `null`（列 4 が外）で、爆弾は (0,0) のまま。6 × 5 にすると、開始マスは (3,4) のまま（インデックス 22）
  - 今と同じサイズは、盤面が変わらない（手にならない）
- 全消去: 爆弾がすべて消え、開始マスと幅・高さは変わらない。爆弾が 0 個なら、盤面が変わらない（手にならない）
- 履歴
  - 初期 12 × 12 の空の盤面で、マス 5 に爆弾を置く（手 a）、マス 6 に置く（手 b）。取り消すと爆弾は {5}、やり直すと {5, 6}。取り消してからマス 7 に置くと、やり直しの側が空になり、やり直しても何も起きず、爆弾は {5, 7}
  - 空の履歴で取り消し・やり直しをしても、状態は変わらない
  - 盤面が変わらない状態を記録しても、取り消しの側もやり直しの側も変わらない（取り消した直後に、同じサイズの「反映」をしても、やり直せる）
  - 上限（テストでは上限 3 を渡す）: 手 a・b・c・d を記録すると、取り消しの側が持つのは、a の後・b の後・c の後の状態の 3 つだけ（最初の状態は捨てられる）。3 回取り消すと a の後の状態になり、4 回目は何も起きない（最初の状態には戻れない）。既定の `UNDO_LIMIT` は 100（101 手を記録すると、100 回だけ取り消せる）
  - サイズ変更の手を取り消すと、元の幅・高さ・爆弾・開始マスが戻る（開始マスが解除された手も戻る）。やり直すと、もう一度同じ結果になる
  - 全消去の手を取り消すと、爆弾が戻る
  - 入力の状態・履歴を破壊的に変更しない（返った値は別の配列）
- 「反映」の丸め: 入力 100 は 50、入力 1 は 2 に丸めてから写す（幅 5 × 高さ 4 の盤面で 100 × 1 を入れると 50 × 2 になり、(0,4) の爆弾だけが残る）
- 回帰（既存の純粋関数のテストは変えない）: 取り消し・やり直し・「反映」のあとの盤面で、隣接爆弾数・開始マスの設定可否・爆弾の設置可否・盤面テキストが、同じ状態から新しく作った盤面と一致する。`evaluateDifficulty` とそのテスト、`play.ts` のテストは変えない
- キー判定（Ctrl・⌘・Shift・Alt・`key`・入力欄にフォーカス中か・プレイ中か → 取り消し・やり直し・なし）
  - Ctrl+`z`、⌘+`z` → 元に戻す。Ctrl+Shift+`Z`、⌘+Shift+`z`、Ctrl+`y`、Ctrl+Shift+`y` → やり直す。`z` だけ（Ctrl・⌘ なし）→ なし
  - Alt を押しているとき、入力欄にフォーカス中、プレイ中 → なし
- ボタンの有効・無効（純粋関数でも Scene でもよい）: 取り消しの履歴の有無・やり直しの履歴の有無・爆弾の有無・プレイ中から、上の「ボタンの有効・無効」の表のとおり決まる

DOM（ブラウザ）の確認は QA で行う（単体テストの対象外）: ボタンの並びと有効・無効の切り替え、爆弾のトグル → 元に戻す → やり直す、全消去の確認ダイアログ（キャンセルで何も変わらない）と取り消し、「反映」で重なる範囲の爆弾と開始マスが残ること、取り消しで幅・高さの入力欄が戻ること、取り消し・やり直しで表示倍率・表示モードが変わらないこと、Ctrl（⌘）+Z / Ctrl（⌘）+Shift+Z / Ctrl+Y が効くこと、W・H の入力欄にフォーカス中とプレイ中は効かないこと（入力欄ではブラウザ標準の取り消しが働く）、プレイ中は 3 つのボタンが無効で、編集に戻ると履歴が残っていること。

## 完了条件

- 「元に戻す」「やり直す」「全消去」が、「開始マスを指定」「盤面テキストをコピー」の行の直下の 1 行にあり、有効・無効が上の表のとおりに切り替わる
- 爆弾のトグル・開始マスの設定・全消去・サイズ変更が、1 回 1 手で元に戻せ、やり直せる。盤面が変わらない操作は手にならない。新しい手でやり直しの履歴が消える。履歴は `UNDO_LIMIT` 手まで
- 全消去は、確認ダイアログで OK のときだけ、爆弾をすべて消す（開始マス・サイズは変わらない）。取り消せる
- 「反映」は、重なる範囲の爆弾と開始マスを残す。開始マスが盤面の外になるときだけ解除し、状態表示で知らせる。取り消せる
- 取り消し・やり直しのあと、盤面・数字・判定結果・幅と高さの入力欄が、戻した盤面にそろう。表示倍率・表示モード・開始マス指定モードは変わらない
- キー（Ctrl（⌘）+Z、Ctrl（⌘）+Shift+Z、Ctrl（⌘）+Y）が効き、入力欄にフォーカス中・プレイ中・Alt 併用では効かない。プレイ中はボタンも無効で、プレイの前後で履歴は変わらない
- 回帰（今までと同じ。この拡張で意図して変える挙動は、「反映」が盤面全体を消さずに重なる範囲の爆弾と開始マスを残すことだけ。「反映」が開始マス指定モードを終えること・サイズの丸め・状態表示の文言は今までどおり）: 隣接爆弾数の計算、開始マスの制約（周囲 8 マス・拒否・自動解除しない）、爆弾のトグル、`evaluateDifficulty` とそのテスト、判定の数値（`D`・`B`・`A`・`C`・`U`）、サイズ入力の丸め（2〜50）、「盤面テキストをコピー」の形式、ズーム・表示モード・プレイモードの挙動、反映・リサイズで表示倍率が変わらないこと、スクロールが盤面表示エリア内だけ、既存のボタン・表示の並びの順番（この拡張の 1 行の分だけ下がる）
- `npm run lint` / `npm run test` / `npm run test:coverage` / `npm run build` が成功する。カバレッジ 90% 以上
