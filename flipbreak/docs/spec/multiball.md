# スペシャルブロックとマルチボール

## 概要

各面に、崩すと玉が 1 個増える「スペシャルブロック」（記号 `*`）を 2 個ずつ置く。玉は同時に最大 `MULTI_BALL_MAX` 個まで台に出る。面の終わりの「残り数個を探して待つ時間」を縮め、どのブロックを先に狙うかと、玉が複数のときの打ち分けを加える。玉の動き・得点・フリッパー・発射のルールは変えない。

## 操作仕様（追加・変更分）

操作は変えない。玉が複数あるあいだ、押している指の扱いは次のとおり。

- 「玉がレーンにある」（`ready`）とは、台にある玉がちょうど 1 個で、その玉が `isReady` であること。玉が 2 個以上あるあいだは `ready` ではない（溜めは進まず、タッチは左右の半分のフリッパーになる。キーボードは今までどおりつねにフリッパー）。
- 発射・溜め・「離すまで無視する指・キー」の規則は、`ready` の玉に対して今までどおり働く。`ready` が false から true になった時点（他の玉が抜けて 1 個になった、など）で押されていた指・キーは、離すまで溜めに使わない（`isReady` になった時点で押されていた指・キーの規則と同じ）。

## 画面・Scene構成（追加・変更分）

HUD・Title・Result・Scene の構成は変えない。台（Game）に次を足す。

### スペシャルブロックの見た目

- 面の定義の `*` は、普通のブロックと同じ格子の 1 マス（同じ大きさ・同じ当たり）。色は `SPECIAL_COLOR`（明るいシアン 0x4df0ff）。行ごとの色（実装裁量）のどれとも見分けがつくこと。
- 印: ブロックの矩形の中心に、外半径 `SPECIAL_STAR_R` の「★」（5 つの頂点の星形）を、暗い色（背景より明るくなく、シアンと見分けられる色。実装裁量）で描く。ブロックと同じ Graphics に描き、ブロックが崩れたとき（描き直し）に消える。
- 崩れたときの演出（白い四角・「+100」・SCORE の強調）は普通のブロックと同じ。玉が増える瞬間の専用の演出は無い（玉が崩れた位置に現れる）。

### 玉の見せ方

- 台にある玉はすべて同じ見た目（同じ色・半径 `BALL_R`）。描く順は「玉」の層（玉の軌跡 → 玉）にすべて含める。
- 玉の軌跡は玉ごとに別の `TrailBuffer` で記録する（`MULTI_BALL_MAX` 個を Scene の始まりに作って使い回す）。玉が増えた・消えた・レーンへ戻したときは、その玉の分の記録を空にする（増えた玉は、そのフレームの位置から記録し直す）。記録の規則（`TRAIL_MIN_SPEED`・`TRAIL_JUMP`・`trailAlpha`）は今までどおり。
- 玉が消える（他に玉があるとき）ときは、消える演出を付けない（その玉の表示物がなくなる）。

### 状態遷移

Game の状態（`playing` / `stageClear` / `ending`）は変えない。

- `stageClear`・`ending` の間は、すべての玉が止まって見える（今までと同じ。玉は増えない・消えない）。
- 次の面の始まりでは、玉は 1 個（レーンの置き位置）だけになる。残っていた玉はなくなる。
- 玉を落としたことによる残機の減り方は、下の「ルール」のとおり。

## ルール

### スペシャルブロック

- ブロックの当たり・崩れ方・得点は普通のブロックと同じ（玉が重なると崩れ、`SCORE_BLOCK` 点。反発は `BLOCK_E`）。
- 面の定義（`docs/spec.md`「面」）の `*` がスペシャルブロック。面のブロック数は `*` も 1 個に数える（面クリアは、`#` と `*` がすべて崩れたとき）。
- スペシャルブロックが崩れた物理の刻みの終わりに、台にある玉の数が `MULTI_BALL_MAX` 未満なら、玉を 1 個足す。`MULTI_BALL_MAX` 個あるときは玉を足さない（ブロックは崩れ、得点は入る）。1 つの刻みに複数のスペシャルブロックが崩れたら、崩れた順に 1 個ずつ、そのつど上限を見て足す。その刻みで面のブロックがすべて崩れて面クリア（`stageClear`）に入るときは、玉を足さない（止まって見える玉が増えないため）。

### 足す玉

- 位置: 崩れたブロックの格子の 1 マスの中心（x = `BLOCK_X0` + 列 × `BLOCK_W` + `BLOCK_W` / 2、y = `BLOCK_Y0` + 行 × `BLOCK_H` + `BLOCK_H` / 2）。隣のブロックとは重ならない（中心から隣のブロックの矩形までは 10 px 以上で、`BALL_R` 7 より大きい）。
- 速度: 崩した玉の、その刻みの終わりの速度を (vx, vy) として、足す玉は (−vx, vy)（x 成分だけ反転、速さは同じ）。
  - vx の絶対値が 1e-6 未満のときは、足す玉の vx を、ブロックの中心 x < `FIELD_W` / 2 なら +`MULTI_SIDE_VX`、中心 x ≥ `FIELD_W` / 2 なら −`MULTI_SIDE_VX` にする（vy は同じ。この場合だけ速さが変わる）。
- 足した玉は、その刻みでは動かさず、次の刻みから動かす。乱数は使わない。
- 玉が複数あるとき、バンパー・壁・フリッパー・ブロックとの当たりは、玉ごとに今までどおり計算する。フリッパーの角度は 1 つの刻みに 1 回だけ進める（玉の数で進まない）。玉どうしは当たらない（すり抜ける）。
- 1 つの刻みに複数の玉が同じブロックに重なったときは、玉の並びの順（先に出た玉が先）で最初の玉だけが崩し、得点は 1 回。

### 玉を落とす

- 玉が台から抜ける（`isDrained`）と、その玉は台から取り除く。
- 取り除いたあとに台に玉が残っていれば、残機は減らさず、「玉を落としたとき」の演出（揺れ・赤い重ね・`BALL` の点滅）も出さない。得点・ブロックはそのまま。
- 取り除いたあとに台に玉が 0 個になったときだけ、残機 −1（`docs/spec.md` の「玉を落とす」のとおり。玉を落としたフレームの結果 `ballsLost` は 1。演出も出す）。同じ刻みに最後の複数の玉が一緒に抜けても、残機は 1 だけ減る。残機が 1 以上残るなら、玉 1 個をレーンの置き位置に置き直す（溜め 0・フリッパーは今の角度のまま）。残機が 0 なら `ending`。
- 1 フレームの結果 `ballsLost` は、残機が減ったときだけ 1（今までと同じ意味）。玉が複数あるときに 1 個が抜けても 0。
- 同じ刻みに、スペシャルブロックで玉が足されるのと、別の玉が抜けるのが重なったら、足す → 取り除く の順に処理する（崩した玉は台の上にいて同じ刻みには抜けないので、足した玉と崩した玉が残り、残機は減らない。結果は処理の順によらない）。
- 玉を落としたことでフレームの残りの物理を止める（`docs/spec.md` 演出・UI の最後の項）のは、残機が減ったとき（最後の 1 個を落としたとき）だけ。玉が残っているときに 1 個が抜けても、そのフレームの残りの刻みは続ける。

### レーンに入った玉

- 各物理の刻みの終わり（足す・取り除くのあと）に、台に玉が 2 個以上あって、`isReady` の玉があれば、その玉を取り除く（残機は減らさない。演出は出さない）。`isReady` の玉が複数あって、そのまま取り除くと玉が 0 個になるときは、玉の並びの先頭の玉を残す。
- 台に玉が 1 個だけのときは、今までどおり（レーンの玉は発射待ち）。

### 詰まりの救済（玉が複数のとき）

- 数えるのは玉ごと。玉が「止まっている」とは、`isReady` ではなく、どちらのフリッパーも押しておらず、速さが `STALL_SPEED` 未満であること。止まっている間だけ、その玉の経過を足し、止まっていなければ（フリッパーを押した・速さが `STALL_SPEED` 以上・`isReady` になった）その玉の経過を 0 に戻す。足した玉の経過は 0 から始める。
- 玉の経過が `STALL_TIME` 秒に達したとき、台に玉が 2 個以上あれば、その玉を取り除く（残機は減らさない。演出は出さない）。台に玉がその 1 個だけなら、今までどおりレーンの置き位置に戻す（溜め 0）。1 フレームに複数の玉が達したときは、玉の並びの順に 1 個ずつ処理する（最後に残る 1 個はレーンへ戻る）。
- 玉をレーンに置き直した・次の面が始まったときは、すべての経過を 0 にする。

### スコア

- 変えない。ブロックは `SCORE_BLOCK`（スペシャルブロックも同じ）、バンパーは `BUMPER_SCORE`。玉が複数あるので、バンパーの得点は玉ごとに入る（1 フレームの結果 `hitBumpers` は、同じバンパーを 1 回だけ数える今までの規則のまま）。面のブロックの満点（ブロック数 × `SCORE_BLOCK`）は変わらない。

## パラメータ表

| 名前 | 初期値 | 意味 |
|---|---|---|
| `MULTI_BALL_MAX` | 3 | 台に同時に出る玉の上限。バランス調整の対象 |
| `MULTI_SIDE_VX` | 120 px/s | 崩した玉の vx が 0 のとき、足す玉に与える横の速さ |
| `SPECIAL_COLOR` | 0x4df0ff | スペシャルブロックの色 |
| `SPECIAL_STAR_R` | 6 | 「★」の外半径（論理 px。ブロックの高さの矩形 16 に収まる） |

スペシャルブロックの位置は、`docs/spec.md`「面」の表のとおり（面ごとに 2 個、計 10 個）。

## テスト観点

足す玉（`GameSession` の物理の刻みを通して確かめる）:
- 面 1 の左上のスペシャルブロック（行 0・列 0、中心 (39, 69)）を崩す刻みの終わりの玉の速度が (100, 300) のとき → 玉が 2 個になり、足した玉は位置 (39, 69)、速度 (−100, 300)。+100 点。足した玉はその刻みでは動かず、次の刻みから動く
- vx = 0 のとき: ブロックの中心 x = 39（< 165）→ 足した玉の vx = +120。面 1 の右上（列 7、中心 x = 291）→ vx = −120。面 4 の行 0・列 3（中心 (147, 69)）→ +120。中心 x がちょうど 165 になるブロックは無いが、規則は「x ≥ 165 なら −120」
- 台に玉が 3 個あるときにスペシャルブロックを崩す → 玉は 3 個のまま、+100 点、ブロックは崩れる。玉が 2 個のとき → 3 個になる
- 1 つの刻みにスペシャルブロックが 2 個崩れ、玉が 2 個のとき → 3 個になる（2 個目は足さない）
- 2 個の玉が同じブロックに同じ刻みで重なる → 崩れるのは 1 回（+100 を 1 回）
- 玉が複数のとき、フリッパーの角度は玉の数によらず、1 刻みに 1 回だけ進む（1 個のときと同じ角度の列）

玉を落とす:
- 玉 2 個のうち 1 個が抜ける → 玉は 1 個、残機は 3 のまま、`ballsLost` は 0、`phase` は `playing`
- 続けて最後の 1 個が抜ける → 残機 2、`ballsLost` は 1、玉は 1 個でレーンの置き位置（速さ 0）、溜め 0
- 玉 2 個が同じ刻みに両方抜ける → 残機は 1 だけ減る（3 → 2）、`ballsLost` は 1
- 残機 1 で、玉が複数のうち 1 個が抜ける → 残機 1 のまま。最後の 1 個が抜ける → 残機 0、`ending`
- 玉 2 個（A: スペシャルブロックを崩す玉、B: 台から抜ける玉）で、同じ刻みに A が崩して B が抜ける → 玉は A と足した玉の 2 個、残機は減らない、`ballsLost` は 0
- 玉が 3 個のうち 1 個が抜けたフレームでも、残りの物理の刻みは続く（同じフレームの時間を使い切る）。玉が 1 個で抜けて残機が減ったフレームは、そこで物理を止める（今までどおり）
- 最後のブロックがスペシャルブロックで、それを崩す刻みに面クリアに入る → 玉は足されない（玉の数は変わらず）、+100 点
- 玉が 1 個のときに抜ける → 今までどおり（残機 −1、玉はレーン）

レーンに入った玉・`ready`:
- 玉 2 個のうち 1 個が `isReady`（例: (345, 623)・速度 0）になる → その玉が取り除かれる。残機・得点は変わらない
- 玉 2 個がどちらも `isReady` → 玉の並びの先頭が残る
- 玉が 1 個で `isReady` → 取り除かれない（発射待ち）
- 玉が 2 個以上のとき、`ready` は false（タッチで溜めが進まず、フリッパーが動く）。玉が 1 個で `isReady` なら `ready` は true

詰まりの救済（玉ごと）:
- 玉 2 個のうち 1 個が速さ 14（< 15）のまま 5 秒（ちょうど `STALL_TIME`）→ その玉が取り除かれる（残機は減らない）。4.99 秒では取り除かれない。もう 1 個が動いていても、止まった玉は数える
- 玉が 1 個だけで止まったまま 5 秒 → 今までどおりレーンの置き位置に戻る
- 玉 2 個が同じフレームに 5 秒に達する → 1 個が取り除かれ、もう 1 個はレーンの置き位置に戻る
- 足した玉の経過は 0 から始まる（足した直後に取り除かれない）
- 玉の速さが 15 ちょうど・フリッパーを押した → その玉の経過を 0 に戻す（今までの規則）

面・状態:
- 面の定義: 各面の `*` の数と位置が表のとおり（面 1・3・5 は行 0 の列 0 と列 7、面 2 は行 0 の列 0 と行 1 の列 7、面 4 は行 0 の列 3 と行 1 の列 5）。各面のブロック数は 24・16・26・20・34 のまま（`*` も数える）。`loadBlocks` が `*` のブロックに特殊の印を付ける
- すべてのブロック（`#` と `*`）が崩れると面クリア。`*` だけが残っていれば面クリアではない
- `stageClear` の間、玉の数・位置は変わらず、玉は増えない。次の面の始まり → 玉 1 個（レーンの置き位置）。それまでに複数あっても 1 個になる
- 玉の軌跡: 玉が増えたとき、その玉の記録は空から始まる。玉が取り除かれたら、その玉の記録は空になる

変えないものの回帰（既存のテストは期待値を変えずに通る）:
- スペシャルブロックの無い配置（`*` を `#` に読み替えた面）で、同じ入力の列から、これまでと同じスコア・残機・ブロック・玉の位置になる
- 玉が 1 個のあいだの物理・溜め・発射・詰まりの救済・玉を落としたときの残機・演出の結果（`brokenBlocks`・`hitBumpers`・`ballsLost`）は今までと同じ
- 得点: スペシャルブロックも +100、バンパーは玉ごとに +10、ブロックの満点は面ごとのブロック数 × 100。2 個の玉が同じ刻みに同じバンパーに当たる → +20 点、`hitBumpers` にはそのバンパーの番号が 1 回（脈打ちも 1 回）
- 残機は 3 から始まる。「縦にしてください」の案内が出ている間は、すべての玉・玉ごとの詰まりの経過が止まる。タッチ・キーの割り当て（左右の半分・← → Z `/`）は変わらない
- 発射・フリッパーの強さ・回転の速さ・バンパー・壁・自己ベストの保存形式・Title・Result は変えない
- 単体テストの対象外: スペシャルブロックの色と「★」の見た目、玉が複数のときの描画・軌跡の見た目。QA（ブラウザでの目視）で確かめる

## 完了条件

- `docs/spec.md` の完了条件に加えて、スペシャルブロック（シアンと「★」）が、SE の縦（375 × 550）・スマホ縦（390 × 844）・PC（1280 × 720）のスクリーンショットで、普通のブロックと見分けられる。面 1〜5 のすべてで 2 個ずつ見える
- スペシャルブロックを崩すと、その位置に玉が 1 個現れ、台に玉が 2 個以上あるあいだに 1 個を落としても、画面が揺れず、残機の ● が減らない（ブラウザの連写で確認）
- 玉が 3 個あるときにスペシャルブロックを崩しても、玉は 4 個にならない
- 最後の 1 個を落とすと、今までどおり揺れ・赤い重ね・`BALL` の点滅が出て、残機が 1 減り、玉がレーンに戻る
- 玉が複数あるあいだに画面を押すと、溜めずにフリッパーが動く
- 公開版との比較（ボットの自動プレイ。PR に載せる）: 面のクリアにかかる時間と、全面クリア率が、公開版よりも易しくなる向きであること。値の閾値は置かない（バランス調整で見直す）。ボットの規則: 台にある玉のうち最も低い玉（y が最大）が高さ 515〜550 に来たら、その側のフリッパーを 0.15 秒上げる（上げる高さの早め / 遅めの 2 通り）。発射の溜めは 0.85〜1.0。試行は 2 通り × 60 回。報告する指標は、面ごとのクリア時間の中央値と、全面クリア率（公開版と新版の両方）。ボットは使い捨ての試験用で、リポジトリには入れてもよい・入れなくてもよい（実装裁量）
- 「変えないものの回帰」（上の「テスト観点」）のとおり、既存のテストの期待値を変えずに通る
- `npm run lint` / `npm run test` / `npm run test:coverage`（90% 以上）/ `npm run build` が通り、単体ビルドと共有ビルドの両方で起動する

## 実装裁量

- 「★」の暗い色、行ごとの色との見分けを保つ範囲でのシアンの微調整（`SPECIAL_COLOR` の値を、行の色と離れるように変えてよい）
- 玉の並びの持ち方（配列・固定長のスロット）、玉が消える・増えるときの内部の処理の順（このファイルのルールの順に結果が一致すれば）、`GameSession` の公開の形（`balls` など）
- 玉ごとの詰まりの経過の持ち方
- 玉が増えたときのスロットの再利用の方法（描画の表示物・軌跡の記録を使い回すこと）
- 玉の速度の反転の計算の細かい丸め（結果が ±1e-9 で一致すればよい）
