# flipbreak 仕様

## ゲーム名

フリップブレイク（`flipbreak`）

## コンセプト

縦長のピンボール台の上に並んだブロックを、フリッパーで玉を打ち上げて崩す。バンパーで跳ね返る軌道を読み、ブロックを全部崩すと面クリア。玉を落とすと残機が 1 減り、3 回でゲームオーバー。

## ターゲットプレイヤー

スマホで 1 面 1〜2 分ずつ、すき間時間に遊ぶ人。PC のブラウザ（キーボード）でも遊べる。ピンボールの打ち上げのタイミングと、ブロック崩しの「全部崩す」達成感の両方を楽しみたい人。

## コアループ

1. 右端のレーンでプランジャーを溜めて離し、玉を発射する
2. 玉が壁・バンパー・ブロックで跳ね返る
3. 落ちてくる玉を、フリッパーのタイミングで打ち上げる
4. ブロックを全部崩せば面クリア、玉が下に抜ければ残機 −1（玉はレーンに戻って、もう一度発射する）

## 操作仕様

主な入力はタッチ（スマホ）。キーボードでも同じことができる。

| 操作 | タッチ | キーボード |
|---|---|---|
| 左フリッパー | 画面の左半分を押している間（玉が `isReady` でない間） | ← または Z を押している間 |
| 右フリッパー | 画面の右半分を押している間（玉が `isReady` でない間） | → または `/` を押している間 |
| 玉の発射 | 玉がレーンにある間、画面のどこかを押し続けて溜め、離して発射 | ↓ または Space を押し続けて溜め、離して発射 |
| START（Title）/ もう一度（Result） | ボタンをタップ | Enter または Space |
| タイトルへ（Result） | ボタンをタップ | Esc |

- フリッパーは押している間だけ上がり、離すと下がる（回転の速さは `FLIPPER_SPEED`）。
- 「玉がレーンにある」とは、玉が発射できる状態（`isReady`: x > `LANE_X`、y > 論理の高さ − `READY_Y_MARGIN`、速さの縦成分の絶対値 < `READY_MAX_VY`）のこと。
- 溜めは押している間、`CHARGE_TIME` 秒で 0 → 1 に増える（1 で止まる）。離したときの溜めの量 `charge`（0〜1）で、玉の発射速度が `launchSpeed(charge)` = `LAUNCH_MIN` + (`LAUNCH_MAX` − `LAUNCH_MIN`) × `charge` で決まる。玉は真上（vx = 0、vy = −発射速度）に出る。溜めを 0 のまま離しても（すぐ離しても）`LAUNCH_MIN` で発射する。
- マウスはタッチと同じ（ポインターとして扱う。ボタンを押している間が「押している」）。
- 玉が `isReady` の間だけ、タッチではフリッパーは動かさない（画面を押すと溜めになる）。台に玉が複数あるあいだは「レーンにある」状態にならない（[スペシャルブロックとマルチボール](spec/multiball.md)）。`isReady` でなければ、玉がレーンの中を上昇中・バウンド中でも、タッチでフリッパーが動き、溜めは進まない。キーボードのフリッパーは、玉が `isReady` でもつねに動く。
- 溜めと発射の指（キー）が複数あるとき: 溜めに使える指・キーが 1 本（個）でも押されている間、溜めは進む（最初の押下から数える）。溜めに使っていた指・キーがすべて離れたとき、発射する（1 本だけ離しても、ほかが押されていれば発射しない）。
- 次の指・キーは、離すまで無視する（離して、押し直したときから効く）:
  - Scene に入った時点（START・「もう一度」の直後の Game など）で、すでに押されていた指・キー。
  - 玉がレーンで止まった（`isReady` になった）時点で、すでに押されていた指・キー（フリッパーを押したまま玉を落とした直後に、勝手に溜まらないため）。
- 複数の指を同時に使える（左右のフリッパーを同時に押す、など）。左の半分にある指があれば左、右の半分にある指があれば右のフリッパーが上がる。半分は論理の幅の中央（x = `W` / 2）で分ける。

## 画面・Scene 構成

| Scene | 役割 |
|---|---|
| Title | ゲーム名・自己ベスト・START ボタン・操作の説明を出す |
| Game | プレイ。台（壁・ブロック・バンパー・フリッパー・レーン）・玉・HUD |
| Result | ゲームオーバー（または全面クリア）の結果。スコア・到達面・自己ベスト・ボタン 2 つ |

流れ: Title →（START）→ Game →（ゲームオーバー、または最後の面のクリア）→ Result →（「もう一度」）→ Game /（「タイトルへ」）→ Title。

### 画面の大きさ（論理サイズ）

- 論理サイズは `W` × `H`（360 × 640）で固定。Phaser の `Scale.FIT` で中央に置く。台の幾何（落下の距離・フリッパーの角度・レーンの高さ）はプレイテストで手触りを決めた値なので、画面に合わせて伸ばさない。
- 黒帯が出ることを許容する理由: スマホの縦（390 × 844 → 縮小率 1.083）では上下に黒帯（合計 18%）、iPhone SE の縦（375 × 550 → 0.859）では左右に黒帯（合計 18%）、PC（1280 × 720 → 1.125）では左右に黒帯が出る（合計 68%）。台の縦横比（9 : 16）はゲームの一部で、縦長に伸ばすと打ち上げの手応えが変わるため。
- 表示が横長（幅 > 高さ）で、縮小率（`min(表示の幅 / W, 表示の高さ / H)`）が `ROTATE_PROMPT_SCALE` 未満のとき（iPhone SE の横 667 × 310 は 0.484、スマホの横 844 × 390 は 0.609）は、文字が小さすぎるので、どの Scene でも、その上に「画面を縦にしてください」の案内を全面に出す。この間 Game は進行を止め（玉・フリッパー・溜め・タイマーが動かない）、Title・Result はボタンとキーの入力を受け付けない。条件を外れたら、案内を消して続きから再開する（Game の溜めは 0 に戻す）。PC（1280 × 720 は 1.125）では出ない。
- 案内の文字の大きさ: `promptFontSize(縮小率)` = min(ceil(`PROMPT_REAL_FONT_SIZE` ÷ 縮小率), `PROMPT_MAX_FONT_SIZE`)（縮小率が 0 以下なら `PROMPT_MAX_FONT_SIZE`）。1 行（11 文字 × 文字の大きさ）が `W` − 40 に収まるときは 1 行で、収まらないときは「画面を縦に」「してください」の 2 行に分ける（`promptText(文字の大きさ)`）。上限の 53 でも、各行（6 文字 × 53 = 318）は `W` − 40（320）に収まる。

### 台の幾何（Game）

論理座標（左上が原点、y は下向き）。

- 台は x = 0 〜 `FIELD_W`、右端の x = `FIELD_W` 〜 `W` が発射レーン（玉の置き位置は x = `LANE_BALL_X`、レーンの床は y = `LANE_FLOOR_Y`、玉は床の上に y = `LANE_FLOOR_Y` − `BALL_R` で止まる）。
- 壁は次の線分（玉は線の両側のどちらから来ても、玉の半径ぶん離れた所で跳ね返る。反発 `WALL_E`）:
  - 左: (0, 0)–(0, `H`)、上: (0, 0)–(`W`, 0)、右: (`W`, 0)–(`W`, `H`)
  - レーンの壁: (`LANE_X`, `LANE_WALL_TOP`)–(`LANE_X`, `H`)。レーンの床: (`LANE_X`, `LANE_FLOOR_Y`)–(`W`, `LANE_FLOOR_Y`)
  - 右上の斜め壁（デフレクター）: (`W`, `DEFLECTOR_Y`)–(`DEFLECTOR_X`, 0)。レーンを上がってきた玉を台の側へ曲げる
  - 左の斜面: (0, 501.56)–(98.29, 553.82)。右の斜面: (`FIELD_W`, 501.56)–(231.71, 553.82)。これは、フリッパーを下げたとき上面と同じ高さでつながる位置（フリッパーの根元 (95, 560) / (235, 560) から、法線の向きに `FLIPPER_R` ずらした点。傾きは `FLIPPER_REST_DEG`）。つなぎ目に段差があると、低速の玉が根元で止まる（プレイテストで起きた不具合）
- フリッパー 2 枚: 根元（ピボット）は左 `FLIPPER_LEFT_PIVOT`、右 `FLIPPER_RIGHT_PIVOT`。長さ `FLIPPER_LEN`、太さは半径 `FLIPPER_R` のカプセル形。左は根元から右下（角度 `FLIPPER_REST_DEG` = 下げた状態）に伸び、右は根元から左下に伸びる（左右対称）。上げると `FLIPPER_UP_DEG`（水平より上）まで回る。
- 玉が画面の下に抜ける（玉の中心が y > `H` + `BALL_R` × 3 になる）と、玉を落としたことになる。フリッパーの先の隙間（下げたとき左右の先端の中心が x = 146.21 と 183.79、先端の間の空きは約 23.6 = 玉の直径の約 1.7 倍）が主な落ち口で、フリッパーを上げ切った状態の外側（斜面の下）にも落ち口がある。
- ブロックは 8 列 × 最大 6 行の格子（1 マス `BLOCK_W` × `BLOCK_H`、左上は (`BLOCK_X0`, `BLOCK_Y0`)）。描くブロックはマスより縦横 1 px ずつ小さく（`BLOCK_W` − 2 × `BLOCK_H` − 2、マスの左上から 1 px 内側）、当たりも同じ矩形。
- バンパーは円（半径 `BUMPER_R`）。面ごとに位置が決まっている（下の「面」）。

### Title

- 上から順に: ゲーム名「フリップブレイク」（`TITLE_FONT_SIZE`）、自己ベスト（`BEST 1200（STAGE 3）`。記録が無ければ `BEST ---`。`BEST_FONT_SIZE`）、START ボタン（`BUTTON_W` × `BUTTON_H`、文字は `RESULT_FONT_SIZE`、画面の下 1/3 に置く）、START の下に操作の説明（`HELP_FONT_SIZE`）を 2 行:「← → / 画面の左右: フリッパー」「↓ Space / 押し続けて溜め、離して発射」。どれも画面の幅の中に収まり、重ならない。
- デモ（ボットが遊ぶ様子）は今回は作らない（`game-title` の仕事）。
- START（ボタンのタップ、Enter、Space）で Game を始める。START ボタンの脈打ちと Scene のフェードは「演出・UI（Title・すべての Scene）」。

### Game

- レイアウト: 台が画面いっぱい（論理の全体）。上端の HUD の 2 行（`HUD_FONT_SIZE`）: 1 行目（上端 y = `HUD_Y`）の左端（x = 6）に `SCORE 1200`、同じ行の右端（右端を x = `DEFLECTOR_X` − 4 にそろえる）に `BALL ●●●`（残機の数だけ ●。左端を固定し、残機 `LIVES` 個のときの幅で右端を `DEFLECTOR_X` − 4 にそろえた位置。玉を落としたときの点滅は下の「演出・UI（Game）」）。2 行目（上端 y = `HUD_Y` + `HUD_ROW_H`）の左端に `STAGE 2/5`（現在の面 / 全 `STAGE_COUNT`）。HUD は x = 6 〜 `DEFLECTOR_X` − 4 の中に収める（斜め壁と重ねない）。スコアは最大でも 6 桁（ブロック 120 個で 12000 点 + バンパー）なので、1 行目は 290 px に収まる（`SCORE 123456` + `BALL ●●●` で約 230 px）。2 行目の下端は y = `BLOCK_Y0` より上。玉が HUD の文字に重なるときは、玉を手前に描く（文字が玉に隠れてよい）。
- 玉がレーンにあるとき、操作の手がかり「押し続けて溜め、離して発射」（`HELP_FONT_SIZE`、画面の幅の中心 x = `FIELD_W` / 2、y = `HINT_Y`）を出す。玉がレーンを離れたら消す。溜めている間の棒と目安の線は、下の「演出・UI（Game）」。
- 描画の順（奥から）: 背景 → 壁 → ブロック → ブロックの白い四角（崩れたとき）→ バンパー → HUD → 操作の手がかり・溜めの棒・目安の線 → フリッパー → 玉の軌跡 → 玉 → 「+100」 → 赤い重ね → 中央の文字（`STAGE n CLEAR` / `ALL CLEAR`）→「縦にしてください」の案内。
- 状態と遷移:

| 状態 | 内容 | 次へ進む条件 |
|---|---|---|
| `playing` | 物理が動き、入力を受け付ける | 面のブロックが 0 個になった → `stageClear` / 玉を落として残機が 0 になった → `ending` |
| `stageClear` | 中央（`CLEAR_FONT_SIZE`、中心 (`W` / 2, `H` / 2)）に「STAGE n CLEAR」（最後の面は「ALL CLEAR」）を出す。物理・入力・溜めは止まる（玉とフリッパーはその場で止まって見える） | `CLEAR_PAUSE` 秒たった → 最後の面でなければ次の面を始めて `playing`（文字を消す）/ 最後の面なら Result へ（全面クリア） |
| `ending` | ゲームの動き（玉・フリッパー・溜め・タイマー）をすべて止める。入力を受け付けない。中央の文字は出さない。演出は「演出・UI（Game）」のとおり再生を続ける | `RESULT_DELAY` 秒たった → Result へ |

- 玉を落としたとき（残機が 1 以上残る）: 残機を 1 減らし、玉をレーンの置き位置（x = `LANE_BALL_X`、y = `LANE_FLOOR_Y` − `BALL_R`、速さ 0）に置き直し、溜めを 0 に戻す。フリッパーは今の角度のまま。時間の待ちは無い（すぐ次の発射ができる）。
- 面の始まり（ゲームの開始と、次の面）: 面のブロック・バンパーを置き、玉をレーンの置き位置に置き、フリッパーを下げた角度（`FLIPPER_REST_DEG`、回転速度 0）にし、溜めを 0 にする。残機とスコアは引き継ぐ。ゲームの開始は、スコア 0・残機 `LIVES`・面 1。
- 玉が詰まったときの救済: 玉が台に出ていて（`isReady` でない）、どちらのフリッパーも押していない状態で、玉の速さが `STALL_SPEED` 未満のまま `STALL_TIME` 秒続いたら、玉をレーンの置き位置に戻す（残機は減らさない。ブロック・スコアはそのまま）。フリッパーを押した、玉の速さが `STALL_SPEED` 以上になった、玉がレーンに入った、のどれかで数え直す。
- 玉が複数あるとき（スペシャルブロックで増える）: 玉を落とす・詰まりの救済・レーンの玉の扱いは [スペシャルブロックとマルチボール](spec/multiball.md) のとおり。この節と「ルール」の玉・玉を落とす・詰まりの規則は、台に玉が 1 個のときの規則で、複数のときの違いは上のファイルに書く。

#### 演出・UI（Game）

見た目だけを足す。ルール・数値（重力・反発・速さ・得点・残機・発射・当たり）と、物理の結果は変えない。演出は、Game が 1 フレームごとに返す結果（崩れたブロック・当たったバンパー・落とした玉。下の「テスト観点」）と、状態から描く。

時間の決まり（すべての演出に共通）: きっかけのフレームを t = 0 とし、決めた長さ D のちょうどで消える（元に戻る）。演出は Phaser の tween・タイマー・`camera.shake` で動かし、`stageClear` / `ending` の間も最後まで再生する（止まるのはゲームの進行で、演出は止めない。例外は中央の文字で、状態の表のとおり）。最も長い演出（玉を落としたときの点滅、`BALL_BLINK_DURATION` 0.6 秒）は `RESULT_DELAY`（0.8 秒）より短いので、Result に移るときには終わっている。「+100」（`SCORE_POP_DURATION` 0.5 秒）も `CLEAR_PAUSE`（1.0 秒）・`RESULT_DELAY` より短い。Scene が終わると演出の表示物はすべて破棄され、「もう一度」で始めたときに残るものは無い。演出の間も入力は止めない。

| 演出 | きっかけ | 見た目 | 重なったとき |
|---|---|---|---|
| 玉を落としたとき | 玉を落としたフレーム（残機が 0 になるときも） | ① 画面を `SHAKE_DURATION` 秒、強さ `SHAKE_INTENSITY` で揺らす（`camera.shake`。HUD も一緒に揺れる）。② 画面全体に赤（0xff3b3b 系）を不透明度 `DAMAGE_FLASH_ALPHA` で重ね、`DAMAGE_FLASH_DURATION` 秒で線形に 0 にする（揺れても端に隙間が見えない大きさ。画面の端から 8 px 以上はみ出す）。③ HUD の `BALL ●●●` に、落とした 1 個ぶんの ● を、`BALL_BLINK_INTERVAL` 秒ごとに出す・消すを繰り返し、`BALL_BLINK_DURATION` 秒で消えた状態で終わる（`ghostBall`。出している間の表記は `ballText(残機, 1)`。残りの ● と `BALL` の文字は動かさない） | 玉を落とすことは、発射して台を抜けるのに 0.6 秒以上かかるので、演出の途中で重ならない。起きたら最初からやり直す |
| ブロックを崩したとき | 崩れたブロック 1 個ごと（1 フレームに複数あれば、その数だけ） | ① 崩れたブロックと同じ位置・大きさの白い四角が、`BREAK_FLASH_DURATION` 秒で大きさ 1.0 → `BREAK_FLASH_SCALE` 倍・不透明度 1 → 0 になって消える。② ブロックの中心から、「+100」（`+` と `SCORE_BLOCK`、白、黒の縁取り、文字の大きさ `SCORE_POP_FONT_SIZE`）が `SCORE_POP_RISE` px 上へ動きながら `SCORE_POP_DURATION` 秒で不透明度 1 → 0 になって消える。文字の中心 x は [26, `FIELD_W` − 26] に収める（画面の左右から切れない。ブロックの中心 x は 39〜291 なので通常は効かない防御的な規則）。上段のブロックでは、上がる間に HUD の文字（SCORE・STAGE の行）と 0.5 秒だけ重なって通過してよい（「+100」は HUD より手前に描く） | ブロックごとに 1 つ（重ねて再生してよい。同時に出せる数に上限を設けてよい） |
| SCORE の強調 | スコアが増えたフレーム（ブロックでもバンパーでも） | HUD の `SCORE n` の文字だけが（`BALL` と `STAGE` は動かさない）、`SCORE_BUMP_DURATION` 秒で大きさ `SCORE_BUMP_SCALE` 倍 → 1.0 倍に戻る（線形。左端・縦の中央を固定して広がる。`scoreBumpScale`） | 同じフレームに複数でも 1 回。途中でまた増えたら最初からやり直す |
| バンパーに当たったとき | 当たったバンパー 1 個ごと | そのバンパーが `BUMPER_PULSE_DURATION` 秒で大きさ 1.0 → `BUMPER_PULSE_SCALE` 倍 → 1.0 倍（前半で広がり後半で戻る。中心を固定） | バンパーごとに独立。途中でまた当たったら、そのバンパーだけ最初からやり直す |
| 溜めの棒と目安の線 | 溜めている間（`charge` > 0） | レーンの中、玉の後ろに、中心 x = `LANE_BALL_X`、幅 `CHARGE_BAR_W`、下端 y = `LANE_FLOOR_Y`、高さ `CHARGE_BAR_MAX` × `charge` の棒を出す。色は `chargeColor(charge)`: `charge` が `CHARGE_MID` 未満は緑（0x4dffb0）、`CHARGE_MID` 以上 `CHARGE_MARK` 未満は黄（0xffe14d）、`CHARGE_MARK` 以上は橙（0xff9f43）。棒の高さ `CHARGE_BAR_MAX` × `CHARGE_MARK` の所に、レーンの幅いっぱいの白い横線（太さ 2、不透明度 0.8）を、溜めている間だけ出す（台に出る目安） | `charge` が 0 に戻る（離した・案内が出た・玉がレーンを離れた）と、棒と線を消す |
| 面クリアの文字 | `stageClear` に入ったフレーム | 中央の文字が、`CLEAR_POP_DURATION` 秒で大きさ `CLEAR_POP_FROM` 倍 → 1.0 倍に縮み、不透明度 0 → 1 になりながら現れる（どちらも線形。中心を固定。始めの倍率でも文字が画面の幅 `W` に収まる: `CLEAR_FONT_SIZE` × 13 文字 × `CLEAR_POP_FROM` ≈ 340 ≤ 360） | 面ごとに 1 回 |

- 演出は画面の揺れと一緒に動く（カメラが揺れるので、HUD・軌跡・「+100」も揺れる）。揺れの間も入力の位置はずれない（入力は画面の座標で読む）。

## ルール

- 玉は重力（`GRAVITY`）で落ち、壁・フリッパー・バンパー・ブロックで跳ね返る。速さは `MAX_SPEED` を超えない（超えたら向きを保って `MAX_SPEED` にする）。
- 跳ね返り: 玉の中心と相手（線分・円・矩形）の最近点との距離が、玉の半径 + 相手の半径（壁・ブロックは 0）より小さくなったら、玉を相手の外へ押し出し、接触面の法線方向の速度成分（相手に近づく向きのとき）を `−(1 + 反発係数) ×` で反転する。反発係数: 壁 `WALL_E`、フリッパー `FLIPPER_E`、ブロック `BLOCK_E`、バンパー `BUMPER_E`。
- フリッパー: 動いている面の速度を足す。接触点が根元から距離 d の位置のとき、その面の速度は (d × ω × (−s × sin a), d × ω × cos a)（a: 今の角度（ラジアン）、ω: 角速度（ラジアン/秒。上げるとき負、下げるとき正、止まっていれば 0）、s: 左フリッパー +1・右フリッパー −1）。玉の速度から面の速度を引いた相対速度で反射を計算する。フリッパーの向きは (s × cos a, sin a)。
- バンパー: 反射のあと、玉の速さが `BUMPER_MIN_OUT` 未満なら、向きを保って `BUMPER_MIN_OUT` にする（速さが 0 なら、バンパーの中心から玉への向きに `BUMPER_MIN_OUT`）。当たるたびに `BUMPER_SCORE` 点。
- ブロック: 玉が重なると（押し出しが起きたとき。近づく向きかどうかによらず）崩れて消え、`SCORE_BLOCK` 点。1 回の物理の刻みで複数のブロックに当たったら、当たった数だけ崩して得点する。スペシャルブロック（`*`）も同じ点で、崩れると玉が 1 個増える（[スペシャルブロックとマルチボール](spec/multiball.md)）。
- 面クリア: 面のブロックが全部消えた（`stageClear` に入る）。ボーナス点は無い。
- 玉を落とす: 玉の中心が y > `H` + `BALL_R` × 3 になる。残機 −1。残機が 0 になったらゲームオーバー（`ending` → Result）。台に玉が 1 個のとき、同じ刻みでブロックを崩して玉を落とすことは起きない（ブロックは台の上、落ち口は下）。玉が複数のときは [スペシャルブロックとマルチボール](spec/multiball.md) のとおり（最後の 1 個を落としたときだけ残機 −1）。
- スコア: ブロックとバンパーの得点の合計。ゲームオーバーでも全面クリアでも、Result に出す。
- 自己ベスト: `shared/best-store` の `BestStore('flipbreak')`。Game が終わって Result に入るとき（Result の表示の前）に、Phaser に依存しない関数（`BestStore` を引数で受ける）から `record(スコア, ラベル)` を呼ぶ（スコア 0 でも渡す）。ラベルはゲームオーバーなら `STAGE n`（n = 落としたときの面）、全面クリアなら `STAGE 5`。厳密に超えたときだけ更新（同点では更新しない）。

## 技術要件

- Phaser 4 + Vite + TypeScript（リポジトリ共通のスキャフォールド）。ESLint のエラー 0、Vitest のカバレッジ 90% 以上（ステートメント・分岐・関数・行）
- 物理エンジン（Arcade・Matter など）は使わず、玉の移動と当たりは下の純粋なロジックで計算する（フリッパーの面の速度を反射に足すため）。1 フレームの時間は `PHYSICS_DT` 刻みに分けて進める（時間が余ったら次のフレームに持ち越す）
- 次の規則は Phaser に依存しない純粋なモジュールに置き、単体テストする:
  - 玉の移動（重力・速さの上限）と、線分（壁・斜面・フリッパー）・円（バンパー）・矩形（ブロック）との当たりと跳ね返り、フリッパーの面の速度
  - フリッパーの角度と角速度の更新（`stepFlipper`）、フリッパーの先端の位置
  - 発射速度（`launchSpeed`）、発射できる状態の判定（`isReady`）、溜めの更新
  - 面の読み込み（文字列 → ブロックの並び）、面クリアの判定、玉を落としたかの判定
  - スコア、残機、Game の状態遷移（`playing` / `stageClear` / `ending`）、玉が詰まったかの判定（`STALL_SPEED` と `STALL_TIME`）
  - 玉が複数のときの規則（玉を足す・取り除く・残機・レーンの玉・玉ごとの詰まり。[スペシャルブロックとマルチボール](spec/multiball.md)）
  - 「縦にしてください」を出すかの判定、案内の文字の大きさ（`promptFontSize`）と改行（`promptText`）
  - 演出に使う 1 フレームの結果（`GameSession.frame` が返す: 崩れたブロックの番号・当たったバンパーの番号・落とした玉の数）、HUD の文字（`ballText` と点滅の `ghostBall`）、SCORE の強調の倍率（`scoreBumpScale`）、棒の色（`chargeColor`）、玉の軌跡の記録（`TrailBuffer`）と不透明度（`trailAlpha`）
  - 自己ベストの読み書きは `shared/best-store` の `BestStore`（ストレージは注入できる）を使う。このゲームに置くのは、渡す `score` / `label`（`STAGE n`）の組み立てと、表示の文字（`formatBest`）だけ。`flipbreak/package.json` に `"best-store": "workspace:*"` を宣言する
- Scene 側（描画・入力の読み取り・Scene の切り替え）は上のロジックを呼ぶだけにする。時間・乱数に頼らない（このゲームに乱数は無い）。
- パラメータ表の数値は 1 つのファイルに、表の名前で置く
- Scene は Title / Game / Result に分け、`create` で入力を登録し、Scene の `shutdown` で外す。毎フレームの処理で表示物（Phaser のオブジェクト）を新しく作らない（ブロックは 1 つの Graphics に描き、面の始まりとブロックが崩れたときだけ描き直す。バンパーは 1 個ずつ別の表示物にして（Scene の始まりに最大数ぶん作り、面の始まりに位置を置いて使う）、脈打ちはその表示物を動かす。演出の表示物（白い四角・「+100」・軌跡の丸）は、必要な数を Scene の始まりに作って使い回し、毎フレーム新しく作らない。演出の tween は、Scene の終わりに止める）。`GameSession.frame` が返す演出用の結果は、フレームごとに配列を新しく作らず、使い回す
- 単体ビルド（`npm run build`）と共有ビルドの両方で起動する

## テスト観点

- 発射速度 `launchSpeed(charge)`: 0 → 450、0.5 → 775、1 → 1100、−0.2 → 450（0 に収める）、1.5 → 1100（1 に収める）
- 発射できる状態 `isReady`: (345, 623, vy 0) → true、x = 330 ちょうど（`LANE_X`）→ false、y = 600 ちょうど（`H` − `READY_Y_MARGIN`）→ false、y = 601 → true、vy = 40 → false、vy = −39 → true
- フリッパーの更新 `stepFlipper`（`PHYSICS_DT` = 1/240、`FLIPPER_SPEED` 18 rad/s、1 刻みで 0.075 rad = 4.30°）: 下げた角度 28°（0.48869 rad）から押す → 1 刻み後に角度 23.70°、ω = −18。13 刻み後に −27.86°。14 刻み後に −28°（行き過ぎない）、そのときの ω = −0.572（残りの 0.00238 rad ÷ `PHYSICS_DT`）。押さないまま −28° にいる → 下がる向き（ω > 0）。目標の角度にいる → ω = 0
- フリッパーの面の速度での反射（左フリッパー、根元 (95, 560)、角度 −10°、ω = −18 rad/s、静止した玉が根元から 29 の位置に面の法線方向へ接している: 玉の中心 (121.13, 541.18)）: 面の速度 (−90.64, −514.07)、反射後の玉の速度 (−122.37, −693.99)（許容 ±0.5）。ω = 0 で同じ位置に静止した玉が接していても、速度は変わらない（0 のまま）。玉が離れる向きに動いているときは、速度を変えない
- 斜面とフリッパーのつなぎ目: 下げた左フリッパーの上へ、斜面の上から低速（初速 0〜30 px/s）で玉を落としても、止まらずに下へ抜ける（左右・複数の初期位置で、15 秒以内に玉を落とす）。斜面の端点が 98.29 / 553.82、右が 231.71 / 553.82（許容 ±0.01）
- バンパー: 玉が速さ 200 で当たる → 反射後の速さが 480。速さ 600 で当たる → 反射後も 600（変わらない）。速さ 0 で重なる → 中心から玉への向きに 480。当たるたびに +10 点（1 刻みで同じバンパーに、玉ごとに 1 回だけ）
- ブロック: 下から速さ 300（vy = −300）で当たる → 崩れて vy = +300（vx は変わらない）、+100 点。横から当たる → vx が反転。角に当たる（中心がブロックの角から玉の半径未満）→ 法線は角から玉の中心への向き。玉の中心がブロックの内側にある（押し出し）→ 一番浅い辺の外へ出す。1 刻みで 2 個のブロックに当たる → 2 個崩れて +200 点
- 壁: 玉 (6, 300)・速度 (−100, 0) が左の壁に食い込む → x = 7 に戻り、vx = +60（−100 − (1 + 0.6) × (−100)）。レーンの壁（x = 330、y = 120 から下）は、玉 (336, 200)・速度 (−100, 0) → x = 337 に戻り vx = +60、玉 (336, 100)（壁の上端 (330, 120) までの距離 20.9）→ 当たらない。右上の斜め壁で、玉 (345, 65)・速度 (0, −500) → 左へ曲がる（vx < 0、vy < 0 のまま）
- 玉を落とす: y = 667（`H` + `BALL_R` × 3）ちょうど → 落としていない、y = 667.01 → 落とした
- 面の読み込み: 面 1 → ブロック 24 個（3 行 × 8 列、左上のマスが (21, 60)、描く矩形は (22, 61) 34 × 16）、面 2 → 16 個、面 3 → 26 個、面 4 → 20 個、面 5 → 34 個。バンパーの数と位置が表のとおり。面のブロックが全部消えたら面クリア、1 個でも残っていれば面クリアではない
- 溜め: 押している間 `CHARGE_TIME` 秒で 1 まで増える（0.5 秒で 0.5、1.0 秒で 1、それ以上は 1 のまま）。離すと発射して 0 に戻る。玉がレーンにないとき（`isReady` でない）は溜まらない。押したまま玉がレーンで止まった場合（押し始めたのが `isReady` になる前）は、離して押し直すまで溜まらない
- 発射の確かめ（シミュレーション）: 溜め 0.5（発射速度 775）→ 玉は台に出ず、レーンに戻って `isReady` になる。溜め 1（1100）→ 玉が台の側（x < 330）に出る。溜め 0 → 玉が高さ約 145 px まで上がって戻る
- 状態遷移: `playing` でブロックが 0 になる → `stageClear`（最後の面ではない）、`CLEAR_PAUSE` 秒後に次の面が始まる（ブロック・バンパーが次の面、玉がレーン、フリッパーが下がった角度・ω 0、残機・スコアは引き継ぐ）。最後の面で 0 になる → `stageClear`（「ALL CLEAR」）、`CLEAR_PAUSE` 秒後に Result へ。玉を落として残機 3 → 2: `playing` のまま、玉がレーンの置き位置、溜め 0、フリッパーの角度はそのまま。残機 1 → 0: `ending`、`RESULT_DELAY` 秒後に Result へ。`stageClear` の間は入力・物理が進まない。`ending` の間は入力が効かない
- 玉の詰まりの救済: 台に出た玉が速さ 14（< 15）のまま 5 秒（ちょうど `STALL_TIME`）→ レーンの置き位置に戻る（残機・スコア・ブロックは変わらない）。4.99 秒では戻らない。速さが 15 ちょうど → 数え直す（詰まりでない）。どちらかのフリッパーを押す → 数え直す。レーンにいる玉は対象外
- 入力: 左半分（x < 180）を押す → 左フリッパー、x = 180 ちょうど → 右（半分の境は右が含む）、左右同時に押す → 両方。玉が `isReady` のときの画面タッチ → 溜め（フリッパーは動かない）。`isReady` でない玉（レーンを上昇中・バウンド中）への画面タッチ → フリッパーが動き、溜めは進まない。溜めの指が 2 本（t = 0 と t = 0.3 に押す）→ 最初の押下から数えて溜めが進み、1 本目だけ離しても発射しない、2 本目も離した時点で発射する（溜めはその時点の値）。キーボードのフリッパーは、玉がレーンにあっても動く。Scene に入る前から押されていた指・キーは、離すまで無視する。玉がレーンで止まる前から押されていた指・キーは、離して押し直すまで溜めに使わない
- 論理サイズの縮小率と案内: 390 × 844 → 縮小率 1.083（案内なし）、375 × 550 → 0.859（なし）、1280 × 720 → 1.125（なし）、667 × 310 → 0.484（出す）、844 × 390 → 0.609（出す）、横長で縮小率がちょうど 0.7（`ROTATE_PROMPT_SCALE`）→ 出さない（500 × 448: 縮小率 = min(500 ÷ 360, 448 ÷ 640) = 0.7）、500 × 447 → 出す（0.698）、縦横が同じ（448 × 448）→ 横長ではないので出さない、縦長の表示 → 縮小率にかかわらず出さない、高さ 0 の横長 → 出す（縮小率 0、文字の大きさは `PROMPT_MAX_FONT_SIZE`）
- 案内の文字 `promptFontSize`: 縮小率 0.484 → 38（18 ÷ 0.484 = 37.2 を切り上げ）、0.609 → 30、0.7 → 26（18 ÷ 0.7 = 25.7）、0.3 → 53（60 が上限で切られる）、0 → 53。`promptText(26)` → 1 行（11 × 26 = 286 ≤ 320）、`promptText(30)` → 2 行（330 > 320）、`promptText(53)` → 2 行（各行 ≤ 318）
- 自己ベスト（ゲーム側）: `BestStore` に渡す値は score と `STAGE <面>`（スコア 0 でも渡す）。注入したフェイクのストレージ・`today`（例: `() => '2026-01-01'`）で、保存される JSON は `{"score":1200,"label":"STAGE 3","date":"2026-01-01"}`（`BestStore` が `date` を足す）。`formatBest(null)` → `BEST ---`、`formatBest({score:1200,label:"STAGE 3"})` → `BEST 1200（STAGE 3）`。Result の「NEW BEST!」は `record()` の `isNew` で出し分ける。自己ベスト自体のテストは `shared/best-store` 側（ゲームでは再テストしない）
- 演出に使う 1 フレームの結果: 1 刻みで 2 個のブロックを崩す → 崩れたブロックの番号が 2 つ（`world.blocks` の並びの順）。バンパーに当たる → 当たったバンパーの番号。玉を落とす → 落とした玉の数 1（残機 3 → 2。この値は、残機が減ったときの 1。玉が複数あって台に玉が残るときは 0）。同じバンパーに 1 フレームで何度当たっても番号は 1 回だけ入れる（番号の小さい順）。何も起きなかったフレームは、すべて空（0）。前のフレームの結果は残らない（結果は呼び出しのたびに空に戻してから埋める。同じ配列を使い回すので、呼び出した側は次のフレームまで持ち続けない。テストはその場で値を読む）。ブロックを崩した刻みのあとで玉を落としても、両方入る

- SCORE の強調 `scoreBumpScale(経過秒)`: 0 → 1.25、0.075 → 1.125、0.15 ちょうど → 1.0、0.3 → 1.0（それ以上は 1.0 のまま）。経過が負 → 1.25 に収める
