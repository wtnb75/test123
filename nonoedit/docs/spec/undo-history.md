# 元に戻す／やり直す（undo-history）

`docs/spec.md` の一部。編集モードの履歴（元に戻す・やり直す）を、独立して書いたもの。`docs/spec.md` と合わせて 1 つの spec である。

## 概要

編集モードで盤面を変える操作を履歴に残し、元に戻す・やり直すができるようにする。直線ドラッグは広い範囲を一度に変え、全消去（`R`）・インポート・サイズ変更は盤面全体を置き換えるので、1 回の操作ミスで作った絵を失わないための安全網になる。編集のコアループ（描く → 確かめる → 直す）は広げない。編集の規則・解析・PBM・テストプレイの判定は変えない。

## 操作仕様

- 履歴に残す操作（1 回で 1 手）は 5 つ。いずれも編集モードの操作。
  - 1 マスのクリック（タップ）
  - 1 回の直線ドラッグ（ポインタを離したとき）
  - 全消去（キー `R`）
  - インポートの成功（`Import` ダイアログの `Load PBM`）
  - サイズ変更（`[Resize]`・`Resize`・キー `1`〜`9`）
- 盤面が変わらない操作は、手として残さない。盤面が変わらない = 操作の前後で、幅・高さ・全マスの `filled` / `empty` がすべて同じ。例: 空の盤面での全消去、今と同じサイズへのサイズ変更、今の盤面と同じ内容のインポート。インポートの失敗（エラー表示）も手にならない。
- 元に戻す: 直前の手を取り消し、盤面を、その操作の前の状態（幅・高さ・全マス）に戻す。取り消した手は、やり直しの側に積む。履歴が空なら、何も起きない。
- やり直す: 最後に取り消した手をもう一度行い、盤面をその操作の後の状態にする。やり直しの履歴が空なら、何も起きない。
- 新しい手を記録したとき、やり直しの履歴はすべて捨てる。盤面が変わらない操作は、手を足さず、やり直しの履歴も捨てない。
- 履歴は `UNDO_LIMIT` 手まで。超えたら、いちばん古い手から捨てる（捨てた手より前の状態には戻れない）。
- 履歴の 1 手は、その手の前の盤面（幅・高さ・全マス）をまるごと持つ。サイズ変更で小さくして、はみ出して消えたマスも、取り消すと戻る。
- ボタン: 編集モードで、画面のボタン `Undo`（元に戻す）と `Redo`（やり直す）を使う。履歴が空のときは無効（既存の無効ボタンと同じ見た目で、タップしても何も起きない）。置き場所は下の「画面・Scene構成」。
- キー（編集モードだけ）:
  - `Z`: 元に戻す。`Y`: やり直す。ほかの単キー（`R`・`T` など）と同じく、Shift の有無は問わない。
  - `Ctrl`（`⌘`）+`Z`: 元に戻す。`Ctrl`（`⌘`）+`Shift`+`Z`、`Ctrl`（`⌘`）+`Y`: やり直す（`Ctrl` と `⌘` は同じ扱い）。
  - 次のときは効かせず、何もしない（ブラウザの標準のまま。`preventDefault` もしない）: `Alt` を押しているとき、キーの対象が文字を入力する要素（`textarea`・`input`。インポートのダイアログなど）のとき、プレイモードのとき、ドラッグ中（ポインタを押している間）のとき。
  - 上に当たらないとき、履歴が空でも、`Ctrl`（`⌘`）併用のキーは `preventDefault` する（ブラウザの標準の取り消しが、ページを巻き込まないため）。
  - キーのリスナーは Scene の終了時に解除する（既存のキーと同じ）。
- テストプレイ中（`play` モード）は、ボタンを出さず、キーも効かせない。履歴はテストプレイで変わらず、編集モードに戻ると、テストプレイの前の履歴のまま使える。
- 例外（既存の挙動の明文化）: キー `R` は今までどおりテストプレイ中も盤面を全消去する。このとき盤面が変わったなら、全消去の 1 手として記録する（編集に戻ったあとで元に戻せるように。プレイ中の `Undo` / `Redo` のボタンとキーが効かない点は変わらない）。サイズ変更（`1`〜`9`）とインポートは、実行すると編集モードに戻るので、通常の手として記録する。
- 履歴は保存しない。ページの再読み込みや Scene の再開始で空になる。
- メッセージ行（英語の UI）: 元に戻したとき `Undo`、やり直したとき `Redo`。ほかの操作のメッセージは今までどおり。

## 画面・Scene構成

新しい Scene・画面は作らない。`Game` Scene の編集モードのボタンを足す。

- PC（画面幅 > 768px）: 編集モードのツールバーの、既存のボタン（`[Resize]` `[Import]` `[Copy PBM]` `[Analyze]` `[Test Play]`）の右に `[Undo]` `[Redo]` を、この順で置く。ボタンは今までどおり 1 つの横一列（実装では `y = 20` の行）に並んでおり、`[Undo]` は `[Test Play]` の右隣、テストプレイ中に `[Input: …]` が置かれる位置（`x = 720`）から始める。画面例（`docs/spec.md`）の 2 行に分かれた描き方は、略図であり、位置の根拠にしない。画面幅が狭く、1 行目の右端（`[Redo]` の右端 = 880px）が画面の外になるとき（ツールバーの既存のボタンの右にある余白に収まらないとき）は、`[Undo]` `[Redo]` を 2 行目（`[Resize]` `[Import]` の下の空き）に折り返してよい。既存のボタンの位置は変えない。テストプレイ中は出さない。`[Clear]` ボタンは元から無い（全消去はキー `R` だけ。この拡張でも足さない。`docs/spec.md` の画面例から `[Clear]` を除いたのは、実装に合わせた訂正）。
- モバイル（画面幅 <= 768px）: 「編集」タブのパネルの、編集モードの行（`Resize` `Play`）に、`Undo` `Redo` を、この順で足す。
  - 4 つのボタンは同じ行に置く。各ボタンは、高さ 44px・幅 44px 以上（FIT 後の実寸。[モバイル対応](mobile.md) のタッチターゲット基準）。パネル幅に収めるために、既存の `Resize` `Play` の幅を縮めてよい。
  - 行に収まらない狭い画面では、`Undo` `Redo` を次の行に折り返してよい。そのときパネルの高さを、その行の分だけ増やしてよい（増やしたときも、盤面とヒントは画面に収まる。盤面の表示が小さくなる分は許容する）。
  - 「情報」「入出力」タブ、テストプレイ中の「編集」タブには足さない。
- ボタンの有効・無効（編集モードのとき）: `Undo` は元に戻す履歴があるとき有効、`Redo` はやり直す履歴があるとき有効。ボタンの見た目・大きさ・文字は、既存のボタンと同じ範囲。
- 元に戻す・やり直すのあとは、盤面とヒントを、戻した盤面で描き直す（クリック・ドラッグの編集と同じ描画の経路でよい）。幅・高さが変わる手のときは、サイズ変更のときと同じく、盤面の配置を計算し直す。モード（`edit`）・モバイルのタブは変えない。
- 解析: 元に戻す・やり直すのあと、ほかの編集と同じく、解析を再実行する（`[Analyze]` ボタンではない通常の要求。[非同期の解析](analysis-async.md) の「解析を始める操作」の 1 つ）。解析中でも、元に戻す・やり直すは使える（走っている解析は打ち切られる）。解析中（pending）の間は、今までどおり PBM のコピーが使えない（[非同期の解析](analysis-async.md) のとおり）。
- 状態遷移: 画面の状態を増やさない。履歴（取り消しの側・やり直しの側）は、`edit` / `play` のモード切替では変わらない。

## ルール

- 盤面の状態（`BoardSnapshot`）: 幅、高さ、全マス（既存の `solution` と同じ表現のコピー。履歴に入れた後で、現在の盤面を書き換えても、履歴の状態は変わらない）。
- 履歴は、取り消しの側とやり直しの側の 2 つ。手を記録すると、操作の前の状態を取り消しの側の最後に積み、やり直しの側を空にする。取り消しの側が `UNDO_LIMIT` を超えたら、いちばん古いものを捨てる。
- 元に戻す: 現在の状態をやり直しの側に積み、取り消しの側の最後を現在にする。やり直す: 現在の状態を取り消しの側に積み、やり直しの側の最後を現在にする（取り消しの側は常に `UNDO_LIMIT` 以内で、やり直しの積みで上限を超えることはない）。
- 「盤面が変わらない」の判定は、幅・高さ・全マスの比較（深い比較）で行う。
- 履歴の記録と取り消し・やり直しは、盤面の配列を別に持つ純粋なデータ操作として切り出す（Phaser・DOM に依存せず、引数を破壊的に変更しない。上限は引数で渡せる）。
- テストプレイのプレイヤー盤面（`unknown` / `filled` / `marked`）は、履歴の対象にしない。取り消し・やり直しのあと、プレイヤー盤面は今までどおり、テストプレイを始めるときに空状態で作り直される。
- 変えないもの: 編集の基本操作（クリック・直線ドラッグの規則と軸の決め方）、PBM `P1` の入出力形式、テストプレイの判定（`filled` の一致のみ）、解析・難度の結果、サイズの範囲（5〜25）、既存のショートカット・ボタンの意味。

| 名前 | 初期値 | 意味 |
|---|---|---|

## テスト観点

純粋関数（`src/game/core/` の履歴・キー判定。Phaser・DOM に依存せず、引数を破壊的に変更しない。上限は引数で渡せる）の単体テスト。期待値は、上の規則から手で出す。

- 履歴（盤面 10 × 10、空から。マスは (x, y)）
  - (0,0) をクリック（手 a）、(1,0) をクリック（手 b）。元に戻すと {(0,0)}、やり直すと {(0,0), (1,0)}。元に戻してから (2,0) をクリックすると、やり直しの側が空になり、やり直しても何も起きず、盤面は {(0,0), (2,0)}
  - 空の履歴で、元に戻す・やり直すをしても、状態は変わらない（同じ盤面が返る）
  - 盤面が変わらない状態を記録しても、取り消しの側もやり直しの側も変わらない（元に戻した直後に、同じサイズへのサイズ変更や、空の盤面での全消去をしても、やり直せる）
  - 上限（テストでは 3 を渡す）: 手 a・b・c・d を記録すると、取り消しの側が持つのは、a の後・b の後・c の後の状態の 3 つだけ（最初の状態は捨てられる）。3 回元に戻すと a の後の状態になり、4 回目は何も起きない。既定の `UNDO_LIMIT` は 100（101 手を記録すると、100 回だけ元に戻せる）
  - 直線ドラッグの手: 横線 (0,0)〜(3,0) を 1 回のドラッグで黒にした手は、1 回の元に戻すで、4 マスすべてが白に戻る
  - 全消去の手: 黒が 3 マスの盤面を全消去した手を元に戻すと、3 マスが戻る。やり直すと、もう一度空になる
  - サイズ変更の手: 10 × 10 で (9,9) と (0,0) が黒の盤面を 5 × 5 にすると、(0,0) だけが残る。元に戻すと、10 × 10 で (9,9) と (0,0) が黒の盤面に戻る（はみ出して消えたマスも戻る）。やり直すと 5 × 5 で (0,0) だけ
  - インポートの手: 10 × 10 の盤面に、5 × 5 の盤面をインポートした手を元に戻すと、10 × 10 の元の盤面に戻る。同じ内容のインポートは手にならない
  - 入力の状態・履歴を破壊的に変更しない（返った値は別の配列。履歴に入れた盤面を、あとで現在の盤面の書き換えから守る）
- キー判定（キー・`Ctrl` / `⌘` / `Shift` / `Alt`・対象が入力要素か・プレイ中か・ドラッグ中か → 元に戻す・やり直す・なし。`preventDefault` するかも返す）
  - `z`、`Z` → 元に戻す。`y`、`Y` → やり直す
  - `Ctrl`+`z`、`⌘`+`z` → 元に戻す。`Ctrl`+`Shift`+`Z`、`⌘`+`Shift`+`z`、`Ctrl`+`y`、`Ctrl`+`Shift`+`y` → やり直す
  - `Alt` 併用、入力要素が対象、プレイ中、ドラッグ中 → なし（`preventDefault` しない）
  - `Ctrl`+`z` で履歴が空のとき: 元に戻すの結果は何も起きないが、`preventDefault` は行う（対象が入力要素・`Alt`・プレイ中・ドラッグ中のときは行わない）
  - 関係ないキー（`x` など）→ なし
- ボタンの有効・無効（純粋関数でも Scene でもよい）: 取り消しの履歴の有無・やり直しの履歴の有無から、`Undo` / `Redo` の有効・無効が決まる
- 回帰（既存のテストは変えずに通る）: 取り消し・やり直し・サイズ変更・インポートのあとの盤面で、ヒント生成・PBM の書き出し・解析（`analyzePuzzle`）の結果が、同じ盤面から新しく作ったものと一致する。`editOps`・`pbm`・ソルバーの既存のテストは変えない

DOM（ブラウザ）の確認は QA で行う（単体テストの対象外）: PC とモバイル（375 × 550・390 × 844・667 × 310 を含む）でのボタンの並び・有効・無効の切り替えと 44px 以上のタップ、クリック → `Undo` → `Redo`、ドラッグ → `Undo`、`R` → `Undo`、サイズ変更 → `Undo`（はみ出した部分が戻る）、インポート → `Undo`、キー `Z` `Y` と `Ctrl`（`⌘`）+`Z` / `Ctrl`（`⌘`）+`Shift`+`Z` / `Ctrl`（`⌘`）+`Y`、インポートの `textarea` にフォーカス中は効かないこと、テストプレイ中はボタンが無く（キーも効かず）、編集に戻ると履歴が残っていること、元に戻す・やり直しのあとに解析パネルが更新されること。

## 完了条件

- 編集モードで、`Undo` / `Redo` のボタン（PC はツールバー、モバイルは「編集」タブ）とキー（`Z` / `Y` と `Ctrl`（`⌘`）併用）が使え、履歴の有無でボタンの有効・無効が切り替わる。モバイルのボタンは実寸 44px 以上
- 1 マスのクリック・1 回の直線ドラッグ・全消去・インポートの成功・サイズ変更が、1 回 1 手で元に戻せ、やり直せる。盤面が変わらない操作とインポートの失敗は手にならない。新しい手でやり直しの履歴が消える。履歴は `UNDO_LIMIT` 手まで
- サイズ変更を元に戻すと、はみ出して消えたマスも戻る
- 元に戻す・やり直すのあと、盤面・ヒントが戻した盤面になり、解析が再実行されて解析パネルが更新される
- 入力要素にフォーカス中・テストプレイ中・ドラッグ中・`Alt` 併用ではキーが効かない。テストプレイ中はボタンが無く、テストプレイの前後で履歴は変わらない
- 回帰（今までと同じ。この拡張で意図して変えるのは、編集モードに `Undo` / `Redo` のボタンとキーが増えることと、`docs/spec.md` の「Undo/Redo は未提供」を提供するに改めることだけ）: 編集の基本操作（クリック・直線ドラッグの規則と軸の決め方）、PBM `P1` の入出力形式、テストプレイの判定（`filled` の一致のみ）とクリア表示、解析・難度の結果と表示、サイズの範囲（5〜25）、既存のショートカット・ボタンの意味と位置（PC のツールバーの既存のボタンの位置は変わらない）、モバイルの「情報」「入出力」タブ
- `npm run lint` / `npm run test` / `npm run test:coverage` / `npm run build` が成功する。カバレッジ 90% 以上
