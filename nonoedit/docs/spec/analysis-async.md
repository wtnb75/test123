# 非同期の解析（解析を別スレッドで実行する）

`docs/spec.md` の一部。論理解可否判定・難易度判定（解析）を Web Worker で実行し、編集中に画面が固まらないようにする仕組みを、独立して書いたもの。`docs/spec.md` と合わせて 1 つの spec である。解析そのもの（手筋・難易度・タイムアウト）は [論理解可否判定と難易度判定](solver.md) のとおりで、変えない。

## 概要

解析（`analyzePuzzle`）は今まで、編集のたびにメインスレッドで同期的に走り、重い盤面では最大 3 秒、画面が固まっていた。これを Web Worker で実行し、結果は届いたら更新する。解析中は解析パネルに「解析中」を出し、結果の値と、PBM のコメントに入れる難易度の情報が、置いた盤面とずれないようにする。判定の結果は変えない（編集の操作性だけを直す。コアループは広げない）。

## 操作仕様

- 追加する操作はない。次の操作の効き方だけが、解析中に変わる。
  - 「Copy PBM」（PC のボタン、モバイルの「入出力」タブの Copy ボタン、キー `C`）: 解析中は、コピーしない（下の「コピー」）。
  - 「Test Play」（ボタン、キー `T`）: 解析中でも始められる（下の「テストプレイ」）。
- 編集の基本操作（クリック・直線ドラッグ）、`Resize`・`Clear`・`Import`・`[Analyze]`・`D` の操作そのものは変えない。

## 画面・Scene構成

新しい Scene・画面は作らない。`Game` Scene の解析パネルと、解析を始める操作を変える。

### 解析を始める操作と、解析の状態

解析は次のときに始める（今の `runAnalysis` の呼び出しと同じ）: 編集の確定（編集モードでポインタを離したとき）、`Import`（読み込みに成功したとき）、`Resize`、`Clear`（`R`）、`[Analyze]` ボタン、キー `D`、Scene の開始（`create`）。

| 状態 | 内容 | 遷移 |
|------|------|------|
| idle | 解析が走っていない。パネルは最新の結果を、今の盤面について表示する | 解析を始める操作で pending へ |
| pending | 解析が走っている。パネルは「解析中」の表示（下） | 結果が届くと idle へ。解析を始める操作が来ると、走っている解析を打ち切って、新しい解析で pending のまま |

- 盤面を変える操作（編集の確定・`Import`・`Resize`・`Clear`）は、解析の結果を待たずに、盤面にすぐ反映する（盤面の表示・ヒントの更新は今までどおり即時）。
- 解析は、そのときの最新の盤面だけを対象にする。新しい解析を始めるときは、走っている解析を打ち切る（Worker を止める）。打ち切った解析の結果は使わない（古い要求の結果が届いても、無視する）。
- 結果が届いたら、解析パネルを更新する。プレイモードの間に届いた結果でも、更新する（下の「テストプレイ」の警告を除き、ほかの表示は変えない）。
- `[Analyze]` ボタンを押したときは、`Analysis started` を、**要求を出す前**にメッセージ行へ設定する。その解析の結果が届いたら、`Analysis updated` を出す（キー `D` は、今までどおり、メッセージを変えない）。同期実行（フォールバック）では、結果が要求から戻る前に処理されてよく、その場合の最終的なメッセージは `Analysis updated` になる。

### 解析パネルの表示（pending のとき）

PC の右パネル（`Analysis`）と、モバイルの「情報」タブのパネルで、位置・行の並びは変えずに、次のように表示する。

| 項目 | pending のとき | idle のとき |
|------|----------------|-------------|
| `solvable` / `unique` / `logical` / `difficulty` / `score` / `remaining` の値 | `…`（例: `solvable: …`） | 今までどおり（最新の結果） |
| 手筋ごとの回数（PC の `fill: n` など、モバイルの `f:n e:n …`） | 数の代わりに `-`（例: `fill: -`、`f:- e:- o:- c:- x:-` / `s:- b:- p:-`） | 今までどおり |
| `timeout: 3s` の行 | 出さない | タイムアウトしたときだけ、今までどおり |

- 直前に完了した結果は内部に持ってよいが、pending の間は表示しない（古い値を、今の盤面の結果と読み違えないため）。
- 表示の言語・文字の大きさ・色は今までどおり（英語の UI）。pending の値の色だけ、実装で薄くしてよい。

### コピー

- pending の間は、「Copy PBM」（PC のボタン、モバイルの Copy ボタン、キー `C`）を使えない。
  - ボタンは使えない見た目（グレー）にし、タップしても、コピーしない。
  - ボタンのタップとキー `C` は、メッセージ行に `Analysis running: copy after it finishes` を出す（何もコピーしない）。
- idle のときは今までどおりコピーする。PBM のコメント（`# difficulty` / `# score` / `# unique`）は、コピーの時点の盤面の解析結果になる（pending を避けることで、盤面とずれない）。
- pending は、結果が届くか、同期実行（下の「フォールバック」）が終わるまで。長くても解析のタイムアウト（`analysisTimeoutMs`）に、Worker の起動の時間を足した程度。

### テストプレイ

- pending の間でも、`Test Play`（ボタン、キー `T`）を始められる。
- 始めるとき、pending の間は、警告を出さずに `Play mode started` を出す（結果がまだ分からないため）。idle のときは今までどおり（非一意・論理未解決なら警告、そうでなければ `Play mode started`）。
- プレイモードの間に結果が届き、その結果が `!unique || !solvable` のときだけ、今までと同じ警告 `Warning: puzzle is not unique/solvable but play is allowed` をメッセージ行に出す。それ以外（一意で論理だけで解ける）は、メッセージを変えない。編集モードに結果が届いたときは、パネルの更新だけ。
- テストプレイの入力・クリア判定（`filled` の一致のみ）は変えない。

## ルール

- 解析の結果（`solvable` / `unique` / `logical` / `difficulty` / `score` / `remainingCells` / 手筋の回数 / `timedOut`）は、同じ盤面とヒントに対して、同期実行と Worker で同じ値になる。
- 解析のタイムアウト（`analysisTimeoutMs`、3 秒）と、タイムアウトしたときの扱い（`logical = false`、`unsolved`、`timeout: 3s` の警告。[論理解可否判定と難易度判定](solver.md)）は、Worker の中で今までと同じに働く。数え始めるのは、Worker が解析を始めたとき（Worker の起動の時間は含めない）。
- Worker への要求は、`{ id, solution, rowHints, colHints, maxMillis }`、Worker からの結果は `{ id, result }`（`result` は `AnalysisResult` の値）。`id` は要求ごとに増える整数で、結果の `id` が最新の要求と違うものは捨てる。
- 解析を始めるたびに、走っている解析を打ち切る。打ち切りは、Worker を止める（`terminate`）か、それと同じく計算を確実に止める方法で行う。走っている解析がないときは、同じ Worker を使い回してよい。
- **フォールバック**: Worker が使えない（`Worker` がない、作れない）とき、または Worker が要求の途中でエラーを返したとき（`error`・`messageerror`）は、その要求と以降の要求を、今までと同じ同期実行（メインスレッドで `analyzePuzzle`）に切り替える。同期実行の結果は同じ値で、結果が届く処理（パネルの更新など）も同じ経路を通す。
- Scene が終わるとき（`shutdown` / `destroy`）、走っている Worker を止め、保留中の結果の処理を捨てる。
- 解析の要求・結果・打ち切り・フォールバックの管理は、Phaser に依存しない純粋なロジックとして切り出し、Worker の作り方（ファクトリ）と同期の解析関数を差し込めるようにする。
- **応答のない Worker**: 要求から `analysisWatchdogMs` 経っても結果も `error` も返らないとき、Worker を止め、その要求を同期実行にフォールバックして処理する（以降の要求も同期実行）。pending が解けなくなることを防ぐための最後の手段。
- 解析の初期値: `analysis` の初期値（Scene が作られてから、最初の結果が届くまで）は、同期の解析を呼ばない定数（空盤面の結果など）でよい。最初の描画は pending で出す（Scene の開始の要求は非同期）。
- プレイモードの間に届く結果の警告は、どの要求（編集の確定・`Import` 以外も含め、`[Analyze]`・`D` を含む）の結果でも出す。
- 画面例にあるインポート領域の「Copy Current as PBM」などの PBM コピーの操作を作る場合も、コピーと同じ扱い（pending の間は使えない）にする。
- 新しい依存は足さない（ブラウザ標準の Worker だけを使う）。単体ビルド（`npm run build`）と共有ビルド（`task build`、サブパスで配信）の両方で、Worker が読み込まれて動くこと。

## パラメータ表

| 名前 | 初期値 | 意味 |
|------|--------|------|
| `analysisTimeoutMs` | 3000 | 解析のタイムアウト（ms）。今までと同じ。Worker の中で数える |
| `analysisWatchdogMs` | 6000 | 要求から結果（または `error`）が返らないときに、Worker を止めて同期実行にフォールバックするまでの時間（ms。`analysisTimeoutMs` の 2 倍） |
| pending の値の表記 | `…` / `-` | pending のときの、値と手筋の回数の表記 |
| メッセージ | `Analysis started` / `Analysis updated` / `Analysis running: copy after it finishes` | 追加するメッセージ行の文字（英語の UI） |

## テスト観点

純関数・Phaser 非依存のロジックとして `core/` に切り出し、Worker はファクトリを差し込んだ偽物でテストする（本物の Worker は使わない）。

- **解析の管理（要求・結果・打ち切り）**:
  - 要求すると、`id`・盤面・ヒント・`maxMillis` を持つ要求が Worker に送られ、pending になる。結果の `id` が一致すれば、結果の処理が 1 回呼ばれ、idle に戻る。
  - 要求を続けて 2 回出すと、1 回目の Worker が止められ（偽物の `terminate` が呼ばれる）、2 回目の結果だけが処理される。1 回目の `id` の結果が遅れて届いても、無視される（結果の処理は 2 回目の分の 1 回だけ）。
  - 打ち切り（Scene の終了）で、Worker が止まり、その後に届いた結果は無視される。
  - 要求の `id` は要求ごとに増える。
- **フォールバック**:
  - Worker のファクトリが例外を投げる、または `undefined`（Worker がない）のとき、その要求は同期の解析で結果が返り、pending が残らない。
  - Worker が要求の途中で `error` / `messageerror` を返したとき、その要求は同期の解析で結果が返り、以降の要求は Worker のファクトリを呼ばずに同期で処理される。
  - 同期の解析関数（注入）に渡す引数が、Worker への要求と同じ（`solution`・`rowHints`・`colHints`・`maxMillis`）。
- **応答のない Worker**（時刻を注入）: 要求から `analysisWatchdogMs` 未満（5999ms）では pending のまま、`analysisWatchdogMs`（6000ms）で Worker が止められ、その要求が同期で処理されて結果が返り、以降の要求はファクトリを呼ばずに同期で処理される。
- **同期と Worker の同値**: Worker の中で要求を処理する関数（`id` と `AnalysisResult` を返す純関数）の結果が、同じ盤面・ヒント・`maxMillis` の `analyzePuzzle` の結果と、`toEqual` で一致する。盤面は、5 × 5 の空盤面、一意解を持つ小さな手計算の盤面、複数解の盤面、解なしのヒント、乱数（シード固定）で作った 7 × 6 の盤面を使う。どれも `timedOut` が `false` で、`solvable` / `unique` が真・偽の両方、手筋の回数が 0 でないものを含む（空でない結果を確かめる）。
- **パネルの表示（pending）**（純関数: 解析結果と pending から、表示の文字列を返す）:
  - pending のとき、6 つの値がすべて `…`、手筋の回数がすべて `-`、`timeout` の行がない。
  - idle のとき、値と回数が `AnalysisResult` どおり、`timedOut` のときだけ `timeout: 3s` の行がある。
  - 直前の結果が `timedOut` でも、pending のとき `timeout` の行がない。
- **コピーの可否**（純関数）: pending のとき不可、idle のとき可。pending でコピーを試みると、コピーせずにメッセージ `Analysis running: copy after it finishes` を返す。idle のときは、PBM の文字列が今までと同じになる（`exportPBM` の既存のテストがそのまま通る）。
- **テストプレイの警告**（純関数: モードと解析結果から、結果が届いたときのメッセージを返す）: プレイモードで `!unique` → 警告、`!solvable` → 警告、一意かつ論理で解ける → なし（メッセージを変えない）。編集モードでは、どの結果でもなし。
- **`[Analyze]` のメッセージ**: ボタンの要求の結果が届いたときだけ `Analysis updated`。キー `D`・編集の確定・`Import` などの要求では、結果が届いても `Analysis updated` を出さない。同期実行（フォールバック）でも、ボタンの要求の最終的なメッセージが `Analysis updated` になる（`Analysis started` で止まらない）。
- **プレイ中の警告**: プレイモードの間に届いた結果の警告は、どの要求の結果でも（`D` を含む）、`!unique || !solvable` のとき出る。
- **回帰（変えないもの。既存のテストを変えずに通ること）**: ソルバー・手筋・難易度・PBM の入出力・ヒント生成・盤面の既存のテストがそのまま通る。`analyzePuzzle` の引数と結果の形は変わらない。

Scene の結線（Worker の生成、パネルの描画、ボタンの見た目、メッセージ行）は画面で確かめる（`game-qa`）。

## 完了条件

- 15 × 15 以上の重い盤面（例: 20 × 20 の乱数の盤面）を編集しても、解析が走っている間、盤面の編集・スクロール・タブ切り替えが固まらない（ブラウザで確認。解析が走っている間にもう 1 マス編集できる）。
- 解析中、解析パネルの値が `…`、手筋の回数が `-` になり、結果が届くと今までと同じ値に更新される（PC の右パネルとモバイルの「情報」タブ。スクリーンショットで確認）。
- 続けて編集すると、前の解析が打ち切られ、最新の盤面の結果だけが表示される（古い盤面の結果が一瞬でも表示されたままにならない）。
- 解析中は「Copy PBM」が使えず、タップ・キー `C` でメッセージ `Analysis running: copy after it finishes` が出る。結果が届いたあとは、今までどおりコピーでき、PBM のコメントが盤面と一致する。
- 解析中でも `Test Play` を始められ、警告なしの `Play mode started` が出る。結果が届いたとき、非一意・論理未解決なら、プレイ中に警告が出る。
- `[Analyze]` を押すとメッセージ `Analysis started`、その結果が届くと `Analysis updated` が出る（同期実行のフォールバックでも、最終的に `Analysis updated`）。
- Worker が実行時にエラーを返しても、または応答がなくても、解析の結果が今までと同じ同期実行で出る（偽の Worker・開発者ツールでの確認と単体テスト）。
- Scene を離れる（`shutdown`）と、走っている Worker が止まり、保留中の結果の処理が捨てられる（単体テスト）。
- 3 秒を超える盤面で、今までと同じく `unsolved` と `timeout: 3s` の警告が出る。
- Worker が使えない環境（Worker を無効にして確認）でも、今までと同じ同期実行で、同じ結果が出る。
- 単体ビルド（`npm run build`）と共有ビルド（`task build`、サブパス）の両方で、Worker が読み込まれ、エラーなく解析の結果が出る（ブラウザで確認）。
- 変えないもの（回帰条件。既存の単体テストがそのまま通ること、ブラウザ QA の操作確認が前回と同じ結果であること）: 編集の基本操作（クリック・直線ドラッグ）、PBM `P1` の入出力形式とコメントの内容、テストプレイの判定（`filled` の一致のみ）とクリア表示、解析の結果の値（どの盤面でも同期実行と同じ）、3 秒のタイムアウトと `unsolved`、難易度の算出、Import のエラー処理、モバイルのタブとレイアウト、`Resize` の動き。
- `npm run lint` / `npm run test` / `npm run test:coverage` / `npm run build` がすべて通り、カバレッジが 90% 以上。

## 実装裁量

- Worker ファイルの名前・置き場所と、Worker の作り方（`new Worker(new URL(..., import.meta.url), { type: 'module' })` など。ビルド設定の変更は、単体・共有の両方で動くことを確かめてから）。
- 解析の管理のロジックの名前・ファイル分け、要求と結果の型の名前。走っていない Worker を使い回すか、毎回作り直すか。
- pending の値の色（薄くしてよい）、グレーの Copy ボタンの色・見た目。
- 解析の結果が届いたときの再描画の方法（既存の `requestRender` を使う）。
- 開発用のログの扱い。
