# ゲーム名

NonoEdit

# コンセプト

モノクロのノノグラム問題を作成、検証、共有するためのブラウザ向けステージエディタ。
作者が盤面を直接編集しながら、論理だけで解けるか、どの程度の難しさかを即座に確認できることを重視する。

# 仕様策定の前提

- 現在は Phaser + Vite + TypeScript による実装が存在し、編集・解析・テストプレイを 1 画面内モード切替で提供している
- 本書は実装準拠の仕様として、挙動の明文化と今後の拡張余地の整理を目的とする
- まずは単体で完結するローカル編集ツールとして運用し、外部保存やオンライン共有は後続段階で検討する

# ターゲットプレイヤー

- ノノグラム問題を自作したいパズル制作者
- 自作問題をブラウザ上で素早く試したいプレイヤー
- SNS やメッセージで問題データを共有したいユーザー

# コアループ

1. 盤面サイズを決める
2. セルを白黒で編集して問題盤面を作る
3. 行・列ヒントを自動生成して妥当性を確認する
4. 難易度判定と論理解可否判定を実行する
5. テストプレイで実際の解き心地を確認する
6. 問題データをクリップボードへコピーして共有する

# 操作仕様

- 入力デバイスはマウスを基本とし、キーボードは補助操作に使う
- 盤面サイズ指定は画面 UI を主手段とし、ショートカットは補助手段として扱う
- 画面 UI にはサイズ指定コントロールを配置する
  - 幅と高さを直接入力できる数値入力
  - よく使うサイズを即時選択できるプリセット選択
  - `Apply` または `Resize` 実行で反映
- 左クリックで黒マスを配置、再度クリックで白マスに戻す
- 左ドラッグで直線編集を行える
  - 水平または垂直のみ対応し、斜めは非対応
  - 軸は、ポインタが開始セルとは別のセルに最初に入った時点の、開始セルからの差で決め、そのドラッグの間は変えない。横の差の絶対値が縦以上なら水平、そうでなければ垂直（同じなら水平）。軸が決まったら、もう一方の座標は開始セルに固定した線分を対象にする
  - ポインタが開始セルとは別のセルに一度も入らずに離した場合（タップ）は、開始セル 1 つだけをクリックの規則で切り替える。一度でも別のセルに入った場合は、開始セルに戻って離してもドラッグとして扱い（タップではない）、範囲は開始セル 1 つで、ドラッグの規則を適用する
  - 編集モードの規則: クリックは黒と白を入れ替える。ドラッグは、線分に白が 1 つでもあれば白のマスだけを黒にし、すべて黒ならそのすべてを白にする
  - テストプレイの規則（`Fill` / `Mark` のどちらのモードでも、対象の状態は `Fill` なら `filled`、`Mark` なら `marked`）
    - クリック: `unknown` なら対象の状態にし、それ以外（`filled` / `marked`）なら `unknown` に戻す。手数は 1 増える
    - ドラッグ: 線分に `unknown` が 1 つでもあれば、`unknown` のマスだけを対象の状態にする。`unknown` が無く、すべてが現在のモードの対象の状態（`Fill` なら全部 `filled`、`Mark` なら全部 `marked`）なら、そのすべてを `unknown` に戻す。それ以外（`filled` と `marked` が混在など）は何も変えない
    - 手数は、ドラッグで状態が変わったマスの数だけ増える（`unknown` に戻すときは線分のすべてのマスを数える）
- 右クリックまたは補助キー付きクリックで編集補助モードを呼び出せる設計を許容する
- キーボードショートカットを設ける
- 主要候補
  - `1-9`: 盤面サイズのプリセット切り替え
  - `R`: 盤面全消去
  - `T`: テストプレイ開始
  - `E`: 編集モードへ戻る
  - `C`: 問題データをクリップボードへコピー
  - `D`: 難易度判定を再実行

現行実装では Undo/Redo (`Z` / `Y`) は未提供とする。

ショートカットの初版マッピング。

- `1`: 5 x 5
- `2`: 7 x 7
- `3`: 10 x 10
- `4`: 12 x 12
- `5`: 15 x 15
- `6`: 18 x 18
- `7`: 20 x 20
- `8`: 22 x 22
- `9`: 25 x 25

# 盤面仕様

- 盤面はモノクロ 2 値とし、各セルは `filled` または `empty` のどちらかを持つ
- UI 上の意味は `filled = 黒マス`、`empty = 白マス` とする
- 編集モードの正解盤面は 2 状態のみを持つ
  - `filled`: 黒マス
  - `empty`: 白マス
- テストプレイ中のプレイヤー盤面は 3 状態を持つ
  - `unknown`: 未確定
  - `filled`: 黒マスとして入力済み
  - `marked`: 白マス候補としてバツ印を付けた状態
- `marked` はプレイ補助用の状態であり、正解盤面や PBM 出力には含めない
- 初版では長方形盤面を対象とする
- 想定サイズ範囲
  - 最小: 5 x 5
  - 初期値: 10 x 10
  - 最大: 25 x 25
- 編集中は正解盤面そのものを保持し、問題ヒントはそこから自動算出する
- テストプレイ時のプレイヤー盤面は別状態として持ち、編集データを破壊しない

# 画面・Scene 構成

## 1. Game Scene（単一 Scene）

- 盤面編集、解析表示、テストプレイを 1 つの Scene で管理する
- モードは `edit` / `play` を切り替える
- セルグリッド、行ヒント、列ヒント、現在サイズ、解析結果、各種ボタンを表示する
- 編集のたびに盤面更新を行い、編集確定時に解析を再計算する（解析は Web Worker で非同期に実行し、結果は届いたら更新する。[非同期の解析](spec/analysis-async.md)）
- 画面上で幅と高さを入力して盤面サイズを変更できる
- インポートは複数行テキストを貼り付けできる `textarea` ダイアログで行う

## 2. Analysis UI

- 難易度判定結果、最も重い手筋（`Hardest`）、論理解可否、残セル数、警告メッセージを表示する
- 複数解、解なし、論理のみで未確定などの状態を明示する
- 使用した推論手筋の内訳を簡潔に表示する

## 3. Play モード

- 作成済み問題を実際に解くためのモード
- 編集用の正解盤面を隠し、プレイヤー入力と現在の解答状況を管理する
- 入力は `Fill` / `Mark` のトグルモードで扱う
  - `Fill` クリック: `unknown -> filled`, `filled/marked -> unknown`
  - `Mark` クリック: `unknown -> marked`, `filled/marked -> unknown`
- プレイヤー盤面が正解盤面と一致したら自動でクリア判定を行う
- クリア時はクリア済みであること、所要操作数、経過時間を表示し、編集モードへ戻れる

# モード仕様

## 編集モード

- 正解盤面の作成と調整を行う
- 編集結果に応じてヒント、解の一意性、論理解可否、難易度を再計算する
- 解析が重い場合は手動再実行ボタンを許容する
- 盤面サイズは画面 UI で幅と高さを指定して変更できる
- PBM テキストの貼り付けによるインポートを行える
- 読み込み失敗時は、不正トークンやサイズ・セル数不整合などのエラー文字列を表示する

## テストプレイモード

- プレイヤー視点で問題を解く
- 初期表示では正解盤面は見えない
- 行・列ヒントだけを表示する
- 任意のタイミングで編集モードへ戻れる
- クリア後に編集盤面とプレイ結果を比較表示できる設計を許容する
- プレイ開始時は編集盤面からプレイヤー盤面を空状態で初期化する
- プレイヤー入力ごとに自動でクリア判定を行い、正解した瞬間にクリア演出と完了表示を出す
- 入力 UI は `Fill` / `Mark` のトグルを用いる
- プレイヤー盤面の 3 状態は以下で扱う
  - `unknown`: まだ何も入力していない
  - `filled`: 黒マスとして確定入力した
  - `marked`: 白マスの目印として付けたバツ印
- クリア判定は `filled` の一致のみで行う
- `unknown` と `marked` はクリア判定の対象外とする

# ルール

- 対象はモノクロのノノグラムのみとする
- 行・列ヒントは黒マスの連続長を左から右、上から下の順で算出する
- 空行または空列は `0` 表記で統一する
- 問題として成立する最低条件
  - 少なくとも 1 つの黒マスが存在する
  - 解が一意である
  - 論理のみで解ける設定を目標とする
- 難易度は、解くのに必要になった最も重い推論手法で段階化する（回数・スコア・盤面サイズには依存しない。[spec/solver.md](spec/solver.md)）
- テストプレイ開始は、解なしや非一意解でも警告表示の上で許可する
- テストプレイではプレイヤーの `filled` 入力が正解盤面の `filled` と一致した時点でクリアとする
- コピーと保存は盤面状態（解なし・非一意解を含む）に関係なく許可する。ただし解析中（pending）は、解析が終わるまでコピーできない（PBM のコメントを盤面と一致させるため。[非同期の解析](spec/analysis-async.md)）

# MVP 範囲

- 長方形のモノクロ盤面を編集できる
- 盤面から行・列ヒントを自動生成できる

# 技術要件

- Phaser と Vite を使ったブラウザゲームとして実装する
- 実装言語は既存構成に合わせて TypeScript を使う
- 単一 Scene 内で `edit` / `play` モードを分離し、解析ロジックはコアモジュールとして切り出す
- 盤面データ、ヒント生成、ソルバー、難易度判定は描画から切り離した純粋関数寄りの設計にする
- クリップボードコピーは PBM テキストをブラウザ API で扱い、失敗時は UI にエラーを表示する
- インポートは貼り付けテキスト入力と将来のクリップボード貼り付けイベントの両対応を見据える
- 難易度判定はソルバーの推論ログをもとに計算できる形にする
- 解析ロジックは Phaser 非依存モジュールとして実装し、Vitest で単体テストできる構成にする
- 盤面状態は `edit` / `play` を基本に管理し、解析情報は別データとして保持する
- 編集・テストプレイの盤面操作（クリック 1 マスの切り替え、線分ドラッグの適用、ドラッグの軸と範囲の決定）は、Phaser 非依存の純粋なモジュール（`src/game/core/editOps.ts`）にする。盤面の配列を直接書き換え、変えたマス数を返す。Scene は、入力の取得・タップかドラッグかの判定（別のセルに入ったかどうか）・描画・手数の加算・クリア判定の呼び出しだけを受け持つ
- ソルバーは手筋ルールの追加と順序調整がしやすい構造にする
- ESLint エラー 0、Vitest カバレッジ 90% 以上を維持する
- ビルド成果物は静的ホスティングで動作すること

# テスト観点

- ヒント生成
  - 黒マス連続数が正しく算出される
  - 空行、空列、全黒行、交互配置などの境界ケースを扱える
- 盤面シリアライズ: [spec/pbm.md](spec/pbm.md) の「テスト観点」
- 一意解判定
  - 一意解あり、複数解、解なしを区別できる
- 論理解可否判定・難易度判定: [spec/solver.md](spec/solver.md) の「テスト観点」
- テストプレイ
  - 正解した瞬間に自動でクリア判定になる
  - クリア時に完了表示が出る
  - 未完成盤面や誤入力をクリア扱いしない
- 盤面操作（`editOps`。期待値は「操作仕様」の規則から手で出す）
  - 範囲の決定: 横の差と縦の差が等しいと水平になる。縦の差のほうが大きいと垂直になる。軸が決まると、もう一方の座標は開始セルに固定される。軸が決まる前（現在セルが開始セルと同じ）の範囲は開始セル 1 つ。一度決めた軸は、現在セルが動いても変わらない（水平で始めて縦に動かしても、範囲は水平のまま）
  - 編集のクリック: 白→黒、黒→白で、変えたマス数は 1
  - 編集のドラッグ: 白が混在する線分は白だけが黒になり、変えたマス数は白の数。すべて黒の線分はすべて白になり、変えたマス数は線分の長さ。すべて白の線分はすべて黒になる。1 マスの線分も同様
  - テストプレイのクリック: `Fill` で `unknown`→`filled`、`Mark` で `unknown`→`marked`、`filled` / `marked` はどちらのモードでも `unknown` に戻る。変えたマス数は 1
  - テストプレイのドラッグ: `unknown` を含む線分は `unknown` だけが対象の状態になり、数は `unknown` の数。`Fill` ですべて `filled`、`Mark` ですべて `marked` の線分は、すべて `unknown` に戻り、数は線分の長さ。`filled` と `marked` が混在し `unknown` が無い線分、`Fill` ですべて `marked`、`Mark` ですべて `filled` の線分は、何も変わらず数は 0
  - テストプレイの 1 マス線分のドラッグ（別のセルに出てから開始セルに戻って離した場合）: `Fill` で `filled` のマスは `unknown` に戻り数 1、`Fill` で `marked` のマスは変わらず数 0（クリックなら `unknown` に戻って数 1 になる点が違う）。`Mark` で `marked` のマスは `unknown` に戻り数 1、`Mark` で `filled` のマスは変わらず数 0
  - 操作は盤面の配列を書き換え、範囲の外のマスは変わらない
- UI 操作
  - 編集からテストプレイへ遷移できる
  - コピー成功と失敗の表示が切り替わる
  - インポート成功と失敗の表示が切り替わる
  - モバイルで `編集` / `情報` / `入出力` タブ切替ができる

4. 難易度ランク算出と解析結果表示を実装する
5. テストプレイモードを実装する
6. クリップボードコピーと最終的な UI 調整を行う

# 完了条件

- 編集モードでモノクロ盤面を作成できる
- 作成した盤面からヒントが自動生成される
- 論理だけで解けるかどうかを画面上で確認できる
- 難易度判定結果（ランクと最も重い手筋）を画面上で確認できる
- 問題データをクリップボードへコピーできる（解析中を除く。解析が終われば、盤面と一致する解析結果つきでコピーできる）
- テストプレイモードで作成済み問題を実際に遊べる
- 問題データの書き出しと読み込み: [spec/pbm.md](spec/pbm.md) の「完了条件」
- 解なし、多重解、論理未解決を区別して表示できる
- テストプレイで正解した瞬間に自動クリア判定とクリア表示が行われる
- 編集・テストプレイのクリックとドラッグの結果（切り替えの規則、ドラッグの軸と範囲、変えたマス数と手数の数え方）が、「操作仕様」の規則のとおりである。盤面操作の純粋なモジュールの単体テストで確かめる
- クリア判定（`filled` の一致のみ）、PBM `P1` の入出力、解析（Web Worker）、モバイルのレイアウトが、盤面操作の切り出しの前後で変わらない
- 難易度ランクの定義（最も重い手筋で決める）を変えても、編集の操作、PBM `P1` の形式、テストプレイの判定、`solvable` / `unique` / `logical` / `remainingCells` / 手筋の回数 / スコアの値は変わらない（[spec/solver.md](spec/solver.md) の「完了条件」）
- `npm run lint`、`npm run test`、`npm run test:coverage`、`npm run build` を通過する
- 主要ロジックのカバレッジが 90% 以上である

# パラメータ表

ゲーム性に関わる数値は、盤面のサイズ範囲と、ドラッグの軸の決め方だけである（難易度の重みなどは [spec/solver.md](spec/solver.md)、解析のタイムアウトなどは [spec/analysis-async.md](spec/analysis-async.md) のパラメータ表）。

| 名前 | 初期値 | 意味 |
|---|---|---|
| 盤面サイズの最小 | 5 x 5 | 幅・高さの下限 |
| 盤面サイズの初期値 | 10 x 10 | 起動時のサイズ |
| 盤面サイズの最大 | 25 x 25 | 幅・高さの上限 |
| プリセット | 5, 7, 10, 12, 15, 18, 20, 22, 25（`1`〜`9` キー） | 正方形のサイズ |
| ドラッグの軸が同じ差のとき | 水平 | 横の差と縦の差の絶対値が等しいときの軸 |
