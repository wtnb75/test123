# digdle 拡張候補（backlog）

公開済みの digdle（Wordle 風の素数当てゲーム）に、次に足せるものの候補を、上から順に並べたものです。上のカードが「次の候補」です。仕様（`spec.md`）ではありません。`game-extend` が上から順に 1 件を選び、目的・コアループへの効き方・変えないものを固めてから、仕様に書きます。

- 規模: S = 1 画面と数値の追加程度、M = 複数の画面や仕組みにまたがる追加、L = 大きいので、`game-extend` で 1 PR 分に切り出してから採用する。
- 1 つのカードは 1 つの目的にする（1 変更 1 目的）。
- 外部の画像・音のアセットは、足してよいかをユーザーに確認してからにする。
- 数値だけの再調整（桁数ごとの試行回数）は、カードにせず `game-balance` で行う。測定（下記）では、2〜3 桁は運の要素が大きく（勝率 56%・69%）、4 桁以上は余裕がある（97%・100%・100%）。
- 測定の条件: 「これまでのヒントと矛盾しない素数だけを推測する」ボット。各桁数 200 ゲーム（6 桁は 80 ゲーム）、答えは乱数。人間は全素数を列挙できないので、実際の勝率はこれより低い。

### 素数でない入力の扱いを見直す（回数の消費・上限）（`prime-probe`）

- 狙い: 素数でない入力は、試行回数を消費せずに拒否される。素数かどうかを自分で判定できなくても、入力して確かめるだけで通る（素数の知識が要らない）。根拠: `spec`「ルール」（不正入力は試行回数を消費しない）
- 何を足すか: 素数でない入力にも、制限を付ける。案: (A) 1 ラウンドの拒否に上限（例: 3 回）を付け、超えたら試行回数を 1 つ消費する。(B) 素数でない入力も 1 回として数える。(C) いまのまま（意図した設計とする）。
- コアループへの効き方: 深める — 「素数を知っている」ことに意味が生まれる。
- 種別: gameplay
- 規模: S
- 出どころ: spec 分析
- メモ: ユーザーの方針が要る（A / B / C）。ハードモードの違反（拒否）は別に考える。通知の文言と、数の表示の変更を伴う。

### 判定の色が順にめくれる演出を足す（`reveal-effect`）

- 狙い: 判定の色が、一瞬で全桁に付く。Wordle のように 1 桁ずつ明かされる手応えが無い。根拠: `spec`「非 MVP 範囲」（演出強化）
- 何を足すか: Enter の判定後、各桁の色が左から順にめくれる（0.1 秒ずつ程度）。めくれている間も、入力はロックして問題ない（短い）。
- コアループへの効き方: 広げない — 演出。ルールは変えない。
- 種別: presentation-only
- 規模: S
- 出どころ: spec 分析
- メモ: 入力を妨げない長さにする（`spec` の 0.3 秒以下の目安）。色だけで区別しない（既存の表示を保つ）。

### 効果音を足す（入力・判定・クリア・ゲームオーバー）（`sound`）

- 狙い: BGM・効果音は非 MVP のまま。判定の結果・勝敗の手応えが、音で補える。根拠: `spec`「非 MVP 範囲」（サウンド）
- 何を足すか: キー入力・判定（green / yellow / gray）・クリア・ゲームオーバー・不正入力の効果音を、Web Audio で作って鳴らす（外部の音声ファイルは使わない）。ミュートの切り替えを付ける。
- コアループへの効き方: 広げない — 演出の仕上げ。
- 種別: presentation-only
- 規模: S〜M
- 出どころ: spec 分析
- メモ: 最初のタップの後に鳴らす（自動再生の制限）。外部の音声ファイルを使う場合は、足してよいかを確認する。
