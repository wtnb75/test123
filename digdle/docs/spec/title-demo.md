# Title のデモ

`docs/spec.md` の拡張。`Title` の空いた場所（桁数ボタンの下、または右の列）で、ボットが 4 桁の素数を推理する様子を流す。

## 概要

`Title` に、4 列 × 5 行の盤面を置き、ボットが素数を当てに行く様子（1 手ごとに、数字が 1 桁ずつ入り、4 桁そろうと色ヒント green / yellow / gray が付く）を見せる。正解するか 5 回使い切ったら 1 ラウンド終了、2 ラウンドで 1 走りとし、走りの終わりは透明にして最初から繰り返す。「推測 → 色ヒントを読む → 次の推測」というコアループを、開始前に見せるだけで、ルール・試行回数・難易度は変えない。`Title` の操作（モード切替・桁数ボタン・キー `2`〜`6`・`🏠`）は変えない。このデモを置くために、`Title` の副題とヒントの文字は無くし、ボタンを小さくして、画面が低いときは 2 列の配置にする（`docs/spec.md` の「Title」）。

## 操作仕様

デモは操作を受け付けない（プレイヤーの入力では動かず、デモの領域のタップ・クリックは何も起こさない）。`Title` の操作（モード切替、桁数ボタン、キー `2`〜`6`、`🏠`）は `docs/spec.md` のとおりで、デモの再生中・透明化中も変わらずに働く。

## 画面・Scene構成

### レイアウト

画面幅を W、高さを H とする（Scale.RESIZE のため、W・H は実行時の値）。`Title` の要素の位置は `docs/spec.md` の「Title」の配置（縦並び / 2 列）で決まる。この節は、どちらの配置にするかと、デモの盤面の大きさ・位置を決める。

- **盤面**: `cols` = `demoDigits`（4）、`rows` = `demoDigits` 桁の試行回数（`docs/spec.md` の「試行回数」で 5）。セルの一辺 `cell`、間隔 `demoCellGap`。盤面の幅 = `cols × cell + (cols − 1) × demoCellGap`、高さ = `rows × cell + (rows − 1) × demoCellGap`。
- **縦並びで入るか**: `cell` = `min(demoCellMax, floor((H − 208 − demoMargin − (rows − 1) × demoCellGap) / rows))`（208 は桁数ボタンの下端 192 + 間隔 16。`demoMargin` は下端の余白）。`cell` が `demoCellMin` 以上なら、縦並びでデモを置く。盤面の左端 = `floor((W − 盤面の幅) / 2)`、上端 = `y0 + 208`（`y0` は `docs/spec.md` の式。全体の高さ = `208 + 盤面の高さ + demoMargin`）。
- **2 列で入るか**（縦並びで入らないとき）: `colW` = `floor(W / 2) − 16`、`cell` = `min(demoCellMax, floor((H − 2 × demoMargin − (rows − 1) × demoCellGap) / rows))`。桁数ボタンの幅 `floor((colW − 48) / 5)` が `titleDigitMinW`（40 px）以上、かつ `cell` が `demoCellMin` 以上なら、2 列でデモを置く。盤面の左端 = `floor(W × 3 / 4 − 盤面の幅 / 2)`、上端 = `floor((H − 盤面の高さ) / 2)`。
- **どちらも入らない**: デモを描かない。高さ H が 192 以上、または幅 W が 504 未満なら縦並び（`y0` の全体の高さは 208。H が低いと下が切れる）、H が 192 未満で W が 504 以上なら 2 列（左の列だけ。右の列は空）。
- 手計算の例（桁数ボタンの幅 `digitW`、名前の中心 y、モード切替の上端 y、桁数ボタンの上端 y、盤面の左上）:

  | 画面（W × H） | 配置 | `cell` | 盤面（幅 × 高さ） | `digitW` | 名前 y / モード上端 / 桁数上端 | 盤面の左上 |
  |---|---|---|---|---|---|---|
  | 375 × 550（iPhone SE 縦） | 縦並び（`y0` = 27） | 44 | 194 × 244 | 64 | 71 / 111 / 167 | (90, 235) |
  | 390 × 844 | 縦並び（`y0` = 125） | 44 | 194 × 244 | 64 | 169 / 209 / 265 | (98, 333) |
  | 1280 × 720 | 縦並び（`y0` = 84） | 44 | 194 × 244 | 64 | 128 / 168 / 224 | (543, 292) |
  | 1280 × 388 | 縦並び（`y0` = 0） | 28 | 130 × 164 | 64 | 44 / 84 / 140 | (575, 208) |
  | 1280 × 387 | 2 列（縦並びは `cell` 27） | 44 | 194 × 244 | 64 | 130 / 170 / 226（x 中心 320） | (863, 71) |
  | 667 × 310（iPhone SE 横を想定） | 2 列 | 44 | 194 × 244 | 53 | 92 / 132 / 188（x 中心 166） | (403, 33) |
  | 360 × 300 | デモなし（縦並び。`y0` = 30） | — | — | 62 | 74 / 114 / 170 | — |
  | 667 × 190 | デモなし（2 列。H < 192） | — | — | 53 | 32 / 72 / 128（x 中心 166） | — |

  （2 列の `digitW` は `colW` からの値: 667 × 310 は `colW` = 317 で `floor((317 − 48) / 5)` = 53、1280 × 387 は 624 で 64 に頭打ち。縦並びの `digitW` は `min(64, floor((W − 48) / 5))`。360 × 300 は、2 列にしても桁数ボタンの幅が `floor((164 − 48) / 5)` = 23 で 40 に届かず、縦並びでも `cell` が 10 のため、デモなし（`digitW` = 62）。667 × 190 は 2 列の `cell` が 26 で 28 に届かないためデモなし（H < 192 なので、桁数ボタンが切れる縦並びではなく 2 列。`top0` = floor(20 / 2) = 10）。）

- **セルの見た目**（`Game` の盤面と同じ）: 塗り `0x1f2937`、枠 2 px `0x4b5563`、数字は等幅（monospace）で `max(20, floor(cell × 0.5))` px、白（`#ffffff`）、セルの中央。ヒントが付いた行のセルの塗りは green `0x16a34a` / yellow `0xf59e0b` / gray `0x6b7280`（`Game` のヒントの色と同じ）。色が付く前（入力中）のセルは塗りが空のセルと同じ（`0x1f2937`）で、入った数字だけが見える。まだ推測されていない行は、空のセル（数字なし）。
- 描画順（奥から）: 背景 → `Title` の要素 → デモの盤面。デモは自分の場所だけに描き、他の要素と重ならない。
- リサイズ/回転では、配置（縦並び / 2 列 / デモなし）を選び直し、要素とデモの位置・大きさを再計算して、デモの今の状態（進み具合）から描き直す（走りは作り直さない）。デモなしになったら描かない（進行は続ける。非表示は描画だけに影響し、経過時間は進む）。デモを置けるようになったら、その時点の状態から再び描く。

### 状態

デモの進行は、共有パッケージ `title-demo` の `DemoDirector`（README が仕様）。このゲームでの対応:

| `DemoDirector` の要素 | このゲームでの内容 |
|---|---|
| 状態 `S` | 正解の 4 桁の素数、これまでの推測の履歴（推測と各桁の色）、まだ矛盾しない候補、ラウンドの結果（`playing` / `won` / `lost`）、注入できる乱数 |
| ラウンド | 1 つの素数を、当てるか 5 回使い切るまで推理すること（`rounds` = `demoRounds`） |
| `start()` | 新しい正解（4 桁の素数からランダム）と空の履歴で始める。走りの作り直しにも使う |
| `plan(state)` | 「ボットの推測」で決めた推測 1 つの手順（長さ 1） |
| `play(state, action)` | 推測に `Game` と同じ判定で色を付け、桁の間隔（ランダム。「行の見せ方」）とともに履歴に足す。全桁 green または 5 回目なら `roundDone: true` |
| `advance(state)` | ラウンドが終わったあと、新しい正解（直前の正解と異なる素数）と空の履歴にする |
| `timing` | `stepMs` は使われない（1 ラウンドが複数の手順に分かれるため）。値は `demoWaitMs` と同じにする。`waitMs` = `demoWaitMs`、`fadeMs` = `demoFadeMs` |

- 1 つの推測を `plan` の長さ 1 の手順として返すので、推測の時刻から次の推測の時刻までは `waitMs`（その間に行の入力と色の表示が入る。下の「行の見せ方」）になる（`DemoDirector` は、手順が尽きて `roundDone` でないとき、新しい `waiting` に入って手順を取り直す）。ラウンドが終わると、終わりの推測から `waitMs` 経ったあと `advance` で盤面を空にし、さらに `waitMs` 待って最初の推測に入る。`demoRounds` に達したラウンドの後は、終わりの推測から `waitMs` 経ったあと `fade-out`（透明になり、`fade-in` で新しい走りが現れる）。
- `DemoDirector` は `Title` の `create` のたびに新しく作る（時刻 0 から。`Game` から `Title` に戻るたびに、新しい走りが始まる）。時間は、`Title` に入ってからの経過時間を `update` の経過時間（delta）で自前に数える（`delayedCall` は使わない）。1 回の `update` で進めるイベントは最大 1 つ。
- 行の見せ方（推測を受けた `action` イベントの時刻を T、経過時間を `e` = 今 − T とする。T は、その `action` を返した `tick` に渡した時刻（`Title` の経過時間。期限の予定時刻ではない）。`e` < 0 は 0 桁（まだ現れない）として扱う。状態（履歴）には、推測と色が T の時点で入る。表示だけをずらす）:
  - 1 桁ずつ入る間隔は**固定ではなく、ランダム**。`play` が推測を履歴に足すとき、同じ乱数 `rng` から、桁の間隔 `d_1 … d_(demoDigits − 1)`（4 桁なら 3 つ）を、この順に、推測を選んだあとに引く。`d_k` = `demoDigitMinMs + floor(rng() × (demoDigitMaxMs − demoDigitMinMs + 1))`（`demoDigitMinMs` 以上 `demoDigitMaxMs` 以下の整数 ms）。入る時刻（推測の時刻からの ms）は `typeAt[0] = 0`、`typeAt[k] = typeAt[k − 1] + d_k`。色が付く時刻は `judgeAt = typeAt[demoDigits − 1] + demoJudgeMs`。この `typeAt` と `judgeAt` は、推測の履歴の一部として状態に持つ。
  - `k` 桁目（0 始まり）は `e ≥ typeAt[k]` で現れる（1 桁目は `e = 0` で現れる）。入った数字は、色が付くまでセルの塗りは空のままで、数字だけが見える。
  - 色は `e ≥ judgeAt` で、行の全桁が同時に付く。
  - 進み具合は、`e` と履歴の `typeAt`・`judgeAt` だけで決まる（リサイズなどの描き直し、非表示から表示に戻ったときも、今の `e` から描く）。`e` が `judgeAt` を過ぎていれば、最初から色が付いた行として描く。
  - `demoWaitMs` は、`judgeAt` の最大値 `(demoDigits − 1) × demoDigitMaxMs + demoJudgeMs`（初期値で 1500 ms）より長くする（初期値 1800 ms）。次のイベント（次の推測、`advance`、`fade-out`）の時点では、前の行の表示は完了している。
  - ラウンドの終わりの行（全桁 green または 5 回目）も同じ見せ方。`advance` で盤面を空にするまでの間（`demoWaitMs − judgeAt`。300〜1050 ms）、色が付いた行を見せる。
- 開始の門: 桁数ボタンまたはキー `2`〜`6` の開始が受け付けられたら（`StartGate` または既存の `starting` の旗。同じフレームの 2 つ目の開始は無視する）、以後 `tick` を呼ばず、再生中の演出を捨てる。`Scene` を離れるときも同じ。
- 再生中の演出（行の現れ方など）は、`advance`・`fade-out`・`fade-in` のイベントで捨て、盤面を状態から描き直す（古い行が残らない）。
- 走りの終わりの透明化は `DemoDirector.opacity` を使い、デモの盤面全体にかける（`Title` の他の要素は透明にしない）。

### ボットの推測

乱数 `rng`（注入できる）を使う。

1. 最初の推測: `demoDigits` 桁の素数（先頭が 0 でない）の全体から、一様にランダムに 1 つ選ぶ。
2. 2 回目以降の推測: これまでの全ての（推測、色）と矛盾しない素数のうち、ランダムに 1 つ選ぶ。「矛盾しない」は、その素数を正解と仮定して、`Game` と同じ判定（Wordle と同じ重複数字の扱い。`docs/spec.md` のルール。実装の `judgeGuess`）を行ったとき、全ての過去の推測について、実際に付いた色と一致すること。
3. 推測した素数は、正解でなければ必ず次の候補から外れる（自分自身を正解と仮定すると全桁 green になり、実際の色（全桁 green ではない）と一致しないため）。したがって、同じ推測を繰り返さない。
4. ラウンドは、全桁 green（正解）か、`demoDigits` 桁の試行回数（5 回）を使い切ったら終わる。
5. ハードモードの制約（確定した桁の強制）は使わない。デモは常にノーマルモードの扱いで、`Title` で選んでいるモードにも依らない。

## ルール

デモは `Game` のルール・試行回数・得点に影響しない。`Title` から `Game` を始めるときに渡すもの（`{ digits, mode }`）にも、デモは影響しない。デモの状態は、`localStorage` など、いかなる保存にも書かない（デモは何も読み書きしない。`Title` がデイリーの済みの印のために保存を読むのは、デモとは別。[日替わりのお題](daily.md)）。

## パラメータ表

| 名前 | 初期値 | 意味 |
|---|---|---|

| `demoRounds` | 2 | 1 走りのラウンド数 |

| `demoMargin` | 16 px | 縦並びでのデモと画面の下端の間の余白（桁数ボタンとデモの間の 16 は、上端 208 = 192 + 16 に含まれる）。2 列では、デモの上下の最小の余白 |

| `demoCellMin` | 28 px | これ未満になる配置ではデモを置かない |

| `titleDigitMinW` | 40 px | 2 列にするときの、桁数ボタンの幅の下限 |
| セルの見た目 | 塗り `0x1f2937`、枠 2 px `0x4b5563`、数字 monospace `max(20, floor(cell × 0.5))` px・`#ffffff`、ヒントの色は `Game` と同じ | 「レイアウト」のとおり |

## テスト観点

- 配置（純関数。手計算の値）: 上の表の 8 つの画面（座標・`cell`・配置の種類）。境界（幅 528 以上の画面）: 高さ 388（縦並び・`cell` 28）と 387（`cell` 27 で 2 列）、H = 191（W が 504 以上なら 2 列）と 192（縦並び）の切り替え、W = 503 と 504（H = 180。縦並びと 2 列）の切り替え（どちらもデモなし）、桁数ボタンの幅 `floor((colW − 48) / 5)` の 39 と 40、2 列の `cell` が 27 と 28 になる高さ（H = 195 / 196）、`y0` の `floor` が割り切れない場合（例: 375 × 551 の `y0` = floor(83 / 3) = 27）。
- ボットの推測（乱数を注入）: 最初の推測は 4 桁の素数。2 回目以降の推測は、過去の全ての（推測、色）と矛盾しない素数で、同じ推測を繰り返さない。全ての推測は 4 桁の素数。ラウンドは 5 回以内に終わる（全桁 green か 5 回目）。正解が候補から外れない。
- 多数のシードでの性質テスト（空振りの検査つき）: 正解したラウンド数と、5 回使い切ったラウンド数の両方を数え、正解したラウンドが 0 でないこと。全ラウンドで上の性質が成り立つ。
- 進行（手計算。各ラウンドが 2 回目の推測で終わる（正解する）場合、`demoWaitMs` 1800・`demoFadeMs` 400・`demoRounds` 2、時刻は `DemoDirector` の構築時を 0 とする）:

  | t (ms) | 起きること |
  |---|---|
  | 1800 | 1 回目の推測（ラウンド 1。数字が 1 桁ずつ入る。色が付くのは 1800 + `judgeAt`。`judgeAt` は 3 × 150 + 300 = 750 〜 3 × 400 + 300 = 1500） |
  | 3600 | 2 回目の推測（正解、`roundDone`。色が付くのは 3600 + `judgeAt`） |
  | 5400 | `advance`（盤面が空になり、新しい正解） |
  | 7200 | ラウンド 2 の 1 回目の推測 |
  | 9000 | 2 回目の推測（正解、`roundDone`） |
  | 10800 | `fade-out`（透明度 1 → 0 が始まる。11000 で 0.5） |
  | 11200 | `fade-in`（履歴が空・新しい正解、透明度 0） |
  | 11600 | 待ちが終わる（`waiting`。ラウンド数 0） |
  | 13400 | 新しい走りの 1 回目の推測 |
- 行の見せ方（純関数。桁数 4、`demoJudgeMs` 300）:
  - 桁の間隔が（200, 150, 400）のとき、`typeAt` = (0, 200, 350, 750)、`judgeAt` = 1050。`e` = −1 → 0 桁、0 → 1 桁・色なし、199 → 1 桁、200 → 2 桁、349 → 2 桁、350 → 3 桁、749 → 3 桁、750 → 4 桁・色なし、1049 → 4 桁・色なし、1050 → 4 桁・色あり、それ以後は同じ。
  - 桁の間隔の乱数: `rng` が常に 0 を返すと全ての間隔が 150（`judgeAt` = 750）、常に 0.999… を返すと全ての間隔が 400（`judgeAt` = 1500）。桁の間隔は、推測を選んだあと、`play` の中で 3 つ引く。推測や正解を選ぶときに乱数を何回引くかは実装裁量で、テストは定数を返す `rng` か同じ種を使う（同じ種なら同じ動きになる）。どの `judgeAt` も `demoWaitMs` より小さい（多数のシードで確かめる）。
- 作り直しで正解が直前の正解と異なる（ラウンド間の `advance`）。
- 5 回使い切る場合: 正解ではない推測を 4 回続けた状態で、5 回目の推測が `roundDone: true`・結果 `lost` になり、続く `advance` で次のラウンドが空の履歴・新しい正解で始まる（乱数を固定して作る。多数のシードの性質テストでこの経路に当たらなくても検査できる）。
- リサイズ（Scene の動作。QA で確認する）: 走りの途中で幅・高さを変えて配置が縦並び ↔ 2 列 ↔ デモなしと変わっても、デモの行数・ラウンド数は変わらず（作り直されず）、デモが置ける配置に戻ると今の進み具合から描かれる。
- 入力（Scene の動作。QA で確認する）: デモの再生中・透明化中でも、キー `2`〜`6` で開始し、`1`・`7`・`Enter` では開始しない。選択中のモードが `Game` に渡る。デモの領域のタップは何も起こさない。デモは `localStorage` に触れない。デモが置けない画面（360 × 300 など）では、要素は縦並びで、デモは描かれない。
- 回帰: `Title` の操作（ボタン・キー・モード切替・`🏠`）と `Game` は変わらない。既存の判定・検証・ハードモード・ラウンド生成のテストは変更しない（`Title` の配置のテストは、この配置に合わせて更新する）。

## 完了条件

- `Title` に、4 列 × 5 行の盤面が表示され（縦並びでは桁数ボタンの下、2 列では右の列）、ボットが 1 行ずつ、数字を 1 桁ずつ（間隔はランダム）入れて、4 桁そろうと色ヒントが付く（スクリーンショットの連続で、390 × 844・375 × 550・1280 × 720・667 × 310 で確認する。入力中の行は、数字が入るが塗りは空のまま）。
- 正解するか 5 回使い切ると結果が見え、次のラウンドで盤面が空になり、2 ラウンドのあと透明になって最初から繰り返す。
- デモを置けない画面（360 × 300 など）では、デモが描かれず、`Title` の要素は縦並びで全て見える（はみ出さない高さなら）。
- `Title` の副題とヒントの文字は無い。名前・モード切替・桁数ボタン・`🏠` が、「パラメータ表」の大きさ・位置で並ぶ。キー `2`〜`6` で開始し、`1`・`7`・`Enter` では開始しない。選択中のモードを `Game` に渡す。
- デモの再生中・透明化中でも、桁数ボタン・キー・モード切替・`🏠` が働く。
- `Game` のルール・試行回数・ハードモード・判定・検証順序・同じ N・同じモードのリプレイ、`Game` の見た目・操作は変わらない。
- リサイズ/回転（W が 528 以上のとき、高さ 388 / 387 の縦並び ↔ 2 列の境界）で `Title` が崩れず、デモが今の状態から描き直される（走りは作り直されない。配置が縦並び / 2 列 / デモなしに変わっても、進み具合が保たれる）。
- デモは `localStorage` を読み書きしない。
- `npm run lint` / `npm run test` / `npm run test:coverage` / `npm run build` が成功し、既存のロジックのテスト（判定・検証・ハードモード・ラウンド生成）は変更されない。

## 実装裁量

- デモの純粋なロジック（状態・ボットの推測・配置の計算）をどのファイルに置くか、関数の名前と分け方
- 数字が入るとき・色が付くときの細かい動き（現れ方、色が変わる間の短い動きなど。各 0.15 秒以内にし、入力を妨げない。時刻の進み具合は「行の見せ方」のとおり。桁の間隔の乱数の引き方は仕様どおり）
- 盤面を `Title` の既存の要素と同じ Scene の中にどう持つか（オブジェクトの作り方・破棄の方法）
- 注入する乱数の種（走りごとに変える。`createRng` を使ってよい）
- `Game` の盤面とデモで共有するセルの色・枠の定数の置き場所（`Game` の見た目は変えない）
