# 日替わりのお題（デイリー）

`docs/spec.md` の拡張。Title のモードに「デイリー」を足す。端末のローカル日付と桁数から決まる素数を、1 日 1 回だけ遊ぶ。同じ日付・同じ桁数なら、誰が遊んでもお題は同じになる。ノーマル / ハードの遊びは変えない。

## 概要

- 何を足すか: Title のモード切替に「デイリー」（ノーマル / ハード / デイリーの 3 択）。デイリーを選んで桁数ボタン（またはキー `2`〜`6`）を押すと、その日のその桁数のお題が始まる。ルール・試行回数・判定はノーマルと同じ。
- コアループへの効き方: 広げる。「1 日 1 回の挑戦」という軸が加わる。既存の「推測 → 色ヒントを読む → 次の推測」は変えない。
- 1 日 1 回: 終えた桁数のお題はやり直せない（結果を見るだけ）。途中で抜けても、入力済みの推測を保存してあるので、続きから再開する（抜け直して見直すことはできない）。
- 保存はこの端末の `localStorage` だけ（サーバーは使わない）。

## 操作仕様

- Title:
  - モード切替が 3 ボタンになる（左からノーマル、ハード、デイリー）。タップで切り替える。選択中のモードは枠の色で強調する（デイリーは `dailyStroke`）。
  - デイリーを選んでいる間、桁数ボタンまたはキー `2`〜`6` で、その桁数のデイリーを始める（Game を `{ digits, mode: 'daily' }` で開始）。
  - Title は、キーの自動リピート（`event.repeat` が真の keydown）では開始しない（結果表示から戻った直後に、押し続けたキーで次のゲームが始まらないため。全モード共通）。
  - デイリーを選んでいる間、その日に終えた桁数のボタンの文字に印が付く（「画面・Scene構成」）。印の付いたボタンも、通常どおり押せる（押すと保存した盤面の読み取り専用表示になる）。
- Game（デイリー）:
  - プレイ中の操作は、ノーマルと同じ（数字キー・Backspace・Enter・仮想キー・`◀️`・`🏠`）。
  - 結果表示中（その場で終えた直後も、終えた桁数を開き直したときも）: どのキー（数字・Enter・Backspace を含む）または画面タップでも、Title へ戻る（次のラウンドは始まらない。そのキー・タップ自体は入力として処理しない）。キーの自動リピート（`event.repeat` が真の keydown）は Title へ戻る入力にしない（最後の推測の Enter や、Title で押した桁数キーを押し続けても、結果が見えないまま Title へ戻らない。リピートでない keydown は戻る入力）。「桁数を選び直す」も Title へ戻る。結果表示中の `🏠` / `◀️` の位置のタップは画面タップとして扱い、Title へ戻る（`../` へは遷移しない）。Title へ戻るときの `{ mode, candidates }` は `mode` が `'daily'`（デイリーを選択中のまま Title が開く）、`candidates` は受け取った値のまま（💡 の状態は保つ）。この戻り方は、結果表示中の任意のキー・タップ（「桁数を選び直す」を含む）でも同じ。

## 画面・Scene構成

### Scene 間の受け渡し

| 受け渡し | 内容 |
|---|---|
| Title → Game | `{ digits: 2〜6, mode: 'normal' \| 'hard' \| 'daily', candidates: boolean }`（`docs/spec.md` の受け渡しを、`mode` に `'daily'` を足して拡張する。`candidates` は 💡 の状態） |
| Game → Title | `{ mode: 'normal' \| 'hard' \| 'daily', candidates: boolean }`。Title は受け取った mode を選択中として強調し、candidates を 💡 の状態にする。`'normal'` `'hard'` `'daily'` 以外（無い・不正）は `normal`。無い `candidates` は `false` |

### Title のモード切替とデイリーの印

- モード行は 3 つのモードボタンと 💡（候補数）の 4 つ。行の幅・左端・ボタンの幅は `docs/spec.md` の「配置」の式のとおり（行の幅 `min(302, 列の幅)`、💡 は 44 × 44 px で右端、モードは残りの幅を 3 等分して最大 78・下限 48 px）。行の中心 x は従来と同じ（縦並び `floor(W / 2)`、2 列の左の列 `floor(W / 4)`）。上端 y は従来のモード切替の上端と同じ。Title の縦並び / 2 列の境界、`y0`・`top0`、名前・桁数ボタン・デモの座標は変わらない。
- ラベルの文字は `modeButton.fontSize`（16 px）。文言（ja / en。言語の判定は他と同じ）:

  | モード | 日本語 | 英語 |
  |---|---|---|
  | デイリー | デイリー | Daily |

- 印: デイリー選択中だけ、その日に終えた桁数 N のボタンのラベルを、クリアなら `N✓`、失敗（試行回数を使い切った）なら `N✗` にする（例: `3✓`）。途中の桁数・まだの桁数は `N` のまま（途中の印は付けない）。ノーマル / ハード選択中は印を付けない。印の文字の大きさ・色は桁数ボタンのラベルと同じ。
- 印は、Title を作るとき（Scene の開始、リサイズでの再レイアウト）とモードを切り替えたときに、保存（後述）を読んで決める。「その日」は、そのときの端末のローカル日付。

### Game（デイリー）

- 開始: その日付・その桁数のお題（「お題の決め方」）で 1 ラウンドを作り、保存された推測があれば先頭から順に再生して盤面に戻す（色ヒント・キーボードの色も、再生した結果）。再生しきって `won` / `lost` なら、その状態で結果表示（読み取り専用）から始まる。そうでなければ `playing`（入力中）で、保存された推測の次の行から始まる。
- 試行回数・ルール・判定・通知の文言と表示時間は、ノーマルと同じ。ハードモードの制約は適用しない。
- 推測を受理するたび（試行回数を消費したとき）に、その時点の推測の履歴を保存する（結果が `won` / `lost` になった推測も保存する）。不正入力（拒否）では保存しない。
- 結果表示: 文言・見た目はこれまでの結果表示（Clear / GameOver、失敗時は正解の開示、「桁数を選び直す」）と同じ（[戦績の保存と表示](stats.md) の戦績と「戦績を消す」が加わる）。操作だけ、「操作仕様」のとおり Title へ戻る。
- ラウンドの日付: ラウンドは、開始したときのローカル日付で固定する（日付をまたいで遊び続けても、お題は変わらない。保存もそのラウンドの日付で書く）。
- 「直前と異なる正解」の規則（ノーマル / ハードのリプレイ）は、デイリーには適用しない（次のラウンドが無い）。

## ルール

### お題の決め方（全員が同じになる、決定的な式）

1. 日付キー `dateKey` = 端末のローカル日付を `YYYY-MM-DD`（月・日は 0 埋め 2 桁）にした文字列。ローカルの年・月・日（`getFullYear` / `getMonth` + 1 / `getDate`）から作る。
2. シード文字列 = `digdle-daily:` + `dateKey` + `:` + 桁数 N（例: `digdle-daily:2026-10-18:3`）。
3. `seed` = シード文字列を ASCII のバイト列として FNV-1a（32 bit。初期値 `0x811C9DC5`、素数 `0x01000193`、各バイトを XOR してから `Math.imul` 相当の 32 bit 乗算）にかけた値（符号なし 32 bit）。
4. 乱数 `r` = `createRng(seed)` の最初の値（既存の mulberry32）。
5. お題 = その桁数の素数の一覧（既存の `primeMap[N]`。昇順の文字列）の `floor(r × 一覧の長さ)` 番目。

手計算の例（外部の実装で求めた値）は「テスト観点」の表。同じ日付・桁数なら必ず同じお題、日付か桁数が違えば（ほぼ）別のお題。

### 保存

- 保存先: `localStorage` のキー `dailyStorageKey`（`digdle.daily`）。値は JSON で、1 日分だけを持つ。

  ```json
  { "date": "2026-10-18", "rounds": { "3": ["127", "163"], "5": ["60139"] } }
  ```

  `rounds` のキーは桁数（文字列）、値はその桁数で受理された推測（文字列）を入力順に並べたもの。色・結果・お題は保存しない（お題は日付と桁数から、色は判定から再現する）。
- 読み込み:
  - 保存の `date` が、読んだときのローカル日付と違えば、空として扱う（古い日の記録は使わない）。
  - JSON が壊れている、形が違う（`date` が文字列でない、`rounds` がオブジェクトでない、値が文字列の配列でない）ときは、全体を空として扱う。
  - ある桁数の推測の並びを、その日のお題で順に判定してみて、1 つでも不正（桁数が違う・素数でない）、試行回数を超える、結果が決まった後にも推測が続く、のどれかなら、その桁数だけを空として扱う（ほかの桁数は残す）。
  - 結果は、再生した並びから決める: 最後の推測が正解なら `won`、受理した数が試行回数に達して正解でなければ `lost`、どちらでもなければ途中（`playing`）。
- 書き込み: 推測を受理するたびに、その桁数の推測の並びを書く。保存の `date` がラウンドの日付と違えば、保存全体をそのラウンドの日付だけの内容に置き換える（他の桁数は、その日付に属さないので消える）。同じ日付なら、ほかの桁数は残す。
- 保存が使えない場合（`localStorage` へのアクセスが例外を投げる、容量超過、ブロック）: ゲームは止めない。読み込みは空として扱い、書き込みは黙って無視する。ただし、書いた内容はメモリにも持つ。保存が使えるあいだは `localStorage` を読む（別のタブが書いた内容も見える）。読み込みか書き込みのどちらかが一度でも失敗した後と、保存が無いときは、メモリのコピーを読む（保存できなくても、同じページの中では、再開・印・読み取り専用表示は働く。ページを開き直すと失われ、その日の再挑戦ができる）。この場合も通知は出さない。
- 「戦績」「連勝」は、この拡張の保存には持たない（別の保存。[戦績の保存と表示](stats.md)）。この保存は、再開と印のためだけ。

## テスト観点

- 日付キー（純関数。時刻を注入）: ローカルの `2026-10-18 23:59:59` → `2026-10-18`、`2026-10-19 00:00:00` → `2026-10-19`、`2026-01-01` → `2026-01-01`（月・日の 0 埋め）。
- お題の決定性（手計算の値。Python で独立に求めた FNV-1a と mulberry32 による。素数の一覧は昇順の `primeMap`）:

  | 日付 | 桁数 | シード文字列の FNV-1a（`seed`） | 一覧の長さ | 番号 | お題 |
  |---|---|---|---|---|---|
  | 2026-10-18 | 2 | 891030754 | 21 | 3 | 19 |
  | 2026-10-18 | 3 | 907808373 | 143 | 12 | 163 |
  | 2026-10-18 | 4 | 790365040 | 1061 | 583 | 5711 |
  | 2026-10-18 | 5 | 807142659 | 8363 | 4842 | 60139 |
  | 2026-10-18 | 6 | 823920278 | 68906 | 51294 | 758819 |
  | 2026-10-19 | 2 | 752045921 | 21 | 6 | 31 |
  | 2026-10-19 | 3 | 735268302 | 143 | 118 | 827 |
  | 2026-10-19 | 4 | 785601159 | 1061 | 252 | 2909 |
  | 2026-10-19 | 5 | 768823540 | 8363 | 4126 | 52433 |
  | 2026-10-19 | 6 | 819156397 | 68906 | 68422 | 993287 |
  | 2026-01-01 | 2 | 1425266298 | 21 | 9 | 43 |
  | 2026-01-01 | 3 | 1442043917 | 143 | 126 | 881 |
  | 2026-01-01 | 4 | 1324600584 | 1061 | 601 | 5857 |
  | 2026-01-01 | 5 | 1341378203 | 8363 | 912 | 18773 |
  | 2026-01-01 | 6 | 1358155822 | 68906 | 30294 | 478453 |

  同じ入力で何度呼んでも同じ。日付が違う・桁数が違うと別のお題になる（この表の範囲で）。お題は常にその桁数の素数。
- 保存の読み書き（純関数または注入できる保存先で。`localStorage` を直接使わない）:
  - 書いた推測の並びを、同じ日付で読むと同じ並びが戻る。ほかの桁数の記録は残る。
  - 日付が違う保存は、空として読まれる。ラウンドの日付と違う保存に書くと、保存全体がそのラウンドの日付だけの内容になる。
  - JSON が壊れている、`date` が文字列でない、`rounds` の形が違う → 空。1 つの桁数だけが不正（桁数違い・非素数・試行回数超過・結果が決まった後の推測）なら、その桁数だけが空で、ほかは残る。
  - `rounds` のキーが 2〜6 以外（`"7"`、`"abc"` など）の項目は、読み込みでは使わず、書き込みでは捨ててよい。
  - 結果表示中のキーの自動リピート（`event.repeat`）は Title へ戻らない。それ以外の keydown とタップは戻る。
  - 結果の決まり方: 最後が正解 → `won`。受理した数が試行回数（N=3 なら 4）に達して正解でない → `lost`。それ以外 → 途中。
  - 読み込みが例外を投げても、書き込みが例外を投げても、例外は外に出ない。保存が使えない状態でも、同じ保存層の中では書いた内容が読める（メモリ）。保存が使えるあいだは保存を先に読む（別のタブが書いた内容が見え、書き込みで消えない）。書き込みが一度失敗したら、以後はメモリを読む。
  - 結果表示中のキーの自動リピートを捨てる判断（`dropsDailyResultRepeat`）: デイリーの結果表示中のリピートだけ捨てる。最初の keydown・プレイ中のリピート・ノーマル / ハードは捨てない。
- Game（デイリー）: 保存された推測（途中）から始めると、盤面・色・キーボードの色・残りの試行回数が再現され、続きの推測を受理できる。保存が `won` / `lost` の桁数を開くと、結果表示から始まり、どのキーやタップでも Title へ戻り（`{ mode: 'daily' }`）、次のラウンドは始まらない。推測を受理するたびに保存される（不正入力では保存されない）。ラウンドの日付は開始時に固定され、日付が替わっても同じお題。デイリーではハードの制約を適用しない。
- Title: モード切替が 3 ボタンで、左から ノーマル / ハード / デイリー。座標（手計算。`docs/spec.md` の「配置」の式）: 縦並び W = 375（中心 x 187）→ 行の幅 302・左端 36、モード 36・122・208（幅 78）、💡 294〜338。2 列の最小 W = 504（中心 x 126、`colW` 236）→ 行の左端 8、モード 8・72・136（幅 56）、💡 200〜244。名前・桁数ボタン・デモの座標、縦並び / 2 列の境界（高さ 388 / 387 など、幅 504 / 528）、`y0`・`top0` は変わらない。デイリー選択中は、終えた桁数のボタンが `N✓` / `N✗`、途中・未着手は `N`。ノーマル / ハード選択中は印が無い。Game → Title の `{ mode: 'daily' }` で、デイリーが強調されて Title が開く。`modeFromData` は `'daily'` を `'daily'` に、無い・不正を `normal` にする。
- Title → Game: デイリー選択中にボタン・キー `2`〜`6` で `{ digits, mode: 'daily', candidates }` が渡る。キー `1`・`7`・`0`・`Enter` では開始しない。
- 回帰（変えないもの）:
  - ノーマル / ハードのルール・試行回数・ハードの制約・判定・入力の検証順序・同じ N・同じモードのリプレイ（直前と異なる正解）が変わらない。既存のロジックのテストは変更しない。
  - ノーマル / ハードの結果表示中は、どのキー・タップでも次のラウンドが始まる（Title へは戻らない）。
  - Game の見た目・キーボード・通知の文言と表示時間（2.2 秒）・レイアウト（結果表示の戦績と「戦績を消す」の追加を除く）、`🏠` / `◀️` の位置と挙動が変わらない。
  - Title の縦の配置、デモの配置・動き、桁数ボタンの大きさ、キー `2`〜`6` での開始、`🏠` が変わらない。デモは何も保存しない。
  - ノーマル / ハードの桁数ボタンに印が付かない。

## 完了条件

- Title にモード切替の 3 ボタン（ノーマル / ハード / デイリー）が出て、デイリーを選んで桁数を押すと、その日のその桁数のお題が始まる。同じ日付・桁数では、何度始めても（別の端末でも）同じお題。
- デイリーの途中で `◀️` やリロードで抜けても、入力済みの推測が残っていて、続きから再開できる（試行回数・ヒントは戻らない）。
- デイリーを終えると Clear / GameOver が出て、キー / タップで Title へ戻る（次のラウンドは始まらない）。デイリー選択中の Title で、その桁数のボタンが `N✓`（クリア）/ `N✗`（失敗）になり、押すと保存した盤面と結果が読み取り専用で出る（失敗時は正解も出る）。
- 日付が替わると（ローカル 0 時以降に Title を作り直すと）、印が消え、新しいお題が遊べる。
- `localStorage` が使えなくても、デイリーを遊べる（同じページの中では、再開・印・読み取り専用表示も働く）。壊れた保存でも例外で止まらない。
- スクリーンショット（390 × 844・375 × 550・1280 × 720・667 × 310、日本語と英語）で、Title の 3 ボタンのラベルが切れず重ならず、デイリー選択中の桁数ボタン（`N✓` / `N✗`）が収まっていること。Title の縦並び / 2 列の境界（幅 504 / 528、高さ 388 / 387）と、デモの位置が変わらない。
- 「テスト観点」の「回帰」の各項目が成り立つ。
- `npm run lint` / `npm run test` / `npm run test:coverage` / `npm run build`（単体・共有の両方の起動確認）が成功し、カバレッジ 90% 以上。

## 実装裁量

- 日付キー・お題・保存・再生（結果の決まり方）を、どのファイルにどの関数名で置くか。保存先（`localStorage` とメモリ）の注入の仕方、時刻（`Date`）の注入の仕方
- Game がデイリーのラウンドかどうかの持ち方（`RoundState` への足し方、Scene のフィールドなど）。保存した推測の再生を `applyGuess` を使って行うかどうか
