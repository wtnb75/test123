# 戦績の保存と表示

`docs/spec.md` の拡張。1 ラウンドが終わるたびに、「モード × 桁数」ごとの勝敗と使った試行回数をこの端末に保存し、結果表示に、いま遊んだ「モード・桁数」の戦績（勝率・連勝・平均の試行回数）を出す。ルール・判定・Title は変えない（presentation-only）。

## 概要

- 何を足すか: 戦績の保存（`localStorage`）と、結果表示への戦績の表示、「戦績を消す」ボタン。
- コアループへの効き方: 広げない。記録を持ち越す（上達・連勝という目標を見せる）。既存の「推測 → 色ヒント → 次の推測」と、ラウンドの進み方・ルール・判定は変えない。
- 保存はこの端末の `localStorage` だけ（サーバーは使わない）。保存できない環境でも遊べる（ページを開いている間だけ覚える）。

## 操作仕様

- 結果表示（`won` / `lost`。ノーマル・ハード・デイリー）に、「戦績を消す」ボタンが出る。
  - 1 回目のタップ: ボタンのラベルが「もう 1 回押すとすべて消えます」に変わる（`STATS_CLEAR_CONFIRM_MS` の間）。
  - 押し待ちのラベルは長いので、押し待ちの間だけ、文字を `statsPendingFontPx`（14 px）にして、ボタンの幅 − 12 px の中で折り返す（最大 2 行、ボタンの中に収まる。ja の文言は「もう 1 回押すと」と「すべて消えます」の間に改行を入れて 2 行にし、en は単語の間で折り返す）。
  - `STATS_CLEAR_CONFIRM_MS` 以内の 2 回目のタップ: すべての戦績（全モード・全桁数）を消す。戦績の行は「戦績は空です」になり、ボタンのラベルは「戦績を消す」に戻る。
  - 2 回目が来ないまま `STATS_CLEAR_CONFIRM_MS` が経つと、ラベルは「戦績を消す」に戻る（何も消えない）。
  - このボタンの位置のタップは、ボタンの動作として扱い、**次のラウンドを始めない**（`docs/spec.md` の「結果表示中の『桁数を選び直す』ボタンの位置のタップ」と同じ扱い）。結果表示中のキー入力は、これまでどおり次のラウンドを始める（デイリーは Title へ戻る）。ボタンの位置のタップは、デイリーでも Title へ戻らない。
- 2 回目のタップが `STATS_CLEAR_CONFIRM_MS` ちょうどのときの扱いは、タップ時刻と 1 回目の時刻の差で決める（差が `STATS_CLEAR_CONFIRM_MS` 以下なら消す）。ラベルを戻すタイマーは表示を戻すだけで、判定には使わない。
- 「戦績を消す」の状態（押し待ち）は、結果表示を作り直す（次のラウンドの開始、リサイズでの再レイアウト）たびに、元に戻る（リサイズでは、表示は作り直すが保存は変えない）。

## 画面・Scene構成

結果表示（`Game` の `won` / `lost`）に、次の 2 つを足す。仮想キーボードは結果表示のとき消える（既存）ので、その場所を使う。それ以外（盤面・「Clear」「GameOver」・「正解」・「桁数を選び直す」・通知）の位置と見た目は変えない。

### 縦長（高さ H > 幅 W）

下から順に、すべて「桁数を選び直す」ボタンと同じ中心 x（現在の位置のまま。`(W − 240) / 2 + 120`）に置く。

| 要素 | 位置・大きさ |
|---|---|
| 「桁数を選び直す」（既存・変えない） | 240 × 44、上端 `H − 70` |
| 「戦績を消す」 | 160 × 44、文字 `statsClearFontPx`（16 px）、上端 = 「桁数を選び直す」の上端 − 8 − 44（= `H − 122`） |
| 戦績の文字 | 文字 `statsFontPx`（14 px）、行の高さ `statsLineHeight`（20 px）、1 行。中心 y = 「戦績を消す」の上端 − 8 − 10（= `H − 140`） |

- 戦績の文字の 1 行の幅（14 px で描いたときの実寸。Scene が測って渡す）が `W − 24` を超えるときは、2 行に折り返す。折り返しは、1 行目と 2 行目の間（ja: 「勝率 …（… / …）」と「連勝 …・平均 …」、en: 「Win …% (… / …)」と「Streak … · Avg …」）。2 行のとき、文字のかたまりの下端 =「戦績を消す」の上端 − 8（上へ伸びる）。1 行目の中心 y = 「戦績を消す」の上端 − 8 − 30、2 行目の中心 y = 「戦績を消す」の上端 − 8 − 10。
- 手計算の例: SE（375 × 550）: 「桁数を選び直す」480〜524、「戦績を消す」428〜472、戦績（1 行）の中心 y = 410（400〜420）。N=6 の盤面の下端は 385（盤面の上端 62 + 高さ 323）なので、15 px 空く。390 × 844: 「桁数を選び直す」774〜818、「戦績を消す」722〜766、戦績（1 行）の中心 y = 704。
- 2 行になるのは、カウントが 3 桁で幅が狭いとき（SE で 351 px を超えるとき）だけ。その SE の N=6 では、1 行目の上端が盤面の下端に最大 5 px 重なりうる（保証の範囲外。許容する）。

### 横長（W ≥ H）

仮想キーボードのあった右パネル（x は `keyboardStartX` 〜 `W − outerMargin`、幅 `panelWidth`。既存の配置の値）に、縦に並べる。中心 x = `keyboardStartX + floor(panelWidth / 2)`。1 行目の上端 `y0` = `max(boardTop + 8, floor(H / 2) − 70)`（`boardTop` = 60）。

| 要素 | 位置・大きさ |
|---|---|
| 戦績 1 行目 | 勝率（ja: 「勝率 80%」、en: 「Win 80%」）。上端 `y0`、高さ 20 |
| 戦績 2 行目 | 勝ち / 戦数（「12 / 15」）。上端 `y0 + 20` |
| 戦績 3 行目 | 連勝（ja: 「連勝 3」、en: 「Streak 3」）。上端 `y0 + 40` |
| 戦績 4 行目 | 平均（ja: 「平均 3.4 回」、en: 「Avg 3.4 tries」）。上端 `y0 + 60` |
| 「戦績を消す」 | 幅 `panelWidth`、高さ 44、上端 `y0 + 88`、文字 16 px |

- 空の戦績（「戦績は空です」/「No stats」）は、横長でも 1 行（戦績 1 行目の位置）。
- 手計算の例: 667 × 310: `panelWidth` 140、`keyboardStartX` 514、中心 x 584、`y0` 85、「戦績を消す」173〜217（「桁数を選び直す」は x 213〜453、y 240〜284 なので重ならない）。1280 × 720: `panelWidth` 220、`keyboardStartX` 1046、中心 x 1156、`y0` 290、「戦績を消す」378〜422。

### 文言（ja / en。言語の判定は他と同じ）

| 要素 | 日本語 | 英語 |
|---|---|---|
| 戦績（縦長の 1 行） | 勝率 80%（12 / 15）・連勝 3・平均 3.4 回 | Win 80% (12 / 15) · Streak 3 · Avg 3.4 tries |
| 空 | 戦績は空です | No stats |
| ボタン | 戦績を消す | Clear stats |
| 押し待ち | もう 1 回押すとすべて消えます | Press again to erase all |

- 戦績に出す値は、いま終わったラウンドの「モード・桁数」の分（その結果を足したあとの値）。デイリーは「デイリー・その桁数」の分。記録しなかった結果表示（終わっていたデイリーの開き直し）では、現在の保存値をそのまま出す（その桁数の戦績が空なら「戦績は空です」）。
- 勝率 = `round(100 × 勝ち ÷ 戦数)` %（`Math.round`。例: 1 / 3 → 33、2 / 3 → 67、1 / 8 → 13）。平均 = `勝ったゲームの試行回数の合計 ÷ 勝ち` を小数第 1 位に四捨五入（`toFixed(1)`）。勝ちが 0 のときは `-`（ja は「平均 -」、en は「Avg -」。「回」「tries」は付けない）。勝ち・戦数・連勝が 999 を超えたら `999+` と書く（勝率・平均は実際の値から計算する）。

## ルール

### 戦績の数え方

- 保存の単位: 「モード」（`normal` / `hard` / `daily`）と「桁数」（2〜6）の組ごとに、`played`（戦数）・`won`（勝ち）・`streak`（現在の連勝）・`attemptsWon`（勝ったラウンドで使った試行回数の合計）。すべて 0 以上の整数。
- 1 ラウンドが終わった（`won` または `lost` になった）とき、**ちょうど 1 回**、そのラウンドのモード・桁数に対して記録する: `played` + 1。勝ちなら `won` + 1、`streak` + 1、`attemptsWon` に使った試行回数を足す。負けなら `streak` = 0。
- 数えないもの: 途中で Title（`◀️`）・ゲーム一覧（`🏠`）へ離れたラウンド。リサイズ・再レイアウトで結果表示を作り直しても、再度は記録しない。
- デイリー: そのラウンドが「その場で」終わったとき（途中から再開して、そのセッションで終えたものを含む）に 1 回だけ数える。終えた桁数を開き直して結果を見るだけ（保存された推測から再生して、すでに終わっていた）のときは、数えない。
- ハードモードのラウンドは `hard`、デイリーは `daily` に数える（ノーマルと混ぜない）。

### 保存

- `localStorage` のキー `digdle.stats`（`STATS_STORAGE_KEY`）に、JSON `{ "version": 1, "entries": { "<モード>:<桁数>": { "played": …, "won": …, "streak": …, "attemptsWon": … } } }` で保存する。1 ラウンドの記録のたびに、全体を書き直す。
- 読むとき: キーが無い・JSON として読めない・`version` が 1 でない・`entries` がオブジェクトでないときは、すべて空として扱う。エントリごとに、キーが「モード:桁数」の形でない（モードが 3 つ以外、桁数が 2〜6 以外）、数値が 0 以上の整数でない、`won` > `played`、`streak` > `won`、`attemptsWon` < `won`（勝ち 1 回は最低 1 試行）のどれかなら、そのエントリだけを空として扱う（ほかのエントリは生かす）。
- 保存を使えない場合（ブロック・容量超過・`localStorage` が無い）でも、ゲームは止まらない。デイリーの保存（`docs/spec/daily.md`）と同じで、読み書きの失敗のあとは、書いたものの**ページ内のメモリのコピー**を使い続け、戦績の表示と記録が、ページを開いている間は動く。バックエンドは、使えるあいだは呼ぶたびに読み直す（別のタブの書き込みが見える）。
- 「戦績を消す」（2 回目）は、`entries` を空にして保存する（キーは残す）。

## パラメータ表

| 名前 | 値 | 意味 |
|---|---|---|

| `STATS_CLEAR_CONFIRM_MS` | 3000 ms | 「戦績を消す」の 1 回目から、2 回目を受け付ける時間 |
| `statsFontPx` / `statsLineHeight` | 14 px / 20 px | 戦績の文字の大きさと行の高さ（縦長・横長とも） |

| 横長の戦績の位置 | `y0` = `max(60 + 8, floor(H / 2) − 70)`、戦績 4 行（各 20 px）、ボタンの上端 `y0 + 88` | 右パネルの中の並び |

## テスト観点

- 記録（純粋関数。空から）: ノーマル・4 桁で、3 回で勝つ → `{ played 1, won 1, streak 1, attemptsWon 3 }`、5 回で勝つ → `{ 2, 2, 2, 8 }`、負ける → `{ 3, 2, 0, 8 }`、2 回で勝つ → `{ 4, 3, 1, 10 }`（勝率 `round(100 × 3 ÷ 4)` = 75、平均 `10 ÷ 3` = 3.3）。別のモード・別の桁数の記録は混ざらない（ノーマル 3 桁とハード 3 桁、ノーマル 4 桁が別）。入力を壊さない（元の戦績を変更せず、新しい値を返す）
- 整形: 勝ち 12・戦数 15 → 「勝率 80%（12 / 15）」、連勝 3、平均 `41 ÷ 12` = 3.4166… → 「3.4」。勝ち 0 → 平均「-」。戦数 1000 → 「999+」（勝率は 1000 のまま計算）。勝率の丸め: 1 / 3 → 33、2 / 3 → 67、1 / 8 → 13（12.5 は 13）。ja / en の文言（縦長の 1 行、横長の 4 行、空）
- 読み込みの検証: null・壊れた JSON・`version` 違い・`entries` が配列 → 空。エントリの壊れ（負・小数・`won` > `played`・`streak` > `won`・`attemptsWon` < `won`・モード / 桁数のキーが不正）はそのエントリだけ空で、ほかは残る。未知のキーは落とす
- 保存（バックエンドを注入）: 読み書きが例外を投げるバックエンドでも、記録と表示がメモリのコピーで動く。バックエンドの値は呼ぶたびに読み直す（別のタブの書き込みが見える）。消す → 全エントリが空。消したあとの記録は 1 戦目から
- デイリーの数え方: その場で終えたら 1 回、途中から再開して終えても 1 回、終わっていた桁数を開き直して結果を見るだけでは数えない（判断の純粋関数 `shouldRecordRound` の真偽）。結果表示の再レイアウト（リサイズ）で、記録が二重にならない
- 押し待ちのラベル（ja「もう 1 回押すとすべて消えます」、en「Press again to erase all」）が、縦長（ボタン幅 160）と横長（667 × 310 でボタン幅 140）で、14 px・幅 − 12 px の中に 2 行以内で収まり、ボタンの高さ 44 px からはみ出さない（`game-qa` のスクリーンショットでも確かめる）。勝ち 0 の平均は ja「平均 -」・en「Avg -」。終わっていたデイリーを開き直した結果表示は、現在の保存値（空なら「戦績は空です」）を出す
- 配置（純粋関数。Scene は、戦績の文字の 1 行の幅と、`W`・`H`・既存の配置の値を渡す）: 縦長 375 × 550 で「戦績を消す」428〜472・戦績（1 行）の中心 y = 410、390 × 844 で 722〜766・704。折り返し（1 行の幅が `W − 24` を超える / ちょうど `W − 24`）の境界で、1 行 ↔ 2 行が切り替わる。2 行の中心 y が `H − 8 − …` の式どおり。横長 667 × 310 で `y0` = 85・ボタン 173〜217・中心 x = 584、1280 × 720 で `y0` = 290・ボタン 378〜422・中心 x = 1156。「戦績を消す」と「桁数を選び直す」（横長は x 213〜453、y 240〜284）の矩形が交わらない。戦績の行・「戦績を消す」が盤面・既存のボタンと交わらない（N=2〜6、375 × 550・390 × 844・667 × 310・1280 × 720。ただし「画面・Scene構成」で保証の範囲外とした SE の N=6 で 2 行になる場合を除く）
- 「戦績を消す」の状態（純粋な状態遷移）: 1 回目で押し待ち、`STATS_CLEAR_CONFIRM_MS` 以内の 2 回目で消す、ちょうど `STATS_CLEAR_CONFIRM_MS` の 2 回目は消す（境界は含む）、`STATS_CLEAR_CONFIRM_MS` + 1 ms の 2 回目は 1 回目として扱う（押し待ちになる）、2 回目が来ないまま時間が経つと元に戻る（何も消えない）。消したあとのラベルは「戦績を消す」
- ボタン位置のタップは次のラウンドを始めず、Title へも戻らない（Scene の処理。`game-qa` で確かめる）。結果表示中のキー入力が次のラウンドを始める規則は変わらない
- 回帰（戦績を足しても変わらないこと）: 既存のロジック（判定・検証・ハードモード・ラウンド生成・デイリー・Title の配置・Game の配置）のテストを変更せずに通る。Clear / GameOver・「正解」・「桁数を選び直す」の位置・大きさが変わらない（`game-qa` のスクリーンショットで、変更前後を見比べる）

## 完了条件

- ノーマル・ハード・デイリーのどれでも、1 ラウンド終わるたびに戦績が増え、結果表示に、そのモード・桁数の戦績（勝率・勝ち / 戦数・連勝・平均）が出る。ブラウザを開き直しても（保存できる環境では）残る
- 途中で離れたラウンド・終わっていたデイリーの開き直しは数えない。デイリーを途中から再開して終えると 1 回数える
- 「戦績を消す」は、1 回目で「もう 1 回押すとすべて消えます」になり、3 秒以内の 2 回目ですべて消える。タップは次のラウンドを始めない
- 保存が使えない（ブロックされた）環境でも、ゲームが止まらず、ページを開いている間は戦績が動く
- 縦長（SE の 375 × 550 の N=2〜6、390 × 844）で、戦績・「戦績を消す」・「桁数を選び直す」が、盤面と重ならずに見える（「画面・Scene構成」で保証の範囲外とした、SE の N=6 で戦績が 2 行になる場合を除く）。押し待ちのラベルもボタンの中に収まる。横長（667 × 310、1280 × 720）で、右パネルに収まり、「桁数を選び直す」と重ならない。戦績の文字は実寸 14 px 以上で、「戦績を消す」は高さ 44 px 以上（スクリーンショットで確かめる）
- 変えないもの（回帰条件）: ルール・試行回数・判定・入力の検証順序・ハードモード、デイリーのお題・保存・結果の扱い、Title（配置・デモ・表示）、Game の盤面・キーボード・通知の配置、「Clear / GameOver」・「正解」・「桁数を選び直す」の見た目と位置、結果表示中の「どこをタップしても次のラウンド」「キーで次のラウンド」の規則（「戦績を消す」の位置のタップを除く）、既存のテスト
- `npm run lint` / `npm run test` / `npm run test:coverage`（90% 以上）/ `npm run build` が成功する。README に戦績の説明が 1 行ある

## 実装裁量

- 戦績・保存・整形・配置の関数を置くファイルと名前、保存の `entries` の中の型
- 「戦績を消す」ボタンと戦績の文字の色・枠・背景（見た目。ただし文字は読める濃さで、ボタンは押せると分かること）。結果表示の背景は現状のまま
- ボタンの押し待ちの、ラベルの切り替えの見せ方（`STATS_CLEAR_CONFIRM_MS` の間の表示。色を変えてもよい）。時間の計測に使う Phaser の API（`time.delayedCall` など）
- 戦績の文字の幅の測り方（`Text` の `width` など）と、折り返しの 2 行の描き方（2 つの `Text` か、改行のある 1 つか）
