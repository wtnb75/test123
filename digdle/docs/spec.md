# ゲーム名（仮称可）

digdle

# コンセプト（1-3 行）

Wordle 風の数当てゲーム。
お題は N 桁（2/3/4/5/6）の素数で、プレイヤーも N 桁の素数を入力して推理する。
重複数字判定は Wordle と同等ルールに従う。
ハードモードでは確定ヒントを次手以降に強制利用する。

# ターゲットプレイヤー

- 数字パズルが好きなプレイヤー
- 短時間で遊べる推理ゲームを求めるプレイヤー
- Wordle 系の手触りで数当てを楽しみたいプレイヤー

# コアループ（プレイ中に繰り返す行動）

1. N 桁（2/3/4/5/6）とモード（ノーマル/ハード）を選択する
2. N 桁の素数を入力する
3. Enter で判定し、色ヒント（green/yellow/gray）を読む
4. ヒントを使って次の素数を入力する
5. 制限回数内の正解を目指す

# 操作仕様（入力デバイスと主要操作）

- 入力デバイス: キーボード、画面上のボタン・仮想キー
- Title（開始前）:
  - 桁数ボタン `2`〜`6`、または数字キー `2`〜`6`: その桁数・選択中のモードで Game を開始する
  - モード切替ボタン（ノーマル / ハード / デイリー）: タップで切り替える。選択中のモードは枠の色で強調する。デイリーは、その日の桁数ごとのお題を 1 日 1 回遊ぶモード（[日替わりのお題](spec/daily.md)）
  - 候補数ボタン（💡）: モード切替と同じ行の右に置く。タップで、候補数の補助をオン / オフする（既定はオフ）。オンのときは枠を黄（`0xfde047`）にして強調する。値は Title から Game へ渡すだけで、保存しない（リロードでオフに戻る）。デイリーを選んでいても 💡 は押せて、状態は保つ（デイリーの Game では「候補数の一行」が出ない。Game の「候補数の一行」を参照）
- Game（プレイ中）:
  - 数字キー（0-9）: 1 文字入力
  - Backspace / ⌫: 1 文字削除
  - Enter / ⏎: 判定実行
  - 入力制約: 先頭 0 と非数字文字は入力不可
- ナビゲーション:
  - 左上 `🏠`（Title・Game 共通）: ゲーム一覧のページ（相対パス `../`）へ遷移するリンク。Scene の遷移ではない。Game の結果表示中は、`◀️` と同じく画面タップ（次のラウンド）として扱い、`../` へは遷移しない
  - 右上 `◀️`（Game のみ。Title には無い）: プレイ中に押すと Title へ戻る。選択中のモードは保持する。結果表示中も表示されるが、結果表示中のタップは画面タップ（次のラウンド）として扱う
  - 結果表示中の「桁数を選び直す」ボタン: Title へ戻る。選択中のモードは保持する

# 画面・Scene 構成

| Scene | キー | 役割 |
|---|---|---|
| Title | `Title` | 起動時の最初の Scene。名前・モード・桁数の選択。選ぶと Game を開始する |
| Game | `Game` | ラウンドの進行（盤面・仮想キーボード・結果表示） |

- 起動順: Title → Game。
- Scene 間の受け渡し:
  - Title → Game: `{ digits: 2 | 3 | 4 | 5 | 6, mode: 'normal' | 'hard' | 'daily', candidates: boolean }`（`candidates` は 💡 の状態。開始時に 1 回。Game は受け取ったらすぐラウンドを始める。Game に桁数・モードの選択フェーズは無い。`daily` の扱いは [日替わりのお題](spec/daily.md)）
  - Game → Title（◀️・「桁数を選び直す」）: `{ mode, candidates }`（`mode` は `'normal' | 'hard' | 'daily'`、`candidates` は `boolean`）。Title は受け取った mode を選択中として強調し、candidates を 💡 の状態にする。Title が何も受け取らずに始まったとき（起動直後）は `normal` で、`candidates` は `false`
- Title:
  - 構成: 名前 `digdle`、モード切替（ノーマル / ハード / デイリーの 3 ボタン）と候補数ボタン（💡）の 1 行、桁数ボタン（2・3・4・5・6 の 1 行 5 個）、左上の `🏠`、ボットが素数を推理するデモ（余白が足りない画面では出さない。[Title のデモ](spec/title-demo.md)）。副題とヒントの文字は無い。デモは操作を受け付けない
  - 文言: ブラウザの言語が `ja` で始まれば日本語、それ以外は英語（Game と同じ判定）。Title の文字は名前 `digdle`、モード、💡（絵文字）、桁数（数字。デイリー選択中は終えた桁数に `✓` / `✗` が付く）だけ

    | 要素 | 日本語 | 英語 |
    |---|---|---|
    | モード | ノーマル / ハード / デイリー | Normal / Hard / Daily |

  - 配置（画面幅 W・高さ H）: 要素の大きさは「パラメータ表」の Title の行どおり。モード行は左からノーマル、ハード、デイリー、💡 の 4 つ。行の幅 `modeRowW` = `min(302, 列の幅)`（列の幅は縦並びでは W、2 列では `colW` = `floor(W / 2) − 16`）。行の左端 = `floor(中心 x − modeRowW / 2)`。💡（`candidateButton`）は 44 × 44 px で、行の右端に置く（左端 = 行の左端 + `modeRowW` − 44）。上端 = モード切替の上端 − 2 で、44 px の中心を 40 px のモードボタンの中心に合わせる。3 つのモードボタンは残りの幅を 3 等分する: 幅 `modeW` = `min(78, floor((modeRowW − 44 − 24) / 3))`（下限 48 px）。i 番目（0 始まり）の左端 = 行の左端 + i × (`modeW` + 8)。例: 縦並び W 375 は行の幅 302・左端 36、モードは 36・122・208（幅 78）、💡 は 294〜338。2 列 W 504 は `colW` 236・`modeW` 56・左端 8（中心 x 126）、モードは 8・72・136、💡 は 200〜244。ラベルは 16 px。ラベルの幅が `modeW` − 8 を超えるときは 1 px ずつ小さくし、12 px で止める（全角 4 字の「ノーマル」「デイリー」は 12 px で 48 px）。桁数ボタンは従来どおり縮む。2 列の境界（既存の値。W 504・528 など）は変えない。2 列の最小 W 504 でも、行は `modeW` 56 で入る。桁数ボタンは左から 2・3・4・5・6 の順に 1 行 5 個。配置は次の 2 種類で、どちらにするかは [Title のデモ](spec/title-demo.md) の「レイアウト」が決める（縦並びを優先し、入らなければ 2 列。どちらでもデモが入らないときは、縦並びでデモを出さない。ただし高さ H が 192 未満で、かつ幅 W が 504 以上のときは、縦並びだと桁数ボタンが切れるので、2 列でデモを出さない。W が 504 未満なら縦並びのまま、下が切れることを許容する）。座標は整数にそろえる（`floor`）。中心 x は `floor(W / 2)`（縦並び）、`floor(W / 4)`（2 列の左の列）、`floor(W × 3 / 4)`（2 列の右の列）で、中心に置く要素の左端 = `floor(中心 x − 幅 / 2)`。想定する画面の幅は 320 px 以上（これ未満では、はみ出しを許容する）。
    - **縦並び**: 全ての要素を水平中央（x = W / 2）に置く。上から名前・モード切替・桁数ボタン・デモ。`y0` からの相対で、名前の中心 y = `y0 + 44`、モード切替の上端 = `y0 + 84`（下端 `y0 + 124`）、桁数ボタンの上端 = `y0 + 140`（下端 `y0 + 192`）、デモの上端 = `y0 + 208`。`y0 = max(0, floor((H − 全体の高さ) / 3))`。全体の高さ = デモがあれば `192 + 16 + 盤面の高さ + 16`、無ければ `192 + 16`（208）。
    - **2 列**: 左の列に名前・モード切替・桁数ボタン、右の列にデモを置く。左の列の中心 x = `floor(W / 4)`、幅 `colW` = `floor(W / 2) − 16`。左の列の 3 つの要素は、縦に 170 px（名前の上端から桁数ボタンの下端まで）の塊として、垂直は画面の中央（`top0 = max(0, floor((H − 170) / 2))`）に置く: 名前の中心 y = `top0 + 22`、モード切替の上端 = `top0 + 62`、桁数ボタンの上端 = `top0 + 118`。右の列のデモは、中心 x = `floor(W × 3 / 4)`、垂直は画面の中央。
    - 桁数ボタンの幅 `digitW` = `max(1, min(64, floor((列の幅 − 16 − 32) / 5)))`（列の幅は、縦並びでは W、2 列では `colW`。最小 1 は極端に狭い幅での 0 以下の防止）。5 個の列の幅は `5 × digitW + 4 × 8` で、列の中心 x に置く。名前・モード切替・桁数ボタンの行は、どれも列の中心 x に置く（2 列では `colW` の範囲ではなく `floor(W / 4)` が中心）。
    - `🏠` は左上の同じ位置（余白 20 px）。デモを置く配置（縦並びは W が約 200 px 以上、2 列は W が 528 px 以上）では、名前（約 130 px 幅）は `🏠` と重ならない。デモを置かない低い画面（H < 192 の 2 列）では、狭いと重なることがある（許容する）。
  - 状態遷移: 無し（単一の選択画面）。モードの切替は Title に留まる。桁数ボタンまたはキー `2`〜`6` で Game を開始する（他の入力では何も起きない）。Scene を開始させた入力（キー・タップ）は、Game では処理しない（開始したキーが盤面の数字として入力されない）
  - リサイズ/回転で再レイアウトする（選択中のモードは保持）
- Game:
  - 構成: 盤面（試行回数 x N 桁）、仮想キーボード、結果表示（Clear / GameOver）、左上 `🏠`・右上 `◀️`
  - UI フェーズ: `playing`（入力中）→ `won` / `lost`（結果表示）。`playing` → `won`/`lost` は判定の結果（正解 / 試行回数を使い切る）。`won`/`lost` では（デイリーを除く。下の 1 行）、どのキー（数字・Enter・Backspace を含む）または画面タップでも、同じ N・同じモードの次ラウンドを `playing` で始める（直前と異なる正解。そのキー・タップ自体は入力として処理しない）。結果表示中の「桁数を選び直す」ボタンの位置のタップは、画面タップよりボタンの動作（Title へ戻る）を優先する（「戦績を消す」ボタンの位置のタップも同じで、次のラウンドを始めない。[戦績の保存と表示](spec/stats.md)）。結果表示中の `🏠` / `◀️` の位置のタップは、画面タップ（次のラウンド）として扱う。「桁数を選び直す」（結果表示中）と `◀️`（プレイ中）は Title へ戻る（その時点のラウンドは破棄する）。キーの自動リピートによる keydown は、通常のキー入力として扱う（Scene を開始したキーを押し続けた場合も、リピートは入力になる）
  - 候補数の一行（`candidates` が true で、モードがノーマルかハードのとき）: 判定の後（`playing` のまま）、通知の帯の中央（y 30）に「あと n 個」（en:「n left」。n = 1 のときも「あと 1 個」）を出す。`n` は「候補」の数で、N 桁の素数 p のうち、これまでの全ての判定（不正入力は履歴に入らない）を「p が答えだった」として計算し直した色の並びが、実際の色の並びと一致するもの。ただし直前のラウンドの答えは含めない（次の答えは直前と異なるため。答えの抽選が直前の答えを除く）。ハードでも色の一致だけで数え、追加の絞り込みはしない（確定ヒントの制約は色の一致から自然に満たされる）。判定の履歴は次のラウンドで空になり、一行は判定が 1 回入るまで出ない。`won` / `lost`（結果表示）では出さない。不正入力の通知（2.2 秒）が出ている間は通知を優先し、通知が消えた後に同じ帯の中で候補の一行に戻る。背景は敷かず、文字 16 px・`#e5e7eb`・一行（折り返さない。最長の「あと 68906 個」は SE の折り返し幅 234 px に収まる）
  - デイリー（`mode: 'daily'`）の Game は、`won`/`lost` で次のラウンドを始めず Title へ戻る。お題・保存・再開は [日替わりのお題](spec/daily.md)
  - 文言（ja / en。言語の判定は Title と同じ）: 結果「Clear」「GameOver」（言語によらず同じ）、不正解の開示「正解: <数> / Answer: <数>」（`lost` のみ）、ボタン「桁数を選び直す / Choose digits again」、入力が不正（桁数不一致・非素数・ハードモード違反）のときの通知は、理由を表す文（ja / en）を一時的に出す（試行回数は消費しない。文言・表示時間は現状のまま）
  - 結果表示（`won` / `lost`。ノーマル・ハード・デイリー）に「コピー」ボタンを置く（ja「コピー」・en「Copy」）。タップで、結果を次の形式でクリップボードに入れる（言語の文字は使わず、ゲーム名 `digdle`・数字・絵文字だけ。言語によらず同じ）:
    - 1 行目: `digdle <N> <使った試行回数>/<試行回数の上限>`（例: 4 桁・3 回目で正解 → `digdle 4 3/5`）
    - 2 行目以降: 試行 1 回につき 1 行。その試行の色の並び（N 個の 🟩🟨⬛。緑・黄・灰の順は盤面と同じ）。負けたときは上限までの全ての試行を並べる
    - 答えの数字と、日付・個人を特定する情報は入れない
  - コピーは次のラウンドを始めない（「戦績を消す」と同じ扱い。デイリーでもタップで Title へ戻らない）。キーでは何もしない
  - クリップボードに書き込めない（権限が無い・ブロックされている・API が無い）ときは、ボタンの文字を一言（ja「コピーできませんでした」・en「Could not copy」。文字 14 px、ボタンの幅 − 12 px の中で最大 2 行）に変えて `2.2 秒` の間だけ出し、その後「コピー」に戻す。ゲームは止まらず、結果表示のまま続けられる
  - リサイズ/回転で再レイアウトする
- レイアウト（Game。画面幅 W・高さ H。座標と大きさは整数にそろえる）:
  - 縦長（H > W）: 下部ドック型キーボード（4 列 × 3 行）。横長: 右側ドック型キーボード（2 列 × 6 行。この改訂では変えない）
  - 領域: 左端に縦向きの題名 `digdle`（意図した配置。盤面の高さを使わないよう、左の幅 36〜62 px に回転して置く）、画面上端から盤面の上端（`boardTop`）までは通知の帯、その下に盤面、縦長では盤面の下にキーボード
  - 縦長のキー高さ `keyH` = `max(44, min(54, floor((H × 0.22 − 16) / 3)))`（キーの隙間は 8 px。キーは実寸 44 px 以上）。キーボード全体の高さ = `3 × keyH + 16`
  - 縦長の盤面の高さの上限 = `H − outerMargin − キーボード全体の高さ − panelGap − boardTop`（`outerMargin` = `max(8, min(14, floor(W × 0.02)))`、`panelGap` = `max(6, min(12, floor(W × 0.02)))`）。セルの大きさは、この上限と盤面の幅の上限の小さい方に合わせて決める（現状の式のまま。`keyH` が上がった分だけ上限が下がり、セルが縮む）。全ての行が、通知の帯・キーボードと重ならずに見える
  - 手計算の例（縦長、SE 375 × 550）: `keyH` = 44、キーボード全体 148 px、盤面の高さの上限 327 px。N=6（7 行）は隙間 6・セル 41、N=4（5 行）は隙間 9・セル 58。スマホ縦 390 × 844 は `keyH` = 54（従来と同じ）、N=6 のセルは 45
  - 通知（入力が不正のときの文）は、画面上端から `boardTop`（60 px）までの帯に出す。縦長・横長とも同じ。盤面・キーボードには重ねない（結果表示中は通知を出さない）。帯の中の位置と折り返しは「パラメータ表」の通知の行どおり
  - 結果表示の「コピー」ボタン（「戦績を消す」と同じ列。戦績の下）:
    - 縦長（H > W）: 「戦績を消す」と同じ行に、左右に並べる。「戦績を消す」は中心 x から左へ、「コピー」は右へ、隙間 8 px（両方とも 160 × 44。上端は「戦績を消す」の上端のまま、中心 x は「桁数を選び直す」と同じ）。375 × 550 では「戦績を消す」23.5〜183.5、「コピー」191.5〜351.5（y 428〜472）。390 × 844 では 31〜191・199〜359（y 722〜766）
    - 横長（W > H）: 「戦績を消す」の下に、右パネルの幅（`panelWidth`）・高さ 44、上端 = 「戦績を消す」の下端 + 8（`y0 + 140`）。667 × 310 では 514〜654、y 225〜269。1280 × 720 では `panelWidth` 220（中心 x 1156、x 1046〜1266）、y 430〜474
    - 結果表示のときだけ出す。文字 16 px（失敗の一言は 14 px）
  - 「戦績を消す」の縦長の x の位置だけ、この節の値に変わる（y と大きさは変えない）
  - 縦長でも横長でも、「桁数を選び直す」・戦績の文字・盤面・通知と重ならない
  - リサイズ/回転時に再レイアウト

# ルール（勝利条件、失敗条件、スコア条件）

- 勝利条件: 制限回数内に正解の N 桁素数を当てる
- 失敗条件: 制限回数を使い切る
- 試行回数:
  - N=2: 3 回
  - N=3: 4 回
  - N=4: 5 回
  - N=5: 6 回
  - N=6: 7 回
- 不正入力（桁不一致/非素数）は試行回数を消費しない
- ハードモード:
  - green 確定桁は次手以降も同じ位置に同じ数字を入力しなければならない
  - yellow 確定桁は次手以降のどこかに必ずその数字を含めなければならない
  - 同じ数字が 1 回の推測で green と yellow の両方に出た場合は、その合計個数（green の個数 + yellow の個数）以上を、次手以降の推測に含めなければならない（例: 正解 `1137` に対する推測 `1317` は green・yellow・yellow・green なので、数字 `1` を 2 個含める必要がある）
  - ハードモード違反の入力は「ルール違反」として拒否し試行回数を消費しない
  - 入力確定後、モード変更は不可（ゲーム中は固定）
- 終了後は入力ロックし、次入力で同じ N・同じモードの次ゲームへ進む（デイリーを除く。デイリーは次入力で Title へ戻る）
- 結果表示中の「桁数を選び直す」、またはプレイ中の `◀️` で Title へ戻れる（モードは保持。N は Title で選び直す）

# 技術要件（Phaser/Vite/ESLint/Vitest での実装方針）

- Phaser + Vite 構成を維持
- ゲームロジックは純関数として分離
  - 素数判定/生成
  - 判定ロジック
  - 入力検証
  - 状態遷移
- 乱数は `createGame({ seed?: number })` で注入可能
- 画面リサイズ時は Scene を再レイアウトし、干渉を回避
- Title と Game は別の Scene。Title の選択 UI（要素の配置・桁数ボタンの並べ方）と、両 Scene の共用部品（テキスト・ボタン・文言・`🏠`）は Phaser に依存しない値の計算を純関数に切り出して単体テストできるようにする。Scene 間の受け渡し（`{ digits, mode, candidates }`・`{ mode, candidates }`）の形も型で表す
- デイリーの日付キー・お題の選び方・保存の読み書きと検証は、Phaser と `localStorage` に依存しない純関数（時刻と保存先を注入できる）に切り出して単体テストできるようにする
- Game の盤面・キーボード・通知の配置の計算（`keyH`、盤面の上限、セルの大きさ、通知の位置と折り返し幅）は、Phaser に依存しない純関数に切り出して単体テストできるようにする（入力は W・H・行数・列数、出力は座標と大きさ）。通知の文字を小さくする判断だけは、測った高さを受け取る純関数にする
- ESLint エラー 0 を維持
- Vitest でロジック中心にテスト

# テスト観点（最低限の単体テスト対象）

- 重複数字判定（例: 1013 vs 1111）
- Enter 時の検証順序（桁数 -> 素数 -> ハードモード制約）
- 不正入力で試行回数を消費しない
- ハードモード: green 位置違反で拒否される
- ハードモード: yellow 未包含で拒否される
- ハードモード: 同じ数字が green と yellow の両方に出た場合、合計個数に満たない推測は拒否される
- ノーマルモードではハードモード制約チェックを行わない
- seed 指定時の決定性 / 未指定時の非決定性
- 次ゲームで直前解答を避ける
- レイアウト変更でゲームロジックが壊れない
- Title の配置（純関数。手計算の値は [Title のデモ](spec/title-demo.md) の表）: 縦並びと 2 列の座標、切り替えの境界（幅 528 以上で、高さ 388 と 387。2 列の高さ 195 と 196、桁数ボタンの幅 39 と 40、H = 191 と 192）、`y0` の計算、桁数ボタンの幅（`floor((列の幅 − 48) / 5)` が 64 を超えないこと）、奇数の幅での左端（`floor`）
- Title → Game の受け渡し: ボタン・キー `2`〜`6` で選んだ桁数と選択中のモードが Game に渡る。Title が mode を受け取らずに始まるとモードは `normal`。キー `1`・`7`・`0`・`Enter` では開始しない
- Game → Title: プレイ中の `◀️` と結果表示中の「桁数を選び直す」で Title に戻り、選択中のモード（ハードを選んでいれば強調がハード）と 💡 の状態が保持される
- Title の文言: ブラウザの言語が `ja` で始まれば日本語、それ以外（`en-US` など）は英語（モードの表示）
- Title のリサイズ: 縦並びと 2 列が、高さの変化（388 / 387 など）で入れ替わる。ハードを選んだままでも強調は保持される
- Scene を開始させたキー（例: `2`）が、Game の盤面の入力として二重に処理されない
- 結果表示中（ノーマル / ハード）: どのキーでも次ラウンドが始まり（そのキーは入力されない）、同じ N・同じモード。「桁数を選び直す」は Title へ戻る
- `🏠` の遷移先（`../`）は Title と Game（プレイ中）で同じ
- 結果表示中（ノーマル / ハード）: `🏠` / `◀️` の位置のタップは次のラウンドを始め、Title にも `../` にも遷移しない。「桁数を選び直す」の位置のタップは Title へ戻る。プレイ中の `◀️` は Title へ戻る
- キーの自動リピートによる keydown は通常のキー入力として扱われる（ノーマル / ハードの結果表示中のリピートは次のラウンドを始める。デイリーの結果表示中のリピートは Title へ戻る入力にしない。[日替わりのお題](spec/daily.md)）
- Game の配置（純関数。手計算の値は「レイアウト（Game）」の例）: 縦長の `keyH`（SE 375 × 550 で 44、390 × 844 で 54、`floor((H × 0.22 − 16) / 3)` が 44 未満・54 超の境界）、SE の N=6 でセル 41・隙間 6、N=4 でセル 58・隙間 9、全ての行の下端がキーボードの上端より上にあること（N=2〜6 の全てで）、390 × 844 の N=6 でセルが 45（従来と同じ）
- 通知の位置: 縦長・横長のどちらでも、帯（y 0〜60）に収まり、盤面の行・キーボードのキーと矩形が交わらない（N=2〜6、375 × 550・390 × 844・667 × 310・1280 × 720）。背景の最大幅が偶数（SE は 262）で文字の折り返し幅が最大幅 − 28（SE は 234）、背景の矩形が `🏠` / `◀️` の矩形と交わらない。高さが 58 px 以下なら 16 px のまま、58 px を超えるときは 1 px ずつ小さくなり、最小 12 px で止まる（境界: 58 と 59、12 に達する場合）
- 横長（右ドック）の `keyH`・セルの大きさ・キーボードの位置は変わらない（667 × 310、1280 × 720 で従来と同じ値）。縦向きの題名の位置（x = `outerMargin + floor(左幅 / 2)`、y = `floor(H / 2)`）、`boardStartX` / `boardCenterX` の式、`🏠` / `◀️` の位置も従来と同じ値（純関数にした範囲は単体テスト、それ以外は回帰のスクリーンショット）
- 範囲外（保証しない）: 縦長で盤面の上限が下限 120 px に張り付く低い画面（最小のセル 28 px・隙間 4 px では N=6 の盤面が 220 px 要るので、縦長で H が約 445 未満）と、文字が最小 12 px でも帯の高さを超える通知（許容する。従来の下限の挙動のまま）
- 通知の文言・表示時間（2.2 秒）・試行回数を消費しないことは変わらない
- デイリー（日付キー・お題の決定性・保存と再開・Title の 3 ボタンと印・Game → Title の戻り方）: [日替わりのお題](spec/daily.md) のテスト観点
- 戦績（記録・整形・読み込みの検証・保存・配置・「戦績を消す」）: [戦績の保存と表示](spec/stats.md) のテスト観点
- コピーの文字（純関数。結果から作る）: 4 桁・3 回目で正解 → 1 行目 `digdle 4 3/5`、続けて 3 行（各 4 個の 🟩🟨⬛）。負け（5 回使い切り）は 5 行。答えの数字が、どの行にも現れない。デイリーも同じ形式で、日付を含まない
- コピーのボタン: タップで次のラウンドを始めず、Title へも戻らない（デイリーでも）。キーでは何も起きない
- コピーの失敗: 書き込みが拒否されたとき、ボタンの文字が一言になり、2.2 秒後に「コピー」へ戻る。ゲームは結果表示のまま続けられる
- コピーのボタンの配置（純関数。Scene は `W`・`H`・既存の配置の値を渡す）: 縦長 375 × 550 で「戦績を消す」23.5〜183.5・「コピー」191.5〜351.5（y 428〜472）、390 × 844 で 31〜191・199〜359（y 722〜766）、横長 667 × 310 で「コピー」514〜654（y 225〜269）、1280 × 720 で 1046〜1266（y 430〜474）。「桁数を選び直す」（横長は x 213〜453、y 240〜284）と重ならない
- モード行の幅（純関数）: `modeRowW` = `min(302, 列の幅)`、`modeW` = `min(78, floor((modeRowW − 44 − 24) / 3))`。縦並び W 375 で行 302・`modeW` 78・左端 36・💡 の左端 294。2 列 W 504（`colW` 236）で `modeW` 56・行の左端 8。`colW` 212 で `modeW` が下限 48 になる（それ未満の列は 2 列にならないので扱わない）。ラベルは `modeW` − 8 に収まるまで縮み、12 px で止まる
- 候補の一行の表示（純関数。状態を入れて出す）: ノーマル・ハードで `candidates` が true、判定が 1 回以上、通知が無い、`playing` のときだけ true。デイリー・`candidates` が false・判定が無い・通知の表示中・`won` / `lost` のどれかなら false。ラウンドが替わると判定の履歴は空になる。n = 1 は「あと 1 個」
- 候補数の数え方の例: 判定の履歴に「11 → green, gray」（N = 2）が入ったとき、候補は 13・17・19 の 3 個（11 は候補にならない）
- 候補数の数え方（純関数。素数の表と判定を注入）: 判定の履歴が空で、直前の答えが無い（1 ラウンド目）とき、N = 2 / 3 / 4 / 5 / 6 で 21 / 143 / 1061 / 8363 / 68906 個（素数の個数）。2 ラウンド目以降は直前の答えを 1 つ除く（N = 2 で 20）。N = 2 で 11 に対して色の並び「green, gray」（答えの 1 桁目は 1、2 桁目は 1 ではない）なら、候補は 13・17・19 の 3 個。6 桁で判定を 1 回入れた後の数え直しが 100 ms 以内
- 候補数の受け渡し: Title の 💡 の状態が Game に渡る。Game → Title で戻ると 💡 の状態が保たれる。起動直後は `false`
- 回帰: 既存のロジックのテスト（判定・検証・ハードモード・ラウンド生成）は変更しない
