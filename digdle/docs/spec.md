# ゲーム名（仮称可）

digdle

# コンセプト（1-3 行）

Wordle 風の数当てゲーム。
お題は N 桁（2/3/4/5/6）の素数で、プレイヤーも N 桁の素数を入力して推理する。
重複数字判定は Wordle と同等ルールに従う。
ハードモードでは確定ヒントを次手以降に強制利用する。

# ターゲットプレイヤー

- 数字パズルが好きなプレイヤー
- 短時間で遊べる推理ゲームを求めるプレイヤー
- Wordle 系の手触りで数当てを楽しみたいプレイヤー

# コアループ（プレイ中に繰り返す行動）

1. N 桁（2/3/4/5/6）とモード（ノーマル/ハード）を選択する
2. N 桁の素数を入力する
3. Enter で判定し、色ヒント（green/yellow/gray）を読む
4. ヒントを使って次の素数を入力する
5. 制限回数内の正解を目指す

# 操作仕様（入力デバイスと主要操作）

- 入力デバイス: キーボード、画面上のボタン・仮想キー
- Title（開始前）:
  - 桁数ボタン `2`〜`6`、または数字キー `2`〜`6`: その桁数・選択中のモードで Game を開始する
  - モード切替ボタン（ノーマル / ハード）: タップで切り替える。選択中のモードは枠の色で強調する
- Game（プレイ中）:
  - 数字キー（0-9）: 1 文字入力
  - Backspace / ⌫: 1 文字削除
  - Enter / ⏎: 判定実行
  - 入力制約: 先頭 0 と非数字文字は入力不可
- ナビゲーション:
  - 左上 `🏠`（Title・Game 共通）: ゲーム一覧のページ（相対パス `../`）へ遷移するリンク。Scene の遷移ではない。Game の結果表示中は、`◀️` と同じく画面タップ（次のラウンド）として扱い、`../` へは遷移しない
  - 右上 `◀️`（Game のみ。Title には無い）: プレイ中に押すと Title へ戻る。選択中のモードは保持する。結果表示中も表示されるが、結果表示中のタップは画面タップ（次のラウンド）として扱う
  - 結果表示中の「桁数を選び直す」ボタン: Title へ戻る。選択中のモードは保持する

# 画面・Scene 構成

| Scene | キー | 役割 |
|---|---|---|
| Title | `Title` | 起動時の最初の Scene。名前・モード・桁数の選択。選ぶと Game を開始する |
| Game | `Game` | ラウンドの進行（盤面・仮想キーボード・結果表示） |

- 起動順: Title → Game。
- Scene 間の受け渡し:
  - Title → Game: `{ digits: 2 | 3 | 4 | 5 | 6, mode: 'normal' | 'hard' }`（開始時に 1 回。Game は受け取ったらすぐラウンドを始める。Game に桁数・モードの選択フェーズは無い）
  - Game → Title（◀️・「桁数を選び直す」）: `{ mode }`。Title は受け取った mode を選択中として強調する。Title が mode を受け取らずに始まったとき（起動直後）は `normal`
- Title:
  - 構成: 名前 `digdle`、副題、ヒント、モード切替（ノーマル / ハードの 2 ボタン）、桁数ボタン（2・3・4・5・6）、左上の `🏠`
  - 文言: ブラウザの言語が `ja` で始まれば日本語、それ以外は英語（Game と同じ判定）

    | 要素 | 日本語 | 英語 |
    |---|---|---|
    | 副題（`N` は文字のまま。桁数に置き換えない） | N桁の素数を当てよう | Guess the N-digit prime |
    | ヒント | 2 / 3 / 4 / 5 / 6 を選択 | Choose 2 / 3 / 4 / 5 / 6 |
    | モード | ノーマル / ハード | Normal / Hard |

  - 配置（画面幅 W・高さ H）: 名前・副題・ヒント・モード切替は水平中央。縦位置は「パラメータ表」の Title の行どおり。モード切替は左がノーマル、右がハード。桁数ボタンは左から 2・3・4・5・6 の順で、W が `titleNarrowWidth` 未満（narrow）なら 3 + 2 の格子（1 行目 2・3・4、2 行目 5・6。3 列分の幅 90 × 3 + 12 × 2 = 294 px を水平中央に置き、2 行目は 1 行目の左端に揃える）、それ以外は 1 行（幅 100 × 5 + 16 × 4 = 564 px）を水平中央に並べる。H が足りなくても縮小せず、はみ出しを許容する
  - 状態遷移: 無し（単一の選択画面）。モードの切替は Title に留まる。桁数ボタンまたはキー `2`〜`6` で Game を開始する（他の入力では何も起きない）。Scene を開始させた入力（キー・タップ）は、Game では処理しない（開始したキーが盤面の数字として入力されない）
  - リサイズ/回転で再レイアウトする（選択中のモードは保持）
- Game:
  - 構成: 盤面（試行回数 x N 桁）、仮想キーボード、結果表示（Clear / GameOver）、左上 `🏠`・右上 `◀️`
  - UI フェーズ: `playing`（入力中）→ `won` / `lost`（結果表示）。`playing` → `won`/`lost` は判定の結果（正解 / 試行回数を使い切る）。`won`/`lost` では、どのキー（数字・Enter・Backspace を含む）または画面タップでも、同じ N・同じモードの次ラウンドを `playing` で始める（直前と異なる正解。そのキー・タップ自体は入力として処理しない）。結果表示中の「桁数を選び直す」ボタンの位置のタップは、画面タップよりボタンの動作（Title へ戻る）を優先する。結果表示中の `🏠` / `◀️` の位置のタップは、画面タップ（次のラウンド）として扱う。「桁数を選び直す」（結果表示中）と `◀️`（プレイ中）は Title へ戻る（その時点のラウンドは破棄する）。キーの自動リピートによる keydown は、通常のキー入力として扱う（Scene を開始したキーを押し続けた場合も、リピートは入力になる）
  - 文言（ja / en。言語の判定は Title と同じ）: 結果「Clear」「GameOver」（言語によらず同じ）、不正解の開示「正解: <数> / Answer: <数>」（`lost` のみ）、ボタン「桁数を選び直す / Choose digits again」、入力が不正（桁数不一致・非素数・ハードモード違反）のときの通知は、理由を表す文（ja / en）を一時的に出す（試行回数は消費しない。文言・表示時間は現状のまま）
  - リサイズ/回転で再レイアウトする
- レイアウト（Game）:
  - 縦長: 下部ドック型キーボード
  - 横長: 右側ドック型キーボード
  - リサイズ/回転時に再レイアウト

# ルール（勝利条件、失敗条件、スコア条件）

- 勝利条件: 制限回数内に正解の N 桁素数を当てる
- 失敗条件: 制限回数を使い切る
- 試行回数:
  - N=2: 3 回
  - N=3: 4 回
  - N=4: 5 回
  - N=5: 6 回
  - N=6: 7 回
- 不正入力（桁不一致/非素数）は試行回数を消費しない
- ハードモード:
  - green 確定桁は次手以降も同じ位置に同じ数字を入力しなければならない
  - yellow 確定桁は次手以降のどこかに必ずその数字を含めなければならない
  - 同じ数字が 1 回の推測で green と yellow の両方に出た場合は、その合計個数（green の個数 + yellow の個数）以上を、次手以降の推測に含めなければならない（例: 正解 `1137` に対する推測 `1317` は green・yellow・yellow・green なので、数字 `1` を 2 個含める必要がある）
  - ハードモード違反の入力は「ルール違反」として拒否し試行回数を消費しない
  - 入力確定後、モード変更は不可（ゲーム中は固定）
- 終了後は入力ロックし、次入力で同じ N・同じモードの次ゲームへ進む
- 結果表示中の「桁数を選び直す」、またはプレイ中の `◀️` で Title へ戻れる（モードは保持。N は Title で選び直す）

# 技術要件（Phaser/Vite/ESLint/Vitest での実装方針）

- Phaser + Vite 構成を維持
- ゲームロジックは純関数として分離
  - 素数判定/生成
  - 判定ロジック
  - 入力検証
  - 状態遷移
- 乱数は `createGame({ seed?: number })` で注入可能
- 画面リサイズ時は Scene を再レイアウトし、干渉を回避
- Title と Game は別の Scene。Title の選択 UI（要素の配置・桁数ボタンの並べ方）と、両 Scene の共用部品（テキスト・ボタン・文言・`🏠`）は Phaser に依存しない値の計算を純関数に切り出して単体テストできるようにする。Scene 間の受け渡し（`{ digits, mode }`・`{ mode }`）の形も型で表す
- ESLint エラー 0 を維持
- Vitest でロジック中心にテスト

# テスト観点（最低限の単体テスト対象）

- 重複数字判定（例: 1013 vs 1111）
- Enter 時の検証順序（桁数 -> 素数 -> ハードモード制約）
- 不正入力で試行回数を消費しない
- ハードモード: green 位置違反で拒否される
- ハードモード: yellow 未包含で拒否される
- ハードモード: 同じ数字が green と yellow の両方に出た場合、合計個数に満たない推測は拒否される
- ノーマルモードではハードモード制約チェックを行わない
- seed 指定時の決定性 / 未指定時の非決定性
- 次ゲームで直前解答を避ける
- レイアウト変更でゲームロジックが壊れない
- Title の配置: 画面幅 559 は narrow（3 + 2 の格子）、560 は 1 行。名前・副題・ヒント・モード切替・桁数ボタンの縦位置が「パラメータ表」の値と一致する（H = 768 で名前の中心 y = 115、H = 400 では 72 に下限される）
- Title → Game の受け渡し: ボタン・キー `2`〜`6` で選んだ桁数と選択中のモードが Game に渡る。Title が mode を受け取らずに始まるとモードは `normal`。キー `1`・`7`・`0`・`Enter` では開始しない
- Game → Title: プレイ中の `◀️` と結果表示中の「桁数を選び直す」で Title に戻り、選択中のモード（ハードを選んでいれば強調がハード）が保持される
- Title の文言: ブラウザの言語が `ja` で始まれば日本語、それ以外（`en-US` など）は英語。副題の `N` は文字のまま
- Title のリサイズ: 幅を 560 以上から 559 以下に変えると 1 行から 3 + 2 の格子に変わる。ハードを選んだままでも強調は保持される
- Scene を開始させたキー（例: `2`）が、Game の盤面の入力として二重に処理されない
- 結果表示中: どのキーでも次ラウンドが始まり（そのキーは入力されない）、同じ N・同じモード。「桁数を選び直す」は Title へ戻る
- `🏠` の遷移先（`../`）は Title と Game（プレイ中）で同じ
- 結果表示中: `🏠` / `◀️` の位置のタップは次のラウンドを始め、Title にも `../` にも遷移しない。「桁数を選び直す」の位置のタップは Title へ戻る。プレイ中の `◀️` は Title へ戻る
- キーの自動リピートによる keydown は通常のキー入力として扱われる（結果表示中のリピートは次のラウンドを始める）
- 回帰: 既存のロジックのテスト（判定・検証・ハードモード・ラウンド生成）は変更しない
