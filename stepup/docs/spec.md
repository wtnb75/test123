# 空中足場のぼり（`stepup`・仮称）

## ゲーム名

空中足場のぼり（`stepup`）。Title には「空中足場のぼり」と、小さく `STEPUP` を出す。

## コンセプト

自動で上へ進む画面を、ジャンプと、空中で自分で作る一時的な足場で登っていく。上から降ってくる弾（垂直・斜め）をよけながら、高さ 200 m のゴールに乗ればステージ 1 クリア。ボタンは 1 つで、足が地面（足場）についていればジャンプ、空中なら足場づくりになる。

## ターゲットプレイヤー

スマホで 1 回 1〜2 分、すき間時間に遊ぶ人。主な入力はスワイプとタップ（縦持ち）。キーボード・マウスは補助。

## コアループ

1. 降ってくる弾（落ちる位置の予告つき）を見る
2. 足場に立っていればジャンプして上へ、空中なら足元に足場を作って次の踏み場を確保する（足場は同時に 2 枚まで、3 秒で消える）
3. 左右に動いて弾をよけながら登る。画面は一定の速さで上へ進み、下に取り残されると終わり
4. ゴールの足場に乗ればクリア。弾に当たるか取り残されたら失敗で、結果画面から再挑戦する

## 操作仕様

| 場面 | タッチ（主） | マウス（PC・補助） | キーボード（補助） |
|---|---|---|---|
| Title | START ボタンをタップ（押した場所で離したときに働く） | 同じ（クリック） | Space / Enter で START |
| Game | 画面のどこでも: 左右にスワイプで移動、タップでアクション（接地中=ジャンプ、空中=足場づくり）、スワイプ中は 2 本目の指のタップでアクション | ドラッグで移動、クリックでアクション | ← → で移動、Space または ↑ でアクション |
| Result | 「もう一度」「タイトルへ」をタップ（押した場所で離したときに働く） | 同じ（クリック） | Space / Enter で「もう一度」 |

### Game のタッチ・マウス操作（指ごとの決まり）

- 指（ポインタ）は押した瞬間に、次のどれかの役割になる:
  - **候補**: 画面に他の「候補」「移動」の指が 1 本も無いときに押された指。タップにもスワイプにもなりうる
  - **移動**: 候補の指が `TAP_MAX_MOVE` を超えて動いた（押した点からの直線距離 > `TAP_MAX_MOVE`）と、その瞬間から移動になる。移動の間は、押した点の x を基準点にして、指の x から `swipeStep` で向き（−1 / 0 / +1）を毎回決める
  - **無視**: 画面に「候補」または「移動」の指がすでにある状態で押された指。押した瞬間にアクションを 1 回行い、以後は何もしない（動かしても移動にならない）。これでスワイプしている指を離さずに、もう 1 本の指でジャンプ・足場づくりができる
- 候補の指は、離したとき、押してから離すまでが `TAP_MAX_MS` 以下（ちょうども含む）ならタップとしてアクションを 1 回行う。`TAP_MAX_MS` を超えて動かさずに離した指は、何もしない。離した場所がキャンバスの外でも同じ
- `swipeStep(基準点, 指の x)`: 指が基準点から `SWIPE_RADIUS` を超えて離れたら、基準点を「指から `SWIPE_RADIUS` 離れた位置」まで動かす。そのあと、指 − 基準点 が `SWIPE_DEAD` を超えて正なら +1、超えて負なら −1、それ以外は 0。指を止めたまま押さえていると、向きは保たれる（動き続ける）。逆向きに戻すと、基準点が指に追従しているので `SWIPE_RADIUS` より小さい動きで反転する
- 「候補」「移動」の指は、同時に 1 本までしか無い（2 本目以降は押した瞬間に「無視」になるため）。移動の向きは、キーボードの向き（← = −1、→ = +1）と、「移動」の指 1 本の向き（無ければ 0）を足して、−1〜+1 に収めたもの
- Game を始める前から押されていた指と、「縦にしてください」の案内が出ている間に押された指は、役割を持たない（数えない）。離すまで何もせず、案内が消えても役割は持たない。案内が出た瞬間にすでに押されていた指（候補・移動・無視）は、アクションなしで離したのと同じに扱い、役割を消す（移動の向きも 0 に戻る。案内が消えたあとも、その指は役割を持たない）
- アクションは、Game が `playing` の間だけ受け付ける。Game を始める前から押されていた指（START を押した指など）は、離すまで何もしない。ポインタが cancel されたら、その指は離したのと同じに扱うが、アクションは行わない
- キーボードのアクションは押した瞬間に 1 回だけ（押しっぱなしのリピートは無視）。Title の START と Result の「もう一度」のキー（Space / Enter）も同じで、押した瞬間にだけ働く（Game 中から押しっぱなしの Space が、Result のガード明けのリピートで働かない）。Ctrl / Alt / Meta を押しながらのキーは無視する

### その他

- 同じフレームに複数の入力が来たら、届いた順に処理する。アクションは次のフレームの更新の最初（下の「Game の 1 フレームの順序」）で適用する
- 「縦にしてください」の案内が出ている間は、すべての入力を受け付けない（下の「画面の大きさ」）
- Result を始めてから `RESULT_INPUT_GUARD_MS` の間は、ボタンとキー（Space / Enter）を受け付けない（終わりの瞬間まで連打していたタップが、そのまま「もう一度」を押さないため）。ボタンは押した時刻で判定する（ガード中に押した指は、ガード明けに離しても働かない）
- タップの的: Game は画面全体なので 44 px の問題は無い。ボタンは `BUTTON_W` × `BUTTON_H`（実寸 44 px 以上になるのは縮小率 0.79 以上）

## 画面・Scene構成

| Scene | 役割 |
|---|---|
| Title | ゲーム名・遊び方・START ボタン |
| Game | プレイ。HUD（高さ）・足場・弾・予告・自分・ゴール |
| Result | クリア／失敗の結果。到達した高さ・2 つのボタン |

### 画面の大きさ（論理サイズ）

- 幅は `SCREEN_WIDTH` で固定。高さは `round(SCREEN_WIDTH × 表示の高さ / 表示の幅)` を `[SCREEN_HEIGHT_MIN, SCREEN_HEIGHT_MAX]` に収めた値 H にする。Title に入ったとき、Title にいる間に表示の大きさが変わったとき、Game を始めるとき（START と「もう一度」）に決め直す。Game・Result の間は変えない。Phaser の `Scale.FIT` で中央に置く
- 手計算の例（縮小率 = `min(表示の幅 / 論理の幅, 表示の高さ / H)`）:

| 表示の大きさ | 論理の大きさ | 縮小率 | 黒帯 |
|---|---|---|---|
| 390 × 844（スマホ縦） | 360 × 779 | 1.083 | なし |
| 375 × 550（iPhone SE 縦） | 360 × 528 | 1.042 | なし |
| 1280 × 720（PC） | 360 × 520（下限） | 1.385 | 左右に計 61%。縦持ちを前提にしたゲームなので許容する（文字・ボタンは十分に大きい） |
| 667 × 310（スマホ横） | 360 × 520（下限） | 0.596 | 案内を出す（下） |

- 表示が横長（幅 > 高さ）で、縮小率が `ROTATE_PROMPT_SCALE` 未満のとき（667 × 310 は 0.596、844 × 390 は 0.75。0.875 以上は出ない）は、どの Scene でも、その上に「画面を縦に」「してください」の 2 行の案内を全面に出す。この間 Game は進行を止め（時間・スクロール・弾・予告・足場の寿命・`RESULT_DELAY` が進まない）、Title・Result も入力を受け付けない。表示の大きさが変わって条件を外れたら案内を消して続きから再開する。案内の文字の大きさは、論理で `min(ceil(PROMPT_REAL_FONT_SIZE ÷ 縮小率), PROMPT_MAX_FONT_SIZE)`（縮小率が 0 以下なら `PROMPT_MAX_FONT_SIZE`）。PC（縮小率 1.385）や 1024 × 768（1.477）には出ない。縦長の表示（幅 ≤ 高さ）には出ない。想定外として、幅が約 315 px 未満の端末は、文字が小さくなるが対応しない

### 文字の大きさ（論理 px。実寸 = 論理 × 縮小率）

主な情報は実寸 14 px 以上、補助は 11 px 以上（AGENTS.md 4.6）。縦持ちの縮小率は、幅 320 px の端末でも 0.89 以上。

| 要素 | 論理 | 実寸（縮小率 0.89 / 1.04） | 区分 |
|---|---|---|---|
| HUD（`137 / 200 m`） | `FONT_HUD` 18 | 16 / 19 | 主 |
| Game の操作ヒント | `FONT_HINT` 14 | 12.5 / 14.6 | 補助 |
| Title の `STEPUP`・ステージ名 | `FONT_SUB` 16 | 14.2 / 16.6 | 主 |
| Title の説明 | `FONT_HELP` 14 | 12.5 / 14.6 | 補助 |
| Result の「ステージ 1」・理由・高さ | `FONT_RESULT` 18 | 16 / 19 | 主 |
| ボタンの文字 | `FONT_BUTTON` 18 | 16 / 19 | 主 |

Title のゲーム名は `FONT_TITLE` 36、Result の「クリア！」「ゲームオーバー」は `FONT_RESULT_TITLE` 32（どちらも見出し）。主な情報（論理 16 以上）は補助（論理 14 以下）より小さくならない。`ROTATE_PROMPT_SCALE`（0.875）のとき、`FONT_SUB`（16）は実寸 14、補助（14）は 12.25 で基準を満たす（14 ÷ 16 = 0.875 から決めた）。

### Game

- 世界の座標は y が下向き。スクロールは視点（画面の上端）の y（`viewTop`）が減ることで表す。以下の位置はすべて世界の y
- 配置（論理の高さ H）:
  - 開始の足場（地面）の上面 y = `startY` = `round(H × START_Y_RATIO)`。`viewTop` の初期値は 0（つまり開始時、足場は画面の縦の中央に見える）。自分は画面の横の中央で、足が `startY`
  - ゴールの足場の上面 y = `goalY` = `startY − GOAL_METERS × PX_PER_METER`
  - HUD: 画面の左上（x = 8、上端 y = 6）に `137 / 200 m`（到達した高さ / `GOAL_METERS`。下がっても減らない。画面に固定）
  - 操作ヒント: 開始の足場の下（世界に固定。画面と一緒には動かず、足場と一緒に下へ流れて消える）に 2 行（`FONT_HINT`、横中央）。1 行目「左右にスワイプで移動」（中心 y = `startY + 50`）、2 行目「タップ: ジャンプ ／ 空中で足場」（中心 y = `startY + 74`）
- 開始の足場とゴールの足場は、横幅が画面より広く（左右の端をまたぐ）、寿命は無い。開始の足場の厚さは `PLATFORM_H`、ゴールは `GOAL_H`。ゴールの足場は、他の足場と違う色（緑系）にする
- 自分は `PLAYER_W` × `PLAYER_H` の長方形（x は中心、y は足の位置）。当たり判定は見た目と同じ。x は `[PLAYER_W / 2, SCREEN_WIDTH − PLAYER_W / 2]` に収める。開始時の状態は `onGround = true`・`vy = 0`・`lock = 0`（開始の足場の上に立っている）。したがって、開始直後のアクションはジャンプになる
- 描画の順（奥から手前へ）: 操作ヒント < 足場（開始・ゴール・作った足場）< 土煙 < 弾 < 自分 < 紙吹雪 < 下端の帯 < 進行バー < 予告 < HUD（演出の層は「演出・UI（Game）」）。弾は HUD の下を通る。予告は HUD と重ならない位置（`WARN_Y`）に出る
- 状態と遷移:

| 状態 | 内容 | 次へ進む条件 |
|---|---|---|
| `playing` | 入力を受け付ける。スクロール・弾・足場の寿命・物理が進む | 終わりの判定（下）のどれかが成立した → `ending`（結果の種類と高さを記録） |
| `ending` | 時間・スクロール・弾・予告・足場・入力をすべて止める（画面はそのまま残す。演出の時計だけは進み、失敗・クリアの合図と、出ている土煙が最後まで動く） | `RESULT_DELAY` 秒たった → Result へ（結果の種類・高さを渡す） |

- Game の 1 フレームの順序（`dt` は実時間の差を `DT_MAX` で打ち切ったもの）:
  1. 入力の適用: たまっていたアクション（`pressAction`）を届いた順に 1 つずつ処理する
  2. 足場の年齢を `dt` 進め、寿命（`PLATFORM_LIFE`）に達した足場を消す。足場づくりのロックを `lock = max(0, lock − dt)` にする
  3. スクロール: `viewTop = max(goalY − GOAL_VIEW_MARGIN, viewTop − scrollSpeed(高さ) × dt)`（ゴールが画面の上端から `GOAL_VIEW_MARGIN` の位置に来たら止まる）
  4. 自分の移動を進める: x を `向き × MOVE_SPEED × dt` だけ動かして収め、`vy += GRAVITY × dt`（`MAX_FALL` で頭打ち）、足の y を `vy × dt` だけ動かす。`onGround` をいったん偽にして、一方通行の足場への着地の判定（前のフレームの足 = このステップの最初の足の y）で着地できたら真にする。そのあと画面の上端より上に出ないよう押し戻す。足場を作った直後のフレームは、前の足 = 作った足場の上面なので、その足場にすぐ着地する
  5. 最高到達の更新（足の y の最小値。下がっても高さは減らない）
  6. 弾（この順に行う）: (a) すでにある弾を動かす（x += `vx × dt`、y += `vy × dt`）。(b) すでにある予告の残り時間を `dt` 進め、0 以下になった予告を弾にする（弾は予告の x、`viewTop − BULLET_R` に置き、そのフレームでは動かさない）。(c) 出現タイマーを `dt` 進め、0 以下になったら予告を `bulletsPerSpawn` 個出して次の間隔にする（新しい予告の残り時間は `WARN_TIME` から始め、出したフレームでは引かない）。そのあと、画面の下端より `BULLET_OFFSCREEN` 下、または左右の端から `BULLET_OFFSCREEN` 外に出た弾を消す
  7. 終わりの判定（優先順位: 弾に当たった > 取り残された > クリア）。複数が同じフレームで成立したら、いちばん優先順位の高いものを結果にする
- 終わりの判定:
  - **弾に当たった**（結果 `hit`）: いずれかの弾（円）と自分（長方形）が重なる（円の中心から長方形までの最短距離 ≤ `BULLET_R`）
  - **取り残された**（結果 `left-behind`）: 自分の頭（足の y − `PLAYER_H`）が画面の下端（`viewTop + H`）より下（厳密に超える）
  - **クリア**（結果 `clear`）: 足が地面についていて（着地している）、足の y が `goalY + 0.5` 以下
- 予告と弾の出現（ステージ 1）:
  - 最初の予告は開始から `FIRST_SPAWN_DELAY` 秒後。以後は、出すたびに `spawnInterval(高さ)` 秒後に次を出す
  - 出現タイマーが 0 以下になったら予告を出し、タイマーは余りを持ち越さず `spawnInterval(高さ)` に戻す。1 回に出す予告の数は `bulletsPerSpawn(高さ)`（高さ < `DOUBLE_SPAWN_METERS` で 1、以上で 2）。高さは予告を出す時点の値
  - 予告 1 個ごとに、乱数を x、種類（斜めか垂直か）、向き（斜めの左右）の順に 1 回ずつ引く。x は `[BULLET_X_MARGIN, SCREEN_WIDTH − BULLET_X_MARGIN]` の一様乱数。`vx` は `pickBulletVx`、`vy = bulletSpeed(高さ)`。この `vx`・`vy` は予告を出した時点で決まり、弾に引き継がれる
  - 予告は画面の上端近くに出る三角形で、弾の飛ぶ向きを指す（垂直は真下、斜めは傾く）。傾きは真下から `atan2(vx, vy)`（世界座標での向き。画面はスクロール分だけ縦に動くので、画面上の弾の向きはこれよりわずかに立つ。m = 0 で約 28.8°、m = 100 で約 21.4°、m = 200 で約 17.0°）。中心は画面の上端から `WARN_Y` 下で、予告の x に置く。画面に固定（スクロールしても画面の上端から同じ距離にある）
  - 予告が `WARN_TIME` 秒たつと、その x、`viewTop − BULLET_R`（画面の上端のすぐ外）から、引き継いだ `vx`・`vy` で弾が動き出す。予告は消える
  - 弾は `BULLET_R` の円で、画面の外へ出るまで直進する（足場や自分には当たっても消えない。自分に当たったら終わり）
- 「高さ」（m）: 到達した最高点と開始位置の差。`(startY − 足の y の最小値) ÷ PX_PER_METER`。HUD・Result の表示は、切り捨てた整数を `GOAL_METERS` で頭打ちにした値（開始時 0、ゴールの足場の上で 200。ゴールの足場は下から通り抜けられるので、200 m を超えて跳んでも表示は 200）。難易度の式（`scrollSpeed` など）には切り捨てない実数を使う
- Result へ渡すもの: 結果の種類（`clear` / `hit` / `left-behind`）、高さ（切り捨てた整数）
- 画面外に出た弾・消えた足場・予告はその場で捨てる。リトライ（Game を始め直す）では、足場・弾・予告・タッチの状態・タイマーが残らない

#### 演出・UI（Game）

ルール・当たり判定・数値には触れない、見た目だけの変更。どの演出も入力を遅らせず（入力の受け付けは「操作仕様」のまま。`ending` の間は入力を受け付けない）、ルールの判定は演出の状態を読まない。

**共通の規則**

- 時間: 演出の時計は、Game の `update` で進める `dt`（`DT_MAX` で打ち切った値）の合計。「縦にしてください」の案内の間は止まる（演出も止まる）。`ending` の間は進み続ける（`RESULT_DELAY` の 0.8 秒のあいだ）。ただしカメラの揺れ（`camera.shake`）は Phaser 自身の時計で動き、この時計の対象外（最長 250 ms で 0.8 秒以内に終わる）
- 時間の規則: 演出の「経過時間 t」は、きっかけのフレームで t = 0、長さ D ちょうどで消える（D 以降は何も描かない）。同じ演出のきっかけがもう一度来たら、新しいものを足す（上限は各項目）
- 描画の順（奥から手前へ）: 操作ヒント < 足場 < 土煙 < 弾 < 自分 < 紙吹雪 < 下端の帯 < 進行バー < 予告 < HUD（弾は HUD・進行バー・下端の帯の下を通る。紙吹雪と土煙は世界の座標、帯・バー・予告・HUD は画面に固定）
- 状態の持ち越し: 演出の状態（土煙・紙吹雪・揺れ・点滅）は、Game を始め直すとすべて消える（`ending` から Result へ移るときも、カメラの揺れを止めて残さない）
- 画面の端: 土煙・紙吹雪は画面の外へはみ出してよい（小さく、すぐ消える）。予告の三角は、拡大した結果が画面の外に出るときは、はみ出さない最小の量だけ横にずらして描く（弾の位置は変えない）。帯・バーは画面の内側に収まる

**1. 下端の危険表示（`playing` と `ending`）**

- 常に画面の下端に、高さ `DANGER_H` の赤い帯を重ねる。不透明度 = `dangerAlpha(足の y, 画面の下端 y)`（画面の下端 y = `viewTop + H`）。足が下端から `DANGER_RANGE` 以上上にあれば 0、下端に近づくほど増えて、下端ちょうどとそれより下では `DANGER_MAX_ALPHA`。式: `DANGER_MAX_ALPHA × clamp((足の y − (下端 y − DANGER_RANGE)) ÷ DANGER_RANGE, 0, 1)`
- `ending` の間は、`left-behind` 以外では止まった状態のまま表示する（その時点の濃さ）。`left-behind` で終わったときは、「3. 失敗の合図」のとおり点滅する

**2. 進行バー（`playing` と `ending`）**

- 画面の右端に縦のバー（幅 `BAR_W`、右端から `BAR_RIGHT` の位置）。上端 y = `BAR_TOP`、下端 y = H − `BAR_BOTTOM_MARGIN`。薄い色の溝を全長に引き、下端が 0 m、上端がゴール（`GOAL_METERS`）。現在の高さの印（横長の小さな長方形 `BAR_MARKER_W` × `BAR_MARKER_H`、中心 x = バーの中心 x（W − 6。印は x = W − 12〜W）、中心 y = `barMarkerY(m, H)`）と、上端にゴールの印（緑の同じ大きさの長方形）を出す
- 印の位置は、切り捨てない実数の高さ m を `[0, GOAL_METERS]` に収めて決める: `barMarkerY = (H − BAR_BOTTOM_MARGIN) − (clamp(m, 0, GOAL_METERS) ÷ GOAL_METERS) × (H − BAR_BOTTOM_MARGIN − BAR_TOP)`。H = 528 では、0 m で 512、100 m で 284、200 m で 56。下がっても印は戻らない（高さは最高点なので）
- HUD（左上）と重ならない（バーは HUD より下から始まり、右端にある）。予告はバーより手前に描かれるので、画面の右端近く（x ≈ 346）の斜めの予告が脈動で拡大したとき、先端がゴールの印（y = 54〜58）と数 px 重なってよい（予告が手前）
- 現在の印とゴールの印が同じ位置（200 m）になったときは、現在の印を手前に描く（ゴールの印は緑、現在の印は別の明るい色。細部は実装裁量）

**3. 失敗の合図（`ending`）**

- きっかけ: `playing` から `ending` に入るフレーム（t = 0）。結果ごとに次のとおり
  - `hit`: カメラを `SHAKE_MS` 秒、強さ `SHAKE_INTENSITY` で揺らす（Phaser の `camera.shake`）。自分を `ENDING_BLINK_S` ごとに赤と通常の色で切り替える（t = 0 は赤。`floor(t ÷ ENDING_BLINK_S)` が偶数なら赤、奇数なら通常）。点滅は `ending` の間ずっと続く。HUD も画面に固定なので、揺れの間は一緒に揺れる
  - `left-behind`: 揺らさない。成立した時点で自分は画面の下端より下（画面の外）にいるので、代わりに下端の帯を点滅させる: 不透明度 = `DANGER_MAX_ALPHA`（t = 0 から）と `DANGER_MAX_ALPHA ÷ 2` を `ENDING_BLINK_S` ごとに切り替える（`floor(t ÷ ENDING_BLINK_S)` が偶数なら `DANGER_MAX_ALPHA`、奇数なら半分）。自分の色は通常のまま（見えない）
  - `clear`: 次の項目（クリアの合図）。揺らさない・自分の色は通常
- 同じフレームに複数の終わりが成立しても、結果は 1 つなので、合図も 1 つ（優先順位は `hit` > `left-behind` > `clear`）

**4. クリアの合図（`ending`、結果が `clear`）**

- ゴールの足場を、`ENDING_BLINK_S` ごとに不透明度 1 と `GOAL_BLINK_ALPHA` で切り替える（t = 0 は 1。`floor(t ÷ ENDING_BLINK_S)` が偶数なら 1、奇数なら `GOAL_BLINK_ALPHA`）
- 自分の中心（x、足の y − `PLAYER_H` ÷ 2）から、紙吹雪 `CONFETTI_COUNT` 個（`CONFETTI_SIZE` 四方の正方形）が上向きに散る。i 番目（0 から）の初速の向きは `−π + π × (i + 0.5) ÷ CONFETTI_COUNT`（x 軸からの角度。y は下向きが正なので、すべて上半分）、速さは `CONFETTI_SPEED + CONFETTI_SPEED_STEP × (i mod 3)`。位置 = 出発点 + 初速 × t + (0, ½ × `CONFETTI_GRAVITY` × t²)、不透明度 = `1 − t ÷ CONFETTI_S`（t ≥ `CONFETTI_S` で消える）。色は 3 色を i の順に巡る（細部は実装裁量）
- `clear` を除く結果では出さない

**5. ジャンプ・着地の土煙、足場づくり（`playing`。`ending` の扱いは本文）**

- 土煙のきっかけ（1 フレームの更新の前後の `onGround` と `vy` から決める。`ending` に入るフレームの移動も数える: そのフレームのジャンプ・着地も t = 0 で土煙を出す。例: ゴールの足場に落ちて着地した `clear` のフレームは、着地前の `vy ≥ LAND_PUFF_MIN_VY` なら土煙も出て、紙吹雪と同時に動く）: ジャンプ = 更新の前に `onGround` が真で、後に偽かつ `vy < 0`。着地 = 更新の前に `onGround` が偽で、後に真、かつ更新の前の `vy ≥ LAND_PUFF_MIN_VY`。ジャンプと着地は同じフレームに起きない。足場の端から歩いて出ただけ（後の `vy ≥ 0`）では出さない
- 土煙: 足元（自分の x、足の y − 2）に、円 `PUFF_COUNT` 個を、x 方向に `PUFF_SPACING` ずつ間隔を空けて並べる（中心から `(k − 1.5) × PUFF_SPACING`、k = 0〜3）。半径は t = 0 で `PUFF_R0`、`PUFF_S` で `PUFF_R1`（直線で増える）、不透明度は `PUFF_ALPHA × (1 − t ÷ PUFF_S)`（t ≥ `PUFF_S` で消える）。同時に残る土煙は `PUFF_MAX` 組まで（超えたら古いものから消す）
- 足場づくり: 作った足場の見た目の幅は `platformDrawWidth(年齢)` = `PLATFORM_W × min(1, 年齢 ÷ PLATFORM_GROW_S)`（中心は同じ）。描画に使う年齢は、そのフレームの手順 2（年齢を `dt` 進める）のあとの値（作ったフレームの描画は年齢 `dt`。`dt` = 1/60 s で幅 13.3 px）。足場の判定の幅は、作った瞬間から `PLATFORM_W` のまま（広がるのは見た目だけ）
- `ending` の間は足場の年齢が止まるので、広がり・点滅（6）も、その時点の見た目のまま止まる

**6. 足場が消える直前の点滅（`playing`。`ending` の間は止まった見た目）**

- 作った足場の年齢が `PLATFORM_LIFE − PLATFORM_BLINK_WARN_S` 以上になったら、`PLATFORM_BLINK_S` ごとに、寿命による不透明度（`platformAlpha`）と `PLATFORM_BLINK_ALPHA` を切り替える。k = `floor((年齢 − (PLATFORM_LIFE − PLATFORM_BLINK_WARN_S)) ÷ PLATFORM_BLINK_S)` が偶数なら `platformAlpha`、奇数なら `PLATFORM_BLINK_ALPHA`（最初の 0.1 秒は通常から始まる）。開始・ゴールの足場には適用しない

**7. 予告の脈動（`playing`。`ending` の間は止まった見た目）**

- 予告の残り時間 r ≤ `WARN_PULSE_S` のとき、三角形を中心を保ったまま拡大・縮小する。倍率 = `1 + WARN_PULSE_SCALE ÷ 2 × (1 − cos(2π × (WARN_PULSE_S − r) ÷ WARN_PULSE_PERIOD))`（r = `WARN_PULSE_S` で 1.0、`WARN_PULSE_PERIOD` の半分で 1 + `WARN_PULSE_SCALE`、1 周期で 1.0 に戻る）。r > `WARN_PULSE_S` では 1.0
- `ending` の間は止まったまま（その時点の倍率を保つ）

**テストの手がかり**: 上の式は Scene の外の純関数（`dangerAlpha`、`barMarkerY`、`playerLook`、`goalBlinkAlpha`、`confettiParticle`、`moveEvents`、`puffParams`、`platformDrawWidth`、`platformEffectAlpha`、`warnPulseScale`、はみ出さないための横ずらし）にして、手計算の値で確かめる。揺れ・描画・レイヤーの重なりは Scene のグルーで、QA で確認する。

### Result

- 上から順に（H = 528 の例の中心 y）: 「ステージ 1」（`FONT_RESULT`。y = 100）、結果の見出し（`FONT_RESULT_TITLE`。`clear` は「クリア！」、`hit`・`left-behind` は「ゲームオーバー」。y = 146）、理由の行（`FONT_RESULT`。`clear`「ゴールにとうたつ！」、`hit`「弾に当たった」、`left-behind`「下に取り残された」。y = 196）、高さの行（`FONT_RESULT`。`高さ 137 / 200 m`。`clear` は `高さ 200 / 200 m`。y = 232）、ボタン 2 つ（`BUTTON_W` × `BUTTON_H`）: 「もう一度」の中心 y = H − `RESULT_BUTTON1_FROM_BOTTOM`（388）、「タイトルへ」の中心 y = H − `RESULT_BUTTON2_FROM_BOTTOM`（458）。2 つのボタンの間は 14 px 以上空き、下端は H より内側
- 「もう一度」は Game を始め直す（画面の大きさを決め直す）。「タイトルへ」は Title へ。状態は 1 つ

#### 演出・UI（Result）

- ボタンの強弱: 「もう一度」は主ボタン（今の青）、「タイトルへ」は控えめなボタン（暗い灰青の塗りと細い縁）にする。どちらも文字は `FONT_BUTTON` の白で、塗りとの明るさの比（WCAG のコントラスト比）が 4.5:1 以上になる塗りにする（暗い灰青なら例えば `0x3a4460` で約 9.6:1）。位置・大きさ・押す・ホバーの仕組みは変えない。主ボタンのほうが、塗りの明るさ・彩度が高く、一目で次の操作だと分かること（色の細部は実装裁量）
- Title の START は今のまま（主ボタンと同じ青）。ただし主ボタンのホバーの塗りは、白文字とのコントラスト比 4.5:1 を保つため、以前（MVP）のホバーの色より少し暗い青にしてある（Title の START も同じ。押した色・通常の色は変えない）。Title・Result のほかの見た目は変えない

## ルール

- **勝利条件**: ゴールの足場の上に立つ（結果 `clear`）。クリアすると Result へ。次のステージは無い（MVP）
- **失敗条件**: 弾に当たる、または画面の下端に取り残される（結果 `hit` / `left-behind`）。失敗しても何も失わず、Result から何度でもやり直せる
- **スコア**: 無い（クリアしたかどうかと、到達した高さを Result に出す）。記録の保存はしない
- **画面のスクロール**: 画面は常に一定に近い速さで上へ進む（`scrollSpeed(高さ)`）。ゴールが見える位置まで来たら止まる
- **ジャンプ・足場（アクション）**:
  - 自分が地面（足場の上）に立っている（`onGround`）とき: ジャンプ。上向きの速さが `JUMP_SPEED` になり、足場づくりのロック `lock` が `JUMP_LOCK` 秒になる
  - 空中のとき: 足元（自分の x が中心、足の y が上面）に、幅 `PLATFORM_W`・厚さ `PLATFORM_H` の足場を作る。ただし `lock` が 0 より大きい間（地面からのジャンプの直後 `JUMP_LOCK` 秒）は何も起きない。足場の端から歩いて出て落ち始めたときは `lock` が 0 なので、すぐ作れる
  - 作った足場（寿命のあるもの）は同時に `MAX_PLATFORMS` 枚まで。超えると、いちばん古いものが消える。開始の足場・ゴールの足場は数えない
  - 作った足場は `PLATFORM_LIFE` 秒で消える。寿命が近づくにつれて薄くなる（不透明度は 1 から `PLATFORM_MIN_ALPHA` へ、年齢に比例して減る）
- **足場の乗り方（一方通行）**: 下から上へ通り抜けられる。落下中（`vy ≥ 0`）に、前のフレームの足が足場の上面と同じかそれより上にあり、いまの足が上面に届いた（同じかそれより下）、かつ x が重なっている（`|自分の x − 足場の x| < 足場の幅 / 2 + PLAYER_W / 2`）とき、上面に着地して `vy = 0`、`onGround` になる。複数の足場が同時に条件を満たしたら、上面がいちばん高い（y がいちばん小さい）足場に着地する
- **移動**: 左右は `MOVE_SPEED` で一定。空中でも同じ。重力は `GRAVITY`。落下速度は `MAX_FALL` まで
- **上端**: 自分の頭が画面の上端（`viewTop`）より上に出ない（出たら、頭が上端に揃う位置に戻し、上向きの速さは 0 にする）。上端に出ると弾の出現位置より上に逃げられてしまうため
- **難易度**: 高さ m に応じて次のとおり（式は下の「パラメータ表」）。難しさは主に弾で上げ、スクロールはゆっくり

  | 高さ m | 0 | 8 | 50 | 90 | 100 | 141.3 | 200 |
  |---|---|---|---|---|---|---|---|
  | `scrollSpeed`（px/s） | 32.0 | 32.4 | 34.5 | 36.5 | 37.0 | 39.1 | 42.0 |
  | `bulletSpeed`（px/s） | 200 | 206.4 | 240 | 272 | 280 | 313.0 | 360 |
  | `spawnInterval`（s） | 1.2 | 1.168 | 1.0 | 0.84 | 0.8 | 0.635 | 0.45（下限。m ≥ 187.5 で到達） |
  | 斜めの割合 | 0（m < 8） | 0.25 | 0.376 | 0.496 | 0.526 | 0.65（上限） | 0.65 |
  | `bulletsPerSpawn` | 1 | 1 | 1 | 2 | 2 | 2 | 2 |

  （`scrollSpeed` と `bulletSpeed` の上限 45 / 380 は 200 m までには届かない）
- **乱数**: 予告の x、斜めか垂直か、斜めの左右だけが乱数。足場・物理・当たり判定・難易度の式は乱数を使わない

## 技術要件

- Phaser 4 + Vite + TypeScript。描画は Phaser の Graphics / Text で行い、画像アセットは使わない（スキャフォールドのテンプレートの画像は使わなければ消す）
- ESLint エラー 0、Vitest のカバレッジは 4 指標とも 90% 以上
- Scene は Title / Game / Result に分け、`preload` / `create` / `update` の責務を混ぜない。入力イベント（ポインタ・キー）は Scene の終了時に外す。毎フレームの処理は、物理・スクロール・弾・予告・足場の寿命に絞り、`update` 中の無駄なオブジェクトの生成を避ける。描画は Graphics を 1 つ使い、毎フレーム描き直してよい
- Phaser に依存しない純ロジック（役割ごとのモジュールに分ける）:
  - 自分の物理: 左右の移動と収め、重力・落下速度の上限、一方通行の足場への着地、画面の上端への押し戻し
  - アクション（`pressAction`）: ジャンプ / 足場づくり / 何も起きない（ロック中）の判定、足場の同時枚数の管理（古い順に消す）、足場の年齢と寿命、足場の不透明度
  - 高さ（`meters`）と、`scrollSpeed` / `bulletSpeed` / `spawnInterval` / `bulletsPerSpawn` / 斜めの割合 / `pickBulletVx`（乱数を引数で受け取る）
  - 弾の出現（予告のタイマー・数・x の抽選）、弾の移動、画面外で消す条件、予告の三角形の向き（傾き）
  - 当たり判定（円と長方形）、取り残された判定、クリア判定、終わりの判定の優先順位（`hit` > `left-behind` > `clear`）
  - タッチの状態遷移（指ごとの役割の決まり、`swipeStep`、タップの判定）を、「押した・動いた・離した（時刻つき）」のイベントから向きとアクションの回数を返す純関数（または小さなクラス）にする
  - 画面の大きさ（論理の高さ、縮小率、案内を出す条件、案内の文字の大きさ）、Title・Result の配置の計算（H から各 y）
  - Result の見出し・理由・高さの行の文字の組み立て
  - 演出の値の決定（Scene の外の純関数）: `dangerAlpha`、`endingDangerAlpha`（`left-behind` の `ending` の帯の点滅）、`barMarkerY`、`playerLook`（結果と経過時間から自分の色）、`goalBlinkAlpha`、`confettiParticle`（i 番目の経過時間 t から位置・不透明度）、`moveEvents`（更新の前後の `onGround`・`vy` からジャンプ・着地のきっかけ）、`puffParams`（経過時間から半径・不透明度）、`platformDrawWidth`、`platformEffectAlpha`（寿命による不透明度と点滅）、`warnPulseScale`、予告の三角が画面から出ないための横ずらし。揺れ（`camera.shake`）・描画・層の重なりは Scene のグルー
- 乱数は `rng: () => number`（[0, 1)）を引数で渡す。時間は `dt` を引数で渡す。純ロジックの中で `Math.random` や `Date` を使わない。タッチの時刻は引数（ミリ秒）で渡す

## テスト観点

- ジャンプ: 地面でアクション → `vy = −JUMP_SPEED`・`lock = JUMP_LOCK`・空中。`dt = 1/60` で積み上げたときの頂点が 99〜101 px（半陰的 Euler: 毎ステップ `vy += GRAVITY × dt`、そのあと `y += vy × dt`。連続の式の理論値 104.5 px より約 4.6 px 低い）
- 足場づくり: 空中でアクション（`lock` = 0）→ 足元（x = 自分の x、上面 = 足の y）に幅 `PLATFORM_W` の足場。ロック中（ジャンプから 0.25 秒）は何も作られない。ロックが明けた（0.35 秒）あとは作れる。足場の端から歩いて出て落ちたときは、ロックが 0 なのですぐ作れる。ロックの境界（ちょうど 0.3 秒）は浮動小数で揺れやすいので、境界の両側で確かめる
- 同時枚数: 3 回作ると最古が消えて 2 枚。開始・ゴールの足場は数えない。寿命: 年齢が `PLATFORM_LIFE`（3.0 s）に達した足場が消える（2.99 s で残り、3.0 s で消える）。不透明度は年齢 0 で 1、1.5 s で 0.65、3.0 s で 0.3
- 一方通行: 上昇中は足場を通り抜ける。落下中、前のフレームで足が上面より上、いまのフレームで上面以下 → 着地。ちょうど上面（前も同じ高さ）は着地。x の重なり: `|dx| < PLATFORM_W / 2 + PLAYER_W / 2`（= 50）で着地、50 ちょうどは着地しない、49.9 は着地する。足が上面を通り過ぎて上へ出たあと、落ちてきたら着地する
- 物理: 左右の端で止まる（x が `[10, 350]`）。落下速度が `MAX_FALL` で頭打ち。画面の上端への押し戻し: 頭が上端より上なら頭が上端に揃い、上向きの速さは 0（下向きの速さは保たれる）
- 高さ: 開始で 0、`startY − 足の y` を `PX_PER_METER` で割る。下がっても減らない。HUD・Result は切り捨て（199.9 → 199、200 ちょうど → 200）
- 難易度の式（表の値）: `scrollSpeed` 0 → 32、200 → 42、上限 45（m = 260 以上）。`bulletSpeed` 0 → 200、100 → 280、225 以上で 380。`spawnInterval` 0 → 1.2、100 → 0.8、187.5 以上で 0.45。斜めの割合: m = 7.99 → 0、8 → 0.25、100 → 0.526、141.34 以上で 0.65。`bulletsPerSpawn`: 89.99 → 1、90 → 2
- 弾の向き（`pickBulletVx`）: 割合 0.25（m = 8）のとき `randKind = 0.249` で斜め、`0.25` で垂直（境界）。斜めのとき `randSign < 0.5` で −`BULLET_VX`、以上で +`BULLET_VX`。m < 8 は常に 0。予告の傾き = `atan2(vx, vy)`: m = 0（`vy` = 200）で ≈ 0.503 rad（28.8°）、m = 100（`vy` = 280）で ≈ 0.374 rad（21.4°）、m = 200（`vy` = 360）で ≈ 0.297 rad（17.0°）。傾きの符号と `vx` の符号が一致し、垂直弾（`vx` = 0）は 0。弾は予告のときの `vx`・`vy` で動き出す（予告から弾になる間に高さが変わっても変わらない）
- 弾の出現: 最初の予告は 1.0 秒後（0.99 秒ではまだ、1.0 秒でちょうど出る）。予告は、出したフレームでは残り時間を引かず、次のフレームから `WARN_TIME` 分の更新（`dt` 0.1 s を 8 回など）で弾になり、そのフレームでは動かない（出現位置は `viewTop − BULLET_R`・予告の x ちょうど）。予告の x は `rng` の端（0 と 0.999…）で `[14, 346]` に収まる。1 回に出す数が高さで 1 → 2。弾が画面の下端の外 20 px、または左右の外 20 px で消える
- 当たり判定: 円（半径 7）と長方形（20 × 28）。弾の中心が長方形の辺から距離ちょうど 7 → 当たり、7.01 → 外れ。角（長方形の角から斜めに距離 7 / 7.01）。弾が長方形の中にある → 当たり
- 終わりの判定: 取り残され = 頭が `viewTop + H` を超えたとき（頭 = `viewTop + H` ちょうどは取り残されない）。クリア = 着地していて足の y ≤ `goalY + 0.5`（空中で通り過ぎただけでは `clear` にならない）。同じフレームに弾に当たってゴールに着地 → `hit`。`hit` と取り残しが同時 → `hit`。スクロールがゴールで止まる（`viewTop` が `goalY − 170` を下回らない）。H = 528 の例: `startY` = 264、`goalY` = −1736、スクロールが止まる `viewTop` = −1906
- タッチの状態遷移（手作業の例）: 指 A を (100, 300) に押して、(105, 300) へ動かす（5 px → まだ候補）。離す（t = 200 ms）→ タップ → アクション 1 回。指 A が (100, 300) → (113, 300)（13 px > 12）→ 移動になる（基準点 = 100）。`swipeStep`: 指 105 → 向き 0（差 5 ≤ 8）、指 108 → 0（差 8 ちょうど。「超えて」ではないので 0）、指 108.01 → +1、指 140 → 基準点 112・向き +1、指 120 に戻す → 差 8 → 0、指 110 → 差 −2 → 0、指 103 → 差 −9 → −1。指 A が移動中に指 B を押す → B は押した瞬間にアクション 1 回、B が動いても移動にならない。B を離してもアクションは増えない。タップ境界: 離すまで 300 ms ちょうど → タップ、301 ms → 何もしない。動き 12 px ちょうど → 候補のまま（タップ）、12.01 px → 移動。候補を長く押さえたまま（動かさず 400 ms）離す → 何もしない。A（候補）の押下中に B を押す → B がアクション、A は候補のまま（その後 A がスワイプすれば移動）。`pointercancel` → アクションなしで指が消える。「縦にしてください」の案内が出た瞬間に移動の指があった → 向きが 0 に戻り、その指を離しても何も起きず、案内が消えたあとの最初のタップがアクションになる（役割の枠が空いている）。`playing` 以外（`ending`・案内中）のイベントは無視
- 向きの合成: 左キー + 右キー → 0。キーの右 + 移動の指の右 → +1（クランプ）。キーの右 + 移動の指の左 → 0。移動の指が無ければ 0
- 画面の大きさ: 表の 4 つの表示の大きさで論理の大きさ・縮小率・案内の有無が一致（390 × 844 → 779、375 × 550 → 528、1280 × 720 → 520、667 × 310 → 案内あり、844 × 390 → 案内あり、1024 × 768 → 案内なし）。案内の境界: 600 × 455 は縮小率 0.875 ちょうどで案内なし、600 × 454 は 0.873 で案内あり。縦長の表示には出ない。表示の幅が 0 のとき高さは下限。案内の文字の大きさ: 縮小率 0.596 で 31、縮小率 0.2 で上限 53、縮小率 0 以下で 53
- 配置: H = 528 と 779 で `startY` = 264 / 390（`round(H × 0.5)`、779 × 0.5 = 389.5 → 390）。Title・Result の各 y が上の例（H = 528）と一致し、START・ボタンが重ならず画面に収まる。H = 520（下限）でも同様
- Result の文字: `clear` → 見出し「クリア！」・理由「ゴールにとうたつ！」・`高さ 200 / 200 m`。`hit` → 「ゲームオーバー」「弾に当たった」・`高さ 137 / 200 m`。`left-behind` → 「ゲームオーバー」「下に取り残された」
- ガード: Result の開始から `RESULT_INPUT_GUARD_MS` 未満はボタン・キーを無視し、ちょうど経過した時点から受け付ける。ボタンは押した位置のボタンの上で離したときだけ働く
- Game の状態: 終わりのフレームで `ending` に入り、それ以降の入力・スクロール・弾・足場の更新は止まる。`RESULT_DELAY`（0.8 秒）で Result に移る（Scene のグルーは QA で確認）
- 下端の危険表示（`dangerAlpha`、`DANGER_RANGE` 100・`DANGER_MAX_ALPHA` 0.5）: 足 = 下端 − 101 → 0、− 100 → 0、− 50 → 0.25、± 0（下端ちょうど）→ 0.5、下端 + 30 → 0.5（上限）

- 自分の色（`playerLook`）: `hit` は t = 0.05 で赤、0.15 で通常、0.25 で赤（`ENDING_BLINK_S` 0.1 ごとに切り替え。境界の 0.1 ちょうどは浮動小数で揺れるので、各区間の真ん中で確かめる）。`left-behind`・`clear`・`playing`（結果なし）は任意の t で通常
- 下端の帯の点滅（`left-behind` の `ending`、`endingDangerAlpha(t)`）: t = 0.05 → 0.5、0.15 → 0.25、0.25 → 0.5（`DANGER_MAX_ALPHA` 0.5 と半分の 0.25 の切り替え）。`left-behind` 以外の `ending` は、その時点の `dangerAlpha` のまま

- 375 × 550・390 × 844・1280 × 720 で、Title・Game（開始直後・プレイ中・ゴール付近）・Result（クリア・失敗）のすべての文字・ボタンが画面に収まり重ならず、主な情報は実寸 14 px 以上・補助は 11 px 以上（スクリーンショットで確認）。予告の三角が画面の端で切れない
- 667 × 310 と 844 × 390 では「縦にしてください」の案内が全面に出て、Game が進まない（スクリーンショットと、スクロール・弾が進まないことの確認）。1024 × 768 では出ない
- 保つ挙動（確認方法つき）:
  - 開始時、足場が画面の縦の中央にあり、自分が横の中央に立つ（スクリーンショット・テスト）
  - スクロールがゆっくりで、ジャンプを続けざまに押さなくても、足場の乗り継ぎで追いつける（テスト: `scrollSpeed`。QA）
  - 弾は垂直と斜めで、斜めは 8 m から混ざる。予告の三角が弾の向きを指す（テスト＋スクリーンショット）
  - 画面の上端より上に出られない（テスト）
  - 地面でのジャンプ直後 `JUMP_LOCK` 秒は足場が作れない（テスト）
  - 足場は同時 2 枚・3 秒（テスト）
  - ゴールは 200 m で、足場に着地するとクリアし、そこでスクロールが止まる（テスト＋スクリーンショット）
  - 左右スワイプで移動し、指を止めたまま押さえていると動き続ける。タップでジャンプ・足場。スワイプ中の 2 本目の指のタップでアクション（テスト: タッチの状態遷移。QA: 実機または Playwright のタッチで 2 本指）
- 終わり方: 弾に当たる・取り残される・クリア、のどれでも Result に移り、「もう一度」で Game が最初から始まる（足場・弾・予告・タッチの状態が残らない）。「タイトルへ」で Title に戻る（QA）
- 入力: タッチ・マウス・キーボードのどれでも一通り遊べる（QA。キーボードは ← → と Space）
- 演出・UI（スクリーンショットと連続撮影で確認。375 × 550・390 × 844・1280 × 720）:
  - 下端の危険表示: 足が下端に近づくと、下端に赤い帯が出て濃くなる（スクロールで足場が流れ落ちる場面）。帯は画面の内側に収まる
  - 進行バー: 右端にあり、HUD と重ならない（予告の先端とは、右端近くの脈動で数 px 重なってよい）。スクロール・ジャンプ（QA では開発用の補助）で高さを変えると、印が下端（0 m）から上端（200 m）へ動く。ゴールの印が上端にある
  - 失敗の合図: `hit` で画面が揺れ（0.25 秒）、自分が赤と通常で点滅する。`left-behind` では揺れず、下端の帯が濃い・半分の濃さで 0.1 秒ごとに点滅する（自分は画面の外）。0.8 秒後に Result へ移り、揺れ・点滅が Result や次の Game に残らない
  - クリアの合図: ゴールの足場が点滅し、自分から紙吹雪が上へ散って 0.8 秒で消える。揺れない
  - 土煙: ジャンプと、落下から着地したときに足元に出て 0.25 秒で消える。頂点付近（落下速度が `LAND_PUFF_MIN_VY` 未満）で足場を作ってすぐ乗ったとき（軽い着地）には出ない。落下の途中（速度が上回る）で作ってすぐ乗ったときは出る
  - 足場づくり: 作った足場が 0.1 秒で広がる。足場が消える前の 0.5 秒は点滅する。広がっている間も、その足場に乗れる（判定は最初から 80 px）
  - 予告の脈動: 弾が出る直前の 0.3 秒、予告の三角が拡大・縮小する。画面の端の予告も切れない
  - Result: 「もう一度」が主ボタン、「タイトルへ」が控えめで、どちらも読める（控えめなボタンの塗りと白文字のコントラスト比が 4.5:1 以上であることを、塗りの色から計算して確かめる）。位置・大きさは変わらない
- 演出で変えないもの（回帰条件）: ルール・難易度・当たり判定・得点（無し）・足場の寿命と枚数・ジャンプ直後のロック・タッチの操作の感触（スワイプ・タップ・2 本目の指）は変わらない（上の回帰テスト。「ルールのテストが変更なしで通る」）。演出が入力を遅らせない（QA: 土煙・足場の広がり・予告の脈動の間も、タップのジャンプ・足場づくりがすぐ効く）。Result へ移る時間（`RESULT_DELAY`）、入力ガード（`RESULT_INPUT_GUARD_MS`）、案内中の凍結は変わらない
- README に、ゲームの目的・ルール・操作方法が書かれている

## 実装裁量

- 色・フォント（固定幅を推奨）・背景・枠線の太さ・角丸。自分・足場・弾・予告・ゴールの色（ただしゴールは他の足場と違う色にする。弾と予告は同じ系統の色にする）
- 自分の見た目の細部（長方形のままでもよい）、足場・弾の縁や影
- 操作ヒントの見え方の細部（色・不透明度）。ヒントの文言の「タップ: ジャンプ ／ 空中で足場」は仕様どおり
- 演出の細部: 色（自分の赤、土煙・紙吹雪の 3 色、帯の赤、バーの溝と印、Result の控えめなボタンの塗りと縁。ただし控えめなボタンは白文字とのコントラスト比 4.5:1 以上）、土煙の円の動きの細部（位置を固定のままでよい）、紙吹雪の回転の有無、揺れの細部（`camera.shake` の既定でよい）、点滅の切り替えが一瞬で切り替わるか短く補間されるか（0.05 秒未満）
- 演出の層の作り方（Graphics を層ごとに分ける、`setDepth`・`setScrollFactor` の使い方）、粒子・土煙のオブジェクトの使い回し方（毎フレームの生成は避ける）
- 画面の外に出た弾・予告・足場の捨て方、オブジェクトの使い回し方、モジュールの分け方・ファイル名、Scene 間のデータの渡し方
- `dt` の取り方（`DT_MAX` で打ち切るなら、固定刻みで細かく刻んでもよい。ただしジャンプの頂点・着地の仕様の値を守る）
- Title・Result の余白の細部（ただし配置・文字の大きさ・ボタンの位置は守る）
- ボタンの押下・ホバーの見た目（0.1 秒未満の切り替え）
- 文字のきれいさのための `resolution`・`roundPixels` の設定
