# fukuwarai 拡張候補（backlog）

公開済みの fukuwarai（元絵を覚えて、パーツをドラッグで置き、似ている度合いで採点する福笑い風ゲーム）に、次に足せるものの候補を、上から順に並べたものです。上のカードが「次の候補」です。仕様（`spec.md`）ではありません。`game-extend` が上から順に 1 件を選び、目的・コアループへの効き方・変えないものを固めてから、仕様に書きます。

- 規模: S = 1 画面と数値の追加程度、M = 複数の画面や仕組みにまたがる追加、L = 大きいので、`game-extend` で 1 PR 分に切り出してから採用する。
- 1 つのカードは 1 つの目的にする（1 変更 1 目的）。
- 外部の画像・音のアセットは、足してよいかをユーザーに確認してからにする（仕様は図形描画）。
- 変えないもの（設計の核）: 「つまんで、引っ張って、置く」操作の感触と、「配置エリアで離したら確定し、以後動かせない」。専用の回転ハンドルは置かない（`spec`「操作仕様」「技術要件」）。
- 数値だけの再調整（ぼかし半径・回転の補間係数など）は、カードにせず `game-balance` で行う。

### ベスト点の保存と、新記録の表示（`high-score`）

- 狙い: 点数は結果に出すだけで、保存しない。比べる記録が無い。根拠: `spec`「非 MVP 範囲」（ランキング）
- 何を足すか: ベスト点を `localStorage` に保存し、`Result` に新記録を出す（お題は 5 種類あるので、お題ごとにするかを決める）。
- コアループへの効き方: 広げない — 再挑戦の動機。
- 種別: presentation-only（保存を足す）
- 規模: S
- 出どころ: spec 分析
- メモ: 保存の失敗（ブロック・容量超過）でも、ゲームは止まらない。お題（5 種類。遊ぶたびに変わる）は入っているので、お題ごとのベストにするかを決める。 保存の読み書きは、ゲームごとに実装が分かれている（`bouncewave/src/game/logic/best.ts`・`pushline/src/game/logic/best.ts`・`first-game/src/game/core/highScore.ts`）。コピーを増やす前に、`shared/` への切り出しを検討する。

### 元絵を 1 回だけ見直せるようにする（`peek`）

- 狙い: 元絵は最初に 1 度だけで、以後は見られない。パーツの途中で迷っても、確かめる手段が無い。根拠: `spec`「非 MVP 範囲」（元絵をもう一度見る機能）
- 何を足すか: 配置フェーズで、元絵を数秒だけ見直せるボタンを 1 回だけ置く（使うと、点数から差し引く。または見直しの回数を結果に出す）。
- コアループへの効き方: 深める — 「覚える」と「確かめる」の駆け引きができる。
- 種別: gameplay
- 規模: S〜M
- 出どころ: spec 分析
- メモ: 差し引く量・見直しの秒数は `game-balance` で決める。見直している間の操作（パーツを掴めるか）を `game-extend` で決める。

### 画面の縦横比に合わせた論理サイズにする（黒帯を減らす）（`screen-fit`）

- 狙い: 論理サイズは固定の 540 × 960 で、FIT で縮める。390 × 844 では上下の黒帯が約 18%（151 / 844）で、基準の 15% を超える。375 × 550 では左右が約 18%。PC の横長では、細い縦帯になる。根拠: AGENTS.md 4.6、`constants.ts`（`GAME_WIDTH` / `GAME_HEIGHT`）
- 何を足すか: 画面の縦横比に合わせて、論理サイズ（またはレイアウト）を決める（`computeScreenSize` / `pickLayout` の方式）。配置エリアとトレイの比率を、画面の縦に応じて変える。
- コアループへの効き方: 広げない — 画面の使い方。ルールは変えない。
- 種別: presentation-only
- 規模: M（レイアウト定数の見直し、パーツのサイズ・当たり判定との関係、採点のキャンバスは変えない）
- 出どころ: spec 分析
- メモ: 許容する理由を spec に書く方法もある（`game-extend` で決める）。パーツのサイズが画面によって変わると、操作の感触が変わるので、回転の更新条件（速さの ramp。実装済み）の感触を実機で確かめながら行う。

### パーツを増やす（ほくろ・ひげ・髪など）（`more-parts`）

- 狙い: パーツが眉 2・目 2・鼻 1・口 1 の計 6 個で固定。配置の種類が少ない。根拠: `spec`「MVP 範囲」
- 何を足すか: パーツの種類を、お題ごとに増やす（ほくろ・ひげ・髪・耳など）。トレイに並べる数が増える。
- コアループへの効き方: 広げる — 覚えるものと置くものが増える。
- 種別: gameplay
- 規模: M
- 出どころ: spec 分析
- メモ: お題（`topics`）は入っている。トレイに並ぶ数が増えると、小さい画面で足りなくなるので、トレイの配置（複数段）を決める。

### 仕上がりの画像を保存・共有する（`share-image`）

- 狙い: 福笑いは、出来上がった顔を見て笑うゲーム。結果の顔を、持ち出す手段が無い。根拠: `spec`「非 MVP 範囲」（SNS シェア）、`Result` の趣旨
- 何を足すか: 結果の顔（と点数）を画像として保存する（ダウンロード・共有シート）。
- コアループへの効き方: 広げない — 結果を持ち出せる。
- 種別: presentation-only
- 規模: S〜M
- 出どころ: spec 分析
- メモ: 画像はブラウザ内で作り、外部に送らない。OS ごとの共有の対応を確かめる。

### 見た目を工夫する（顔・パーツ・背景・結果）（`look`）

- 狙い: 顔・パーツは図形（円・楕円・弧）だけで、背景は 1 色。雰囲気が無い。根拠: `spec`「技術要件」
- 何を足すか: 顔の輪郭・パーツの線と塗り・背景・結果画面の演出を整える。笑える雰囲気（出来上がりの見せ方）を決める。
- コアループへの効き方: 広げない — 雰囲気。採点（ピクセル差分）に影響する描画は、お手本とプレイヤーの描画で同じ処理を使う（変えるなら両方）。
- 種別: presentation-only
- 規模: S〜M
- 出どころ: spec 分析
- メモ: 採点用の描画（`drawFaceOnCanvas`）と見た目の描画が共通なので、変えると点数が変わる。基準の確認を、`game-balance` と合わせる。外部画像は使わない。

### 効果音を足す（掴む・置く・採点・結果）（`sound`）

- 狙い: BGM・効果音は非 MVP のまま。掴む・置く・確定の手応えが、音で補える。根拠: `spec`「非 MVP 範囲」
- 何を足すか: 掴む・置く（確定）・トレイに戻す・採点・結果の効果音を、Web Audio で作って鳴らす（外部の音声ファイルは使わない）。ミュートの切り替えを付ける。
- コアループへの効き方: 広げない — 演出の仕上げ。
- 種別: presentation-only
- 規模: S〜M
- 出どころ: spec 分析
- メモ: 最初のタップの後に鳴らす（自動再生の制限）。外部の音声ファイルを使う場合は、足してよいかを確認する。
