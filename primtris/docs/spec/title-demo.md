# Title のデモ

`docs/spec.md` の拡張。`Title` の画面で、ボットが落ちてくる数字をボックスへ仕分ける様子を流す。

## 概要

`Title` の「操作」の説明（4 行）の場所に、ボットのプレイ風景を置く。数字が上に現れ、正しい（ときどき間違った）ボックスへ落ちて、数字が消える・桁ごとに残る様子が見える。決まった個数を流したら透明になり、最初から繰り返す。ルール・スコア・難易度は変えず、`Title` でコアループ（振り分け → 判定 → 残留 / 巻き添え消去）を見せるだけである（チュートリアルの作り込みやエフェクトの強化ではない）。意図して変えるのは、「操作」の 4 行の説明が、1 行のヒントになる点だけである。

## 操作仕様

デモは操作を受け付けない（プレイヤーの入力では動かず、デモの領域のタップ・クリックは何も起こさない）。`Title` の操作（START のタップ・クリック、Enter、桁数の ◀▶ のタップ、左右キー）は `docs/spec.md` の「Title の操作」のとおりで、変わらない。ただし桁数の選択が変わると、デモは今のものを透明にして、その桁数の新しい走りに入れ替わる（下の「ルール」。この入れ替えは `Title` の `Scene` が自分で行うもので、`DemoDirector` のイベントではない）。

## 画面・Scene構成

### レイアウト

キャンバスは固定の 540×960（`Scale.FIT`）。`Title` には、名前（0.2）・桁数の選択の帯（0.38。高さ 72 px）・デモ・START（0.84。高さ 72 px）・操作のヒント（0.92）がある（いずれも画面の高さ H = 960 に対する比で、中心の位置）。一言説明と「桁数を選択」の文字は無い。

- **デモの領域**: 上端 `regionTop` = `round(0.38 × H + 72 / 2 + demoRegionGap)`（= `round(412.8)` = 413）、下端 `regionBottom` = `round(0.84 × H − 72 / 2 − demoRegionGap)`（= 758）。高さ 345 px。幅は画面全体（x = 0〜540）。
- **ボックスの行**: 領域の下端に、高さ `demoBoxHeight`（140 px）で置く（上端 y = `regionBottom − demoBoxHeight` = 618）。ボックスの数 n は、選択中の桁数のアクティブなボックスの数（2 桁: 5 個 `x2`・`x3`・`x5`・`x7`・`P`、3 桁・4 桁: 6 個 `x2`・`x3`・`x5`・`x7`・`xN`・`P`。`Game` の `getBoxOrder` と同じ）。1 つの幅は `540 / n`（5 個: 108 px、6 個: 90 px）で、隙間なく左から並べる。背景色は `Game` と同じ（奇数番目 `0x415a77`・偶数番目 `0x33415c`、0 始まりの番号）。
- **各ボックスの中身**（`Game` と同じ書式。大きさだけ小さい）: ボックスの上端を 0 として、ラベル（`x2`・`P` など、`demoLabelFontSize` = 18 px の太字、水平中央）の上端が +8、残留桁（等幅 `demoBoxFontSize` = 18 px の太字、水平中央。`Game` と同じく桁を 1 行 5 桁で並べ、最後の 3 行だけ見せる。行の間隔 20 px。空なら `--`）の上端が +34（3 行で +94 まで）、`残留数/容量`（`demoCapacityFontSize` = 14 px、水平中央）の上端が +116。
- **数字のタイル**: 落ちてくる数字は、`Game` と同じく**桁を縦に積んで**（1 桁ずつ改行）、`demoTileFontSize`（28 px）の太字・中央寄せで描く。待機中の位置は、水平は画面の中心（x = 270）、上端は `regionTop`（= 413）。縦に積んだ高さ h は描画した文字の高さ（4 桁で 140 px 前後）で、領域の高さ（`boxRowTop − regionTop − 4` = 201 px）を超えるときは、その高さに収まるように一様に縮める。落ちるときは、タイルの**下端**がボックスの行の上端（y = 618）に着くまで落ち（タイルの上端は 618 − h）、着いたら消える（ボックスの中身には重ならない）。
- **操作のヒント**: 1 行の文字「ドラッグで移動 / 離して投入」を、START の下の中心 y = `round(0.92 × H)`（= 883）に、水平中央・16 px の文字で置く（デモの透明化の対象にしない）。
- 描画順（奥から）: 背景 → ボックスの行 → 数字のタイル。名前・桁数の選択・START・ヒントは、デモの領域と重ならない。

### 状態

デモの内部フェーズは、共有パッケージ `title-demo` の `DemoDirector`（README が仕様）と同じ。このゲームでの対応:

| `DemoDirector` の要素 | このゲームでの内容 |
|---|---|
| 状態 `S` | 選択中の桁数・ボックスの残留（`createEmptyBoxes`）・投入の分布（`createDistributionState`）・出題のキュー（`QueueState`）・注入できる乱数 |
| ラウンド | 数字 1 個を仕分けること（`rounds` = `demoRounds`） |
| `start()` | 空のボックスと、新しい出題のキュー（`createQueue`。数字は `Game` と同じ生成器 `generatePlayableNumber` と分布で作る）で始める。走りの作り直しにも使う |
| `plan(state)` | 「ボットの手」で決めたボックス 1 つの手順（長さ 1）。選んだボックスと迷いの先（無ければ無し）を、状態 `S` の `intent` にも持つ（`DemoDirector` の `plan` の戻り値 `'pending'` とは別） |
| `play(state, action)` | 選んだボックスへ、`Game` と同じ `resolvePlacement` で投入する。常に `roundDone: true` |
| `advance(state)` | 次の数字（`advanceQueue`）に進める |
| `timing` | `stepMs` は使われない（1 ラウンドは 1 手）。値は `demoWaitMs` と同じにする。`waitMs` = `demoWaitMs`、`fadeMs` = `demoFadeMs` |

- 時間は、`Title` に入ってからの経過時間 `clock` を、`update` の経過時間（delta）で自前に数える（`delayedCall` は使わない）。1 回の `update` で進めるイベントは最大 1 つ。`DemoDirector` の `now` には `clock` を渡す。透明度は 2 種類あり、走りの終わりの透明化（`fade-out` / `fade-in` のイベント）は `DemoDirector.opacity` を使い、桁数の選択による入れ替えの透明化は `Title` の `Scene` が自分の線形の透明度（下の「デモの繰り返し」）で行う（この間は `DemoDirector.opacity` を使わない）。
- 1 つの数字の流れ（`demoWaitMs` = 700 ms の例。t = 0 を数字が現れた時刻とする）: t = 700 ms に手を打つ（`action`）。その時刻から、タイルが対象のボックスの中心の x まで `demoSlideMs`（250 ms）で水平に動き、続いて `demoDropMs`（200 ms）でボックスの上端まで落ちる。`action` の時点で内部の状態（`play` の結果）は更新されるが、画面のボックスの残留桁・残留数は、タイルが着く時刻（t = 1150 ms）まで**古いまま**で、着いた時刻に、タイルを消して新しい状態にする（巻き添えで消える桁もこの時刻に消える）。そのため、画面は内部の状態の表示用の写しを別に持ち、`action` の `detail`（投入後のボックス）で更新する。t = 1400 ms（手から `demoWaitMs` 後）に `advance`（次の数字がタイルとして現れる）。8 個目の数字では、1400 ms の時点で `advance` の代わりに `fade-out` になる。
- 対象のボックスは、タイルが動いている間（t = 700〜1150 ms）、背景を `0x778da9` にする（`Game` の掴み中のハイライトと同じ色）。タイルが着いたら元の色に戻す。
- **迷い**（見た目だけの動き。投入の結果・内部の状態には影響しない）: 手を決めたとき、確率 `demoHesitateRate`（0.35）で「迷う」。`plan` を呼んだ `tick`（`DemoDirector` が `waiting` に入ってから最初の `tick`。通常はその 1 フレーム後）で、手のボックスと迷いの先（無ければ無し）が決まり、デモの状態 `S` の `intent` に入る。`Scene` は、手の予定時刻 `T_act` = （その `waiting` に入った `tick` の `now`）+ `demoWaitMs` を覚える。迷うとき、`T_act − demoHesitateLeadMs`（500 ms）から（`intent` が分かったのがそれより遅いときは、その時刻から。ただし開始時刻が `T_act − demoHesitateSlideMs` より遅いときは迷わない）、タイルが「迷いの先」（対象以外のアクティブなボックスの 1 つ）の中心の x まで `demoHesitateSlideMs`（150 ms）で水平に動く。動き始めと同時に、迷いの先のボックスの背景を `0x778da9` にして、`T_act` まで待つ。`T_act` に、ハイライトは対象のボックスに移り（迷いの先は元の色に戻る。タイルはまだ迷いの先の上にある）、タイルは迷いの先の位置から対象の中心の x まで `demoSlideMs` で動く（その後の落下は同じ）。迷わないときは、タイルは数字が現れた位置（x = 270）にとどまる。`intent` は、`action` の時点で空にする（手を打った後の待ちでは `plan` が呼ばれないので、古い `intent` を使わない）。`action` の `detail` にも、同じ手のボックスと迷いの先を持つ。
- `fade-out` の間、デモの描画（ボックスの行とタイル）全体に `DemoDirector.opacity` を掛ける。`fade-in` のイベントで、新しい走りの状態（空のボックス・新しい数字）に差し替え、`demoFadeMs` かけて現れる。新しい走りの最初の手は、`fade-in` のイベントから `demoFadeMs + demoWaitMs`（= 1100 ms）後。名前・一言説明・桁数の選択・START・ヒントは透明にしない。
- 開始（START のタップ・クリック、Enter）が受け付けられている間は、デモを進めない（`tick` を呼ばない。桁数の選択による入れ替えの透明化と入れ替えも止まり、その間に入れ替えの時刻が来ても行わない）。同じフレームに手の時刻が来ていても進めない。遷移しなかったときに START を再び受け付けるようになったとき（既存の挙動: 200 ms 後）は、デモ・透明化も再び進む。

## ルール

### ボットの手

`Game` の判定（`getValidBoxes`・`resolvePlacement`・`isCorrectPlacement`）をそのまま使う。乱数 `rng` は注入できる（既定は `Math.random`）。数字 `value`、アクティブなボックス（`getBoxOrder(digitCount)`）、残留 `boxes`、容量 `boxCapacity`（`Game` と同じ。選んだ桁数の容量。`docs/spec.md` の「難易度調整」の表: 桁数 2 は 9、桁数 3 は 8、桁数 4 は 7）に対して:

1. `r1 = rng()`。`r1 < demoMissRate` のとき「ミスする」。
2. **正しい候補** = `getValidBoxes(value)` のうちアクティブなもの（`BOX_ORDER` の順）。**間違った候補** = アクティブなボックスのうち、正しい候補でないもの（`BOX_ORDER` の順）。
3. 「ミスする」かつ間違った候補が 1 つ以上あるときは、間違った候補を使う。そうでなければ、正しい候補を使う。
4. `r2 = rng()`。使う候補の並びの `floor(r2 × 候補の数)` 番目のボックスを仮に選ぶ。
5. 仮に選んだのが間違った候補で、そこへ投入すると `resolvePlacement` の `gameOver` が `true`（容量超過）になるときは、正しい候補の並びに切り替え、同じ `r2` で `floor(r2 × 正しい候補の数)` 番目を選び直す（デモはゲームオーバーにしない。`rng` は余計に引かない）。
6. `r3 = rng()`。`r3 < demoHesitateRate` のとき「迷う」。
7. 迷うときは `r4 = rng()`。迷いの先 = アクティブなボックスのうち、選んだボックス以外（`BOX_ORDER` の順）の `floor(r4 × その数)` 番目。迷わないときは `r4` を引かない。

乱数 `rng` は 1 つで、数字の生成（`generatePlayableNumber`。`Game` と同じ生成器・分布）と、ボットの手の両方に使う。ボットの手では、数字 1 つにつき `rng` を 3 回（`r1`、`r2`、`r3`。迷うときは `r4` も加えて 4 回）引く。`r3`・`r4`（迷い）は、選ぶボックスには影響しない。

### デモの繰り返し

- 1 回の走りは `demoRounds`（8 個）の数字。8 個目を仕分けて `demoWaitMs` 待ったあと、`demoFadeMs` かけて透明になり、新しい走り（空のボックス）を始める。繰り返す。
- 桁数の選択が変わったとき（◀▶ のタップ、左右キー）の入れ替え（`Title` の `Scene` が行う。`DemoDirector` のイベントではない）: 今の走りの描画全体（ボックスの行とタイル）の不透明度を、そのときの値 `a` から、線形に `demoFadeMs` あたり 1 の割合で 0 まで下げる（`a` は、通常は 1。`DemoDirector` の `fade-out` / `fade-in` の途中なら `DemoDirector.opacity` の値、入れ替えの透明化の途中・現れる途中なら `Scene` の透明度の値。`a` = 0 のときは、その `update` で入れ替える）。下げている間、`DemoDirector` の `tick` を呼ばず、タイル・ハイライト・ボックスの表示は最後の `tick` の時刻で止める（古い走りの未反映の結果は捨てる。古い `DemoDirector` のイベントは以後届かない）。透明になりきった時刻 `T_swap` に、そのとき選ばれている桁数の新しい走り（空のボックス・新しい数字）を持つ `DemoDirector` を、`now` = `T_swap + demoFadeMs` で作り（`clock` がその時刻になるまで `tick` を呼ばない。その間、`director.state` を読んで描画する）、`Scene` の透明度を 0 から 1 まで `demoFadeMs` かけて上げる（`DemoDirector.opacity` は使わない）。最初の手は `T_swap + demoFadeMs + demoWaitMs`（= 1100 ms）後。下げている途中・上げている途中（不透明度 `a`）に選択が変わったときは、そこから `a × demoFadeMs` かけて 0 まで下げ、入れ替えは最後の選択で 1 回だけ行う（2 → 3 → 2 と戻っても、入れ替えは 1 回行う）。選択が変わらなかったとき（端で止まっているとき）は何もしない。
- デモは `localStorage` などのストレージを読まず・書かない。`Game` へは、今までどおり `{ digitCount }` だけを渡す。

| `demoHesitateRate` | 0.35 | ボットが手の前に別のボックスへ寄り道する（迷う）確率 |

| `demoHesitateSlideMs` | 150 | 寄り道の先まで水平に動く時間（ms）。`demoHesitateSlideMs` ≦ `demoHesitateLeadMs` ≦ `demoWaitMs` を保つ（そうでないと、迷いが数字の現れる前に始まる） |

| `demoHintYRatio` | 0.92 | 操作のヒントの中心の高さ（画面の高さに対する比） |
| `demoTileFontSize` | 28 | 数字のタイルの文字の大きさ（px。縦積みの行間 2 px） |
| `demoBoxFontSize` | 18 | ボックスの残留桁の文字の大きさ（px）。ラベルは `demoLabelFontSize`（18 px）、残留数 / 容量は `demoCapacityFontSize`（14 px） |

## テスト観点

純粋なロジック（ボットの手・レイアウトの計算・デモのフロー）の単体テストと、Scene の QA で確認する。

- **ボットの手**（`rng` は固定の値の列で注入する。手計算の値）:
  - `value` = 30、桁数 2（アクティブ `x2`・`x3`・`x5`・`x7`・`P`）、`rng` が `[0.5, 0.5, 0.9]` → ミスしない（0.5 ≥ 0.2）。正しい候補 `[x2, x3, x5]`、`floor(0.5 × 3)` = 1 番目 → **`x3`**。
  - 同じ `value`、`rng` が `[0.1, 0.99, 0.9]` → ミスする。間違った候補 `[x7, P]`、`floor(0.99 × 2)` = 1 番目 → **`P`**（30 を P に入れると、残留 `3`・`0`）。
  - `value` = 31、桁数 2（素数。正しい候補 `[P]`）、`rng` が `[0.0, 0.0, 0.9]` → ミスする。間違った候補 `[x2, x3, x5, x7]`、0 番目 → **`x2`**（残留が空のとき）。
  - 容量のガード: 桁数 4（容量 7）、`value` = 3003（= 3 × 7 × 11 × 13。正しい候補 `[x3, x7]`、間違った候補 `[x2, x5, xN, P]`）、`rng` が `[0.0, 0.0, 0.9]`（ミスする、0 番目）。`x2` の残留が空のとき → 間違った候補の 0 番目 **`x2`**（3003 の 4 桁が残る）。`x2` の残留が 4 桁（`[1,1,1,1]`）のとき → `x2` へ入れると 4 + 4 = 8 > 7 で容量超過なので、正しい候補に切り替わり、0 番目 **`x3`**。
  - どの `rng` の列でも、選んだボックスはアクティブなボックスの中にあり、投入しても `gameOver` にならない（性質テスト: 桁数 2〜4 × シード 1〜200 × 8 個）。
  - 迷い: `value` = 30、桁数 2、`rng` が `[0.5, 0.5, 0.1, 0.0]` → 手は `x3`（上と同じ）。`r3` = 0.1 < 0.35 なので迷う。迷いの先は `[x2, x5, x7, P]`（`x3` 以外）の `floor(0.0 × 4)` = 0 番目 → **`x2`**。`rng` が `[0.5, 0.5, 0.9]` → `r3` = 0.9 ≥ 0.35 なので迷わない（`r4` は引かない）。迷いの先は、選んだボックスと違う。
  - 同じ `rng`・同じ入力なら同じ手と迷い（決定的）。`rng` の呼び出しは数字 1 つにつき、迷わないとき 3 回、迷うとき 4 回（ボットの手の分。数字の生成は別）。
  - 迷いの時刻（フロー。`demoWaitMs` = 700、`waiting` に入った `tick` の `now` = 0 とする）: 迷うとき、`tick(1)`（最初の `plan` の呼び出し）の後に `intent`（手のボックス・迷いの先）が読める。t = 200 ms にタイルが迷いの先の中心 x へ動き始め（迷いの先の背景が `0x778da9`）、350 ms に着き、700 ms（`action`）にハイライトが対象に移って、タイルが `demoSlideMs` で対象へ動く。迷わないときは、タイルは 270 のまま 700 ms に動き始める。`action` の後、`intent` は空になる（次の `advance` まで）。`plan` が 600 ms で呼ばれた場合（遅いフレーム）は、開始が `T_act − 150` = 550 ms より遅いので迷わない。
- **デモのフロー**（`DemoDirector` の動作は共有パッケージ側のテスト。ここでは、このゲームの対応を確認する）:
  - `demoRounds` = 8 の走りで、手が 8 回打たれてから `fade-out` になる。`fade-in` の時点の状態は、空のボックス・新しい数字。
  - 1 つの数字の流れの時刻（`demoWaitMs` = 700）: 数字が現れてから 700 ms で手、さらに 700 ms で次の数字（`advance`）。
  - 手のたびに、`resolvePlacement` と同じ結果（残留・巻き添え消去）になる。正解の投入では投入した桁が残らず、同じボックスの一致した残留桁が 1 対 1 で（新しいものから）消える。間違いでは投入した桁が残る。
- **レイアウト**（手計算の値）:
  - `regionTop` = `round(0.38 × 960 + 36 + 12)` = `round(412.8)` = 413、`regionBottom` = `round(0.84 × 960 − 36 − 12)` = `round(758.4)` = 758、ボックスの行の上端 = 618、ヒントの中心 y = `round(0.92 × 960)` = `round(883.2)` = 883。
  - 桁数 2: ボックス 5 個、幅 108、`x2` の左端 0・`P` の左端 432。桁数 3・4: 6 個、幅 90、`xN` の左端 360・`P` の左端 450。
  - 数字のタイルの対象の x = 対象のボックスの中心（例: 桁数 2 の `x3` は 108 + 54 = 162、桁数 3 の `P` は 450 + 45 = 495）。
- **桁数の選択**: 選択が 2 → 3 に変わったとき、デモは透明になり（不透明度 1 から 200 ms で 0.5、400 ms で 0）、400 ms の時点で 6 個のボックスの新しい走りに入れ替わり、そこから 200 ms で 0.5、400 ms で 1 になる。最初の手は現れ始めから 1100 ms 後。不透明度 0.5 のとき（透明化の 200 ms 後）に選択が変わったときは、そこから 200 ms で 0 になり、入れ替わる。透明化の間に 2 → 3 → 4 と変えたときは、4 桁（6 個）の走りへ 1 回だけ入れ替わる。選択が端（2 桁で ◀、4 桁で ▶）で変わらないときは、何も起こらない。
- **入力**: デモの領域のタップ・クリックは、何も起こさない（`Game` へ進まず、選択も変わらない）。
- **入れ替えの時刻（手計算）**: 不透明度 1 から選択が変わった時刻を 0 として、200 ms で 0.5、400 ms で 0（入れ替え）、600 ms で 0.5、800 ms で 1。最初の手は 400 + 400 + 700 = 1500 ms（選択が変わってから）。0.5 のとき（200 ms）に選択がもう一度変わると、400 ms で 0（入れ替え）。2 → 3 → 2 と戻っても、入れ替えは 1 回行われ、新しい走りの桁数は 2 桁（5 個）になる。入れ替えの透明化の間、`DemoDirector` の `tick` は呼ばれず、古い走りの `action` / `advance` は起きない。START が受け付けられている間は、透明度も入れ替えも進まない。
- **回帰条件**（変えないもの）:
  - `Game` の既存のテスト（分類判定・数値生成・投入・巻き添え消去・容量超過・難易度・スコア）が通る。容量を前提にするテストは、桁数ごとの容量（9・8・7）に合わせて期待値を直す。それ以外は書き換えずに通る。
  - `Game` の見た目と操作（ボックスの背景・ラベル・残留桁・残留数 / 容量・ドラッグ・ハイライト・CURRENT / NEXT・ログ・ゲームオーバーのスローモーション）は、ボックスの描画を取り出しても変わらない（QA で、変更前（`origin/main` のビルド）と並べて確認する）。
  - `Title` の START（タップ・クリック・Enter）・桁数の選択（◀▶・左右キー）・`Game` への `{ digitCount }` の引き渡しは変わらない。`Title` のコードは、ブラウザのストレージを使わない（コードの検索で確認する）。
