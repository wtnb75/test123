# primtris 拡張候補（backlog）

公開済みの primtris（落ちてくる数字を、素数・倍数でボックスへ振り分けるパズル）に、次に足せるものの候補を、上から順に並べたものです。上のカードが「次の候補」です。仕様（`spec.md`）ではありません。`game-extend` が上から順に 1 件を選び、目的・コアループへの効き方・変えないもの・spec の置き場所を対話で固めます。

- 規模: S = 1 画面と数値の追加程度、M = 複数の画面や仕組みにまたがる追加、L = 大きいので、`game-extend` で 1 PR 分に切り出してから採用する。
- 1 つのカードは 1 つの目的にする（1 変更 1 目的）。
- 外部の画像・音のアセットは、足してよいかをユーザーに確認してからにする。
- 数値だけの再調整（容量・出現の偏り）は、カードにせず `game-balance` で行う。

### Title の操作のヒントと遊び画面の文字を、SE 縦で読めるようにする（`layout-breathe`）

- コアループへの効き方: 広げない — 見え方だけを変える（ルール・出題・得点は変えない）。
- 種別: presentation-only

- メモ: 黒帯（SE 縦 17.5%・スマホ縦 17.9%・PC 68%）は別カード `screen-fit`。落下中の数値を桁ごとに縦に積む表示は、spec で決めた仕様（「常に縦積み」）で、変えない。

### 画面の縦横比に合わせた論理サイズにする（黒帯を減らす）（`screen-fit`）

- 狙い: 論理サイズは固定の 540 × 960 で、FIT で縮める。390 × 844 では上下の黒帯が約 18%（151 / 844）、375 × 550 では左右が約 17.5% で、基準の 15% を超える。PC（1280 × 720）では 405 px の細い縦帯（左右の黒帯 68%）になる。根拠: AGENTS.md 4.6、2026-11-15 の縮小率の計算（`layout-breathe` の確認で分かった）
- 何を足すか: 画面の縦横比に合わせて、論理サイズ（またはレイアウト）を決める（`computeScreenSize` / `pickLayout` の方式）。ボックス・落下領域・文字の配置を、画面の縦に応じて変える。
- コアループへの効き方: 広げない — 画面の使い方。ルールは変えない。
- 種別: presentation-only
- 規模: M（540 × 960 を前提にした Title のデモ・ボックス・落下距離・Result の配置の見直し）
- 出どころ: 画面構成の調査・spec 分析
- メモ: 許容する理由を spec に書く方法もある（`game-extend` で決める）。fukuwarai の同名カードと同じ性質。落下の速さ（`entryFallSpeed` など）が論理の高さで変わらないかを確かめる。

### ベスト記録を保存し、結果に出す（`best-score`）

- 狙い: スコアは結果に出すだけで、保存しない（Title の仕様に「ブラウザのストレージは使わない」と明記）。比べる記録が無い。根拠: `spec`「Title の操作」「非 MVP 範囲」（ランキング）
- 何を足すか: 桁数ごとのベストスコアを `localStorage` に保存し、`Result` と Title に出す。新記録を知らせる。
- コアループへの効き方: 広げない — 再挑戦の動機。
- 種別: presentation-only（保存を足す）
- 規模: S
- 出どころ: spec 分析
- メモ: 「ブラウザのストレージは使わない」の記述を、spec で書き換える（`game-spec`）。保存の失敗でもゲームは止まらない。保存するのは、`chain-score` で変わった合計スコア（置いた枚数 + 巻き添え + 連続）。内訳（置いた枚数・巻き添え・連続）も保存するかは、このカードで決める。 保存は `shared/best-store` を使う（`browserStorage` と `BestStore`。ベスト記録をキー `<game-dir>.best`・値 `{score, label}` で持つと、トップページのカードに `label` が出る）。

### スキル／アイテムを足す（保留・箱の一部を消す）（`power-ups`）

- 狙い: 長く続く場面での、「ピンチからの一発逆転」の手段が無い。根拠: `spec`「非 MVP 範囲」（スキル/アイテム）
- 何を足すか: 一定数を置くたびに貯まるスキルを 1 種類（例: 1 枚保留する・選んだ箱の桁を 3 つ消す）。使うタイミングはプレイヤーが決める。
- コアループへの効き方: 深める — 「いつ使うか」の判断が加わる。
- 種別: gameplay
- 規模: M
- 出どころ: spec 分析
- メモ: 時間の圧力（数字ごとの待ち時間）は入っているので、スキルの価値が出る。スキルの種類・貯まる条件・UI の置き場所（6 列のボックスの下）を決める。

### 効果音を足す（投入・正解・不正解・ゲームオーバー）（`sound`）

- 狙い: サウンド/エフェクトの大幅強化は非 MVP のまま。正誤の手応えが、音で補える。根拠: `spec`「非 MVP 範囲」
- 何を足すか: 掴む・投入・正解（巻き添え消去あり／なし）・不正解・ゲームオーバーの効果音を、Web Audio で作って鳴らす（外部の音声ファイルは使わない）。ミュートの切り替えを付ける。
- コアループへの効き方: 広げない — 演出の仕上げ。
- 種別: presentation-only
- 規模: S〜M
- 出どころ: spec 分析
- メモ: 最初のタップの後に鳴らす（自動再生の制限）。外部の音声ファイルを使う場合は、足してよいかを確認する。

### 戻ったときに操作してから再開する（`pause-resume`）

- 狙い: 数字の待ち時間（時間切れで自動投入）が、タブを離れても進み続け、戻ると不正解になりうる。根拠: ユーザーの声（復帰時に突然再開されるゲームがある。フォーカス外れとスマホで動作を揃えたい）、`primtris/docs/spec.md`（待ち時間の時間切れで投入する。「ポーズは今の実装には無い。実装されたときはポーズ中に計時と残り秒の表示を止める」と記載済み）
- 何を足すか: ページが見えなくなった（`HIDDEN`）かウィンドウがフォーカスを失った（`BLUR`）とき、ゲームの時間を止めて幕を出す。戻っても勝手には再開せず、タップかキーを押したときに、止まった続きから再開する。再開に使った操作は、それだけで終わる（打つ・動くなどのゲームの操作にはならない）。待ち時間の計時と残り秒の表示を止め、再開で続きから進める（spec の既存の記述どおり）。
- コアループへの効き方: 広げない — 復帰時の不意の失点・失敗を防ぐ。コアループそのものは変えない。
- 種別: gameplay
- 規模: S
- 出どころ: ユーザー
- メモ: `shared/pause` の `PauseState` を使う（absorb が先例。入れる順はルート `docs/backlog.md` の `pause-rollout`）。spec のポーズの記述は、このカードで実装と合わせる。spec は `absorb/docs/spec/pause.md` と同じ形（`docs/spec/pause.md`）に分ける。
