# 再挑戦ラウンド（間違えた語だけをもう一度出題する）

`docs/spec.md` の一部。結果の後に、間違えた語だけを落ちゲー形式でもう一度出題する「再挑戦ラウンド」を、独立して書いたもの。`docs/spec.md` と合わせて 1 つの spec である。用語（タイル・スロット・言語モード・難易度・正誤フラッシュ・適応難易度）は `docs/spec.md` のとおり。

## 概要

Result / Review から、そのラウンドで「最終的に不正解のままの語」だけを、同じ言語モード・難易度の落ちゲーで 1 周出題する。間違えた語を一覧で見るだけだった復習に、覚えたかを確かめる手段を足す（コアループを深める）。再挑戦の結果から、まだ間違えた語だけでもう一度再挑戦できる。

## 操作仕様

- 追加する操作は、再挑戦ボタンのタップ（クリック）だけ（キーボードの手段は足さない）。Result は論理 540 × 960 の固定のまま縮小して表示するので、スマホ横（667 × 310、縮小率 0.323）では再挑戦ボタンの実寸の高さが約 26 px になり、44 px に届かない。既存の Result のボタン（高さ 60 → 約 19 px）も同じで、このゲームはスマホ縦を基準にしている（`docs/spec.md`）ため、横画面の 44 px は求めない。縦画面（375 × 550 以上）で 44 px 以上を満たす。再挑戦ラウンドの中の操作（タッチのドラッグ、矢印キー、Space / Enter）は `docs/spec.md` のとおりで、変えない。
- 再挑戦ボタンは、間違えた語が 1 語以上のときだけ出す。0 語のときは出さない。

## 画面・Scene構成

新しい Scene は作らない。既存の Game / Result / Review Scene を、再挑戦ラウンドかどうかで切り替える。

### 再挑戦ラウンドの種類

- **通常ラウンド**: Title から始めたゲーム、または Result の「もう一度」「最初から」から始めたゲーム。
- **再挑戦ラウンド**: 再挑戦ボタンから始めたゲーム。再挑戦ラウンドの Game は、再挑戦する語の一覧（`KogoEntry[]`）と、元の `GameConfig` を Scene data で受け取る。Result / Review には、再挑戦ラウンドであることを Scene data で引き渡す。

### Game Scene（再挑戦ラウンド）

- 出題する語: 再挑戦ボタンを押した画面の「間違えた語」（Result / Review が持つ `wrongEntries`）。`id` が同じ語は 1 語にまとめ、1 語 1 回だけ出す。
- 出題数: 出題する語の数（1〜30）。進捗表示・ゲージ・NEXT は、この数で数える。Title の出題数は使わない。
- 出題順: ラウンドの開始時に、ランダムに並べ替える（出題順の再現は求めない）。
- 言語モード・難易度: 元の `GameConfig` を引き継ぐ。Title には戻らない。
- スロット: 4 個固定。適応難易度（スロット数の増減・プールの切り替え・出題列の作り直し）は使わない。
- ダミーの選択肢: 元の難易度の出題プール（`docs/spec.md` のルール）と、再挑戦する語を合わせたプール（`id` で重複を除く）から選ぶ。選び方は、通常ラウンドと同じスロット生成の処理（`generateSlots`）にこのプールを渡して行う（`docs/spec.md` の「スロット選択肢の生成ルール」のとおり。それ以外の除外ルールを足さない）。
- 正解した語を以降の出題から除く処理（出題列の作り直し）は行わない。出題列はラウンドの開始時に決めた並びのまま進む。
- 落下速度、タイルの見た目、正誤フラッシュ（正解 1.2 秒・不正解 2.5 秒）、連続正解の表示、入力の受け付けは、通常ラウンドと同じ。
- 全問を出し終えたら、フラッシュの後に Result へ進む。

### Result Scene

通常ラウンドと再挑戦ラウンドで同じ Scene を使う。違いは次のとおり。

| 項目 | 通常ラウンド | 再挑戦ラウンド |
|------|-------------|---------------|
| 見出し | リザルト | 復習ラウンド |
| 出題数・正答数・不正答数・正答率 | 出題した全問で数える | 再挑戦した語だけで数える |
| 再挑戦ボタンのラベル | 間違えた語を再挑戦 (N語) | まだ間違えた語を再挑戦 (N語) |
| 「もう一度」ボタンのラベル・動き | 「もう一度」: 元の設定で新しい通常ラウンドを始める | 「最初から」: 元の設定で新しい通常ラウンドを始める |

- N は、その Result の間違えた語の数（`id` で重複を除く）。
- 復習ボタン（Review へ進む）の表示は既存のとおり。Review には、そのラウンドの語（再挑戦ラウンドなら再挑戦した語）を渡す。
- 元のゲームの数字は、再挑戦の結果で上書きしない（Result の数字は保存しない。語ごとの回答の記録だけは、[苦手な語の記録と出題](weak-words.md) のとおり再挑戦ラウンドでも保存する）。再挑戦ラウンドの Result から元の数字は見えない。

#### Result の配置（論理 540 × 960、中心の y、高さは px）

| 要素 | 間違いが 1 語以上 | 間違いが 0 語 |
|------|------------------|--------------|
| 見出し | y=96 | y=96 |
| 数字（4 行） | y=288 | y=288 |
| 復習ボタン（高さ 64） | y=538 | y=538 |
| 再挑戦ボタン（幅 443、高さ 80） | y=636（596〜676） | 出さない |
| 「もう一度」「タイトルへ」（高さ 60） | y=760 | y=691（今のまま） |

- 再挑戦ボタンの実寸の高さは、SE 縦（375 × 550、縮小率 0.573）で 80 × 0.573 = 46 px（44 px 以上）。
- 再挑戦ボタンは、既存の復習ボタンと同じ幅（画面幅の 0.82）で、復習ボタンとは違う色にする（色は実装裁量）。
- 再挑戦ボタンのラベルは 20px 以上。幅 443 px に収まらない場合は 2 行に折り返す。

### Review Scene

- 間違えた語が 1 語以上のとき、下端のボタン行（既存の「もう一度」「タイトルへ」）の上に、全幅の「間違えた語を再挑戦 (N語)」ボタンを置く。N は表示中のラウンドの間違えた語の数（`id` で重複を除く）。
- ボタンの実寸の高さは 44 px 以上。ラベルは 16px 以上。
- 一覧のスクロール領域は、そのぶん縮む。オーバーレイの実寸の高さが 400 px 未満（横画面など。オーバーレイの幅が狭くなる）のときは、一覧の領域と下端のボタン行を画面内に収めることを優先する。再挑戦ボタンを下端のボタン行に入れ（折り返してよい）、3 つのボタンの文字を 13px、余白を小さくして、44 px 以上とラベル 16px 以上は求めない。一覧の実寸の高さは 100 px 以上にする。一覧の内容・「正解した単語も表示」の切り替えは変えない。
- 再挑戦ラウンドから来た Review では、「もう一度」のラベルを「最初から」にする（動きは Result と同じ）。
- 再挑戦ボタンを押すと、Review の DOM を後始末してから、再挑戦ラウンドの Game を始める（「もう一度」「タイトルへ」と同じ後始末）。

### 状態遷移

| 遷移 | きっかけ |
|------|---------|
| Result / Review → 再挑戦ラウンドの Game | 再挑戦ボタンのタップ |
| 再挑戦ラウンドの Game → Result（再挑戦ラウンド） | 最後の問題のフラッシュが終わる（タイマー） |
| Result（再挑戦ラウンド）→ 再挑戦ラウンドの Game | 「まだ間違えた語を再挑戦」のタップ |
| Result / Review（再挑戦ラウンド）→ 通常ラウンドの Game | 「最初から」のタップ |
| Result / Review → Title | 「タイトルへ」のタップ |

## ルール

- 再挑戦ラウンドは 1 周で終わる。全問正解するまで自動で繰り返さない。まだ間違えた語があれば、結果画面から自分で再挑戦ラウンドをもう一度始める。
- 正誤判定、判定のフィールド、フラッシュの表示は `docs/spec.md` のとおり。
- 「間違えた語」とは、そのラウンドで一度も正解しておらず、不正解だった語（`id` で 1 語）。一度間違えた語をあとで正解すると、間違えた語から外れる。一度正解した語は、そのあとで不正解になっても間違えた語に戻らない（通常ラウンドも同じ）。再挑戦ラウンドは 1 語 1 回しか出さないので、再挑戦ラウンドで正解した語は外れ、不正解の語は残る。
- Result の N は、間違えた語を `id` で重複を除いて数えた値。
- 再挑戦ラウンドでの出題順の乱数は、注入できる乱数関数で決める（テストで再現できるようにする）。

## パラメータ表

| 名前 | 初期値 | 意味 |
|------|--------|------|
| 再挑戦ラウンドの出題数 | 間違えた語の数（1〜30） | `id` で重複を除いた語の数。Title の出題数は使わない |
| 再挑戦ラウンドのスロット数 | 4 | 適応難易度を使わず固定 |
| 再挑戦ラウンドの出題順 | ランダム | ラウンドの開始時に 1 回並べ替える |
| 再挑戦ボタン（Result）の中心 y | 636 | 論理 px。高さ 80（596〜676）、幅 = 画面幅 × 0.82 |
| 「もう一度」「タイトルへ」の中心 y（再挑戦ボタンあり） | 760 | 再挑戦ボタンが出ないときは今のまま 691 |
| 再挑戦ボタン（Review）の実寸の高さ | 44 px 以上 | DOM ボタン |

通常ラウンドの数値（落下速度 400px/s、TILE_READY_Y、フラッシュの時間、適応難易度の評価の窓 5 問・上げる 80%・下げる 40% など）は変えない。

## テスト観点

純関数として `logic/` に切り出し、Phaser なしでテストする。

- 再挑戦する語の並び（例: `createRetrySequence`）:
  - 同じ `id` の語が複数あっても、1 回だけ含まれること（先に現れた順で 1 語にまとめてから並べ替える）
  - 結果の語の集合が、入力の語の集合（`id` で重複を除いたもの）と一致すること
  - 乱数関数を注入して、並びが再現できること。別の乱数で並びが変わること
  - 空の入力で空の配列が返ること。1 語の入力で、その 1 語だけが返ること
  - 入力の配列を書き換えないこと
- 再挑戦のダミーのプール（例: `buildRetryPool`）:
  - 元の難易度のプールと再挑戦する語の和集合で、`id` の重複がないこと
  - 再挑戦する語がプールに含まれない（上位の難易度で出た）場合でも、プールに含まれること
  - 再挑戦する語が 1 語だけでも、プールがダミーを 3 つ作れるだけの語を持つこと（元のプールが十分にあるため）
- 再挑戦ラウンドのスロット:
  - 4 スロットになり、正解の語が 1 つだけ含まれること（`generateSlots` に再挑戦のプールを渡す）
- Result の配置（例: `resultLayout(hasRetry)`）:
  - 間違いありで、再挑戦ボタンの y が 636、高さが 80、下段のボタンの y が 760 であること
  - 間違いなしで、再挑戦ボタンがなく、下段のボタンの y が 691 であること（回帰）
  - 再挑戦ボタンの範囲（596〜676）が、復習ボタン（506〜570）と下段のボタン（730〜790）に重ならないこと
- Result の表示（例: 見出し・ラベルを決める関数）:
  - 通常ラウンドで見出しが「リザルト」、再挑戦ラウンドで「復習ラウンド」であること
  - 再挑戦ボタンのラベルが、通常ラウンドで「間違えた語を再挑戦 (N語)」、再挑戦ラウンドで「まだ間違えた語を再挑戦 (N語)」であること
  - 再挑戦ラウンドの「もう一度」が「最初から」になること（通常ラウンドは「もう一度」のまま）
  - N が、`id` で重複を除いた間違えた語の数であること
- 間違えた語の定義:
  - 一度間違えた語をあとで正解すると、間違えた語から外れること。一度正解した語をあとで間違えても、間違えた語に戻らないこと。一度も正解していない語は、間違えたまま残ること
- 回帰（通常ラウンドが変わらないこと。既存のテストを変えずに通ること）:
  - 単語抽選、スロット生成、正誤判定、正答率の既存のテストがそのまま通ること
  - 再挑戦の指定がない Game の出題が、既存の `createQuestionSequence` で作られること

Scene の結線は画面で確かめる（`game-qa`）。再挑戦ラウンドで適応難易度が動かないこと、出題列が作り直されないこと、Result への引き渡しに加えて、通常ラウンドで次が変わらないこと: 適応難易度の「難易度 UP / DOWN」の表示とスロット数の増減、連続正解の表示、正誤フラッシュの長さ（正解 1.2 秒・不正解 2.5 秒）、落下速度、Review の「正解した単語も表示」の切り替え、Result の数字。

## 完了条件

- 間違いが 1 語以上の Result と Review に、再挑戦ボタンが出る。0 語の Result と Review には出ない
- 再挑戦ボタンを押すと、間違えた語だけが、元の言語モード・難易度で 1 周出題される。語の数だけ出題され、同じ語は 1 回だけ出る
- 再挑戦ラウンドのスロットは 4 個のまま。5 問目以降も「難易度 UP / DOWN」の表示が出ず、スロット数もプールも変わらない
- 再挑戦ラウンドで正解した語の後に、出題列が作り直されない（出題数が語の数のまま変わらない）
- 再挑戦ラウンドの Result の見出しが「復習ラウンド」で、数字が再挑戦した語だけで数えられている
- まだ間違えた語があれば「まだ間違えた語を再挑戦 (N語)」が出て、押すとその語だけで再挑戦ラウンドが始まる。全問正解なら出ない
- 再挑戦ラウンドの「最初から」を押すと、元の言語モード・難易度・出題数で新しい通常ラウンドが始まる
- 次の既存の挙動が変わらない: 通常ラウンドの落下速度・正誤フラッシュの長さ（正解 1.2 秒・不正解 2.5 秒）・出題の抽選・スロット生成・適応難易度（評価 5 問、上げる 80%・下げる 40%）、連続正解の表示、タッチとキーボードの操作、Title、Review の一覧と「正解した単語も表示」の切り替え、通常ラウンドの Result の数字の出し方、間違いが 0 語のときの Result の表示と配置（下段のボタンが y=691）
- 小さい画面（375 × 550、667 × 310）と、スマホ縦（390 × 844）、PC（1280 × 720）で、Result・Review の再挑戦ボタンが切れず、他のボタンと重ならない。縦画面では、再挑戦ボタンの実寸の高さが 44 px 以上。Review の一覧の領域は、667 × 310 でも実寸の高さが 100 px 以上
- `npm run lint` / `npm run test` / `npm run test:coverage` / `npm run build` がすべて通り、カバレッジが 90% 以上

## 実装裁量

- Scene data のフィールド名と型（再挑戦する語の一覧、再挑戦ラウンドかどうかの印）。`QuestionCount` 型を 1〜30 の再挑戦の出題数に合わせて広げる方法
- 再挑戦ボタンの色、角の丸み、押したときの見た目
- 進捗のゲージ（出題数ぶんの区切り）の見た目。出題数が少ないときも、既存のゲージの領域に収める
- 再挑戦ラウンドの Result で、見出しの色を変えるかどうか（見出しの文字は「復習ラウンド」）
- Review の再挑戦ボタンの色・余白
- `logic/` の関数名・ファイル分け
- 開発用のログ（`console.log`）の扱い
