# 苦手な語の記録と出題（間違えた語を保存し、次回以降の出題で重く出す）

`docs/spec.md` の一部。語ごとの回答の記録を端末に保存し、通常ラウンドの出題で、間違えやすい語を出やすくする仕組みを、独立して書いたもの。`docs/spec.md` と合わせて 1 つの spec である。用語（タイル・スロット・言語モード・難易度・出題プール・通常ラウンド・再挑戦ラウンド）は `docs/spec.md` と [再挑戦ラウンド](retry-missed.md) のとおり。

## 概要

語ごとの正解・不正解の回数を `localStorage` に保存し、通常ラウンドの出題の抽選で、誤答率の高い語の重みを上げる。Title で重み付けのオン・オフを選べ、保存した記録は Title から消せる。何も保存しないために、次に遊ぶと前に間違えた語を覚えていなかったのを直し、苦手な語が繰り返し出るようにする（コアループを深める）。記録がないとき、およびオフのときの出題は、今までと同じ。

## 操作仕様

- 追加する操作は、Title の 2 つの部品のタップ（クリック）だけ（キーボードの手段は足さない）。
  - 「苦手な語を多めに出す」の切り替え: タップのたびにオン・オフが入れ替わる。
  - 「苦手な語の記録を消す」: 2 回タップで消す（下の「記録を消す操作」）。
- 落ちゲーの中の操作（タッチのドラッグ、矢印キー、Space / Enter）は `docs/spec.md` のとおりで、変えない。

## 画面・Scene構成

新しい Scene は作らない。Title Scene に 2 つの部品を足し、Game Scene が回答を記録する。

### Title Scene の配置（論理 540 × 960、中心の y、高さは px）

| 要素 | 位置 | 備考 |
|------|------|------|
| 出題数のステッパー | y=645（下端 671） | 既存のまま |
| **切り替え「苦手な語を多めに出す: オン／オフ」** | y=697（675〜719）、幅 367、中心の x=270 | 新規。高さ 44。常に表示する |
| 「はじめる」ボタン | y=758（724〜792）、高さ 68 | 既存のまま |
| **「苦手な語の記録を消す」** | y=830（810〜850）、タップの範囲 240 × 40、文字 16px、中心の x=270 | 新規。記録があるときだけ表示する |

- 既存の要素（言語モード・難易度・出題数・「はじめる」・警告文）の位置・見た目・既定値は変えない。
- 切り替えの見た目: オンのときは既存の選択中の色、オフのときは既存の未選択の色。ラベルは「苦手な語を多めに出す: オン」「苦手な語を多めに出す: オフ」（文字 16px）。
- 実寸: スマホ縦（390 × 844、縮小率 0.722）で、切り替えの高さは 44 × 0.722 ≒ 32 px、ラベルは 16 × 0.722 ≒ 11.6 px。SE 縦（375 × 550、縮小率 0.573）で 25 px・9.2 px。既存の Title のボタン（難易度の高さ 68 → SE で 39 px）も同じ事情で、Title の配置・文字の大きさの見直しは別の拡張（`field-fit`）で行う。この拡張では 44 px・11 px の実寸は求めない。「記録を消す」（タップの範囲の高さ 40 → スマホ縦で約 29 px、SE 縦で約 23 px）も同じ理由で例外とする（誤って押しにくい、小さな補助の操作でもあり、2 回タップで消す）。
- 切り替えの状態（オン・オフ）は、Title が始まるときに端末の保存から読み、タップのたびに保存する。初期状態（保存がない・読めない）はオン。
- Title の選択（言語モード・難易度・出題数）と同じく、切り替えの状態は、Game を始めるときの `GameConfig` に入れる（「もう一度」「最初から」でも引き継ぐ）。

### 記録を消す操作（Title）

| 状態 | 表示 | 遷移 |
|------|------|------|
| idle（記録があるとき） | 「苦手な語の記録を消す」 | タップで armed へ（`clearConfirmMs` のタイマーを始める） |
| armed | 「もう一度タップで消す」 | 1 回目のタップからの経過が `clearConfirmMs` **未満**（2999ms まで）のタップで記録をすべて消し、非表示にする。`clearConfirmMs` 以上（3000ms 以上）になったら idle に戻る（タイマー。戻ったあとのタップは 1 回目として扱う） |
| 非表示（記録がない） | 出さない | — |

- armed の間に、他の部品（切り替え・「はじめる」・他の選択）を操作しても、armed は変わらない。idle に戻すのはタイマーだけ（「はじめる」で Game へ進むときは Scene の後始末でタイマーを止める）。
- 消すのは語の記録だけ。切り替えの状態は消さない。
- Scene が終わるとき、タイマーを止める（後始末）。
- 記録の有無は、Title が始まるときに数える（有効な記録が 1 語以上あれば「ある」）。消したあとは「ない」。

### 回答の記録（Game Scene）

- 正誤判定のたびに、出題された語（`KogoEntry.id`）の正解・不正解の回数を 1 増やし、保存する（通常ラウンドも再挑戦ラウンドも。正誤フラッシュの前後どちらでもよい）。
- 保存の失敗でゲームを止めない（下の「保存」）。

## ルール

### 記録

- 記録は語ごとに 1 件。キーは `KogoEntry.id`。言語モード・難易度をまたいで同じ件を使う。
- 1 件は、正解の回数 `c` と不正解の回数 `w`（どちらも 0 以上の整数）。
- 回答のたびに、正解なら `c`、不正解なら `w` を 1 増やす（切り替えがオフでも記録は続ける）。記録のない語は `{c: 0, w: 0}` から始める。
- 通常ラウンドと再挑戦ラウンドの回答を、どちらも記録する。
- 出題データにない `id` の記録は、読んでも使わない（捨てない。そのまま残してよい）。
- 数が不正な件（整数でない・負・欠けている）は、「記録のない語」として扱う。

### 重み

- 語の重み = 1 + `weakBoost` × `w` ÷ (`c` + `w`)。記録がない語、および `c` + `w` が 0 の語の重みは 1。
- 例（`weakBoost` 4）: `{c:0, w:0}` → 1、`{c:3, w:0}` → 1、`{c:1, w:1}` → 3、`{c:3, w:1}` → 2、`{c:0, w:3}` → 5、`{c:9, w:1}` → 1.4。間違えたあとに正解を重ねると、重みは自然に下がる。

### 重み付きの出題

- 重み付けが**有効**なのは、次のすべてを満たすとき: 通常ラウンドである、切り替えがオン、抽選に使うプール（`excludeIds` で絞ったあとの `activePool`）のどれかの語の重みが 1 でない。この判定は、乱数を引く前に済ませる。
- 有効なときの出題列は、`createQuestionSequence`（既存）がデッキを作る処理（開始時と、プールを周回して作り直すとき）で、`shuffleArray` の代わりに**重み付きシャッフル**を使う。それ以外（出題数・直前の語を連続させない規則・周回の折り返しの入れ替え・難易度ごとのプール・`excludeIds`・適応難易度による作り直し）は変えない。
- 重み付きシャッフル（注入できる乱数関数 `rng` を使う）: プールの語を並びの順に見て、語ごとに `u = rng()` を 1 回引き、キー = `u` の (1 ÷ 重み) 乗とする。キーの大きい順に並べる（キーが同じなら、プールの並びが先の語が先）。`u` が 0 のキーは 0。
  - 例: プール [A（重み 1）, B（重み 5）]、乱数が [0.5, 0.5] のとき、キーは A=0.5、B=0.5^0.2≒0.871 なので B が先。乱数が [0.9, 0.1] のとき、A=0.9、B=0.1^0.2≒0.631 なので A が先。
- 重みは、出題列を作る時点の記録から求める（ラウンドの途中に記録が変わっても、作り終えた出題列は変えない。適応難易度で出題列を作り直すときは、直前の回答を記録してから、その時点の記録を使う）。
- 無効なとき（オフ、記録がない、重みがすべて 1、再挑戦ラウンド）は、今までと同じ `shuffleArray` を使い、乱数の引き方も今までと同じ。
- 再挑戦ラウンドの出題（間違えた語の固定セット、`createRetrySequence`）は、重み付けの影響を受けない。

### 保存

- 保存先は `localStorage`（ブラウザの端末内）。キーは `kogodrop.records`（記録。`id` をキー、`{c, w}` を値にした JSON のオブジェクト）と `kogodrop.weakWords`（切り替え。`"true"` / `"false"`）。
- 読み書きに失敗しても（`localStorage` が使えない、ブロック、容量超過、JSON が壊れている）ゲームを止めない。
  - 読めない・壊れている: 記録なし（切り替えはオン）として扱う。
  - 書けない: 何もしない（そのセッションの間の記録・切り替えは、メモリの上にだけ持ってよい）。
- 記録を消す操作は、`kogodrop.records` を消す（または空にする）。`kogodrop.weakWords` は消さない。
- `kogodrop.weakWords` が `"true"` / `"false"` 以外（保存がない・壊れている）のときは、オンとして扱う。
- 保存するのはこの 2 つだけ。出題の履歴、スコア、Title の他の選択（言語モード・難易度・出題数）は保存しない。

## パラメータ表

| 名前 | 初期値 | 意味 |
|------|--------|------|
| `weakBoost` | 4 | 重み = 1 + `weakBoost` × 誤答率。いつも間違える語が 5 倍、間違えない語・初見の語が 1 倍 |
| `clearConfirmMs` | 3000 | 「記録を消す」の 1 回目のタップから、2 回目のタップを待つ時間（ms） |
| 切り替えの中心 y・高さ・幅 | 697・44・367 | Title の論理 px（540 × 960）。x の中心は 270 |
| 「記録を消す」の中心 y・タップの範囲 | 830・240 × 40 | Title の論理 px。文字 16px（「もう一度タップで消す」も 1 行で収まる幅） |
| 保存のキー | `kogodrop.records`、`kogodrop.weakWords` | `localStorage` のキー |
| 切り替えの初期状態 | オン | 保存がない・読めないとき |

通常ラウンドの数値（落下速度 400px/s、フラッシュの時間（正解 1.2 秒・不正解 2.5 秒）、適応難易度の評価の窓 5 問・上げる 80%・下げる 40%、出題数 10 / 20 / 30、難易度ごとのプール）は変えない。

## テスト観点

純関数として `logic/` に切り出し、Phaser なしでテストする。`localStorage` は注入できる形（`Storage` 互換のオブジェクトを引数に受け取る）にして、壊れたものも渡せるようにする。乱数は `rng` を注入する。

- **重み**（手計算の値で）: 記録なしは 1。`{c:0,w:0}` → 1、`{c:3,w:0}` → 1、`{c:1,w:1}` → 3、`{c:3,w:1}` → 2、`{c:0,w:3}` → 5、`{c:9,w:1}` → 1.4。`weakBoost` を変えた値（例: 2 で `{c:1,w:1}` → 2）。数が不正な件（負・小数・欠け）は 1。
- **記録の更新**: 正解で `c` が 1 増える、不正解で `w` が 1 増える（切り替えのオン・オフにかかわらず）。記録のない語は 0 から始まる。入力の記録を書き換えない（新しいオブジェクトを返す）。別の語の記録は変わらない。
- **重み付きシャッフル**（`rng` を注入）:
  - 例の値のとおり: プール [A(1), B(5)] で乱数 [0.5, 0.5] → [B, A]、[0.9, 0.1] → [A, B]。
  - 結果の語の集合がプールと一致する（欠けない・重複しない）。入力の配列を書き換えない。
  - 重みがすべて 1 のときの並びは、キー（`u`）の大きい順になる。キーが同じなら、プールの並びが先の語が先。
  - 重みの大きい語が先頭に来る割合が、重みの小さい語より高い（固定の乱数の列で、先頭に来る回数を数えて比べる。数が 0 でないことも確かめる）。
- **出題列（`createQuestionSequence`）**:
  - 重み付けが有効なとき、重い語がそうでない語より、先頭の出題数のうちに含まれやすい（乱数の列を決め、手計算できる小さなプールで、重い語が先頭に来ることを確かめる）。
  - 無効なとき（重みがすべて 1・オフ）の出題列が、重みを渡さない従来の呼び出しと**同じ**になる（同じ乱数の列で `toEqual`。乱数を引く回数も同じ）。
  - 出題数・直前の語を連続させない規則・周回・難易度ごとのプール・`excludeIds` は、重み付けが有効でも守られる。
- **読み書き**:
  - 記録: 保存した記録を読むと同じ値が返る。壊れた JSON・オブジェクトでない値・不正な件は、記録なし（または不正な件だけ無視）になる。保存がないと空。
  - 切り替え: 保存がないとオン、`"false"` でオフ、`"true"` でオン、それ以外の値はオン。保存すると読み戻せる。
  - 失敗: `getItem` / `setItem` が例外を投げる、`Storage` がない（`undefined`）ときも、例外を出さずに、読みは「記録なし・オン」、書きは何もしない。
  - 記録を消すと、読みが空になり、切り替えの保存は残る。
  - 「記録がある」の判定: 有効な件が 1 つ以上で真、空・壊れたもので偽。
- **記録を消す操作（状態機械）**: idle でタップ → armed（時刻を渡す）。`clearConfirmMs` 未満でタップ → 消す。ちょうど `clearConfirmMs`（3000ms）経過後は idle に戻っている（2 回目のタップは 1 回目として扱う）。2999ms なら armed のまま消せる。消したあとは非表示。
- **有効の判定**: `excludeIds` で絞ったあとのプールの重みがすべて 1 のとき（元のプールには重い語があっても）は、`shuffleArray` と同じ乱数の引き方になる。
- **再挑戦**: 再挑戦ラウンドの出題（`createRetrySequence`）は、記録があっても従来と同じ結果になる。
- **回帰（通常ラウンドが変わらないこと。既存のテストを変えずに通ること）**: 単語抽選・スロット生成・正誤判定・正答率・不正解リスト・再挑戦のテストがそのまま通る。重みを渡さない `createQuestionSequence` の結果が、変更前と同じ。

Scene の結線は画面で確かめる（`game-qa`）: Title の切り替えと記録を消す部品の見た目・位置・動き、回答が記録されること（`window.__qa` などで確認）、再挑戦ラウンドでも記録されること、保存が使えなくても遊べること、通常ラウンドで次が変わらないこと（適応難易度の表示・正誤フラッシュの長さ・落下速度・Result・Review）。

## 完了条件

- Title に「苦手な語を多めに出す: オン／オフ」の切り替えがあり、タップで入れ替わる。初期状態はオンで、選んだ状態は次に開いたときも残る（ブラウザで確認）。
- 通常ラウンドと再挑戦ラウンドで回答するたびに、語ごとの記録が保存される。切り替えがオフでも記録される（ブラウザで `localStorage` を確認）。
- 記録がたまると、通常ラウンドの出題で、間違えた語が出やすくなる（重みと重み付きシャッフルの単体テスト。実機では、間違えた語が次のラウンドに含まれやすい）。切り替えがオフのときは、記録があっても重み付けが効かない。
- 記録があるときだけ、Title に「苦手な語の記録を消す」が出る。2 回タップで記録が消え、1 回目のあと 3 秒たつと元の表示に戻る。切り替えの状態は消えない。
- `localStorage` が使えない・容量超過・壊れた記録でも、ゲームは止まらず遊べる（単体テストと、ブラウザで保存を壊して確認）。
- 変えないもの（回帰条件。既存の単体テストがそのまま通ること、ブラウザ QA の操作確認が前回と同じ結果であること）:
  - 落ちゲーの操作（タッチのドラッグ、矢印キー、Space / Enter）、落下速度、正誤フラッシュ（正解 1.2 秒・不正解 2.5 秒、入力を受け付けない）。
  - スロット選択肢の生成、言語モード、正誤判定、正答率、適応難易度（評価 5 問、上げる 80%・下げる 40%）、難易度ごとの出題プール、出題数の選択。
  - Result・Review の内容、再挑戦ラウンドの対象（間違えた語の固定セット）と動き。
  - Title の既存の選択（言語モード・難易度・出題数）の見た目・位置・既定値（古語→現代語・ふつう・20 問）。
  - 記録がないとき、切り替えがオフのとき、再挑戦ラウンドの出題（今までと同じ抽選と乱数の引き方）。
- 小さい画面（375 × 550、667 × 310）、スマホ縦（390 × 844）、PC（1280 × 720）で、Title の 2 つの部品が切れず、他のボタンと重ならない。
- `npm run lint` / `npm run test` / `npm run test:coverage` / `npm run build` がすべて通り、カバレッジが 90% 以上。

## 実装裁量

- 記録・重み・重み付きシャッフル・保存の読み書き・記録を消す状態機械の、`logic/` での関数名・ファイル分け。`GameConfig` に切り替えの状態を入れるフィールド名と、その欠けているときの扱い（Title を通らずに Game・Result・Review が始まる開発用の経路だけの話で、欠けているときはオフとして扱ってよい。Title から始めたゲームは必ず値を持つ）。
- 切り替え・「記録を消す」の色（切り替えの選択中・未選択の色は既存のものを使う）、角の丸み、押したときの見た目、「記録を消す」の armed のときの文字の色。
- メモリの上に持つ記録の形（保存が書けないときの扱い）。回答を保存するタイミング（正誤判定と同時、またはフラッシュの直後）。
- 重みの計算で、小数の丸めを行うかどうか（行わなくてよい。テストの値は丸めなしで 1.4 など）。
- 開発用のログ（`console.log`）の扱い。
