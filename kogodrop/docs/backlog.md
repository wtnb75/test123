# kogodrop（古語ドロップ） 拡張候補（backlog）

公開済みの kogodrop（古語を落として意味スロットへ振り分ける、高校受験向けの落ちゲー）に、次に足せるものの候補を、上から順に並べたものです。上のカードが「次の候補」です。仕様（`spec.md`）ではありません。`game-extend` が上から順に 1 件を選び、目的・コアループへの効き方・変えないもの・spec の置き場所を対話で固めます。

- 規模: S = 1 画面と数値の追加程度、M = 複数の画面や仕組みにまたがる追加、L = 大きいので、`game-extend` で 1 PR 分に切り出してから採用する。
- 1 つのカードは 1 つの目的にする（1 変更 1 目的）。
- 外部の画像・音のアセットは、足してよいかをユーザーに確認してからにする。
- 数値だけの再調整（落下速度・フラッシュの時間・出題プールの語数）は、カードにせず `game-balance` で行う。
- 現状の事実: 保存は何もしない（`localStorage` を使わない）。ゲームオーバー・時間制限は無い。1 問は、落下 4〜6 秒 + 正誤フラッシュ（正解 1.2 秒・不正解 2.5 秒。入力を受け付けない）。5 問ごとに正答率を見て、スロットが 4〜6 個に増減する（適応難易度）。語は約 160（やさしい 約 60・ふつう 約 120・むずかしい 約 160）。例文は `Review` でだけ使っている。`Result` / `Review` から、間違えた語だけを 1 周再出題する再挑戦ラウンドがある（`spec/retry-missed.md`）。

### 間違えた単語を保存し、次回以降の出題で重く出す（`weak-words`）

- 狙い: 何も保存しないので、次に遊ぶと、前に間違えた単語を覚えていない。同じ語を何度も出して定着させる手段が無い。根拠: `Game` / `Result` に保存が無い（`localStorage` を使わない）
- 何を足すか: 単語ごとの正解・不正解の回数を `localStorage` に保存し、出題の抽選で、間違えた語（正解率の低い語）の重みを上げる。Title で、重み付けのオン・オフを選べる。
- コアループへの効き方: 深める — 苦手な語が、繰り返し出る。
- 種別: gameplay
- 規模: M
- 出どころ: spec 分析
- メモ: 保存の失敗（ブロック・容量超過）でもゲームは止まらない。重み付けの式は `game-extend` と `game-balance` で決める。保存した記録を消す操作を付ける。
### 意味や形が紛らわしい語を、ダミーの選択肢に選ぶ（`similar-dummies`）

- 狙い: ダミーの選択肢は、出題プールからのランダム。明らかに違う意味の語が混ざり、消去法で当たる。紛らわしい語（意味の近い語・同じ品詞）で迷えば、学習になる。根拠: `spec`「スロット選択肢の生成ルール」
- 何を足すか: ダミーを、意味の分類（品詞・感情語などのタグ）が同じ語から優先して選ぶ。むずかしい難易度ほど、紛らわしさを強める。
- コアループへの効き方: 深める — 選ぶ判断に、区別するべき語が出る。
- 種別: gameplay
- 規模: M
- 出どころ: spec 分析
- メモ: データにタグ（品詞・意味の分類）が要る場合は、`spec/word-data.md` の改訂を伴う（データの追加は、ユーザーが確認する）。正解スロットの位置はランダムのまま。

### 場を縦に広げ、補助の文字を読めるようにする（`field-fit`）

- 狙い: スマホ縦で、場が上下の黒帯（画面の約 18%）で狭く、NEXT・進捗「0 / 20」・Title のラベル（「タイル（出題）」「スロット（答え）」）が実寸 9〜10 px で読みにくい。SE では左右にも黒帯が出る。落ちるカードは、場に対して小さい。根拠: 2026-10-12 の画面構成の調査（dev サーバー、スマホ縦 390×844・SE 375×550・PC 1280×720、汎用の操作で進めた画像）／AGENTS.md 4.6（補助の文字 11 px 以上、黒帯 15% 超は縦横比に合わせる）
- 何を足すか: 論理サイズ（540 × 960 固定）を画面の縦横比に合わせて場を広げ、NEXT・進捗・Title のラベルを 11 px 以上にする。落ちるカードを、場の幅に対して大きくする。
- コアループへの効き方: 広げない — 見え方だけを変える（出題・落下速度・判定は変えない）。
- 種別: presentation-only
- 規模: M
- 出どころ: 画面構成の調査
- メモ: Title の選択 UI（タイル・スロット・難易度・出題数）が詰まっているので、`game-title`（Title とデモ）の配置の設計と一緒に決めるのがよい。

### 出題のカテゴリ（品詞・分野）を選べるようにする（`categories`）

- 狙い: 全ての語から出るので、苦手な分野（動詞・形容詞・感情語など）だけを練習できない。根拠: `spec`「非 MVP 範囲」（出題カテゴリ選択）
- 何を足すか: Title で出題のカテゴリを選ぶ（複数選択可）。出題プールを、選んだカテゴリの語に絞る。
- コアループへの効き方: 広げる — 練習の絞り込み。
- 種別: gameplay
- 規模: M
- 出どころ: spec 分析
- メモ: データにカテゴリのタグが要る（`similar-dummies` と共通。先にデータを整える）。語数が少ないカテゴリでは、ダミーが足りなくなる（重複許容のフォールバックを確かめる）。

### 落下が段階的に速くなる／連続正解でボーナスを付ける（任意のモード）（`pace-up`）

- 狙い: 時間制限も失敗も無く、緊張感が無い（落ち着いて学習するには良いが、慣れた語では単調）。根拠: `spec`「落下速度仕様」「ゲーム終了条件」「非 MVP 範囲」（タイムアタックモード）
- 何を足すか: Title で、通常（いまのまま）とチャレンジを選ぶ。チャレンジでは、連続で正解するほど落下が速くなり、ミスで元に戻る。結果にスコア（連続正解の最大・正答率）を出す。
- コアループへの効き方: 広げる — 習熟した語での、反射の速さという軸。
- 種別: gameplay
- 規模: S〜M
- 出どころ: spec 分析
- メモ: 通常モードの落下速度・フラッシュの時間は変えない（回帰条件）。フラッシュの時間（入力を受け付けない 2.5 秒）を、チャレンジでは短くするかを決める。

### 正誤フラッシュの後に、複数の意味・例文の解説を出す（`explain-popup`）

- 狙い: 正誤の直後は、1 行の意味だけ。例文・複数の意味は、結果の後の `Review`（間違えた語のみ）でしか見られない。正解した語の意味の幅（多義語）を学べない。根拠: `spec`「非 MVP 範囲」（複数の意味を持つ語の詳細解説ポップアップ）、`exampleSentences.ts`
- 何を足すか: 正誤フラッシュ（2.5 秒）の中に、例文を 1 つ（または、「詳しく」で複数の意味）出す。
- コアループへの効き方: 広げない — 学習の情報を増やす。ルールは変えない。
- 種別: presentation-only
- 規模: S〜M
- 出どころ: spec 分析
- メモ: 例文のない語の扱い（出さない）。フラッシュの長さ・入力の受け付けは、`pace-up` と合わせて決める。

### 効果音を足す（着地・正解・不正解・クリア）（`sound`）

- 狙い: サウンド/BGM は非 MVP のまま。正誤の手応えが、音で補える。根拠: `spec`「非 MVP 範囲」
- 何を足すか: 着地・正解・不正解・結果表示の効果音を、Web Audio で作って鳴らす（外部の音声ファイルは使わない）。ミュートの切り替えを付ける。
- コアループへの効き方: 広げない — 演出の仕上げ。
- 種別: presentation-only
- 規模: S〜M
- 出どころ: spec 分析
- メモ: 最初のタップの後に鳴らす（自動再生の制限）。外部の音声ファイルを使う場合は、足してよいかを確認する。
