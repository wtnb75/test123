# kogodrop（古語ドロップ） 拡張候補（backlog）

公開済みの kogodrop に、次に足せるものの候補を、上から順に並べたものです。上のカードが「次の候補」です。仕様（`spec.md`）ではありません。`game-extend` が上から順に 1 件を選び、目的・コアループへの効き方・変えないもの・spec の置き場所を対話で固めます。

- 規模: S = 1 画面と数値の追加程度、M = 複数の画面や仕組みにまたがる追加、L = 大きいので、`game-extend` で 1 PR 分に切り出してから採用する。

### 場を縦に広げ、補助の文字を読めるようにする（`field-fit`）

- 狙い: スマホ縦で、場が上下の黒帯（画面の約 18%）で狭く、NEXT・進捗「0 / 20」・Title のラベル（「タイル（出題）」「スロット（答え）」）が実寸 9〜10 px で読みにくい。SE では左右にも黒帯が出る。落ちるカードは、場に対して小さい。根拠: 2026-10-12 の画面構成の調査（dev サーバー、スマホ縦 390×844・SE 375×550・PC 1280×720、汎用の操作で進めた画像）／AGENTS.md 4.6（補助の文字 11 px 以上、黒帯 15% 超は縦横比に合わせる）
- 何を足すか: 論理サイズ（540 × 960 固定）を画面の縦横比に合わせて場を広げ、NEXT・進捗・Title のラベルを 11 px 以上にする。落ちるカードを、場の幅に対して大きくする。
- コアループへの効き方: 広げない — 見え方だけを変える（出題・落下速度・判定は変えない）。
- 種別: presentation-only
- 規模: M
- 出どころ: 画面構成の調査
- メモ: Title の選択 UI（タイル・スロット・難易度・出題数）が詰まっているので、`game-title`（Title とデモ）の配置の設計と一緒に決めるのがよい。
