# 3マッチパズル（`match3`・仮称）

## ゲーム名

3マッチパズル（`match3`）。Title には「3マッチパズル」と、小さく `MATCH 3` を出す。

## コンセプト

隣り合う 2 つの石を交換して、同じ色を縦か横に 3 つ以上そろえて消す。消えた分は上から補充され、連鎖でスコアが伸びる。決まった手数の中で高スコアを狙う、オーソドックスな 3 マッチパズル。

## ターゲットプレイヤー

スマホで、1 回 1〜2 分のすき間時間に遊ぶ人。ルールを知っている人は説明なしで遊べる。

## コアループ

盤面を見る → 隣と交換する → そろって消える → 落下・補充 → 連鎖、を繰り返す。4 個以上をそろえると特殊な石が残り、次の手で使える（[特殊な石](spec/special-gems.md)）。手数が尽きたら結果を見て、もう一度遊ぶ。

## 操作仕様

| 場面 | タッチ / マウス | キーボード（補助） |
|---|---|---|
| Title | START ボタンをタップ（押した場所で離したときに働く） | Space / Enter で START |
| Game | 石を 2 回タップして交換（1 つ目で選び、隣の石で交換）。または石から隣の方向へ指（マウス）を動かして交換（スワイプ） | ← → ↑ ↓ でカーソルを動かす。Space / Enter で今のカーソルの石を選ぶ（もう一度押すと選択を解く）。石を選んでいる間は、← → ↑ ↓ でその方向の隣と交換する。Esc で選択を解く |
| Result | 「もう一度」「タイトルへ」をタップ（押した場所で離したときに働く） | Space / Enter で「もう一度」 |

Game の入力の細部:

- 石の選択: 盤面の石をタップすると選択され、白い枠（選択枠）が付く。選択中に隣の石をタップすると交換する。隣でない石（斜め・2 マス以上離れた石）をタップしたら、その石を選び直す。選択中の石をもう一度タップしても、選択は変わらない（そのまま選択中）。盤面の外のタップは何も起こさない。
- スワイプ: 石の上で押してから、押した点との距離の大きい方の軸（x か y。同じなら x）に `CELL` × `SWIPE_RATIO` 以上動いた瞬間に、その方向（符号）の隣の石と交換する（指を離すのを待たない）。隣が盤面の外なら何も起こさない（選択も解く）。スワイプで交換するときは、それまでの選択を解く。移動量が足りないまま離したときは、タップとして扱う（上の石の選択）。
- 交換の成否: 交換した結果、1 つ以上の「そろい」（3 つ以上の同じ色の縦・横の並び）ができたら成立し、手数を 1 つ使う。できなければ元に戻り、手数を使わない。ただし、色の石（特殊な石。[特殊な石](spec/special-gems.md)）を含む交換は、「そろい」が無くても成立する。
- 入力を受け付けない間: 交換・消去・落下・シャッフルのアニメーションの間、終了の演出（`ending`）の間。この間のタップ・スワイプ・キーは無視する（押した時点で受け付けない状態なら、そのタップは何も起こさず、離したときにも働かない）。
- カーソル（キーボード）: カーソルが見えていないときのキー入力は、カーソルを現すだけで、他には何もしない（矢印で動かさず、Space で選ばず、選択中でも交換しない）。現れる位置は、ポインタで選択中の石があればその石の位置（選択は残る）、なければ最後にポインタで触れた石（タップした石、またはスワイプを始めた石）の位置、それも無ければ `CURSOR_START`（行 3・列 3。0 始まり）。見えているときの矢印は、盤面の端では止まる（回り込まない）。ポインタ（タップ・スワイプ）を使うとカーソルは見えなくなる。カーソルは細い黄色の枠、選択枠は白い太い枠で区別する。キーで交換が起こったあと（成立・不成立とも）選択は解け、カーソルは交換を始めた石の位置に残る。選択中の石から盤面の外へ向かう矢印キーは何も起こさない（選択は残る）。キーの自動リピート（押しっぱなしの繰り返し）は無視し、1 回の押下を 1 回の入力とする。
- 1 回の押下とスワイプ: 1 回の押下（押してから離す、または `pointercancel`）で起こる交換は 1 回まで。スワイプで交換した、または盤面の外へ向かって何もしなかったあとに離しても、タップとしては働かない。`pointercancel` では、そこまでの押下の記録を捨てて何もしない。

## 画面・Scene構成

| Scene | 役割 |
|---|---|
| Title | ゲーム名・遊び方・自己ベスト・START ボタン |
| Game | プレイ。HUD（SCORE / MOVES / BEST）と 8 × 8 の盤面 |

### 画面の大きさ（論理サイズ）

- 幅は `SCREEN_WIDTH` で固定。高さは `round(SCREEN_WIDTH × 表示の高さ / 表示の幅)` を `[SCREEN_HEIGHT_MIN, SCREEN_HEIGHT_MAX]` に収めた値 H にする。Title に入ったとき、Title にいる間に表示の大きさが変わったとき（画面を回したときなど）、Game を始めるとき（START と「もう一度」）に決め直す。Game・Result の間は変えない（プレイ中に盤面の大きさを変えないため）。Phaser の `Scale.FIT` で中央に置く。
- 手計算の例（縮小率 = `min(表示の幅 / 論理の幅, 表示の高さ / H)`）:

| 表示の大きさ | 論理の大きさ | 縮小率 | 黒帯 |
|---|---|---|---|
| 390 × 844（スマホ縦） | 360 × 779 | 1.083 | なし |
| 375 × 550（iPhone SE 縦） | 360 × 528 | 1.042 | なし |
| 1280 × 720（PC） | 360 × 520（下限） | 1.385 | 左右に計 61%。縦持ちを前提にした盤面（8 列を幅に並べる）なので許容する（石・文字は十分に大きい） |
| 667 × 310（スマホ横） | 360 × 520（下限） | 0.596 | 案内を出す（下） |

- 石 1 マスの大きさは `CELL` = 44（論理）で、実寸は縮小率 1.042（SE 縦）で 45.8、1.083（390 縦）で 47.7。タップの的は 1 マス全体で、実寸 44 px 以上は、論理の幅 360 以上の端末（縮小率 1.0 以上）で満たす。幅が 360 px より狭い端末（例: 320 px で縮小率 0.889、実寸 39）では 44 を割るが、8 列を 1 画面の幅に並べる都合で許容する（スワイプでも交換でき、的が隣り合うので誤タップは「選び直し」にとどまる）。
- 表示が横長（幅 > 高さ）で、縮小率が `ROTATE_PROMPT_SCALE` 未満のとき（667 × 310 は 0.596、844 × 390 は 0.75。0.875 以上は出ない）は、文字が読めない大きさになるので、どの Scene でも、その上に「画面を縦に」「してください」の 2 行の案内を全面に出す。この間 Game は進行を止め（アニメーション・ヒントの計時・`RESULT_DELAY_MS` が進まない）、Result の計時（`COUNT_UP_MS`・`BEST_BLINK_MS`・`RESULT_INPUT_GUARD_MS`）もすべて止め、Title・Result も入力を受け付けない。表示の大きさが変わって条件を外れたら案内を消して続きから再開する。案内の文字の大きさは、論理で `min(ceil(PROMPT_REAL_FONT_SIZE ÷ 縮小率), PROMPT_MAX_FONT_SIZE)`（縮小率が 0 以下なら `PROMPT_MAX_FONT_SIZE`）。PC（1280 × 720、縮小率 1.385）や 1024 × 768（1.477）には出ない。縦長の表示（幅 ≤ 高さ）には出ない。想定外として、幅が約 315 px 未満の端末や、正方形に近い小さな窓では、文字が小さくなるが対応しない。

主な情報は実寸 14 px 以上、補助は 11 px 以上（AGENTS.md 4.6）。縦持ちの縮小率は、幅 320 px の端末でも 0.89 以上。

### Title

- 文字のかたまり（ゲーム名・`MATCH 3`・説明 3 行・自己ベスト）を、画面の上端と START ボタンの間の中央に置く。かたまりの高さは `TITLE_BLOCK_H`、START の上端との間は `TITLE_BLOCK_GAP`。かたまりの上端 y = `max(16, floor((START の上端 y − TITLE_BLOCK_GAP − TITLE_BLOCK_H) ÷ 2))`。
- かたまりの中身（かたまりの上端からの中心 y）: ゲーム名 +30、`MATCH 3` +70、説明 3 行 +120 / +144 / +168、自己ベスト +220。
- 説明（3 行）:「となり合う石を入れかえて」「同じ色を 3 つ以上そろえて消そう」「手数 30。連鎖と 4 個以上でボーナス」（手数は `MOVES` の値から作る）。得点の計算式は書かない（プレイテストで、常設の説明は要らないとされた。点数はポップアップで見せる）。
- 自己ベスト: `BEST` と数字（記録が無ければ `BEST ---`）。
- START ボタン: 画面の幅の中央、中心 y = H − `TITLE_BUTTON_FROM_BOTTOM`、大きさ `BUTTON_W` × `BUTTON_H`。
- 手計算: H = 528 のとき、START の上端 = 528 − 130 − 26 = 372、かたまりの上端 = max(16, floor((372 − 24 − 240) ÷ 2)) = 54、ゲーム名の中心 y = 84、自己ベストの中心 y = 274、START の中心 y = 398。H = 779 では、START の上端 = 623、かたまりの上端 = floor((623 − 24 − 240) ÷ 2) = 179、自己ベスト y = 399、START y = 649（縦長のスマホで、かたまりの下端 419 と START の上端 623 の間に約 204 の空きが残る。START を親指の届く画面の下 1/3 に置くための余白なので許容する）。

### Game

#### 配置

盤面（`COLS` × `ROWS` マス、1 マス `CELL`）と HUD を 1 つのかたまりとして、画面の上下中央に置く。

- かたまりの高さ `GROUP_H` = `HUD_H` + `HUD_GAP` + `ROWS` × `CELL` = 88 + 8 + 352 = 448。かたまりの上端 y = `max(0, floor((H − GROUP_H) ÷ 2))`。
- 盤面の左端 x = `(SCREEN_WIDTH − COLS × CELL) ÷ 2` = 4。盤面の上端 y = かたまりの上端 + `HUD_H` + `HUD_GAP`。
- HUD（かたまりの上端からの位置）: 左に `SCORE`（見出しの中心 y +12、値の中心 y +42。左端 x = `HUD_SIDE_MARGIN`）、右に `MOVES`（同じ y。右端 x = `SCREEN_WIDTH − HUD_SIDE_MARGIN`）、画面の幅の中央に `BEST 1230`（中心 y +76。記録が無く、スコアも 0 のときは `BEST ---`）。
- BEST の数字: 保存された自己ベストと今のスコアの大きい方。スコアが自己ベストを超えたら、その瞬間から BEST の数字はスコアと同じ値で増える（保存は Result で行う）。
- 手計算: H = 528 → かたまりの上端 40、盤面の上端 136、下端 488。H = 520（下限）→ 上端 36、盤面 132〜484。H = 779 → 上端 165、盤面 261〜613。H = 800（上限）→ 上端 176、盤面 272〜624。縦長のスマホで盤面の上下に空きが残るのは、盤面が幅で決まる正方形（8 × 8）で、縦に伸ばせないため。

#### 状態

| 状態 | 内容 | 次へ進む条件 |
|---|---|---|
| `idle` | 入力を受け付ける。ヒントの計時が進む | 隣り合う 2 つの石の交換の操作（成立・不成立を問わない）→ `swapping` |
| `swapping` | 2 つの石が `SWAP_MS` で位置を入れかわる。入力は無視 | 交換が成立する（交換後の盤面に「そろい」がある、または色の石を含む。[特殊な石](spec/special-gems.md)）→ 手数を 1 減らして `resolving`。成立しない → 元に戻す動き（`SWAP_MS`）のあと `idle`（手数は減らない） |
| `resolving` | そろった石を `CLEAR_MS` で消す → 落下・補充を `FALL_MS_PER_CELL` × 落ちる段数（落ちる石のうち最大の段数に合わせる）で動かす → 再び「そろい」を探す、を「そろい」が無くなるまで繰り返す。1 周ごとに連鎖の段数が 1 増える。入力は無視 | 「そろい」が無くなった → 手数が 0 なら `ending`。0 より多く、動かせる手が無ければ `shuffling`。それ以外は `idle` |
| `shuffling` | `NO MOVES` / `SHUFFLE` の通知を出し、盤面の石の並びを入れかえる（動かせる手がある並びになるまで）。入力は無視 | `SHUFFLE_NOTICE_MS` たった → `idle` |
| `ending` | `FINISH` の通知を出す。入力は無視。盤面・HUD はそのまま残す | `RESULT_DELAY_MS` たった → Result へ（スコアを渡す） |

- 手数は交換が成立した瞬間（`swapping` → `resolving`）に減る。最後の手でも、連鎖は最後まで続き、得点はすべて入る。
- 手数が 0 になる最後の交換のあとは、動かせる手が無くてもシャッフルしない（`ending` へ行く）。
- Game に入ったときは `idle`。手数 `MOVES`、スコア 0、盤面は新しく作る。

| ヒント | `idle` のまま、最後の入力（タップ・スワイプ・キーの押下・離し）または `idle` に入ってから `HINT_DELAY_MS` たった | 動かせる手のうち「ヒントの手」（ルール「ヒントの手」）の 2 つの石を、大きさ 1.0 ↔ `HINT_SCALE` で `HINT_HALF_MS` ごとに往復させる（止めるまで繰り返す）。ヒントの手は、出す瞬間（`HINT_DELAY_MS` たったとき）の盤面で 1 回だけ決める | 押下・キー入力・`idle` を抜けたとき（`swapping` など）に止めて、大きさを 1.0 に戻す。`idle` に戻ったら、また `HINT_DELAY_MS` から数える。`ending`・案内中は出さない。同時に 1 つだけ |
| 盤面の板 | Game に入ったとき（以後ずっと表示） | 盤面の外側へ `PANEL_PAD` ずつ広げた角丸（半径 `PANEL_RADIUS`）の矩形を `COLOR.panel` で塗り、盤面の範囲を見せる。石・選択枠・カーソルより奥、背景より手前 | 補充の石は板の上端より上に見えない（「落下・補充」の行の覆い）。ヒントで大きくなった石が盤面の端のマスで板の外へはみ出すのは許容する。入力は受け付けたままで、板自体はタップに反応しない。盤面の外のタップは「盤面の外」のまま（板の余白 `PANEL_PAD` は盤面に含めない） |
| MOVES の警告 | 表示している残り手数が `MOVES_WARN` 以下になった（成立した交換で手数が減る瞬間） | HUD の MOVES の数字を `COLOR.warn`（赤）にする。見出し `MOVES` と他の HUD は変えない | 境界: 6 は白、5 は赤、0 も赤（`ending`・Result へ移るまで）。手数は増えないので白へは戻らない。新しい Game（もう一度・Title から）では `MOVES` の値が `MOVES_WARN` より大きいので白から始まる |
| SCORE の強調 | 消去が始まる瞬間に HUD の SCORE が増えた（連鎖の 1 周ごと） | HUD の SCORE の数字を、左端と縦の中心を固定して、大きさ 1.0 → `SCORE_BUMP_SCALE` → 1.0 に `SCORE_BUMP_MS` で往復させる（中央 `SCORE_BUMP_MS` ÷ 2 で最大）。Phaser の tween の yoyo | 途中でまた増えたら、大きさ 1.0 から数え直して最初からやり直す（重ねない）。連鎖で続けて増える場合も同じ。Game に入った直後（スコア 0）は出さない。`ending` で Result へ移ると、途中でも消える。入力は止めない。HUD の他の項目は動かさない |
| 通知 | `shuffling` と `ending` | 盤面の中央に、黒（不透明度 0.8）の背景つきの文字（`NO MOVES` / `SHUFFLE` の 2 行、または `FINISH`）。`shuffling` は `SHUFFLE_NOTICE_MS`、`ending` は `RESULT_DELAY_MS` の間出し、終わったら消す（`ending` は Result への切り替えで消える） | `shuffling` では、石の並びは通知が出た直後に変わり、通知の間は石は動かない |

- 描画の順（奥から手前）: 背景 → 盤面の板 → 盤面の石 → カーソル → 選択枠 → 覆い → 通知 → ポップアップ → HUD の文字。HUD は盤面と重ならない領域にある。
- 効果音・パーティクル・画面の揺れは出さない（非MVP範囲）。

### Result

- `RESULT`（見出し）・`SCORE` の見出し・スコア（`COUNT_UP_MS` で 0 から数え上げる）・自己ベストの行・2 つのボタン。
- 文字のかたまり（見出し・スコア・自己ベストの行）を、画面の上端とボタンの間の中央に置く。かたまりの高さ `RESULT_BLOCK_H`、ボタンの上端との間 `RESULT_BLOCK_GAP`。かたまりの上端 y = `max(16, floor((ボタンの上端 y − RESULT_BLOCK_GAP − RESULT_BLOCK_H) ÷ 2))`。中身（かたまりの上端からの中心 y）: 見出し +24、`SCORE` の見出し +72、スコア +112、自己ベストの行 +170。
- 自己ベストの行: 新記録なら `NEW BEST!`（黄。`BEST_BLINK_MS` で不透明度 1 ↔ `BEST_BLINK_ALPHA` を `BEST_BLINK_COUNT` 回点滅。スコアの数え上げが終わってから始める）。そうでなければ `BEST` と自己ベストの数字（保存されたベストが無いときは `BEST ---`）。新記録の条件: 保存されたベストが無く、スコアが 1 以上のとき、または保存されたベストをスコアが厳密に超えたとき（同点・スコア 0 は新記録にしない）。
- ボタン: 左に「もう一度」、右に「タイトルへ」。大きさ `RESULT_BUTTON_W` × `BUTTON_H`、間 `RESULT_BUTTON_GAP`、中心 y = H − `RESULT_BUTTON_FROM_BOTTOM`。2 × 156 + 16 = 328 ≤ 360。H = 528 のとき: ボタンの中心 y = 458（上端 432）、かたまりの上端 = max(16, floor((432 − 24 − 200) ÷ 2)) = 104。
- 「もう一度」→ 画面の大きさを決め直して Game へ。「タイトルへ」→ Title へ。
- 入力ガード: Result を始めてから `RESULT_INPUT_GUARD_MS` の間、ボタン・キーを受け付けない（最後の操作の連打が「もう一度」に当たるのを防ぐ）。
- 保存: Result に入るとき（Game から渡されたスコアで）自己ベストを記録する。

### ボタン（Title・Result）

- 押した位置のボタンの上で離したときだけ働く（押して外へ出して離す・押さずにホバーだけ・ガード中に押してガード明けに離す・`pointercancel` では働かない）。
- 見た目: 通常 `COLOR.button`、ホバー `COLOR.buttonHover`、押している間 `COLOR.buttonPressed` で、大きさ `BUTTON_PRESS_SCALE` 倍。色は実装裁量で近い色にしてよい。

## ルール

### 盤面

- 盤面は `COLS` × `ROWS`（8 × 8）の格子で、各マスに `COLORS`（6）色のうちの 1 色の石が 1 つ入る（特殊な石の色の石だけは色を持たない。[特殊な石](spec/special-gems.md)）。空きは、消去から補充の間だけ。
- Game に入るときに盤面を新しく作る。作った盤面は、「そろい」が 1 つも無く、動かせる手（交換して「そろい」ができる隣り合う 2 つの石の組）が 1 つ以上ある。補充の色は、その時点の盤面と関係なく、各マスで一様な乱数で選ぶ（連鎖は偶然に起こりうる。起きるように細工しない）。

### そろい

- 同じ色の石が縦または横に 3 つ以上連続したら、その連続した全部の石が「そろい」。縦と横の並びが交わるとき（L 字・T 字・十字）の交点の石は、1 つとして数える。盤面全体で同時にできたすべての「そろい」を、1 回の消去でまとめて消す（特殊な石になるマスの石、と特殊な石の効果の扱いは [特殊な石](spec/special-gems.md)）。

### 交換

- 隣り合う（上下左右）2 つの石だけが交換できる。交換して「そろい」ができなければ元に戻り、手数は減らない。できれば手数が 1 減り、消去が始まる。色の石を含む交換は例外で、「そろい」が無くても成立する（[特殊な石](spec/special-gems.md)）。

### 落下・補充・連鎖

- 消したあと、各列で石が下に詰まる（空きの下にある石は動かない。石の上下の順は変わらない）。空いた上の部分に新しい石を補充する。補充の乱数を引く順は、列ごとに左から右、各列は上から下（テストで再現するため）。石の色の番号 = `floor(rng() × COLORS)`（0 〜 `COLORS` − 1。`COLOR.gems` の並びの順）。
- 補充のあとにまた「そろい」があれば、連鎖の段数を 1 増やして消去を繰り返す。連鎖の段数は交換のたびに 1 から始まる。
- 4 個以上の直線や L 字・T 字・十字をそろえると、そろえたマスに特殊な石が残る。特殊な石は落下でも種類をつけたまま動き、補充の石は通常の石だけ。消去の細部（できる位置・効果・数え方）は [特殊な石](spec/special-gems.md)。

### スコア

- 1 回の消去（連鎖の 1 周）の得点 = `(消した数 × SCORE_PER_GEM + max(0, 消した数 − 3) × BONUS_PER_EXTRA_GEM) × 連鎖の段数`。消した数は、その 1 回の消去で消えた石の総数（縦横の並びが複数でも、離れた複数の「そろい」でも合算する）。特殊な石の効果で消えた石と、特殊な石になる石も数える（[特殊な石](spec/special-gems.md)「消去の決め方」）。
- 例: 3 個・1 段 = 30、4 個・1 段 = 60、5 個・1 段 = 90、3 個・2 段 = 60、5 個・3 段 = (50 + 40) × 3 = 270、離れた 3 個と 3 個を同時 = 6 個・1 段 = 60 + 60 = 120。
- 得点は、消去が始まる瞬間（ポップアップを出す瞬間）に HUD のスコアへ加える。

### ヒントの手

無操作のヒントが光らせる手（動かせる手のうち 1 つ）は、次の順で決める。乱数は使わず、同じ盤面（色と石の種類）なら必ず同じ手になる。

1. **段**: 手の「段」は、交換する 2 つの石のうち下のほうの行（行番号が大きいほう。左右の交換なら石の行、上下の交換なら下の石の行）。段が大きい（盤面の下の）手を優先する。
2. **消える数**: 同じ段の手は、その交換の最初の消去の「数える石」の数（[特殊な石](spec/special-gems.md)「消去の決め方」の 8。特殊な石・色の石の効果で消える石と、特殊な石になる石を含む）が多い手を優先する。色の石を含む交換も、同じものさしで他の手と並べる（特別扱いしない）。数えるときの交換は、探索の順で先の石（各組の先の石）を先に指定した交換として試す（特殊な石のできる位置が先に指定した石に依存するので、これで固定する。実際にどちらから触るかによらない）。
3. **探索の順**: ここまでが同じ手は、探索の順（上の行から、同じ行では左から、各石について「右との交換」を先に、次に「下との交換」）で先の手。各組は、探索の順で先の石から 1 回だけ数える。

動かせる手があるかどうかの判定（盤面の生成・手詰まり・シャッフル・手数 0 のあとの次の状態）は、この選び方によらない（動かせる手が 1 つでもあるかだけを見る）。

例（手計算。行・列は 0 始まり）: 行 2 の左右の交換（段 2、3 個）と、行 5 と行 6 の上下の交換（段 6、3 個）の 2 つしか動かせる手が無いとき、段 6 の手を指す（探索の順では行 2 の手が先だが、段が大きいほうを優先）。どちらも段 5 の手で、3 個消えるものと 4 個消えるものなら 4 個のほう。段も数も同じ 2 つなら、探索の順で先のほう。

### 手詰まり

- 連鎖が終わり、手数が残っていて、動かせる手（色の石を含む隣り合う組も数える。[特殊な石](spec/special-gems.md)）が無いとき、石の並びを自動で入れかえる（`shuffling`）。入れかえは、いまの盤面の石をすべて使って並べ直し、「そろい」が無く、動かせる手がある並びになるまで繰り返す。`SHUFFLE_MAX_TRIES` 回続けてもそういう並びにならないときは、盤面を新しく作り直す（石の色の内訳は変わる。ごくまれ）。入れかえで手数もスコアも変わらない。

### 終わり

- 手数が 0 になり、その最後の連鎖が終わったら終わり（`ending` → Result）。勝ち負けは無く、スコアを自己ベストと比べる。

### 自己ベスト

- Result に入るとき、まず保存前のベスト（`load()`）とスコアから新記録かどうかを判定し（純関数）、そのあとでスコアを共有パッケージ `best-store` で記録する（キー `match3.best`、値 `{ score, label }`。`label` は `<スコア>点`、例: `1230点`）。スコアが 0 のときは記録しない（保存されたベストが無いままになり、Title・Game・Result は `BEST ---` を出す）。保存の約束と、保存が使えないとき（メモリだけで動く）の扱いは `shared/best-store/README.md` のとおり。Title の自己ベストと Game の BEST は、同じ値を読む。

## MVP範囲（初版で作る範囲）

- Title・Game・Result の 3 Scene
- 8 × 8・6 色の盤面、タップ 2 回とスワイプでの交換、そろい・消去・落下・補充・連鎖、手数 30 のスコア勝負
- 4 個以上を同時に消したときのボーナス、連鎖の倍率、得点のポップアップ
- 動かせる手が無いときの自動シャッフル、無操作のヒント
- 自己ベストの保存と表示（`best-store`）
- キーボード操作（補助）
- 画面の大きさへの対応（高さを縦横比に合わせる、横長の小さい画面では「縦にしてください」）

## 非MVP範囲（今回は作らない範囲）

- アイテム、パワーアップ（4 個以上でできる特殊な石は拡張で入っている）
- 目標付きのステージ、面の選択
- ランキング
- 交換のルールの派生（ナナメ隣・桂馬・列スライド）。ただし、交換できる相手の決め方（どの石とどの石が交換できるか）は 1 つの関数にまとめ、差し替えられる形にしておく（技術要件）
- 石の形の違い（色覚の違いへの配慮）、効果音、BGM、パーティクル、画面の揺れ
- 一時停止、難易度の選択

## 技術要件

- Phaser 4 + Vite + TypeScript。描画は Phaser の Graphics / Text で行い、画像アセットは使わない（スキャフォールドのテンプレートの画像は使わなければ消す）。石は Graphics で描いたテクスチャ（円とハイライト）を使い回してよい
- 自己ベストは共有パッケージ `best-store` を使う（`package.json` に `"best-store": "workspace:*"` を宣言する。AGENTS.md 2.1 節）
- ESLint エラー 0、Vitest のカバレッジは 4 指標とも 90% 以上
- Scene は Title / Game / Result に分け、`preload` / `create` / `update` の責務を混ぜない。入力イベントは Scene の終了時に外す。毎フレームの処理は最小にする（アニメーションは Phaser の tween・timer に任せ、`update` で石を動かさない）。Phaser の機能で足りるもの（tween・timer・camera）は自前で作らない
- Phaser に依存しない純ロジック（役割ごとのモジュールに分ける）:
  - 盤面の生成（そろい無し・動かせる手あり）、「そろい」の検出（縦横・L / T 字の交点を 1 つに数える・空きは無視）、交換の判定、動かせる手の探索（探索の順で最初の手を返す。動かせる手があるかの判定に使う）、ヒントの手の決定（盤面と石の種類から、ルール「ヒントの手」の順で 1 つ選ぶ。各候補の「数える石」の数は、交換を盤面と石の種類の複製で試して数える。元の盤面は変えない。出す瞬間に 1 回だけ呼ぶので、毎フレームの処理にはならない）
  - 交換できる相手の決め方（上下左右の隣。差し替えられる 1 つの関数）
  - 落下（各石の落ちる段数の一覧を返す）と補充（新しい石の位置と色）、手詰まりのときの並べ直し（`SHUFFLE_MAX_TRIES` を超えたら作り直し）
  - スコア（1 回の消去の得点）と連鎖の段数
  - 特殊な石（[特殊な石](spec/special-gems.md)）: 石の種類、並びのグループ化と特殊な石の種類・位置の決定、効果の展開（消える石の集まり）、色の石の交換。盤面の石は色と種類を持つ。乱数は使わない
  - 盤面の座標とマスの変換（タップ点 → マス。盤面の外は無し。マス → 中心の座標）、スワイプの判定（移動量・方向・隣のマス・盤面の外）
  - 入力の状態の決め方（選択・選び直し・交換・カーソルの移動と端での止まり・キーでの交換）
  - 画面の大きさ（論理の高さ、縮小率、案内を出す条件、案内の文字の大きさ）、Title・Game・Result の配置の計算（かたまりの上端、盤面の位置）
  - 演出の値の決定（Scene の外の純関数）: ポップアップの行（`CHAIN x`・`BONUS`・`+得点`）、ポップアップの倍率（連鎖の段数 → 倍率）、ポップアップの位置の切り詰め（倍率つき）、残り手数の警告の判定（`MOVES_WARN` 以下）、新記録の判定、スコアの数え上げの値（経過時間 → 整数）、ボタンの状態と離したときに働く条件
  - 自己ベストの記録・読み出し（`best-store` に `Storage` を引数で渡す形）
- 乱数は `rng: () => number`（[0, 1)）を引数で渡す。時間は引数で渡す。純ロジックの中で `Math.random` や `Date` を使わない。Scene が使う乱数は 1 か所（`Math.random` を `rng` として渡す）にまとめる

## テスト観点

- 「そろい」の検出: 横 3・縦 3・4・5 連続、L 字（5 個、交点を 1 つに数える）、T 字・十字、離れた 2 つの「そろい」（合算）、盤面の端・角、2 連続は対象外、別の色が間に入ると途切れる、空き（`null`）のマスは「そろい」にならない（空きが 3 つ並んでも検出しない）
- 盤面の生成: 多くの seed（例: 200）で、そろい無し・動かせる手あり・全マスが `COLORS` 未満の色で埋まる。`rng` の端の値（0 と 0.999…）でも終わる
- 動かせる手: 交換して「そろい」ができる組だけが対象（色の石の無い盤面で。盤面の端をまたがない）、手が無い盤面で空、探索の順（上の行・左の石・右との交換が先）で最初の手が決まる。探索しても盤面は変わらない
- 交換の判定: 隣り合わない（斜め・2 マス・同じマス）は不可、成立しない交換は元に戻る
- 落下・補充: 各列で石が下へ詰まる（順番は変わらない・空きの下は動かない）、落ちる段数の一覧が手計算と一致、補充は空きの数だけで、`rng` を列ごとに左から右・上から下の順に引く
- スコア: 3 個 1 段 = 30、4 個 1 段 = 60、5 個 1 段 = 90、3 個 2 段 = 60、5 個 3 段 = 270、6 個 1 段 = 120、0 個 = 0（消した数が 3 未満でも追加点は負にならない）
- 手詰まり: 並べ直しのあとの盤面は、そろい無し・動かせる手あり・石の色の内訳が元と同じ。`SHUFFLE_MAX_TRIES` 回で見つからないとき盤面を作り直す（`rng` を固定して、並べ直しが成立しない盤面で）。手数 0 のときはシャッフルしない（Game の状態のテスト）
- 連鎖: 消去のあとに補充でまた「そろい」ができる手作業の盤面で、連鎖の段数が 2 になり、得点が（消した数 × 10 + 追加点）× 段数。交換のたびに段数が 1 に戻る
- 手数: 成立した交換で 1 減り、不成立の交換では減らない。最後の手の連鎖の得点が入ってから `ending` に入る
- スワイプ: 移動量が `CELL` × `SWIPE_RATIO`（17.6）未満で不成立（タップ扱い）、ちょうど 17.6 で成立、x と y が同じ移動量なら x が優先、方向の符号（左・右・上・下）、盤面の外へ向かうスワイプは何も起こさず選択を解く
- タップ → マス: 盤面の左上（x = 4、y = 盤面の上端）が行 0・列 0、右下の 1 px 内側が行 7・列 7、盤面の外（x = 3、x = 356、y = 盤面の上端 − 1、y = 盤面の下端）は無し
- 入力の状態: 1 つ目のタップで選択、隣のタップで交換、斜めのタップで選び直し、選択中の石を再度タップしても変わらない、入力を受け付けない状態のタップは無視（離したときにも働かない）。キー: カーソルが端で止まる（回り込まない）、Space で選択・もう一度で解除、選択中の矢印で交換（盤面の外へは何も起こらず選択は残る）、交換後に選択が解けてカーソルが元の位置、Esc で解除、ポインタの使用でカーソルが消える
- 配置: H = 520・528・779・800 のかたまりの上端と盤面の位置（上の手計算の値。H = 440 のように低くてもかたまりの上端は 0 以上）、Title のかたまりの上端（H = 528 → 54、H = 779 → 179）、Result のかたまりの上端（H = 528 → 104）
- 画面の大きさ: 表の 4 つの表示の大きさで、論理の大きさ・縮小率・案内の有無が一致（390 × 844 → 779、375 × 550 → 528、1280 × 720 → 520、667 × 310 → 案内あり、844 × 390 → 案内あり、1024 × 768 → 案内なし）。案内の境界: 600 × 455 は縮小率 0.875 ちょうどで案内なし、600 × 454 は 0.873 で案内あり。縦長の表示には案内が出ない。表示の幅が 0 のとき高さは下限。案内の文字の大きさ: 縮小率 0.596 で 31、縮小率 0.2 で上限 53、縮小率 0 以下で 53
- 演出の値: ポップアップの行 — 連鎖 1 段・3 個 → `+30` のみ、連鎖 1 段・4 個 → `BONUS` と `+60`、連鎖 2 段・3 個 → `CHAIN x2` と `+60`、連鎖 3 段・5 個 → `CHAIN x3`・`BONUS`・`+270`。位置の切り詰め（倍率 1.0）: x が 10 → 60、x が 350 → 300、y が盤面の上端 + 10 → 盤面の上端 + 110、盤面の下端 − 10 → 盤面の下端 − 40。倍率: 連鎖 1 段 → 1.0、2 段 → 1.0、3 段 → 1.15、4 段 → 1.30、5 段 → 1.45、6 段 → 1.5（上限）、10 段 → 1.5（浮動小数点の誤差があるので、許容誤差つきで比べる）。倍率 1.5 の切り詰め: x が 10 → 90、x が 350 → 270、y が盤面の上端 + 10 → 盤面の上端 + 130（= 60 + 70）、盤面の下端 − 10 → 盤面の下端 − 60。残り手数の警告: 6 → 警告なし、5 → 警告、0 → 警告、30 → 警告なし。盤面の板・SCORE の強調・MOVES の赤の見た目は QA（スクリーンショット）で確かめる
- ヒント: 無操作が 4999 ms では出ず、5000 ms ちょうどで出る。タップ・キーで止まり、`idle` を抜けると止まる。`ending`・案内中は出ない。シャッフル後は新しい盤面のヒントの手を指す
- ヒントの手（盤面と石の種類を手で組んで確かめる。結果の 2 つの石の順は問わない）: 段が違う 2 つの手では段が大きいほう（行 2 の左右の交換と、行 5・6 の上下の交換 → 後者。上下の交換の段は下の石の行 6）。同じ段で消える数が違う手では多いほう（3 個と 4 個 → 4 個）。段も数も同じ手では探索の順で先（左の石・右との交換が先）。動かせる手が 1 つだけならその手。手が無い盤面では無し。色の石を含む交換は、数える石の数（相手の色が全部消える数）で他の手と並べる（同じ段で、色の石の手が 8 個・通常の手が 3 個 → 色の石の手。逆に、色の石の手が下の段で、数が少なくても → 段が優先で色の石の手）。特殊な石の効果で消える数も数える（線の石が並びに入る手は、行や列の分だけ多い）。数えるときの交換は探索の順で先の石を先に指定したものとして試す（実際のプレイと同じ呼び方で数える。どちらを先にしても数は変わらない）。同じ盤面で何度呼んでも同じ手。呼んでも盤面と石の種類は変わらない。動かせる手があるかの判定（盤面の生成・手詰まり・手数 0 のあと）は、今までと同じ結果（既存のテストが期待値のまま通る）
- 変えないもの（ヒントの拡張。回帰）: ヒントの手の決定以外の既存のテスト（交換の成否・得点・補充の乱数順・動かせる手の探索 `findMove`・手詰まり・入力・配置・画面の大きさ・Result・保存）は、期待値を変えずに通る。ヒントの出る時間・止まる条件・見た目と、Title の文言は QA（スクリーンショット）で確かめる
- Result: スコアの数え上げは、スコア 350 で t = 0 → 0、300 ms → 175、600 ms → 350、900 ms → 350、スコア 0 は常に 0。新記録の条件（記録なしでスコア 1 → 新記録、記録なしでスコア 0 → 新記録でない、同点 → 新記録でない、超える → 新記録）。「NEW BEST!」の点滅は Phaser の tween（`BEST_BLINK_MS` / 2 ごとに不透明度 1 ↔ `BEST_BLINK_ALPHA` の往復を `BEST_BLINK_COUNT` 回、`COUNT_UP_MS` 待ってから始める）に任せ、値の関数は作らない。見た目は QA（スクリーンショット）で確かめる
- ガード: Result の開始から `RESULT_INPUT_GUARD_MS` 未満はボタン・キーを無視し、ちょうど経過した時点から受け付ける
- ボタン: 押した位置のボタンの上で離したときだけ働く（押して外へ出して離す・押さずにホバーだけ・ガード中に押してガード明けに離す・押している間に案内が出た・`pointercancel` では働かない）。状態の決まり（押している > ホバー > 通常。ガード中・案内中は通常）
- 自己ベスト: 保存した値が Title・Game の BEST・Result から同じ値で読める。保存の例外・壊れた値の扱いは `best-store` のテストに任せ、このゲームでは保存キーが `match3.best` であることと `label` の形（`1230点`）、スコア 0 のときに記録しないこと（`BEST ---` のまま）、新記録の判定が保存前の値で行われることを確認する
- Game の状態（Scene のグルーは QA で確認）: `swapping` → 成立で `resolving`・不成立で `idle`、`resolving` の終わりで手数 0 なら `ending`、動かせる手が無ければ `shuffling`、`ending` から `RESULT_DELAY_MS` で Result

## 完了条件

- `npm run lint` / `npm run test` / `npm run test:coverage`（4 指標とも 90% 以上）/ `npm run build` が通る。共有ビルド（`SHARED_VENDOR=1`）でも起動する
- 375 × 550・390 × 844・1280 × 720 で、Title・Game（プレイ中・ポップアップが出ている間・通知が出ている間）・Result のすべての文字・ボタンが画面に収まり重ならず、主な情報は実寸 14 px 以上・補助は 11 px 以上。盤面の 1 マスの実寸が 44 px 以上（375 × 550 と 390 × 844 で。スクリーンショットで確認）
- 667 × 310 と 844 × 390 では「縦にしてください」の案内が全面に出て、Game の進行（アニメーション・ヒントの計時）が止まる。1024 × 768 では出ない
- 操作が仕様どおりに働く: タップ 2 回で隣と交換できる。不成立の交換は `SWAP_MS` × 2 で元に戻り、手数が減らない。入力を受け付けない間のタップは無視される。`CELL` × `SWIPE_RATIO`（17.6 px）以上のスワイプは、指を離す前に交換される（テストと、実ブラウザでの操作で確かめる）
- 4 個以上を同時に消すとポップアップに `BONUS` が出て、得点が仕様の式と一致する（手作業の盤面で 4 個・5 個を確かめる）。連鎖のポップアップに `CHAIN xn` が出る
- 盤面の板が、375 × 550 と 390 × 844 で盤面を囲んで見え、石がその外へはみ出さない（補充の石が板より上に見えない）。手数が 5 になった交換で MOVES の数字が赤になり、6 以上では白。得点が入るたびに SCORE の数字が弾み、連鎖 3 段以上のポップアップは 2 段までより大きく、375 × 550 でも盤面の中（HUD に重ならない範囲）に収まる（スクリーンショットで確認。最悪の場合の確認として、連鎖 6 段以上〈倍率 1.5〉を、盤面の左右・上下の端に近いマスの消去で作る手作業の盤面で 1 回見る。切り詰めの値は純関数のテストで確かめる）
- 5 秒操作しないとヒントの 2 つの石が脈動し、操作を始めると止まる。脈動する石は、ルール「ヒントの手」で決まる手の 2 つ（動かせる手のうち、下の段・消える数が多いほうを指す。手作業の盤面で、上の段の手と下の段の手がある盤面を作り、下の段の手が光ることをスクリーンショットで確かめる）。ヒントの出る時間・脈動の大きさ・動きは変わらない。常設の得点の説明テキストは画面に無い
- 変えないもの（ヒントの拡張）: 操作の感触（タップ・スワイプ・キー）、8 × 8・6 色・手数 30、交換の成立条件、得点の式と連鎖の倍率、補充の乱数の順、動かせる手があるかの判定（盤面の生成・手詰まりのシャッフル・手数 0 のあと）、ヒントの出る時間・止まる条件・見た目、画面の大きさ・配置・文字の大きさ、保存キー `match3.best`、Title の文言。変わるのはヒントが指す手だけ
- 動かせる手が無い盤面を作って、`NO MOVES` / `SHUFFLE` の通知のあとに動かせる盤面になる。最後の手のあとは、動かせる手が無くてもシャッフルせず Result に進む
- 手数が 0 になり、最後の連鎖の得点が入ったあと、`FINISH` を `RESULT_DELAY_MS` 出して Result に移り、新記録のとき `NEW BEST!` が点滅する。もう一度遊ぶと盤面が新しくなり、手数 `MOVES`・スコア 0 から始まる
- キーボードだけで、Title（Space）→ Game（矢印・Space で選択・矢印で交換）→ Result（Space で「もう一度」）まで遊べる
