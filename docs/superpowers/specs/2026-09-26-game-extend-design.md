# game-extend スキル設計（公開後の要素追加・拡張フロー）

- 日付: 2026-09-26
- ブランチ: `docs/skill-game-extend`
- 状態: 承認済み・実装済み

## 1. 背景と目的

現状の `game-*` スキル群は「アイデア → MVP 実装 → 公開」までを一直線に扱う。
公開後に要素を追加・拡張する専用フローは無く、`game-spec` の
「Post-publish revision」節で直接 spec を改訂するしかない。その結果:

- 「何を足すか・どこまで足すか・何を変えないか」を詰める段階が無く、曖昧な
  要望のまま spec 改訂に入る
- `game-next` は全段階 `done` のとき `complete` を返し、再バランス以外の
  入口を示さない
- 下流スキル（test / qa / publish）の一部は初回実装・初回公開を前提に書かれて
  おり、拡張時に「既存挙動の回帰」や「既に公開済み」を扱えない
- 拡張を重ねると `docs/spec.md` が肥大化する（拡張前の時点で既に
  kogodrop 577 行、nonoedit 587 行）

本設計では、公開後の拡張の**入口となる対話段階 `game-extend`** を新設し、
既存の spec → impl → … → publish チェーンを拡張でも正しく回せるよう
関連スキルを修正する。あわせて spec の分割ルールを定める。

## 2. 決定事項（ユーザー合意済み）

| 論点 | 決定 |
|---|---|
| 最初に作る範囲 | 「何を足すかを決める」入口（A）。バックログ管理（B）・大規模拡張の安全な導入（C）は後続 |
| 対象 | 公開後（`status_publish: done`）のゲームのみ。公開前の追加は対象外 |
| 進捗記録 | frontmatter に記録しない（`game-idea` と同じ対話のみの段階）。記録は後続で検討 |
| 下流スキルの修正 | 今回の対象に含める |
| 1 サイクルの単位 | 拡張は 1 件だけ。複数あれば分割して次サイクルへ |
| 「変えないもの」の置き場 | 新節は作らず、完了条件とテスト観点に回帰条件として書く |
| 拡張履歴 | spec には残さない（spec は常に現在の仕様。理由は PR と git 履歴） |
| spec 肥大化対策 | 独立した要素ごとに `docs/spec/<slug>.md` へ分割（案 B） |

## 3. 全体フロー

```
game-next（complete のとき）
  └→ game-extend【新規・対話のみ】 何を 1 件足すか・何を変えないかを決める
       └→ game-spec  公開後の改訂：feat/<game>-<slug> ブランチ作成、spec 改訂、下流を pending に reset
            └→ impl → test → check → codereview → qa → polish → balance → publish
```

`game-status.sh` の `STAGES` は変更しない。`game-extend` の後は既存の
改訂フロー（`game-spec` が下流を `pending` に戻す）がそのまま進捗を追跡する。

## 4. spec の構成ルール（分割）

### 4.1 定義

ゲームの spec は **`docs/spec.md` と、そこからリンクされた
`docs/spec/*.md` すべて**で構成される。spec を読む・渡す・レビューする
すべての箇所はこの定義に従う。

### 4.2 `docs/spec.md`（本体・目次）

- frontmatter（`status_*`）は本体にのみ置く
- AGENTS.md 2.4 の必須項目はすべて本体に置く（基本ゲームの仕様）
- 分割ファイルが 1 つ以上あるとき、本体に `## 拡張` 節を置き、各ファイルへの
  相対リンクと 1 行説明を列挙する

### 4.3 分割基準

| 種類 | 置き場所 |
|---|---|
| その要素だけでルール・パラメータ・画面を持つもの（新モード、ステージ群、独立したシステム、新 Scene） | `docs/spec/<slug>.md` を新規作成 |
| 既存要素の変更・小さな追加（既存パラメータの変更、既存 Scene へのボタン追加など） | 本体の該当節を直接書き換え |
| 拡張が既存ルール（本体または他の分割ファイル）を変える場合 | 変えられる側のファイルを書き換える |

各ファイルは常に「現在の仕様」を表す。ルール変更を差分として積み重ねない。

### 4.4 分割ファイルの必須項目

`docs/spec/<slug>.md` には、その要素について以下を書く（該当しない項目は
「なし」と明記し、省略しない）:

- 概要（1-3 行。何を足し、コアループにどう効くか）
- 操作仕様（追加・変更分）
- 画面・Scene 構成（追加・変更分。レイアウト方針・状態遷移・演出・UI を含む）
- ルール
- パラメータ表
- テスト観点（この要素の単体テスト対象 + 回帰条件のテスト）
- 完了条件（この要素の受け入れ条件 + 回帰条件）
- 実装裁量

frontmatter は持たない。

### 4.5 肥大化時の分割サイクル

本体が 600 行を超えたら、`game-extend` が既存部分の分割を提案する。
これは挙動を変えない docs のみの変更なので、拡張とは別サイクル
（別ブランチ・別 PR）で行う。本文の移動のみとし、内容は書き換えない。
既存の大きい spec（kogodrop / nonoedit）の分割作業自体は本設計の対象外。

## 5. `game-extend`（新規）

`.claude/skills/game-extend/SKILL.md`

### 5.1 入力・前提

- `PACKAGE=<game-dir>`。無ければ `task game:detect` で推定しユーザーに確認
- `status_publish: done` が前提。未公開なら「MVP を先に出す」よう案内し
  `game-next` へ戻す
- ファイルは触らない。frontmatter も更新しない

### 5.2 手順

1. **現状把握**: `docs/spec.md` とリンク先（コンセプト・コアループ・
   非MVP範囲・パラメータ表）と README を読む。必要なら `game-qa` の
   Docker+Playwright 手順で 1 回遊び、スクリーンショットで現状を確認する
   （任意。ユーザーが最近遊んでいれば省略可）
2. **候補出し**: ユーザーのアイデアと非MVP範囲から候補を挙げ、**1 件だけ**
   選んでもらう。複数なら分割し、残りは次サイクルとして伝える
3. **1 問ずつ詰める**: 何を足すか／なぜ足すか（今のどこが不満・物足りないか）
   ／コアループへの効き方（深くする・横に広げる）／操作の追加・変更有無／
   見た目・数値の初期方針
4. **変えないものを決める**: 既存の操作感・ルール・スコア体系・難易度のうち
   今回変えないものを明示する。変わるものは「意図した変更」として合意する
5. **サイズ判定**: 1 PR を超えるなら最小の一歩に削る。既存コードの構造変更が
   必要ならその旨を伝えて合意する。本体が 600 行超なら分割サイクル（4.5）を
   先に行うか提案する
6. **spec の置き場所判定**: 4.3 の基準で分割ファイルか本体かを決める
7. **ブランチ slug 提案**: `feat/<game-dir>-<slug>` の slug を提案する
8. `game-review STAGE=extend` でセルフレビュー
9. 合意内容（追加内容・理由・変えないもの・置き場所・slug）を要約し、
   明示的な承認を得る

### 5.3 引き継ぎ

承認後、`game-spec` を呼ぶ。`game-spec` が公開後の改訂としてブランチを
作成し、spec を改訂し、下流を `pending` に戻す。

## 6. 既存スキル・文書の修正

| ファイル | 修正内容 |
|---|---|
| `game-next` | `complete` 時の案内を「`game-extend`（拡張）／`game-balance`（再調整）」の選択にする。description と段階一覧に extend を追記（`task game:next` からは返らない旨も明記） |
| `game-spec` | 4 章の spec 構成ルール（定義・分割基準・分割ファイル必須項目・`## 拡張` 節）を追加。`game-extend` から来た改訂では: 変えないものを完了条件／テスト観点に回帰条件として書く、拡張対象を非MVP範囲から外す、履歴は spec に残さない。公開後改訂の `<type>` 判定例に `game-extend` 由来 → `feat` を追加 |
| `game-review` | `STAGE=extend`（self）チェックリストを新設（5.2 の各項目が満たされているか）。description の STAGE 一覧に extend 追加。spec/impl/test サブエージェントの成果物を「spec.md とリンク先すべて」に変更。`STAGE=spec` に「回帰条件が完了条件・テスト観点にあるか」「`## 拡張` のリンク切れ・未リンクの `docs/spec/*.md` が無いか」「分割ファイルが 4.4 の必須項目を満たすか」を追加 |
| `game-impl` | spec の参照先を「spec.md とリンク先」に変更 |
| `game-test` | spec の参照先を同様に変更。改訂時は「既存テストを緩めて通すことを禁止」「回帰条件ごとにテストを書く」を追加 |
| `game-qa` | 改訂時は新要素に加え、既存の画面・状態（title / mid-play / clear / game-over 等）の回帰スクリーンショットも撮る。`game-review STAGE=qa` にも対応項目を追加 |
| `game-balance` | 拡張後は、新要素によって既存の難易度カーブ・テンポが崩れていないかを観点に加える |
| `game-publish` | 公開後の改訂では `GAMES` の uncomment を省略（既に有効）し、README のルール・操作説明が拡張を反映しているか確認する。PR 本文は「何を足したか・なぜ」 |
| `AGENTS.md` | 2.4 節に spec 分割ルールの要約（1 段落）を追加。10 節の段階表に `game-extend` 行を追加 |
