# Title とデモ

`docs/spec.md` の拡張。`Title` Scene を新設し、背景の中央で、ボットが演算を選んで目標値に合わせる様子（デモ）を流す。

## 概要

起動したら、すぐ 60 秒のラウンドが始まるのをやめ、`Title`（名前・一言・デモ・START・ヒント）を最初に出す。デモは、`Game` と同じ見た目の縮小版の盤面で、ボットが（順不同に）演算を選び、ときどき**間違えて、直しながら**、現在値が目標値に一致するまでを見せる。ルール・難易度・制限時間・レベルは変えない（`Game` は `Title` から START で始まり、これまでどおり Lv.1 から）。コアループ（全手を見渡す → 任意の手を選ぶ → 現在値を読む）を、開始前に見せるだけである。

## 操作仕様

- START（ボタンのタップ・クリック）、`Enter`、`Space`: `Game` を開始する。最初の 1 回だけ有効（同じフレームの 2 回目以降は無視する）。
- デモは操作を受け付けない（デモの領域のタップは何も起こさない）。START はデモの再生中・透明化中でも働く。
- `Space` を押してもページがスクロールしない（キーのキャプチャは `Title` を離れるときに解除する）。
- `Game` の操作は変わらない。

## 画面・Scene構成

### Scene と受け渡し

| Scene | キー | 役割 |
|---|---|---|
| Title | `Title` | 起動時の最初の Scene。名前・一言・デモ・START・ヒント。START で `Game` を始める |
| Game | `Game` | これまでどおり（`docs/spec.md`）。起動のとき Lv.1 から始める（`loadLevel` は常に 1） |

- 起動順: Title → Game。`Title` は `localStorage` を読み書きしない。`Game` に渡すデータは無い。
- `Game` から `Title` へ戻る導線は無い（リロードで戻る）。

### 状態

デモの進行は、共有パッケージ `title-demo` の `DemoDirector`（README が仕様）を、`TitleDemoRunner`（時計・開始の門・透明度）経由で使う。

| `DemoDirector` の要素 | このゲームでの内容 |
|---|---|
| 状態 `S` | 目標値・初期値・手ごとの候補と選択（`TurnSlot[]`）・`evaluateProgress` の結果・最短の解（`HistoryEntry[]`）・ラウンドの結果 |
| ラウンド | 1 つの問題を、目標値に合わせるまで（`rounds` = `demoRounds`） |
| `start()` | 新しい問題（下の「問題の作り方」）で始める。走りの作り直しにも使う |
| `plan(state)` | 最短の解の、スキップでない手の選択を、ランダムな順に並べ、そこに「誤った選択 → 待つ → 直す」を挟んだもの（1 要素 = 1 ステップ。「ボットの手」）。スキップでない手が無い問題は作らない（「問題の作り方」）ので、`null` や `[]` は返さない |
| `play(state, action)` | `action.kind` が `pick` / `mistake` / `fix` なら、その手の選択を設定して `evaluateProgress` で再計算する。`hold` は何も変えない（待ちの 1 ステップ）。`mistake` のあと `fix` までは「間違い中」（`wrong`）。目標値に一致したら（`won`）`roundDone: true`、勝利後の行は自動スキップ |
| `advance(state)` | ラウンドが終わったあと、新しい問題にする |
| `timing` | `stepMs` = `demoStepMs`、`waitMs` = `demoWaitMs`、`fadeMs` = `demoFadeMs` |

- `TitleDemoRunner` は `Title` の `create` のたびに新しく作る（時刻 0 から）。`update` の経過時間（delta）で時計を進め、1 回の `update` で進めるイベントは最大 1 つ。
- 開始の門: START が受け付けられたら（`runner.requestStart()` が `true`）、以後 `tick` を呼ばず、再生中の演出を捨てて `Game` を始める。
- 再生中の演出は、`advance`・`fade-out`・`fade-in` のイベントで捨て、盤面を状態から描き直す。
- 透明化（走りの作り直し）は `runner.opacity()` を、デモのブロック（ヘッダー・表・状態の文字）だけに掛ける。名前・一言・START・ヒントは透明にしない。
- 間違いの表示: 「間違い中」（`mistake` から `fix` まで）は、ヘッダーの 2 行目（現在値）の色を `#f87171` にする（勝利のときは `#4ade80`）。誤った選択のボタンは、ふつうの選択中と同じ青で、特別な印は付けない。
- 勝利の演出: ラウンドの結果が勝利のとき、状態の文字に「クリア!」を出し、ヘッダーの 2 行目（現在値）の色を `#4ade80` にする（上の「ヘッダー」）（どちらも `advance` で新しい問題になると消える）。カメラのフラッシュ・シェイクは使わない（`Title` の他の要素に及ぶため）。

### 問題の作り方とボット

乱数 `rng`（注入できる）を使う。

1. **問題**: 最大 `demoAttempts` 回、次をこの順に繰り返す（乱数もこの順に使う）。初期値を `demoInitialMin`〜`demoInitialMax` の一様な整数、目標値を `demoTargetMin`〜`demoTargetMax` の一様な整数、手ごとの候補を `createTurnSlots(demoTurns, OPERATION_POOL, rng)` で作り、`findShortestSolutionFromOptions` で最短の解（一致するのが最も早い手の番号で終わる解。スキップでない手の数が最小という意味ではない）を求める。解が存在し、スキップでない手が `demoMinOps` 個以上ならそれを採用する（初期値と目標値が同じなら解は空で、採用されない）。
2. **フォールバック**: `demoAttempts` 回で見つからなければ、`Game` と同じく、新しく初期値（`demoInitialMin`〜`demoInitialMax`）→ 手ごとの候補（`createTurnSlots`）の順に引き、目標値を「最初の手の最初の候補を初期値に適用した値」にする（スキップでない手は 1 個。最短の解もその 1 手）。目標値は `demoTargetMin`〜`demoTargetMax` の範囲の外になりうる（範囲の検査の対象外）。
3. **ボットの手**（`plan` の中で 1 回。乱数はこの順に使う）:
    1. 最短の解の、スキップでない手（手の番号と演算）を、1 つの配列にして、`i` を末尾から 1 まで下げながら `j = floor(rng() × (i + 1))` と入れ替える Fisher–Yates（`pickOperations` と同じ）でランダムな順にする（これを「正しい選択の列」とする）。スキップの手は何もしない（初期状態のスキップのまま）。
    2. 正しい選択の列の先頭から順に、各 1 つずつ `rng() < demoMistakeRate` なら「間違える候補」にする。ただし、候補は先頭から `demoMaxMistakes` 個まで。候補が 1 つも無ければ、正しい選択の列から `floor(rng() × 長さ)` 番目を 1 つだけ、強制的に候補にする（どのラウンドでも、間違いが少なくとも 1 回は見える）。
    3. 候補の選択（手 t、正しい演算 c）ごとに、その手の 4 つの候補のうち c でない 3 つの演算から、**この時点までの選択で、選ぶと目標値に一致してしまうもの（誤った選択で勝ってしまうもの）を除いた**ものを、`floor(rng() × 個数)` 番目で 1 つ選び、これを誤った演算 w とする。除いて 1 つも残らなければ、その候補は間違えない（ふつうの選択のまま）。「この時点までの選択」は、列の前の要素まで（誤った選択と直した選択を含めて）を順に適用したもの。
    4. 間違える候補の選択は、3 つの要素に置き換える: `mistake`（手 t に w を選ぶ）、`hold`（何も変えない）、`fix`（手 t に c を選び直す）。ほかの選択は `pick`（正しい演算を選ぶ）。
    5. 1 要素を 1 ステップ（`demoStepMs`）で進める。
4. 順不同で選ぶので、正しい選択の途中で値が目標値に一致して、全部を選ぶ前にラウンドが終わることがある（`Game` のルールどおり。残りの手は自動スキップ。以降の `hold` / `fix` も実行されない）。誤った選択で一致することは、3. で避けるので無い。

## ルール

デモは `Game` のルール・難易度・制限時間・レベル・`localStorage` に影響しない。`Title` は `localStorage` を読み書きしない（デモの状態も保存しない）。`Game` に渡すものは無い。

## パラメータ表

| 名前 | 初期値 | 意味 |
|---|---|---|
| `demoTurns` | 5 | デモの手（行）の数 |
| `demoRounds` | 2 | 1 走りのラウンド数 |
| `demoStepMs` | 700 ms | 1 ラウンドの中の、選択と選択の間隔 |
| `demoWaitMs` | 1500 ms | 走りの始まり・ラウンドの終わり（結果を見せる）・作り直しの後の待ち |
| `demoFadeMs` | 400 ms | 走りの終わりの透明化・出現の長さ（それぞれ） |
| `demoInitialMin` / `demoInitialMax` | 1 / 5 | 初期値の範囲（`docs/spec.md` の Lv.1 と同じ） |
| `demoTargetMin` / `demoTargetMax` | 20 / 50 | 目標値の範囲（Lv.1 と同じ） |
| `demoMinOps` | 2 | 問題として採用する、スキップでない手の最小の個数 |
| `demoMistakeRate` | 0.4 | 正しい選択 1 つごとに、間違える候補にする確率（1 つも無ければ 1 つを強制する） |
| `demoMaxMistakes` | 2 | 1 ラウンドで間違える最大の回数 |
| `demoAttempts` | 200 | 問題を作り直す最大の回数（`Game` と同じ） |
| 領域 / ブロック | 300〜780、`blockH` = 48 + 12 + `demoTurns` × 50 + 40（350）、`blockTop` = 300 + floor((480 − `blockH`) / 2)（365） | 「レイアウト」のとおり |
| 行 / ボタン | 行の高さ 50、ボタン 72 × 28、中心 x = 40・120・200・280・360 | `Game` の盤面と同じ |

## テスト観点

- 問題の作り方（乱数を注入）:
  - 多数のシードで、採用される問題は、解が存在し（`findShortestSolutionFromOptions` が `null` でない）、スキップでない手が `demoMinOps` 個以上で、初期値・目標値が範囲内（空振りの検査つき: フォールバックを使った回数と使わなかった回数の両方を数え、使わなかった回数が 0 でないこと）。
  - フォールバック（乱数を固定して、`demoAttempts` 回とも `demoMinOps` を満たさない問題にする）: 最初の手の最初の候補を 1 回使うだけで目標値になる。
- ボットの手（`plan`）:
  - 正しい選択（`pick` と `fix`）は、最短の解のスキップでない手の全部を、1 回ずつ（重複・欠けなし）含み、スキップの手を含まない。同じ種なら同じ列。
  - 各 `mistake` の直後は、同じ手の `hold`、その次が同じ手の `fix`（正しい演算）。`mistake` の演算は、その手の候補の 1 つで、正しい演算ではない。
  - `mistake` の数は 0 以上 `demoMaxMistakes` 以下。多数のシードで、ほぼ全ての計画（95% 以上）に `mistake` が 1 つ以上ある（強制の候補が選べない場合だけ 0）。空振りの検査: `mistake` のある計画の数が 0 でないこと。
  - どの `mistake` も、それまでの選択を順に適用したとき、目標値に一致しない（誤った選択では勝たない）。

- `play`: `pick` / `mistake` / `fix` は選択を設定して `evaluateProgress` と一致する値になる。`mistake` で「間違い中」になり、`fix` で戻る。`hold` は何も変えない（`moved: true`、`roundDone: false`）。目標値に一致したら `roundDone: true`、一致するまでは `false`。勝利後の行は自動スキップ。順不同で選んで途中で勝利する場合（手 3 → 手 1 の順で、手 1 の選択で一致するなど、手計算の例）を含む。
- 進行（手計算。各ラウンドがスキップでない手 3 個で、最後で一致する場合、`demoStepMs` 700・`demoWaitMs` 1500・`demoFadeMs` 400・`demoRounds` 2、時刻は構築時を 0 とする）:

  | t (ms) | 起きること |
  |---|---|
  | 1500 | 1 回目の選択（ラウンド 1） |
  | 2200 | 2 回目の選択 |
  | 2900 | 3 回目の選択（一致、`roundDone`） |
  | 4400 | `advance`（新しい問題） |
  | 5900 | ラウンド 2 の 1 回目の選択 |
  | 6600 | 2 回目の選択 |
  | 7300 | 3 回目の選択（一致、`roundDone`） |
  | 8800 | `fade-out`（透明度 1 → 0 が始まる。9000 で 0.5） |
  | 9200 | `fade-in`（新しい問題、透明度 0） |
  | 9600 | `fade-in` の透明化が終わり、`waiting` に入る（待ちは 11100 に終わる。イベントは無い） |
  | 11100 | 新しい走りの 1 回目の選択 |
- 配置（純関数。手計算の値）: `blockTop` = 365、`tableTop` = 425、行 i の中心 y = 450 + 50 i、状態の文字の中心 y = 701。
- 入力（Scene の動作。QA で確認する）: START のタップ、`Enter`、`Space` で `Game` が始まる（1 回だけ）。デモの再生中・透明化中でも働く。`Title` は `localStorage` に触れない。`Space` でページがスクロールしない。
- 回帰: `Game` のルール・難易度表・60 秒・レベルの扱い（Lv.1 で開始、「最初から / 続きから」）・演算プール・解の生成の保証・結果の流れ・`calcRushLevel` のキー、既存のロジックのテスト（`logic.test.ts` / `logic.oracle.test.ts`）は変更しない。

## 完了条件

- 起動すると `Title` が出て、デモが流れる。START（ボタン・`Enter`・`Space`）で `Game` が始まり、Lv.1 から遊べる。
- デモは、ボットが演算を順不同に選び、現在値が変わる。**どのラウンドでも、たいてい 1 回は誤った選択をして（現在値が赤くなる）、少し待ってから直す**。目標値に一致すると「クリア!」が出る。次のラウンドで新しい問題になり、2 ラウンドのあと透明になって最初から繰り返す（スクリーンショットの連続で確認する）。
- 画面サイズ（390 × 844・375 × 550・667 × 310・1280 × 720）で、`Title` の全ての要素がキャンバスの中に収まる（`scripts/qa/title-viewports.mjs`）。
- デモの再生中・透明化中でも START が働く。デモの領域のタップは何も起こさない。
- `Game` のルール・難易度・制限時間・レベル・見た目・操作は変わらない。`Title` 経由で始めても、`Game` の結果の流れ（クリアで次のレベル、模範解答の表示、敗北後の「最初から」と「続きから」）が変わらない（QA で、`Title` から始めて、クリアと敗北の両方を確認する）。
- `Title` に何秒いても、START のあとの最初のラウンドの残り時間は 60 秒から始まる（`Title` の滞在時間は持ち時間に数えない。QA で、`Title` に 12 秒いてから START し、残り時間が 58 秒を超えることを確かめる）。`Game` の時刻の基準はゲームループの時刻（`game.loop.time`）で、`Scene` の更新が止まっていた間の古い `time.now` を使わない。
- `Title` は `localStorage` を読み書きしない（QA で、起動から START までの `getItem` / `setItem` の呼び出しが 0 回であることを、ページの初期化スクリプトで数えて確かめる）。
- `Title` を離れたあと、`Title` のキーのリスナと `Space` のキャプチャが残らない（`shutdown` で解除する。コードレビューで確認する）。
- `npm run lint` / `npm run test` / `npm run test:coverage` / `npm run build` が成功し、既存のロジックのテストは変更されない。

## 実装裁量

- デモの純粋なロジック（問題の作り方・ボットの手・状態）をどのファイルに置くか、関数の名前と分け方
- 誤った選択を直す前の待ち（`hold` の 1 ステップ）のあいだの細かい動き（現在値の点滅など。0.2 秒以内）
- 選択の瞬間・「クリア!」が出るときの短い動き（0.2 秒以内。入力を妨げない）
- START の押している間・ホバーの見た目（色の変化など）。押したら、演出なしですぐ `Game` を始める
- `Title` の文字・ボタンの描画方法（Arial 指定以外の細かい設定）
- `Game` と共有する色・盤面の幾何の定数の置き場所（`Game` の見た目は変えない）
- 注入する乱数の種（走りごとに変える）
