# TYPE RAIN（`typerain`）の拡張候補（backlog）

公開済みの `typerain` に足せる候補を、上から順に並べたものです。上のカードが「次の候補」です。仕様（`spec.md`）ではありません。新しいゲームのアイデアは `docs/ideas.md` に書きます。

- 規模: S = 1 つのファイルや画面の追加程度、M = 複数のファイル・仕組みにまたがる追加、L = 大きいので、game-extend で 1 PR 分に切り出してから採用する。
- 1 つのカードは 1 つの目的にする（1 変更 1 目的）。
- 自動プレイの数字は、`Round` を固定 dt・seed 付き乱数で動かした単純な bot（一番下の単語から打つ。50 seed、上限 600 秒）の結果。人の感じ方（体感、人が取る賭け）は分からない。
- 画面の高さ（321・528・779）で結果は変わらない（落ちきるまでの時間が高さによらない仕様どおり）。

### 後半の新しい圧力（`late-pressure`）

- 狙い: t = 140 秒で難易度がすべて頭打ちになり、速い人は終わらない。根拠: 自動プレイ（ミス率 2%）で、7 打鍵/秒の中央値が 176 秒、7.5 打鍵/秒では 50 回中 47 回が 600 秒を生き残り、8 打鍵/秒以上でほぼ死なない（ミス率 8% では 8.5 打鍵/秒以上）。8 打鍵/秒は約 100 WPM で、スマホではまれ。PC の速打ちの人にだけ効く
- 何を足すか: 難易度の頭打ち（t = 140 秒）のあとに、まだ増える要素を 1 つ足す（例: 出現の間隔の下限をさらに下げる、同時に降る束〔2〜3 語〕が時々来る）。具体的な要素は game-extend で決める。
- コアループへの効き方: 深める — 速い人にも、終わりを作る。
- 種別: gameplay
- 規模: M
- 出どころ: 自動プレイ
- メモ: 主な対象が PC の速打ちの人で、スマホ（主なターゲット）では効かない。盤面の一掃（`board-wipe`）が入ったので、速い人はさらに死ににくくなった（自動プレイ、ミス率 8%・7.5 打鍵/秒の生存時間の中央値が 216 秒 → 395 秒）。優先度を上げて検討する。具体的な要素は 2026-11-15 の対話で決めた（下の合意）。
- 状態: 着手可（2026-11-15、基準 `0a87e89`）
- 合意:
  - 足すもの: t = 140 秒を過ぎても、落下の速さの上限と出す間隔の下限を、t = 300 秒まで線形に変える。新しい規則・新しい要素は足さず、パラメータを 4 つ足すだけ
    - 進み具合: `u` = `clamp((t − LATE_RAMP_START) ÷ (LATE_RAMP_END − LATE_RAMP_START), 0, 1)`（`LATE_RAMP_START` = 140・`LATE_RAMP_END` = 300）
    - 落下の速さ: `min(速さの上限(t), FALL_SPEED_START + FALL_SPEED_RAMP × t)`。速さの上限(t) = `FALL_SPEED_MAX` + (`FALL_SPEED_MAX_LATE` − `FALL_SPEED_MAX`) × `u`。`FALL_SPEED_MAX_LATE` = 0.40（落ちきるまで約 2.5 秒。いまの上限 0.28 は約 3.6 秒）
    - 出す間隔: `max(下限(t), SPAWN_START_SEC − SPAWN_DECAY_PER_SEC × t)`。下限(t) = `SPAWN_MIN_SEC` − (`SPAWN_MIN_SEC` − `SPAWN_MIN_SEC_LATE`) × `u`。`SPAWN_MIN_SEC_LATE` = 0.6 秒
    - t = 300 秒以降: そのまま（それ以上は増えない）。t < 140 秒: 変えない（速さ・間隔・最大文字数は今のまま）
    - 注意: 単語どうしの縦のすき間（78 px）が先に効く画面（小さい H）では、間隔の下限の変更は効かず、落下の速さの変更だけが効く。画面の高さ（321・528・779）で結果が大きく違わないかは、実装後の測定で確かめる
  - 対象: PC の速打ちの人。スマホ（主なターゲット）では、140 秒より前に終わるので、変わらない見込み
  - 操作: なし
  - 見た目と初期値の方向: 見た目は変えない。初期値は `LATE_RAMP_START` 140・`LATE_RAMP_END` 300・`FALL_SPEED_MAX_LATE` 0.40・`SPAWN_MIN_SEC_LATE` 0.6。数値は `game-balance` で調整してよい
  - 変えないもの: t < 140 秒の挙動、盤面の一掃、スコア・コンボ、ライフ、単語リスト、最大文字数、ロックオン、Title・Result、操作
  - 意図して変えるもの: t > 140 秒の落下の速さと出現が上がり、速い人が終わるようになる
  - 測ったこと: 未測定（実装してからでないと測れない）。実装後に、`Round` を固定 dt・seed 付き乱数で動かす単純なボット（一番下の単語から打つ。50 seed、上限 600 秒）で、打鍵速度 5・7・7.5・8 打鍵/秒、ミス率 2%・8%、画面の高さ 321・528・779 の生存時間の中央値を新旧で比べ、PR 本文に載せる。目標は、7.5 打鍵/秒・ミス率 8% の中央値が、395 秒から 300 秒前後に下がること。5 打鍵/秒以下の結果が変わる（t < 140 秒の変更が漏れた）ときは、`game-autopilot` は止めてユーザーに聞く
  - spec の置き場所: `docs/spec.md`（361 行）を直接書き換える（落下の速さ・出す間隔の節、パラメータ表、テスト観点）
  - ブランチ: `feat/typerain-late-pressure`

### 金の単語（打ち切るとライフ +1）（`heart-word`）

- 狙い: ライフが減るだけで増えない。根拠: 自動プレイ（2.5〜6 打鍵/秒、ミス率 2%・8%）で、最初のライフを失ってから 3 つ目を失うまでが中央値で 2〜10 秒。立て直す手段が無い
- 何を足すか: 一定の間隔（例: コンボが 10 の倍数になったあと最初の出現）で、金色の単語を 1 つ出す。打ち切るとライフが 1 増える（上限 `LIVES`）。床に着いても追加のペナルティは無く、通常の単語と同じくライフが 1 減る。
- コアループへの効き方: 深める — 「どの単語から打つか」に、近い単語を先に消すか、金の単語を取りに行くかの判断が生まれる。
- 種別: gameplay
- 規模: M
- 出どころ: 自動プレイ
- メモ: 盤面の一掃（`board-wipe`）が入って連鎖が断たれるようになり、必要性が薄れた（優先度を下げる）。連鎖の最中に金の単語が降ってくる保証が無く、遅れているときは取りに行く余裕も無いので、単独では連鎖の解消に弱い。出す間隔・回復の量・上限は game-balance と同じ手順で決める。bot は最短の単語から打つ単純な規則なので、金の単語を取りに行く判断の効果は未測定。

### Result に正確さと最高コンボ（`result-stats`）

- 狙い: タイピングの練習をしたい人に、結果の画面で速さ・正確さの手がかりが無い。根拠: spec「ターゲットプレイヤー」（英単語のタイピングを軽く練習したい人）と「Result」（SCORE・WORDS・BEST のみ）。自動プレイでは、ミス率 2% と 8% で最高コンボの中央値が 19〜24 と 9〜10 になり、差が結果に出るが、プレイヤーには見えない
- 何を足すか: Result に「最高コンボ」と「正確さ（打った文字のうち、合っていた割合 %）」を足す。ルール・得点は変えない。
- コアループへの効き方: 広げる — 遊んだあとに、自分のミスの傾向が分かり、次の遊びの目標（ミスを減らす）が生まれる。
- 種別: presentation-only
- 規模: S
- 出どころ: spec 分析
- メモ: Result の配置（H = 240 の最小画面で、行が重ならない・ボタンが下 1/3 に収まる）を spec の手計算で確かめ直す。打った文字数・ミス数を数えるだけで、判定の結果は変えない。

### 難易度の段階表示（`stage-banner`）

- 狙い: 時間とともに最大の文字数・速さ・出現の間隔が上がるが、プレイヤーには進み具合が見えない。根拠: spec「パラメータ表」（文字数は 20 秒ごと、出現と速さは t = 80〜140 秒まで連続で変わる）と、Game の HUD（SCORE・ライフ・コンボのみ）
- 何を足すか: 最大の文字数が上がるとき（20 秒ごと）に、画面の上にひと言（例: `LEVEL 3`）を短く出す。ルール・数値は変えない。
- コアループへの効き方: 広げる — 「いま何秒、どこまで来たか」の手応えが生まれる。
- 種別: presentation-only
- 規模: S
- 出どころ: spec 分析
- メモ: 「後半の新しい圧力」を採用するなら、その新しい段階の表示も一緒に決めると効果が高い。HUD の文字の大きさ（主な情報は実寸 14 px 以上）を守る。

### 戻ったときに操作してから再開する（`pause-resume`）

- 狙い: 単語が落ち続けるのに、タブを離れても止まらない（spec の非範囲に「一時停止」）。根拠: ユーザーの声（復帰時に突然再開されるゲームがある。フォーカス外れとスマホで動作を揃えたい）、`typerain/docs/spec.md`（一時停止は非範囲）
- 何を足すか: ページが見えなくなった（`HIDDEN`）かウィンドウがフォーカスを失った（`BLUR`）とき、ゲームの時間を止めて幕を出す。戻っても勝手には再開せず、タップかキーを押したときに、止まった続きから再開する。再開に使った操作は、それだけで終わる（打つ・動くなどのゲームの操作にはならない）。入力用の隠し `<input>` のフォーカスは、再開の操作でつけ直す（スマホのキーボードが閉じたままにならないようにする）。
- コアループへの効き方: 広げない — 復帰時の不意の失点・失敗を防ぐ。コアループそのものは変えない。
- 種別: gameplay
- 規模: S
- 出どころ: ユーザー
- メモ: `shared/pause` の `PauseState` を使う（absorb が先例。入れる順はルート `docs/backlog.md` の `pause-rollout`）。再開の操作は、タイピングのキーと混ざらない形にする（タップか、文字以外のキー）。spec は `absorb/docs/spec/pause.md` と同じ形（`docs/spec/pause.md`）に分ける。
