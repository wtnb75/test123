# TYPE RAIN（`typerain`・仮称）

## ゲーム名

TYPE RAIN（`typerain`）。Title には `TYPE RAIN` と出す。

## コンセプト

上から英単語が降ってくる。OS のキーボードで打ち切ると単語が消え、床に着くとライフが減る。ライフ 3 つが尽きるまでのスコアを競う、スマホで遊べるオーソドックスなタイピングゲーム。キーボードが出て画面が狭くなっても、盤面が隠れず読める大きさのまま遊べる。

## ターゲットプレイヤー

スマホで 1 回 1〜2 分、すき間時間に遊ぶ人。英単語のタイピングを軽く練習したい人。主な入力はスマホの OS キーボード（縦持ち）。PC の物理キーボードでも遊べる。

## コアループ

1. 降りてくる英単語を見る
2. 先頭の文字から打つ（その文字で始まる、一番下の単語にロックオンする）
3. 打ち切ると単語が消えて得点が入る（ミスをするとコンボが切れる）
4. 次の単語を選ぶ。床に着いた単語はライフを減らし、ライフが尽きたら結果画面

## 操作仕様

| 場面 | タッチ（スマホ） | キーボード（PC） |
|---|---|---|
| Title | START ボタンをタップ。押した位置のボタン上で離したときに働き、同じ処理の中で OS キーボードを出す | Enter で START |
| Game | OS キーボードで英字を打つ。キーボードが閉じているときは、画面のどこかをタップするとキーボードが出る | 物理キーで英字を打つ（A〜Z。大文字・小文字とも同じ） |
| Result | 「もう一度」「タイトルへ」をタップ（押した位置のボタン上で離したときに働く）。「もう一度」は同じ処理の中で OS キーボードを出す | Enter で「もう一度」 |

- 文字の入力は、画面外の隠し入力欄（`<input>`、見えない）で受ける。Game の間、この入力欄にフォーカスがあるあいだ、打った文字（a〜z。大文字は小文字として扱う）を 1 文字ずつ、打った順に処理する。a〜z 以外の文字と Backspace による削除は無視する（変換中かどうか〔composition〕は見ない。Android のキーボードが英字を変換中の入力として届けても、増えた文字を打った文字として扱う）。iOS Safari はユーザーの操作の中でしかフォーカスできないため、START と「もう一度」は、ボタンを離した処理の中でフォーカスする
- 入力欄の見えない設定: 自動大文字・自動修正・予測変換・スペルチェックを切る。文字の大きさは 16 px 以上にする（iOS の自動ズームを避ける）
- 入力の読み方（実装裁量の範囲で変えてよいが、結果は同じにする）: 入力欄の値が増えた分だけを新しく打たれた文字として処理し、値が減ったら（Backspace）処理せず、値の長さだけを合わせる。値が長くなりすぎたら（24 文字を超えたら）、その増分を先に処理してから、値を空にして長さを 0 に合わせる（25 文字目も打った文字として反映される）
- Game の最中にフォーカスが外れた（キーボードを閉じた）ときも、ゲームは止まらない。画面のどこかをタップするとフォーカスし直す（その間に落ちた単語は戻らない）。フォーカスが外れている間、床の下の帯に「タップでキーボードを出す」を出す（フォーカスが戻ったら消す）
- Title・Result の Enter は押した瞬間に 1 回だけ働く（押しっぱなしのリピートは無視）。Game 中の Enter は何もしない
- 「縦にしてください」の案内が出ている間は、すべての入力（タップ・キー・文字）を受け付けない（下の「画面の大きさ」）
- Result を始めてから `RESULT_INPUT_GUARD_MS` の間は、ボタンと Enter を受け付けない（最後まで打っていたタップや文字が、そのまま「もう一度」を押さないため）
- ボタンの押し方: ボタンの上でポインタを押し、同じボタンの上で離したときだけ働く（押したまま外に出して離す・別のボタンで離す・押していないポインタの離しは何も起きない）。押している間（押した位置のボタンの上にある間）は色を `COLOR.buttonPressed` にする。ポインタがボタンの上にあるだけ（マウスのホバー）のときは `COLOR.buttonHover`。ガードの間・案内の間は通常の色のまま

## 画面・Scene構成

| Scene | 役割 |
|---|---|
| Title | ゲーム名・遊び方・自己ベスト・START ボタン |
| Game | プレイ。降ってくる単語・HUD・床・入力の受け付け |
| Result | ゲームオーバー。スコア・打った単語数・自己ベスト・2 つのボタン |

### 画面の大きさ（論理サイズ）

- 幅は `SCREEN_WIDTH` で固定。高さは `round(SCREEN_WIDTH × 表示の高さ / 表示の幅)` を `[SCREEN_HEIGHT_MIN, SCREEN_HEIGHT_MAX]` に収めた値 H にする。「表示」は、ブラウザが見せている領域（スマホでは OS キーボードが出ると高さが縮む `visualViewport`。未対応のブラウザでは `window.innerWidth / innerHeight`）。縮小率 = `min(表示の幅 / SCREEN_WIDTH, 表示の高さ / H)`。Phaser の `Scale.FIT` で中央に置く。文字は縮めず、キーボードが出ると高さ H だけが縮む
- H は、どの Scene でも、表示の大きさが変わるたびに決め直す（キーボードの出入り・画面を回したとき）。Title・Result は決め直した H で配置し直す。Game は、床の位置と HUD を配置し直し、落ちている単語の高さ方向の位置を「場の中での割合」で保つ（下の「場」）
- 手計算の例:

| 表示の大きさ | H | 縮小率 | 余白（黒帯） | 案内 |
|---|---|---|---|---|
| 390 × 844（スマホ縦） | 779 | 1.083 | なし | なし |
| 375 × 550（iPhone SE 縦。キーボードなし） | 528 | 1.042 | なし | なし |
| 375 × 334（iPhone SE 縦。キーボードが出ている目安） | 321 | 1.040（= min(1.0417, 334 ÷ 321)） | なし | なし |
| 1280 × 720（PC） | 240（下限） | 3.0 | 左右に計 16%。縦持ちを前提にしたゲームなので許容する（文字は大きく見える） | なし |
| 667 × 310（スマホ横。キーボードなし） | 240（下限） | 1.29 | 左右に計 30%。同上 | なし（START でキーボードが出ると、下の行になる） |
| 667 × 150（スマホ横。キーボードが出ている目安） | 240（下限） | 0.625 | — | あり |
| 315 × 210（境界） | 240 | 0.875 | — | なし（ちょうど `ROTATE_PROMPT_SCALE`） |

- 案内: 表示が横長（幅 > 高さ）で、縮小率が `ROTATE_PROMPT_SCALE` 未満のときは、どの Scene でも、その上に「ROTATE」「画面を縦にしてください」の案内を全面に出す。この間、Game は進行を止め（時間・落下・出現・`RESULT_DELAY`・`ending` の待ちが進まない）、入力を受け付けない。表示が変わって条件を外れたら案内を消して続きから再開する。案内の文字の大きさは、論理で `min(ceil(PROMPT_REAL_FONT_SIZE ÷ 縮小率), PROMPT_MAX_FONT_SIZE)`（縮小率が 0 以下なら `PROMPT_MAX_FONT_SIZE`）にして、縮んだ画面でも実寸を保つ（2 行とも画面の幅に収まる: 「画面を縦にしてください」は 11 文字 × 30 = 330 ≤ 360）。PC（1280 × 720、縮小率 3.0）には出ない。縦長の表示（幅 ≤ 高さ）には出ない
- 文字の大きさ（論理 px。実寸 = 論理 × 縮小率）。主な情報は実寸 14 px 以上、補助は 11 px 以上（AGENTS.md 4.6）。縦持ちの縮小率は、幅 320 px の端末でも約 0.89 以上。案内が出ない最小の縮小率 0.875 でも、主な情報の最小（論理 16）が実寸 14 を保つ（14 ÷ 16 = 0.875。`ROTATE_PROMPT_SCALE` の根拠）

| 要素 | 論理 | 実寸（縮小率 0.89 / 1.04） | 区分 |
|---|---|---|---|
| 降ってくる単語 | `FONT_WORD` 22 | 19.6 / 22.9 | 主 |
| HUD（SCORE・ライフ） | `FONT_HUD` 18 | 16 / 18.7 | 主 |
| コンボ（`COMBO x5`。現在値なので主） | `FONT_COMBO` 16 | 14.2 / 16.6 | 主 |
| 床の下の帯の案内 | `FONT_HINT` 13 | 11.6 / 13.5 | 補助 |
| Title の遊び方 | `FONT_HELP` 14 | 12.5 / 14.6 | 補助 |
| Title の名前 | `FONT_TITLE` 36 | 32 / 37 | 主 |
| Title・Result の BEST・WORDS・NEW BEST | `FONT_RESULT` 16 | 14.2 / 16.6 | 主 |
| Result の SCORE | `FONT_RESULT_SCORE` 24 | 21 / 25 | 主 |
| Result の GAME OVER | `FONT_RESULT_TITLE` 28 | 25 / 29 | 主 |
| ボタンの文字 | `FONT_BUTTON` 18 | 16 / 19 | 主 |
| 得点のポップアップ（`+30`） | `FONT_POP` 18 | 16 / 19 | 主 |
| 「縦にしてください」の案内 | 上の式（`PROMPT_REAL_FONT_SIZE` 18 を保つ） | 18 | 主 |

主な情報（論理 16 以上）は、補助の文字（論理 14 以下）より小さくならない。

### Title

- 上から順に: ゲーム名 `TYPE RAIN`（中心 y = `max(TITLE_NAME_MIN_Y, round((H − 70 − 114) / 2))`。70 は画面の下端から START の上端までの距離〔`BUTTON_FROM_BOTTOM` + `BUTTON_H` / 2 = 44 + 26〕、114 はゲーム名の中心から BEST の中心までの距離〔44 + 22 × 2 + 26〕で、名前〜BEST の中心の並びを、画面の上端から START の上端までの中央に置く。`FONT_TITLE`）、遊び方の 3 行（最初の行の中心 y = ゲーム名の中心 + 44、行の間隔 22、`FONT_HELP`）、自己ベスト（最後の行の中心 + 26。`BEST 1230`。記録が無ければ `BEST ---`。`FONT_RESULT`）、START ボタン（`BUTTON_W` × `BUTTON_H`、中心 y = H − `BUTTON_FROM_BOTTOM`。画面の下 1/3 に入る）
- 遊び方の 3 行: 「降ってくる英単語を打って消す」「床に着くとライフが 1 減る（3 つで終了）」「打ち間違えるとコンボが切れる」。どの行も画面の幅 − 32 に収まる
- 手計算（H = 240 の最小の例）: ゲーム名 y = 43、遊び方 y = 87 / 109 / 131（最後の行の下端は 142）、自己ベスト y = 157（上端 149、下端 165）、START の中心 y = 196（上端 170）。START の上端 170 は自己ベストの下端 165 より下で、重ならない。H = 321 ではゲーム名 y = 69（`round(68.5)`）、BEST y = 183（START の上端 251）。H = 528 では 172 / BEST 286（上端 458）。H = 779 では 298 / BEST 412（上端 709）
- 状態は 1 つ（START を押すか Enter で Game へ）

### Game

- レイアウト（上から。H は論理の高さ）:
  - HUD の 1 行目（上端 y = `HUD_Y`）: 左に `SCORE 120`、右に残りのライフ（`♥` を残りの数だけ並べる。0 なら空）。どちらも `FONT_HUD`
  - HUD の 2 行目（中心 y = `COMBO_Y`）: 左に `COMBO x5`（`FONT_COMBO`）。コンボが 2 以上のときだけ出す
  - 場: y = `FIELD_TOP` から `FLOOR_Y`（= H − `FLOOR_FROM_BOTTOM`）まで。`FLOOR_Y` に細い赤い線を引く。単語は上端が `FIELD_TOP` の位置から出て下へ落ちる
  - 床の下の帯（`FLOOR_Y` から H まで）: フォーカスが外れているときだけ「タップでキーボードを出す」（`FONT_HINT`）を、帯の中央に出す
- 場: 単語の高さを `WORD_H`（= `FONT_WORD` の行の高さ。26）、「落ちる距離」`FALL_DISTANCE` = `FLOOR_Y` − `FIELD_TOP` − `WORD_H` とする。単語の位置 y は単語の上端。`y = FIELD_TOP` で出て、下端（y + `WORD_H`）が `FLOOR_Y` に届いたフレームで「床に着いた」となる。単語の「進み」p = (y − `FIELD_TOP`) / `FALL_DISTANCE`（出た時 0、床に着く時 1）。H が変わったときは、新しい `FALL_DISTANCE` で各単語の y を p を保つように置き直す（落ちきるまでの残り時間は変わらない）。このとき単語どうしの縦の間隔も `FALL_DISTANCE` の比で伸び縮みするので、H が小さくなった直後は、単語どうしが縦に重なってもよい（その単語が消えるか床に着くまで。置き直しのとき間隔は補正しない）。重ならないことが保たれるのは、H が一定のあいだに出した単語どうしだけ
- 単語の見た目: 通常は `COLOR.word`、ロックオンした単語は `COLOR.locked`、そのうち打ち終えた先頭の部分は `COLOR.typed`（黄）。等幅フォント。単語は画面の左右にはみ出さない
- 状態と遷移:

| 状態 | 内容 | 次へ進む条件 |
|---|---|---|
| `playing` | 単語が出て落ち、入力を処理する。始まった時点の経過時間 t = 0 | ライフが 0 になった（その瞬間に `ending` へ） |
| `ending` | 落下・出現・入力（文字・タップ）をすべて止め、入力欄のフォーカスを外す。単語・HUD はそのまま残す | `RESULT_DELAY` 秒たったら Result へ（スコア・打った単語数を渡す） |

- 同じフレームの順序: 入力（打った文字の処理）→ 時間の更新（`dt` を `DT_MAX_SEC` を上限に丸めて進める。タブが隠れたあとなどに 1 フレームで大きく進まないため）→ 単語の出現 → 落下 → 床に着いた単語の処理（y が大きい順）。ライフは 0 未満にならない。同じフレームに複数の単語が床に着いてライフが尽きたら、尽きた時点で `ending` へ移り、残りの単語のライフ減は無視する（`ending` のあとに床に着いた単語は何も起こさない）
- キーボードが閉じて（フォーカスが外れて）も、遊びは続く。`ending` に入ったときのフォーカス解除で表示の高さが変わっても、Game は H の変化に追従するだけで、進行に影響しない

#### 演出・UI（Game）

時間の決まり（すべての演出に共通）: きっかけのフレームを t = 0 とし、決めた長さ D のちょうどで消える（または元に戻る）。揺れは Phaser のカメラの揺れ（`camera.shake`）、それ以外は Phaser の tween で動かし、どれも入力を止めない（拾う・打つ処理は演出の完了を待たない）。`ending` の扱い: 再生中のものは `ending` の間は続け、Result への切り替えで切る（切り替えを遅らせない）。`ending` に入るフレームの入力・床に着く処理で起きる演出は、そのフレームでも出す。Scene が終わるときに残っているものは破棄する（「もう一度」で始まる Game に何も残らない）。「縦にしてください」の案内の間も、演出は案内の下で再生し続けてよい。

| 演出 | きっかけ | 見た目 | 重なったとき・境界 |
|---|---|---|---|
| ミスの揺れ | ミス（下の「打つ」）が起きたフレーム | `MISS_SHAKE_MS`・`MISS_SHAKE_INTENSITY` の揺れ | 揺れの再生中に新しいミスや床の揺れが起きても、新しい揺れは足さない（`camera.shake` の既定の動作に任せる）。同じフレームにミスと床に着くが両方起きたら、後に処理される床の揺れが無視される（先に起きたミスの揺れが再生される） |
| 床の揺れ | 単語が床に着いたフレーム（ライフが減ったとき） | `FLOOR_SHAKE_MS`・`FLOOR_SHAKE_INTENSITY` の揺れ | 同じフレームに複数の単語が床に着いても 1 回。ライフが尽きて `ending` に入るフレームでも出す（`ending` の間は続け、Result への切り替えで切る） |
| 消えるときの広がり | 単語を打ち切ったフレーム | その単語（全体）を `COLOR.typed`（黄）にし、その位置で `CLEAR_POP_MS` かけて、大きさ 1.0 倍 → `CLEAR_POP_SCALE` 倍（単語の中心が拡大の中心）、不透明度 1 → 0 にして消す。ゲームの状態（画面の単語の一覧・ロックオン）からはそのフレームのうちに外れていて、見た目だけが残る | 同じフレームに複数の単語を打ち切ったら、それぞれに出す。再生中の見た目は、ロックオン・判定・入力に関わらない |
| 得点のポップアップ | 同上 | `+30`（その単語の得点。`+` と整数）を `FONT_POP`・`COLOR.typed` で、文字の中心 x を単語の中心 x、文字の上端 y を単語の上端 y に合わせた位置を開始位置として出し、`SCORE_POP_MS` で `SCORE_POP_RISE` px 上へ動きながら不透明度 1 → 0 で消す（`FIELD_TOP` = 48 の単語でも、終点の文字の上端は 48 − 40 = 8 で画面の中に収まる）。x は、文字の幅の半分 + `MARGIN` を画面の左右の端から確保するよう収める | 同じフレームに複数なら、それぞれに出す（位置が重なっても足さない）。生きている単語の背面・HUD の背面に描くので、上へ動いて次の単語や HUD の行に重なっても、単語と HUD は読める |
| 床に着いた単語の点滅 | 単語が床に着いて数えられたフレーム（ライフが減ったとき。`ending` のあとに着いて無視される単語は含まない） | その単語を、着いた位置（下端が `FLOOR_Y`）に残し、`COLOR.warn`（赤）にして、`LAND_FLASH_MS` で不透明度 1 → 0 にして消す | 同じフレームに複数なら、数えられた単語ごとに出す。`ending` に入るフレームでも出す |
| 床の線の光 | 同上（同じフレームに何語着いても 1 回） | 床の線を白にして、`FLOOR_GLOW_MS` で `COLOR.floor` に戻す（線の太さは変えない） | 途中でまた起きたら、白から数え直す |
| ♥ の消え方 | 同上（失ったライフの数だけ） | HUD の ♥ は、残りのライフの数を右揃えで並べる。失った ♥ は、その並びの左隣（ライフが 0 なら右端）に、`HEART_LOSE_MS` で ♥ の中心を保ったまま大きさ 1.0 倍 → 0 倍になって消える見た目を重ねる | 同じフレームに 2 つ失えば、2 つが並んで縮む。ライフが 0 になるフレームでも出す |
| ロックオンの帯 | 単語にロックオンしている間 | ロックオン中の単語の背面に、`COLOR.lockBand`（白）を不透明度 `LOCK_BAND_ALPHA` で、左端 = 単語の左端 − `LOCK_PAD_X`、幅 = 文字数 × `CHAR_W` + 2 × `LOCK_PAD_X`、高さ `WORD_H` の帯を敷き、単語に付けて動かす | 打ち切る・床に着くとロックオンが外れ、帯も消える。`ending` の間は、ロックオン中の単語に付いたまま残る |

- 描画の順（奥から）: 背景 → 床の線・床の下の帯の案内 → ロックオンの帯 → 得点のポップアップ → 単語（通常・ロックオン・打ち終えた部分）→ 床に着いた単語の点滅・消えるときの広がり → HUD（♥ の消え方を含む）→ 「縦にしてください」の案内（最前面）。揺れは画面全体にかかる
- 効果音・BGM・パーティクルは MVP には無い

### Result

- 上から順に: `GAME OVER`（中心 y = 34、`FONT_RESULT_TITLE`）、`SCORE 1230`（中心 y = 72、`FONT_RESULT_SCORE`）、`WORDS 7`（打ち切った単語の数。中心 y = 104、`FONT_RESULT`）、`BEST 1230`（中心 y = 128）、今回のスコアが自己ベストを更新したら「NEW BEST!」（中心 y = 152、`FONT_RESULT`。更新しないときは何も出さず、行も詰めない）、ボタン 2 つ（「もう一度」「タイトルへ」。`RESULT_BUTTON_W` × `BUTTON_H`、すき間 `RESULT_BUTTON_GAP`、横に並べ、中心 y = H − `BUTTON_FROM_BOTTOM`。画面の下 1/3 に入る）
- 手計算（H = 240 の最小の例）: 「NEW BEST!」の下端は 160、ボタンの上端は 240 − 44 − 26 = 170。重ならない
- 「もう一度」は、スコア 0・ライフ `LIVES`・経過時間 0・単語を全部消した状態で Game を最初から始める。「タイトルへ」は Title へ
- Game から Result に入ったとき、入力欄のフォーカスは外れている（`ending` で外す）。「もう一度」で、同じ処理の中でフォーカスし直す
- 自己ベストの判定と保存は、Result を始めるときに 1 回行う

## ルール

### 単語

- 語彙は下の「単語リスト」（120 語。英小文字だけ。3〜8 文字が各 20 語）。同時に出す数の上限は `MAX_ON_SCREEN`
- 出す間隔: 経過時間 t（秒。`playing` で進み、案内の間は進まない）から `max(SPAWN_MIN_SEC, SPAWN_START_SEC − SPAWN_DECAY_PER_SEC × t)` 秒。最初の単語は、プレイが始まってから `FIRST_SPAWN_SEC` 秒後に出す。出す時刻になっても、次のどれかを満たすあいだは出さず、満たさなくなった最初のフレームで出す（そのとき間隔のタイマーを 0 に戻す）: 画面の単語が `MAX_ON_SCREEN` 個、または、直前に出した単語がまだ `FIELD_TOP` + `WORD_H` + `SPAWN_GAP` より上にある（単語どうしが縦に重ならないため）
- 出す単語の選び方: 文字数 n を、`WORD_MIN_LEN` から `maxLen(t)` までの整数から一様に選ぶ。`maxLen(t)` = `min(WORD_MAX_LEN, WORD_MAX_LEN_START + floor(t / WORD_LEN_UP_SEC))`。次に、文字数が n で、画面に出ていない単語のうち、先頭の文字が画面の他の単語の先頭の文字と重ならないものから一様に選ぶ。そのような単語が無ければ、重なってもよいので、文字数が n で画面に出ていない単語から選ぶ。それも無ければ、画面に出ていない全語から選ぶ
- 横の位置: 単語の左端 x を、`MARGIN` から `SCREEN_WIDTH − MARGIN − 単語の幅` までの一様な乱数で決める（単語の幅は等幅フォントの 1 文字の幅 `CHAR_W` × 文字数。実際の幅を測って使ってよい）。範囲が 0 以下なら `MARGIN`
- 落下の速さ: `FALL_DISTANCE` に対する割合 / 秒で、`min(FALL_SPEED_MAX, FALL_SPEED_START + FALL_SPEED_RAMP × t)`。すべての画面の高さで、落ちきるまでの時間は同じ（開始時は約 11.9 秒、`FALL_SPEED_MAX` では約 3.6 秒）

### 打つ

- 打った 1 文字ごとに、次の順で判定する:
  1. ロックオン中の単語が無いとき: 画面の単語のうち、先頭の文字が打った文字と同じものがあれば、その中で一番下（y が最大）のものにロックオンし、その 1 文字目を打ったことにする（打ち終えた文字数 1）。同じ文字で始まる単語が無ければ「ミス」（ロックオンは起きない）
  2. ロックオン中の単語があるとき: 打った文字が、その単語の次の文字と同じなら、打ち終えた文字数を 1 増やす（他の単語の先頭の文字でも、ロックオンは移らない）。違えば「ミス」
  3. 打ち終えた文字数が単語の文字数になったら、その単語を消す（ロックオンも外れる）。得点とコンボを更新する（下）
- ロックオンは、打ち切るか、その単語が床に着くまで外れない（自分で外す操作は無い。仕様として決めている）
- ミス: コンボを 0 にし、ミスの揺れを出す。ミス自体のペナルティ（ライフ減・得点減）は無い。ロックオン中の単語の打ち終えた文字数は変えない
- 1 文字につき処理は 1 回。同じフレームに複数の文字が届いたら、届いた順に 1 文字ずつ処理する

### 床に着く

- 単語の下端が `FLOOR_Y` に届いたら、その単語を消し、ライフを 1 減らし、コンボを 0 にし、床の揺れを出す。ロックオン中の単語なら、ロックオンを外す。ライフが 0 になったら `ending`

### スコア

- 単語を打ち切ったとき: 得点 = `round(文字数 × SCORE_PER_CHAR × min(COMBO_MULT_CAP, 1 + コンボ × COMBO_STEP))`（コンボは、その単語を打ち切る前の値）。そのあと、コンボを 1 増やす。HUD の `COMBO x5` は現在のコンボ（2 以上のとき）
- スコア = 得点の合計。勝利は無く、ライフが 0 になるのが唯一の終わり
- 自己ベスト: ゲーム終了時のスコアが、保存されている自己ベストを超えたら更新し、Result に「NEW BEST!」を出す（同点は更新しない）。記録が無い（保存なし）ときは、スコアが 1 以上なら更新する。スコア 0 のときは更新しない。保存先は `localStorage` のキー `typerain:best`（数値の文字列）。読んだ値が 0 以上の整数でなければ「記録なし」として扱う。読み書きに失敗したとき（使えない・例外）は、そのセッションの間だけメモリに持ち、Title・Result の `BEST` はそのメモリの値を出す

## 技術要件

- Phaser 4 + Vite + TypeScript。描画は Phaser の Graphics / Text で行い、画像アセットは使わない（スキャフォールドのテンプレートの画像は使わなければ消す）
- ESLint エラー 0、Vitest のカバレッジは 4 指標とも 90% 以上（共通設定のとおり、Phaser に依存する `src/game/scenes/**` と `src/main.ts`・`src/game/main.ts` は対象外。DOM に触る部分〔隠し入力欄・`visualViewport` の追従〕は、これらのファイルに置くか、判定の部分を純ロジックに分けて、そちらをテストする）
- Scene は Title / Game / Result に分け、`preload` / `create` / `update` の責務を混ぜない。入力イベントと隠し入力欄は、Scene の終了時に外す・後片付けする（Title・Result へ戻るたびに重複して登録しない）。毎フレームの処理は、単語の移動・出現と判定に絞る。ゲームの共通部（隠し入力欄、画面の大きさの追従、案内）は Scene をまたいで 1 つだけ持つ
- 隠し入力欄は、Scene の外（DOM）に 1 つだけ作る。画面の大きさは、`visualViewport` の `resize` / `scroll` を監視して、Phaser の表示の領域（ゲームを入れる要素）を、`position: fixed` で `visualViewport` の左上（offsetLeft / offsetTop）と大きさに合わせ（ページはスクロールさせない。iOS Safari が入力欄を見せようとしてスクロールしても、表示の領域が追従して盤面が上にずれて見えなくならない）、`game.scale.setGameSize` で H を変え、Scene へ伝える（Scene 側は `scale` の `resize` を購読する）
- Phaser に依存しない純ロジック（役割ごとのモジュールに分ける）:
  - 単語リストと、単語の選び方（文字数の選択、画面にある単語の除外、先頭の文字が重ならない優先、フォールバック）
  - 時間による変化（落下の速さ、出す間隔、最大の文字数）と、出す条件（上限・直前の単語との縦のすき間）
  - 打った 1 文字の判定（ロックオン、一致、ミス、打ち切り）
  - スコアの計算（コンボ倍率・上限・`round`）、コンボとライフの更新
  - 画面の大きさ（H の決定、縮小率、案内を出す条件）、場の中の割合（H が変わったときの y の置き直し）
  - 単語の横の位置の決定
  - 自己ベストの保存・読み出し（`Storage` を引数で渡す）
  - 入力欄の値の増分から打った文字の列を取り出す処理
  - 演出の値（Scene の外の純関数）: 得点のポップアップの文字（`+30`）と、その x を画面内に収める計算、ロックオンの帯の左端と幅、1 回のライフ減で失った ♥ の数（前後のライフの差）、Title の名前の y（`max(TITLE_NAME_MIN_Y, round((H − 70 − 114) / 2))`）。動きそのもの（拡大・上昇・薄れ・点滅）は tween が行い、Scene で確かめる
- 乱数は `rng: () => number`（[0, 1)）を引数で渡す。時間は `dt` を引数で渡す。純ロジックの中で `Math.random` や `Date` を使わない

## テスト観点

- スコア: 3 文字・コンボ 0 → 30、8 文字・コンボ 0 → 80、5 文字・コンボ 5（倍率 1.5）→ 75、4 文字・コンボ 20 → 120、4 文字・コンボ 25（上限の 3 のまま）→ 120。コンボは打ち切ったあとに 1 増え、ミス・床に着くで 0
- 時間による変化: 落下の速さ — t = 0 で 0.084、t = 100 で 0.224、t = 140 以降で 0.28（超えない）。出す間隔 — t = 0 で 2.4、t = 40 で 1.6、t = 80 以降で 0.8（下回らない）。最大の文字数 — t = 0 と 19.9 で 4、t = 20 で 5、t = 80 以降で 8
- 単語の選び方: 画面にある単語は選ばれない。先頭の文字が重ならない候補があるときはそれから選ぶ（`rng` の端の値で候補の先頭・末尾）。そのような候補が無いとき、同じ文字数の他の単語から選ぶ。全語が選ばれうる。文字数が `[3, maxLen]` から一様に選ばれる
- 出す条件: 画面に `MAX_ON_SCREEN` 個あるとき出ない。直前の単語が `FIELD_TOP` + `WORD_H` + `SPAWN_GAP`（= 78）ちょうどまで下がっていれば出る（77.9 では出ない）。出せなかった間のタイマーは進み続け、条件を満たした最初のフレームで出す
- ロックオンと判定: ロックオン無しで先頭の文字を打つと、その文字で始まる一番下の単語にロックオンする（同じ文字で始まる 2 語があれば y が大きい方）。同じ文字で始まる単語が無ければミスでロックオンしない。ロックオン中に次の文字を打つと進み、違う文字はミス（打ち終えた文字数は変わらない）。他の単語の先頭の文字を打ってもロックオンは移らない。打ち切ると消えてロックオンが外れる
- 床に着く: 下端が `FLOOR_Y` ちょうどで着く（1 px 手前では着かない）。ライフが 1 減ってコンボが 0 になり、ロックオン中の単語ならロックオンが外れる。同じフレームに 2 語が床に着いてライフが 1 のとき、ライフは 0 で止まり（負にならない）、`ending` へ移り、2 語目は無視される
- 画面の大きさ: 表の 7 つの表示（390 × 844 → 779・1.083、375 × 550 → 528、375 × 334 → 321、1280 × 720 → 240・3.0・案内なし、667 × 310 → 240・案内なし、667 × 150 → 240・0.625・案内あり、315 × 210 → 縮小率 0.875 ちょうどで案内なし）。縦長の表示（幅 ≤ 高さ）には案内が出ない。表示の幅が 0 のときも壊れない（H は下限）。案内の文字の大きさ: 縮小率 0.625 で 29、縮小率 0.2 で上限 30、縮小率 0 以下で 30。`dt` は `DT_MAX_SEC`（0.1）で丸める（0.5 秒のフレームで 0.1 秒だけ進む）
- H の変化と y の置き直し: p（進み）を保つ。例: `FALL_DISTANCE` が 200 → 100 に変わるとき、`FIELD_TOP` + 100 に居た単語（p = 0.5）は `FIELD_TOP` + 50 になる
- 入力の読み方: 値が "ab" → "abc" で 'c' だけを新しく打った文字として返し、"abc" → "ab" では何も返さず長さを合わせ、その次に "abx" で 'x' を返す。大文字は小文字にし、a〜z 以外は捨てる。24 文字の値に 1 文字足した（25 文字目）ときは、その 1 文字も返してから、値を空にして長さを 0 に合わせる
- 自己ベスト: 更新の条件（超えたとき・同点・スコア 0・記録なしで 1 以上）、`Storage` が例外を投げるとき・壊れた値のとき（"abc"、"-3"、"1.5"）にメモリで動く
- 演出の値（手計算）: ポップアップの文字は 3 文字・コンボ 0 の語で `+30`、4 文字・コンボ 20 で `+120`。ポップアップの x の収め方は、文字の幅 40 のとき、単語の中心 10 → 28（= `MARGIN` 8 + 20）、中心 350 → 332（= 360 − 8 − 20）、中心 180 → 180。ロックオンの帯は、`cat`（3 文字）が左端 10 にあるとき、左端 6・幅 47（= 3 × 13 + 2 × 4）。失った ♥ の数は、ライフ 3 → 2 で 1、2 語が同時に着いて 3 → 1 で 2、1 → 0 で 1
- 回帰（演出の追加前後）: 純ロジック（打つ・床に着く・スコア・出現・画面の大きさ・自己ベスト）の出力は同じで、既存のテストは変更せずに通る。演出の有無で、ロックオンの判定・ライフ・得点・コンボが変わらない
- 演出の寿命（QA。Scene はカバレッジの対象外のため）: 開発ビルドの `window.__qa` が `effects`（いま動いている時間つきの演出の数: 消えるときの広がり・得点のポップアップ・床に着いた単語の点滅・床の線の光・♥ の消え方の合計）と `lockBand`（ロックオンの帯が出ているか）を出す。単語を打ち切った直後は `effects` が 2 以上（広がり + ポップアップ）で、`SCORE_POP_MS` + 1 フレーム後に 0、ロックオンの帯は打ち切った直後に `lockBand` が false。Result へ切り替えた直後と、「もう一度」で始めた Game の最初のフレームで、`effects` は 0
- Title の配置（演出の見直し後）: ゲーム名の y は H = 240 で 43、321 で 69、528 で 172、779 で 298。BEST の下端（BEST の中心 + 8）が START の上端（H − 70）より上で、重ならない（H = 240 でちょうど 5 のすき間、H ≥ 243 で 8 以上）
- Game の状態: ライフが 0 になった瞬間に `ending` へ移り、それ以降の文字は無視される。`ending` から `RESULT_DELAY` 秒で Result へ移る。案内の間は時間が進まない（Scene のグルーは QA で確認）
- ボタン: 押した位置のボタンの上で離したときだけ働く（押して外へ出して離す・別のボタンで離す・ガード中に押して明けに離すでは働かない）。ガード（`RESULT_INPUT_GUARD_MS`）の境界（499 ms で無視、500 ms で受付）

- 実機のスマホ（縦持ち）で、START をタップするとキーボードが出て、打った文字が反映され、床の線まで見える（実機での確認。スマホでのキーボード入力はヘッドレスブラウザで再現できないため、QA ではビューポートを縮めて近い状態を確かめ、実機は `game-playtest` で確かめる）

- 自己ベストが `localStorage` に保存され、再読み込みしても Title・Result に出る。`localStorage` が使えなくても遊べる
- 演出（スクリーンショットと連続撮影で確認）: 打ち切った単語が黄色に広がって消え、`+点` が上へ動いて消える（375 × 550 と 390 × 844 で、画面の左右にはみ出さない）。床に着いた単語が赤く点滅して消え、床の線が光り、♥ が 1 つ縮んで消える。ロックオン中の単語に薄い帯が付き、打ち切る・床に着くと消える。縦長の画面（390 × 844、375 × 550）で Title の名前〜BEST が上端と START の間の中央にあり、START との間が空きすぎない
