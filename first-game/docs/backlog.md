# first-game 拡張候補（backlog）

公開済みの first-game（Minefield Rogue）に、次に足せるものの候補を、上から順に並べたものです。上のカードが「次の候補」です。仕様（`spec.md`）ではありません。`game-extend` が上から順に 1 件を選び、目的・コアループへの効き方・変えないものを固めてから、仕様に書きます。

- 規模: S = 1 画面と数値の追加程度、M = 複数の画面や仕組みにまたがる追加、L = 大きいので、`game-extend` で 1 PR 分に切り出してから採用する。

### タイトルのデモ再生（`title-demo`）

- 狙い: Title がゲーム名と Start だけで、遊びの見本がない。マインスイーパーを知らない人には、数字を読んで推理して進むゲームだと伝わりにくい。根拠: spec 「Title 画面」（ゲーム名と Start だけ）／ユーザー（pushline・spotdiff の Title のデモを first-game にも入れたい）
- 何を足すか: Title の背景で、ボットが推理して（確定した安全なマスだけを踏み、確定した爆弾には旗を立てて）ゴールまで進むデモを流す。ボットの頭脳は `core/solver.ts` の `analyzeCurrentState`。デモの進行と開始の門は共有パッケージ `title-demo`（`DemoDirector` / `StartGate`）を使う。
- コアループへの効き方: 広げる — ゲームの中身は変えず、タイトルでコアループを見せる。
- 種別: presentation-only
- 規模: L（`Game.ts`（1190 行）から盤面の描画を取り出して Title と共有する再構成と、ボットの手順づくりを含む）
- 出どころ: ユーザー
- メモ: Title の新設と spec の整備（パラメータ表・実装裁量）を先に 1 回で済ませ、デモは分けた（再構成のリスクを独立した PR にするため）。デモは `localStorage`（ハイスコア・開始ステージ）に触れない。ステージ生成は乱数なので、本編の答えを見せる心配はない。

### ゲームオーバーから Title へ戻る導線（`back-to-title`）

- 狙い: Title を足したあと、ゲームオーバーの画面から Title に戻れず、ページを開き直す必要がある。根拠: spec 「Title 画面」（Title に戻る導線はいまは無い）
- 何を足すか: ゲームオーバーの表示に「TITLE」ボタン（と対応するキー）を足し、押すと `Title` に戻る。`Game` の Retry / New Game はそのまま。
- コアループへの効き方: 広げる — ゲームの外側の導線を整える。
- 種別: presentation-only
- 規模: S
- 出どころ: spec 分析
- メモ: 使う人が増えてから判断する。ボタンの数が 3 つになるので、並べ方は `game-extend` で決める。

### FLAG / STAGE ボタンを離したときに盤面のタップとして扱われる疑い（`button-release-move`）

- 狙い: FLAG や STAGE のボタンを押した指を離すと、その位置が盤面のタップとして扱われ、プレイヤーの隣のマスの上にボタンがあると、意図せず 1 マス動く（死ぬことがある）恐れがある。根拠: コードレビュー（`Game.ts` の `onPointerDown` はボタンで早期 return するが、`onPointerUp` は盤面のタップの処理に進む）。未再現
- 何を足すか: ボタンを押した指の離しは、盤面のタップとして扱わない（押し始めがボタンなら、離しは無視する）。あわせて、タッチのキャンセル（`pointer.wasCanceled`）も、ゲームオーバーの画面・ジョイスティック・盤面のタップで無視する。
- コアループへの効き方: 深める — 誤った入力で死なない（操作の信頼性）。
- 種別: gameplay（入力の扱いの修正。バグの疑い）
- 規模: S
- 出どころ: コードレビュー
- メモ: 先に再現して確認する。修正するときは `fix/first-game-<slug>` ブランチで、回帰テストを先に書く。Title は同じ問題を持たないようにしてある（Phaser の標準の当たり判定と `wasCanceled` の確認）。
