# 降りるときの暗転（`floor-fade`）

## 概要

▼ で降りるとき、画面全体を黒で覆い、中央に次のフロアの番号「B<n + 1>F」を大きく出す。次のフロアの生成は、画面が完全に暗くなってから行い、そのあと明転して次のフロアが現れる。いまは `ClearDelay`（250 ms）で一瞬で切り替わり、降りた実感がなく、生成が長いフロア（B20F 以上で数百 ms〜数秒）の待ちが止まったように見える。暗転で「降りていく」感触を足し、生成の待ちを暗転の間に収める（presentation-only。コアループは広げず、降りる感触だけを足す）。ルール・スコア・生成・難しさ・操作の判定は変えない。

## 操作仕様

- 操作（キー・タップ・仮想パッド・FLAG・コード操作・スクロール・M キー・MAP）は、追加も変更もしない。
- **入力を受け付けない間**: ▼ に着いたフレームから、保持が終わって明転が始まった `update` までは、すべての入力（キー（T・R・M を含む）・盤面のタップ・仮想パッド・FLAG・MAP・ドラッグのスクロール）を受け付けない（いまの `ClearDelay` の間と同じ扱い。フロアの全体図も出さない）。dev の「STAGE」ボタンだけは、いつでも受け付ける（本番には無い）。
- **明転が始まったら**: 明転が始まった `update` の次の `update` から、入力をふつうに受け付ける（追加の入力ロックは無い）。明転の間に、移動・フラグ・コード操作・スクロール・M キー・MAP が使える。
- ▼ に着く前から押していた指（タップ・仮想パッド・ドラッグ）と、受け付けない間に押し始めた指は、離したとき何もしない（いまの「ゴール後」の規則と同じ。押し始めの記録は ▼ に着いたフレームで破棄する）。▼ に着く前から押しているキーの自動リピート（`repeat`）は、受け付けない間に無視し、明転が始まった後も、押し直すまで動きのきっかけにならない。
- dev の「STAGE」ボタンで有効な番号へジャンプしたとき（暗転・保持・明転のどの時点でも）、暗転（明転も）を即座に取り消す（不透明度 0・ラベルも消す）。待っている次のフロアの生成は取り消し（まだ生成していなければ行わない）、ジャンプ先のフロアを演出なしで始める（今までのジャンプと同じ）。無効な入力・キャンセルは、暗転を変えない。

## 画面・Scene構成

### 見た目

- **覆い**: `Game` の画面全体（幅 × 高さ。カメラのスクロールで動かない。`scrollFactor` 0）を覆う黒（`FadeColor` = `0x000000`）の矩形。盤面・壁と扉・通路・プレイヤー・HUD の帯と文字・画面外の矢印・全体図・仮想パッド・FLAG・MAP・STAGE・ゲームオーバーの暗幕と墓石を含む、`Game` のすべてのものより手前に描く（このフェードの層が最前面）。入力は遮らない（覆いの上の押し始めは、その下のものとして、いまの入力の規則どおり扱う。受け付けない間は、規則により何も起きない）。dev の「STAGE」ボタンは、覆いの下で見えなくても押せる（dev のみ）。
- **ラベル**: 覆いの中央（画面の幅・高さの中心）に、文字列 `B<n + 1>F`（`n` は降りる前のフロア番号。表記は [HUD のメッセージとステータス](hud.md) のフロアの表記と同じ。`StageMax` を超えても続く: B100F から降りると `B101F`）。大きさ `FadeLabelSize`（48 px）・太字・明るい色（黒の覆いの上で読める色）。覆いの手前（覆いの不透明度と同じ不透明度で、一緒に現れ・消える）。`B100F`・`B101F` でも、幅 320 px の画面に収まる（5〜6 文字 × 48 px のおよその幅は 190 px 以下）。ラベルの文字は、実寸 14 px よりずっと大きく、HUD の文字より大きい。
- 暗転の間、ほかの絵（盤面・HUD など）は動かさず・変えない（覆いの下で、そのまま。HUD のメッセージ `You descend the stairs.` は、次のフロアを生成するまで変わらない）。生成のあと、覆いの下の盤面・HUD・カメラは次のフロアのもの（HUD のメッセージは、フロアの開始の文言。[hud.md](hud.md)）になる。
- `resize`（画面の回転・ウィンドウの変更）では、覆いを新しい画面全体の大きさに、ラベルを新しい中心に、すぐに置き直す（時間は変えない）。

### 状態遷移

▼ に着く（フロアクリア）→ 暗転 → 生成 → 保持 → 明転 → 通常、の順に進む。暗転から保持の終わりまでは、フロアの流れの `clearing`（[フロアの全体図](floor-map.md)の「受け付ける場面」で受け付けない場面）である。明転が始まった `update` で `play` に戻る。

| 遷移 | 契機 |
|---|---|
| 部屋の中（`play`）→ 暗転（`clearing`） | ▼ のマスに着いた（フロアクリア）。メッセージ `You descend the stairs.` を出す。この `update` の終わりのフレームを、暗転の t = 0（不透明度 0）とする |
| 暗転 → 暗転の完了 | 暗転の経過時間 t が `ClearDelay` 以上になった `update` で、不透明度を 1 にして描く |
| 暗転の完了 → 生成 | 暗転の完了の `update` の次の `update`（完全に暗い画面が、少なくとも 1 フレーム描かれたあと）で、次のフロアの生成と、その盤面・HUD・カメラの置き直しを行う（同期。長くかかってもよい）。生成を終えた `update` から保持を数える |
| 生成 → 保持 | 生成を終えた `update`。この `update` の `delta` は保持の時間に足さない |
| 保持 → 明転（`play`） | 保持の経過時間が `FadeHoldMs` 以上になった `update`。その `update` で、フロアの流れを `play` に戻し、明転を始める（その `update` が明転の t = 0。不透明度 1。`delta` は足さない） |
| 明転 → 終わり | 明転の経過時間 t が `FadeInMs` 以上になった `update` で、覆いとラベルを非表示にする（不透明度 0 なので描かない） |
| 暗転・保持・明転 → 新しいフロア | dev の「STAGE」で有効な番号へジャンプしたとき（上の「操作仕様」） |

- 時間は、通路・全体図と同じく、`Game` が進めるフレームの時間（1 フレームの `delta` は `CorridorMaxFrameMs`（100 ms）で頭打ち。ページが見えていない間は進めない）で数える。画面の回転・リサイズでは変えない。
- 「次のフロアの開始は 1 回だけ」: 暗転の間に、生成が 2 回行われない（フロアが飛ばない。▼ に着いたあとに、ほかの入力でも次のフロアの生成は起きない）。ゲームオーバーも起きない（暗転の間は、爆弾を踏めない）。
- **明転の間に起きること**: 明転は `play` に戻ったあとも、状態によらず、一定の時間で最後まで進む（途中で止めず・早めない）。明転の間に爆弾を踏んで死んでも（`dying`・ゲームオーバー・墓石）、通路に入っても、全体図を出しても、覆いは最前面のまま（ゲームオーバーの暗幕・墓石・ボタンの手前）、残りの時間でフェードアウトする。覆いは入力を遮らないので、ゲームオーバーのボタンは見えるようになるまでの間も、いまの規則どおり押せる。取り消すのは、dev の STAGE のジャンプ・RETRY・NEW GAME・TITLE・`Game` を離れるときだけ（RETRY・NEW GAME・TITLE のときは、新しい `Game`・フロアの開始で覆いが残らない）。
- 暗転の間に `Game` が閉じる・始め直される（`Title`・RETRY・NEW GAME は、入力を受け付けないので起きない）ことは無い。`Game` を離れるときは、覆い・ラベルを破棄する。

### 場面

- 暗転が出る場面は、▼ で降りるときだけ。RETRY（同じフロアのやり直し）・NEW GAME・dev の STAGE のジャンプ・扉と通路・`Title` の Start は、演出なし（いまのとおり）。
- 全体図は、▼ に着いたフレームで消える（[floor-map.md](floor-map.md) のとおり）。明転が始まってから、M キー・MAP で出せる。全体図は覆いの奥（覆いが手前）。

## ルール

- 暗転はゲームの状態を読むだけで、次のフロアの生成・盤面・爆弾・スコア・ハイスコア・保存を変えない。同じシードで同じフロア番号なら、いままでと同じ盤面が生成される。
- 生成の時間は、暗転の間に収まるかどうかによらず、保持の時間に数えない（生成が何秒かかっても、生成のあとに `FadeHoldMs` のあいだラベルを見せる）。
- スコアは、フロア番号 − 1（変えない）。HUD のステータス行は、いままでどおり新しいフロアが始まるとき（次のフロアの生成のとき。覆いの下）に、新しい `B<n>F`・`Score` になる。

## パラメータ表

| 名前 | 初期値 | 意味 |
|---|---|---|
| `ClearDelay` | 250 ms | ▼ に着いてから画面が完全に暗くなるまでの暗転の長さ（`docs/spec.md` のパラメータ表。独立した待ちではなく、暗転の長さ） |
| `FadeHoldMs` | 500 ms | 次のフロアの生成を終えてから、暗いまま「B<n + 1>F」を見せる時間 |
| `FadeInMs` | 250 ms | 明転の長さ（不透明度が 1 から 0 へ直線的に下がる） |
| `FadeLabelSize` | 48 px | ラベルの文字の大きさ（太字） |
| `FadeColor` | `0x000000` | 覆いの色（不透明度は 0〜1。ラベルの色は実装裁量） |
| `CorridorMaxFrameMs` | 100 ms | 1 フレームの `delta` の頭打ち（通路・全体図と同じ。`rooms-and-floors.md` のパラメータ表） |

初期値のまま、合計は暗転 250 ms + 生成 + 保持 500 ms + 明転 250 ms（約 1 秒 + 生成）。入力を受け付けない間は、約 750 ms + 生成（フレームの区切りで 100 ms 程度のずれは許す）。

## テスト観点

- **覆いの不透明度**（純粋な関数。手計算。`ClearDelay` = 250・`FadeInMs` = 250）:
  - 暗転: t = 0 → 0、125 → 0.5、250 → 1（完了）、400 → 1（頭打ち）。
  - 保持: 1。
  - 明転: t = 0 → 1、100 → 0.6、125 → 0.5、200 → 0.2、250 → 隠す（描かない。`null`）、300 → 隠す。
  - ラベルの不透明度は、覆いと同じ。
- **時間の進み**（状態を持つ純粋なクラスか関数。手計算。`delta` は 100 ms ずつ。▼ に着いた `update` を u0 とする）:
  - u1: t = 100 → 不透明度 0.4・生成しない。u2: t = 200 → 0.8。u3: t = 300 → 1（暗転の完了。まだ生成しない）。
  - u4: 生成する（`delta` は保持に足さない）。保持 = 0。u5〜u8: 保持 = 100 / 200 / 300 / 400（まだ入力を受け付けない・不透明度 1）。u9: 保持 = 500 → 明転を始める（`play` に戻る・不透明度 1・t = 0）。
  - u10: 入力を受け付ける・t = 100 → 0.6。u11: t = 200 → 0.2。u12: t = 300 → 隠す。
  - 1 つの `update` の `delta` が 1500 のとき、100 として数える（頭打ち。保持・暗転・明転のどれでも）。ページが見えていない間（`delta` を進めない）は、時間が進まない。生成を行った `update` の `delta` は、どれだけ長くても保持に足さない。
  - ちょうど境界: t = 249（暗転の途中。不透明度 0.996）→ まだ完了でない。t = 250 → 完了。保持 499 → まだ。保持 500 → 明転を始める。
- **ラベルの文字列**（純粋な関数。手計算）: 降りる前のフロア 1 → `B2F`、9 → `B10F`、99 → `B100F`、100 → `B101F`（`StageMax` を超えても続く）。
- **受け付ける場面**: 暗転・保持の間は、`mapAccepted('clearing')` が偽（全体図を出さない）。明転が始まった `update` の次の `update` から、入力・全体図を受け付ける。M キー・MAP・T・R・移動・フラグ・スクロールが、暗転と保持の間は何も起こさず、明転の間は通常どおり動く。
- **取り消し**: 暗転の間・保持の間・明転の間のどこで dev の STAGE のジャンプを受けても、覆いとラベルが消え、生成の予約が取り消され（ジャンプ先のフロアが 1 回だけ作られ）、入力を受け付ける状態になる。無効な入力は、暗転を変えない。
- **明転の間の出来事**: 明転が始まった `update` の次の `update` で爆弾を踏んで死んでも、覆いの不透明度は明転の規則どおりに下がり続け（t = 100 → 0.6、200 → 0.2、250 以上 → 非表示）、ゲームオーバーの暗幕・墓石・ボタンの手前に描かれる。明転の途中で RETRY・NEW GAME を選ぶと、覆いとラベルが消える（次のフロアの開始で残らない）。
- **回帰条件**（変えないもの。完了条件にも書く）:
  - 同じシード・同じフロア番号の生成の結果（盤面・爆弾・扉・通路・▼ の位置）が、いままでと同じ。
  - スコア（降りるたびに + 1）・ハイスコア・保存の読み書き・フロアの表記（`B<n>F`）・HUD の文言（`You descend the stairs.`・フロアの開始の文言）が、いままでと同じ。
  - ▼ の判定（▼ に着くとクリア。旗を立てて踏むと死ぬ）・死亡・RETRY・NEW GAME・dev の STAGE のジャンプ（演出なし）・扉と通路・全体図・ゲームオーバーの 2 段階が、いままでと同じ。
  - 移動・フラグ・コード操作・走る・タップ・長押し・仮想パッド・FLAG の判定と、`Title`・デモが、いままでと同じ。
  - 既存の単体テストが、書き換えずに通る。ただし、「ゴール後 `ClearDelay` で次のフロアを始め、`play` に戻る」ことを確かめている既存のテストは、新しい規則（暗転 → 生成 → 保持 → `play` に戻る）に合わせて直してよい（直してよいのはこの時間の規則だけ。ほかの期待値は変えない）。

## 実装裁量

- 覆いの描き方（黒の矩形・`Graphics`・`RenderTexture` など）と、層の `depth` の値（`Game` のすべての層より手前であること）。ラベルの色・フォント・縁取り（黒の上で読めること）。
- 暗転・生成・保持・明転を進める純粋な状態（クラスか関数か）の名前・置き場所・分け方。フロアの流れ（`StageFlow`）の相の増やし方（`clearing` のまま持つか、内部の段階を足すか。player から見える規則は、上の「状態遷移」と同じであること）。
- 「完全に暗い画面を少なくとも 1 フレーム描いてから生成する」の実現方法（次の `update` で行う・描画のあとのイベントで行う、など）。
- `window.__qa`（dev のみ）に暗転の状態（不透明度・段階）を出すかどうか。
- 暗転の間の、ほかの絵（HUD の文字など）の内部の更新の順序（見た目は、覆いの下で、上の「見た目」のとおり）。
