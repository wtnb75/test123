# HUD のメッセージとステータス

`docs/spec.md` の「画面・Scene 構成」の一部。`Game` の上部に出る HUD（メッセージ行・ステータス行・凡例の行・帯）の文言・配置・描画順を、独立して書いたもの。`docs/spec.md` と合わせて 1 つの spec である。

## 概要

ローグ風に、上にメッセージ行（直前の出来事を 1 文で）、その下にステータス行（`Stage:<n>  Score:<s>  High:<h>`）を置く。ゲームオーバーの間だけ、色の凡例の行が出る。HUD の裏には半透明の帯を敷き、盤面をスクロールして HUD の位置に来ても文字が読めるようにする。ルール・スコア・操作は変えない（presentation-only）。

## 操作仕様

なし（HUD は入力を受け付けない。入力の種類（キー / タッチ）で文言が変わる規則は、下の「入力の種類」に書く）。

## 画面・Scene構成

### HUD のメッセージとステータス

画面の左上に、上から次の行を、左端 20 px から左揃えで積む。どの行も `scrollFactor` 0 で、盤面のスクロールでは動かない。HUD の裏には半透明の「帯」（下の「帯」）を敷き、帯と文字は盤面より手前に描く。奥から: 盤面（マスの四角・文字・マスの中の ▲▼）→ プレイヤーの強調 → 「@」の印 → 帯 → HUD の文字 → GOAL の矢印 → 仮想パッド・FLAG・STAGE → ゲームオーバーのボタン。2 段目（墓石画面）の暗幕（盤面の手前・帯の奥）と墓石の絵（仮想パッド・FLAG・STAGE の手前・ボタンの奥）の層は [game-over.md](game-over.md) に書く。プレイヤーの強調と「@」は盤面の一部として帯の奥に入る（盤面の中の前後は変更前と同じ）。GOAL の矢印・仮想パッド・FLAG・STAGE・ゲームオーバーのボタンの前後と描画の層は、変更前のまま（HUD の文字と帯が、盤面側の部品と GOAL の矢印の間に入る）。帯と HUD の文字の `depth`、プレイヤーの強調・「@」の `depth` は、名前のある定数にする（値の意味を即値にしない。置き場所は実装裁量）。

| 行 | 内容 | 文字 | 位置（上端） |
|---|---|---|---|
| メッセージ行 | 直前の出来事の 1 文（下の表） | 14 px・等幅・薄い青（`#c6deff`） | y = `HudMessageY`（8） |
| ステータス行 | `Stage:<n>  Score:<s>  High:<h>`（`<n>` = 現在のステージ番号、`<s>` = ステージ番号 − 1、`<h>` = ハイスコア。区切りは半角スペース 2 つ。値の意味・計算は変えない） | 18 px・等幅・白（`#ffffff`）。幅に収まらないときは、整数 px ずつ 1 px 刻みで、収まる最大の大きさにする（下限 14 px。14 px でも収まらないときは、項目の区切りで次の行へ折り返す） | メッセージ行の下端 + `HudGap`（2 px） |
| 凡例の行（ゲームオーバーのときだけ） | `Orange=mine Green=safe Purple=bad flag` | 12 px・等幅・薄い青 | ステータス行の下端 + `HudGap`。「STAGE」ボタンがある（dev）ときは、「STAGE」ボタンの下端 + `HudGap` との、大きいほう |

- **幅**: メッセージ行とステータス行は、右上の「STAGE」ボタンの下に潜らないよう、幅 `W − 20 − (STAGE ボタンの幅 + 28)`（`W` は画面の幅。ボタンの幅は 90、コンパクト時 82。`28` = ボタンの右の余白 20 + 隙間 8）までに収め、超える文は単語の区切りで折り返す。折り返した分だけ、その下の行は下がる（行は重ならない）。凡例の行は、上端が「STAGE」ボタンの下端より下なので、幅 `W − 40` まで（ボタンの下に潜らない）。「STAGE」ボタンが無い本番ビルドでは、メッセージ行・ステータス行・凡例の行とも、幅 `W − 40` までに収める（左右の余白 20 px ずつ）。
- **帯**: 画面の幅いっぱい・上端 y = 0・下端 = 「いま出ている HUD の行のうち最も下の行の下端」+ `HudBandPadding` の矩形を、`HudBandColor`・不透明度 `HudBandAlpha` で、HUD の文字の裏（盤面より手前）に敷く。HUD の高さが変わったとき（メッセージの折り返し・凡例の行の出入り・画面の大きさの変更）は、帯の下端も同じフレームのうちに追従する（行の位置を決めた直後に決める）。`scrollFactor` 0 で、盤面のスクロールでは動かない。入力は遮らない（帯は押し始めを受け付ける対象ではなく、帯の上のタップ・ドラッグは、これまでと同じ座標の規則で盤面・パッドに届く）。帯は `Game` の Scene にだけあり（`Title` とデモには出ない）、不透明度 `HudBandAlpha` は常に一定（ゲームオーバーの間も、盤面のフェードなどでも変えない）。凡例の行が出ている間は、凡例の行が最も下の行になる。
- **盤面との関係**: 盤面は従来どおり y = 80 から始まる（動かさない）。盤面をスクロールして盤面のマスが HUD の位置に来たときは、マスが帯の下に潜り（半透明なので、うっすら見える）、HUD の文字は常に読める。折り返しなどで HUD が y = 80 を超えたときは、帯が盤面の最初の行の一部を覆う（HUD が読めることを優先する）。超えうるのは、キー向けの長い文言（ステージ開始の操作説明・死亡の案内）が、幅の狭い画面（幅 600 px 未満）で 2 行以上に折り返すときだけで、タッチ向けの文言と、幅 600 px 以上の画面では、凡例の行の下端まで y = 80 以内に収まる。
- **更新**: メッセージ行は、下の表の出来事が起きるたびに置き換える（前のメッセージは残らない）。ステータス行は、ステージの開始・ジャンプ・死亡・ゴールのたびと、メッセージを置き換えるたびに作り直す（値は常に現在のもの）。凡例の行は、死亡の表示と同時に出て、ステージの開始（RETRY・NEW GAME・ジャンプ・次のステージ）で消える。

#### 入力の種類（キー / タッチ）

HUD の文言は、「いまの入力の種類」で 2 通りになる（ステージの開始と死亡のメッセージだけ。ほかの文言は同じ）。

- 初期値: ページを開いたとき、`navigator.maxTouchPoints > 0` なら「タッチ」、そうでなければ「キー」（タッチ対応のノート PC は、最初は「タッチ」になり、キーを押した時点で「キー」になる）。
- 切り替え: `Game` の `keydown` に届いたキー（修飾キー単独・自動リピートも含む）で「キー」、画面のタッチ（`pointer.wasTouch` が true のポインターの押し始め）で「タッチ」。マウスの押し始めは「キー」にする。ゲームオーバーの「他のキーで NEW GAME」のキーも「キー」にする（`Game` を作り直す前に反映する）。
- 値は、ページを開いてからの最後の入力の種類として、`Game` を作り直す NEW GAME・`Title` を経ても保つ（ハイスコアのセッション最大と同じく、`Game` Scene の外に持つ。保存はしない）。切り替わっても、すでに出ているメッセージは変えない（次に出すメッセージから反映する）。

#### メッセージの文言（`k` は新しく開いたマスの数、`n` はステージ番号）

| 出来事 | メッセージ |
|---|---|
| ステージの開始（`Game` の開始・RETRY・次のステージ） | キー: `Move: arrows/QWEA-XZDC  Flag: Shift+dir  Chord: S` / タッチ: `You enter stage <n>.` |
| 「STAGE」で有効な番号へジャンプした | `You jump to stage <n>.`（ステージの開始のメッセージより優先する） |
| 「STAGE」の入力が範囲外・数値でない | `Stage must be 1-<StageMax>.`（状態は変えない） |
| 移動した。新しく開いたマスがない（開示済みのマス・フラグの上の通過） | `You move.` |
| 移動して、`k` 個（`k ≥ 1`。ゼロの連鎖開示の分を含む）のマスが新しく開いた | `You open <k> cell.`（`k = 1`）/ `You open <k> cells.`（`k ≥ 2`） |
| 移動がゴール（下り階段 ▼）に着いた | `You descend the stairs.`（その後 `ClearDelay` で次のステージ。開いたマスの数は言わない） |
| 盤面の外へ移動しようとした | `There is a wall there.` |
| 隣接マスのフラグを立てた / 外した | `You flag the cell.` / `You unflag the cell.` |
| フラグ操作が何も変えなかった（盤面の外、または開示済みのマス） | `You can't flag there.` |
| フラグモードを切り替えた | `Flag mode on.` / `Flag mode off.` |
| コード操作で `k ≥ 1` マスが開いた | `You open <k> cell.` / `You open <k> cells.` |
| コード操作でマスが開かなかった（`auto-opened` だが新しく開いたマスが 0。隣が全部開示済み・旗） | `Nothing to chord here.` |
| コード操作で `k ≥ 1` 個のマスに旗を立てた（`auto-flagged`） | `You flag <k> mine.`（`k = 1`）/ `You flag <k> mines.`（`k ≥ 2`） |
| コード操作が確定できなかった（`not-enough-info`） | `You can't tell yet.` |
| コード操作の実行条件に当てはまらない（`chord-not-available`） | `Nothing to chord here.` |
| コード操作で、周囲のフラグが数字より多い（`flag-overflow`） | `Too many flags around you.` |
| 死亡（移動・コード操作を問わず、結果の status が dead になったとき。爆弾を旗なしで踏んだ・誤った旗を踏んだ・コード操作で開いたマスが爆弾だった、のどれも同じ文言） | キー: `You died. [R]etry [T]itle` / タッチ: `You died.` |

- 優先: 1 回の入力は、上の行のうち 1 つだけの文言を出す（同じ入力で複数当てはまるときは、死亡 > ゴール > ジャンプ > それ以外の順）。
- 同じ文言が続けて出ても、そのまま置き換える（回数は付けない）。

## ルール

なし（文言を出す条件と優先は、上の「メッセージの文言」に書く。ゲームのルール・スコアは `docs/spec.md` のとおり）。

## パラメータ表

| 名前 | 初期値 | 意味 |
|---|---|---|
| `HudMessageY` | 8 px | メッセージ行の上端（画面の左上からの高さ）。盤面の開始位置（y = 80）は変えない |
| HUD の文字 | メッセージ 14 px・ステータス 18 px（14 px まで縮む）・凡例 12 px | 主な情報（ステージ・スコア・ハイスコア）は 14 px 以上、補助の凡例は 11 px 以上（AGENTS.md 4.6） |
| `HudGap` | 2 px | HUD の行の間隔 |
| `HudBandPadding` | 6 px | 帯の下端と、HUD の最も下の行の下端の間隔 |
| `HudBandColor`・`HudBandAlpha` | `#0a1f2f`（盤面の背景色と同じ）・0.7 | HUD の裏の帯。マスが潜っても文字が読め、潜ったマスがうっすら見える濃さ（初期値。`game-polish` で見て調整してよい） |
| HUD の幅 | dev: `W − 20 − (STAGE ボタンの幅 + 28)`（凡例は `W − 40`。上端はボタンの下端 + `HudGap` 以上）。本番（「STAGE」ボタン無し）: すべての行で `W − 40` | 「STAGE」ボタンの下に文字が潜らないための折り返しの幅 |

## テスト観点

- **HUD の文言とステータス行**（純粋な関数。入力は出来事の種類・開いたマスの数・旗の数・入力の種類・ステージ番号・`StageMax`、出力は文字列。手計算の値）：
  - 移動で開いたマス: `k = 1` → `You open 1 cell.`、`k = 2` → `You open 2 cells.`、`k = 0`（開示済みのマスへ）→ `You move.`
  - コード操作: `auto-opened` で `k = 3` → `You open 3 cells.`、`k = 0` → `Nothing to chord here.`、`auto-flagged` で `k = 1` → `You flag 1 mine.`、`k = 2` → `You flag 2 mines.`。`not-enough-info` → `You can't tell yet.`、`chord-not-available` → `Nothing to chord here.`、`flag-overflow` → `Too many flags around you.`
  - 盤面の外 → `There is a wall there.`。フラグ操作: 立てた → `You flag the cell.`、外した → `You unflag the cell.`、変わらなかった → `You can't flag there.`
  - ステージの開始: キー → `Move: arrows/QWEA-XZDC  Flag: Shift+dir  Chord: S`、タッチ → `You enter stage 7.`（`n = 7`）。死亡: キー → `You died. [R]etry [T]itle`、タッチ → `You died.`。ゴール → `You descend the stairs.`。ジャンプ（`n = 12`）→ `You jump to stage 12.`。範囲外（`StageMax` = 100）→ `Stage must be 1-100.`。フラグモード → `Flag mode on.` / `Flag mode off.`
  - ステータス行: ステージ 5・ハイスコア 9 → `Stage:5  Score:4  High:9`、ステージ 1・ハイスコア 0 → `Stage:1  Score:0  High:0`、ステージ 100 → `Stage:100  Score:99  High:<h>`
  - 入力の種類: 初期値（タッチ対応の端末 → タッチ、そうでなければ キー）、キー押下 → キー、タッチの押し始め → タッチ、マウスの押し始め → キー。切り替えは、すでに決まった文言を変えない
  - 行の幅: 幅 390（コンパクト、STAGE ボタンの幅 82）→ `390 − 20 − 110 = 260`、幅 1280（STAGE ボタンの幅 90）→ `1280 − 20 − 118 = 1142`、幅 320（コンパクト）→ `320 − 20 − 110 = 190`。本番（ボタン無し）: 幅 390 → 350、幅 1280 → 1240、幅 320 → 280。凡例の行の上端（本番）= ステータス行の下端 + `HudGap`
  - ステータス行の文字の大きさ（1 文字の幅 = 0.6 × 大きさ とした注入値で、整数 px・18 から 14 まで 1 刻み）: 幅 260 で `Stage:1  Score:0  High:0`（24 文字）→ 18 px（24 × 0.6 × 18 = 259.2 ≤ 260）。幅 260 で `Stage:100  Score:99  High:99`（28 文字）→ 15 px（18: 302.4、17: 285.6、16: 268.8 は超え、15: 252 ≤ 260）。幅 190 で同じ文 → 14 px でも 235.2 > 190 なので、14 px で、項目の区切りで折り返す
  - 優先と置き換え: 死亡かつゴールの入力 → 死亡の文言。ジャンプとステージの開始 → ジャンプの文言。同じ出来事が続けて起きても、回数を付けずに同じ文言のまま
  - コード操作の結果が dead（`bomb-without-flag`）→ 死亡の文言（入力の種類による 2 通り）
  - 開いたマスの数 `k` は、結果の `changedCellIndices` の長さ（移動では移動先のマス自身を含む。`auto-flagged` は旗を立てたマスの数）
- **帯の大きさ**（純粋な関数。入力は HUD の行ごとの下端の y と `HudBandPadding`、出力は帯の高さ。手計算の値）：行の下端が [25, 48]・`HudBandPadding` 6 → 54。[25, 48, 66]（凡例の行あり）→ 72。折り返しで [42, 66]（メッセージが 2 行）→ 72。行が無いとき（空の配列）→ 0（帯を出さない。`Game` ではメッセージ行が常にあるので起こらない）。入力の順番は問わない（最大の下端で決まる）。帯の高さは、最も下の行の下端が増えると、必ず増える。行の下端は `Text` の実測の高さから決める（QA は実測値で確かめる）

- [ ] 回帰（HUD の変更で変えないもの）: ルール・スコア・ハイスコア・保存・生成・難しさ・操作（キー・タップ・パッド・FLAG・STAGE）・ゲームオーバーの色分けとボタン・`Title` とデモが変わらない。ステータス行の値（Stage / Score / High）の意味と計算が変わらない。HUD の文字は `scrollFactor` 0 のままで、位置が動かない（ステージ 10 以上でドラッグしてスクロールしても）。盤面の位置（y = 80）・カメラの追従・スクロールの範囲・マスの絵・GOAL の矢印・パッド・FLAG・STAGE・ゲームオーバーのボタンの位置と、それらの間の前後が変わらない（盤面側の部品（プレイヤーの強調・「@」を含む）と HUD の前後だけが、下の項目のとおり変わる）。既存の単体テストを書き換えずに通る（HUD の文言を直接見ていたものは、spec の表の値に置き換える）
- [ ] HUD が盤面の下に隠れない。QA: ステージ 10 以上でドラッグ（または追従）して盤面を上へ送り、マスが HUD の位置に来た状態（開始・死亡の凡例が出ている状態を含む）で、メッセージ行・ステータス行・凡例の行が、縁だけが残るような欠けなく読める。盤面が画面に収まる小さいステージで、盤面がスクロールされていない最初の画面（盤面の最初の行が y = 80）では、帯の下端が y = 80 以下のとき（メッセージが 1 行のとき。凡例の行が出ていても）、帯がマスを覆わない。幅 600 px 未満のキー向けの長い文言（375x550）でメッセージが 2 行以上に折り返し、帯が y = 80 を超えるときは、盤面の最初の行の上端が帯の下にうっすら見えるだけで、HUD の文字は読める。帯の下端は、死亡して凡例の行が出たのと同じフレームで「凡例の行の下端 + `HudBandPadding`」になり、STAGE のジャンプ・RETRY・NEW GAME で凡例が消えたとき、同じフレームで縮む。画面の回転・リサイズ・折り返し・凡例の出入りで、帯の下端が HUD の最下行に追従する。帯の上でのタップ・ドラッグ・STAGE・FLAG・パッドの操作が、従来どおり働く

## 実装裁量

- HUD のメッセージの文言と文字の大きさは spec に固定してある（上の表。変えるときは spec が先）。HUD の文字の測り方（フォントの実寸から折り返し・縮小の幅を決める方法）、入力の種類を持つ場所（`Game` の中の状態でよい）、メッセージを決める純粋な関数の名前・分け方。帯と HUD の文字の `depth` の値、およびそれに合わせてプレイヤーの強調・「@」の `depth` を帯より下げること（相対順はこの文書の「画面・Scene構成」のとおり。強調 < 「@」 < 帯 < HUD の文字 < GOAL の矢印の `depth` 10 は変えない）。帯の描画方法（矩形のゲームオブジェクト）、色の定数をカメラの背景色と共有するか。
