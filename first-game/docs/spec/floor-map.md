# フロアの全体図（M キー・MAP ボタン）

## 概要

M キー、またはタッチ用の「MAP」ボタンを押すと、フロアの全体図が盤面に重なって出て、一定時間のあと自動でフェードアウトして消える。全体図には、入った部屋・歩き始めた通路・まだ通っていない扉の印（「？」）だけを描く（未訪問の部屋は描かない）。部屋が複数あり、輪もあるフロアで、いまの部屋・通った道・まだ通っていない扉が見分けられるようにする（presentation-only）。ルール・スコア・操作の判定・生成は変えない。コアループは広げず、探索の見通しだけを良くする。

## 操作仕様

| 操作 | 入力 | 動作 |
|---|---|---|
| 全体図を出す | M キー（`KeyM`。押した 1 回につき 1 回。`repeat` は無視。Shift が付いていてもよい。Ctrl・Alt・Meta が付いているときは無視する） / 「MAP」ボタンの押し始め | 全体図を出す。すでに出ている間（フェード中を含む）は、最初から数え直す（不透明度 1 に戻る） |

- **受け付ける場面**: プレイ中（`play`。盤面の入力を受け付けるとき）と、通路を歩いている間（`corridor`。[rooms-and-floors.md](rooms-and-floors.md)「状態遷移」）。ほかの場面では受け付けない: ゴール後の `ClearDelay` の間（`clearing`）、死亡から `DeathDelay` の間（`dying`）、ゲームオーバーの 1 段目（`gameover`）、墓石画面（`grave`）、RETRY / NEW GAME / TITLE を選んで次の Scene・ステージが作られるまでの間（`restarting`）。受け付けない場面では、M キーも MAP の押し始めも、この全体図としては何も起こさない（MAP ボタンの当たり判定は無いものとして、押し始めはその場面のいまの規則のとおり扱う。ゲームオーバーの画面では、M キーは「R・T 以外のキー」、MAP の位置の押し始めは「STAGE 以外の場所の押し始め」として、[game-over.md](game-over.md) のとおり扱う）。`Title`（デモを含む）には M キーも MAP ボタンも無い（何も起こさない）。
- **出ている全体図の消し方**: 次のどれかが起きたフレームで、その場で消す（持ち越さない）。死亡（`dying` に入る）・ゴール（`clearing` に入る）・次のフロアの開始・RETRY・NEW GAME・TITLE・dev の「STAGE」のジャンプ・`Game` の終了。
- 全体図が出ている間も、ほかの入力（移動・フラグ・コード操作・スクロール・FLAG）は止めない。モードも入力ロックも無い。全体図は入力を受け取らない（全体図の上の押し始めは、その下の盤面・パッドなどとして扱う）。
- 「MAP」ボタン（タッチ用。FLAG と同じ種類のボタン）の押し始めは、受け付ける場面では、押した瞬間に全体図を出し、FLAG と同じく、盤面のタップ・スクロール・仮想パッドとして扱わない（押し始めの記録は「ボタン」。離したとき何もしない）。通路の間は、他のボタン・盤面の入力は受け付けない（いまのとおり）が、MAP ボタンだけは受け付ける。M キー・MAP の押し始めは、HUD の入力の種類（[hud.md](hud.md)）をいまの規則のとおり切り替える（M キーはキー、MAP はタッチ・マウス）。
- M キーを、ほかの入力（移動の矢印・テンキー・QWEA・XZDC・S・R・T・Shift・Enter・Space）に割り当てない。「操作の判定は変えない」。

## 画面・Scene構成

### 配置

- 「MAP」ボタンは、FLAG ボタンの真上に、FLAG と同じ大きさの円を置く（中心の x は FLAG と同じ。円の下端が FLAG の円の上端から `MapButtonGap`（12 px）上）。FLAG の円の直径は 52 px（コンパクト = 高さ 520 px 以下または幅 400 px 以下の画面では 44 px）。FLAG・仮想パッド・STAGE・HUD の位置と大きさは変えない。
- 当たり判定は、円の半径 + `MapButtonHitMargin`（2 px）の円（FLAG の当たり判定（半径 + 10 px）の上端と、MAP の当たり判定の下端が接するだけで、重ならない）。判定の順は、FLAG を先にする（接する点では FLAG）。
- 見た目: 暗い青の塗り（FLAG の OFF と同じ塗り）・FLAG の緑と区別できる青系の細い枠・ラベル `MAP`（11 px 以上。FLAG と同じ種類の文字）。出ている間・出ていない間で見た目は変えない。受け付けない場面でも、位置・見た目は変えない（押しても何も起きない）。
- 位置（計算）: FLAG の円の中心は (画面の幅 − 20 − 直径 / 2, 画面の高さ − 20 − 直径 / 2)（現行のとおり。変えない）。MAP の中心 = (FLAG と同じ x, FLAG の中心の y − 直径 − `MapButtonGap`)。直径 52 のとき MAP の y = 画面の高さ − 110、直径 44 のとき 画面の高さ − 98。MAP の層は、仮想パッド・FLAG・STAGE と同じ（ゲームオーバーの暗幕・墓石の絵との前後も FLAG と同じ）。

### 全体図の表示

- **領域**: HUD の帯の下端 + `MapTopGap`（8 px）から、画面の下端 − `MapBottomMargin`（16 px）まで。左右は画面の端から `MapSideMargin`（16 px）。この領域の全面に、背景の板（半透明の暗い塗り。盤面を暗くして図を読ませる）を敷き、その上に図を描く。HUD の帯と文字・矢印・仮想パッド・FLAG・MAP・STAGE は、その手前（隠さない）。
- **縮尺**: フロア全体（すべての部屋・通路を含む外接する長方形。`cols` × `rows` マス。フロアの座標）が領域に収まる最大の大きさ `fit = min(領域の幅 / cols, 領域の高さ / rows)` を、`MapCellMax`（6 px / マス）で頭打ちにしたもの `c = min(MapCellMax, fit)`（実数。下限は無い。常に領域に収まる）。縮尺は、探索して入った部屋が増えても変わらない（フロア全体の外接する長方形で決める）。領域・縮尺・位置は、全体図を出した（押した）フレームの HUD の帯の下端で決め、その表示の間は変えない（メッセージの折り返しで帯が伸び縮みしても動かない。押し直したら決め直す。画面の回転・リサイズでも決め直す）。領域の中央に置く（`ox = 領域の左 + (領域の幅 − cols × c) / 2`、`oy = 領域の上 + (領域の高さ − rows × c) / 2`）。マス (gx, gy) は、画面の (ox + gx × c, oy + gy × c) から c 四方。
- **描くもの**（奥から）:
  1. 入った部屋ごとに、盤面の長方形（フロアの座標の origin から幅 × 高さ。塗り + 輪郭）。いまの部屋（プレイヤーがいる部屋。通路を歩いている間は、出てきた部屋のまま）は、塗りを明るく・輪郭を太くして強調する。
  2. 歩き始めた通路ごとに、そのマスを 1 マスずつ塗る（大きさ `max(c, MapMinStroke)`（`MapMinStroke` = 2 px）の正方形を、マスの中心に置く）。輪の通路も同じ。通路は、歩き始めたフレームから描く（盤面の「#」と同じ）。
  3. 入った部屋の扉ごとに、その扉が壁にある位置（扉のマスの外側の縁の中心）に、扉の印（大きさ `max(c, 3)` px の正方形）。扉の向こうの通路を歩き始めていれば、扉の印だけ。まだ歩いていないときは、その扉から外へ `MapStubCells`（2 マス）の短い線（太さ `max(c, MapMinStroke)`）と、その先（壁の縁から外へ 2.5 マスの位置）に「？」（11 px・太字）。
  4. 入った部屋の ▲（部屋 A の ▲ のマス）と、入った ▼ の部屋の ▼ のマスに、記号 ▲ / ▼（11 px 以上）。どちらも、入っていない部屋には出さない。
  5. 「？」（3 で述べた位置。ほかの図形より手前）。
  6. プレイヤーの点（大きさ `max(c, 4)` px の円。フロアの座標でのプレイヤーのマスの中心。通路を歩いている間は、いま歩いているマス。最も手前）。
- 図形どうしの重なり（▲ とプレイヤーの点、隣り合う扉の「？」、「？」が他の部屋・通路に載る）は許す（上の順の手前が見える）。図が操作 UI（仮想パッド・FLAG・MAP・STAGE）の下に隠れることも許す（領域の全面を使い、操作 UI が手前に重なる）。
- **通路を歩いている間**: 入った部屋は出発側の部屋だけ（行き先の部屋は、到着したフレームで初めて描く）。通路は、歩き始めたフレームから全マスを描く。出発側の扉は印だけで、通路の行き先側の端には何も描かない（行き先の部屋に入るまで）。いまの部屋の強調は、出発側の部屋のまま（戻るとき（子 → 親）も、出てきた子の部屋が強調のまま）。プレイヤーの点は、通路のいま歩いているマス。
- 描かないもの: 入っていない部屋・歩き始めていない通路・先の部屋の中身・盤面の数字・爆弾・旗（部屋の中身は描かない。部屋の四角と ▲ / ▼ だけ）。
- **層**: 盤面・壁と扉・通路の「#」・プレイヤーの強調・「@」の手前、HUD の帯（`HUD_BAND_DEPTH` = 7）の奥。具体的な値は、「@」（6）より大きく 7 未満（実装裁量）。
- **ほかの演出との関係**: 画面外の矢印（DOOR / GOAL）・HUD の文字・パッド・FLAG は全体図の手前で、そのまま見える。盤面のスクロール・カメラの追従・通路の移動のカメラは、全体図に影響しない（全体図は画面に固定。`scrollFactor` 0）。画面の回転・リサイズでは、時間を変えずに、領域・縮尺・位置を配置し直す。

### 時間と状態

| 状態 | 内容 |
|---|---|
| 非表示 | 何も出ていない |
| 表示 | 押したフレームを t = 0 として、`t` < `MapHoldMs` の間は不透明度 1 |
| フェード | `MapHoldMs` ≤ `t` < `MapHoldMs` + `MapFadeMs` の間、不透明度が 1 から 0 へ直線的に下がる（`1 − (t − MapHoldMs) / MapFadeMs`） |
| 非表示（終了） | `t` ≥ `MapHoldMs` + `MapFadeMs`（2.0 秒）で、完全に消える |

- 時間は、通路と同じく、`Game` が進めるフレームの時間（1 フレームの `delta` は `CorridorMaxFrameMs`（100 ms）で頭打ち。ページが見えていない間は進めない）で数える。押したフレーム自身が t = 0 で、その `update` の `delta` は足さず、次の `update` の `delta` から数える（通路の時間と同じ）。画面の回転・リサイズでは変えない。
- 出ている間・フェード中に押し直したら、`t` を 0 に戻す（不透明度 1）。同じフレームに M キーと MAP ボタンの両方が来ても、1 回の押し直しとして扱う。
- 押したフレームと同じフレームに受け付けない場面へ入った（死亡・ゴールなど）ときは、その場面を優先して、全体図は出さない（出ていれば消す）。

## ルール

- 全体図はゲームの状態を読むだけで、盤面・旗・ルール・スコア・生成・通路の速さ・カメラを変えない。
- 全体図に載る「入った部屋」は、その部屋の盤面の描画部品が作られた（初めて入った）部屋と同じ。「歩き始めた通路」は、盤面の通路の「#」が描かれた通路と同じ。
- 全体図の座標は、フロアの座標（[rooms-and-floors.md](rooms-and-floors.md)「フロアの座標」）をそのまま使う。部屋 A の左上が (0, 0) でない（外接する長方形の左上でない）ときも、フロアの座標のまま描く。

## パラメータ表

| 名前 | 初期値 | 意味 |
|---|---|---|
| `MapHoldMs` | 1500 ms | 全体図が不透明度 1 で見える時間（押してから） |
| `MapFadeMs` | 500 ms | そのあとのフェードアウトの時間（全体で 2.0 秒） |
| `MapCellMax` | 6 px / マス | 1 マスの最大の大きさ（小さいフロアで図が大きくなりすぎない） |
| `MapSideMargin`・`MapBottomMargin`・`MapTopGap` | 16 px・16 px・8 px | 領域の左右・下の余白と、HUD の帯の下端からの間隔 |
| `MapMinStroke` | 2 px | 通路・線の最小の太さ（縮尺が小さくても見える） |
| `MapStubCells` | 2 マス | まだ通っていない扉の短い線の長さ |
| `MapButtonGap` | 12 px | MAP の円と FLAG の円の間（縦） |
| `MapButtonHitMargin` | 2 px | MAP の当たり判定の、円の半径からの余白。`MapButtonGap` が 12 px なので、FLAG の当たり判定（余白 10 px）と重ならないよう、2 px（= 12 − 10）以下にする。タップの的は円の直径 + 4 px（コンパクトで 48 px） |
| 背景の板の色・不透明度 | `0x0a1f2f`・0.88 | 盤面を暗くして図を読ませる（フェードのときは、全体に不透明度をかける） |

## テスト観点

- **フェードの不透明度**（純粋な関数 `mapAlpha(elapsedMs)`。`MapHoldMs` = 1500・`MapFadeMs` = 500。手計算）: 0 → 1。1000 → 1。1500 → 1（フェードの始まり）。1600 → 0.8。1750 → 0.5。1900 → 0.2。2000 → 0（消える）。2100 → 非表示（`null`。描かない）。1799 から押し直す（t = 0）→ 1。
- **全体図の配置**（純粋な関数。手計算。画面 390 × 844・帯の下端 52・`MapTopGap` 8）: 領域は x = 16〜374（幅 358）、y = 60〜828（高さ 768）。フロアが 23 × 36 マス → `fit` = min(358 / 23, 768 / 36) = min(15.57, 21.33) = 15.57 → `c` = 6。図の大きさ 138 × 216 → `ox` = 16 + (358 − 138) / 2 = 126、`oy` = 60 + (768 − 216) / 2 = 336。画面 375 × 550（帯の下端 52）: 領域 x = 16〜359（幅 343）、y = 60〜534（高さ 474）→ `fit` = min(14.91, 13.17) = 13.17 → `c` = 6。フロアが 110 × 120 マス（大きい部屋のフロア）→ `fit` = min(343 / 110, 474 / 120) = min(3.12, 3.95) = 3.12 → `c` = 3.12（頭打ちなし）、図は領域に収まる。`cols` = 1・`rows` = 1 でも `c` ≤ 6。
- **部屋・通路・扉の位置**（手計算。上の 390 × 844・23 × 36 のフロア。部屋 A の左上がフロアの座標 (1, 0)・幅 8）: 部屋 A の長方形は、x = 126 + 1 × 6 = 132、y = 336、幅 48、高さ 48。扉 A1（部屋 A の座標 (7, 2)・向き 右）の印の中心は、壁の縁 x = 126 + (1 + 8) × 6 = 180、y = 336 + 2 × 6 + 3 = 351 → (180, 351)。歩いていないとき、線は (180, 351) から x = 192 まで、「？」の中心は (195, 351)。通路 1 の最初のマスがフロアの座標 (9, 2) のとき、その正方形の中心は (126 + 9 × 6 + 3, 336 + 2 × 6 + 3) = (183, 351)、大きさ `max(6, 2)` = 6。縮尺 c = 1 のとき、通路のマスの大きさは 2、扉の印は 3、プレイヤーの点は 4。
- **載せる範囲**（`Game` の状態から決める純粋な関数。手計算。`RoomCount` = 5 の木 A→{B→D, C→E}）: フロアの開始（A にいて、何も歩いていない）→ 描く部屋は A だけ、通路なし、扉 A1・A2 は線と「？」、▲ は出る、▼ は出ない。A1 を歩き始めて B に入る → 部屋 A・B、通路 1、扉 A1 の印と B の入口の扉の印、扉 A2・B の出口（D へ）は線と「？」。D（▼ の部屋でない場合）に入っただけでは、E は描かない。▼ の部屋に入るまで ▼ は出ない（入ったら出る）。輪（B–C を足す）: B と C に入っても、輪を歩くまでは B・C の輪の扉は線と「？」（両方）。歩いたら、輪のマスが描かれ、両端は扉の印になる。いまの部屋の強調: A→B を歩いている間は A のまま、B に出たら B。
- **受け付ける場面**（純粋な関数 `mapAccepted(phase)`）: `play` → 受け付ける。`corridor` → 受け付ける。`clearing`・`dying`・`gameover`・`grave`・`restarting` → 受け付けない。受け付けない場面へ入ると、出ている全体図は消える（フェードの途中でも）。
- **M キーの判定**（純粋な関数。手計算）: `KeyM`（`repeat` = false）→ 出す。`KeyM`（`repeat` = true）→ 何もしない（押し直しにならない）。Shift + `KeyM` → 出す。Ctrl・Alt・Meta + `KeyM` → 何もしない。`KeyN`・`Comma` → 出さない。
- **MAP ボタンの配置**（純粋な関数。手計算）: 画面 390 × 844（幅 400 px 以下なのでコンパクト。FLAG の円の直径 44。FLAG の中心 = (390 − 20 − 22, 844 − 20 − 22) = (348, 802)）→ MAP の中心 = (348, 802 − 44 − 12) = (348, 746)（円の下端 = 768 = FLAG の円の上端 780 − 12）。当たり判定の半径 = 22 + 2 = 24、下端 = 770。FLAG の当たり判定の半径 = 22 + 10 = 32 の上端 = 802 − 32 = 770（接するだけで重ならない。押し始めは FLAG を先に判定する）。画面 1280 × 720（コンパクトでない。直径 52。FLAG の中心 = (1280 − 20 − 26, 720 − 20 − 26) = (1234, 674)）→ MAP の中心 = (1234, 674 − 52 − 12) = (1234, 610)、当たり判定の半径 28・下端 638 = FLAG の当たり判定の上端（674 − 36）。コンパクト（375 × 550。直径 44。FLAG の中心 = (375 − 20 − 22, 550 − 20 − 22) = (333, 508)）→ MAP の中心 = (333, 508 − 44 − 12) = (333, 452)、当たり判定の下端 = 452 + 24 = 476 = FLAG の当たり判定の上端（508 − 32）。画面 667 × 310（コンパクト）→ FLAG の中心 = (625, 268)、MAP の中心 = (625, 212)（HUD の帯・STAGE（右上）と重ならない）。
- **回帰条件**（変えないもの）: 全体図を出しても、移動・フラグ・コード操作・スクロールの結果、HUD の文言、矢印、スコア、生成、通路の時間、ゲームオーバーの表示が変わらない。MAP ボタンの押し始めが、盤面のタップ・仮想パッド・FLAG の切り替えにならない。M キーが、移動・フラグ・コード操作・TITLE・RETRY の入力にならない。既存の単体テストを書き換えずに通る。

- [ ] 変えないもの（回帰条件）: 操作（キー・タップ・パッド・FLAG・STAGE・コード操作・スクロールの判定と配置）、ルール・スコア・ハイスコア・生成・難しさ・通路の速さ、HUD の文言・帯・位置、矢印、カメラ・スクロール（`board-fit` で変わる、マスの大きさ・画面上の位置・収まる部屋の中央寄せを除く。[board-render.md](board-render.md)「盤面の大きさと位置」）、ゲームオーバー（2 段階・ボタン・墓石）、`Title` とデモ、既存の公開 API。既存の単体テストが、書き換えずに通る。意図した変更: M キーが「R・T 以外のキー」として使われる場面（ゲームオーバーの 1 段目・墓石画面）は、いまのとおり。
- [ ] 共有ビルド（`SHARED_VENDOR=1`）で起動し、全体図が出てエラーが出ない。本番ビルドに `window.__qa` が残らない。

## 実装裁量

- 色（背景の板・部屋の塗りと輪郭・いまの部屋の強調・通路・扉の印・線と「？」・プレイヤーの点・▲ ▼。背景の板に対して読め、盤面の色（▲ ▼ の緑・橙、扉の青）と見分けられる範囲で）。初期値の目安: 部屋の塗り `#1f3b57`、いまの部屋 `#2f6fa3`、輪郭 `#6f8197`、通路 `#a4b0be`、扉の印 `#74b9ff`、線と「？」 `#ffd166`、プレイヤーの点 `#ffffff`。
- MAP ボタンの枠の青・ラベルの色・文字の大きさ（FLAG と区別でき、11 px 以上であること）。
- 描画の仕組み（Graphics の使い回し・「？」の Text の置き方（使い回し）・全体図を出すたびに作り直すか、状態が変わったときだけ作り直すか）。ただし、毎フレームのオブジェクトの生成はしない。
- 全体図の層の `depth` の値（「@」（6）より大きく HUD の帯（7）未満）、純粋な関数（`mapAlpha`・配置・載せる範囲・受け付ける場面・M キーの判定）の名前・置き場所・分け方。
- 押し直しの同じフレームの扱いの細部（2 つの入力が同じフレームに来ても 1 回の押し直し）の実装方法。
- `window.__qa`（dev のみ）に全体図の状態（不透明度・描いた部屋の数など）を出すかどうか。
