# 盤面の描画

`docs/spec.md` の拡張。`Game` と `Title` のデモが共有する盤面の描画部品（マス・数字・旗・爆弾・階段（▲ ▼）・プレイヤーの印）の作り方を、大きいステージでも軽くなるものにする。ルール・操作は変えない（presentation-only）。マスの色・旗・プレイヤーの印の見た目は、下の「マスの見た目」で定める。

## 概要

いまの描画は、マスごとにコンテナ・四角・文字のオブジェクトを作り、ステージの開始・ゲームオーバーの色分けのたびに盤面全体を作り直す。ステージ 100（107 × 107 マス）では、ゲームオーバーの色分けの全体描画に約 300〜400 ms かかり、プレイ中の fps も落ちる。マスの四角をまとめて描き、文字は要るマスの分だけ持ち、変わったマスだけを更新することで、大きい盤面でも操作の応答が落ちないようにする（コアループの「推理して進む」の応答を保つ）。

## 操作仕様

変更なし（入力・スクロールは `docs/spec.md` のとおり。カメラは、下の「盤面の大きさと位置」の中央寄せを除いて `docs/spec.md` のとおり）。

## 画面・Scene構成

画面・Scene の構成と配置は変えない。変えるのは、盤面の描画部品の内側だけ。

- マスの四角は、マスごとのオブジェクトにせず、まとめて描く（1 つの `Graphics`、または `RenderTexture`。どちらにするかは実装裁量）。
- 数字・爆弾（\*）・誤った旗の「×」・確定爆弾の「!」・確定安全の「○」の文字と、旗の図形は、マスごとに文字オブジェクト（`Text`）を作らない。見た目ごとに 1 つの見本を持ち、それが要るマスの分だけ、見本を使い回して表示する（要らなくなったら外す）。
- 盤面の中の重なり順（奥から）: マスの四角 → マスの図形（旗）→ マスの文字（数字・爆弾・「▲」「▼」など。盤面の外の帯のマーカーは無い）→ プレイヤーの強調 → 「@」の印（これらはすべて HUD の帯の奥）。盤面全体に同じ不透明度を掛ける（`setAlpha`。Title のデモのフェード）のも変えない。
- Scene の他のオブジェクトとの前後関係は、盤面が HUD の帯・HUD の文字・GOAL の矢印・仮想パッド・FLAG・STAGE ボタン・結果のボタンの奥にある（[spec.md](../spec.md)「HUD のメッセージとステータス」。盤面の描画部品の置き換えでは、この順を変えない。盤面のスクロールでマスが HUD の位置に来ても、HUD の文字は帯の手前に読める）。
- 描画部品が `Game.ts` と `Title.ts` に見せる呼び出し（`render`・`renderChanged`・`updatePlayer`・`canDiff`・`setAlpha`・`setLayout`・`destroy`）は、呼び出す側のコードを変えずに使える形のままにする。`Game.ts` / `Title.ts` を変えてよいのは、呼び出しの最小限の修正だけ。

### 変わったマス（更新の単位）

- 「変わったマス」= 更新の前後で、マスの見た目の決定（下の純粋な関数）の結果が違うマス。手を進めたとき・フラグを立てたとき・コード操作のとき・ゲームオーバーの色分けのとき、変わったマスは**全て**更新する（古い色や文字を残さない）。変わっていないマスは触らない。
- 盤面全体の作り直しを許す場面: ステージの開始（ゴール後の次のステージ・RETRY・NEW GAME・STAGE のジャンプ・Title から `Game` を始めたとき）、盤面の大きさ・位置の変更（`setLayout` の後。画面の回転・リサイズ）、Title のデモのステージの差し替え、部屋 A 以外の部屋の初回の出現（[部屋と通路](rooms-and-floors.md)。部屋ごとに別の描画部品（別のテクスチャ）を持ち、フロア全体を 1 枚のテクスチャにしない。部屋の切り替え・通路の出入りでは盤面を作り直さない）。それ以外は差分で更新する。
- ゲームオーバーの色分けは、いまと同じく `render(stage, logical)` の呼び出しで描画部品に届く（`canDiff` / `renderChanged` を通らない）。描画部品は、自分が持っている前回の見た目と比べて、変わったマスだけを更新してよい。`Stage` の前後の比較は使えない（ゲームオーバーでは、爆弾を開示するために `Stage` の中身が直接書き換わるため）。盤面の大きさ・スタート・ゴールの位置が前の描画と違うときは、全体を作り直す（ステージ番号だけが違うときは、マスの見た目の差で更新する）。`canDiff` の契約は、これと矛盾しない範囲で実装が決める。

### 盤面の大きさと位置（`board-fit`）

`Game` の 1 マスの大きさ `cell`（px）を、画面とステージで決め、遊べる領域に収まる部屋は領域の中央に置く。マスの大きさ以外の寸法（壁の太さ・「+」・「#」・「@」・強調の枠・旗の図形・数字の文字など、基準のマス 30 px で書いたもの）は、すべて `cell / 30` 倍する（拡大も縮小も同じ式。文字は 8 px の下限、寸法は 1 px の下限）。ルール・生成・操作・HUD・各ボタンの位置と大きさは変えない（presentation-only）。`Title` とそのデモは変えない（`REFERENCE_CELL` = 30 px 以下の縮小のまま）。

- **遊べる領域**（`boardArea(W, H)`。`W`・`H` は画面の幅・高さ）: 左 = `BoardAreaSide`（20 px）、上 = `BoardAreaTop`（80 px。盤面の開始位置 y = 80 と同じ。HUD の帯の下）、幅 = `W` − 2 × `BoardAreaSide`、下端 = 操作の部品の上端 `controlsTop`、高さ = `controlsTop` − `BoardAreaTop`（幅・高さは 1 px 未満にならない）。`controlsTop` = 「MAP」ボタンの円の上端と、仮想パッドの土台の円の上端の、小さいほう。MAP の上端 = `H` − `CONTROL_MARGIN`（20） − 2 × FLAG の大きさ − `MAP_BUTTON_GAP`（12）。パッドの上端 = `H` − `CONTROL_MARGIN` − 2 × 土台の半径（52、コンパクトは 41）。FLAG の大きさ = 52（コンパクトは 44。コンパクト = 高さ 520 px 以下または幅 400 px 以下。`controlsLayout` と同じ）。
- **1 マスの大きさ**（`boardCell(n, area, compact)`。整数 px）: `N` = 8 + `n`（`n` = フロア番号 = ステージ番号。そのステージで最も大きい部屋の一辺。奥の部屋の大きさで、`RoomCount` が 4 以上なら必ずある。▼ の位置や、実際のフロアの形によらない）、`fit` = floor(min(領域の幅, 領域の高さ) / `N`)、`cell` = min(`CellComfort`, max(`CellMin`, `fit`))。`CellComfort` = FLAG の大きさ（コンパクト 44・それ以外 52）。`CellMin` = 30（基準のマス）。1 つのフロアの部屋・通路は同じ `cell` で 1 つの格子に置く（部屋ごとに変えない）。`cell` が変わるのは、ステージ（フロア）が変わるときと、画面の大きさが変わるときだけ。
- **手計算**（`CellComfort` / `CellMin` = 44 / 52 と 30）:

| 画面（コンパクトか） | 領域（幅 × 高さ。`controlsTop`） | n = 1（N = 9） | n = 3（N = 11） | n = 4（N = 12） | n = 9（N = 17） |
|---|---|---|---|---|---|
| 390×844（コンパクト） | 350 × 644（724） | floor(350 / 9) = 38 → **38** | floor(350 / 11) = 31 → **31** | floor(350 / 12) = 29 → **30** | floor(350 / 17) = 20 → **30** |
| 375×550（コンパクト） | 335 × 350（430） | floor(335 / 9) = 37 → **37** | floor(335 / 11) = 30 → **30** | 27 → **30** | 19 → **30** |
| 667×310（コンパクト） | 627 × 110（190） | floor(110 / 9) = 12 → **30** | 10 → **30** | 9 → **30** | 6 → **30** |
| 1280×720 | 1240 × 504（584） | floor(504 / 9) = 56 → min(52, 56) = **52** | floor(504 / 11) = 45 → **45** | floor(504 / 12) = 42 → **42** | floor(504 / 17) = 29 → **30** |

  （n = 2・5・8 の PC: 50・38・31。例: 390×844 の MAP の上端 = 844 − 20 − 88 − 12 = 724、パッドの上端 = 844 − 20 − 82 = 742、小さいほう 724。1280×720 は MAP 720 − 20 − 104 − 12 = 584、パッド 720 − 20 − 104 = 596。）
- **収まる部屋**: 部屋の盤面（幅 × `cell`、高さ × `cell`）が、領域の幅・高さの両方に収まる（幅 × `cell` ≤ 領域の幅 かつ 高さ × `cell` ≤ 領域の高さ）とき、その部屋は収まる。大きさの違う部屋は部屋ごとに判定する（最大の部屋に合わせた `cell` で、小さい部屋が収まることがある。収まる判定は盤面のマスだけで、壁の線（2 px）は含まない（ぴったり収まる部屋の壁の線が、領域の端から数 px はみ出してもよい）。例: 390×844・ステージ 4（`cell` 30）で、基準の部屋 11 × 30 = 330 ≤ 350 は収まり、奥の部屋 12 × 30 = 360 > 350 は収まらない。1280×720・ステージ 9 で、基準の部屋 16 × 30 = 480 ≤ 504 は収まり、奥の部屋 17 × 30 = 510 > 504 は収まらない）。
- **カメラ**: (a) いまの部屋が収まるとき、その部屋の盤面の中心を領域の中心に置く: スクロール `scrollX` = 部屋の盤面の左上の x + 幅 × `cell` / 2 − `W` / 2、`scrollY` = 部屋の盤面の左上の y + 高さ × `cell` / 2 − (`BoardAreaTop` + 領域の高さ / 2)（整数に丸める。0.5 は大きい側）。部屋の盤面の左上は、フロアの座標（`BoardOrigin` (20, 80) + 格子の位置 × `cell`）。収まる間は、プレイヤーを追わない（盤面が全部見えているので、プレイヤーは常に見えている）。(b) 収まらないとき: これまでの追従（プレイヤーが画面の端から `CAMERA_FOLLOW_MARGIN`（4 マス）より近いとき追う。追従は、(d) で広げる前のフロアの範囲の内側で止まる。通路を追う間も同じ）。(c) 中央に置く場面: フロアの開始（RETRY・NEW GAME・ジャンプを含む。部屋 A）、通路を歩き終えて部屋に入ったとき（初めても、戻ったときも）、画面の大きさ・向きが変わって `cell` と配置を計算し直したとき（盤面は新しい `cell` で描き直す。ゲームの状態は残す）。それ以外（ドラッグのスクロール）では、中央に戻さない（次に (c) の場面が来るまで、ドラッグした位置のまま）。通路を歩く間は、これまでどおり通路を追う（歩く間に画面の大きさが変わったときは、歩きの経過時間を変えず、`cell` と配置だけを計算し直し、カメラは通路を追ったまま。中央に置くのは、歩き終えたフレームで、入る側の部屋）。ゲームオーバーでは、これまでどおり死亡時のカメラの位置のまま（ゲームオーバー中に画面の大きさが変わったときは、`cell` と配置を計算し直し、死んだ部屋が収まるなら領域の中央、収まらないなら死んだマスが追従の規則を満たす位置に置く。ボタン・墓石の追従は [game-over.md](game-over.md) のとおり）。(d) カメラの動ける範囲は、フロアの外接する長方形（`cell` px の格子）+ 左右 20・上 80・下 40 px の余白に、収まる部屋の中央寄せのスクロールを含むように広げる（広げた分は背景色の空白。ドラッグでもその範囲まで動ける。範囲は、左・上と右・下の両端について、中央寄せのスクロールを含む）。例: 390×844・ステージ 1（`cell` 38・部屋 A 8 × 8）で、部屋 A の左上が (20, 80) のとき、`scrollX` = 20 + 8 × 38 / 2 − 195 = −23、`scrollY` = 80 + 152 − (80 + 644 / 2) = −170（部屋 A の盤面は画面の x = 43〜347、y = 250〜554 に映る。中心 (195, 402) = 領域の中心 (195, (80 + 724) / 2)）。
- **変わらないもの**: HUD（帯・文字・位置）、パッド・FLAG・MAP・STAGE の位置と大きさと当たり判定、画面外の矢印（画面に固定）、全体図（`MapCellMax` で決まる。`cell` に依らない）、`Title` のデモ、ゲームオーバーの暗幕・墓石・ボタン。盤面のタップは、`cell` で（タップした位置 → マスの座標）に変換する（的は `cell` px 四方。コンパクトの上限 44 px）。収まらない部屋の追従は、これまでどおり画面全体を使い、遊べる領域（`controlsTop`）は使わない。そのため、領域の高さが低い画面（667×310 の 110 px など）では、追従する盤面やプレイヤーがパッド・MAP・FLAG の下に入ることがある（変更前からの挙動。領域に収めて追う拡張は、`docs/backlog.md` の `tap-travel`・`rect-fit` と合わせて決める）。スクロールの判定（8 px・100 ms）は px のまま。通路を歩く速さは 1 マス `CorridorStepMs`（120 ms）のまま（画面上の px の速さは、`cell` が大きいぶん速い）。

## ルール

- 見た目は、上の「マスの見た目」のとおり。変えるのは、マスの色（未開示・開示済み）・旗の図形・プレイヤーの「@」と強調の枠・階段（▲ ▼。盤面の外の帯のマーカーは廃止）だけで、それ以外（28 px の四角と 2 px の隙間・数字の色と縁取り・爆弾・誤った旗の「×」・ゲームオーバーの色分けの塗りと「!」「○」・プレイヤーの強調と「@」の位置・重なり順）は、この変更の前の画素と同じ。`Title` のデモの縮小したセル・`Game` の拡大したセルでも同じ規則（文字は 8 px 未満にならず、寸法は 1 px 未満にならない）。
- ゲームのルール・生成・スコア・入力・HUD・各ボタン・数値は変えない。カメラは、スクロールの位置を整数の画素に丸める点（と、「盤面の大きさと位置」の中央寄せ・動ける範囲の広げ方）だけを変える（奇数の画面幅でスクロールが半画素になると、マスの縁の画素が、図形で描いていた変更前と半画素ずれるため）。丸める箇所と方法: (a) 追従（`centerOn`）の直後に `Math.round`（0.5 は大きい側）で丸める（ステージの開始・画面の大きさの変更・回転の追従も同じ）。追従しない（追従のマージン内）ときは触らない。(b) ドラッグでは、ポインターの移動量を 1 画素単位で適用し、1 画素に満たない分は次の移動に繰り越す（ゆっくり小数の移動量で引いても、合計の分だけスクロールする）。境界（bounds）の制限は変えない（境界は整数なので、丸めて範囲外に出ない）。動くのは盤面と、スクロールに追従するもの（盤面の上のマーカー・プレイヤーの印・GOAL の矢印の位置の判定）が 0.5 画素以内。HUD・ボタン（スクロールに依らない物）は動かない。丸める以外のカメラの挙動（追従のマージン・スクロールの量・境界）は変えない（「盤面の大きさと位置」の中央寄せと、動ける範囲を広げる点を除く）。

## テスト観点

純粋なロジックの最低限のテスト対象（`Phaser` の描画そのもの・重なり順は QA のピクセル比較で確認する）。

- **マスの見た目の決定**（Phaser に依存しない純粋な関数）:
  - 入力: マスの状態（開示済みか・爆弾か・旗か・隣接の爆弾数 0〜8・階段（なし / 上り ▲ = スタート / 下り ▼ = ゴール）。扉は盤面のマスではないので、マスの状態には入らない、論理解析の分類（確定爆弾・確定安全・どちらでもない・解析なし）。
  - 出力: 背景色と、文字の並び（文字列・色・太さ・基準セルでの大きさ・縁取りの色と太さ。文字はすべてマスの中央に置く）と、図形の並び（種類（四角 / 三角形）・基準のマスの角からの頂点の座標・色。旗は、柱の四角と旗の三角形の 2 つ。誤った旗は、色が違うだけで、「×」は文字の並びに入る）。基準セル（30 px）の値で表にし、縮小は別の点（8 px の下限・1 px の下限）で確認する。
  - 表の取り方: 変えない部分（数字・爆弾・「×」「!」「○」・ゲームオーバーの色分けの塗り）は、現行の表（既存のテスト）の値のまま。変える部分（未開示・開示済みの塗り・旗の図形・階段）は、上の「マスの見た目」の表の値（`0x3d4f63`・`0x243341`・旗の色 `#ff6b6b` / `#a29bfe`・▲ `#7bed9f`・▼ `#ffa502`、16 px・太字・縁取り 3 px `#0b1220`）を手で書く。階段の組み合わせ: ▲（開示済みの塗り + ▲）、▼ の未開示（未開示の塗り + ▼）、▼ が連鎖開示で開いた（開示済みの塗り + ▼）、▼ + 旗（旗の図形だけ。▼ なし）、▼ + 誤った旗（ゲームオーバー。紫の塗り + 紫の旗 + 「×」。▼ なし）、▼ + 確定安全（ゲームオーバー。緑の塗り + ▼。「○」なし）。階段の情報は、`Stage` の `start` / `goal` から、マスの状態に加える（描画部品の呼び出しの形は変えない）。ただし、扉のマス（部屋 A の出口（`Stage` の出口。2 つ）・ほかの部屋の入口（`Stage` の `start`）と出口。`Stage` の出口の種類 / `startKind` が `door` のとき）には、階段（▲ ▼）を付けない（ふつうのマス。扉の「+」は壁に描く）。階段の組み合わせの表に、「扉のマス → 階段なし」を足す。新しい実装から導いた値は使わない。旗は、文字（「F」）の出力ではなく、図形（種類・色・基準のマスでの位置と大きさ）の出力にする。
  - プレイヤーの印: 「@」の大きさ 14 px・縁取り 2 px・中心 (6, 7)、強調の枠 3 px・不透明度 0.95 以上、強調の塗りの不透明度 0.4・大きさ・位置が変わらないことは、描画部品の定数として、数値を直接確かめる。
  - 旗の図形の縮小: 基準のマス（30 px）では柱 (8, 5, 2×18)・三角形 (10, 5)・(20, 11)・(10, 17)。セルが 15 px のとき、各座標が半分（柱 (4, 2.5, 幅 1×高さ 9)・三角形 (5, 2.5)・(10, 5.5)・(5, 8.5)）。柱の幅は、セルがどれだけ小さくても 1 px 未満にならない。
  - 行: ルールから起こりうる全ての組み合わせ（開示済み / 未開示 × 爆弾 / 安全 × 旗の有無 × 確定爆弾 / 確定安全 / どちらでもない / 解析なし）。起こりえない組み合わせを除くときは、その規則と理由を表の隣に書き、除いた数と残した数の和が全組み合わせの数と一致することを確認する。
- **盤面の大きさと位置**（純粋な関数 `boardArea`・`boardCell`・部屋が収まるかの判定・中央寄せのスクロール・動ける範囲。手計算）: 上の節の表の値（4 つの画面 × n = 1・3・4・9）、n = 2・5・8 の PC（50・38・31）。`fit` が `CellMin` 未満なら 30、`CellComfort` 超なら上限（1280×720・n = 1 は fit 56 で 52）。領域の幅・高さが 0 以下の極端な画面（667×310 の高さ 110 より小さい画面）でも `cell` は 30 以上（領域は 1 px 以上）。収まる判定の境界: 幅 × `cell` が領域の幅とちょうど同じ（例: 390×844、`cell` 35、10 マス = 350）は収まる（≤）、1 px 大きいと収まらない。中央寄せ: 390×844・ステージ 1（`cell` 38）の部屋 A（左上 (20, 80)・8 × 8）の `scrollX` = −23・`scrollY` = −170。収まらない部屋は中央寄せにならず、追従の規則（`CAMERA_FOLLOW_MARGIN`）のまま。動ける範囲: フロアの外接する長方形（`cell` px の格子）+ 余白に、収まる部屋の中央寄せのスクロールを含める（上の例なら x の最小 −23、y の最小 −170）。タップ → マス: `cell` 44・52 で、盤面の左上 (20, 80)・スクロール (0, 0) のとき、画面の (20 + 44 × 3 + 1, 80 + 44 × 2 + 1) = (153, 169) はマス (3, 2)、`cell` 52 で (20 + 52 × 3, 80 + 52 × 2) = (176, 184) はマス (3, 2) の左上の角。
- **変わったマスの集合**: 更新の前後の盤面から求めた「見た目の決定の結果が違うマス」と、更新したマスの集合が一致する（取りこぼし・余分がない）。手を進める・フラグ・コード操作（ゼロの自動展開を含む）・ゲームオーバーの色分けの各場合。
- **全体を作り直す場面**（純粋な関数 `sameBoardShape` と、マスの状態を作る `cellStateOf`）: 盤面の大きさ・スタート / ゴールの位置が変わるときは差分にならない。同じときは、ステージ番号が違っても、ゲームオーバーの色分けでも差分になる（見た目はマスの見た目の決定の結果の差で決まる）。
