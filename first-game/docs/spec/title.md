# Title 画面

`docs/spec.md` の拡張。ゲームを開いたときに最初に出る画面（`Title` Scene）。画面中央のデモは [spec/title-demo.md](title-demo.md)。

## 概要

ゲーム名「Minefield Rogue」、ボットが自動プレイするデモ（[spec/title-demo.md](title-demo.md)）、「Start」ボタンの画面を、`Game` の前に置く。Start（ボタンのタップ・クリック、Enter、Space）で `Game` へ進む。コアループとルールは `docs/spec.md` のとおりで、`Title` はゲームの外側の 1 画面である。

## 操作仕様

| 操作 | 入力 | 動作 |
|---|---|---|
| ゲームを始める | 「Start」ボタンの上でマウスのボタン・指を離す（どのマウスボタンでもよい。押し始めの位置は問わない） | `Game` へ進む |
| ゲームを始める | Enter、Space（`KeyboardEvent.code` が `Enter` または `Space`。修飾キー（Shift・Ctrl・Alt・Meta）が付いていてもよい） | `Game` へ進む |

- 上記以外の入力（矢印キー・WASD・hjklyubn・テンキー（`NumpadEnter` を含む）・Shift・S・R・ボタンの外のタップ・ドラッグ）は何も起こさない。
- キーを押し続けたときの自動リピート（`repeat`）は無視する（1 回の押下につき 1 回）。
- システムによって中止された（cancel）タッチは、離しとして扱わない。
- 開始の要求は最初の 1 回だけを受け付ける（同じフレームに 2 つ以上届いても、`Game` を開始するのは 1 回）。開始した後の入力は無視する。
- Space を押してもページがスクロールしない（Space のブラウザ既定の動作を止める。`Title` が終わるときに元に戻す）。

## 画面・Scene構成

Scene 名は `Title`。ゲームを開くと最初にこの Scene が始まり、Start で `Game` が始まる。`Game` のゲームオーバーの画面から、「TITLE」ボタン・T キーで `Title` に戻れる（[spec.md](../spec.md) の「Game のUI要素」）。戻ったときの `Title` は新しく始まる（デモは最初から、開始の門も新しい）。

### レイアウト

- 背景色は `Game` と同じ（`0x0a1f2f`）で、`Title` の camera に設定する（ゲーム全体の設定の背景色は使わない）。ゲーム名・デモの盤面・「Start」ボタンを、画面の水平中央（x = W / 2 を四捨五入した整数 px）に、上から順に縦に並べる。デモの盤面の置き方は [spec/title-demo.md](title-demo.md) の「レイアウト」。
- ゲーム名「Minefield Rogue」は、中心を `titleMargin + titleFontSize / 2`（四捨五入した整数 px）の高さに、等幅フォント（`Game` の HUD と同じ monospace）の太字で置く（画面の上端から `titleMargin` の余白）。文字の大きさは `titleFontSize`（画面の幅から決める）。
- 「Start」ボタンは、中心を `H − titleMargin − titleButtonHeight / 2`（H は画面の高さ。四捨五入した整数 px）の高さに置く（画面の下端から `titleMargin` の余白）。幅は `titleButtonWidth`（画面が狭いときは縮める）、高さは `titleButtonHeight`。ボタンの中に「Start」と書く。
- 「パッド」ボタン（設定）: ゲーム名の下の行の右端に置く（幅 `titleSettingsWidth`、高さ `titleSettingsHeight`。上端は、ゲーム名の下端から `DEMO_GAP` 空けた位置、右端から `titleMargin` の余白）。その行の分、デモの領域は下がる（上端は、この行の下端から `DEMO_GAP` 空けた位置）。文字は、表示のときは「パッド: 表示」、隠すときは「パッド: 隠す」。押し始めと離しが同じボタンの上で、離したときに切り替える（開始の要求ではない。`Title` は待機のまま）。切り替えた値は、`Game` の仮想パッドと FLAG ボタンの表示に使う（[spec.md](../spec.md)「タッチ操作」の「隠す設定」）。保存は `minefield-rogue-pad`（値 `hidden`。それ以外・無いときは表示）。読み書きに失敗したら、表示として続ける。
- 画面の大きさが変わったとき（Phaser の `Scale.RESIZE` の `resize`）は、新しい大きさで配置し直す。引き継ぐ状態は、デモの状態（[spec/title-demo.md](title-demo.md)）だけである（`Title` 自体の状態は、下の「待機」「開始」）。
- 幅 240px 未満の画面では、ゲーム名が画面に収まることを保証しない（収まらなくてよい）。

### 状態

| 状態 | 内容 | 遷移 |
|---|---|---|
| 待機 | 入力を待つ。`Title` を始めるたび（ゲームを開いたとき、`Game` から戻ったとき）に、ここから始まる | Start の要求（上の操作）が来たら、開始へ |
| 開始 | `Game` へ遷移中。入力は無視する | `Game` が始まる |

### 演出・UI

- 演出は、デモの盤面（[spec/title-demo.md](title-demo.md)）だけである。ゲーム名と「Start」ボタンには、アニメーション演出はない。ボタンの見た目の変化（押下・ホバー）は実装裁量。
- `Title` はブラウザのストレージを読まず、書かない。

## ルール

- `Game` へは、パラメータ・状態を何も渡さない。`Game` は、作成時に開始ステージを決める（[spec.md](../spec.md)「開始ステージの決め方」。ページを開いて最初の `Game` だけ `?stage=` と（dev の）保存された開始ステージを見る）。
- `Title` が生成するステージは、デモ用のステージ 1〜`demoStages` だけである（[spec/title-demo.md](title-demo.md)）。開始ステージは、`Title` では決めず・読まず・使わない（生成は `Game` の作成時）。

## パラメータ表

| 名前 | 初期値 | 意味 |
|---|---|---|
| `titleMargin` | 16 | 画面の上端とゲーム名の間、画面の下端と「Start」ボタンの間の余白 px |
| `titleFontSize` | `clamp(floor(W / 10), 24, 48)` | ゲーム名の文字の大きさ px。W は画面の幅。1024 で 48、390 で 39、300 で 30、240 以下で 24 |
| `titleButtonWidth` | `min(200, W - 32)` | 「Start」ボタンの幅 px（W は画面の幅。左右に 16px 以上の余白） |
| `titleButtonHeight` | 64 | 「Start」ボタンの高さ px（タッチで押しやすい大きさ） |
| `titleSettingsWidth` | 110 | 「パッド」ボタンの幅 px（「パッド: 隠す」が入る幅。右端から `titleMargin`） |
| `titleSettingsHeight` | 34 | 「パッド」ボタンの高さ px |
| 背景色 | `0x0a1f2f` | `Game` と同じ |

## テスト観点

純粋なロジックの最低限のテスト対象（Scene の描画・入力の受付は QA で確認する）。

- **開始キー**: Enter と Space は開始（`repeat` でないとき）。`repeat` のときは開始でない。矢印・WASD・hjklyubn・テンキー（`Numpad5` を含む）・`KeyS`・`KeyR`・`ShiftLeft` は開始でない。
- **開始の門**: 最初の開始要求だけが通り、2 回目以降は通らない。共有パッケージ `title-demo` の `StartGate` を使う（そのテストはパッケージ側にある）。
- **配置の計算**（手計算の境界値）:
  - 画面 1024x768: ゲーム名の中心 y = 40（16 + 48 / 2）、ボタンの中心 y = 720（768 − 16 − 64 / 2）、文字の大きさ 48、ボタンの幅 200。
  - 画面 390x844: ゲーム名 y = 36（16 + 39 / 2 = 35.5 を四捨五入）、ボタン y = 796（844 − 16 − 32）、文字の大きさ 39、ボタンの幅 200。
  - 画面 240x400: 文字の大きさ 24（floor(240 / 10) = 24）、ボタンの幅 min(200, 208) = 200。画面 200x400: 文字の大きさ 24（floor(200 / 10) = 20 を下限 24 に）、ボタンの幅 168（200 − 32）。
  - 幅 240px 以上・高さ 320px 以上のどの画面でも、ゲーム名とボタンが画面内に収まり、重ならない（ゲーム名の下端 = 中心 y + 文字の大きさ ÷ 2 < ボタンの上端 = 中心 y − ボタンの高さ ÷ 2。ゲーム名の幅は 15 文字 × 0.6 × 文字の大きさ）。
- **ステージ生成・ルール**: 爆弾配置・数字ヒント・移動・フラグ・コード操作・即死・生成の解決可能性は、`core/` のテスト（`docs/spec.md` の「テスト観点」）で確認する。開始ステージの決め方（[spec.md](../spec.md)「開始ステージの決め方」）は `Game` が作成時に行い、`Title` は参照しない（QA で `?stage=5` を確認する）。デモのボットの手順・デモ用ステージの生成は、[spec/title-demo.md](title-demo.md) のテスト観点。
- **回帰条件**: `Game` のテスト（爆弾配置・数字ヒント・移動・フラグ・コード操作・解決可能性・生成）が、Title の追加で書き換えずに通る。`Title` が使うブラウザのストレージは、「パッド」の設定の読み書き（`minefield-rogue-pad`）だけである（コードの検索で確認する。ハイスコア・開始ステージの保存には使わない）。`Title` が生成するステージは、デモ用のステージ番号 1〜`demoStages` だけで、`?stage=` や保存された開始ステージを使わない。

## 完了条件

- ゲームを開くと、`Title`（ゲーム名・デモ・「Start」）が最初に出る。Start のタップ・クリック、Enter、Space のどれでも `Game` が始まる。それ以外の入力では始まらない（QA のスクリーンショットで確認する）。
- `Game` に進むと、開始ステージ（最初の `Game` は `?stage=`、dev では保存された開始ステージ、無ければ 1。2 つ目以降は 1。[spec.md](../spec.md)「開始ステージの決め方」）から始まり、Retry / New Game・ハイスコアの保存・コード操作・フラグ・スクロール・仮想パッドが動く。
- 幅 390px の縦長の画面で、ゲーム名とボタンが画面内に収まる。ウィンドウの大きさを変えると、配置し直される。
- `npm run lint`・`npm run test`・`npm run test:coverage`（90% 以上）・`npm run build` がすべて成功し、単体ビルドと共有ビルドの両方で `Title` から `Game` へ進める。
- `first-game/package.json` に `"title-demo": "workspace:*"` の依存を足し（共有パッケージ `shared/title-demo` の `StartGate` を使う。AGENTS.md 2.1 の `shared/` の規約）、`pnpm-lock.yaml` を更新する。単体ビルドと共有ビルドの両方で解決され、`pnpm install --frozen-lockfile` が通る。
- `?stage=5` を付けて開くと、Title で Start を押した後、HUD のステータス行が `Stage:5` で始まる。「STAGE」ボタン（dev のみ）・移動・フラグ・コード操作・スクロール・死亡・RETRY / NEW GAME / TITLE・ハイスコアの保存が動く（QA で確認する）。
- 公開の一覧（`Taskfile.yml` の `GAMES`）と `task build` の成果物の構成は変わらない（共有パッケージは `ALL_GAMES` に混ざらない）。
- `README.md` に、最初に Title が出ることと Start の操作（タップ・Enter・Space）を書く。

## 実装裁量

- 色（ゲーム名・ボタンの塗り・枠・文字）、太字以外のフォントの指定、ボタンの角の丸み・枠の太さ、押下・ホバーの見た目（0.3 秒未満の変化に限る）。ただし、背景とゲーム名・ボタンが識別できること。
- 内部のモジュール構成（`Title` の Scene と、純粋ロジック（開始キーの判定・配置の計算）の分け方、ファイル名）。
- 画面の大きさの変更に追従する方法（リスナーの登録と、Scene 終了時の後始末の方法）。
