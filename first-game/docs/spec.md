# ゲーム仕様書：地雷原ローグライク

## ゲーム名（仮称）

**Minefield Rogue**（地雷原ローグライク）

---

## コンセプト

マインスイーパーのフィールドを舞台にしたローグライクゲーム。
プレイヤーは数字のヒントを手がかりに爆弾の位置を**論理的に確定**しながら、スタートからゴールへ移動する。
爆弾の上を安全に通るには旗を立てる必要があるが、空白マスに誤って旗を立てて踏んでも即死する。
ステージはすべて**推理のみでクリア可能**（運や確率的推測が不要）なように生成され、ステージをクリアするたびに難易度が上がる。誤りは即死（パーマデス）。

---

## ターゲットプレイヤー

- マインスイーパーを知っているユーザー
- ローグライク・パズル系ゲームが好きなユーザー
- 論理推理・確実なクリアを好むプレイヤー（ギャンブル要素が嫌いな人にも向く）

---

## コアループ

1. ステージ開始：グリッドフィールドが表示される（爆弾位置は非表示）
2. 隣接数字ヒントを読み、爆弾マスを推理する
3. 移動前にフラグを立てるかどうか判断する
4. プレイヤーをスタートからゴールへ 1 マスずつ移動させる
5. ゴール到達でステージクリア、次のステージへ
6. 誤った行動（爆弾を素踏み、非爆弾マスに旗を立てて踏む）で即死 → ゲームオーバー

---

## 操作仕様

| 操作 | 入力 |
|------|------|
| プレイヤー移動（8方向） | 矢印キー / テンキー 1〜9（5 を除く）/ QWEA + XZDC キー / タップ（隣接8マスへ 1 マス移動） |
| 隣接マスにフラグを立てる / 外す | Shift + 方向キー（移動と同じキーの組み合わせ） |
| コード操作（自動展開/自動フラグ） | テンキー 5 / S キー（現在地に対して実行） |
| フィールドスクロール | マウスドラッグ / タッチスワイプ |

### 移動方向の詳細

8方向移動が可能。キー対応：

```
Q W E        7 8 9
A   D   /   4   6   （テンキー）
Z X C        1 2 3
```

- `S` は移動キーではなく**コード操作**に割り当てる（下移動は `X`）
- `Shift + 同キー` で、その方向の隣接マスにフラグを立てる / 外す
- テンキー `5` / `S` キー：コード操作（後述）

### フラグ操作の詳細

- フラグは**隣接マス**に立てる（現在地ではなく、移動先候補のマスを事前にマーク）
- フラグ操作と移動操作は独立。フラグを立てた後に必ずそこへ移動する義務はない
- フラグを立て直し（誤り訂正）は同じ操作を繰り返すことで解除できる

### タッチ操作

- 盤面のタップ: プレイヤーに隣接する 8 マスのタップは、そのマスへ 1 マス移動する（それ以外のマスのタップは何も起こさない）
- 仮想パッド（左下のジョイスティック）: 押している間、土台の中心から 14 px 以上離れた位置にあると、その方向（8 方向）が決まり、最初は 380 ms 後、以降 180 ms ごとに 1 マス動く（リピート。FLAG が ON ならフラグ操作）。リピートが一度も起きずに離したときは、押し始めの位置との距離が 14 px 未満ならコード操作、14 px 以上ならその方向へ 1 マス（フリック。フリックの方向は、押し始めの位置から離した位置への向きで決める。リピートの方向は、土台の中心から見た向き）
- 「FLAG」ボタン（右下）は、フラグモードの ON / OFF を切り替える。ON のとき、パッドのフリックは移動の代わりに、その方向の隣接マスのフラグ操作になる（同じマスにもう一度行うと解除のトグル）
- 押し始めが「FLAG」「STAGE」ボタンの上だった指は、離したときに盤面のタップとして扱わない（マスへ動かない）。システムによって中止された（cancel）タッチは、そのポインターの仮想パッドの状態・リピート・ドラッグ・押し始めの記録を破棄し、何も実行しない（コード操作・フリック・盤面のタップ・RETRY / NEW GAME / TITLE のどれにもならない。ジョイスティックのつまみは中央に戻る）。離しは、**押し始めが受け付けられた入力**に対してだけ働く（死亡・ゴールの前から押していた指、`ClearDelay` の間に押し始めた指、ボタンの上で押し始めた指は、離したとき何もしない。ゲームオーバーの画面の RETRY / NEW GAME / TITLE は、ボタンが出てからの押し始めと離しの両方が要り、離した位置で決める（押し始めの位置は問わない）。ゲームオーバーの画面では、STAGE 以外の場所での押し始め（仮想パッド・FLAG・盤面を含む）も、そのまま離した位置で判定する）

### 開始ステージの決め方

`Game` を作るとき（`Title` の Start、NEW GAME）、フラグモードは OFF から始まり（直前の `Game` の状態は持ち越さない）、開始ステージを次の順で決める。数値の読み方は、すべて基数 10 の `parseInt(s, 10)`（先頭の空白と符号を許し、`0x` は 16 進と読まない）で、結果が整数のときだけ有効とする（桁数の多い数が `Infinity` になるときも、整数として扱い `StageMax` に収める。ハイスコアだけは有限の整数のみを有効とし、`Infinity` は無いものとして扱う）。

1. URL の `?stage=` の先頭の整数部分（`parseInt`）が 1 以上なら、それ（`StageMax`（100）を超える値は 100）。
2. そうでなければ、保存された開始ステージ（`minefield-rogue-start-stage`）の先頭の整数部分が 1 以上なら、それ（`StageMax` を超える値は 100）
3. そうでなければ 1

保存された開始ステージは、`?stage=` が有効だったときだけ、最初のステージの生成と描画が済んだ**あと**に、`StageMax` に収めた値で更新する（保存値・既定値から始まったときは書かない。起動できなくなっても、保存は残らない）。保存された値が `StageMax` を超えていても、読むときに `StageMax` に収める（次に保存するまで書き換えない）。「STAGE」ボタンの入力は、1〜`StageMax` の整数だけが有効で、そのステージへ移った後に保存する（範囲外・0・負・数値でない・空は、メッセージを出して何も変えず、丸めない。キャンセルはメッセージも出さず何も変えない。メッセージとプロンプトの範囲の数字は `StageMax` と一致させる。プロンプトの初期値は現在のステージ番号で、`StageMax` を超えるときは `StageMax` にする）。`?stage=` が付いている間は、NEW GAME・`Title` の Start のたびに（1.）が優先される。

### コード操作（S / テンキー5）

マインスイーパーのコード（和音）操作に相当する便利機能。現在地のマス（数字が確定済み）に対して：

- 周囲8マスのうち、論理的に**爆弾と確定しているマス**に自動でフラグを立てる
- または、フラグを立て終えた状態で再度実行すると**安全マスを自動で踏んで開く**
- 誤ったフラグ状態でコードを実行すると即死の可能性があるため、プレイヤーの責任で使用する
- 現在地が**旗マス**の場合は、その旗の周囲8マスのうち、周辺の開示済み数字から**安全と確定しているマスのみ**を自動で開く

#### コード操作の実行条件（厳密定義）

- 現在地マスが開示済みかつ数字 `n > 0` のときのみ実行可能
- 周囲8マスのフラグ数を `f` とする
- `f < n` の場合：未確定マスに自動フラグを試みる（確定できる場合のみ）
- `f = n` の場合：未フラグの隣接マスを自動開示する
- `f > n` の場合：入力エラー扱いとして何もしない（警告表示のみ）
- 現在地が旗マスの場合：周辺の開示済み数字マスについて「その数字 = 周囲フラグ数」が成立しているとき、その数字に隣接する未フラグ・未開示マスを安全確定として開く

### フラグと移動のルール

- **爆弾マスにフラグあり → 踏んでも安全（通過できる）**
- **爆弾マスにフラグなし → 踏んだら即死**
- **非爆弾マスにフラグあり → 踏んだら即死**
- **非爆弾マスにフラグなし → 踏んでも安全（通過できる）**

### 数字ヒントの隣接定義

マインスイーパーと同様に **8方向（斜め含む）** の隣接マスを対象として数字ヒントを計算する。

### 数字ヒントの開示とゼロ自動展開

- 初期状態で表示される数字は、**スタート地点を起点とした開示領域のみ**とする（フィールド全体の数字は表示しない）
- ヒントが **0 のマス**（隣接爆弾なし）を開いたとき、周囲8マスを自動的に連鎖開示する（0 が隣接する限り再帰的に開く）
- 連鎖開示で開いた領域の境界にある数字マスのみ表示される
- スタート地点が 0 の場合、初期状態でその連鎖開示結果が反映される

| Scene 名 | 役割 |
|----------|------|
| `Title` | タイトル画面（ゲーム名・ボットのデモ・Start）。詳細は [spec/title.md](spec/title.md)、デモは [spec/title-demo.md](spec/title-demo.md) |
| `Game` | メインゲームプレイ（フィールド表示・移動・判定）。ステージクリアとゲームオーバー（Retry / New Game / Title）も `Game` の中で表示する |

### Game のUI要素

- グリッドフィールド（数字ヒント付き）、プレイヤーキャラクター、スタート・ゴールの位置を示すマーカー（盤面の端の外側に描く。ゴールが画面の外にあるときは、画面の端に「GOAL <方向の矢印>」）
- 上部の HUD（ローグ風）: 上から「メッセージ行」（直前の出来事を 1 文で）、その下に「ステータス行」`Stage:<n>  Score:<ステージ番号 − 1>  High:<ハイスコア>`。ゲームオーバーの間だけ、その下に色の凡例の行が出る。詳細は下の「HUD のメッセージとステータス」
- 仮想パッド（画面の左下のジョイスティック。8 方向）、右下の「FLAG」ボタン（フラグモードの切り替え。ON のとき、仮想パッドの方向の入力は移動ではなくフラグの操作になる）、右上の「STAGE」ボタン（開始ステージの番号を 1〜`StageMax` で入力して、そのステージへ移る。範囲外・数値でない入力・キャンセルは何も変えない）
- ゲームオーバーの表示: 全爆弾の開示。論理的に確定できた爆弾（橙）・安全マス（緑）・誤ったフラグ（紫）の色分け。`DeathDelay` 後に「RETRY [R]」「NEW GAME」ボタンと、その 1 段下に「TITLE [T]」ボタン（`DeathDelay` の間は、「STAGE」を除くキー・ポインタの入力を受け付けない。「TITLE」は、ゲームオーバーの画面だけにある）
  - R キー・「RETRY」ボタンの上で離す: 死んだステージ番号を、新しく生成した盤面でやり直す（同じ盤面ではなく、乱数で作り直す）。
  - T キー・「TITLE」ボタンの上で離す: `Title` へ戻る（`Game` の状態を捨てて `Title` を始める。`Title` はデモを最初から流し、開始の門も新しい（[spec/title.md](spec/title.md)）。そこで Start すると、`Game` は開始ステージ（「開始ステージの決め方」）から始まる。ハイスコアのセッション最大は残り、保存された値・開始ステージはこの遷移で書き換えない）。
  - それ以外のキー、「RETRY」「TITLE」の外のどこかで離す（NEW GAME ボタンの上を含む）: 新しいゲーム（`Game` を作り直し、開始ステージ（「開始ステージの決め方」）から）
  - 再開・遷移の要求（RETRY・NEW GAME・TITLE）は、最初の 1 回だけを受け付ける（同じフレームに 2 つ以上届いても、先に処理された 1 つだけが効く）
  - T キーは、プレイ中・`DeathDelay`・`ClearDelay` の間は何も起こさない。ボタンの範囲は、画面の座標（ポインターの位置）で、境界を含み、どのマウスボタンの離しでもよい。ボタンの位置は、画面の大きさ（幅・高さ）から「ボタン（RETRY / NEW GAME）」「ボタン（TITLE）」の式で決める。ボタンが出ている間に画面の大きさが変わった（`resize`。端末の回転・ウィンドウの変更）ときは、そのたびに、新しい大きさで 3 つのボタンの絵と範囲を置き直す（押し始めの記録は変えない。離したときは、離した時点の配置で判定する。リサイズより前に押し始めた指でも、ボタンが出てからの押し始めなら、離した位置で決まる。ボタンが出る前に押し始めた指は、`resize` があっても離しは何もしない）。ボタンが出る前（`DeathDelay` の間）に変わったときは、ボタンを出さず、出るときの大きさで置く。ボタンが出ていない間（`DeathDelay` の前、RETRY / NEW GAME / TITLE・STAGE のジャンプで取り消された後、`Game` を離れた後）の `resize` は、ボタンを作らず・出さず、何も起こさない。幅・高さとも 320 px 以上の画面で、3 つのボタンは画面に収まる。ボタンは仮想パッド・FLAG の絵より手前に描き、ゲームオーバーの画面ではパッドは押し始めを受け付けない（小さい画面でボタンがパッドの絵に重なってもよい）
- 死亡したとき、仮想パッドの押下の状態とリピートを解除する（RETRY の後に、指を置いていないのに動かない）。押しっぱなしのキーの自動リピート（`repeat`）は、RETRY / NEW GAME / TITLE のきっかけにならない（押し直したキーだけがきっかけ。`KeyR` は修飾キーが付いていても RETRY、`KeyT` は修飾キーが付いていても TITLE、それ以外のキー（修飾キーだけを含む）は NEW GAME）
- ステージクリア（ゴール到達）では、メッセージを出して `ClearDelay` 後に次のステージへ進む。ゴールに着いたとき、仮想パッドの押下の状態とリピートも解除する（押し直すまで動かない）。`ClearDelay` の間は入力（キー・盤面のタップ・仮想パッド・FLAG・ドラッグのスクロール）を受け付けず、次のステージの開始は 1 回だけである（ステージが飛ばず、クリア済みのステージで死なない）。「STAGE」ボタンだけは、`DeathDelay`・ゲームオーバーの画面・`ClearDelay` の間も受け付け、ジャンプしたときは、待っている次のステージの開始・RETRY / NEW GAME / TITLE のボタン・`DeathDelay` を取り消し、仮想パッドの押下の状態・リピート・ドラッグ・押し始めの記録も破棄する（死亡・ゴールと同じ。ジャンプ前から押していた指の離しは何もしない）
- スコアは「ステージ番号 − 1」（開始ステージが 1 より大きいときは、それより前のステージも数える）。死んだとき、ハイスコアを超えていれば保存する

### HUD のメッセージとステータス

画面の左上に、上から次の行を、左端 20 px から左揃えで積む。どの行も `scrollFactor` 0 で、盤面のスクロールでは動かない。HUD の裏には半透明の「帯」（下の「帯」）を敷き、帯と文字は盤面より手前に描く。奥から: 盤面（マスの四角・文字・スタート・ゴールのマーカー）→ プレイヤーの強調 → 「@」の印 → 帯 → HUD の文字 → GOAL の矢印 → 仮想パッド・FLAG・STAGE → ゲームオーバーのボタン。プレイヤーの強調と「@」は盤面の一部として帯の奥に入る（盤面の中の前後は変更前と同じ）。GOAL の矢印・仮想パッド・FLAG・STAGE・ゲームオーバーのボタンの前後と描画の層は、変更前のまま（HUD の文字と帯が、盤面側の部品と GOAL の矢印の間に入る）。帯と HUD の文字の `depth`、プレイヤーの強調・「@」の `depth` は、名前のある定数にする（値の意味を即値にしない。置き場所は実装裁量）。

| 行 | 内容 | 文字 | 位置（上端） |
|---|---|---|---|
| メッセージ行 | 直前の出来事の 1 文（下の表） | 14 px・等幅・薄い青（`#c6deff`） | y = `HudMessageY`（8） |
| ステータス行 | `Stage:<n>  Score:<s>  High:<h>`（`<n>` = 現在のステージ番号、`<s>` = ステージ番号 − 1、`<h>` = ハイスコア。区切りは半角スペース 2 つ。値の意味・計算は変えない） | 18 px・等幅・白（`#ffffff`）。幅に収まらないときは、整数 px ずつ 1 px 刻みで、収まる最大の大きさにする（下限 14 px。14 px でも収まらないときは、項目の区切りで次の行へ折り返す） | メッセージ行の下端 + `HudGap`（2 px） |
| 凡例の行（ゲームオーバーのときだけ） | `Orange=mine Green=safe Purple=bad flag` | 12 px・等幅・薄い青 | ステータス行の下端 + `HudGap` と、「STAGE」ボタンの下端 + `HudGap` の、大きいほう |

- **幅**: メッセージ行とステータス行は、右上の「STAGE」ボタンの下に潜らないよう、幅 `W − 20 − (STAGE ボタンの幅 + 28)`（`W` は画面の幅。ボタンの幅は 90、コンパクト時 82。`28` = ボタンの右の余白 20 + 隙間 8）までに収め、超える文は単語の区切りで折り返す。折り返した分だけ、その下の行は下がる（行は重ならない）。凡例の行は、上端が「STAGE」ボタンの下端より下なので、幅 `W − 40` まで（ボタンの下に潜らない）。
- **帯**: 画面の幅いっぱい・上端 y = 0・下端 = 「いま出ている HUD の行のうち最も下の行の下端」+ `HudBandPadding` の矩形を、`HudBandColor`・不透明度 `HudBandAlpha` で、HUD の文字の裏（盤面より手前）に敷く。HUD の高さが変わったとき（メッセージの折り返し・凡例の行の出入り・画面の大きさの変更）は、帯の下端も同じフレームのうちに追従する（行の位置を決めた直後に決める）。`scrollFactor` 0 で、盤面のスクロールでは動かない。入力は遮らない（帯は押し始めを受け付ける対象ではなく、帯の上のタップ・ドラッグは、これまでと同じ座標の規則で盤面・パッドに届く）。帯は `Game` の Scene にだけあり（`Title` とデモには出ない）、不透明度 `HudBandAlpha` は常に一定（ゲームオーバーの間も、盤面のフェードなどでも変えない）。凡例の行が出ている間は、凡例の行が最も下の行になる。
- **盤面との関係**: 盤面は従来どおり y = 80 から始まる（動かさない）。盤面をスクロールして盤面のマスが HUD の位置に来たときは、マスが帯の下に潜り（半透明なので、うっすら見える）、HUD の文字は常に読める。折り返しなどで HUD が y = 80 を超えたときは、帯が盤面の最初の行の一部を覆う（HUD が読めることを優先する）。超えうるのは、キー向けの長い文言（ステージ開始の操作説明・死亡の案内）が、幅の狭い画面（幅 600 px 未満）で 2 行以上に折り返すときだけで、タッチ向けの文言と、幅 600 px 以上の画面では、凡例の行の下端まで y = 80 以内に収まる。
- **更新**: メッセージ行は、下の表の出来事が起きるたびに置き換える（前のメッセージは残らない）。ステータス行は、ステージの開始・ジャンプ・死亡・ゴールのたびと、メッセージを置き換えるたびに作り直す（値は常に現在のもの）。凡例の行は、死亡の表示と同時に出て、ステージの開始（RETRY・NEW GAME・ジャンプ・次のステージ）で消える。

#### 入力の種類（キー / タッチ）

HUD の文言は、「いまの入力の種類」で 2 通りになる（ステージの開始と死亡のメッセージだけ。ほかの文言は同じ）。

- 初期値: ページを開いたとき、`navigator.maxTouchPoints > 0` なら「タッチ」、そうでなければ「キー」（タッチ対応のノート PC は、最初は「タッチ」になり、キーを押した時点で「キー」になる）。
- 切り替え: `Game` の `keydown` に届いたキー（修飾キー単独・自動リピートも含む）で「キー」、画面のタッチ（`pointer.wasTouch` が true のポインターの押し始め）で「タッチ」。マウスの押し始めは「キー」にする。ゲームオーバーの「他のキーで NEW GAME」のキーも「キー」にする（`Game` を作り直す前に反映する）。
- 値は、ページを開いてからの最後の入力の種類として、`Game` を作り直す NEW GAME・`Title` を経ても保つ（ハイスコアのセッション最大と同じく、`Game` Scene の外に持つ。保存はしない）。切り替わっても、すでに出ているメッセージは変えない（次に出すメッセージから反映する）。

#### メッセージの文言（`k` は新しく開いたマスの数、`n` はステージ番号）

| 出来事 | メッセージ |
|---|---|
| ステージの開始（`Game` の開始・RETRY・次のステージ） | キー: `Move: arrows/QWEA-XZDC  Flag: Shift+dir  Chord: S` / タッチ: `You enter stage <n>.` |
| 「STAGE」で有効な番号へジャンプした | `You jump to stage <n>.`（ステージの開始のメッセージより優先する） |
| 「STAGE」の入力が範囲外・数値でない | `Stage must be 1-<StageMax>.`（状態は変えない） |
| 移動した。新しく開いたマスがない（開示済みのマス・フラグの上の通過） | `You move.` |
| 移動して、`k` 個（`k ≥ 1`。ゼロの連鎖開示の分を含む）のマスが新しく開いた | `You open <k> cell.`（`k = 1`）/ `You open <k> cells.`（`k ≥ 2`） |
| 移動がゴールに着いた | `You reach the goal.`（その後 `ClearDelay` で次のステージ。開いたマスの数は言わない） |
| 盤面の外へ移動しようとした | `There is a wall there.` |
| 隣接マスのフラグを立てた / 外した | `You flag the cell.` / `You unflag the cell.` |
| フラグ操作が何も変えなかった（盤面の外、または開示済みのマス） | `You can't flag there.` |
| フラグモードを切り替えた | `Flag mode on.` / `Flag mode off.` |
| コード操作で `k ≥ 1` マスが開いた | `You open <k> cell.` / `You open <k> cells.` |
| コード操作でマスが開かなかった（`auto-opened` だが新しく開いたマスが 0。隣が全部開示済み・旗） | `Nothing to chord here.` |
| コード操作で `k ≥ 1` 個のマスに旗を立てた（`auto-flagged`） | `You flag <k> mine.`（`k = 1`）/ `You flag <k> mines.`（`k ≥ 2`） |
| コード操作が確定できなかった（`not-enough-info`） | `You can't tell yet.` |
| コード操作の実行条件に当てはまらない（`chord-not-available`） | `Nothing to chord here.` |
| コード操作で、周囲のフラグが数字より多い（`flag-overflow`） | `Too many flags around you.` |
| 死亡（移動・コード操作を問わず、結果の status が dead になったとき。爆弾を旗なしで踏んだ・誤った旗を踏んだ・コード操作で開いたマスが爆弾だった、のどれも同じ文言） | キー: `You died. [R]etry [T]itle, any key: new game` / タッチ: `You died.` |

- 優先: 1 回の入力は、上の行のうち 1 つだけの文言を出す（同じ入力で複数当てはまるときは、死亡 > ゴール > ジャンプ > それ以外の順）。
- 同じ文言が続けて出ても、そのまま置き換える（回数は付けない）。

### スクロール時の入力競合ルール

- ポインタ移動量が 8px 未満はタップ判定、8px 以上はスクロール判定とする
- スクロール開始後は、そのポインタイベント中の移動/フラグ入力を無効化する
- スクロール終了後の最初の 100ms は誤タップ防止のため入力を受け付けない

## ルール

### 生存条件

- 爆弾マスを踏む前に正しくフラグを立てていること
- 非爆弾マスにはフラグを立てずに踏むこと

### 死亡条件（即死・ゲームオーバー）

- 爆弾マスをフラグなしで踏んだ
- 非爆弾マスにフラグを立てた状態で踏んだ

### クリア条件

- ゴールマスに到達する

### ステージ進行

- クリアごとにステージ番号が増加
- ステージ番号に応じてフィールドサイズと爆弾密度が増加
- パーマデス：死亡するとゲームオーバー。RETRY は死んだステージをやり直し、NEW GAME は開始ステージ（既定は 1）から新しいゲームを始め、TITLE は `Title` へ戻る

### 論理的解決可能性の保証

**全ステージは推理のみでクリア可能でなければならない**（生成の上限に達した場合を除く。下の「リトライ上限と難易度フォールバック」を参照）。具体的には：

- フィールド生成後、爆弾位置の全マスが数字ヒントの論理推理だけで確定できることを検証する
- 確定できないマスが残る場合は爆弾配置を再生成する（リトライ上限あり）
- 判定アルゴリズムは制約伝播（Constraint Propagation）をベースにする：
  1. 数字ヒントから「このマスは必ず爆弾 / 必ず安全」が確定できるマスを繰り返し絞り込む
  2. すべての爆弾マスが確定できれば「論理的解決可能」と判断する
  3. 確定できないマスが残る場合は再生成
- スタートおよびゴールの隣接マスは必ず安全マスにする（最初の一手と最後の一手でヒント情報が得られる状態にする）

### 難易度の深さ設計

難易度はフィールドのサイズ・爆弾数に加え、**推理の深さ（手数）** で制御する。

- **深さ 1（初級）**：1 ステップの制約伝播で解ける（「このヒントだけでここが確定できる」が多い）
- **深さ 2〜3（中級）**：複数のヒントを組み合わせないと確定できないマスが含まれる
- **深さ 4+（上級）**：広域の制約網を複数ステップ伝播させないと解けない配置

ステージが進むにつれて解くのに必要な最低伝播深さが増加するよう、フィールド生成時に深さを評価・制御する。
深さが目標値に届かない場合は再生成する（深さが浅すぎる＝簡単すぎる配置は採用しない）。

### リトライ上限と難易度フォールバック

- フィールド生成は「論理解決可能かつ目標深さ以上」を条件に繰り返す
- 250 リトライごとに、条件を満たせていなければ**目標深さを 1 段階下げて再試行**する（リトライの上限は 1000 回）
- 深さ目標が 1 になる段階から、同じ 250 リトライごとの間隔で、爆弾数を 1 ずつ減らす（下限 1）
- リトライ・時間の上限に達したときは、得られた中で推理の深さが最大の候補を使う。この候補は解決可能であるとは限らない（「全ステージ解決可能」の保証の例外）
- ステージ番号と実際の深さは内部で記録し、バランス調整の参考データとして使用できるようにする

### 生成停止条件（時間上限）

- ステージ生成の試行には時間上限を設ける（初期値: 1500ms）
- 時間上限に到達した場合は、それまでに得た候補のうち推理の深さが最大のもの（同値なら先に得たもの）を採用する
- 候補が1件も得られない場合のみ、ひとつ前のステージパラメータを流用して再試行する

### スコア

- スコア（ステージ番号 − 1）の最大値をハイスコアとして記録する
- 1 ステージ内でのフラグ設置数・移動ステップ数はボーナス計算の候補（MVP外）

## 技術要件

- **ゲームエンジン**: Phaser 4 (TypeScript)
- **ビルド**: Vite
- **テスト**: Vitest（カバレッジ 90% 以上）
- **Lint**: ESLint（エラー 0 件）
- ゲームロジック（爆弾配置・数字ヒント計算・判定・論理解決可能性検証）はPhaserに依存しない純粋な関数として実装し、単体テストを書きやすくする
- HUD の文言（出来事・開いたマスの数・入力の種類から文字列を決める）とステータス行の文字列は、Phaser に依存しない純粋な関数（`core/` の下）にし、`Game` は結果を `Text` に渡すだけにする。入力の種類の切り替え規則（初期値・キー・タッチ・マウス）も純粋な関数にする。HUD の帯の高さ（行の下端から決める）も純粋な関数にする
- `Title` の開始の門は、共有パッケージ `title-demo`（`shared/title-demo`。ワークスペースの依存 `workspace:*`）の `StartGate` を使い、デモの進行は同じパッケージの `DemoDirector` を使う（ボットの手順は `core/solver.ts` の `analyzeCurrentState` を使う純粋な関数。[spec/title-demo.md](spec/title-demo.md)）。開始キーの判定と配置の計算は、`Game` と同じく Phaser 非依存の純粋な関数にする（詳細は [spec/title.md](spec/title.md)）
- `Game` Scene はロジック層を呼び出す描画・入力レイヤーとして分離する
- 論理解決可能性の検証（制約伝播）はフィールド生成ロジックの一部として実装する
- フィールドサイズが画面を超える場合はカメラスクロール（Phaser のカメラ機能またはコンテナオフセット）で対応する
- ハイスコアは `localStorage` に保存する
- 保存（ハイスコア・開始ステージ）の読み書きに失敗しても（ブロック・容量超過など）、ゲームは止まらない。読めなければ既定の値（ハイスコア 0・開始ステージ 1）、書けなければ保存しない。数値の読み方は、開始ステージもハイスコアも、先頭の整数部分（`parseInt`）が 0 以上（開始ステージは 1 以上）ならその値、そうでなければ無いものとして扱う（HUD の `High:` が `NaN` にならない）。ハイスコアの書き込みが失敗しても、死亡の表示・全爆弾の開示・RETRY / NEW GAME は通常どおり出す。ハイスコアは、max(読めた保存値, セッション最大) とする。セッション最大は、ページを開いてから、死亡時に確定したスコアの最大（生存中の現在のスコアは含めない）で、`Game` Scene の外に持ち、NEW GAME・RETRY・TITLE で消えない。HUD の `High` はこのハイスコアで、書き込みは「スコア > ハイスコア」のときだけ行う。ハイスコアは、有限の整数だけを有効とする（`Infinity` は無いものとして扱う）

### 難易度メトリクス（内部記録）

- 各ステージで以下を記録し、バランス調整に利用する
- `solverDepth`（最終的に必要だった推理深さ）
- `inferenceSteps`（確定推論ステップ数）
- `generationRetries`（生成リトライ回数）
- `generationMs`（生成時間）

### フィールドスケール

式は「パラメータ表」。例: ステージ 1 は 8×8・爆弾 9・深さ 1、ステージ 3 は 10×10・爆弾 16・深さ 2、ステージ 10 は 17×17・爆弾 44・深さ 4。

- グリッドサイズに上限は設けない（スクロール対応のため）
- 爆弾密度・深さ目標・生成の上限は「パラメータ表」を参照。数値は実装後のプレイテストで調整する

スタートとゴールはフィールドの**対辺の端**にランダム配置する。

- 配置ルール：上端 ↔ 下端、左端 ↔ 右端、のいずれかの組み合わせで対辺を選ぶ
- 各辺の中のどの位置かはランダム（端のマスでも中央でもよい）
- スタートとゴールは爆弾禁止。また両者の隣接マスも爆弾禁止（最初・最後の推理に必要なヒントを確保）

## パラメータ表

ステージ番号を n とする。値はいまの実装の初期値で、バランス調整（`game-balance`）で変わる。

| 名前 | 初期値 | 意味 |
|---|---|---|
| グリッドの幅・高さ | 7 + n | 正方形。上限なし |
| 爆弾密度 | min(0.18, 0.14 + 0.001 × n) | 面積に掛けて爆弾数の下限にする |
| 爆弾数 | max(6, 4 + 4n, round(面積 × 爆弾密度)) | ステージ n の爆弾の数 |
| 推理深さ目標（初期値） | min(5, floor(1 + n / 3)) | 生成時に目指す、推理に必要な最小の伝播深さ |

| 深さ目標の引き下げ | 250 リトライごとに 1（下限 1） | 目標に届かないときのフォールバック。深さ目標が 1 のときは、同じ間隔で爆弾数を 1 ずつ減らす（下限 1） |
| 候補が 1 件も無いときの代替 | ステージ max(1, n − 1) のパラメータ・深さ 1 | 同じステージ番号として使う |

| `CELL_SIZE` | 30 px | 1 マスの大きさ（描画は 1 マスあたり 28 px の四角） |
| 盤面の原点 | (20, 80) px | 左上のマスの位置 |

| スクロールの判定距離 | 8 px | 未満はタップ、以上はスクロール |

| `DeathDelay` | 600 ms | 死亡してから RETRY / NEW GAME / TITLE のボタンを出すまで |
| `ClearDelay` | 250 ms | ステージクリアから次のステージへ進むまで |

## テスト観点（最低限の単体テスト対象）

- **爆弾配置ロジック**：指定数の爆弾がフィールド内に配置されること
- **数字ヒント計算**：各マスの8方向隣接爆弾数が正しく計算されること（角・辺のマスも境界処理が正しいこと）
- **ゼロ自動展開**：0 のマスが連鎖的に開示されること、フィールド境界で無限ループしないこと
- **踏んだ時の判定（4 パターン）**：
  - 爆弾あり × フラグあり → 生存
  - 爆弾あり × フラグなし → 死亡
  - 爆弾なし × フラグなし → 生存
  - 爆弾なし × フラグあり → 死亡
- **8方向移動**：斜め移動が正しく隣接マスへ遷移すること、フィールド外への移動が無効化されること、Shift + 方向でフラグ操作が実行されること
- **コード操作**：隣接爆弾数 = 周囲フラグ数の場合に安全マスが自動展開されること、条件不一致時は何もしないこと
- **論理的解決可能性の検証**：
  - 制約伝播ですべての爆弾マスが確定できるフィールドを「解決可能」と判定すること
  - 解決不能なフィールドを「解決不能」と判定すること
  - 解決不能な配置は再生成されること
- **推理深さの計測**：既知のフィールドに対して正しい深さが返ること
- **リトライフォールバック**：リトライ上限超過時に深さ目標が下がること
- **スタート・ゴールの配置**：スタートとゴールおよびその隣接マスに爆弾が配置されないこと
- **スタート・ゴールの位置**：スタートとゴールが対辺に配置されること
- **難易度スケール**：ステージ番号に応じてフィールドサイズと爆弾数が変化すること
- **開始ステージの決定**（純粋な関数。入力はクエリ文字列と保存された文字列）：入力は `stage` パラメータの値（無いときは null）と保存された文字列（無いときは null）。パラメータ `5` → 5、`0`・`-3`・`abc`・空・null → 保存へ、`7x` → 7、`1e3` → 1、`0x10` → 0（保存へ）、`5.9` → 5、` 5` → 5、`101`・`100000`・桁数の多い数（`Infinity` になるもの）→ 100。保存 `7x` → 7、`NaN`・`-3`・空・null → 1、`5000` → 100。パラメータが有効なら保存より優先する
- **STAGE プロンプトの検証**（純粋な関数。丸めずに受理か拒否かを返す）：`100` → 100、`1` → 1、`5.9` → 5、`1e3` → 1、`101`・`0`・`-3`・`abc`・空 → 拒否（状態は変わらない）、キャンセル（null）→ 何もしない（メッセージなし）。拒否は、待っている次のステージの開始・RETRY / TITLE のボタン・`DeathDelay` を取り消さない（有効なジャンプだけが取り消す）
- **保存の失敗とハイスコア**：読み出しが例外を投げても既定値（ハイスコア 0・開始ステージ 1）になり、書き込みが例外を投げても例外が外へ出ない（死亡の流れが止まらない）。ハイスコアの読み方: `12` → 12、`12x` → 12、`0` → 0、`-3`・`abc`・空・null → 0。スコアがハイスコア（max(保存値, セッション最大)）より大きいときだけ書き、同じ・小さいときは書かない。書き込みが失敗した後に NEW GAME しても、`High` が下がらない（セッション最大が残る）。例外を投げる保存先を注入して確認する
- **キーの判定**：ゲームオーバー後のキーは、`repeat` が true のとき RETRY / NEW GAME / TITLE のきっかけにならない。`repeat` が false の `KeyR` は RETRY、`KeyT` は TITLE、他のキーは NEW GAME（修飾キー単独の `ShiftLeft` も NEW GAME）。判定は `KeyboardEvent.code` で、`KeyR`・`KeyT` は修飾キー（Shift・Ctrl・Alt・Meta）が付いていても、それぞれ RETRY・TITLE
- **ゲームオーバーのボタンの配置と当たり**（純粋な関数。手計算の値）：画面 1024x720 → RETRY の中心 (434, 518.4)、NEW GAME (590, 518.4)、TITLE (512, 578.4)。画面 390x844 → RETRY (117, 607.68)、NEW GAME (273, 607.68)、TITLE (195, 667.68)。離した位置の判定: TITLE の中心から x に ±70・y に ±22 ちょうどは TITLE、±71・±23 は TITLE ではない。RETRY・TITLE のどれの範囲にも入らない位置、NEW GAME の範囲の中は NEW GAME。ボタンの範囲は互いに重ならない（RETRY / NEW GAME の下端 = 0.72H + 22 < TITLE の上端 = 0.72H + 38）。画面の大きさを変えたときは、新しい大きさで同じ関数を呼んだ値になる（390x844 → 844x390 で RETRY (344, 280.8)・NEW GAME (500, 280.8)・TITLE (422, 340.8)。このとき TITLE の下端 340.8 + 22 = 362.8 < 390 で、画面に収まる）。置き直した後の離しは新しい配置で判定する（844x390 で (422, 340.8) の離しは TITLE、同じ位置が置き直し前の 390x844 の配置では TITLE の範囲の外）。置き直しの前後で、ボタンの大きさ（140 × 44）と互いの隙間は変わらない。回転後も 320 px 以上なら収まる（320x568 → 568x320 で TITLE の下端 = 0.72 × 320 + 60 + 22 = 312.4 < 320）。押し始めの規則: `DeathDelay` の間に押し始めた指は、`resize` の後に TITLE の上で離しても何もしない。ボタンが出た後に押し始めて `resize` をまたいだ指は、離した位置を新しい配置で判定する。`DeathDelay` の間の `resize` ではボタンは出ず、出るときの大きさで置かれる。STAGE のジャンプで取り消した後の `resize` で、ボタンは戻らない
- **HUD の文言とステータス行**（純粋な関数。入力は出来事の種類・開いたマスの数・旗の数・入力の種類・ステージ番号・`StageMax`、出力は文字列。手計算の値）：
  - 移動で開いたマス: `k = 1` → `You open 1 cell.`、`k = 2` → `You open 2 cells.`、`k = 0`（開示済みのマスへ）→ `You move.`
  - コード操作: `auto-opened` で `k = 3` → `You open 3 cells.`、`k = 0` → `Nothing to chord here.`、`auto-flagged` で `k = 1` → `You flag 1 mine.`、`k = 2` → `You flag 2 mines.`。`not-enough-info` → `You can't tell yet.`、`chord-not-available` → `Nothing to chord here.`、`flag-overflow` → `Too many flags around you.`
  - 盤面の外 → `There is a wall there.`。フラグ操作: 立てた → `You flag the cell.`、外した → `You unflag the cell.`、変わらなかった → `You can't flag there.`
  - ステージの開始: キー → `Move: arrows/QWEA-XZDC  Flag: Shift+dir  Chord: S`、タッチ → `You enter stage 7.`（`n = 7`）。死亡: キー → `You died. [R]etry [T]itle, any key: new game`、タッチ → `You died.`。ゴール → `You reach the goal.`。ジャンプ（`n = 12`）→ `You jump to stage 12.`。範囲外（`StageMax` = 100）→ `Stage must be 1-100.`。フラグモード → `Flag mode on.` / `Flag mode off.`
  - ステータス行: ステージ 5・ハイスコア 9 → `Stage:5  Score:4  High:9`、ステージ 1・ハイスコア 0 → `Stage:1  Score:0  High:0`、ステージ 100 → `Stage:100  Score:99  High:<h>`
  - 入力の種類: 初期値（タッチ対応の端末 → タッチ、そうでなければ キー）、キー押下 → キー、タッチの押し始め → タッチ、マウスの押し始め → キー。切り替えは、すでに決まった文言を変えない
  - 行の幅: 幅 390（コンパクト、STAGE ボタンの幅 82）→ `390 − 20 − 110 = 260`、幅 1280（STAGE ボタンの幅 90）→ `1280 − 20 − 118 = 1142`、幅 320（コンパクト）→ `320 − 20 − 110 = 190`
  - ステータス行の文字の大きさ（1 文字の幅 = 0.6 × 大きさ とした注入値で、整数 px・18 から 14 まで 1 刻み）: 幅 260 で `Stage:1  Score:0  High:0`（24 文字）→ 18 px（24 × 0.6 × 18 = 259.2 ≤ 260）。幅 260 で `Stage:100  Score:99  High:99`（28 文字）→ 15 px（18: 302.4、17: 285.6、16: 268.8 は超え、15: 252 ≤ 260）。幅 190 で同じ文 → 14 px でも 235.2 > 190 なので、14 px で、項目の区切りで折り返す
  - 優先と置き換え: 死亡かつゴールの入力 → 死亡の文言。ジャンプとステージの開始 → ジャンプの文言。同じ出来事が続けて起きても、回数を付けずに同じ文言のまま
  - コード操作の結果が dead（`bomb-without-flag`）→ 死亡の文言（入力の種類による 2 通り）
  - 開いたマスの数 `k` は、結果の `changedCellIndices` の長さ（移動では移動先のマス自身を含む。`auto-flagged` は旗を立てたマスの数）
- **帯の大きさ**（純粋な関数。入力は HUD の行ごとの下端の y と `HudBandPadding`、出力は帯の高さ。手計算の値）：行の下端が [25, 48]・`HudBandPadding` 6 → 54。[25, 48, 66]（凡例の行あり）→ 72。折り返しで [42, 66]（メッセージが 2 行）→ 72。行が無いとき（空の配列）→ 0（帯を出さない。`Game` ではメッセージ行が常にあるので起こらない）。入力の順番は問わない（最大の下端で決まる）。帯の高さは、最も下の行の下端が増えると、必ず増える。行の下端は `Text` の実測の高さから決める（QA は実測値で確かめる）
- **入力ロックと終了の流れ**（Scene から切り出した純粋な状態の遷移で確認する）：ゴール到達の後、`ClearDelay` の間の入力は無視され、次のステージの開始の要求は 1 回だけ。死亡の後は、パッドの押下の状態とリピートが解除される。`DeathDelay` の間の入力は無視される
- **ボタンの離し・タッチのキャンセル**：押し始めが FLAG / STAGE ボタンの上のポインターは、離したとき盤面のタップにならない。押し始めが死亡・ゴールの前だった、または `ClearDelay` の間だったポインターの離しは何もしない。`wasCanceled` のポインターは、仮想パッドの状態とリピートを破棄し、どの入力（コード操作・フリック・盤面のタップ・RETRY / NEW GAME / TITLE）にもならない（パッドを押し続けてキャンセルされた後に、リピートの移動が起きない）。`DeathDelay` の間に押し始めた指を TITLE の上で離しても、何もしない（ボタンが出てからの押し始めと離しの両方が要る）。TITLE の遷移は、保存された値（ハイスコア・開始ステージ）を書かない
