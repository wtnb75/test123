# ゲーム仕様書：地雷原ローグライク

## ゲーム名（仮称）

**Minefield Rogue**（地雷原ローグライク）

---

## コンセプト

マインスイーパーのフィールドを舞台にしたローグライクゲーム。
プレイヤーは数字のヒントを手がかりに爆弾の位置を**論理的に確定**しながら、スタートからゴールへ移動する。
爆弾の上を安全に通るには旗を立てる必要があるが、空白マスに誤って旗を立てて踏んでも即死する。
ステージはすべて**推理のみでクリア可能**（運や確率的推測が不要）なように生成され、ステージをクリアするたびに難易度が上がる。誤りは即死（パーマデス）。1 つのステージ（フロア）は、扉と通路でつながる `RoomCount`（5）個の部屋（スタートの部屋 A から枝分かれする木と、0〜2 本の輪）で、ゴール（下り階段 ▼）は、出口の無い部屋（葉）の 1 つにだけある。

---

## ターゲットプレイヤー

- マインスイーパーを知っているユーザー
- ローグライク・パズル系ゲームが好きなユーザー
- 論理推理・確実なクリアを好むプレイヤー（ギャンブル要素が嫌いな人にも向く）

---

## コアループ

1. ステージ開始：グリッドフィールドが表示される（爆弾位置は非表示）
2. 隣接数字ヒントを読み、爆弾マスを推理する
3. 移動前にフラグを立てるかどうか判断する
4. プレイヤーをスタートから、扉と通路を通って部屋から部屋へ渡り、ゴールへ 1 マスずつ移動させる（1 フロア = `RoomCount` 部屋の木と輪。[spec/rooms-and-floors.md](spec/rooms-and-floors.md)）
5. ゴール到達でステージクリア、次のステージへ
6. 誤った行動（爆弾を素踏み、非爆弾マスに旗を立てて踏む）で即死 → ゲームオーバー

---

## 操作仕様

| 操作 | 入力 |
|------|------|
| プレイヤー移動（8方向） | 矢印キー / テンキー 1〜9（5 を除く）/ QWEA + XZDC キー / hjklyubn キー / タップ（隣接8マスへ 1 マス移動） |
| 走る（開いたマスだけを 1 歩ずつ。壁・未開示マス・▼ の手前、扉のマス、▲・▼ の隣で止まる） | Shift + 移動キー（上の 8 方向の各キーに Shift を付ける） |
| 隣接マスにフラグを立てる / 外す | `f` を押したあと、移動キーの 1 つ（その方向の隣接マス）。Esc で取り消し |
| コード操作（自動展開/自動フラグ） | テンキー 5 / S キー（現在地に対して実行） |
| フィールドスクロール | マウスドラッグ / タッチスワイプ |

### 移動方向の詳細

8方向移動が可能。キー対応：

```
Q W E        7 8 9
A   D   /   4   6   （テンキー）
Z X C        1 2 3
```

`h` `j` `k` `l` `y` `u` `b` `n` は図に入れていない（下の「`hjklyubn`」と「移動キーの対応」のとおり）。

- `S` は移動キーではなく**コード操作**に割り当てる（下移動は `X`）
- `Shift + 同キー` で、その方向へ走る（下の「走る」）
- テンキー `5` / `S` キー：コード操作（後述）
- `hjklyubn`：`h` 左、`j` 下、`k` 上、`l` 右、`y` 左上、`u` 右上、`b` 左下、`n` 右下。キーの位置（`KeyboardEvent.code`）で判定する。AZERTY などの配列では、同じ位置のキーに別の文字が書かれている（文字ではなく位置で決まる）

### 走る（Shift + 移動キー）

- 押すと、その方向の隣のマスを見る。開いているマス（数字が見えている・空白）なら 1 歩進み、同じ方向の次のマスを見て、同じことを繰り返す
- 次のマスが、盤面の外・壁・未開示のマス・▼ のどれかなら、その手前で止まる（▼ には入らない。▼ へは、移動キーの通常の 1 歩で入る）。扉のマスは、未開示でも入ってよい（扉のマスと周囲 8 マスは爆弾禁止なので安全）。扉のマスに着いたら、そこで止まる。最初の隣が止まる条件に当たるなら、1 歩も動かない（盤面の外・壁なら `There is a wall there.`、未開示・▼ なら何も出さない。メッセージの文言は [spec/hud.md](spec/hud.md)）
- 着いたマスが、▲（上り階段）または下り階段の ▼ の隣（斜めを含む 8 マス）なら、そこで止まる。▼ は下り階段（`goalKind` が `down`・未指定）の部屋だけ判定する。▲ は、上り階段（フロアの入り口の階段）だけを判定する。入口の扉（スタートが扉の部屋）は扉として止まり、その隣では止まらない。扉は、入口でも出口でも同じ（扉のマスに着いたら止まる）。▲ や ▼ そのものへは、走りでは入らない。ただし、走りが 1 歩も進めない位置（▼ の隣など）で、▼ の方向へ Shift + 移動キーを押したときは、▼ へ通常の 1 歩で入る（Shift + 移動キーは、どこで押しても少なくとも 1 歩進む。未開示・盤面の外・壁への 1 歩は除く）
- 走りの各歩のメッセージは、通常の移動と同じ（扉のマスに入れば、そのマスを開いた結果の文言になる）。止まったときは最後の 1 歩の文言が残る
- 扉のマスに立っているときの Shift + 扉の外向きの移動は、通常の 1 歩と同じ（通路へ入る。走りではない）
- 1 歩目は押した瞬間に進む。2 歩目以降は、その 1 歩目から `RunStepMs`（100 ms）ごとに、`Game` の時間で進む。タブが見えない間（ページが隠れている間）は走りを止める
- 開いたマスには爆弾も旗も無いので、走っても即死しない。上り階段（▲）の隣で止まる（上の「走る」）
- カメラは、既存の追従の規則のまま（1 歩ごとに追う）
- 走っている間の新しい押下（キー・タップ・仮想パッドの押し始め・FLAG・移動キー・旗・コード操作・R・T を含む）は、走りを止める。止めた押下は、止まったあとに実行しない。`repeat` の押下（長押しの自動リピート）と、Shift を離したことは、走りを止めない（走りは最初の押下で決まり、続く）。`STAGE`（dev）は常に受け付けるので、走りを止めてジャンプする。M キーと MAP ボタンは、走りか旗の待ちを止めたうえで、全体図を出す（止めた押下は実行しない、の例外）。旗の待ちの間の押下（盤面のタップ・FLAG・パッドを含む）は、待ちを取り消し、その押下は実行しない
- 走りは、通路の自動移動（扉を通ったあとの歩き）の間は始まらない。M キーと MAP ボタンで全体図を出すと、走りは止まる（全体図の表示は通常どおり）
- 死亡・ゴール・`ClearDelay`・`DeathDelay`・ゲームオーバーの画面の間は走らない（その間は入力を受け付けない）
- `f` の待ちの間（下の「フラグ操作の詳細」）に押された Shift + 移動キーは、待ちを取り消して走る（旗は変えない）

### フラグ操作の詳細

- フラグは**隣接マス**に立てる（現在地ではなく、移動先候補のマスを事前にマーク）
- `f` を押すと「旗の待ち」になる。待ちの間の次の押下が移動キー（8 方向・Shift なし）なら、その方向の隣接マスの旗を切り替えて、待ちを終える（1 回の押下につき 1 回だけ）。待ちの間の Esc、移動キー以外のキー、盤面のタップ、Shift + 移動キー（走る。上の「走る」）は、待ちを取り消す（旗は変えない。Shift + 移動キーは走る）。待ちは 1 回だけで、続けて旗を立てるには `f` をもう一度押す
- 旗の待ちは FLAG ボタンのモード（上の「タッチ操作」）とは別。FLAG が ON でも `f` は待ちになり、FLAG の状態は変えない
- 旗の待ちでは、メッセージ行に `Flag: pick a direction (Esc cancels)` を出す（[spec/hud.md](spec/hud.md)）
- フラグ操作と移動操作は独立。フラグを立てた後に必ずそこへ移動する義務はない
- フラグを立て直し（誤り訂正）は同じ操作を繰り返すことで解除できる

### タッチ操作

- 盤面のタップ:
  - プレイヤーに隣接する 8 マスのタップは、そのマスへ 1 マス移動する（開いているマスでも未開示のマスでも。自分のマスのタップは、コード操作。下の「タッチ操作」）
  - 隣接しない開いたマスのタップは、そのマスまで歩く（下の「タップで歩く」）。隣接しない未開示のマスのタップは何も起こさない
  - 扉のマスに立っているときは、その扉の「+」（壁の切れ目）をタップすると、扉の外へ 1 歩通る（[spec/rooms-and-floors.md](spec/rooms-and-floors.md)「扉を通る」）
- タップで歩く: 目的のマスまで、開いたマスだけを通る最短経路（8 方向）を、1 歩ずつ歩く。経路は、歩数が最短のものの中から、向きの変わり目が少ないものを選ぶ。各歩は、次の順で候補を選ぶ（上ほど優先）: (1) 目的を追い越す向きには動かない（未開示・壁を避けるために必要なときを除く）、(2) 直前と同じ向きを続ける、(3) 斜め（目的の両方の軸がまだ残っている）、(4) まっすぐ。1 歩目は押した瞬間に進み、2 歩目以降は `RunStepMs` ごと（`Game` の時間）。経路は、未開示のマス・壁・▼ を通らない（扉のマス・▲ は通ってよく、そこで止まらない）。目的地に着くまで、途中の扉・▲・▼ の隣では止まらない。経路がないとき（開いたマスだけでは届かないとき）は何も起こさない。目的地が ▼ のときは、経路のうち ▼ の隣になる最初のマスで止まる（▼ へは、そこからの隣のタップで入る）
- 歩いている間の新しい入力（タップ・キー・仮想パッド・FLAG・M・MAP・R・T）は、歩くのを止め、その入力は実行しない（走りと同じ）。`repeat` の押下と Shift を離したことは止めない。ページが隠れると止まる。M キーと MAP ボタンは、止めたうえで全体図を出す
- 仮想パッド（左下のジョイスティック）: 押している間、土台の中心から 14 px 以上離れた位置にあると、その方向（8 方向）が決まり、最初は 380 ms 後、以降 180 ms ごとに 1 マス動く（リピート。FLAG が ON ならフラグ操作）。リピートが一度も起きずに離したときは、押し始めの位置との距離が 14 px 未満ならコード操作、14 px 以上ならその方向へ 1 マス（フリック。フリックの方向は、押し始めの位置から離した位置への向きで決める。リピートの方向は、土台の中心から見た向き）
- 「FLAG」ボタン（右下）は、フラグモードの ON / OFF を切り替える。ON のとき、パッドのフリックは移動の代わりに、その方向の隣接マスのフラグ操作になる（同じマスにもう一度行うと解除のトグル）
- 長押しでフラグ（隣接 8 マスの未開示のマス）: 未開示の隣のマスを押し始め、`LongPressMs` を過ぎても押し続けていたら、そのマスのフラグを切り替える（時間が来た瞬間に 1 回。離しても何もしない）。`LongPressMs` より前に離したら、通常のタップ（1 歩。未開示でも踏む）。長押し中に、押し始めの位置から `スクロールの判定距離` 以上動いたら、長押しを取り消してスクロールにする（フラグは変えない）。隣の開いたマスの長押しは、フラグも 1 歩も起こさない（離しても何もしない）。隣接しないマスの長押しも、離しても何もしない（歩かない）
- 自分のマスのタップ（短い・長いのどちらでも、離したとき 1 回）: コード操作（S キーと同じ。パッドのタップと同じ結果）
- 隠す設定: Title の「パッド」ボタン（[spec/title.md](spec/title.md)）で、仮想パッドと FLAG ボタンを隠せる。隠すと、仮想パッドと FLAG ボタンを描かず、その位置での押し始めは盤面の押し始めとして扱う（パッドにも FLAG にもならない）。隠しても、長押しでのフラグと、タップ・キーの操作はそのまま使える（FLAG モードだけは使えない）。MAP ボタンは隠しても位置を変えない。設定は、閲覧者のブラウザに保存し、次に開いたときも同じ（保存の失敗は既定の「表示」として扱う）
- 押し始めが「FLAG」「STAGE」ボタンの上だった指は、離したときに盤面のタップとして扱わない（マスへ動かない）。システムによって中止された（cancel）タッチは、そのポインターの仮想パッドの状態・リピート・ドラッグ・押し始めの記録を破棄し、何も実行しない（コード操作・フリック・盤面のタップ・墓石画面への遷移・RETRY / NEW GAME / TITLE のどれにもならない。ジョイスティックのつまみは中央に戻る）。離しは、**押し始めが受け付けられた入力**に対してだけ働く（死亡・ゴールの前から押していた指、`ClearDelay` の間に押し始めた指、ボタンの上で押し始めた指は、離したとき何もしない。ゲームオーバーの画面の RETRY / NEW GAME / TITLE は、ボタンが出てからの押し始めと離しの両方が要り、離した位置で決める（押し始めの位置は問わない）。ゲームオーバーの画面では、STAGE 以外の場所での押し始め（仮想パッド・FLAG・盤面を含む）も、そのまま離した位置で判定する）

### 開始ステージの決め方

`Game` を作るとき（`Title` の Start、NEW GAME）、フラグモードは OFF から始まり（直前の `Game` の状態は持ち越さない）、開始ステージを次のとおり決める。数値の読み方は、すべて基数 10 の `parseInt(s, 10)`（先頭の空白と符号を許し、`0x` は 16 進と読まない）で、結果が整数のときだけ有効とする（桁数の多い数が `Infinity` になるときも、整数として扱い `StageMax` に収める。ハイスコアだけは有限の整数のみを有効とし、`Infinity` は無いものとして扱う）。

「保存された開始ステージ」（`minefield-rogue-start-stage`）は、**dev だけ**で読み書きする開発用の値である（dev = 「STAGE」ボタンが出る `import.meta.env.DEV` が真のとき。[画面・Scene 構成](#game-のui要素)）。本番ビルドでは、保存された開始ステージを読まず・書かない（以前の保存で残っている値も使わない）。
- **ページを開いて最初の `Game`**（`Title` の最初の Start。ページを開いてから、まだ `Game` を作っていないとき）: (1) URL の `?stage=` の先頭の整数部分（`parseInt`）が 1 以上なら、それ（`StageMax`（100）を超える値は 100）。(2) そうでなければ、dev だけ、保存された開始ステージの先頭の整数部分が 1 以上なら、それ（`StageMax` を超える値は 100）。(3) そうでなければ 1。
- **2 つ目以降の `Game`**（NEW GAME、`Title` へ戻ったあとの Start。`?stage=` は見ない）: 本番は、つねにステージ 1。dev は、保存された開始ステージが 1 以上ならそれ（`StageMax` を超える値は 100）、なければ 1。URL に `?stage=` が付いていても、本番の NEW GAME はステージ 1 から始まる（`?stage=` は、そのページを開いて最初に始めるゲームにだけ効く）。

保存された開始ステージの書き込み（dev だけ）は、最初の `Game` で `?stage=` が有効だったときに、最初のステージの生成と描画が済んだ**あと**に、`StageMax` に収めた値で更新する（保存値・既定値から始まったときは書かない。起動できなくなっても、保存は残らない）。保存された値が `StageMax` を超えていても、読むときに `StageMax` に収める（次に保存するまで書き換えない）。「STAGE」ボタン（dev だけ）の入力は、1〜`StageMax` の整数だけが有効で、そのステージへ移った後に保存する（範囲外・0・負・数値でない・空は、メッセージを出して何も変えず、丸めない。キャンセルはメッセージも出さず何も変えない。メッセージとプロンプトの範囲の数字は `StageMax` と一致させる。プロンプトの初期値は現在のステージ番号で、`StageMax` を超えるときは `StageMax` にする）。

### コード操作（S / テンキー5）

マインスイーパーのコード（和音）操作に相当する便利機能。現在地のマス（数字が確定済み）に対して：

- 周囲8マスのうち、論理的に**爆弾と確定しているマス**に自動でフラグを立てる
- または、フラグを立て終えた状態で再度実行すると**安全マスを自動で踏んで開く**
- 誤ったフラグ状態でコードを実行すると即死の可能性があるため、プレイヤーの責任で使用する
- 現在地が**旗マス**の場合は、その旗の周囲8マスのうち、周辺の開示済み数字から**安全と確定しているマスのみ**を自動で開く

#### コード操作の実行条件（厳密定義）

- 現在地マスが開示済みかつ数字 `n > 0` のときのみ実行可能
- 周囲8マスのフラグ数を `f` とする
- `f < n` の場合：未確定マスに自動フラグを試みる（確定できる場合のみ）
- `f = n` の場合：未フラグの隣接マスを自動開示する
- `f > n` の場合：入力エラー扱いとして何もしない（警告表示のみ）
- 現在地が旗マスの場合：周辺の開示済み数字マスについて「その数字 = 周囲フラグ数」が成立しているとき、その数字に隣接する未フラグ・未開示マスを安全確定として開く

### フラグと移動のルール

- **爆弾マスにフラグあり → 踏んでも安全（通過できる）**
- **爆弾マスにフラグなし → 踏んだら即死**
- **非爆弾マスにフラグあり → 踏んだら即死**
- **非爆弾マスにフラグなし → 踏んでも安全（通過できる）**

### 数字ヒントの隣接定義

マインスイーパーと同様に **8方向（斜め含む）** の隣接マスを対象として数字ヒントを計算する。

### 数字ヒントの開示とゼロ自動展開

- 初期状態で表示される数字は、**スタート地点を起点とした開示領域のみ**とする（フィールド全体の数字は表示しない）
- ヒントが **0 のマス**（隣接爆弾なし）を開いたとき、周囲8マスを自動的に連鎖開示する（0 が隣接する限り再帰的に開く）
- 連鎖開示で開いた領域の境界にある数字マスのみ表示される
- スタート地点が 0 の場合、初期状態でその連鎖開示結果が反映される

## 画面・Scene 構成

| Scene 名 | 役割 |
|----------|------|
| `Title` | タイトル画面（ゲーム名・ボットのデモ・Start）。詳細は [spec/title.md](spec/title.md)、デモは [spec/title-demo.md](spec/title-demo.md) |
| `Game` | メインゲームプレイ（フィールド表示・移動・判定）。ステージクリアとゲームオーバー（Retry / New Game / Title）も `Game` の中で表示する |

アセットは使わない（描画は Phaser の図形とテキストだけ）ので、読み込み用の Scene は無い。

- 盤面の大きさ（`Game` の 1 マス `cell`。30〜52 px）と画面上の位置（収まる部屋は、HUD・パッド・ボタンを除いた遊べる領域の中央）は、[spec/board-render.md](spec/board-render.md)「盤面の大きさと位置」で決まる。
- グリッドフィールド（数字ヒント付き）、プレイヤーキャラクター、スタート（上り階段 ▲）とゴール（下り階段 ▼）のマス（マスの中に描く。盤面の外の帯のマーカーは無い。[spec/board-render.md](spec/board-render.md)「マスの見た目」）。ゴールが画面の外にあるときは、画面の端に「GOAL <方向の矢印>」（▼ の無い部屋では、画面外の扉（入口・出口・輪）に「DOOR <方向の矢印>」。扉・通路は [spec/rooms-and-floors.md](spec/rooms-and-floors.md)）
- 上部の HUD（ローグ風）: 上から「メッセージ行」（直前の出来事を 1 文で）、その下に「ステータス行」`Stage:<n>  Score:<ステージ番号 − 1>  High:<ハイスコア>`。ゲームオーバーの間だけ、その下に色の凡例の行が出る。詳細は下の「HUD のメッセージとステータス」
- 仮想パッド（画面の左下のジョイスティック。8 方向）、右下の「FLAG」ボタン（その真上に全体図の「MAP」ボタン。[spec/floor-map.md](spec/floor-map.md)。FLAG はフラグモードの切り替え。ON のとき、仮想パッドの方向の入力は移動ではなくフラグの操作になる）、右上の「STAGE」ボタン（開始ステージの番号を 1〜`StageMax` で入力して、そのステージへ移る。範囲外・数値でない入力・キャンセルは何も変えない。**dev サーバー（`import.meta.env.DEV` が真のとき）だけに出す開発用のボタン**で、本番ビルド（公開版）には、ボタン・当たり判定・入力のダイアログを作らない。本番ビルドでは、この spec（リンク先のファイルを含む）の「STAGE」ボタン・ジャンプ・`You jump to…` / `Stage must be…` のメッセージ・押し始めの記述、および「STAGE だけは入力を受け付ける」という例外は存在しない（`DeathDelay`・`ClearDelay` の間は、すべての入力を受け付けない）。QA の「STAGE」の項目は、dev でだけ行う。「本番」は、単体ビルド（`npm run build`）と共有ビルド（`SHARED_VENDOR=1`）の両方。`npm run dev` と `share.sh` が起動するサーバーは dev。URL の `?stage=` は本番でも使える（ページを開いて最初の `Game` だけ。「開始ステージの決め方」）。保存された開始ステージは dev だけで読み書きする）
- 仮想パッドと FLAG の見た目（入力の判定・数値は変えない）:
  - **FLAG**: OFF は、暗い青の塗り・緑の細い枠（`FlagOffStrokeWidth`）・ラベル `FLAG`。ON は、明るい緑のべた塗り（不透明）・太い枠（`FlagOnStrokeWidth`）・ラベル `FLAG` / `ON`（2 行。べた塗りの上で読める暗い色の文字）。枠は塗り（円）の内側に描き、塗りの大きさ・位置・当たり判定は ON / OFF で変えない（外形は変わらない）。コンパクト（円 44 px）でも、2 行のラベルは 11 px 以上で、枠の内側に収める。
  - **パッドの色**: FLAG が OFF の間、土台の枠とつまみは青、FLAG が ON の間は緑。切り替えたフレームから変わる（押している最中でも）。
  - **方向の扇形**: パッドを押している間、土台の中心からの距離が `JoystickTapThreshold`（14 px）以上のとき、リピートの方向（8 方向。向きの決め方はリピートと同じ: 土台の中心から見た角度を 45° 刻みに丸める）の 45° の扇形（頂点 = 土台の中心、半径 = 土台の半径（52 px、コンパクトは 41 px）、角度の範囲 = その方向 ±22.5°）を、土台とつまみの手前に光らせる（つまみの上に半透明に重なる。つまみは押している位置にあり、扇形の大半を隠してしまうため）。距離と方向は、土台の中心から、押している位置までで測る。角度は [0°, 360°) に直してから 45° 刻みに丸める（`Math.round(角度 / 45) % 8`。リピートの方向の決め方と同じ。同点は上に丸まる: 22.5° → 1、337.5°（= −22.5°）→ 0、67.5° → 2、292.5°（= −67.5°）→ 7）。最初のリピートが起きるまでの間は薄く（不透明度 `PadSectorAlphaCharge`）、最初のリピートが起きたフレームから濃く（`PadSectorAlphaRepeat`）。「最初のリピートが起きた」は、リピートの tick が発火したこと（盤面の外・壁・フラグ不可で何も起きなくても同じ）。リピートの計時（押し始めから 380 ms 後の最初の tick、以降 180 ms ごと）・方向が変わったとき・14 px 未満からの復帰は、すべて既存のリピートの規則のままで、扇形はそれを見て表示するだけである（計時は変えない）。濃さは、「この押している間に、tick が 1 度でも発火したか」で決まる。色はパッドの色と同じ（FLAG OFF が青、ON が緑）。離す・14 px 未満に戻る・死亡・ゴール・STAGE のジャンプ（dev）・キャンセルで消える。方向が変わったら、その方向の扇形に替わり、濃さは「最初のリピートが起きたか」（その押している間の状態）で決める。入力の判定・リピートの間隔は変えない。層は、土台・つまみの手前（FLAG・HUD・盤面の層との前後は変えない）。
- ゲームオーバーの表示（全爆弾の開示・色分け、RETRY / NEW GAME / TITLE のボタンと入力、`DeathDelay`）は、[spec/game-over.md](spec/game-over.md) に書く。
- ステージクリア（ゴール到達）では、メッセージを出して `ClearDelay` 後に次のステージへ進む。ゴールに着いたとき、仮想パッドの押下の状態とリピートも解除する（押し直すまで動かない）。`ClearDelay` の間は入力（キー・盤面のタップ・仮想パッド・FLAG・ドラッグのスクロール）を受け付けず、次のステージの開始は 1 回だけである（ステージが飛ばず、クリア済みのステージで死なない）。「STAGE」ボタンだけは、`DeathDelay`・ゲームオーバーの画面・`ClearDelay` の間も受け付け、ジャンプしたときは、待っている次のステージの開始・RETRY / NEW GAME / TITLE のボタン・`DeathDelay` を取り消し、仮想パッドの押下の状態・リピート・ドラッグ・押し始めの記録も破棄する（死亡・ゴールと同じ。ジャンプ前から押していた指の離しは何もしない）
- スコアは「ステージ番号 − 1」（開始ステージが 1 より大きいときは、それより前のステージも数える）。死んだとき、ハイスコアを超えていれば保存する

## ルール

### 生存条件

- 爆弾マスを踏む前に正しくフラグを立てていること
- 非爆弾マスにはフラグを立てずに踏むこと

### 死亡条件（即死・ゲームオーバー）

- 爆弾マスをフラグなしで踏んだ
- 非爆弾マスにフラグを立てた状態で踏んだ

### クリア条件

- ゴールマスに到達する

### ステージ進行

- クリアごとにステージ番号（= フロア番号）が増加。1 フロアは `RoomCount`（5）個の部屋の木と 0〜2 本の輪で、ゴールは葉の 1 つの ▼（[spec/rooms-and-floors.md](spec/rooms-and-floors.md)）
- ステージ番号に応じてフィールド（1 部屋）のサイズと爆弾密度が増加。部屋 A から木で 2 段以上離れた部屋（奥の部屋。`RoomCount` = 5 では 2 つ）だけは、基準より少し難しい（大きさ +1 マス・推理の深さの目標 +1。「パラメータ表」。段の数え方は [spec/rooms-and-floors.md](spec/rooms-and-floors.md)）
- パーマデス：死亡するとゲームオーバー。RETRY は死んだステージをやり直し、NEW GAME はステージ 1 から（dev では、保存された開始ステージがあればそこから）新しいゲームを始め、TITLE は `Title` へ戻る

### 論理的解決可能性の保証

ステージ生成の規則（論理的解決可能性の保証、難易度の深さ設計、リトライ上限と難易度フォールバック、生成停止条件）は、[ステージの生成](spec/generation.md) に書く。

### スコア

- スコア（ステージ番号 − 1）の最大値をハイスコアとして記録する
- 1 ステージ内でのフラグ設置数・移動ステップ数はボーナス計算の候補（MVP外）

## 技術要件

- **ゲームエンジン**: Phaser 4 (TypeScript)
- **ビルド**: Vite
- **テスト**: Vitest（カバレッジ 90% 以上）
- **Lint**: ESLint（エラー 0 件）
- ゲームロジック（爆弾配置・数字ヒント計算・判定・論理解決可能性検証）はPhaserに依存しない純粋な関数として実装し、単体テストを書きやすくする
- HUD の文言（出来事・開いたマスの数・入力の種類から文字列を決める）とステータス行の文字列は、Phaser に依存しない純粋な関数（`core/` の下）にし、`Game` は結果を `Text` に渡すだけにする。入力の種類の切り替え規則（初期値・キー・タッチ・マウス）も純粋な関数にする。HUD の帯の高さ（行の下端から決める）も純粋な関数にする
- `Title` の開始の門は、共有パッケージ `title-demo`（`shared/title-demo`。ワークスペースの依存 `workspace:*`）の `StartGate` を使い、デモの進行は同じパッケージの `DemoDirector` を使う（ボットの手順は `core/solver.ts` の `analyzeCurrentState` を使う純粋な関数。[spec/title-demo.md](spec/title-demo.md)）。開始キーの判定と配置の計算は、`Game` と同じく Phaser 非依存の純粋な関数にする（詳細は [spec/title.md](spec/title.md)）
- `Game` Scene はロジック層を呼び出す描画・入力レイヤーとして分離する
- 論理解決可能性の検証（制約伝播）はフィールド生成ロジックの一部として実装する
- フィールドサイズが画面を超える場合はカメラスクロール（Phaser のカメラ機能またはコンテナオフセット）で対応する
- ハイスコアは `localStorage` に保存する
- 保存（ハイスコア・開始ステージ）の読み書きに失敗しても（ブロック・容量超過など）、ゲームは止まらない。読めなければ既定の値（ハイスコア 0・開始ステージ 1）、書けなければ保存しない。数値の読み方は、開始ステージもハイスコアも、先頭の整数部分（`parseInt`）が 0 以上（開始ステージは 1 以上）ならその値、そうでなければ無いものとして扱う（HUD の `High:` が `NaN` にならない）。ハイスコアの書き込みが失敗しても、死亡の表示・全爆弾の開示・RETRY / NEW GAME は通常どおり出す。ハイスコアは、max(読めた保存値, セッション最大) とする。セッション最大は、ページを開いてから、死亡時に確定したスコアの最大（生存中の現在のスコアは含めない）で、`Game` Scene の外に持ち、NEW GAME・RETRY・TITLE で消えない。HUD の `High` はこのハイスコアで、書き込みは「スコア > ハイスコア」のときだけ行う。ハイスコアは、有限の整数だけを有効とする（`Infinity` は無いものとして扱う）

### 難易度メトリクス（内部記録）

- 各ステージで以下を記録し、バランス調整に利用する
- `solverDepth`（最終的に必要だった推理深さ）
- `inferenceSteps`（確定推論ステップ数）
- `generationRetries`（生成リトライ回数）・`generationMs`（生成時間）。部屋ごとに記録する

### フィールドスケール

式は「パラメータ表」。例: ステージ 1 は 8×8・爆弾 9・深さ 1、ステージ 3 は 10×10・爆弾 16・深さ 2、ステージ 10 は 17×17・爆弾 44・深さ 4。奥の部屋は、ステージ 1 で 9×9・爆弾 11・深さ 2、ステージ 10 で 18×18・爆弾 49・深さ 5（部屋 A・B・C は、▼ の部屋でも基準のまま）。

- グリッドサイズに上限は設けない（スクロール対応のため）
- 爆弾密度・深さ目標・生成の上限は「パラメータ表」を参照。数値は実装後のプレイテストで調整する

スタート（フロアに降りてきた位置。上り階段 ▲。ゲーム開始時も階段から降りてきた扱い）とゴール（下り階段 ▼）は、フィールドの**内側のマス**（端から `StairsMargin` マス以上内側。扉は部屋の端、階段は端ではない）にランダム配置する（生成の試行ごとに、スタート、ゴールの順で決め、その後に爆弾を置く）。スタート: 内側のマスから一様な乱数で選ぶ。ゴール: 内側のマスのうち、スタートとのチェビシェフ距離（max(|Δx|, |Δy|)）が `ceil((min(幅, 高さ) − 3) × StairsMinDistanceRatio)` 以上のマスから、一様な乱数で選ぶ。無いときは、内側の 4 つの隅のうち、スタートから最も遠いもの（同じなら、上、左の順）。

スタートとゴールは爆弾禁止。また両者の隣接マスも爆弾禁止（最初・最後の推理に必要なヒントを確保）。最小のフィールドは 8×8（ステージ 1）なので、この制約は緩めない。ここに書いたスタートとゴールの配置は部屋 A の ▲ と ▼ の部屋の ▼ のそれぞれの規則の基になるもので、扉の配置と、部屋の木は [spec/rooms-and-floors.md](spec/rooms-and-floors.md) に書く（▲ と扉 A1・A2、入口・出口の扉と ▼ の組）。

## パラメータ表

ステージ番号を n とする。値はいまの実装の初期値で、バランス調整（`game-balance`）で変わる。

| 名前 | 初期値 | 意味 |
|---|---|---|
| グリッドの幅・高さ | 7 + n（奥の部屋は 8 + n） | 正方形。上限なし。奥の部屋だけ +1 |
| 爆弾密度 | min(0.18, 0.14 + 0.001 × n) | 面積に掛けて爆弾数の下限にする（奥の部屋も同じ密度。上乗せしない） |
| 爆弾数 | max(6, 4 + 4n, round(面積 × 爆弾密度)) | ステージ n の爆弾の数。奥の部屋は面積が大きいぶん増える（式は同じ。`4 + 4n` と密度はステージ n のまま） |
| 推理深さ目標（初期値） | min(5, floor(1 + n / 3))（奥の部屋は min(5, floor(1 + n / 3) + 1)） | 生成時に目指す、推理に必要な最小の伝播深さ。奥の部屋だけ +1（ステージ 12 以上は、基準がすでに 5 なので同じ） |
| 生成のリトライ上限 | 1000 回 | 超えたら、得られた中で深さが最大の候補を使う（解決可能とは限らない） |
| 生成の時間上限 | 1500 ms | 超えたら、その時点の最良候補で打ち切る |
| 深さ目標の引き下げ | 250 リトライごとに 1（下限 1） | 目標に届かないときのフォールバック。深さ目標が 1 のときは、同じ間隔で爆弾数を 1 ずつ減らす（下限 1） |
| 候補が 1 件も無いときの代替 | ステージ max(1, n − 1) のパラメータ・深さ 1 | 同じステージ番号として使う |
| `StageMax` | 100 | 開始ステージの上限（「STAGE」ボタン・`?stage=`・保存された値で共通。下限は 1）。ステージ 100 は 107×107（約 1.1 万マス）で生成に約 1.7 秒。それ以上は生成と描画が重く、起動が固まるため |
| `StairsMargin`・`StairsMinDistanceRatio` | 1 マス・0.9 | スタート（▲）とゴール（▼）を置ける内側（端からの最小距離）と、ゴールをスタートから離す割合（▼ の部屋の ▼ は扉のマスから、部屋 A の扉 A1・A2 は ▲ から、同じ式で離す。[spec/rooms-and-floors.md](spec/rooms-and-floors.md)）（最小の距離 = `ceil((min(幅, 高さ) − 3) × 比)`）。使い捨ての計測（生成 1 回あたりの中央値、ステージ 1 / 5 / 10 / 20 / 30）: 距離は 5 / 8 / 12 / 20 / 27 マス（端に置いていた変更前は 7 / 11 / 16 / 26 / 36）、最初に開いているマスは 29 / 31 / 55 / 54 / 49（変更前は 21 / 23 / 30 / 19 / 30） |
| `CELL_SIZE`（基準のマス `REFERENCE_CELL`） | 30 px | 基準の 1 マスの大きさ（描画は 1 マスあたり 28 px の四角）。`Game` の実際の 1 マス `cell` は、画面とステージで 30〜52 px になる（`CellMin`・`CellComfort`。[spec/board-render.md](spec/board-render.md)「盤面の大きさと位置」）。寸法は `cell / 30` 倍 |
| 盤面の原点 | (20, 80) px | フロア全体（すべての部屋と通路）の外接する長方形の左上のマスの位置。部屋 A がその左上でないフロアでは、部屋 A の盤面は (20, 80) からずれる（[spec/rooms-and-floors.md](spec/rooms-and-floors.md)「フロアの座標」）。この表と他の spec の「盤面の位置（y = 80）」は、この意味 |
| カメラの追従マージン | 4 マス | プレイヤーが画面の端からこの近さになったらカメラが追う |
| スクロールの判定距離 | 8 px | 未満はタップ、以上はスクロール（長押し中の動きにも同じ） |
| `LongPressMs` | 400 ms | 隣の未開示マスの長押しでフラグを切り替えるまでの時間。これより前に離したら通常のタップ（1 歩）。短すぎると歩くつもりのタップが誤ってフラグになる |

- **開始ステージの決定**（純粋な関数。入力はクエリ文字列・保存された文字列・「最初の `Game` か」「保存値を使うか（dev か）」）：入力は `stage` パラメータの値（無いときは null）と保存された文字列（無いときは null）。最初の `Game` で保存値を使う（dev）とき: パラメータ `5` → 5、`0`・`-3`・`abc`・空・null → 保存へ、`7x` → 7、`1e3` → 1、`0x10` → 0（保存へ）、`5.9` → 5、` 5` → 5、`101`・`100000`・桁数の多い数（`Infinity` になるもの）→ 100。保存 `7x` → 7、`NaN`・`-3`・空・null → 1、`5000` → 100。パラメータが有効なら保存より優先する。最初の `Game` で保存値を使わない（本番）: パラメータ `5` → 5、無い・無効 → 1（保存 `7` があっても 1）。2 つ目以降の `Game`: 本番は、パラメータ `5`・保存 `7` のどちらがあっても 1。dev は、パラメータを見ず、保存 `7` → 7、保存 `5000` → 100、保存なし・`NaN`・`-3` → 1。保存へ書くのは、dev で、最初の `Game` に有効な `?stage=` が付いていたときだけ（本番は書かない）
- **STAGE プロンプトの検証**（純粋な関数。丸めずに受理か拒否かを返す）：`100` → 100、`1` → 1、`5.9` → 5、`1e3` → 1、`101`・`0`・`-3`・`abc`・空 → 拒否（状態は変わらない）、キャンセル（null）→ 何もしない（メッセージなし）。拒否は、待っている次のステージの開始・RETRY / TITLE のボタン・`DeathDelay` を取り消さない（有効なジャンプだけが取り消す）
- **パッドの方向の扇形**（純粋な関数。手計算。入力は、土台の中心からの移動量 (dx, dy)（画面の座標。下が +y）と「最初のリピートが起きたか」、出力は扇形の番号（0〜7。0 = 右（E）、1 = 右下、2 = 下、3 = 左下、4 = 左、5 = 左上、6 = 上、7 = 右上）と不透明度）：距離が 13.9 px → 扇形なし（距離 14 px ちょうどは扇形あり）。(20, 0) → 0、(14, 14) → 1、(0, 20) → 2、(−20, 0) → 4、(0, −20) → 6、(14, −14) → 7。境界: 角度 22.4° → 0、22.5° ちょうど → 1（四捨五入）。不透明度: 最初のリピートの前 → 0.35、リピートが起きた後 → 0.7（方向が変わっても、押している間はリピートが起きた状態のまま。壁へのリピートでも濃くなる）。離すと扇形なし。角度（度）を直接受ける関数でも境界を確かめる: 22.5° → 1、337.5° → 0、67.5° → 2、292.5° → 7、112.5° → 3、247.5°（= −112.5°）→ 6、157.5° → 4、202.5°（= −157.5°）→ 5。消える場面（押したままでも）: 離す・14 px 未満・リピートで死んだ同じフレーム・ゴール・キャンセル・RETRY / NEW GAME / TITLE・次のステージの開始・dev の STAGE のジャンプ・`dying` / `gameover` / `grave` / `ClearDelay` の間（その間に押し始めた指では出ない）。色: FLAG OFF → 青、ON → 緑（FLAG を切り替えたら扇形・土台の枠・つまみの色が同じフレームで変わる）。FLAG の見た目: ON / OFF で、位置・大きさ・当たり判定が変わらない。枠の太さは ON 4 px・OFF 2 px。ラベルは ON が `FLAG` / `ON`、OFF が `FLAG`。

- **保存の失敗とハイスコア**：読み出しが例外を投げても既定値（ハイスコア 0・開始ステージ 1）になり、書き込みが例外を投げても例外が外へ出ない（死亡の流れが止まらない）。ハイスコアの読み方: `12` → 12、`12x` → 12、`0` → 0、`-3`・`abc`・空・null → 0。スコアがハイスコア（max(保存値, セッション最大)）より大きいときだけ書き、同じ・小さいときは書かない。書き込みが失敗した後に NEW GAME しても、`High` が下がらない（セッション最大が残る）。例外を投げる保存先を注入して確認する
- **入力ロックと終了の流れ**（Scene から切り出した純粋な状態の遷移で確認する）：ゴール到達の後、`ClearDelay` の間の入力は無視され、次のステージの開始の要求は 1 回だけ。死亡の後は、パッドの押下の状態とリピートが解除される。`DeathDelay` の間の入力は無視される
- **ボタンの離し・タッチのキャンセル**：押し始めが FLAG / STAGE ボタンの上のポインターは、離したとき盤面のタップにならない。押し始めが死亡・ゴールの前だった、または `ClearDelay` の間だったポインターの離しは何もしない。`wasCanceled` のポインターは、仮想パッドの状態とリピートを破棄し、どの入力（コード操作・フリック・盤面のタップ・墓石画面への遷移・RETRY / NEW GAME / TITLE）にもならない（パッドを押し続けてキャンセルされた後に、リピートの移動が起きない）。`DeathDelay` の間に押し始めた指を TITLE の上で離しても、何もしない（ボタンが出てからの押し始めと離しの両方が要る）。TITLE の遷移は、保存された値（ハイスコア・開始ステージ）を書かない

- **移動キーの対応**（対応の値は手計算。キー → 方向を純粋な関数に切り出すか、Scene 内の表にするかは実装裁量）: `h` → (−1, 0)、`j` → (0, 1)、`k` → (0, −1)、`l` → (1, 0)、`y` → (−1, −1)、`u` → (1, −1)、`b` → (−1, 1)、`n` → (1, 1)。既存のキー（矢印・テンキー 1〜9（5 を除く）・QWEA・XZDC）の対応は変えない（回帰）。`S`・テンキー 5・`M`・`R`・`T`・`Enter`・`Space` は移動の対応に入らない。`repeat` が true の押下は、移動も旗も変えない（今のとおり）。プレイ中（`Game` の盤面）で、Ctrl・Alt・Meta が付いた hjklyubn は、移動も旗も変えない（M キーと同じ）。死亡画面・ゲームオーバーでは [game-over.md](spec/game-over.md) の規則のまま（修飾キーだけでも 2 段目へ進む）。このとき、ブラウザの既定の動作（Ctrl+H など）を妨げない（`preventDefault` を呼ばない）。Shift だけが付いたときは、走る（上の「走る」）。Shift + Ctrl / Alt / Meta + hjklyubn は、何もしない。矢印・テンキー・QWEA・XZDC の Ctrl / Alt / Meta は、今までどおり（Shift が付いていれば走る）。同じ押下の keydown の 2 件目は処理しない（1 回の押下につき、移動も旗も 1 回だけ。押下を見分ける方法は実装裁量）。テストでは、同じ押下の 2 件目を与えたとき、判定が無視することを、手計算の例（1 件目は処理、2 件目は無視）で確かめる。
- **Shift + 移動キー**: `h` などの移動キーに Shift を付けると、その方向へ走る（上の「走る」。`Shift` の判定は `shiftKey`、キーの判定は `code`。CapsLock の影響を受けない）。旗は `f` の 2 打（上の「フラグ操作の詳細」）。

## 実装裁量

仕様に書かず、`game-impl` の判断に委ねる。

- 色（盤面・セル・数字・旗・プレイヤー・矢印・ボタン。HUD の文字の色は [spec/hud.md](spec/hud.md) の「HUD のメッセージとステータス」の表の値）、盤面・ボタン・矢印のフォントの大きさ。ただし、数字のヒント・旗・爆弾（開示後）・プレイヤー・スタートとゴールが見分けられること。
- ジョイスティックと各ボタンの細かい位置・大きさ・見た目（画面の大きさに合わせて調整してよい。押しやすい大きさであること）。FLAG ON の緑の具体的な色・枠の色・ラベルの文字色、パッドの青・緑の具体的な色、扇形の描き方（扇形の図形・多角形など。土台の円の内側に収まること）、パッドの青と緑・FLAG の ON / OFF は色相だけでなく明度も変えて見分けやすくする、「STAGE」ボタンを dev だけにする仕組み（`import.meta.env.DEV` の条件で作らない、など。本番のバンドルにダイアログのコードが残らないほうがよい）。
- カメラの追従の滑らかさ（追従マージンの範囲内で目的の位置に入ること）。 生成の乱数アルゴリズム、制約伝播の実装手順（「論理的解決可能性の保証」と、パラメータ表の値を満たすこと）。
- 内部のモジュール構成、ファイル名、データ構造。入力の修正を切り出す純粋な関数（開始ステージの決定、保存の読み書き、キーの判定、入力ロックの状態）の分け方・名前・置き場所。
- キーの対応表を置く場所（Scene 内か、`core` の純粋な関数か）と、判定の関数名。1 回の押下を 1 回だけ処理する仕組み（処理済みの押下を覚える方法）。
