# ゲーム名

dutchcalc

# コンセプト

競馬や toto などで複数の候補（馬・組み合わせ等）に賭けることを考えたとき、複数の倍率（オッズ）と合計購入口数を入力すると、どの候補が当たっても払戻額がなるべく均等になるように口数を配分するブラウザツール。

# ターゲットプレイヤー

- 競馬や toto などで複数点買いをする際に、当たったときの払戻を均等化したい人
- 電卓や表計算で手計算していた配分を、素早く試行錯誤したい人

# コアループ

1. 賭けたい候補（馬・組み合わせ等）の数だけ倍率を入力する
2. 合計購入口数と、1口あたりの金額を入力する
3. 「計算」を押すと、各候補への口数配分と、当たったときの払戻見込み額・回収率・損益が表示される。全体の理論回収率と、元本割れの候補も分かる
4. 倍率や口数を調整しながら結果を見比べ、均等か・黒字かを確かめて、納得のいく配分を確認する

# 操作仕様

- 入力デバイスはマウス／タッチ／キーボードによるフォーム入力のみ
- 候補行: 倍率入力欄（`<input type="number">`）＋ 削除ボタンを行ごとに配置
- 「候補を追加」ボタンで候補行を増やせる（上限 20 件）
- 候補行が 2 件のときは削除ボタンを無効化する（最低 2 候補を維持）
- 合計口数入力欄（整数、上限 100,000）
- 1口あたり金額入力欄（100円単位、`<input type="number" step="100" min="100">`、デフォルト 100）
- 「計算」ボタン押下で入力値を読み取り、配分計算を実行する
- 入力が不正な場合は結果エリアにエラーメッセージを表示し、計算前の結果表示はクリアする

# 画面・Scene 構成

## Game（単一 Scene）

- フォーム入力・結果表示を単一 Scene 内の DOM オーバーレイで完結させる
- `create` でフォーム DOM（候補行・合計口数・単価・ボタン群）と結果表示用 DOM を構築する
- 毎フレーム処理（`update`）は行わない。すべてイベント駆動（ボタン click / input change）で更新する
- 配分計算ロジックは Scene から分離した `src/game/logic/allocate.ts` の純粋関数として実装し、Scene はその呼び出しと DOM 反映のみを担当する
- 損益・元本割れ・理論回収率の計算と表示用の文字列は、`src/game/logic/profit.ts` の純粋関数で作り、Scene は DOM に反映するだけにする

### 結果の表示

結果エリアは、上から次の順に並べる（エラー時は結果エリアを空にする。変更なし）。

1. 結果表: 列は左から `倍率` / `口数` / `払戻` / `回収率` / `損益(円)`。行は候補の入力順
   - `払戻` は払戻見込み額（`Math.round(payout)` の整数。単位の円は付けない）、`回収率` は `payout / totalInvestment` を百分率で小数 1 桁（`toFixed(1)` + `%`）
   - `損益(円)` の値は、`Math.round(payout) - Math.round(totalInvestment)` を符号付きの整数で出す。0 より大きければ `+300`、0 なら `+0`、0 より小さければ `-800`（桁区切りなし）
   - 損益が 0 未満の行は「元本割れ行」とし、行全体に赤系の背景を付け、`損益(円)` のセルの値の下の行に `▼元本割れ` を表示する（色だけに頼らない）。損益が 0 以上の行には付けない
2. サマリー（既存の 1 行）: `合計投資額` / `最小払戻` / `最大払戻` / `バランス度(差)`（文言・値は変更しない）
3. 理論回収率の行: `理論回収率 xx.x%`（下の「ルール」の理論回収率を、百分率にして `toFixed(1)` で小数 1 桁）
4. 判定の行: 理論回収率（表示と同じ `toFixed(1)` の結果を数値にした値）が 100.0 未満なら `どの配分でも、少なくとも 1 つの候補が元本割れになります（円未満の丸めを除く）`、100.0 以上なら `理論上は元本割れを避けられます（口数が整数のため、表の配分では元本割れが残ることがあります）`

結果の組み立て（表・理論回収率の行・判定の行の HTML 文字列）は、Phaser に依存しない関数 `src/game/logic/resultHtml.ts` に切り出し、Scene はその文字列を結果エリアに入れるだけにする。元本割れ行は `tr` のクラス `dutchcalc-loss` で、`▼元本割れ` は `損益(円)` のセル内の `span.dutchcalc-loss-badge` で識別する。

### レイアウト方針

- 幅 481px 以上: 余白・パネル幅は現状のまま（root の padding 24px、panel の padding 20px、panel 幅は `min(560px, 100%)`）
- 「幅」はブラウザの表示幅（CSS の media query `max-width: 480px`）
- 幅 480px 以下: root の padding を 8px、panel の padding を 12px、表のセルの左右の余白を 4px にして、5 列の表が横スクロールなしで収まるようにする（375px 幅で panel の内幅は約 333px）
- 収まることを保証する入力の範囲: 口数が 6 桁以内、払戻・損益が 9 桁以内（口数 100,000・単価 100 円・倍率 [1.5, 1.5, 3.2] が代表の入力）。これを超える桁のときは、表だけが横にスクロールしてよい（`overflow-x: auto`）
- 表の文字は 14px 以上（損益と回収率を含む）。`▼元本割れ` の文字は 11px 以上

# ルール（勝利条件、失敗条件、スコア条件）

このツールに勝敗やスコアの概念はない。代わりに、計算結果の「成功（有効な配分が得られる）」「失敗（入力エラー）」を以下のように定義する。

- 成功条件:
  - 候補が 2 件以上
  - すべての倍率が `1.0` より大きい有限の数値
  - 合計口数が候補数以上、上限（100,000）以下の正の整数
  - 1口あたり金額が 100 以上かつ 100 の倍数
  - 上記をすべて満たす場合、口数配分と払戻見込み額を表示する
- 失敗条件（エラー表示）:
  - 候補が 1 件以下
  - 倍率が未入力・`1.0` 以下・非数値
  - 合計口数が候補数未満、0 以下、非整数、または上限（100,000）超過
  - 1口あたり金額が 100 未満、または 100 の倍数でない
- 配分の均等度（スコア相当）:
  - 各候補の払戻見込み額の最大値と最小値の差（`spread`）を「バランス度」として表示する
  - `spread` が小さいほど、どの候補が当たっても払戻額が近いことを意味する
- 損益（候補ごと）:
  - 損益 = `Math.round(payout) - Math.round(totalInvestment)`（円）。払戻は上の四捨五入した値を使う（10 円未満切り捨てなど、実際の払戻のルールは扱わない）
  - 損益が 0 未満の候補を「元本割れ」とする。0 ちょうどは元本割れではない（`+0`）
- 理論回収率（全体）:
  - `理論回収率 = 1 / Σ(1 / 倍率)`（候補の倍率すべての逆数の和の逆数）。口数が整数であることは考えない、均等にできたときの回収率の上限
  - 100% 未満なら、どの配分でも、少なくとも 1 つの候補が元本割れになる。100% 以上なら、元本割れを避けられる配分があり得る（口数が整数のため、実際の配分で必ず避けられるとは限らない）
  - 表示と判定は、百分率にして `toFixed(1)` で丸めた値で行う（99.96% は `100.0%` と表示され、判定も 100.0 以上の側）。判定は、その文字列を数値にして比べる

# テスト観点

- `allocate()` のロジックテスト:
  - 倍率がすべて同一 → 口数がほぼ均等に分配される（差が1以内）
  - 倍率が大きく偏っている → 払戻額の `spread` が最小化され、`sum(units) === totalUnits` が常に成立する
  - 全候補が最低1口を得る
  - `totalUnits < candidates.length` の場合にエラーになる
  - `odds[i] <= 1.0` を含む場合にエラーになる
  - `unitPrice` が 100 未満、または 100 の倍数でない場合にエラーになる
  - 候補数が1件、または21件以上の場合にエラーになる（候補数は2〜20件）
  - `totalUnits === candidates.length`（remaining = 0）の場合、全候補が1口ずつになる
  - 払戻額が同値でタイになった場合、インデックスが小さい候補から優先して口数が加算される（決定論的な挙動）
  - `totalUnits` が上限（100,000）を超える場合にエラーになる
  - 代表的な入力（2〜5件程度）について、全探索（ブルートフォース）で求めた最小 `spread` の配分と一致する（アルゴリズムの妥当性検証）
- 損益・理論回収率（`profit.ts`。期待値は手計算）:
  - 倍率 [2, 2]・合計 10 口・単価 100 円 → 口数 5 / 5、払戻 1000、投資額 1000、損益 `+0`（元本割れではない）、理論回収率 `100.0%`、判定は 100.0% 以上の文
  - 倍率 [1.5, 1.5]・合計 10 口・単価 100 円 → 口数 5 / 5、払戻 750、損益 `-250`（両方とも元本割れ）、理論回収率 `75.0%`、判定は 100.0% 未満の文
  - 倍率 [2, 4] → 理論回収率 `133.3%`（1 / 0.75）
  - 損益の表示: +300 → `+300`、0 → `+0`、-800 → `-800`。払戻が 999.6・投資額が 1000 のとき、四捨五入で 1000 − 1000 = 0 → `+0`（元本割れではない）
  - 判定の境界: 理論回収率 0.9996 は `100.0%` と表示され 100.0% 以上の文、0.9994 は `99.9%` と表示され 100.0% 未満の文
  - 損益が -1 → 元本割れ、0 → 元本割れではない、+1 → 元本割れではない
  - 判定文の例: 倍率 [2, 2]・合計 11 口 → 配分 6 / 5 で 5 口側が `-100`（元本割れ行が出る）が、理論回収率は 100.0% なので、判定は 100.0 以上の文（表に元本割れ行があっても矛盾しない文言であること）
- 結果の HTML（`resultHtml.ts` の文字列で検証する。Scene の DOM テストは行わない）:
  - 正しい結果から、表が 5 列（倍率 / 口数 / 払戻 / 回収率 / 損益(円)）になり、理論回収率の行と判定の行が出る
  - 損益が 0 未満の行にだけ、`tr` のクラス `dutchcalc-loss` と `span.dutchcalc-loss-badge`（`▼元本割れ`）が付く
  - 見出しは `払戻`（`払戻見込み額` ではない）
  - 480px の境界: CSS に `@media (max-width: 480px)` があり、root の padding 8px・panel の padding 12px がその中にだけある（`public/style.css` の文字列で確認する）
- Scene / UI テスト（最低限。ブラウザで確認する）:
  - 入力を変えただけでは結果は更新されず、「計算」を押したときだけ更新される
  - エラー時は、結果エリア（表・理論回収率・判定）が空になる
  - 既存の 4 列の値とサマリーの 4 項目は、拡張前と同じ文言・値である
  - 候補行の追加・削除で入力欄数が増減する
  - 候補行が2件のとき削除ボタンが無効化される
  - 不正な入力で「計算」を押すとエラーメッセージが表示され、結果テーブルは更新されない
  - 正しい入力で「計算」を押すと結果テーブルが表示される
