# dutchcalc 拡張候補（backlog）

公開済みの dutchcalc（複数の候補の払戻額を均等にする口数配分ツール）に、次に足せるものの候補を、上から順に並べたものです。上のカードが「次の候補」です。仕様（`spec.md`）ではありません。`game-extend` が上から順に 1 件を選び、目的・コアループへの効き方・変えないものを固めてから、仕様に書きます。

- 規模: S = 1 画面と数値の追加程度、M = 複数の画面や仕組みにまたがる追加、L = 大きいので、`game-extend` で 1 PR 分に切り出してから採用する。
- 1 つのカードは 1 つの目的にする（1 変更 1 目的）。
- 外部の画像・音のアセットは、足してよいかをユーザーに確認してからにする。
- 配分のアルゴリズム（`allocate.ts`）は、バランス度が最小になる配分を厳密に求める（`spec.md` / `README.md` もその記述に揃えてある）。

### 行を足す・消すとき、入力途中の倍率を消さない（`keep-typing`）

- 狙い: 候補の行を足す・消す（Enter・「候補を追加」・「削除」）たびに、全部の行を作り直す。入力途中の値（`1.` のように、まだ数として読めないもの）は欄の `value` が空なので、作り直しで消える。押したボタン・欄のフォーカスも外れる。根拠: `docs/review-rejected.md`（変更前からの方式として見送り）、`src/game/scenes/Game.ts`（`renderCandidates` が `innerHTML = ''` から組み直す）
- 何を足すか: 行の追加・削除で、変わらない行の欄はそのまま残す（足す行だけ作る・消す行だけ外す）。フォーカスは、足したときは新しい行、消したときは隣の行に置く。
- コアループへの効き方: 広げない — 買う直前の入力のやり直しを減らす。計算は変えない。
- 種別: presentation-only
- 規模: S
- 出どころ: コードレビュー
- メモ: `look-mobile` と同じ画面なので、順番を合わせる。「提案を適用」「元に戻す」は範囲に入れると 2026-11-15 に決めた（下の合意）。
- 状態: 着手可（2026-11-15、基準 `a0e29bb`）
- 合意:
  - 足すもの: 候補の行を足す・消す・提案を適用する・元に戻すとき、全行を作り直さず、変わらない行の欄（DOM）をそのまま残す。追加（Enter・「候補を追加」）は新しい行だけを作る。削除は消す行だけを外す。適用は提案で消える行だけを外す。元に戻すは、消えた行を元の位置に、元の値で作り直して戻す。残る行の入力途中の値（`1.` のように `value` が空に見えるもの。`type=number` の欄）は消えない。作り直しの経路は 1 つにまとめる（`renderCandidates` の全作り直しを残さない）
  - 操作: なし（追加・削除後のフォーカスの動きだけが変わる）
  - 見た目と初期値の方向: 見た目・配置は変えない。フォーカス: 「候補を追加」・Enter での追加では新しい行の倍率欄に移す。「削除」では、同じ位置に来た次の行の倍率欄に移す（最後の行を消したときは前の行）。提案の適用・元に戻すでは、フォーカスを移さない
  - 変えないもの: 計算（配分・バランス度・提案の中身）、Enter で次の行へ移る・最後の行で追加する動き、行の数の上限（`MAX_CANDIDATES`）と下限（`MIN_CANDIDATES`）・削除ボタンの無効化、見た目・配置・`data-role` の属性、結果の自動再計算の規則、提案を編集で消す規則（`clearSubsetOnEdit`）
  - 意図して変えるもの: 「候補を追加」を押したあとに、新しい行の倍率欄にフォーカスが移る（これまで、ボタンでの追加はフォーカスを移さなかった）。削除のあとに隣の行の倍率欄へフォーカスが移る（スマホではキーボードが開く）
  - 測ったこと: なし（計算を変えない）
  - spec の置き場所: `docs/spec.md` を直接書き換える（行の追加・削除に関する節とテスト観点・完了条件）
  - ブランチ: `feat/dutchcalc-keep-typing`

### 入力を保存し、次に開いたときに復元する（`save-input`）

- 狙い: ページを開き直すと、入力がすべて消える。根拠: `spec`「非 MVP 範囲」（配分結果の保存・共有）
- 何を足すか: 入力（倍率・合計口数・単価）を `localStorage` に保存し、次に開いたときに復元する。
- コアループへの効き方: 広げない — 持ち越し。
- 種別: presentation-only（保存を足す）
- 規模: S
- 出どころ: spec 分析
- メモ: 保存の失敗（ブロック・容量超過）でも、ツールが止まらないようにする。履歴・共有 URL は、この次のカードにする。

### 結果をテキストでコピーできるようにする（`copy-result`）

- 狙い: 結果を他のアプリ（メモ・チャット）に持ち出す手段が無い。根拠: `spec`「非 MVP 範囲」（配分結果の保存・共有）
- 何を足すか: 結果をテキストでコピーするボタンを足す。
- コアループへの効き方: 広げない — 持ち出し。
- 種別: presentation-only
- 規模: S
- 出どころ: spec 分析

### スマホ幅の見た目とタップの大きさを整える（`look-mobile`）

- 狙い: パネルの余白が左右で計 44〜48 px、ボタンの余白が小さい（縦 6 px）。スマホで使う場面（買う直前）で、タップしやすさを確かめていない。根拠: AGENTS.md 4.6、`public/style.css`
- 何を足すか: 375 × 550・390 × 844 で、文字の大きさ（主な情報 14 px 以上）・タップの的（44 px 以上）・結果の表の切れを確かめて、整える。
- コアループへの効き方: 広げない — 読みやすさと操作性。
- 種別: presentation-only
- 規模: S
- 出どころ: spec 分析
- メモ: DOM オーバーレイなので、`scripts/qa/look.mjs` で確かめる。入力欄の `font-size` が 16 px 未満だと、iOS で入力時にズームされる。
