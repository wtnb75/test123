# dutchcalc 拡張候補（backlog）

公開済みの dutchcalc（複数の候補の払戻額を均等にする口数配分ツール）に、次に足せるものの候補を、上から順に並べたものです。上のカードが「次の候補」です。仕様（`spec.md`）ではありません。`game-extend` が上から順に 1 件を選び、目的・コアループへの効き方・変えないものを固めてから、仕様に書きます。

- 規模: S = 1 画面と数値の追加程度、M = 複数の画面や仕組みにまたがる追加、L = 大きいので、`game-extend` で 1 PR 分に切り出してから採用する。
- 1 つのカードは 1 つの目的にする（1 変更 1 目的）。
- 外部の画像・音のアセットは、足してよいかをユーザーに確認してからにする。
- 配分のアルゴリズム（`allocate.ts`）は、バランス度が最小になる配分を厳密に求める。`spec.md` / `README.md` の「逐次貪欲法」の記述は実装とずれているので、カードにせず、docs の修正として別に直す。

### 損益・理論回収率・元本割れを表示する（`profit-view`）

- 狙い: 結果は口数・払戻額・回収率だけで、「この組み合わせで買う意味があるか」（どの候補が当たっても黒字か）が一目で分からない。倍率が低い組み合わせは、均等にしても全員が元本割れになる。根拠: `spec`「配分の均等度」、`Game.ts` の結果表示
- 何を足すか: 候補ごとの損益（払戻 − 合計投資額）を表に足す。全体の理論上の最大回収率（1 / Σ(1/倍率)）を出す。元本割れの候補は、色と記号で見分けられるようにする。
- コアループへの効き方: 深める — 「均等か」に加えて「黒字か」を見て、倍率の組み合わせを選べる。
- 種別: gameplay
- 規模: S
- 出どころ: spec 分析
- メモ: 色だけで見分けない（記号・文字を併用）。`payout-floor` が入ると損益の値が変わるので、先に決めるか、一緒に決める。

### 払戻を実際のルール（10 円未満切り捨て）で表示する（`payout-floor`）

- 狙い: 払戻見込み額は `口数 × 倍率 × 単価` を四捨五入しただけで、実際の払戻（100 円あたり、10 円未満切り捨て）とずれる。均等化の指標（バランス度）が、実際の払戻と合わない。根拠: `Game.ts`（`Math.round`）
- 何を足すか: 払戻額を、100 円あたりの払戻を 10 円単位に切り捨てて計算する。バランス度・回収率も、その値で出す。
- コアループへの効き方: 深める — 表示の数字が、実際の払戻と一致する。
- 種別: gameplay
- 規模: S
- 出どころ: spec 分析
- メモ: 配分の最適化に切り捨てを含めるかを、`game-extend` で決める（含めないと、最適な配分が変わることがある）。単価が 100 円の倍数なので、口数ごとに端数が出る。

### 予算（円）で入力する（`budget-input`）

- 狙い: 合計口数を入力するので、「いくら使うか」から考えるには、予算 ÷ 単価を手で計算する必要がある。根拠: `spec`「操作仕様」
- 何を足すか: 合計口数と並べて、予算（円）の入力欄を足す。予算を入れると、口数 = 切り捨て（予算 ÷ 単価）が入る（口数を入れると予算が入る）。
- コアループへの効き方: 広げる — 入力の入口が増える。計算は変えない。
- 種別: gameplay（入力）
- 規模: S
- 出どころ: spec 分析
- メモ: 余った端数（予算 − 口数 × 単価）を表示する。上限（100,000 口）を超えるときのエラーの出し方を決める。

### 入力のたびに自動で計算し、Enter で次の行へ移る（`live-calc`）

- 狙い: 倍率を変えて見比べる使い方なのに、毎回「計算」を押す必要がある。倍率を 1 件ずつタップして入力する。根拠: `spec`「コアループ」、`Game.ts`
- 何を足すか: 入力が有効なら、入力のたびに結果を更新する（無効なときは、前の結果を残して、エラーを出す）。倍率の欄で Enter を押すと、次の行へ移る（最後の行なら候補を足す）。
- コアループへの効き方: 広げない — 試行錯誤の手間を減らす。計算は変えない。
- 種別: presentation-only
- 規模: S
- 出どころ: spec 分析
- メモ: 「計算」ボタンは残す（キーボード・支援技術のため）。途中の入力（空欄）でエラーを出し続けない。

### 元本割れを避けるための、候補の絞り込みを提案する（`pick-subset`）

- 狙い: 全員が元本割れになるとき、どの候補を外せば黒字にできるかを、自分で試すしかない。根拠: `spec`「非 MVP 範囲」、`profit-view` の延長
- 何を足すか: 「候補を減らす提案」を出す。倍率の高い順に候補を外したとき、理論回収率が 100% を超える最小の組み合わせを示す。外した候補を、元に戻せる。
- コアループへの効き方: 深める — 「何を買わないか」の判断を助ける。
- 種別: gameplay
- 規模: M
- 出どころ: spec 分析
- メモ: `profit-view` の後。候補を外すと、的中の確率は下がる。それを、ツールは判断しない（ユーザーの判断に委ねる）ことを、画面に書く。

### 入力を保存し、結果をコピーできるようにする（`save-input`）

- 狙い: ページを開き直すと、入力がすべて消える。結果を他のアプリ（メモ・チャット）に持ち出す手段が無い。根拠: `spec`「非 MVP 範囲」（配分結果の保存・共有）
- 何を足すか: 入力（倍率・合計口数・単価）を `localStorage` に保存し、次に開いたときに復元する。結果をテキストでコピーするボタンを足す。
- コアループへの効き方: 広げない — 持ち越しと持ち出し。
- 種別: presentation-only（保存を足す）
- 規模: S〜M
- 出どころ: spec 分析
- メモ: 保存の失敗（ブロック・容量超過）でも、ツールが止まらないようにする。履歴・共有 URL は、この次のカードにする。

### スマホ幅の見た目とタップの大きさを整える（`look-mobile`）

- 狙い: パネルの余白が左右で計 44〜48 px、ボタンの余白が小さい（縦 6 px）。スマホで使う場面（買う直前）で、タップしやすさを確かめていない。根拠: AGENTS.md 4.6、`public/style.css`
- 何を足すか: 375 × 550・390 × 844 で、文字の大きさ（主な情報 14 px 以上）・タップの的（44 px 以上）・結果の表の切れを確かめて、整える。
- コアループへの効き方: 広げない — 読みやすさと操作性。
- 種別: presentation-only
- 規模: S
- 出どころ: spec 分析
- メモ: DOM オーバーレイなので、`scripts/qa/look.mjs` で確かめる。入力欄の `font-size` が 16 px 未満だと、iOS で入力時にズームされる。
