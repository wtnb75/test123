# 文字集め（`wordfall`・仮称）

## ゲーム名

文字集め（`wordfall`）。Title には「文字集め」と、小さく `WORDFALL` を出す。

## コンセプト

上から文字が落ちてくる。画面に出ている英単語のお題（日本語の意味つき）を見ながら、必要な文字をタップしてトレイに拾い、材料が揃うと単語が完成して得点と時間が増える。長い単語ほど高得点で、遊び終えると出た単語と意味を一覧で見直せる。トレイの枠が限られるので、複数のお題に共通して使える文字を狙うのが遊びどころ。

## ターゲットプレイヤー

スマホで 1 回 1〜2 分、すき間時間に遊ぶ人。英単語を遊びながら覚えたい中高生・学び直しの大人。主な入力はタップ。キーボードは補助。

## コアループ

1. 落ちてくる文字を見る
2. お題に必要な文字をタップして拾う（トレイに入る）
3. トレイが埋まってきたら、不要な文字をタップして捨てる
4. 材料が揃うと自動で完成 → 得点と時間が増え、新しいお題が出る
5. 時間が 0 になったら結果画面で、出た単語と意味を見直す

## 操作仕様

| 場面 | タッチ / マウス | キーボード（補助） |
|---|---|---|
| Title | START ボタンをタップ（押した場所で離したときに働く） | Space / Enter で START |
| Game | 落ちてくる文字をタップして拾う。トレイの文字をタップして捨てる | 文字キー（A〜Z。大文字・小文字とも同じ）で、その文字のうち一番下（y が最大）に落ちているものを拾う。Backspace でトレイの最後（最後に拾った）の文字を捨てる（トレイが空なら何も起きない） |
| Result | 「もう一度」「タイトルへ」をタップ（押した場所で離したときに働く）。単語の一覧は上下にドラッグ（タッチ）またはホイールでスクロール | Space / Enter で「もう一度」。↑ ↓ で一覧を `RESULT_ROW_H` ずつスクロール |

- タップの的は、見た目より大きく取る（落ちてくる文字は `LETTER_HIT_SIZE`、トレイの枠は枠の高さ `TRAY_SLOT_H` に枠どうしのすき間を足した範囲、ボタンは仕様の大きさ）。実寸 44 px 以上になるのは、縮小率 1.0 以上（幅 360 px 以上の縦持ち）のとき。幅 320 px の端末（縮小率 0.89）では、トレイの枠が 39 px・落ちてくる文字が 44.5 px になる。トレイの枠だけは 44 px を割るが、実寸 39 px でも 2 行 5 列の広い枠（幅 61 px）で、狙いは外しにくいので許容する
- 落ちてくる文字どうしの的が重なる所をタップしたときは、タップした点に中心がいちばん近い文字を拾う（同じ距離なら y が大きい方）。落ちてくる文字の的とトレイの枠が重なる点は無い（文字は下端が `FLOOR_Y` に届く前に消えるため）。トレイの枠のすき間をタップしたときは、近い方の枠として扱う（空の枠なら何も起きない）
- キーは押した瞬間に 1 回だけ働く（押しっぱなしのリピートは無視。Ctrl / Alt / Meta を押しながらのキーも無視する）。Result の ↑ ↓ だけはリピートで動き続ける。日本語 IME が ON でブラウザがキーの文字を報告しないとき（`Process`）は、物理キー（A〜Z、Enter、Space、Backspace、↑ ↓）で同じ操作ができる。変換中の文字を確定する Enter・変換の Space は、ゲームのキーとしては働かない（START や「もう一度」にならない）。キー配列が QWERTY でないときは、押した文字（報告された文字）を使う
- Result の一覧のドラッグは、一覧の上で始めた 1 本目の指だけが動かし、その指が離れるまで 2 本目の指は無視する。ホイールは、ポインタが一覧の上にあるときだけ、1 回の目盛りで `RESULT_WHEEL_ROWS` 行ぶん（ブラウザが報告する量に依らず）動かす
- 同じフレームに複数の入力が来たら、届いた順に 1 つずつ処理する（拾う → 完成判定 → 次の入力）
- 「縦にしてください」の案内が出ている間は、すべての入力を受け付けない（下の「画面の大きさ」）
- Result を始めてから `RESULT_INPUT_GUARD_MS` の間は、ボタンとキー（Space / Enter / ↑ ↓）を受け付けない（時間切れの瞬間までトレイを連打していたタップが、そのまま「もう一度」を押さないため。ガードの間もスクロールのドラッグ・ホイールは受け付ける）

## 画面・Scene構成

| Scene | 役割 |
|---|---|
| Title | ゲーム名・遊び方・自己ベスト・START ボタン |
| Game | プレイ。お題 3 語・落ちてくる文字・トレイ・HUD |
| Result | 時間切れの結果。スコア・完成語数・自己ベスト・出た単語と意味の一覧・2 つのボタン |

### 画面の大きさ（論理サイズ）

- 幅は `SCREEN_WIDTH` で固定。高さは `round(SCREEN_WIDTH × 表示の高さ / 表示の幅)` を `[SCREEN_HEIGHT_MIN, SCREEN_HEIGHT_MAX]` に収めた値 H にする。Title に入ったとき、Title にいる間に表示の大きさが変わったとき（画面を回したときなど）、Game を始めるとき（START と「もう一度」）に決め直す。Game・Result の間は変えない（プレイ中に場の大きさを変えると文字の位置が崩れるため）。Phaser の `Scale.FIT` で中央に置く
- 手計算の例（縮小率 = `min(表示の幅 / 論理の幅, 表示の高さ / H)`）:

| 表示の大きさ | 論理の大きさ | 縮小率 | 黒帯 |
|---|---|---|---|
| 390 × 844（スマホ縦） | 360 × 779 | 1.083 | なし |
| 375 × 550（iPhone SE 縦） | 360 × 528 | 1.042 | なし |
| 1280 × 720（PC） | 360 × 520（下限） | 1.385 | 左右に計 61%。縦持ちを前提にしたゲームなので許容する（文字・ボタンは十分に大きい） |
| 667 × 310（スマホ横） | 360 × 520（下限） | 0.596 | 案内を出す（下） |

- 表示が横長（幅 > 高さ）で、縮小率が `ROTATE_PROMPT_SCALE` 未満のとき（667 × 310 は 0.596、844 × 390 は 0.75。0.875 以上は出ない）は、文字が読めない大きさになるので、どの Scene でも、その上に「画面を縦に」「してください」の 2 行の案内を全面に出す。この間 Game は進行を止め（時間・落下・文字の出現・`RESULT_DELAY` が進まない）、Title・Result も入力を受け付けない。表示の大きさが変わって条件を外れたら案内を消して続きから再開する。案内の文字の大きさは、論理で `min(ceil(PROMPT_REAL_FONT_SIZE ÷ 縮小率), PROMPT_MAX_FONT_SIZE)`（縮小率が 0 以下なら `PROMPT_MAX_FONT_SIZE`）。PC（1280 × 720、縮小率 1.385）や 1024 × 768（1.477）には出ない。縦長の表示（幅 ≤ 高さ）には出ない。想定外として、幅が約 315 px 未満の端末や、正方形に近い小さな窓では、文字が小さくなるが対応しない

### 文字の大きさ（論理 px。実寸 = 論理 × 縮小率）

主な情報は実寸 14 px 以上、補助は 11 px 以上（AGENTS.md 4.6）。縦持ちの縮小率は、幅 320 px の端末でも 0.89 以上（360 より狭い画面では幅で決まる）。

| 要素 | 論理 | 実寸（縮小率 0.89 / 1.04） | 区分 |
|---|---|---|---|
| HUD（SCORE / TIME） | `FONT_HUD` 18 | 16 / 19 | 主 |
| お題の英単語 | `FONT_TARGET` 24 | 21 / 25 | 主 |
| お題の下の意味行 | `FONT_MEANING` 14 | 12.5 / 14.6 | 補助 |
| 落ちてくる文字 | `FONT_LETTER` 26 | 23 / 27 | 主 |
| トレイの文字 | `FONT_TRAY` 22 | 19.6 / 23 | 主 |
| トレイの説明 | `FONT_HINT` 13 | 11.6 / 13.5 | 補助 |
| Title の説明 | `FONT_HELP` 14 | 12.5 / 14.6 | 補助 |
| Result のスコア・語数・自己ベスト・一覧、Title の自己ベスト | `FONT_RESULT` 16 | 14.2 / 16.6 | 主 |
| ボタンの文字（START・もう一度・タイトルへ） | `FONT_BUTTON` 18 | 16 / 19 | 主 |
| ポップアップ（`+170  +7s`） | `FONT_POP` 18 | 16 / 19 | 主 |
| Title の `WORDFALL` | `FONT_TITLE_SUB` 16 | 14.2 / 16.6 | 主 |

主な情報（論理 16 以上）は、補助の文字（論理 14 以下）より小さくならない。横長で案内が出ない最小の縮小率は `ROTATE_PROMPT_SCALE`（0.875）で、そのとき `FONT_RESULT`（16）は実寸 14、意味行 `FONT_MEANING`（14）は 12.25、トレイの説明 `FONT_HINT`（13）は 11.4 になり、基準（主 14 / 補助 11）を満たす。`ROTATE_PROMPT_SCALE` は、主な情報の最小（論理 16）が実寸 14 px を保てる下限（14 ÷ 16 = 0.875）から決めた。

### Title

- 上から順に: ゲーム名「文字集め」（`FONT_TITLE` 40）、`WORDFALL`（`FONT_TITLE_SUB`）、遊び方の説明 4 行（`FONT_HELP`）、自己ベスト（`BEST 1230`。記録が無ければ `BEST ---`。`FONT_RESULT`）、START ボタン（文字は `FONT_BUTTON`）。H = 528 の配置の例: ゲーム名の中心 y = 70、`WORDFALL` = 106、説明の最初の行の中心 y = 142（行の間隔 22）、自己ベストは説明の最後の行の中心から 28 下
- 遊び方の説明（行が画面の幅 − 32 に収まらないときは折り返す。折り返して 5〜6 行になっても自己ベストの行や START ボタンと重ならない）:
  - 「落ちてくる文字をタップしてひろう」
  - 「お題の文字がそろうと単語が完成」
  - 「長い単語ほど高得点。時間も増える」
  - 「トレイは 10 文字まで。いらない文字は捨てる」
- START ボタン（`BUTTON_W` × `BUTTON_H`）は、中心 y = H − `TITLE_BUTTON_FROM_BOTTOM`（画面の下 1/3 に入る。H = 528 で 398、上端 372 ≥ 2/3 H = 352）
- 状態は 1 つ（START を押すと Game へ）

### Game

- レイアウト（論理の高さ H。上から）:
  - HUD: 上端 y = `HUD_Y`。左に `SCORE 120`、右に `TIME 45`（TIME は残り秒の切り上げ。開始時は 60、`ending` では 0）
  - お題 3 行: 行 i（i = 0, 1, 2）の英単語の中心 y = `TARGET_Y0` + `TARGET_ROW_STEP` × i。文字は 1 文字ずつ `TARGET_LETTER_STEP` 間隔で、行の中央に並べる。その `MEANING_OFFSET` 下に、意味行 `ねこ（3文字 +30）`（日本語の意味、文字数、その得点）を中央に出す
  - 場: y = `FIELD_TOP` から `FLOOR_Y`（= H − `FLOOR_FROM_BOTTOM`）まで。`FLOOR_Y` に細い線を引く。文字は `COLUMNS` 本の列のどれかの中心 x に、上端が `FIELD_TOP` になる位置（中心 y = `FIELD_TOP` + `LETTER_SIZE` / 2）から出る（列の幅 = `SCREEN_WIDTH` / `COLUMNS`）。文字は、下端（中心 y + `LETTER_SIZE` / 2）が `FLOOR_Y` に届いたフレームで消える（床の線・説明・トレイに重ならない）
  - トレイの説明: 1 行（`トレイの文字をタップで捨てる`）。中心 y = H − `TRAY_BOTTOM_MARGIN` − トレイの高さ − `HINT_GAP`（H = 528 で 414。文字の上端 ≈ 407.5 は `FLOOR_Y` = 398 より下）
  - トレイ: 画面の下、枠の下端が H − `TRAY_BOTTOM_MARGIN`。`TRAY_COLS` 列 × `TRAY_ROWS` 行の枠（`TRAY_CAPACITY` 個）。トレイの高さ = `TRAY_SLOT_H` × `TRAY_ROWS` + `TRAY_GAP` × (`TRAY_ROWS` − 1)。拾った順に、1 行目の左から右、続けて 2 行目の左から右へ入る。捨てたら後ろの文字が前へ詰める。空き枠も薄く描く
- お題の文字の色: お題の英単語の各文字は、そのお題について、トレイに同じ文字が足りていれば緑、足りなければ灰色にする（同じ文字が 2 つ要る単語は、トレイに 2 つあって初めて 2 つ目が緑。他のお題の分とは数えない）。トレイが変わるたびに更新する
- 状態と遷移:

| 状態 | 内容 | 次へ進む条件 |
|---|---|---|
| `playing` | 文字が出て落ち、時間が減る。タップ・キーで拾う・捨てる。始まった時点（t = 0）で 1 つ目の文字を出し、以降 `SPAWN_INTERVAL_MS` ごとに出す | 時間の更新のあとで残り時間が 0 以下になった → `ending` |
| `ending` | 時間・落下・文字の出現・入力（タップ・キー）をすべて止める。落ちている文字だけを消し、お題・トレイ・HUD（TIME は `0`）はそのまま残す | `RESULT_DELAY` 秒たった → Result へ（結果のデータを渡す） |

- 同じフレームの順序: 入力（拾う・捨てる・完成判定・加算時間）→ 時間の更新（`dt` を引く）→ 終了判定 → 文字の出現と落下。つまり、時間が尽きるフレームに届いたタップは、そのフレームの時間の更新より前に処理され、完成による加算時間が効く
- Result へ渡すもの: スコア、完成語数、お題に出た単語の記録（出た順。各語に完成したかどうか）。自己ベストの判定と保存は、Result を始めるときに 1 回行う

#### 演出・UI（Game）

時間の決まり（すべての演出に共通）: きっかけのフレームを t = 0 とし、決めた長さ D のちょうどで消える（または元に戻る）。同じ演出がもう一度起きたときは、特に書かない限り、前のものは続けたまま新しいものを重ねる。演出は Phaser の tween / タイマーで動かし、入力を止めない（案内が出ていないとき、どの演出の間もタップ・キーは受け付ける）。`ending` の扱い: 時間が尽きるフレームの入力（拾う・完成）で起きる演出は、そのフレームが `ending` に入るフレームでも出す。そのフレームに予約された遅れのポップアップ（`POP_STAGGER_MS` による開始の遅れ）も出す。時間の更新そのもの（TIME が 1 → 0 になること）で起きる演出（TIME の強調）は出さない。`ending` に入ったあとに起きる新しい演出は出さない。再生中のものは `ending` の間は続け、Result への切り替えで残っているもの（遅れの間で始まっていないものを含む）は切る（切り替えを遅らせない。`RESULT_DELAY` 0.8 秒に対して、ポップアップは 1 回の拾いで 3 語完成しても k = 2 の終わりが `POP_STAGGER_MS` × 2 + `POP_MS` = 840 ms なので、最後の 40 ms ぶんだけ切れることがある。なお、完成は 3 秒以上の加算を伴うので、完成の演出が時間切れのフレームをまたぐことは、通常は起きない。ここは念のための規則である）。Scene が終わるときに残っているものは破棄する。「縦にしてください」の案内の間も、演出は案内の下で再生し続けてよい（案内は最前面）。

| 演出 | きっかけ | 見た目 | 重なったとき・境界 |
|---|---|---|---|
| 完成のフラッシュ | 文字を拾って 1 語以上が完成したフレーム | 白い全画面フラッシュ `COMPLETE_FLASH_MS`（Phaser の `camera.flash`） | 同じフレームに複数完成しても 1 回。フラッシュの再生中に新しく完成しても、新しいフラッシュは出さない（`camera.flash` の既定の動作に任せる） |
| 完成した行の強調 | 語が 1 つ完成するたび（1 回の拾いで複数完成したら、その数だけ） | 完成した語の英字を、その行の位置に `FONT_TARGET`・緑（`COLOR.good`）で、お題と同じ文字の間隔（`TARGET_LETTER_STEP`）で出し、行の中心を中心に `COMPLETE_GHOST_MS` で 1.0 倍 → `COMPLETE_GHOST_SCALE` 倍、不透明度 `COMPLETE_GHOST_ALPHA` → 0 にして消す。行はそのフレームのうちに新しいお題へ入れ替わっていて、強調はその上に重なって消える。この間、新しいお題の英字と数百 ms 以内の短い間だけ重なるが、不透明度が 0 へ向かうので許容する（読みやすさを損ねる重なりは、不透明度の初期値 0.7 で避ける） | 1 語ごとに 1 つ。同じ行で続けて完成した（新しいお題がすぐ完成した）ときは、同じ行に重なる |
| 点数・時間のポップアップ | 同上 | 画面の幅の中央、場の上端の少し下（開始 y = `FIELD_TOP` + `POP_START_BELOW`）に、`+170  +7s`（その語の得点と加算秒。`+` の数字は `SCORE_BY_LENGTH`、秒は文字数 × `BONUS_SEC_PER_LETTER`）を `FONT_POP`・`COLOR.accent` で出し、`POP_MS` で `POP_RISE` px 上へ動きながら不透明度 1 → 0 で消える。お題の文字の行からは離れた位置から始める（終わりの y = 170 は最下行の意味行 y = 166 のすぐ下で、文字の枠はごく薄い最後の約 150 ms だけ意味行と重なるが、不透明度が 0.3 以下なので許容する） | 1 回の拾いで複数完成したときは、k 番目（0 から）の開始を `POP_STAGGER_MS` × k だけ遅らせ、さらに開始 y を `POP_STACK_DY` × k だけ下げる（重ならないように縦に並べる。`+170  +7s` と `+50  +4s` が同時に読める）。遅れの間は表示しない。落ちてくる文字の上に重なって描く |
| TIME の強調 | 完成したフレーム、および警告中（減ったあとの表示が `WARN_SEC` 以下）に TIME の表示が減ったフレーム | HUD の `TIME` の文字を、`TIME_BUMP_MS` で大きさ 1.0 → `TIME_BUMP_SCALE` 倍 → 1.0 に戻す（右上を固定して広がる）。HUD の他の項目は動かさない | 同じフレームに両方なら 1 回。途中でまた起きたら、大きさ 1.0 から最初からやり直す。表示が 11 → 10 に減ったフレームも出す（減ったあとが 10 だから）。1 フレームで複数秒減っても 1 回。表示が 1 → 0 になるフレーム（= `ending` に入るフレーム）は出さない |
| 時間の警告 | TIME の表示（残り秒の切り上げ）が `WARN_SEC` 以下 | TIME の文字を `COLOR.warn`（赤）にする。`WARN_SEC` を超えたら（加算で戻ったら）元の色に戻す | 境界: 表示が `WARN_SEC` ちょうど（10）で赤、`WARN_SEC` + 1（11）で白。`ending` の 0 も赤のまま |
| 満杯の手がかり | トレイが満杯で、文字をタップした（または落ちている文字のキーを押した）ために拾えなかったフレーム | トレイの 10 個の枠の縁を `COLOR.warn`（赤）にして `FULL_RIM_MS` で元に戻す。画面の揺れ（`camera.shake`、`FULL_SHAKE_MS`・`FULL_SHAKE_INTENSITY`）は今までどおり同時に出す。文字は拾われず、そのまま落ちつづける | 途中でまた起きたら、元に戻るまでの時間を最初から数え直す |
| 拾った文字の飛び | 文字を拾えたフレーム（満杯で拒否されたときは出さない） | 拾った文字のタイル（`LETTER_SIZE` の正方形と文字）を、その文字があった位置から、トレイの行き先の枠（拾う前のトレイの文字数 = 枠の番号）の中心へ、`FLY_MS` で動かし、大きさを枠の高さ（`TRAY_SLOT_H`）の正方形まで変えながら、着いたら消す。トレイの文字の表示はこれを待たずにそのフレームのうちに更新する（枠にはすぐ文字が出る） | 1 つずつ別々に動く。拾いで完成して枠の文字が取り除かれても、そのまま行き先まで動いて消える |

- 描画の順（奥から）: 背景 → 床の線・トレイの説明 → お題・意味行 → トレイの枠 → 落ちてくる文字 → 拾った文字の飛び → 完成した行の強調 → ポップアップ → HUD → 「縦にしてください」の案内（最前面）。画面の揺れ・フラッシュは画面全体にかかる
- 文字がトレイの枠に収まり、ポップアップの文字は画面の左右にはみ出さない（`FONT_POP` の `+230  +8s` は幅 120 ほどで、幅 360 の中央に置くので収まる）
- 入力に遅れを与えない: 拾う・捨てるはタップの瞬間に決まり、演出の完了を待たない
- 効果音・BGM は MVP には無い（非MVP）

### Result

- 上から順に: 「TIME UP」（`FONT_RESULT_TITLE` 28）、`SCORE 1230`（`FONT_RESULT_SCORE` 22）、`WORDS 7`（完成した語数。同じ単語を 2 回完成したら 2 と数える）と `BEST 1230` を 1 行（`FONT_RESULT`）、今回で自己ベストを更新したら、その下に「NEW BEST!」（`FONT_RESULT`。更新しないときは行ごと詰めずに空けておく）、単語の一覧、ボタン 2 つ
- 配置（H = 528 の例）: 「TIME UP」の中心 y ≈ 24、スコア ≈ 56、語数・自己ベストの行 ≈ 84、NEW BEST ≈ 106。一覧の領域は y = `RESULT_LIST_TOP` から H − `RESULT_LIST_BOTTOM_MARGIN` まで（H = 528 で 124〜450。12 行見える）。ボタン 2 つ（「もう一度」「タイトルへ」。`RESULT_BUTTON_W` × `BUTTON_H`、すき間 `RESULT_BUTTON_GAP`、横に並べ、中心 y = H − `RESULT_BUTTON_FROM_BOTTOM`。画面の下 1/3 に入る）
- 単語の一覧: そのプレイでお題に出た単語を、出た順に 1 行ずつ。同じ単語が複数回出ていたら 1 行にまとめる（最初に出た位置）。完成したことが 1 回でもあれば `✓ CAT  ねこ`（緑）、一度も完成しなければ `・ DOG  いぬ`（灰色）。行の高さ `RESULT_ROW_H`、文字は `FONT_RESULT`。一覧の領域に収まらない分は、上下のスクロールで見る（領域の外は表示しない）。スクロールの量は先頭（0）から「一覧の全体の高さ − 領域の高さ」まで（一覧が領域より短いときはスクロールしない）。キーの ↑ ↓ は `RESULT_ROW_H` ずつ動き、端で止まる。時間切れのときに画面に出ていた 3 語も、ほかの語と同じ規則で並ぶ（その語を過去に完成していれば ✓、なければ ・）
- 「もう一度」は Game を最初から（スコア 0・時間 `START_TIME_SEC`・トレイ空・お題を引き直す）。「タイトルへ」は Title へ

#### 演出・UI（Result）

- スコアの数え上げ: Result が始まったフレームを t = 0 として、`SCORE` の数字を 0 から、`COUNT_UP_MS` で今回のスコアまで増やして表示する（t の間の値 = スコア × min(1, t / `COUNT_UP_MS`) を `Math.round`（0.5 は切り上げ）で整数にしたもの。t = 0 で 0、`COUNT_UP_MS` 以降はスコアちょうど）。桁が増えても数字が左右に揺れないように、中央揃えの固定幅の数字を推奨する（実装裁量）。スコアが 0 のときは動かさず 0 を出す。「案内」が出ている間も数え続けてよい。入力を止めない（ボタンの受付は `RESULT_INPUT_GUARD_MS` のとおり）。`WORDS` と `BEST` は最初から最終の値を出す
- 新ベストの点滅: 「NEW BEST!」は、数え上げが終わったとき（t = `COUNT_UP_MS`）から、不透明度 1 → `BEST_BLINK_ALPHA` → 1 を 1 回 `BEST_BLINK_MS` で、`BEST_BLINK_COUNT` 回くり返し、そのあと不透明度 1 で止まる。数え上げの間は不透明度 1 の静止で表示する（見えない状態から現れない）

#### ボタン（Title・Result）

- 対象は、Title の START、Result の「もう一度」「タイトルへ」。押している間（そのポインタが押した位置のボタンの上にある間）は、色を `COLOR.buttonPressed`（暗い青）にして、大きさを `BUTTON_PRESS_SCALE` 倍にする。ポインタがボタンの上にあるだけのとき（マウスのホバー）は `COLOR.buttonHover`（明るい青）にする。離れたら元の色・大きさに戻る
- ボタンは、押した場所のボタンの上でポインタを離したときに働く。キー（Space / Enter）は押した瞬間に働く
- 押しの登録: ポインタが押された（down）とき、そのボタンの上で、かつ受付中（Result では `RESULT_INPUT_GUARD_MS` が過ぎていて、案内が出ていないとき。Title では案内が出ていないとき）であれば、そのポインタを「そのボタンを押している」と登録する。それ以外のとき（ガード中・案内中・ボタンの外・前の Scene で押し始めた指）は、登録しない。登録されないポインタは、あとでボタンの上で離しても何も起きない
- 登録されたポインタは、ポインタごとに独立に扱う（複数の指が別々のボタンを押していてもよい。それぞれが自分のボタンの上で離したときに働くが、Scene を離れる遷移は最初の 1 回だけ）。次のどれかが起きたら、登録を捨てる: 押している間にポインタがそのボタンの外へ出た（外へ出たあと戻っても、再び登録はしない）、タッチが取り消された（`pointercancel`）、案内が出た、Scene が終わった
- 見た目: 押している（登録された）ポインタがあるあいだ、そのボタンは押している見た目にする。ポインタが押されていない状態でボタンの上にあるだけ（マウスのホバー）のときは、ホバーの見た目にする（押したまま外へ出て戻った指は、押している状態が続いているので、ホバーにも押している見た目にもしない）。ガード中・案内中は、押している・ホバーの見た目を出さない（通常の見た目のまま）。優先: 押している > ホバー > 通常。縮小しても、ボタンの当たり判定は縮小前の大きさのまま（縁でちらつかない）

## ルール

### お題

- お題は常に `TARGET_COUNT` 語を同時に出す。ゲームの開始時に、単語リスト（下）から重複しないように `TARGET_COUNT` 語を引く
- 単語を 1 語引く規則: 今画面に出ている 3 語（完成して入れ替えるときは、その完成した語も含む）を除いた候補から、候補 1 語ごとに「その単語の文字数に対応する `LENGTH_WEIGHT`」を重みとして、重み付きの無作為で選ぶ。（例: リスト 37 語の重みの合計は 6×3 + 7×3 + 6×3 + 6×2 + 6×2 + 6×1 = 87。ゲームの開始時の最初の 1 語目は、3 語を除く前の全体で 8 文字のどれかが選ばれる確率が 6 / 87 ≒ 6.9%）。完成した語が直後に同じ行へ出ることは無いが、時間がたてば再び出てよい
- お題は完成すると、その行が新しく引いた単語に入れ替わる（その行の位置のまま）

### 文字

- 文字は、プレイが始まった時点で 1 つ、以降は `SPAWN_INTERVAL_MS` ごとに 1 つ、`COLUMNS` 列のどれかの上端に出る。どの列かは一様な無作為。ただし、その列にすでにある直近の文字が、出た位置から `LETTER_SIZE` 以上下がっていない列は選ばない（候補の列から一様に選ぶ。最大でも 2 列ほどしか塞がらないので、候補が無くなることは無い）
- 出す文字: 確率 `NEEDED_RATIO` で「今のお題がまだ必要としている文字」から 1 つ、そうでなければ A〜Z から一様に 1 つ（おとり）。「まだ必要な文字」は、お題 3 語それぞれについて、トレイで足りていない文字（上の「お題の文字の色」で灰色の文字）を集めた多重集合から、一様に 1 つ選ぶ（お題どうしで同じ文字は重複して数える）。必要な文字が 1 つも無いとき（トレイにすべて揃っている）はおとりになる
- 落下の速さは、経過時間 `t`（プレイ中の秒。案内で止まっている間は進まない）に対して `min(FALL_SPEED_MAX, FALL_SPEED_START + FALL_SPEED_RAMP × t)` 場の高さ / 秒（場の高さ = `FLOOR_Y` − `FIELD_TOP`）。画面の高さが違っても、場の上端から下端まで動く割合は同じになる。文字が消えるのは、下端が `FLOOR_Y` に届いたとき（上の「場」）。拾わなかった文字にペナルティは無い

### 拾う・捨てる

- 落ちている文字をタップ（または対応する文字キーを押す）と、トレイに空きがあれば、その文字が消えてトレイの末尾に入る。トレイが `TRAY_CAPACITY` 個で満杯なら拾えない（文字はそのまま落ちる。演出は上の揺れ）。キーの場合は、押した文字が落ちているときだけ揺れ、落ちていなければ何も起きない
- トレイの文字をタップ、またはキーの Backspace（最後の 1 文字）で、その文字が捨てられる（得点・時間に影響しない。後ろの文字が前へ詰める）

### 完成

- 文字を拾うたびに完成を判定する。お題を上の行から順に調べ、トレイにそのお題の文字がすべて（重複も数えて）揃っている最初のお題を完成とする。完成したら、そのお題の文字を 1 つずつトレイから取り除き（残りは順番を保って詰める）、得点と時間を足し、その行を新しいお題に入れ替える。入れ替えた新しいお題がすでに揃っていれば、続けて完成にする。完成するお題が無くなるまで繰り返す
- 得点: `SCORE_BY_LENGTH[文字数]`。加算時間: 文字数 × `BONUS_SEC_PER_LETTER` 秒（残り時間に足す。上限は無い）
- 複数のお題が同時に揃うときは、画面で上にある行から先に完成する

### 終わりとスコア

- 勝利は無く、時間が 0 以下になると終わり（失敗条件も同じで、唯一の終わり）。スコア = 完成したお題の得点の合計
- 自己ベスト: ゲーム終了時のスコアが、保存されている自己ベストを超えたら更新し、Result に「NEW BEST!」を出す（同点は更新しない）。記録が無い（保存なし）ときは、スコアが 1 以上なら更新する。スコア 0 のときは更新しない。保存先は `localStorage` のキー `wordfall:best`（数値の文字列）。読んだ値が 0 以上の整数でなければ「記録なし」として扱う。読み書きに失敗したとき（使えない・例外）は、そのセッションの間だけメモリに持ち、Title・Result の `BEST` はそのメモリの値を出す

## 技術要件

- Phaser 4 + Vite + TypeScript。描画は Phaser の Graphics / Text で行い、画像アセットは使わない（スキャフォールドのテンプレートの画像は使わなければ消す）
- ESLint エラー 0、Vitest のカバレッジは 4 指標とも 90% 以上
- Scene は Title / Game / Result に分け、`preload` / `create` / `update` の責務を混ぜない。入力イベントは Scene の終了時に外す。毎フレームの処理は、文字の移動・出現・時間の更新に絞る
- Phaser に依存しない純ロジック（役割ごとのモジュールに分ける）:
  - 単語リストと、お題の抽選（重み付き・重複除外）
  - トレイの操作（拾う・捨てる・満杯の判定・詰める）と、完成の判定・取り除き（重複を数える。複数完成の繰り返し）
  - お題の文字の色の判定（トレイで足りているか）
  - 得点・加算時間・落下の速さ
  - 出す文字の抽選（必要な文字の集計、`NEEDED_RATIO`、おとり）と列の選択
  - 画面の大きさ（論理の高さ、縮小率、案内を出す条件、案内の文字の大きさ）
  - タップ・キーの対象の選択（タップ点に中心が最も近い落下中の文字、同じ距離なら y が大きい方。キーの文字のうち y が最大のもの）、トレイの枠の選択（すき間は近い枠）
  - 場の配置（`FLOOR_Y`・場の高さ・文字が消える位置）と、文字を出す列の選択、Result の一覧のスクロール量の範囲
  - 自己ベストの保存・読み出し（`Storage` を引数で渡す）
  - Result の単語の一覧の組み立て（出た順・重複のまとめ・完成の印）
  - 演出の値の決定（Scene の外の純関数）: ポップアップの文字（`+得点  +秒s`）、ポップアップの開始の遅れ（k 番目）、警告の判定（`WARN_SEC` 以下）、TIME の強調を出す条件（完成した / 警告中に表示が減った / `ending` に入るフレームでは出さない）、演出の進み（経過時間 t と長さ D から 0〜1。t = 0 で 0、t = D と D 以降で 1）と、それに基づく位置・大きさ・不透明度（ポップアップの上昇、完成した行の強調の拡大と薄れ、TIME の強調の往復、拾った文字の飛び）、スコアの数え上げの値（経過時間 → 表示する整数）、拾った文字の行き先の枠の番号、「NEW BEST!」の点滅の不透明度（経過時間 → 値）、ボタンの状態（押している・ホバー・通常）と、離したときに働く条件（登録されたポインタ・ガード・案内・外へ出た・cancel）
  - 1 回の拾いの結果（拾えた / 満杯で拒否 / 無視）と完成した語の列から、どの演出を何回出すか（フラッシュは 1 回、強調とポップアップは語の数、飛びは拾えたときだけ、満杯の手がかりは拒否のときだけ）を決める関数
- 乱数は `rng: () => number`（[0, 1)）を引数で渡す。時間は `dt` を引数で渡す。純ロジックの中で `Math.random` や `Date` を使わない

## テスト観点

- 完成の判定: 同じ文字が 2 つ要る単語（APPLE の P）で、トレイに P が 1 つしか無ければ完成せず、2 つなら完成する。余分な文字があっても完成する。トレイが空なら完成しない
- 完成の取り除き: 取り除くのは 1 文字ずつ（重複の残りは残す）で、残りの順番が保たれる。複数のお題が同時に揃うときは上の行が先。取り除いたあと、新しいお題がすでに揃っていれば続けて完成する（手作業の例を 1 つ作る）
- お題の文字の色: 緑の数がトレイの個数を超えない（足りない分は灰色）
- 抽選: 重み（`LENGTH_WEIGHT`）と除外が効く（`rng` の端の値 0 と 0.999… で、候補の先頭・末尾になる）。3 語が重複しない。リストの全語が選ばれうる
- 出す文字: `rng` が `NEEDED_RATIO` 未満のとき必要な文字、以上のときおとり（境界 0.55 のちょうど）。必要な文字が無いとき常におとり。必要な文字の集計がお題どうしで重複して数えられる
- 得点・時間: 3〜8 文字の得点と加算時間が表どおり
- 落下の速さ: `t` = 0 で 0.25、`t` = 60 で 0.4、`t` = 150 で 0.625、`t` = 152 以上で上限 0.63（超えない）
- 画面の大きさ: 表の 4 つの表示の大きさで、論理の大きさ・縮小率・案内の有無が一致（390 × 844 → 779、375 × 550 → 528、1280 × 720 → 520、667 × 310 → 案内あり、844 × 390 → 案内あり、1024 × 768 → 案内なし）。案内の境界: 600 × 455 は縮小率 0.875 ちょうどで案内なし、600 × 454 は 0.873 で案内あり。縦長の表示には案内が出ない。表示の幅が 0 のとき高さは下限。案内の文字の大きさ: 縮小率 0.596 で 31、縮小率 0.2 で上限 53、縮小率 0 以下で 53
- 対象の選択: 2 つの落下中の文字の的が重なる点で、中心が近い方が選ばれる。同じ距離なら y が大きい方。キーは、同じ文字が 2 つ落ちているとき y が大きい方。トレイの枠のすき間は近い枠。空の枠は何も起きない。トレイが満杯で拾うと拒否され、トレイは変わらない。Backspace が最後の文字を捨てて、空なら何も起きない。捨てたあと後ろの文字が前へ詰める
- 場と列: H = 528 と 779 の `FLOOR_Y`・場の高さ・文字が消える中心 y（378 / 629）。直近の文字が `LETTER_SIZE` 未満しか下がっていない列は選ばれず、ちょうど `LETTER_SIZE` 下がった列は選べる
- Result の一覧のスクロール: 一覧が領域より短いとき 0 に固定、長いとき 0〜(全体 − 領域)、↑ ↓ は `RESULT_ROW_H` ずつ動いて端で止まる
- ガード: Result の開始から `RESULT_INPUT_GUARD_MS` 未満はボタン・キーを無視し、ちょうど経過した時点から受け付ける
- 演出の値: ポップアップの文字が 3 文字の語で `+30  +3s`、8 文字の語で `+230  +8s`。1 回の拾いで 3 語完成したときの開始の遅れが 0 / 120 / 240 ms。警告は TIME の表示 10 で赤、11 で白、0 でも赤（`ending`）。スコアの数え上げは、スコア 350 で t = 0 → 0、300 ms → 175、600 ms → 350、900 ms → 350。スコア 0 は常に 0。拾った文字の行き先の枠の番号 = 拾う前のトレイの文字数（空のトレイで 0、9 文字で 9）。「NEW BEST!」の不透明度は、入力を「点滅の開始（Result 開始から `COUNT_UP_MS` 後）からの経過時間」として、負（点滅の前）で 1、1 回の点滅の中央（150 ms）で `BEST_BLINK_ALPHA`、3 回（900 ms）以降は 1
- ボタン: 押した位置のボタンの上で離したときだけ働く（押して外へ出して離す・外へ出て戻って離す・別のボタンで離す・押さずにホバーだけ・ガード中に押してガード明けに離す・前の Scene で押し始めて離す・押している間に案内が出た・`pointercancel` では働かない）。2 本の指が別々のボタンを押して離したときは、それぞれが自分のボタンで働く（遷移は最初の 1 回だけ）。押している間とホバーの状態の決まり（押している > ホバー > 通常。ガード中・案内中は通常）
- 演出の境界（手計算）: 純関数の進みは直線で、イージングは描画側（tween）がかける。ポップアップの位置（k = 0）は t = 0 で y = 210、t = 300 ms で 190、t = `POP_MS`（600 ms）で 170、不透明度は 1、0.5、0。k = 1 の開始 y は 234、k = 2 は 258。完成した行の強調は t = 0 で 1.0 倍・不透明度 0.7、`COMPLETE_GHOST_MS`（250 ms）で 1.2 倍・0。TIME の強調は t = 0 で 1.0 倍、150 ms で 1.25 倍、300 ms で 1.0 倍。拾った文字の飛びは t = `FLY_MS` で行き先の枠の中心、そこで消える。TIME の強調を出す条件: 完成したフレーム（出す）、表示 11 → 10（出す）、表示 12 → 11（出さない）、表示 10 → 9（出す）、表示 1 → 0 の `ending` に入るフレーム（出さない）、表示 12 → 10 の複数秒（1 回）。警告の色: 表示 10 で赤、11 で白、0 で赤
- 1 回の拾いの結果と演出の回数: 拾えて 0 語完成 → 飛び 1、拾えて 2 語完成 → 飛び 1・フラッシュ 1・強調 2・ポップアップ 2（開始の遅れ 0 と 120 ms）、満杯で拒否 → 手がかり 1・揺れ 1・飛び 0、無視（`ending` 後）→ すべて 0
- 自己ベスト: 更新の条件（超えたとき・同点・スコア 0・記録なしで 1 以上）、`Storage` が例外を投げるとき・壊れた値のとき（"abc"、"-3"、"1.5"）にメモリで動く
- Result の一覧: 出た順・重複のまとめ（2 回出て 1 回完成なら ✓ の 1 行）・未完成の印
- Game の状態: 時間が 0 になるフレームに届いたタップの加算時間が効く、`ending` 以降の入力は無視、`ending` から `RESULT_DELAY` 秒で Result に移る（Scene のグルーは QA で確認）
