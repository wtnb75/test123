# 同時完成ボーナスと狙う文字の手がかり

## 概要

1 回の拾いで 2 語以上が完成したとき（同時完成）に、時間と得点を上乗せする。同時完成を起こせるように、完成で取り除く文字から「他のお題が必要とする字」を除く（規則の本体は `docs/spec.md` の「完成」）。さらに、拾うと同時完成になる文字（リーチ）と、近い状態の文字を、落ちてくる文字の上で光らせて、狙う文字を分かりやすくする。コアループの「どの文字を拾うか」の判断を深める（複数のお題に共通する字を意図して狙う理由ができる）。操作の追加・変更は無い。

## 操作仕様

なし（操作は `docs/spec.md` の「操作仕様」のまま。手がかりは見た目だけで、タップ・キーの対象の選択・的の大きさ `LETTER_HIT_SIZE` を変えない）。

## 画面・Scene構成

Game Scene だけが変わる。Title・Result は変わらない（Result の `WORDS` と単語の一覧は、上乗せの影響を受けない）。

### 手がかりの状態（Game）

手がかりは「状態」であり、トレイ・お題が変わるたびに、次の 2 つの字の集合を求め直す（落ちている文字の位置や数には依らない）。

- 用語: お題のある語について、トレイで足りていない文字（`docs/spec.md`「お題の文字の色」の灰色の文字。重複も数える）の個数を「不足」と呼ぶ。
- **リーチの字**: トレイに空きがあり（満杯だと拾えないので、満杯のときは空集合）、その字 c を A〜Z の 1 つとして拾ったと仮定したとき、**いま画面に出ているお題だけで** 2 語以上が完成する字。求め方は完成の規則そのもの（上の行から順に、揃った語を完成させ、「他のお題が必要とする字は残す」規則で取り除き、完成した行は新しい語に入れ替えず、その行を数えない。残りの語で、揃う語がなくなるまで繰り返し、完成した語の数が 2 以上なら c はリーチの字）。実際の完成では、入れ替えた新しい語が「他のお題」に加わって残す字を増やしうるだけで、残す字が増えても完成は妨げられないので、リーチの字は、実際に 2 語以上が完成することの下限の保証になる。
  - リーチの行: リーチの字のどれかで完成する行（行の番号の和集合）。
- **近い字**: リーチの字ではない字 c のうち、いま画面に出ているお題で c をまだ必要としている語（その語の灰色の文字に c がある）のうち、不足が `NEAR_MAX_SHORT` 以下の語が 2 語以上あるもの（c を必要とする 3 語のうち 2 語の不足が 2 以下で 1 語が 3 なら、近い字になる）。
- 計算は、拾う・捨てる・完成でトレイやお題が変わったフレームの入力の処理のあと（同じフレームの描画の前）に 1 回行う。毎フレームは求め直さない。ゲーム開始時（トレイが空）の状態も同じ規則で求める（このときは、どのお題も不足が 3 以上なので近い字もリーチの字も無い）。`ending` に入ったフレームで、手がかりはすべて消える。

### 見た目（Game）

落ちている文字のうち、文字が「リーチの字」または「近い字」と同じものにだけ手がかりを付ける。トレイの文字には付けない。

| 手がかり | きっかけ | 見た目 | 重なったとき・境界 |
|---|---|---|---|
| 近い字の縁 | 落ちている文字が、近い字と同じ文字である間 | 文字のタイル（`LETTER_SIZE` の正方形。タイル自体は `COLOR.tile` の黄）の縁を、`COLOR.cue`（白）の太さ `NEAR_RIM_W` にする。縁はタイルの内側に描く（静止。動かない） | 近い字は、リーチの字とは重ならない（リーチの字なら下のリーチの見た目だけ）。文字が拾われる・消える・状態が変わると、同じフレームのうちに外れる |
| リーチの字の強調 | 落ちている文字が、リーチの字と同じ文字である間 | ① タイルの縁を、`COLOR.cue`（白）の太さ `REACH_RIM_W` にする（縁はタイルの内側に描き、脈打ちの最大の大きさ 46 を超えない） ② タイルを、その中心を中心に、`1.0` 倍と `REACH_PULSE_SCALE` 倍の間で脈打たせる ③ タイルの後ろ（落ちてくる文字の層の中の、すべてのタイルより奥）に、`LETTER_SIZE + REACH_HALO_PAD` の正方形の光を、`COLOR.accent`・不透明度 `REACH_HALO_ALPHA_MIN` と `REACH_HALO_ALPHA_MAX` の間で脈打たせて敷く | 脈打ちの形・時計は下の「脈打ち」。タップの的は `LETTER_HIT_SIZE` のまま（脈打ちで広がらない）。隣の列のタイルと重ならない（列の間隔 51.4 > 最大の大きさ 40 × 1.15 = 46）。光は隣のタイルの奥に敷くので重なっても文字を隠さない |
| リーチの行の枠 | リーチの行である間 | その行の枠（幅 `SCREEN_WIDTH` − 2 × `REACH_ROW_PAD`、高さ `REACH_ROW_H`、中心 y = その行の英単語の中心 y + `REACH_ROW_DY`）を `COLOR.accent`・太さ `REACH_ROW_RIM_W` の線で描き、不透明度を 1 と `REACH_ROW_RIM_ALPHA_MIN` の間で脈打たせる | 3 行の枠は互いに重ならない（行の間隔 `TARGET_ROW_STEP` 50 > `REACH_ROW_H` 46、枠どうしのすき間 4）。最下行の枠の下端は y = 144 + 9 + 23 = 176 で `FIELD_TOP`（180）より上。枠の線は意味行の文字の下端（意味行の中心 + 7）より下に引く（行 0 で、文字の下端 73、枠の下端 76）ので、文字に触れない。お題の英字・意味行を隠さない（枠は線だけ） |

- 脈打ち: 「リーチの字の集合が空でなくなったフレーム」を t = 0 とする時計を 1 つ持ち、集合が空にならない間は止めない（集合の中身が変わっても続ける）。空になったら時計を捨て、再び空でなくなったら t = 0 から数え直す。脈打ちの値 p(t) は、周期 `REACH_PULSE_MS` の三角波（t = 0 で 0、周期の半分で 1、周期の終わりで 0 に戻る。以降は繰り返す）。タイルの大きさは `1 + (REACH_PULSE_SCALE − 1) × p`、光の不透明度は `REACH_HALO_ALPHA_MIN + (REACH_HALO_ALPHA_MAX − REACH_HALO_ALPHA_MIN) × p`、行の枠の不透明度は `1 − (1 − REACH_ROW_RIM_ALPHA_MIN) × p`。新しく落ちてきたリーチの字のタイルも、その時点の時計の値から始まる。
- 近い字・リーチの字は、同じ文字が複数落ちていれば、そのすべてに付ける。拾った文字の飛びのタイルには付けない（飛びは今までどおり）。
- 手がかりは、拾う・捨てる・完成・満杯の手がかり・タップの結果に影響しない（同じ入力は、手がかりの有無に依らず同じ結果になる）。入力を止めず、遅らせない。
- 描画の順（`docs/spec.md` の順に足す。奥から）: 背景 → 床の線・トレイの説明 → **リーチの行の枠** → お題・意味行 → トレイの枠 → **リーチの字の光** → 落ちてくる文字（縁・脈打ちを含む）→ 拾った文字の飛び → 完成した行の強調 → ポップアップ → HUD → 「縦にしてください」の案内。リーチの行の枠は、お題・意味行より奥なので、完成した行の強調（手前）が重なっても読める。
- 「縦にしてください」の案内の間は、進行が止まり、手がかりの状態は変わらない。脈打ちは案内の下で動き続けてよい。
- 色の見分け: タイルの縁は `COLOR.cue`（白 `#ffffff`。タイルの黄の上で見える色）、光と行の枠は `COLOR.accent`（黄。暗い背景の上で見える色）で、お題の緑（`COLOR.good`）・満杯の赤（`COLOR.warn`）と別。

### 同時完成のポップアップ（Game）

1 回の拾いで完成した語の数 n が 2 以上のとき、`docs/spec.md` の「点数・時間のポップアップ」の語ごとのポップアップ（k = 0〜n − 1）に続けて、k = n 番目として、同時完成のポップアップをもう 1 つ出す。

- 文字: n = 2 は `DOUBLE  +100  +5s`、n = 3 は `TRIPLE  +200  +10s`、n ≥ 4 は `MULTI x4  +300  +15s`（`x` の後は n）。`+` の数字は `MULTI_BONUS_SCORE × (n − 1)`、秒は `MULTI_BONUS_SEC × (n − 1)`。`FONT_POP`・`COLOR.accent` は語ごとのポップアップと同じ。
- 動き・長さ・上昇は語ごとのポップアップと同じ（`POP_MS`・`POP_RISE`）。k = n 番目の開始の遅れは `POP_STAGGER_MS` × n、開始 y は `FIELD_TOP` + `POP_START_BELOW` + `POP_STACK_DY` × n（n = 2 で開始 y = 258・遅れ 240 ms、n = 3 で 282・360 ms）。最長の文字（`MULTI x4  +300  +15s`）でも幅 360 に収まる。
- ほかの演出（フラッシュ 1 回、完成した行の強調とポップアップは語の数）は変えない。TIME の強調は完成のフレームに出る（既存のとおり 1 回）。

## ルール

### 同時完成ボーナス

- 1 回の拾いの中で完成した語の数 n（完成した語が入れ替わった行で続けて完成した語を含む）が 2 以上のとき、通常の語ごとの得点・加算時間に加えて、`MULTI_BONUS_SCORE × (n − 1)` 点と `MULTI_BONUS_SEC × (n − 1)` 秒を、その拾いの入力の処理のうちに 1 回だけ足す。n が 0 または 1 のときは足さない。
- `WORDS`（完成語数）・Result の単語の一覧・自己ベストの判定は、上乗せの有無に依らず今までの規則のまま（`WORDS` は完成した語の数。上乗せ分は含めない。スコアには上乗せの得点が含まれるので、自己ベストにも効く）。
- 上乗せの時間も、残り時間の上限は無い。時間が尽きるフレームに届いた拾いの上乗せも、`docs/spec.md`「同じフレームの順序」のとおり、時間の更新より前に効く。
- 取り除く文字の規則（他のお題が必要とする字を残す）の本体は `docs/spec.md` の「完成」にある。

### 狙う文字の手がかり

上の「手がかりの状態」のとおり。ルール・得点・時間・抽選（出す文字の `NEEDED_RATIO` を含む）・落下には影響しない。

## パラメータ表

| 名前 | 初期値 | 意味・根拠 |
|---|---|---|
| `MULTI_BONUS_SEC` | 5 | 同時完成の上乗せ時間 = この値 × (n − 1)（秒）。3 文字の語 1 つぶん（3 秒）より大きく、同時完成と分かる大きさ。初期値であり、遊んでの調整は `game-balance` |
| `MULTI_BONUS_SCORE` | 100 | 同時完成の上乗せ得点 = この値 × (n − 1)。5〜6 文字の語 1 つぶんに近い大きさ |
| `NEAR_MAX_SHORT` | 2 | 「近い字」の対象にする語の不足の上限（文字数） |
| `COLOR.cue` | `#ffffff` | タイルの縁の色（タイルの黄 `COLOR.tile` と同じ黄では見えないので白） |
| `NEAR_RIM_W` | 3 | 近い字のタイルの縁の太さ（論理 px） |
| `REACH_RIM_W` | 4 | リーチの字のタイルの縁の太さ |
| `REACH_PULSE_MS` | 400 | リーチの脈打ち 1 往復の長さ |
| `REACH_PULSE_SCALE` | 1.15 | リーチの字のタイルが最も大きくなるときの倍率（`LETTER_SIZE` 40 のとき 46。列の間隔 51.4 より小さい） |
| `REACH_HALO_PAD` | 8 | 光の正方形が `LETTER_SIZE` より大きい量（光は 48 で、左端の列でも画面の内側に収まる） |
| `REACH_HALO_ALPHA_MIN` / `REACH_HALO_ALPHA_MAX` | 0.25 / 0.7 | 光の不透明度の範囲 |
| `REACH_ROW_PAD` | 8 | リーチの行の枠の左右の余白（枠の幅 = 360 − 16 = 344） |
| `REACH_ROW_H` | 46 | 枠の高さ（行の英字の中心の 14 上から、意味行の文字の下端より 3 下まで） |
| `REACH_ROW_DY` | 9 | 枠の中心 y が、行の英単語の中心 y より下の量 |
| `REACH_ROW_RIM_W` | 2 | 枠の線の太さ |
| `REACH_ROW_RIM_ALPHA_MIN` | 0.4 | 枠の不透明度の最小 |

H に依らない値（お題の配置は固定）なので、枠の位置は H = 528 でも 779 でも同じ（行 0〜2 の枠の y は 30〜76、80〜126、130〜176）。

## テスト観点

- 取り除く文字（`docs/spec.md`「完成」）: 手計算の例を確認する。
  - お題 CAT・CUP・DOG、トレイ `A T U P C`（C は最後に拾った）→ CAT の完成でトレイ `U P C`、続けて CUP が完成してトレイ `（空）`。他のお題が必要としない字を取り除く例: トレイ `D O G X`、お題 DOG・CAT・SUN → `X`。2 個要る字: トレイ `A P P L E P`、お題 APPLE・PICTURE・DOG → `E P`（P は `max(3 − 2, min(3, 1))` = 1、E は `max(0, min(1, 1))` = 1）。他のお題が必要とする個数が `t − a` より多いとき（a = 1・t = 2・m = 2 → 2 個残る）。他のお題が無い字は従来どおり。取り除く文字は先頭に近いものから、残りの順番は保たれる。
  - 先に完成して入れ替わった新しい語が必要とする字も残す（入れ替わった語を「他のお題」に含める）。取り除く文字が 0 個の完成（W = SUN で、S・U・N をそれぞれ別の他のお題が必要とする）も、得点・時間を足して行を入れ替える。近い字: c を必要とする 3 語のうち 2 語の不足が 2 以下、1 語が 3 → 近い字になる。
- 同時完成の上乗せ（`Round`）: お題 CAT・CUP・DOG（`rng` で入れ替えの語を BIRD・FISH のように、残ったトレイで揃わない語に固定する）、トレイ `A T U P` で `C` を拾う → 完成した語は 2、スコアは 30 + 30 + 100 = 160、残り時間は `START_TIME_SEC` + 3 + 3 + 5 = 71（時間の更新の前）。n = 1 のとき上乗せ 0。n = 3 のとき 200 点・10 秒（`multiBonus(n)` を n = 0・1・2・3・4 で確認: 0/0、0/0、100/5、200/10、300/15）。時間が尽きるフレーム（残り 0.2 秒）に届いた同時完成の拾いの上乗せが効く。`WORDS` は語の数（上乗せを含めない）。
- ポップアップの文字: n = 2 で `DOUBLE  +100  +5s`、n = 3 で `TRIPLE  +200  +10s`、n = 4 で `MULTI x4  +300  +15s`。n = 1 では出さない。開始の遅れ・開始 y（k = n）: n = 2 で 240 ms・258、n = 3 で 360 ms・282。
- 1 回の拾いの結果と演出の回数: 拾えて 2 語完成 → 飛び 1・フラッシュ 1・強調 2・ポップアップ 2 + 同時完成のポップアップ 1（遅れ 0・120・240 ms）。拾えて 1 語完成 → 同時完成のポップアップは 0。
- 手がかりの状態（純関数。トレイ・お題・満杯かどうかから、リーチの字・リーチの行・近い字を返す）:
  - トレイ `A T U P`、お題 CAT・CUP・DOG（空きあり）→ リーチの字 `{C}`、リーチの行 `{0, 1}`、近い字 `{}`。
  - トレイ `A U`、同じお題 → リーチの字 `{}`（C を拾っても完成しない）、近い字 `{C}`（CAT の不足 C・T、CUP の不足 C・P はどちらも 2 以下。DOG は不足 3 で対象外）。
  - トレイが満杯（`A T U P Z Z Z Z Z Z`）、同じお題 → リーチの字 `{}`（拾えない）、近い字 `{C}`。
  - トレイが空、任意のお題 → どちらも空。不足 3 の語だけが C を必要とするときは近い字にならない（`NEAR_MAX_SHORT` ちょうど 2 は含み、3 は含まない）。1 語だけが必要とする字は近い字にならない。
  - リーチの字は近い字に入らない（同じ字が両方に入らない）。リーチの字が 2 つ以上あるとき、リーチの行は和集合。
  - 入れ替えた新しい語はリーチの判定に使わない（現在のお題だけ）。
- 脈打ち `p(t)`: `REACH_PULSE_MS` = 400 のとき、p(0) = 0、p(100) = 0.5、p(200) = 1、p(300) = 0.5、p(400) = 0、p(500) = 0.5、p(600) = 1（周期 400 で繰り返す）。タイルの大きさ: t = 0 で 1.0 倍、t = 200 で 1.15 倍。光の不透明度: t = 0 で 0.25、t = 200 で 0.7。行の枠の不透明度: t = 0 で 1、t = 200 で 0.4。時計: リーチの字の集合が `{}` → `{C}` になったフレームが t = 0、`{C}` → `{C, E}` では数え直さない、`{C}` → `{}` で捨て、再び `{C}` で t = 0 から。
- 手がかりが操作に影響しない: 近い字・リーチの字が落ちていても、タップ・キーの対象の選択、拾えるか（満杯の拒否）の結果は、手がかりが無いときと同じ（対象の選択の関数は手がかりを引数に取らない）。
- 回帰（変えないもの。既存のテストが、取り除く文字の規則を除いて変更なしで通る）: 完成の判定（トレイに揃っている最初のお題、上の行から）、新しいお題の抽選、1 語ごとの得点と加算時間、拾う・捨てる・満杯、落下の速さ、`LETTER_HIT_SIZE`、トレイの上限、時間切れ、`RESULT_DELAY`。他のお題が必要としない字だけで完成する場面（1 語だけが完成する拾い）では、トレイの変化が従来と同じになる。

## 完了条件

- `npm run lint` / `npm run test` / `npm run test:coverage`（4 指標とも 90% 以上）/ `npm run build` が通る。共有ビルド（`SHARED_VENDOR=1`）でも起動する。
- 同時完成が実際に起き、ボーナスが効く: テスト（`Round`）と、QA（確認用にお題とトレイを固定して、`C` を拾うと `DOUBLE  +100  +5s` が出て、スコアと TIME が上乗せ分だけ増える。スクリーンショットと連続撮影）。
- 手がかり（QA のスクリーンショットと連続撮影。375 × 550・390 × 844・1280 × 720）: 近い字が縁だけ付く、リーチの字が強い縁・脈打ち・光で見分けられる、リーチの行の枠が出てお題の英字・意味行が読める、拾う・状態が変わると同じフレームで消える、`ending` で消える。縁・光・枠・ポップアップが画面の外にはみ出さず、HUD・お題・トレイと重ならない。主な情報（`FONT_POP` 18 など）は実寸 14 px 以上（4.6 節）。
- 入力が遅れない: 手がかりが出ている間も、拾う・捨てるはタップの瞬間に決まる（QA: リーチの字のタイルの的の端（`LETTER_HIT_SIZE` の端）でも、脈打ちの大きさに依らず同じ文字が拾える）。
- 変えないもの（回帰条件）: 上の「テスト観点」の回帰のとおり。加えて、同時完成のときも、フラッシュは 1 回、完成した行の強調とポップアップは語の数のまま、同時完成のポップアップが 1 つ増えるだけである。
- 意図した変更（難易度）: 他のお題が必要とする字を残すので、完成しやすくなる。bot（`Round` と同じ規則、60 seed、0.5 秒に 1 回拾う、文字の供給は無制限。落下は含まない）で、完成語数/プレイは何でも拾う bot が 17.9 → 37.4、共通の字を優先する bot が 29.0 → 37.9、同時完成/プレイは 0.00 → 1.92 と 0.03 → 0.48。これは参考の値で、しきい値ではない（人が遊んだ感触は `game-balance` で見る。初期値のまま公開する）。

## 実装裁量

- 縁・光・枠の細かい形（角丸の有無、光のぼかし）。三角波の代わりに、同じ周期・同じ最小最大の滑らかな往復（sin など）にしてもよい（テスト観点の境界の値は、t = 0 で最小、周期の半分で最大、周期の終わりで最小に戻ること）。
- 手がかりの計算を行うモジュールの名前と置き場所、手がかりの状態を Scene へ渡す形。
- 同時完成のポップアップの文字の縁取りなどの細部（色は `COLOR.accent`）。
- 近い字の縁の描き方（タイルの内側・外側）。ただし、タイルの外の大きさ（`LETTER_SIZE`）を超えて隣のタイルに重ならない範囲。
