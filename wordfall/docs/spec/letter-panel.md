# 複数の文字が並んだパネル

## 概要

落ちてくるものに、1 文字ずつのタイルに加えて、2〜3 文字が並んだ「パネル」（例: `ER`、`ING`、`WAT`）を、一定の確率で混ぜる。パネルはタップするとトレイの 1 枠に入り、中の並びは固定で入れ替えられない。お題の綴りの中に、その並びが連続して含まれる語にだけ使える。1 枠で複数の文字を取れる得と、使える語が限られる損の間で、拾うか捨てるかを決める（コアループの「どの文字を拾うか」「何を捨てるか」の判断を深める）。単独の文字の規則・得点・加算時間は変えない。

用語: トレイに入っているものを「要素」と呼ぶ。要素は「単独の文字」（1 文字）か「パネル」（2〜3 文字。長さ k）のどちらか。トレイの枠 1 つに要素が 1 つ入る。パネルが 1 つも無いとき、`docs/spec.md` の規則とこのファイルの規則の結果は、すべて同じになる。

## 操作仕様

操作は `docs/spec.md` の「操作仕様」のまま。パネルについて次を足す。

- パネルは、落ちてくる文字と同じく、タップで拾う（トレイに空きがあれば、トレイの 1 枠に入る）。タップの的は、パネルの中心を中心にした、幅 `k` × `LETTER_HIT_SIZE`・高さ `LETTER_HIT_SIZE` の長方形（k = 2 で 100 × 50、k = 3 で 150 × 50。縮小率 0.89 でも高さは実寸 44.5 px）
- 落ちている要素どうしの的が重なる所をタップしたときは、`docs/spec.md` の規則のとおり、タップした点に中心（パネルは、その長方形の中心）がいちばん近いものを拾う（同じ距離なら y が大きい方）。的に入っていないものは対象にならない。パネルの的と隣の列の単独の文字の的は、横に重ならない（パネルの的の端は、両端の列の中心から外へ `25.7 − 0.7k` ≒ k = 2 で 24.3・k = 3 で 23.6。隣の列の中心はそこから 27.1・27.8 離れ、単独の文字の的の端は中心から 25 なので、すき間は約 2.1・2.8）
- 文字キー（A〜Z）は、単独の文字だけを拾う。パネルは拾わない（キーの対象の選択から外す。パネルしか落ちていない文字キーでは何も起きない。満杯のときの揺れも、押した文字の単独の文字が落ちているときだけ）
- トレイのパネルの枠をタップするか、Backspace（トレイの最後の要素がパネルのとき）で、そのパネルを捨てられる（丸ごと 1 つ。分けて捨てることはできない。得点・時間に影響しない。後ろの要素が前へ詰める）

## 画面・Scene構成

Game Scene だけが変わる。Title・Result は変わらない。Title の説明「トレイは 10 文字まで」も変えない（意図して変えない。10 枠までの意味で読めるので、文言の見直しは別件）。

### 場（Game）

- パネルは、`k` 本の隣り合う列にまたがる。左端の列 `c`（0〜`COLUMNS` − `k`）から出て、中心 x = 列 `c` の中心と列 `c + k − 1` の中心の平均。出る位置の高さ・落ちる速さ・消える規則（下端が `FLOOR_Y` に届いたフレーム）は単独の文字と同じ（上端が `FIELD_TOP` になる位置から出る。`LETTER_SIZE` 四方の文字のタイルと高さが同じ）
- 見た目: 文字のタイルを `k` 個、各列の中心 x に並べ、1 つの帯でつないだ形（帯の幅 = (`k` − 1) × 列の幅 + `LETTER_SIZE`、高さ `LETTER_SIZE`。k = 3 で 142.9 ≤ 3 列の幅 154.3）。文字は `FONT_LETTER`。単独の文字（`COLOR.tile` の黄）と、色と枠（`COLOR.panel` と `COLOR.panelRim`）で区別できる。パネルに手がかり（`docs/spec/multi-complete.md` の縁・光・脈打ち）は付けない
- 描画の順（`docs/spec.md` と `docs/spec/multi-complete.md` の順のうち「落ちてくる文字」の層）: パネルは単独の文字と同じ層に描く（手がかりの光はすべてのタイルより奥、のまま）。パネルと単独の文字の前後は、出た順（あとに出たものが手前）

### トレイ（Game）

- 枠は今までどおり `TRAY_CAPACITY`（10）個。パネルも 1 枠。満杯のとき、パネルも拾えない（拾えない規則・演出〔画面の揺れ・枠の縁の赤〕は単独の文字と同じ）
- 枠の中は、単独の文字は今までどおり 1 文字（`FONT_TRAY`）、パネルは `k` 文字を並べて 1 つのかたまりとして書く（`FONT_TRAY`。k = 3 でも幅 68 の枠に収まる。幅は文字の幅の和で約 40）。パネルの枠は、塗りの色を `COLOR.panel` にして、単独の文字の枠と区別する（空き枠・単独の文字の枠は今までどおり）
- 「トレイの文字をタップで捨てる」の説明は変えない

### 拾った文字の飛び・演出（Game）

- 拾ったパネルも、単独の文字と同じく、その位置から、行き先の枠（拾う前のトレイの要素数 = 枠の番号）の中心へ `FLY_MS` で飛ぶ。パネルのタイル（`k` 個をつないだ形のまま）が、枠に収まる大きさまで縮みながら動き、着いたら消える。きっかけ・時間・描画の順・重なり・`ending` の扱いは、`docs/spec.md` の「拾った文字の飛び」と同じ
- パネルを拾って完成したときの演出（フラッシュ・強調・ポップアップ・TIME の強調）は、語を完成した拾いとして、今までと同じ
- 満杯の手がかり・時間の警告・Result の演出は変えない

### お題の文字の色（Game）

お題の英単語の各文字は、そのお題について、次の「覆い」で決める（他のお題の分とは数えない）。

- 覆い（`covered`）: 語の各位置が、パネルか単独の文字で満たされているか。完成の判定（下）と同じ手順で作る: ① パネルの当てはめ — トレイの要素を前（左）から順に見て、パネルごとに、その並びがその語の綴りに連続して含まれる位置のうち、いちばん左の、すでに当てはまったパネルと重ならないものに当てはめる（その語に当てはまる位置が無いパネルは、この語には使わない）。当てはまったパネルの位置は覆われる ② 残りの位置は、トレイの単独の文字の多重集合で、同じ文字が足りている分だけ、語の先頭から順に覆う（`docs/spec.md` の「お題の文字の色」と同じ数え方）
- 覆われた位置の文字は緑、覆われない位置は灰色

## ルール

### 出現

- 文字を出すたびに（`SPAWN_INTERVAL_MS` ごと。プレイの開始時の 1 つ目も）、まず確率 `PANEL_RATIO` でパネルにするかを決める。パネルにしないとき（残りの確率）は、今までの規則（`docs/spec.md` の「文字」。`NEEDED_RATIO` による必要な文字・おとり、列の選び方）のまま。パネルを出した分、その拍の単独の文字は出ない（パネルも 1 回の出現として数える）
- パネルの長さ k: 確率 `PANEL_LEN3_RATIO`（1/3）で 3、そうでなければ 2
- パネルの文字列: いまのお題 3 語（完成して入れ替わった後の、いま画面に出ている語）から 1 語を等確率で選び、その綴りの連続した k 文字（開始位置は、取りうる位置から等確率）。語の長さが k に満たないときは k を語の長さにする（単語リストの最短は 3 文字なので、現在のリストでは起きない）
- パネルの位置: 左端の列 `c` を、`c` = 0〜`COLUMNS` − `k` のうち、`k` 本の列がすべて「出せる列」（`docs/spec.md` の「文字」: その列の直近の文字〔パネルを含む。パネルは、またがる各列の直近として数える〕が、出た位置から `LETTER_SIZE` 以上下がっている、または無い列）である `c` から、等確率で選ぶ。そのような `c` が 1 つも無いとき（塞がっている列の位置によっては起きる）は、パネルにせず、単独の文字として今までの規則で出す（その拍の出現は単独の文字になる）
- 落ちる速さ・消える規則・拾わなかったものにペナルティが無いことは、単独の文字と同じ
- 乱数の引き方の順は実装裁量（`rng` を引数で渡し、同じ `rng` の列から同じ出現になること）

### 完成の判定

- 文字・パネルを拾うたびに、`docs/spec.md` の「完成」のとおり、お題を上の行から順に調べる。「トレイにそのお題の文字がすべて揃っている」を、次の「覆い」で言いかえる: そのお題の語のすべての位置が覆われる（お題の文字の色が、語の全文字で緑になる）とき、完成とする
- 覆いは上の「お題の文字の色」の手順（パネルの当てはめ → 単独の文字）。パネルは、前から順に、最も左で重ならない位置に当てはめる。当てはまる位置があるのに他の位置の組み合わせなら別のパネルも使えるとき（例: TREASURE で、トレイが `RE`、`EA`、`T`、`R`、`S`、`U` のとき、`RE` が先に 1〜2 文字目に当てはまり、`EA`〔2〜3 文字目〕は重なって使えない。位置を変えて `RE` を 7〜8 文字目にすれば `EA` も使えるが、探さない）も、探さない。このとき、この語は完成しない（あとから `A` と `E` の単独の文字を足せば完成する）
- 使えるパネルは、使えるだけ使う（上の手順で当てはまったパネルは、すべて使う。使わないでおくことは選べない）
- 1 回の拾いで、完成するお題が無くなるまで繰り返す点（入れ替えた新しい語がすでに揃っていれば続けて完成）は `docs/spec.md` のまま
- 得点・加算時間・同時完成の上乗せ（`docs/spec/multi-complete.md`）は、語の文字数から決まり、パネルの有無・使ったパネルの数に依らない（変えない）

### 取り除く

完成した語 W（上の覆いで、パネルが当てはまり、単独の文字が覆った）について、トレイから次を取り除く。

- 当てはまったパネル: すべて丸ごと取り除く。他のお題がその並びを必要としていても、取り除く（分割できない）
- 当てはまらなかったパネル（W に使えないもの）: 残る
- 単独の文字: `docs/spec.md` の「取り除く文字（他のお題が必要とする字は残す）」の式を、次の読み替えで使う。字 x ごとに、`a` = W のうち、パネルに覆われなかった位置の x の個数、`t` = トレイの単独の文字の x の個数、`m` = 他のお題（W 以外の 2 語。先に完成して入れ替わった行は新しい語。綴り全体）それぞれの中の x の個数の最大。完成のあとにトレイに残す x は `max(t − a, min(t, m))` 個。取り除く x は、トレイの先頭に近いものから選ぶ
- 残る要素の順番は保たれ、前へ詰める
- 取り除く要素が 0 個になる完成（W のすべての位置が単独の文字で覆われ、それがすべて他のお題に必要とされる）も、完成として数える（`docs/spec.md` のとおり）

### 手がかり（`docs/spec/multi-complete.md`）の読み替え

`docs/spec/multi-complete.md` の「リーチの字」「近い字」は、トレイの要素（単独の文字とパネル）で求める。

- 用語「不足」: 語の位置のうち、上の覆いで覆われない位置の数
- リーチの字: トレイに空きがあるとき、A〜Z の 1 つの単独の文字 c を拾ったと仮定して（要素を 1 つ足して）、いま画面に出ているお題だけで 2 語以上が完成する字。完成の規則・取り除く規則は、このファイルの「完成の判定」「取り除く」を使う（完成した行は新しい語に入れ替えない）
- 近い字: 手がかりの規則のまま、「不足」と「その語が c を必要とする（覆われない位置に c がある）」をこの読み替えで数える
- 手がかりは、落ちている単独の文字にだけ付く。パネルには付けない。パネルを拾う操作は、手がかりを前提にしない

### 変えないもの

次は、パネルが 1 つも出ない・拾われないプレイで、今までと同じになる（「テスト観点」「完了条件」の回帰）: 得点・加算時間・同時完成の上乗せ、お題の出し方（抽選）、単語リスト、トレイの枠の数（`TRAY_CAPACITY` = 10）、トレイの下の配置、Result（`WORDS`・単語の一覧・自己ベスト）、タップの的（単独の文字の `LETTER_HIT_SIZE`、トレイの枠）、入力の反応（拾う・捨てるはタップの瞬間に決まり、演出を待たない）、文字キーの動き（単独の文字だけを拾う）。

## テスト観点

純ロジック（Phaser 無し）で確かめる。

- 覆い・完成の判定（手計算）:
  - WATER、トレイ `W A T ER`（`ER` はパネル）→ 完成。トレイ `W A T E R` → 完成（単独の文字だけ。従来と同じ）。トレイ `ER`、`E` → 完成しない（`W A T` が不足）。トレイ `RE`（WATER に `RE` は含まれない）と `W A T E R` → 完成する。`RE` は使われず残る
  - 位置の規則（TREASURE の `RE` は 2〜3 文字目と 7〜8 文字目の 2 か所）: トレイ `RE RE T A S U` → 完成（1 つ目の `RE` が 2〜3 文字目、2 つ目が 7〜8 文字目）。トレイ `RE T R E A S U`（パネル 1 つと単独の文字）→ 完成
  - 先に当てはめて他が使えない例（TREASURE = T R E A S U R E。`EA` は 3〜4 文字目）: トレイ `RE EA T R S U` → 完成しない（`RE` が 2〜3 文字目に当てはまり、`EA` は重なるので使われない。残る A・E が単独の文字に無い）。トレイ `EA RE T R S U`（順を替える）→ `EA` が 3〜4 文字目、`RE` は 2〜3 文字目が重なるので 7〜8 文字目に当てはまり、残り T・R・S・U が単独の文字で覆われて完成する（パネルの順で結果が変わることの確認）
  - 3 文字のパネルが語の全体: CAT、トレイ `CAT` → 1 つの拾いで完成。パネルが綴りに含まれない `ACT` → 完成しない
  - パネルを足りないだけの要素と混ぜる: APPLE（P が 2 つ）、トレイ `PP A L E` → 完成。トレイ `PP A L` → 完成しない
  - トレイが空・満杯のとき: 空では完成しない。満杯でパネルを拾うと拒否され、トレイは変わらない
- お題の文字の色: 覆われた位置が緑、覆われない位置が灰色。パネルが当てはまらない語では、そのパネルの文字は緑にならない。緑の数は語の文字数を超えない。パネルが使えない語では、単独の文字の覆い方は従来と同じ（`docs/spec.md` の数え方）
- 取り除く:
  - 当てはまったパネルは丸ごと取り除かれ、使えないパネルは残る（トレイ `ER W A T XY`、お題 WATER・CAT・DOG → 完成のあとトレイ `XY`。ただし `A`・`T` は CAT が必要とする字なので、`A T` は残り、トレイ `A T XY`。W は他のお題が必要としないので取り除く。`ER` は丸ごと取り除く。残る順番は `A T XY` の順）
  - 単独の文字の「他のお題が必要とする字を残す」式が、パネルに覆われなかった位置の個数で働く: WATER、トレイ `ER W A T T`（単独の T が 2 つ）、お題 WATER・TOP・DOG → W の `a` = 1・`t` = 1（取り除く）、A の `a` = 1・`t` = 1（取り除く）、T の `a` = 1・`t` = 2・`m` = 1 → `max(1, min(2, 1))` = 1 個残る。トレイは `T`
  - パネルが他のお題の並びを必要としていても、使ったら丸ごと取り除く（分割しない）
  - パネルが無いトレイでは、取り除く結果が従来と同じ（`docs/spec.md` のテスト観点の例がそのまま通る）
  - 取り除く要素が 0 個の完成も、完成として数える
- 同時完成（`Round`。入れ替えの語は、揃わない語に固定する）: お題 CAT・CUP・DOG、トレイ `UP`（パネル）`A T`、単独の `C` を拾う → CAT が先に完成（C は CUP が必要なので残り、A・T が取り除かれる）、トレイ `UP C` で CUP が完成（`UP` が丸ごと取り除かれ、C も取り除かれる）→ 完成した語は 2、トレイは空、スコアは 30 + 30 + 100 = 160、残り時間は `START_TIME_SEC` + 3 + 3 + 5。パネルを 1 つ使った完成でも、語ごとの得点・加算時間・上乗せは語の文字数だけで決まる。パネルを拾って完成する例: お題 CAT・CUP・DOG、トレイ `T`、パネル `CA` を拾う → CAT が完成し、トレイは空（`CA` は丸ごと取り除かれ、T は他のお題が必要としないので取り除かれる）
- 出現: `rng` を固定して、`PANEL_RATIO` 未満でパネル、以上で単独の文字（境界 0.15 のちょうど）。パネルの長さは、`PANEL_LEN3_RATIO` の境界（1/3 未満で 3、以上で 2）。パネルの文字列が、選んだ語の綴りの連続した部分になる（WATER の `ER`・`WAT`・`ATE`・`TER` などの開始位置が等確率に取れる。`rng` の端の値 0 と 0.999… で、先頭・末尾の位置）。お題 3 語から 1 語が等確率で選ばれる（端の値で先頭・末尾の語）。語の長さが k に満たないとき k が語の長さになる
- パネルの位置: 塞がっている列が無いとき、`c` が 0〜`COLUMNS` − `k` から等確率（k = 3 で 5 通り、k = 2 で 6 通り）。塞がっている列がある `c` は選ばれない。塞がり方によって `c` が 1 つも無い（COLUMNS = 7、k = 3 で、列 2 と 5 が塞がっている）とき、パネルにならず単独の文字になる。パネルがまたがる列は、直近の文字の位置が `LETTER_SIZE` 未満の間、それぞれ塞がる（ちょうど `LETTER_SIZE` 下がったら出せる）。中心 x は両端の列の中心の平均（k = 3、`c` = 0 で列 0〜2 の中心の平均 = 列 1 の中心）
- 的・選択: パネルの的が `k` × `LETTER_HIT_SIZE` × `LETTER_HIT_SIZE`（k = 2 で 100 × 50、k = 3 で 150 × 50）。パネルの的の内側（パネルの中心から横に `25k − 1`。k = 2 で 49、k = 3 で 74）をタップするとパネルが拾え、的の外（`25k + 1`。k = 2 で 51、k = 3 で 76。ほかの要素の的に入らない点）では拾えない。単独の文字の的とパネルの的が重ならない配置で、隣の列の文字が拾われない。重なる配置（同じ列の上下）では、中心が近い方、同じ距離なら y が大きい方が拾われる。文字キーは、同じ文字が単独で落ちていればそれ（y が最大）を拾い、パネルは対象にならない。パネルしか無い文字キーでは何も起きず、満杯の揺れも出ない
- 捨てる: パネルの枠をタップしてパネルが 1 つ丸ごと捨てられ、後ろの要素が前へ詰める。Backspace が最後の要素（単独の文字でもパネルでも）を 1 つ捨てる
- 手がかり（`docs/spec/multi-complete.md` の読み替え）: お題 CAT・CUP・DOG、トレイ `UP`（パネル）`A T`（空きあり）→ リーチの字 `{C}`、リーチの行 `{0, 1}`（上の同時完成の例と一致する）。トレイ `CA`（パネル）`U P` → リーチの字 `{}`（`T` を拾うと CAT だけが完成し〔`CA` は丸ごと取り除かれる〕、`C` を拾うと CUP だけが完成する〔`CA` は CUP に当てはまらず残る〕。どちらも 1 語）。不足は覆いで数える（トレイ `CA` で CAT の不足は 1〔T〕）。リーチの字の判定が、このファイルの完成・取り除く規則と矛盾しない
- 回帰: パネルが無いトレイとお題で、完成の判定・取り除く・手がかりの結果が、従来のテスト（`wordfall` の既存の単体テスト）と同じ（既存のテストが、変更なしでそのまま通る）。`WORDS`・Result の一覧・自己ベスト・得点・加算時間・トレイの上限・時間切れ・`RESULT_DELAY` が変わらない
- 自動プレイ（測る。しきい値ではなく報告）: `Round` を固定 dt・seed 付き乱数で動かす単純な bot（必要な文字・パネルを何でも拾う。タップ間隔 0.35〜1.2 秒・60 seed）で、完成語数と得点を、パネルあり・なしで比べる

## 完了条件

- `npm run lint` / `npm run test` / `npm run test:coverage`（4 指標とも 90% 以上）/ `npm run build` が通る。共有ビルド（`SHARED_VENDOR=1`）でも起動する
- パネルが場に出て、見分けられる（QA のスクリーンショット。375 × 550・390 × 844・1280 × 720。パネルが単独の文字と色・枠で区別でき、場の左右・床・お題・トレイと重ならず、文字が読める）
- パネルをタップしてトレイの 1 枠に入り、枠の中に `k` 文字が 1 つのかたまりとして読める（3 文字でも枠に収まる）。枠をタップして捨てられる。トレイが満杯のとき、パネルを拾えず、揺れと枠の縁の赤が出る
- パネルで語が完成する（QA: 確認用にお題とトレイを固定して、パネルを拾うと完成し、スコアと TIME が加算され、お題の文字の色が覆いのとおりに変わる。`__qa` で確かめる）。使えないパネルは残る。使ったパネルは丸ごと消える
- 文字キーはパネルを拾わない（テスト）。キーの動き・的の大きさ（単独の文字、トレイの枠）が変わらない
- パネルが出ている間も、入力が遅れない（QA: パネルを拾った直後 100 ms 以内に、次の文字をタップして、トレイに入ることを `__qa` で確かめる）。パネルの端（中心から横に `k` × 25 − 1 の点）をタップして拾える（QA）
- 変えないもの（回帰条件）: 「ルール」の「変えないもの」のとおり。パネルが出ないプレイ（`PANEL_RATIO` = 0 の確認用の設定）で、既存のテストが変更なしで通る
- 意図した変更（難易度）: 完成が速くなる（`docs/spec/multi-complete.md` の意図した変更と同じく、参考の値で、しきい値ではない）。自動プレイの数字（完成語数・得点）を PR 本文に載せる。完成語数がパネルなしに比べて 3 割を超えて増えるか減るときは、オートパイロットでは止めてユーザーに聞く。人が遊んだ感触は `game-balance` で見る（初期値のまま公開する）
