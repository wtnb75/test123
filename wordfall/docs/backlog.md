# 文字集め（`wordfall`）の拡張候補（backlog）

公開済みの `wordfall` に足せる候補を、上から順に並べたものです。上のカードが「次の候補」です。仕様（`spec.md`）ではありません。新しいゲームのアイデアは `docs/ideas.md` に書きます。

- 規模: S = 1 つのファイルや画面の追加程度、M = 複数のファイル・仕組みにまたがる追加、L = 大きいので、game-extend で 1 PR 分に切り出してから採用する。
- 1 つのカードは 1 つの目的にする（1 変更 1 目的）。
- 自動プレイの数字は、`Round` を固定 dt・seed 付き乱数で動かした単純な bot（60 seed）の結果。人の感じ方は分からない。

### 複数の文字が並んだパネルが落ちてくる（`letter-panel`）

- 狙い: 落ちてくるものが全時間帯で 1 文字だけで、拾い方・場の見え方が最初から最後まで変わらない。トレイの枠（10）も、1 文字 = 1 枠のままで、配置の工夫が生まれにくい。根拠: spec「文字」「拾う・捨てる」、ユーザーの案
- 何を足すか: 2〜3 文字が並んだパネル（例: `ER`、`ING`）を、一定の確率で落とす。パネルをタップするとトレイの 1 つの枠に入り、中の文字の並びは固定で入れ替えられない。お題の綴りの中に、同じ並びが連続して含まれる語にだけ使える（例: `ER` は WATER・RIVER には使えるが、TREE の `RE` の並びには使えない）。
- コアループへの効き方: 深める — 1 枠で複数の文字を取れる得と、使える語が限られる損の間で、拾うか捨てるかを決める。広げる面もある: 落ちてくるものに種類が増える。
- 種別: gameplay
- 規模: M
- 出どころ: ユーザー
- メモ: 決めること — (1) パネルの文字列をどう選ぶか（お題の部分列から作るか、固定の一覧か）、(2) 使えない語のお題しかないとき、パネルを捨てられるか、(3) 完成の判定（`findCompletable`）を「文字の多重集合」から「並びを含む」へ広げるときの扱い、(4) タップの的の大きさ（パネルは幅が広がる）、(5) 場の列数 7 と重ならない出し方。トレイの枠の数と `TRAY_CAPACITY` は同じ値に保つ（spec「パラメータ表」）。(1)〜(5) は 2026-11-15 の対話で決めた（下の合意）。
- 状態: 着手可（2026-11-15、基準 `0a87e89`）
- 合意:
  - 足すもの:
    - 出現: 文字を出すたびに、確率 `PANEL_RATIO` = 0.15 で「パネル」にする（残り 85% は今の規則のまま）。パネルの長さは、2 文字が 2/3・3 文字が 1/3（`PANEL_LEN3_RATIO` = 1/3）
    - 文字列の選び方: 出すときに、いまのお題 3 語のうち 1 語を等確率で選び、その綴りの連続した 2〜3 文字（位置も等確率）をパネルにする（例: WATER の `ER`・`WAT`）。語が短くて 3 文字が取れないときは 2 文字にする
    - 場: パネルは `k` 文字ぶんの幅（`k` × 列の幅）で、左端が列の境目にそろい、収まる列の組（0〜`COLUMNS` − `k`）から等確率で出る。落ちる速さ・消える規則は文字と同じ。縦に重なる文字がいる場合のタップは、今の「最も近い中心」の規則に従う
    - 拾う・捨てる: タップで、トレイの 1 つの枠（`TRAY_CAPACITY` の 1 個ぶん）に入る。パネルの的は、`k` × `LETTER_HIT_SIZE` の幅・`LETTER_HIT_SIZE` の高さ。トレイでは、枠の中に `k` 文字を 1 つのかたまりとして書く（順は固定で入れ替えられない）。トレイの枠をタップするか Backspace で、ほかの文字と同じく捨てられる（満杯で拾えない規則・演出も同じ）。文字キーで拾う操作はパネルを拾わない（単独の文字だけ）
    - 完成の判定: トレイの要素（単独の文字とパネル）で、お題の語を満たせるとき完成。パネルは、語の綴りの連続した部分に一致するときだけ使え、使うパネルどうしは重ならない。語の残りの文字は、トレイの単独の文字の多重集合で満たす。使えるパネルは、使えるだけ使う（左から順に当てはめる）
    - 取り除く: 使ったパネルは丸ごと取り除く（分割できない）。使わなかったパネルは残る。単独の文字は、今の規則（他のお題が必要とする字を残す）のまま。得点・加算時間（長さによる）は変えない
    - お題の文字の色: 緑にするのは、パネルの当てはめと単独の文字で満たされている文字（完成と同じ判定で決める）
    - 一覧・Result: 変更なし
  - 操作: 上のとおり（タップ・キーの操作は変えない）
  - 見た目と初期値の方向: パネルは文字のタイルを `k` 個つないだ見た目で、単独の文字と区別できること（色・枠など）。トレイの枠の中の文字は読めること（3 文字でも枠の幅に収まる）。初期値は `PANEL_RATIO` 0.15・`PANEL_LEN3_RATIO` 1/3。数値は `game-balance` で調整してよい
  - 変えないもの: 得点・加算時間、お題の出し方、単語リスト、トレイの枠の数（10）、トレイの下の配置、Result、タップの的（文字・枠）、入力の反応
  - 意図して変えるもの: 完成が速くなる（難しさが下がる）。完成の判定・色の判定が「並びを含む」に広がる。落ちてくるものにパネルが増える
  - 測ったこと: 未測定（実装してからでないと測れない）。実装後に、`Round` を固定 dt・seed 付き乱数で動かす単純なボット（必要な文字を何でも拾う。タップ間隔 0.35〜1.2 秒・60 seed）で、完成語数（いまは 12〜18 語）・得点を新旧で比べ、PR 本文に載せる。完成語数が 3 割を超えて増える（または減る）ときは、`game-autopilot` は止めてユーザーに聞く
  - spec の置き場所: 新しい `docs/spec/letter-panel.md`（パネルの規則・完成の判定と取り除き・場・的・パラメータ・テスト観点）。`docs/spec.md` の「文字」「拾う・捨てる」「完成」「お題の文字の色」「パラメータ表」「拡張」の節を、参照と改訂で直す
  - ブランチ: `feat/wordfall-letter-panel`

### 単語リストを増やす（`more-words`）

- 狙い: 単語リストは 37 語（3〜8 文字を各 6 語前後）で、1 回の遊びで 12〜18 語が完成するので、数回遊ぶと同じ語が出る。英単語を覚える目的のターゲットには、すぐに見飽きる。根拠: spec「単語リスト」、非MVP範囲（単語リストの追加）、自動プレイ（完成 12〜18 語。必要な文字を何でも拾う bot、タップ間隔 0.35〜1.2 秒、60 seed）
- 何を足すか: 単語を 80〜120 語程度に増やす（意味つき）。各文字数の個数と `LENGTH_WEIGHT` は今のバランスを保つ。
- コアループへの効き方: 広げる — ルールは変えず、お題の幅を広げて、遊ぶたびに新しい語に出会えるようにする。
- 種別: gameplay
- 規模: M
- 出どころ: spec 分析・自動プレイ
- メモ: 文字の出方（A〜Z を一様に出すおとり）に対し、語に偏りが出ないかを確かめる。リストを切り替える機能（非MVP範囲）は含めない。

### 単語帳（`wordbook`）

- 狙い: 出た単語と意味の一覧が、Result の 1 回分で消える。英単語を覚えたい人（ターゲットプレイヤー）には、遊んだ単語を後から見直す手段が無い。根拠: spec「ターゲットプレイヤー」「Result」、非MVP範囲（単語帳）
- 何を足すか: 完成した単語を `localStorage` に記録し、Title から開ける一覧画面で、単語と意味を見直せる。
- コアループへの効き方: 広げる — ゲームの外に「覚えた語が増える」目標が見える。ルールは変えない。
- 種別: presentation-only
- 規模: M
- 出どころ: spec 分析
- メモ: 保存の形は、`shared/best-store` の README の約束（`<game-dir>.<名前>` のキー）に合わせる。保存が使えない環境では、そのセッションの間だけメモリに持つ（`shared/best-store` の自己ベストと同じ方針）。ランキングは含めない（非MVP範囲）。

### 一時停止（`pause`）

- 狙い: 制限時間が 1〜2 分の遊びで、止める手段が無い。スマホの着信や通知で中断すると、そのまま時間が減る。根拠: spec「ルール」「終わりとスコア」、非MVP範囲（一時停止）
- 何を足すか: Game 中に一時停止して再開できるボタンと、キー操作（例: Esc）を足す。
- コアループへの効き方: 広げない — 中断への備え。ルールは変えない。
- 種別: presentation-only
- 規模: S
- 出どころ: spec 分析
- メモ: タブを切り替えたときの動き（Phaser が止めるか）は spec に書かれておらず、未確認。先に実機で確かめる。 自動の停止（画面が隠れた・フォーカスが外れた）は `pause-resume` のカード。同じ `PauseState` に載せるので、`pause-resume` の後にする。

### 意味から綴るモード（`spell-from-meaning`）

- 狙い: お題は英単語と意味が同時に見えるので、見ながら文字を拾えば遊べる。綴りを思い出す必要が無く、覚えるための手がかりが弱い。根拠: spec「コアループ」「お題」、非MVP範囲（意味から綴る出題）
- 何を足すか: 意味だけを見せ、英単語は伏せる別のモードを足す（ヒントの出し方は game-extend で決める）。
- コアループへの効き方: 深める — 拾う文字を、綴りの記憶から決める。
- 種別: gameplay
- 規模: L
- 出どころ: spec 分析
- メモ: 大きいので、game-extend で 1 PR 分（例: 最初は Title から選ぶ 1 モードだけ）に切り出してから採用する。難易度の選択（非MVP範囲）と混ぜない。

### 効果音（`sfx`）

- 狙い: 拾う・完成・トレイ満杯・残り 10 秒の警告が、画面の見た目だけで伝わる。画面を見続ける遊びなので、すき間時間に遊ぶ人が気づきにくい。根拠: spec「演出・UI」、非MVP範囲（効果音）
- 何を足すか: 拾う・完成・満杯・警告の効果音を、Phaser 標準のサウンドで足す。消音の手段（Title のボタンなど）と、保存を決める。
- コアループへの効き方: 広げない — 反応の手がかりを増やすだけ。ルールは変えない。
- 種別: presentation-only
- 規模: S
- 出どころ: spec 分析
- メモ: BGM は含めない。音声ファイルを使うと配布物が増えるので、WebAudio で作るか、短いファイルにするかを決める。

### 戻ったときに操作してから再開する（`pause-resume`）

- 狙い: 文字が落ち続け、残り時間が減るのに、タブを離れても止まらない（spec の非範囲に「一時停止」）。根拠: ユーザーの声（復帰時に突然再開されるゲームがある。フォーカス外れとスマホで動作を揃えたい）、`wordfall/docs/spec.md`（残り時間 60 秒。一時停止は非範囲）
- 何を足すか: ページが見えなくなった（`HIDDEN`）かウィンドウがフォーカスを失った（`BLUR`）とき、ゲームの時間を止めて幕を出す。戻っても勝手には再開せず、タップかキーを押したときに、止まった続きから再開する。再開に使った操作は、それだけで終わる（打つ・動くなどのゲームの操作にはならない）。
- コアループへの効き方: 広げない — 復帰時の不意の失点・失敗を防ぐ。コアループそのものは変えない。
- 種別: gameplay
- 規模: S
- 出どころ: ユーザー
- メモ: `shared/pause` の `PauseState` を使う（absorb が先例。入れる順はルート `docs/backlog.md` の `pause-rollout`）。spec は `absorb/docs/spec/pause.md` と同じ形（`docs/spec/pause.md`）に分ける。
