# Title とデモ

## 概要

Title を「ゲーム名・デモの窓・自己ベスト・START」の並びにし、窓の中で、ボットが本物の `Run`（`stepRun`）と同じルールで遊ぶ縮小盤面を流す。「敵の玉を受けると自分の玉になり、それで敵を倒す」ことが、遊ぶ前に見て分かる。遊び方の文章（これまでの説明 4 行）は Title から無くなる。ルール・数値・操作・Game・Result は変えない。デモは見せるだけで、何も保存しない。

## 操作仕様

- デモは操作を受け付けない（窓の上のタップ・ドラッグ・キーはデモを動かさない）。Title の操作は、デモの再生中・透明化中も変わらず働く。
- 開始: START ボタンのタップ / クリック（ボタンの上で押して、ボタンの上で離したとき）、Enter / Space（押した瞬間。押しっぱなしのリピートと、Title に入る前から押されていたキーは反応しない）。これまでと同じ（[docs/spec.md](../spec.md) の「操作仕様」）。
- 開始の要求は最初の 1 回だけ有効にする（`TitleDemoRunner.requestStart()` が `true` を返した 1 回だけ Game を始める）。「画面を縦にしてください」の案内が出ている間は、要求を出さない（入力を受け付けない。これまでと同じ）。受け付けたあとは、デモの時計も `Run` も進めない。
- Title に何秒いても、開始したあとの Game は最初の状態から始まり、時間は削られない（Game の進行は `delta` で数えていて、`this.time.now` を使わない。Title の時計も `delta` で数え、`this.time.now` を使わない）。
- Title の Enter / Space のキー登録は、Title の `shutdown` で外す（これまでと同じ。`onKeyPress` が外す）。デモは入力のリスナーを持たない。

## 画面・Scene 構成

Scene は増えない（Title / Game / Result）。デモは Title の中に描く。

### レイアウト

論理サイズは 540 × H（H は `computeScreenSize`。[docs/spec.md](../spec.md) の「画面の大きさ」）。デモ用の `Run` の高さは `DEMO_FIELD_HEIGHT`（630）に固定し、H に関係なく同じ盤面を遊ぶ。窓に映すのは、`Run` の上の壁の上端（y = `DEMO_CROP_TOP` = `FIELD_TOP` − `FRAME_WIDTH` = 56）から下だけで、それより上の、何も描かれない空き（ゲームでは HUD の帯にあたる）は映さない。映す高さは `DEMO_VIEW_HEIGHT` = 630 − 56 = 574。

- 窓の倍率 `s = min(DEMO_MAX_WIDTH / 540, availH / 574)`。`availH = 0.8H − 225`（窓を置ける帯の高さ。帯は `y = DEMO_TOP` から `0.8H − 113` まで）。
- 窓の大きさ（論理 px）は `540s × 574s`。横は画面の中央（`x = 270 − 270s`）。縦は帯の中で中央（`y = DEMO_TOP + (availH − 574s) / 2`）。
- `s ≥ DEMO_MIN_SCALE`（0.30）のときだけ窓を出す。`s` が満たないときは窓を出さず、ゲーム名を `0.17H`、自己ベストを `0.56H` に置く（これまでの Title の並びから、説明を除いたもの）。判定は `availH / 574` を使う（`DEMO_MAX_WIDTH / 540` は 0.926 で、0.30 より大きいので、満たない側は高さで決まる）。
- 窓を出すときの各要素（論理 px）:

| 要素 | 位置 |
|---|---|
| ゲーム名 | 中心 (270, `TITLE_NAME_Y` = 70)。`TITLE_FONT_SIZE`（上端 46〜下端 94） |
| 窓 | 上の式。上端は `DEMO_TOP`（112）以上。外側に `DEMO_BORDER`（2）px の明るい灰色の枠 |
| 自己ベスト | 中心 (270, 0.8H − 82)。`HUD_FONT_SIZE`。文字の上端は中心の `TITLE_BEST_HALF_HEIGHT`（15）上 |
| START ボタン | 中心 (270, 0.8H)。`BUTTON_WIDTH` × `BUTTON_HEIGHT`（上端 0.8H − 42）。画面の下 1/3 |

要素どうしの間（内容の矩形で数える。窓の外側の枠 `DEMO_BORDER` はその外側にはみ出すので、実際の間は枠の分だけ 2 px 狭い）: ゲーム名の下端 94 < 窓の上端（112 以上）、窓の下端 ≤ 自己ベストの上端 − `DEMO_BEST_GAP`（16）= 0.8H − 113、自己ベストの下端 = 0.8H − 67 < START の上端 0.8H − 42。重ならない。

- 窓の中の位置 = (窓の x + `Run` の x × `s`, 窓の y + (`Run` の y − `DEMO_CROP_TOP`) × `s`)。`Run` の x は 0〜540、y は 56〜630 で、`Run` の (0, 56) が窓の左上（上の壁の上端が窓の上端と重なる）。敵・玉・パドルは Game と同じテクスチャ（`makeTextures`）を `s` 倍で描く。
- 窓の中の描画（奥から）: 窓の背景（暗い色。窓の矩形の全体）→ 場の枠（左右の壁 x = 0〜`FRAME_WIDTH` と 540 − `FRAME_WIDTH`〜540、上の壁 y = `FIELD_TOP` − `FRAME_WIDTH`〜`FIELD_TOP`。Game の `drawFrame` と同じ位置で、下は開けたまま）→ 危険ライン（`Run.dangerY` に薄い赤の点線。Game と同じ点線）→ 編隊 → パドル → 敵の玉 → 自分の玉（段の色）。窓の外には何も描かない（下端から出ていく玉は窓の下端で切る）。窓の枠は窓の内容の外側（内容と重ならない）で、窓の下に敷く帯（実装裁量）より手前に描く（下端の枠が帯に隠れて途切れない）。
- 窓の中にスコア・ライフ・WAVE の文字・Game の演出（倒したときの白い四角、「+N」、受けたときの輪・光、赤い重ね、画面の揺れ）は出さない。倒された敵は消える、受けた玉はその場で自分の玉の色になる、だけを見せる。
- 画面の大きさが変わると、Title は Scene ごと並べ直される（これまでの仕組みどおり。[docs/spec.md](../spec.md) の「画面の大きさ」）。デモはその Scene の始まりで、時計 0 の新しい走りから始まる（並べ直しのときはフェードしない）。
- 「画面を縦にしてください」の案内が出ている間も、デモの時計と `Run` は進め続ける（案内の下に隠れる。入力は止まる）。

| 画面 | H | 実寸の倍率 | availH | s | 窓（論理） | 窓の上端 | 窓（実寸） | 敵 1 体（実寸） | 玉の直径（実寸） |
|---|---|---|---|---|---|---|---|---|---|
| 375 × 550（iPhone SE Safari 縦） | 792 | 0.694 | 408.6 | 0.7118 | 384.4 × 408.6 | 112 | 267 × 284 | 27.7 × 14.8 | 8.9 |
| 390 × 844（スマホ縦） | 1169 | 0.722 | 710.2 | 0.9259 | 500 × 531.5 | 201.4 | 361 × 384 | 37.4 × 20.1 | 12.0 |
| 1280 × 720（PC） | 756 | 0.952 | 379.8 | 0.6617 | 357.3 × 379.8 | 112 | 340 × 362 | 35.3 × 18.9 | 11.3 |
| 667 × 310（SE 横） | 756 | 0.410 | 379.8 | 0.6617 | 357.3 × 379.8 | 112 | 案内が全面を覆う（入力は止まる） | – | – |
| 境界の上（H = 497） | 497 | – | 172.6 | 0.3007 | 162.4 × 172.6 | 112 | 窓を出す | – | – |
| 境界の下（H = 496） | 496 | – | 171.8 | 0.2993 | – | – | 窓を出さない（ゲーム名 0.17H、自己ベスト 0.56H、START 0.8H） | – | – |

- H は 756 以上なので、境界（H = 496.5）の下には実際の画面は来ない。`DEMO_MIN_SCALE` は、窓が読めない小ささになる前に隠すための安全弁。
- 実寸の文字: ゲーム名 48 → SE 縦で 33 px、自己ベスト 26 → 18 px、START ボタン 220 × 84 → 153 × 58 px（いずれも `docs/spec.md` の画面の大きさの基準を満たす）。主な情報の自己ベストが、補助の文字より小さくならない（補助の文字は Title に無い）。
- SE 縦の窓は 267 × 284 px、玉は直径 9 px。動きは見えるが、細部は小さい。Enter / Space でも開始できる。

### デモの流れ

| 局面 | 内容 |
|---|---|
| 走り | `Run` をボットが動かす。Title の `update` の `delta` を `frameDt`（上限 `MAX_FRAME_DT`）に通した値で、毎フレーム `stepRun` に渡す |
| 幕が閉じる（`fade-out`） | `DEMO_FADE_MS` かけて、窓の内容が透明になる（不透明度は直線的に 1 → 0）。窓の内容とは、窓の背景・場の枠（壁）・危険ライン・編隊・パドル・玉のすべてで、一括して同じ不透明度にする。窓の外側の枠（`DEMO_BORDER`）・文字・START は透明にしない。走りは続く |
| 作り直し（`fade-in`） | 窓の内容が完全に透明の瞬間に、新しい `Run`（新しい乱数の種）に作り直し、窓の内容（スプライト）を描き直す |
| 幕が開く | `DEMO_FADE_MS` かけて不透明になる（0 → 1）。そのあと次の走り |

- 時計は `TitleDemoRunner`（`shared/title-demo`）。何もしない `DemoGame`: `start` は `0`、`plan` は `[0]`、`play` は `{ moved: true, roundDone: true, detail: undefined }`。`rounds` 1、`timing` は `waitMs` = `DEMO_RUN_MS / 2`、`fadeMs` = `DEMO_FADE_MS`、`stepMs` は何でもよい（手順は 1 手）。時刻は `update(delta)` に渡した `delta`（`frameDt` に通したミリ秒）の合計。
- 時刻列（`DEMO_RUN_MS` 24000、`DEMO_FADE_MS` 300、Title を表示した時刻を 0）:

| t (ms) | 起きること |
|---|---|
| 0 | 走りの始まり（1 回目の `Run` は Scene の始まりで作る） |
| 12000 | 手順の 1 手（何も起きない）。待ちに戻る |
| 24000 | `fade-out`。窓の内容が透明になり始める（不透明度 1） |
| 24150 | 不透明度 0.5 |
| 24300 | `fade-in`。不透明度 0。`Run` を作り直す（1 回目の走りは 24.3 秒） |
| 24600 | 不透明度 1。次の走りの待ち |
| 36600 | 手順の 1 手 |
| 48600 | 2 回目の `fade-out` |
| 48900 | 2 回目の `fade-in`（2 回目の走りは 24.6 秒。以降も同じ） |

- 最長の走りは `DEMO_RUN_MS + 2 × DEMO_FADE_MS` = 24.6 秒（`fade-out` の始まりから `fade-in` まで走りは続き、`fade-in` のあとの幕が開く間は新しい走り）。
- ボットが負けて `Run` が `ending` になったとき（敵の玉が下に落ちてライフが 0、または編隊が危険ラインに届いた）は、幕を閉じずに、その場で新しい `Run` に作り直す（窓の内容を描き直す。時計は変えない）。この作り直しは `fade-out` / `fade-in` のどちらでもない。
- 作り直しのたびに、窓のスプライトをすべて破棄してから描き直す（前の走りの表示物が残らない）。タイマーやリスナーを作らない。
- 開発用の読み取り（dev 専用、`if (import.meta.env.DEV)` の中に直接書く）: `window.__qa` を Title は `{ scene: 'Title', demoVisible, demoPhase, demoRounds, demoWave, demoPaddleX }` にする。`demoVisible` は窓を出しているか、`demoPhase` は `TitleDemoRunner` の `director.phase`、`demoRounds` は `director.rounds`、`demoWave` は今の `Run` のウェーブ、`demoPaddleX` はデモのパドルの x。Game の `__qa` は従来どおり。いずれも本番の bundle に残さない（ビルド後に `rg -c __qa dist/assets/*.js` が何も出さない）。

## ルール

- ゲーム本体のルール・スコア・難易度・操作・数値（`params.ts` の既存の値）は変えない。デモは何も保存しない（`localStorage` を使わない）。デモの `Run` のスコアは Title に出さず、自己ベストにも関係しない。
- デモの `Run` は `createRun(DEMO_FIELD_HEIGHT)` で作り、`stepRun` で進める（Game と同じ関数）。乱数は種から作った関数を注入する（ゲーム内の種は `Math.random` から作ってよい。テストでは固定の種を渡す）。走りを作り直すたびに新しい種にする。
- パドルは、毎フレーム `stepDemoPaddle` で動かす: ボットの `targetX` に向かって、最大 `urgent ? DEMO_PADDLE_SPEED : DEMO_IDLE_SPEED` × `dt` だけ動き（行き過ぎない）、パドルの中心を [`FIELD_LEFT` + `PADDLE_WIDTH`/2, `FIELD_RIGHT` − `PADDLE_WIDTH`/2] = [63, 477] に収める。開始時のパドルの中心は画面の横の中央（x = 270）。`Run` を作り直すたびに（`fade-in` でも `ending` でも）270 に戻す。

### ボット（`demoBot`）

乱数を使わない純関数: `Run` の状態から `{ targetX, urgent }` を返す。同じ状態なら同じ出力。`Run` を書き換えない。

用語:

- **落ちてくる玉**: `vy > 0` の玉（敵の玉も自分の玉も）で、中心の y が `paddleY` + `PADDLE_HEIGHT`/2 + `BALL_RADIUS`（= 547）以下のもの。それより下の玉は受けられないので無視する。
- **着く時間** `t`: `max(0, (paddleY − PADDLE_HEIGHT/2 − BALL_RADIUS − y) / vy)`（玉の円がパドルの上面に触れるまでの秒。すでに触れる位置にあれば 0）。
- **着くときの x**: x と `vx` で `t` 秒進めたあと、左右の壁（玉の中心が [`FIELD_LEFT` + `BALL_RADIUS`, `FIELD_RIGHT` − `BALL_RADIUS`]）で折り返した位置（壁の跳ね返りをたたんだ位置。玉どうし・敵・上の壁は考えない）。
- **一番下の列**: 生きている敵のうち、中心の y が最大のもの（`rect.y` が等しい敵の集まり。編隊は全体が同じ y に降りるので、段ごとに同じ値）。左から並べる。

規則:

1. 落ちてくる玉があるとき: 着く時間が最も短い玉（同じなら id が小さいほう）を選ぶ。
   - 狙う敵: 一番下の列を左から並べ、`(選んだ玉の id) mod (その列の敵の数)` 番目の敵（左から 0 始まり。mod が 0 なら一番左、3 なら左から 4 枚目）。敵がいなければ、狙いは画面の横の中央・y = 300（玉をまっすぐ上へ）として、`dx = 270 − 着くときの x`、`dy = paddleY − 300` で同じ式を使う。
   - `dx` = 狙う敵の x − 着くときの x、`dy` = `paddleY` − 狙う敵の y。`offset` = `atan(dx / dy)` ÷ `PADDLE_MAX_ANGLE` を [−1, 1] に収めた値。
   - `targetX` = 着くときの x − `offset` × `PADDLE_WIDTH`/2 を [63, 477] に収めた値。`urgent` = 真。
2. 落ちてくる玉が無いとき: `targetX` = 生きている敵の中心 x の平均（敵がいなければ 270）。`urgent` = 偽（ゆっくり編隊の下へ寄る。止まって見えない）。

手計算の例（`paddleY` 530、ウェーブ 1 の編隊は x = 95・165・235・305・375・445 の 6 列、一番下の列の y = 233）:

| 状況 | 結果 |
|---|---|
| 敵の玉 (x 270, y 413, vx 0, vy 240, id 3)。ほかに玉なし | `t` = (513 − 413) / 240 = 0.4167、着くときの x = 270。狙いは 0 始まりの 3 番目（左から 4 枚目）= x 305、`dx` 35、`dy` 297、`atan(35/297)` = 6.72°、`offset` = 0.1120、`targetX` = 270 − 0.1120 × 55 = 263.84、`urgent` 真 |
| 同じ玉で id 6（6 mod 6 = 0） | 狙いは 0 番目（一番左）= x 95。`dx` = −175、`dy` 297、`atan` = −30.51°、`offset` = −0.5085、`targetX` = 270 + 27.97 = 297.97 |
| 玉 (x 500, y 413, vx 240, vy 240) | `t` = 0.4167、壁で折り返し 500 → 523 → 446（着くときの x = 446）。折り返しの式は x = 523 から戻る 77 px で 446 |
| 玉 A (y 413, vy 240; `t` 0.4167) と玉 B (自分の玉, y 300, vy 460; `t` 0.463) | 玉 A を選ぶ |
| 同じ `t` の玉が 2 つ | id が小さいほう |
| 玉 y 547 / 548 (vy > 0) | 547 は対象（`t` = 0）、548 は無視 |
| 玉 vy ≤ 0 だけ | 落ちてくる玉なし（規則 2） |
| 一番下の列を倒しきった | 次に y が大きい列が一番下の列になる |
| 狙いが遠く `offset` が ±1 を超える | 収めて ±1（`targetX` は玉から ±55） |
| 敵がいない・玉もない | `targetX` = 270、`urgent` 偽 |
| 編隊が右へ 30 動いた（x の平均 300） | 玉がなければ `targetX` = 300 |

`stepDemoPaddle` の例: x 270、`targetX` 263.84、`urgent` 真、`dt` 1/60 → 最大 23.33 動けるので 263.84 に着く。`urgent` 偽 → 最大 2.5 なので 267.5。`targetX` が 600 なら 477 で止まる。

見た目に動きを持たせる（止まって見えない・同じ動きの繰り返しにならない）ための点: 狙う敵が玉の id で変わる（受けるたびに違う敵を狙う）。玉が無い間も編隊の下へ寄り続ける。

### 品質のしきい値（`demoBot` と `stepDemoPaddle` の性質テストで確かめる）

シード 1〜40 の 40 走り（走りの長さ `DEMO_RUN_MS + 2 × DEMO_FADE_MS` = 24600 ms、60fps で `dt` = 1/60 秒、デモと同じ `createRun(630)`、乱数は種から作った mulberry32 を `stepRun` に注入）で次を満たす。**値は初期値。実装時に測って、変えるときは測った値と日付をこの表に書く。**

試作（狙う敵の選び方と玉の無い間の動きが違う単純版、走りの長さ 24 秒、パドルの上限速度 1400 px/s）の実測: 最後まで生き残ったのは 36/40、倒した敵の数の最小は 17、中央値は 59、受け直し（段 2 以上）の数の最小は 15、中央値は 40、ウェーブの中央値は 3。パドルの上限速度をキー操作の 720 px/s にすると生き残りは 17/40 に落ちた（このため `DEMO_PADDLE_SPEED` は指の速さ並みにする）。

| 性質 | しきい値 |
|---|---|
| 走りの最後まで生き残る（`ending` にならない） | 40 走りのうち 40 |
| 倒した敵の数（毎フレームの `Run.kills.length` を足し込んだ合計。`kills` は `stepRun` が毎フレーム空にする） | 各走りで 15 以上 |
| 受け直し（段 2 以上になった受け。`Run.caught` の `tier ≥ 2` の数。デモのパドルが動かした結果で、`Run` の自動の動きを数えない） | 各走りで 8 以上 |
| パドルの動いた幅（走り全体の x の最大 − 最小） | 各走りで 300 px 以上 |
| パドルがほぼ動かない連続時間（3 秒の窓の中で x の最大 − 最小が 10 px 未満） | 各走りで無い |

（最後の 2 行は試作では測っていない。実装で測って、満たさない場合はボットを直すか、測った値で表を直す。生き残りが 40/40 に届かない場合も同じ。）

## パラメータ表

| 名前 | 初期値 | 意味 |
|---|---|---|
| `DEMO_RUN_MS` | 24000 | 走りの長さ（ms）。幕が閉じ始めるまで。`TitleDemoRunner` の `waitMs` はこの半分 |
| `DEMO_FADE_MS` | 300 | 幕（窓の内容の透明化）が閉じる・開くのにかかる時間（ms） |
| `DEMO_FIELD_HEIGHT` | 630 | デモの `Run` の高さ（論理 px）。危険ラインは y = 450、パドルは y = 530 |
| `DEMO_CROP_TOP` | 56 | 窓に映す範囲の上端（`Run` の y）。上の壁の上端（`FIELD_TOP` − `FRAME_WIDTH`）で、これより上は映さない |
| `DEMO_VIEW_HEIGHT` | 574 | 窓に映す `Run` の高さ（= `DEMO_FIELD_HEIGHT` − `DEMO_CROP_TOP`）。窓の高さは `574s` |
| `DEMO_MAX_WIDTH` | 500 | 窓の幅の上限（論理 px）。左右に 20 ずつ余白 |
| `DEMO_TOP` | 112 | 窓を置ける帯の上端（論理 px）。ゲーム名の下端 94 より下 |
| `TITLE_NAME_Y` | 70 | ゲーム名の中心の y（窓を出すとき） |
| `TITLE_BEST_HALF_HEIGHT` | 15 | 自己ベストの文字の高さの半分（上端の計算に使う） |
| `TITLE_BEST_GAP` | 40 | START ボタンの上端から自己ベストの中心までの距離（論理 px）。中心は 0.8H − 42 − 40 = 0.8H − 82 |
| `DEMO_BEST_GAP` | 16 | 窓の下端から自己ベストの上端までの最小の間隔（論理 px） |
| `DEMO_MIN_SCALE` | 0.30 | 窓の倍率 `s` の下限。下回ったら窓を出さない（H = 496 以下） |
| `DEMO_BORDER` | 2 | 窓の外側の枠の太さ（論理 px） |
| `DEMO_PADDLE_SPEED` | 1400 | 落ちてくる玉があるときのデモのパドルの最大の速さ（px/s、論理）。キー操作（720）では生き残りが 17/40 に落ちた |
| `DEMO_IDLE_SPEED` | 150 | 落ちてくる玉が無いときの最大の速さ（px/s、論理）。ゆっくり編隊の下へ寄る |

値同士の制約: `DEMO_FADE_MS` < `DEMO_RUN_MS` / 2。窓を出す境界は `0.8H − 225 ≥ DEMO_MIN_SCALE × 574`（H ≥ 496.5）。窓の下端 ≤ 自己ベストの上端 − `DEMO_BEST_GAP`。

## テスト観点

- **配置（純粋ロジック `demoLayout(H)`）**: 手計算の表の各行を、H 792 / 1169 / 756 / 497 / 496 で。H = 497 は窓を出し（`s` 0.3007）、H = 496 は出さない（`s` 0.2993）。窓の上端が `DEMO_TOP` 以上、下端が自己ベストの上端 − `DEMO_BEST_GAP` 以下。H = 792 で窓 384.4 × 408.6・上端 112、H = 1169 で窓 500 × 531.5・上端 201.4（幅の上限で決まる）、H = 756 で窓 357.3 × 379.8。窓を出さないときのゲーム名・自己ベスト・START は 0.17H・0.56H・0.8H。窓を出すときのゲーム名 y = 70、自己ベスト y = 0.8H − 82。
- **ボット（手計算の例。`demoBot` を直接呼ぶ）**: 上の例の表の各行（着く時間・壁の折り返し 500 → 446・id による狙いの選び方・`offset` の収め方・一番下の列を倒しきった後・玉が無いときの編隊の下への寄り・y 547 と 548 の境界・同じ `t` の玉の選び方）。`stepDemoPaddle` の例（行き過ぎない・速さの切り替え・[63, 477] への収め）。
- **純関数**: `Math.random` を例外を投げる関数に置き換えても `demoBot` が動く。同じ `Run` で同じ出力。`Run` を書き換えない。
- **性質テスト**: 上の品質のしきい値を、シード固定の走り 40 回で確かめる（空振りの検査つき: 倒した敵の数と受け直しの数が 0 でないこと、生き残らなかった走りが出たときもその数を数える）。
- **走りの時計（時刻列）**: `DEMO_RUN_MS` 24000、`DEMO_FADE_MS` 300 のとき、上の時刻列のとおり（23999 までは `fade-out` が起きず、24000 で `fade-out`、24300 で `fade-in`、24600 で幕が開ききる、36600 で 2 回目の手順、48600 で 2 回目の `fade-out`、48900 で 2 回目の `fade-in`）。不透明度は 24000 で 1、24150 で 0.5、24300 で 0、24450 で 0.5、24600 で 1。`requestStart()` は最初の 1 回だけ `true`、そのあとは時計も `Run` も進まない。1 フレームの `delta` が 50 ms を超えても、時計は 50 ms しか進まない。
- **`ending` での作り直し**: `Run` が `ending` になった `update` の中で、新しい種の `Run` に作り直す（時計は変わらない）。作り直しのあと、前の走りのスプライトが残らない。
- **開始**: 「画面を縦にしてください」の案内が出ている間は、Enter / Space / START で開始しない。出ていなければ、最初の 1 回だけ Game が始まる（2 重に始まらない）。Title に `DEMO_RUN_MS` + 5000 ms 以上いたあとに開始しても、Game の最初の状態（ウェーブ 1・スコア 0・ライフ `LIVES`・玉なし・`playing`）が、すぐ開始したときと同じ。
- **後始末**: Title を 5 回作り直し（`DEMO_RUN_MS` を 5 回またぐ）ても、入力のリスナーとタイマーの数が増えない。Title が終わると、Title のキーのリスナーが外れる。デモは `localStorage` を読み書きしない。
- **回帰**: 既存の `Run`・物理・編隊・段・HUD・画面サイズ・自己ベストのテストは変更しない。Title の自己ベストの文字は従来どおり（`formatBest(null)` → `BEST ---`、`formatBest({score:1230,label:"WAVE 5"})` → `BEST 1230（WAVE 5）`）。START ボタンは、ボタンの上で押して外で離したときは開始しない。Title → Game → Result → Title の遷移（Scene の遷移のテスト、または QA）が成り立つ。
- **単体テストの対象外**: 窓の見た目（枠・背景・スプライトの大きさ・切り取り）、Title の文字の見た目。QA（`scripts/qa/title-viewports.mjs` と画面写真）で確かめる。
