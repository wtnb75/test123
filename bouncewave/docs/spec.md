# bouncewave 仕様

## ゲーム名

打ち返しインベーダー（`bouncewave`）

## コンセプト

画面の上に並ぶ敵の編隊が撃ってくる玉を、パドルで打ち返して自分の玉にし、敵を倒す。全滅させると次のウェーブ。編隊は折り返すたびに降りてきて、赤い線に届くとゲームオーバー。自分の玉が増えるほど攻撃は強くなるが、さばく玉も増えて忙しくなる。

## ターゲットプレイヤー

スマホで 1 回数分、反射神経で遊ぶ人。PC のブラウザでも遊べる。

## コアループ

1. 落ちてくる敵の玉（赤いひし形）を見る
2. パドルで受ける。パドルのどこに当たったかで、跳ね返る角度が変わる（中央は真上、端ほど斜め）
3. 受けた玉は自分の玉（水色の丸）になり、左右と上の壁、敵で跳ね返って、また落ちてくる
4. 落ちてくる自分の玉もパドルで受け直しながら、敵の玉と自分の玉を同時にさばく

## 操作仕様

| 入力 | Title | Game | Result |
|---|---|---|---|
| タッチ・マウス | START ボタンをタップ / クリックで開始 | 画面のどこでも、指（ポインタ）の x 位置にパドルの中心が追従する（触れた瞬間と、動かしたとき。マウスはボタンを押していなくても、動かせば追従する）。y は無視する | 「もう一度」「タイトルへ」ボタン |
| キーボード | Enter / Space で開始 | ← → でパドルを `PADDLE_KEY_SPEED` で動かす（両方を同時に押している間は動かない） | Enter / Space で「もう一度」、Esc で「タイトルへ」 |

- ボタンは、そのボタンの上で押して、そのボタンの上で離したときに反応する。その Scene に入る前から押されていた指（Game でパドルを動かしていた指など）を離しても反応しない
- Enter / Space / Esc は押した瞬間に反応する（押しっぱなしのリピートは無視する）。その Scene に入る前から押されていたキーは、一度離すまで反応しない
- パドルの中心は、パドルが左右の壁の内側からはみ出さない範囲に収める（x ∈ [`FIELD_LEFT` + `PADDLE_WIDTH`/2, `FIELD_RIGHT` − `PADDLE_WIDTH`/2] = [63, 477]）
- ポインタとキーを同時に使ったとき: ポインタが触れた・動いたフレームはポインタの x に合わせ、それ以外のフレームで ← または → が押されていればキーで動かす
- ゲーム開始時のパドルの中心は画面の横の中央
- 入力のイベントは Scene ごとに登録し、Scene を抜けるときに外す（Result からの再開で二重に登録されない）

## 画面・Scene 構成

| Scene | 役割 |
|---|---|
| Title | ゲーム名・遊び方・自己ベスト・START ボタンを出す |
| Game | プレイ。編隊・玉・パドル・HUD |
| Result | ゲームオーバー後の結果。スコア・到達ウェーブ・自己ベスト・2 つのボタン |

### 画面の大きさ（論理サイズ）

- 幅は `SCREEN_WIDTH` で固定。高さは、Title に入ったときの表示領域の大きさから `round(SCREEN_WIDTH × 表示の高さ / 表示の幅)` を求め、`[SCREEN_HEIGHT_MIN, SCREEN_HEIGHT_MAX]` に収めた値にする。Title に入ったとき、Title にいる間に表示の大きさが変わったとき（画面を回したときなど。案内が消える場合も含む）、Game を始めるとき（START と「もう一度」）に決め直す。Game・Result の間は変えない（横向きで遊び始めてから縦に回すと、そのプレイと Result の間は上下に黒帯が出る。プレイ中に場の大きさを変えると玉や編隊の位置が崩れるため許容する）。Phaser の `Scale.FIT` で中央に置く
- これで、スマホの縦（390 × 844 → 540 × 1169）と iPhone SE の縦（375 × 550 → 540 × 792）は黒帯が出ない
- 横長の画面（PC、スマホの横）では高さが `SCREEN_HEIGHT_MIN` になり、左右に黒帯が出る。上の敵から下のパドルまでの縦の距離がこのゲームの読みどころなので、横長の場にはしない。PC（1280 × 720）での縮小率は 0.95 で、文字・ボタンは十分な大きさになる
- 表示が横長（幅 > 高さ）で、縮小率（`min(表示の幅 / 論理の幅, 表示の高さ / 論理の高さ)`）が `ROTATE_PROMPT_SCALE` 未満のとき（iPhone SE の横 667 × 310 は 0.41）は、文字が読めない大きさになるので、どの Scene でも、その上に「画面を縦にしてください」の案内を全面に出す。この間 Game は進行を止め（玉・編隊・パドル・タイマーが動かない）、Title・Result はボタンとキーの入力を受け付けない。表示の大きさが変わって条件を外れたら、案内を消して続きから再開する。Game・Result ではこのとき論理サイズを決め直さない（Title では上のとおり決め直す）
- 案内の文字は、縮小率に合わせて実寸が `PROMPT_REAL_FONT_SIZE` px 前後になるように、論理の大きさを `promptFontSize(縮小率) = min(ceil(PROMPT_REAL_FONT_SIZE ÷ 縮小率), PROMPT_MAX_FONT_SIZE)` にする（縮小率が 0 以下なら `PROMPT_MAX_FONT_SIZE`）。SE の横、縮小率 0.41 で 44。案内が出る縮小率 0.54 未満では、つねに 34 以上。上限で止まるのは縮小率が 18 ÷ `PROMPT_MAX_FONT_SIZE` ≈ 0.217 未満のときだけで（論理の高さ 756 なら、横長で表示の高さ約 164 px 未満。Game の途中で回して論理の高さが大きいままなら、もっと高い表示でも起きる）、そこでは実寸が 18 px を下回るが、案内はキャンバスの中に収まる（ふつうは 2 行）。改行の位置は下の「演出・UI（すべての Scene）」の `promptText` で決める。それでも 1 行が論理の幅 − 40（`SCREEN_WIDTH` − 40 = 500 論理 px）に収まらないとき（端末のフォントが 1 文字ぶんより広いとき）は、1 文字単位で折り返す（日本語には空白が無いため）。案内を出すときと、出している間に表示の大きさが変わったときに計算し直す

### Title

- 上から順に: ゲーム名「打ち返しインベーダー」、遊び方の説明 4 行、自己ベスト（`BEST 1230（WAVE 5）`。記録が無ければ `BEST ---`）、START ボタン
- 遊び方の説明（補助の文字、`HELP_FONT_SIZE`）:
  - 「赤い玉をパドルで受けると、自分の玉になる」
  - 「自分の玉で敵を倒そう。全滅で次のウェーブ」
  - 「赤い玉が下に落ちるとライフが減る」
  - 「敵が赤い点線まで降りてきたらゲームオーバー」（4 行で、SE 縦でも自己ベストの行と重ならない）
- 説明の行が画面の幅に収まらないときは折り返す
- START ボタンは画面の下 1/3 に置く

### Game

- レイアウト: 上端に HUD の 1 行（左から WAVE / SCORE / LIFE）。その下、y = `FIELD_TOP` から下が場（上の壁は HUD の下）。場の中に編隊（1 段目の上端 y = `FORMATION_TOP`）。パドルの中心は y = 論理の高さ − `PADDLE_BOTTOM_MARGIN`
- 場の枠: 玉が跳ね返る壁が見えるように、場の左端・右端・上端に、明るい灰色の壁（太さ `FRAME_WIDTH`）を描く。左右の壁は、内側の面（x = `FIELD_LEFT` / `FIELD_RIGHT`）から画面の外側まで、y = `FIELD_TOP` − `FRAME_WIDTH` から画面の下端の外まで描く（画面に見える太さは `FRAME_WIDTH`）。上の壁は y = `FIELD_TOP` − `FRAME_WIDTH` 〜 `FIELD_TOP` に、画面の左端から右端まで描く（角は左右の壁と重なる）。下は開けたまま（玉が出ていく所）。場は壁の内側（x = `FIELD_LEFT` 〜 `FIELD_RIGHT`、y = `FIELD_TOP` から下）で、玉は壁の内側の面で跳ね返る（左右は玉の外側が x = `FIELD_LEFT` / `FIELD_RIGHT` に触れる所、上は y = `FIELD_TOP` に触れる所）。編隊の折り返しとパドルの動く範囲も壁の内側。画面の揺れで枠も一緒に揺れる。揺れても画面の端に背景のすき間が見えないように、画面の外へ伸ばす長さは揺れの大きさ（上下の揺れ `SHAKE_INTENSITY` × 論理の高さの上限。論理の幅はいつも高さより小さいので、左右の揺れ `SHAKE_INTENSITY` × `SCREEN_WIDTH` もこれより小さい）より長くする（具体的な余白は実装裁量。赤い重ねと「縦にしてください」の案内の背景も同じ長さだけ画面の外へ広げる）。倒したときの白い四角・受けたときの輪・「+N」は壁より手前に描くので、壁際では壁に重なって見えてよい
- HUD の表記: `WAVE 3`、`SCORE 120`、`LIFE ♥♥♥`（残りライフの数だけ ♥。0 のときは `LIFE` だけ）
- 状態と遷移:

| 状態 | 内容 | 次へ進む条件 |
|---|---|---|
| `playing` | 編隊が動き（折り返すたびに降りる）、撃ち、玉が動く | 敵が 0 体になった → `waveClear` / ライフが 0 になった、または編隊が危険ラインに届いた → `ending`（同じフレームで全滅と `ending` の条件がそろったら `ending`） |
| `waveClear` | 画面中央に「WAVE n CLEAR」（n は今のウェーブ番号）を出す。敵がいないので撃たない。玉（敵・自分の両方）とパドルは動き続け、敵の玉が下端から出ればライフは減る | `WAVE_DELAY` 秒たった → 次のウェーブを始めて `playing`（中央の文字を消す）/ この間にライフが 0 になった → `ending`（同じフレームで両方なら `ending`） |
| `ending` | すべての動きを止める（玉・編隊・パドル・タイマー）。入力を受け付けない。中央の文字は出さない（`waveClear` から入ったときは「WAVE n CLEAR」を消す） | `RESULT_DELAY` 秒たった → Result へ |

- ウェーブの開始: ウェーブ番号を 1 増やし、画面に残った敵の玉をすべて消す（自分の玉は残す）。新しい編隊を出し（横の位置は中央、動く向きは右）、撃つまでの残り時間を `fireInterval(新しいウェーブ)` にする。ゲームの開始は「ウェーブ 0 から開始の処理をする」と同じ（ウェーブ 1 になり、消す玉は無い）
- 敵の見た目: インベーダー風のドット絵（Graphics で作るテクスチャ。当たりの矩形 `ENEMY_WIDTH` × `ENEMY_HEIGHT` に収まる大きさで、当たりの大きさは変えない）
- 描画の順（奥から）: 背景 → 場の枠 → 危険ライン → 編隊 → パドル → 敵の玉 → 自分の玉 → 倒したときの白い四角・受けたときの輪 → 得点の表示（+N）→ 赤い重ね → HUD・操作の手がかり → 中央の文字（WAVE n CLEAR）→「縦にしてください」の案内

#### 演出・UI（Game）

時間の決まり（すべての演出に共通）: きっかけのフレームを t = 0 とし、決めた長さ D のちょうどで消える（または元に戻る）。演出は Phaser の tween / タイマーで動かし、`ending` の間も最後まで再生する（`ending` が止めるのはゲームの進行で、演出は止めない）。例外は 2 つ: WAVE n CLEAR は `ending` に入ったフレームで、大きくなる途中でもすぐ消す（状態表の `ending` のとおり）。操作の手がかりは `ending` に入ったら `HINT_FADE` で消す。どの演出も `RESULT_DELAY`（0.8 秒）より短いので、Result に移るときには終わっている。Scene が終わると演出の表示物はすべて破棄され、「もう一度」で始めたときに残るものは無い。「縦にしてください」の案内が出ている間も演出は再生し続ける（案内の下に隠れる）。演出の間も入力は止めない。

| 演出 | きっかけ | 見た目 | 重なったとき |
|---|---|---|---|
| 操作の手がかり | Game が始まったとき（START・「もう一度」とも） | パドルの下（y = 論理の高さ − `PADDLE_BOTTOM_MARGIN` / 2）に「指・マウス・← → でパドルを左右に動かす」を `HELP_FONT_SIZE`（補助の文字）で出す | パドルが初めて動いたフレーム（ポインタでもキーでも、パドルの中心の x が開始時から変わったとき）か、`HINT_TIMEOUT` 秒たったとき（どちらか早い方）に、`HINT_FADE` 秒で消す。1 回のプレイで 1 回だけ。経過時間は Game の進行と同じく、案内が出ている間は進まない。`ending` に入ったら、残っていれば同じく消す |
| 倒したときの白い四角 | 自分の玉が敵を倒したフレーム | 倒れた敵の位置・大きさの白い四角が、`KILL_FLASH_DURATION` 秒で大きさ 1.0 → `KILL_FLASH_SCALE` 倍・不透明度 1 → 0 になって消える。位置は倒れた瞬間のまま固定（編隊の動きには付いていかない）。画面の端の敵では、大きくなった分が画面の外で切れてよい | 1 体ごとに 1 つ（同じフレームに複数倒せば、その数だけ出る。重ねて再生する） |
| 得点の表示 | 同上 | 倒れた敵の位置から「+N」（N = その 1 体で増えたスコア、`SCORE_PER_ENEMY` × ウェーブ番号）を `HELP_FONT_SIZE` で出し、`SCORE_POP_DURATION` 秒で `SCORE_POP_RISE` px 上へ動きながら不透明度 1 → 0 で消える。補助の文字として扱う（主な情報は HUD の SCORE）。文字が画面の左右からはみ出さないように、中心の x を収める | 1 体ごとに 1 つ（重ねて再生する） |
| 受けたときの光 | パドルが玉を受けたフレーム（敵の玉・自分の玉とも） | パドルを `CATCH_FLASH_DURATION` 秒だけ水色にする。受けた玉をパドルの上に置き直したあとの中心に水色の輪（線）を出し、`CATCH_RING_DURATION` 秒で半径 `BALL_RADIUS` → `CATCH_RING_RADIUS`・不透明度 1 → 0 になって消える。輪の位置は固定。壁際では画面の外で切れてよい | パドルの色は最初からやり直す（1 回ぶん）。輪は受けた玉ごとに 1 つ（重ねて再生する） |
| 赤い重ね | ライフが減ったフレーム | 画面全体に赤を不透明度 `DAMAGE_FLASH_ALPHA` で重ね、`DAMAGE_FLASH_DURATION` 秒で 0 にする。HUD より下のオブジェクトとして描く（いちばん上に描かれる `camera.flash` は使わない）。画面の揺れ（上の `SHAKE_DURATION`）と同時に起きる | 同じフレームに複数減っても 1 回。途中でまた減ったら最初からやり直す |
| ライフの点滅 | 同上 | HUD の LIFE で、減った ♥ だけを `LIFE_BLINK_INTERVAL` 秒ごとに消す・出すを繰り返し、`LIFE_BLINK_DURATION` 秒で消えた状態で終わる。残っている ♥ と「LIFE」の文字は動かさない（LIFE の行は左端を固定し、♥ は右へ並べる）。点滅させる ♥ の数 = 今の点滅が始まってから減った数 | 点滅中にまた減ったら、今の点滅で減っていた ♥ と新しく減った ♥ をまとめて最初から点滅させ直す（例: 3→2 の点滅中に 2→1 なら 2 個）。点滅が終わってから減ったら、新しく減った数から数え直す（例: 3→2 の点滅が終わってから 2→1 なら 1 個）。最後のライフ（`ending` に入るフレーム）でも点滅する |
| WAVE n CLEAR | `waveClear` に入ったフレーム | 中央の文字を、`WAVE_TEXT_POP_DURATION` 秒で大きさ `WAVE_TEXT_POP_FROM` 倍 → 1.0 倍にしながら出す | — （`waveClear` は 1 ウェーブに 1 回） |

- 演出は画面の揺れと一緒に動く（カメラが揺れるので、HUD も含めて揺れる）。赤い重ねは画面全体なので、揺れても端に隙間が見えない大きさにする（大きさは実装裁量）
- 同じフレームに倒す・受ける・ライフが減るが重なったら、それぞれの演出をすべて出す

#### 演出・UI（すべての Scene）

- Scene の始まり: Title・Game・Result は、始まったときに `SCENE_FADE_DURATION` 秒で黒から現れる（Phaser の `camera.fadeIn`）。その間も入力は受け付ける。ただし、論理サイズの決め直しで Title を並べ直すとき（画面を回したとき）はフェードしない（回すたびに暗転させない）
- 「縦にしてください」の案内の改行: 1 行（11 文字 × 文字の大きさ）が論理の幅 − 40 に収まるときは 1 行で出す。収まらないときは「画面を縦に」「してください」の 2 行に分けて出す（`promptText(文字の大きさ)`。11 × 45 = 495 なので 45 までは 1 行、46 からは 2 行）。上限の 83 でも、各行（5 文字・6 文字）は 500 に収まる

### Result

- 上から順に: 「GAME OVER」、スコア（`SCORE 1230`）、到達ウェーブ（`WAVE 5`。ゲームオーバー時のウェーブ番号）、自己ベスト（`BEST 1230（WAVE 5）`。今回で更新したら、その下に「NEW BEST!」）、ボタン 2 つ（「もう一度」「タイトルへ」。横に並べ、画面の下 1/3 に置く）
- 「もう一度」は Game を最初から（ウェーブ 1・スコア 0・ライフ `LIVES`・玉なし）。「タイトルへ」は Title へ

## ルール

### 玉

- 玉は 2 種類。敵の玉（赤いひし形）と自分の玉（水色の丸）。どちらも当たりは半径 `BALL_RADIUS` の円で、見た目もその大きさ
- 毎フレーム、速度 × 経過秒だけ進める。経過秒は 1 フレームで最大 `MAX_FRAME_DT` に切る（タブが裏に回ったあとなどの飛びを防ぐ）
- 左右の壁（壁の内側の面 x = `FIELD_LEFT` / `FIELD_RIGHT`）: どちらの玉も跳ね返る（玉の中心の x が `FIELD_LEFT` + 半径より左、または `FIELD_RIGHT` − 半径より右に出たら、その値に戻し、x 方向の速度を壁から離れる向きにする）
- 上の壁（y = `FIELD_TOP`、HUD の下の枠）: 自分の玉だけが跳ね返る（玉の中心の y が `FIELD_TOP` + 半径より上に出たら、y = `FIELD_TOP` + 半径に戻し、下向きにする）。敵の玉は下向きにしか進まないので上の壁に届かない
- 下端: 玉の中心の y が「論理の高さ + `BALL_RADIUS`」を超えたら消える（ちょうどの値では消えない）。敵の玉ならライフ −1。自分の玉は消えるだけ
- 玉どうしは当たらない。敵の玉は敵をすり抜ける
- 玉の数に上限は無い

### パドル

- 下向き（y 方向の速度 > 0）に動いている玉の円が、パドルの矩形（中心から左右 `PADDLE_WIDTH`/2、上下 `PADDLE_HEIGHT`/2）と重なったら、その玉を受ける。円と矩形の重なりは、玉の中心とパドルの中心の差が x で `PADDLE_WIDTH`/2 + 半径以下、かつ y で `PADDLE_HEIGHT`/2 + 半径以下で判定する（ちょうど接しても受ける。取りこぼしを減らすため、敵との当たりより甘くしている）。上向きの玉は素通りする。敵の玉も自分の玉も同じ
- 受けた玉: 速さを `MY_BALL_SPEED` にし、向きを「真上から `offset × PADDLE_MAX_ANGLE` だけ傾けた向き」にする（vx = `MY_BALL_SPEED` × sin、vy = −`MY_BALL_SPEED` × cos）。`offset` = （玉の x − パドルの中心 x）÷（`PADDLE_WIDTH` / 2）を [−1, 1] に収めた値（右寄りに当たると右へ傾く）。玉の y をパドルの上面から半径の分だけ上に置き直す。敵の玉なら自分の玉に変わる

### 敵と編隊

- 編隊は `ENEMY_COLS` 列 × `rowsForWave(wave)` 段。`rowsForWave(wave) = min(ENEMY_ROWS_BASE + floor((wave − 1) / ENEMY_ROWS_EVERY_WAVES), ENEMY_ROWS_MAX)`（ウェーブ 1・2 は 3 段、3・4 は 4 段、5・6 は 5 段、7 以降は 6 段）
- 敵 1 体は `ENEMY_WIDTH` × `ENEMY_HEIGHT` の矩形。隣とのすき間は縦横とも `ENEMY_GAP`。出たとき、編隊全体は画面の横の中央に揃い、1 段目の上端が `FORMATION_TOP`
- 編隊は全体で左右に動く。速さは残りの敵が少ないほど速い: `formationSpeed(残り, 出たときの数) = FORMATION_SPEED × (1 + FORMATION_SPEEDUP × (1 − 残り ÷ 出たときの数))`（18 体のうち 18 体残り → 50 px/s、9 体 → 100、最後の 1 体 → 約 144.4）。動かしたあと、生きている敵のうち一番左の敵の左端が `FIELD_LEFT` より左に出たら、はみ出た分を戻して右向きに、一番右の敵の右端が `FIELD_RIGHT` より右に出たら、はみ出た分を戻して左向きに変える
- 編隊は向きを変えるたび（壁で折り返すたび）に、そのフレームで全体が `formationDrop` だけ下に降りる。`formationDrop = (危険ライン − 出たときの編隊の下端) ÷ FORMATION_TURNS_TO_INVADE`。編隊の下端は一番下の段の敵の下端（出たときは `FORMATION_TOP` + 段数 × `ENEMY_HEIGHT` + (段数 − 1) × `ENEMY_GAP`）。ウェーブごとに出たときに決め、そのウェーブの間は変えない。ウェーブが始まって最初の折り返し（右の壁。半分の距離 59 px を動いたところ）でも降りる。1 フレームの中の順は、横に動く → はみ出しを戻して向きを変える → 降りる → 危険ラインの判定、で、そのあとに玉を動かす（危険ラインに届いたフレームでも、そのフレームの玉の動き・当たり・倒す・スコア・演出は処理する。ただし、そのフレームには敵は新しく撃たない）。画面の縦の長さに関係なく、倒さずにいれば `FORMATION_TURNS_TO_INVADE` 回目の折り返しで危険ラインに届く（最初の速さのままなら、半分の距離の 1 回目を含めて約 58 秒）。例: スマホ縦（論理の高さ 1169）のウェーブ 1 は (989 − 248) ÷ 25 = 29.64 px、SE 縦（792）のウェーブ 1 は (612 − 248) ÷ 25 = 14.56 px
- 危険ライン: y = パドルの中心の y − `DANGER_MARGIN`。降りたあと、生きている敵のうち一番下の敵の下端が危険ライン以上（小数の計算の誤差を吸収するため、危険ライン − 0.001 以上）になったら、そのフレームでゲームオーバー（残りのライフをすべて失い、`ending`）。下の段が全滅していれば、残っている一番下の段で判定する（危険ラインまでは遠くなるが、敵が減るほど編隊は速くなるので、届くまでの時間は短くなりうる。例: 論理の高さ 756 のウェーブ 1 で下の段 6 体を倒すと、放っておいたときの約 58 秒が約 41 秒になる。全滅させればウェーブが終わる）。場の中で、危険ラインを薄い赤の点線で示す（線の見た目は実装裁量。描画の順は場の枠の次、編隊より奥）
- 自分の玉の円が敵の矩形に重なったら、その敵は倒れて消え、玉は跳ね返る。跳ね返り方: 重なりの深さを x・y それぞれ「矩形の半分の大きさ + 半径 − 中心どうしの距離」で求め、浅い方の軸で、玉を深さの分だけ敵から離れる向きに押し戻し、その軸の速度を敵から離れる向きにする（x が y より浅ければ x、それ以外は y）。速さは変えない。重なりの深さが 0 以下（ちょうど接する）なら当たらない。押し戻した結果、玉が左右の壁にめり込んだとき（x が `FIELD_LEFT` + 半径未満、または `FIELD_RIGHT` − 半径を超える）は、位置だけを壁の面に触れる所（x = `FIELD_LEFT` + 半径、または `FIELD_RIGHT` − 半径）に戻す。速度はそのままにし、壁に向いていれば次のフレームの壁の跳ね返りで向きが変わる
- 1 つの自分の玉が 1 フレームに倒すのは 1 体まで。同じフレームに同じ敵へ 2 つの自分の玉が重なったときは、先に判定した玉が倒し、もう一方はその敵とは当たらない

### 敵の攻撃

- 撃つまでの残り時間を毎フレームの経過秒だけ減らし、0 以下になったら 1 発撃って、残り時間を `fireInterval(wave)` に戻す。`fireInterval(wave) = max(FIRE_INTERVAL_BASE × FIRE_INTERVAL_DECAY^(wave − 1), FIRE_INTERVAL_MIN)`（ウェーブ 1 は 1.2 秒、2 は 1.02 秒、5 は約 0.626 秒、7 は約 0.453 秒、8 以降は 0.45 秒）
- 撃つ敵: 生きている敵がいる列それぞれの、一番下の敵の中から、等しい確率で 1 体を選ぶ（乱数 r ∈ [0, 1) で、左の列から並べた候補の `floor(r × 候補の数)` 番目）。撃つ敵を選ぶ乱数と、下の向きの乱数は、それぞれ独立に引く
- 敵の玉は、撃つ敵の矩形の下端の中央から、半径の分だけ下に出る。向きは真下から `(2r − 1) × ENEMY_BALL_SPREAD` だけ傾け（r は [0, 1) の一様乱数。正は右）、速さは `ENEMY_BALL_SPEED`（vx = 速さ × sin、vy = 速さ × cos）

### ウェーブ・スコア・終わり

- 勝利条件は無い。ライフが 0 になるか、編隊が危険ラインに届くまで、ウェーブを進めてスコアを伸ばす
- 敵を全滅させると `waveClear` を経て次のウェーブ（画面・Scene 構成の Game を参照）
- スコア: 敵 1 体を倒すたびに `SCORE_PER_ENEMY × wave` を足す（ウェーブ 3 なら 30）
- ライフ: 初期値 `LIVES`。敵の玉が下端から出るたびに 1 減る。同じフレームに複数出たら、その数だけ減る（0 より下にはしない）。編隊が危険ラインに届いたら、残りのライフがすべてなくなる。0 になったら `ending`。そのフレームで失ったライフの数（演出の「減ったライフの数」）は、減る前のライフ − 減ったあとのライフ（危険ラインのときは減る前のライフすべて。玉と危険ラインが同じフレームでも同じ）
- 自己ベスト: Result に入るときに、今回のスコアが保存済みのベストより大きければ、スコアとそのときの到達ウェーブを保存し「NEW BEST!」を出す（同点は更新しない。記録が無いときはスコア 0 でも保存し、「NEW BEST!」を出す）。保存先は `localStorage` のキー `bouncewave.best`（`{"score": number, "wave": number}` の JSON）。読めない・中身が壊れている（JSON でない、数値でない）ときは「記録なし」として扱い、ゲームは止めない。書けないときは例外を外に出さず、そのページを開いている間だけメモリに持つ

## MVP 範囲（初版で作る範囲）

- Title / Game / Result の 3 Scene と、上の画面の流れ
- 編隊は 1 つの形（格子）。左右に動き、折り返すたびに降りてきて、危険ラインに届くとゲームオーバー。敵が減るほど速くなる。敵は 1 種類、敵の玉は 1 種類
- パドルで受けて自分の玉に変える、自分の玉で敵を倒す、ウェーブの進行、ライフ、スコア
- 自己ベストの保存と表示
- 画面の縦横比に合わせた論理サイズと、横長の小さい画面での「縦にしてください」の案内
- ライフが減ったときの画面の揺れ

## 非MVP範囲（今回は作らない範囲）

- 敵の動きの種類（編隊の形の違い、個別に動く敵）
- 敵の玉の速さをウェーブごとに上げること
- 敵の種類（硬い敵、速い弾・狙い撃ちの弾を撃つ敵）、ボス
- アイテム、チャージで強く打つ操作
- 効果音・BGM、パーティクルの爆発など（`game-polish` で検討する）
- Title のデモ（`game-title`）、ランキング、一時停止ボタン

## 技術要件

- Phaser 4 + Vite + TypeScript（リポジトリ共通のスキャフォールド）。ESLint のエラー 0、Vitest のカバレッジ 90% 以上（ステートメント・分岐・関数・行）
- 物理エンジン（Arcade など）は使わず、玉の移動と当たりは下の純粋なロジックで計算する（パドルでの跳ね返りの角度をルールどおりに決めるため）
- 次のゲームの規則は Phaser に依存しない純粋なモジュールに置き、単体テストする:
  - 玉の移動と壁での跳ね返り、下端から出たかの判定
  - パドルの位置の clamp（ポインタ・キー）
  - 円と矩形の当たりと跳ね返り、パドルで受けたかの判定と受けたあとの速度
  - 編隊の配置（ウェーブ → 段数と各敵の矩形）と、横移動・端での折り返し・折り返しで降りる量（`formationDrop`）・残りの数による速さ（`formationSpeed`）・危険ラインに届いたかの判定
  - 撃つ間隔、撃つ敵の選び方、敵の玉の初速（乱数は注入する）
  - スコア、ライフ、ウェーブの進行と Game の状態遷移（`playing` / `waveClear` / `ending`）
  - 論理サイズの計算と、「縦にしてください」を出すかの判定、案内の文字の大きさ（`promptFontSize`）
  - 自己ベストの読み書き（ストレージは注入する。読めない・壊れている・書けないときの扱いを含む）
  - 演出に使う 1 フレームの結果（受けた玉・倒した敵・減ったライフの数）、操作の手がかりを消すかの判定（`shouldHideHint`）、案内の改行（`promptText`）、ライフの HUD の表記（`lifeText`）と点滅させる ♥ の数（`blinkCount`）
- パラメータ表の数値は 1 つのファイルに、表の名前で置く
- Scene は Title / Game / Result に分け、`create` で入力を登録し、Scene の `shutdown` で外す。毎フレームの処理でオブジェクトを新しく作らない（玉の表示用オブジェクトは、玉が出たときに作り、消えたときに破棄する）
- 単体ビルド（`npm run build`）と共有ビルドの両方で起動する

## テスト観点

- 論理サイズ: 390 × 844 → 540 × 1169、375 × 550 → 540 × 792、1280 × 720 → 540 × 756（下限）、390 × 1000 → 540 × 1170（上限）
- 縦にしてくださいの判定: 667 × 310（論理 540 × 756、縮小率 0.41）→ 出す、1280 × 720（縮小率 0.95）→ 出さない、縦長の表示 → 縮小率にかかわらず出さない、横長で縮小率がちょうど `ROTATE_PROMPT_SCALE` → 出さない、高さ 0 の横長の表示 → 出す（縮小率 0。文字の大きさは上限の `PROMPT_MAX_FONT_SIZE`）
- 案内の文字の大きさ `promptFontSize`: 縮小率 0.41 → 44（18 ÷ 0.41 = 43.9 を切り上げ）、0.5 → 36、0.25 → 72、0.22 → 82（上限の手前）、0.2 → 83（90 が上限で切られる）、0.03 → 83、0 → 83
- `rowsForWave`: 1 → 3、2 → 3、3 → 4、7 → 6、20 → 6
- `fireInterval`: 1 → 1.2、2 → 1.02、7 → 約 0.4526（まだ下限より上）、8 → 0.45（計算値 約 0.3847 が下限で切られる）
- `formationSpeed`: 18 体中 18 体 → 50、9 体 → 100、1 体 → 50 × (1 + 2 × 17/18) ≈ 144.44
- `formationDrop`: 論理の高さ 1169・ウェーブ 1（3 段、下端 248、危険ライン 1069 − 80 = 989）→ 741 ÷ 25 = 29.64。論理の高さ 792・ウェーブ 1（危険ライン 612）→ 14.56。論理の高さ 756・ウェーブ 7（6 段、下端 380、危険ライン 576）→ 7.84
- 降りる: 折り返したフレームで全体が `formationDrop` だけ降りる（敵の y がそろって増える）。折り返さないフレームでは降りない
- 危険ライン: 一番下の敵の下端がちょうど危険ラインなら届いた（ゲームオーバー）、0.01 上なら届いていない。下の段が全滅していれば、残った一番下の段で判定する。倒さずに折り返し続けると、ちょうど 25 回目の折り返しで届き、24 回目では届かない（論理の高さ 1169 と 792 の両方で）
- 危険ラインに届いたフレーム: ライフ 3 → 0、そのフレームで失ったライフの数は 3、`ending`。同じフレームに敵の玉も 1 つ出ていても、失ったライフの数は 3（減る前のライフすべて）
- スコア: ウェーブ 1 で 1 体 → 10、ウェーブ 3 で 1 体 → 30
- パドルで受ける: `offset` 0 → 真上（vx 0、vy −460）、1 → 右へ 60°（vx = 460 × sin60°、vy = −460 × cos60°）、−1 → 左へ 60°、1.5 → 1 に収める。上向きの玉は受けない。x の差がちょうど `PADDLE_WIDTH`/2 + 半径なら受ける。敵の玉は自分の玉に変わる
- 円と矩形: 離れている・ちょうど接する → 当たらない。横から当たる → vx が敵から離れる向き。上下から当たる → vy が敵から離れる向き。両軸の深さが等しい → y で跳ね返る。速さは変わらない
- パドルの中心の clamp: ポインタ x 0 → 63、540 → 477、63 / 477 ちょうどはそのまま。キーで左の壁に押し付けても 63 で、右の壁に押し付けても 477 で止まる
- 玉の移動: 左右の壁の内側で跳ね返る（両方の玉。左は x = 17、右は x = 523 に戻る。17 / 523 ちょうどなら戻さない）。上の壁は自分の玉だけ跳ね返る（y = `FIELD_TOP` + 10 から上へ 2 px 進む → y = `FIELD_TOP` + 9 に戻って下向き。`FIELD_TOP` + 9 ちょうどなら戻さない）。下端は「論理の高さ + 半径」ちょうどでは消えず、それを超えたら消える
- 編隊: ウェーブ 1 の配置が中央に揃う（左端 67、右端 473）。右端が `FIELD_RIGHT`（532）を超えたフレームで、はみ出た分だけ戻って左向きになる（全員残っている速さ 50 のとき）（左端も `FIELD_LEFT`（8）で同様。右への動ける幅は 532 − 473 = 59）。端の列が全滅したあとは、残った列の端で折り返す
- 撃つ敵: 各列の一番下の生きている敵だけが候補になる（下の敵が倒れた列では、その上の敵が候補。全滅した列は候補なし）。乱数 0 → 一番左の候補、1 未満の最大 → 一番右の候補。敵の玉の向き: 乱数 0 → −20°、0.5 → 真下
- 撃つ間隔: 残り時間が 0 になったフレームで 1 発撃ち、残り時間が `fireInterval(wave)` に戻る。`waveClear` 中は撃たない
- ライフとゲームの状態: 敵の玉が 1 つ出る → ライフ −1。同じフレームに 2 つ出る → −2。ライフ 1 で 2 つ出る → 0（負にならない）で `ending`。`waveClear` 中に 0 になる → `ending`。同じフレームで全滅とライフ 0 → `ending`。`WAVE_DELAY` を過ぎたフレームでライフ 0 → `ending`（次のウェーブは始まらない）。`playing` で敵が 0 → `waveClear`、`WAVE_DELAY` 後にウェーブ +1・敵の玉が消え・自分の玉が残る・撃つ残り時間が新しいウェーブの間隔。`ending` から `RESULT_DELAY` 後に Result へ進む合図が出る。危険ラインに届いたフレームで、同じフレームの玉が最後の敵を倒したら、その敵のスコアは足し（演出も出る）、状態は `ending`（`waveClear` にはならない）。危険ラインに届いたフレームで敵の玉が下に出ても、`ending` は 1 回
- 自己ベスト: 記録なしで 120 → 保存して NEW BEST。記録なしで 0 → 保存して NEW BEST。保存 120 に対し 120 → 更新しない。保存 120 に対し 121 → 更新。壊れた JSON・数値でない値・読み出しで例外 → 記録なし。書き込みで例外 → 例外を外に出さず、その後の読み出しでメモリ上のベストを返す
- 演出に使う 1 フレームの結果（Game はこれだけを見て演出を出す）: 受けた玉（置き直したあとの位置）、倒した敵（倒れた瞬間の矩形と、増えたスコア）、減ったライフの数
  - 受けた玉: 敵の玉をパドルで受けたフレーム、自分の玉を受け直したフレームの両方で入る。受けていないフレームでは空。同じフレームに 2 つ受ければ 2 つ入る。位置はパドルの上に置き直したあとの中心
  - 倒した敵: 倒したフレームだけ入る。ウェーブ 3 で倒せば増えたスコアは 30。同じフレームに 2 つの玉で 2 体倒せば 2 つ入る
- 点滅させる ♥ の数 `blinkCount(点滅中か, 今の点滅で減っていた数, 新しく減った数)`: 点滅中ではない・1 → 1、点滅中・1・1 → 2、点滅が終わってから・（前の 1 は数えない）・1 → 1
- `promptFontSize(310 ÷ 792)`（SE の横、論理の高さ 792 のまま）→ 46、`promptText(46)` → 2 行
- 操作の手がかりを消すかの判定 `shouldHideHint(経過秒, パドルが動いたか)`: 2.99 秒・動いていない → 消さない、3.0 秒 → 消す、0 秒でも動いた → 消す
- 案内の改行 `promptText(文字の大きさ)`: 44 → 1 行、45 → 1 行（11 × 45 = 495）、46 → 「画面を縦に」「してください」の 2 行、83 → 2 行。2 行のとき、どちらの行も `SCREEN_WIDTH` − 40 に収まる（83 × 6 = 498）
- ライフの HUD の表記 `lifeText(残り, 点滅で見せる減った数)`: 残り 2・0 → `LIFE ♥♥`、残り 2・1 → `LIFE ♥♥♥`（点滅中の「出す」側）、残り 0・0 → `LIFE`
- 単体テストの対象外: 描画・HUD の見た目・画面の揺れ・ボタンの配置・案内の見た目、演出の動き（白い四角・+N・輪・赤い重ね・点滅・WAVE n CLEAR・Scene の現れ方）。QA（ブラウザでの目視と連写）で確かめる
