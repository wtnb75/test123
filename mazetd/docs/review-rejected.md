- `src/game/logic/world.ts`: `createGame()` with no argument builds an all-plain board, so the real terrain only arrives if the caller passes `initialTerrain()` — 理由: the spec requires both the game's terrain and a terrain-less board (the unit tests' board); `Game` is the only production caller and a test pins that `createGame(initialTerrain())` has the 14-cell path. Flipping the default would rewrite about 40 existing tests for no gain.
- `src/game/logic/world.ts`: `createGame(terrain)` does not validate the terrain (length, plain S/G, a path from S to G) — 理由: the input is the fixed constant map, whose properties are pinned by tests; validating it at runtime would only guard a programming error.
- `src/game/logic/board.ts`: the distance field is an O(V²) Dijkstra, and a placement runs it twice (`hasPath` and `findPath`) — 理由: 108 cells and one run per tap are not measurable; revisit when `maps` grows the board.
- `src/game/scenes/Game.ts`: `drawRock` / `drawSwamp` use pixel offsets that fit `CELL` = 56 and rebuild small arrays on each redraw — 理由: `CELL` is a fixed parameter, the board is redrawn only on player actions, and 5 rocks are not measurable.
- `src/game/logic/terrain.test.ts`: the 101 buildable cells and the 11.375 s walk are restatements of the spec's arithmetic — 理由: the layout lists above them pin the data, and the walking time is a consequence of the path length that the path test checks.
- `src/game/logic/terrain.test.ts`: about 40% of the random-board iterations are skipped because the start column is off a narrow board — 理由: the guards (`reachable`, `unreachable`, `ties`, `swampSteps` floors) show the rest still covers every case.
- `src/game/logic/board.ts`: Dijkstra keeps `dist` with a -1 sentinel plus a `done` array — 理由: it matches the existing `UNREACHABLE` convention used by every caller and the tests.
