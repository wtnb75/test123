# mazetd ゲーム仕様

## ゲーム名

**Maze TD**（ディレクトリ名 `mazetd`）― 迷路を作って守るタワーディフェンス（仮称）

## コンセプト

何もない盤面に「壁」と「砲台」を置いて迷路を作り、敵の道のりを長くして砲台で撃ち落とすタワーディフェンス。
敵は常にスタートからゴールまでの最短経路を歩くので、置き方しだいで道のりが伸びる。「迷路を長くする（壁）か、火力を増やす（砲台）か」の配分がプレイヤーの判断の中心になる。

## ターゲットプレイヤー

- タワーディフェンスを遊んだことがないカジュアル層
- スマートフォン／PC ブラウザで 1 プレイ 5〜10 分程度で遊びたいプレイヤー

## コアループ

1. **建設フェーズ**: コインを使って盤面のマスに壁・砲台を置く（売却もできる）。敵が通る予定の最短経路が盤面に表示され、置くたびに更新される
2. 「開始」ボタンを押すと **ウェーブフェーズ** に入る。敵がスタートから一定間隔で出現し、最短経路を歩いてゴールへ向かう。砲台は射程内の敵を自動で撃つ（プレイヤーの操作はない）
3. 敵を倒すとコインが入る。ゴールに着いた敵 1 体につきライフが 1 減る
4. ウェーブの敵がすべていなくなるとウェーブクリアボーナスのコインが入り、建設フェーズに戻る
5. 最終ウェーブ（`WAVE_MAX`）をしのげばクリア、途中でライフが 0 になればゲームオーバー → 結果画面 → リスタート

## 操作仕様

タッチ（スマートフォン・タブレット）とマウス（PC）の両対応。操作はすべて「タップ（クリック）」だけで完結し、ドラッグ・長押し・キーボードは使わない。タッチとマウスは同じ扱い（Phaser の `pointerdown` で処理）とする。

| 操作 | 方法 | 受け付けるフェーズ |
|------|------|--------------------|
| 道具の選択 | 画面下部の道具ボタン「壁」「砲台」「売却」のどれかをタップ。選んだ道具が強調表示される。初期選択は「壁」 | 建設・ウェーブの両方（ウェーブ中に切り替えてもよい） |
| 設置 | 「壁」または「砲台」選択中に盤面の空きマスをタップ | 建設のみ |
| 売却 | 「売却」選択中に壁・砲台のあるマスをタップ | 建設のみ |
| ウェーブ開始 | 画面下部の「開始」ボタンをタップ | 建設のみ（ウェーブ中はボタンを灰色表示にし、タップしても何も起きない） |
| リスタート | 結果画面のどこかをタップ | 結果画面 |

- 盤面のタップは `pointerdown` の瞬間に 1 回だけ処理する（押したまま指を動かしても別マスには置かない）
- マルチタッチで同時に複数の `pointerdown` が来た場合は、来た順にそれぞれ 1 回ずつ処理する
- 盤面の外（HUD・余白）のタップは何もしない
- ウェーブ中の盤面タップは無視する（メッセージも出さない）

## 画面・Scene 構成

| Scene | 役割 |
|-------|------|
| `Game` | プレイ本体。建設フェーズとウェーブフェーズを内部フェーズで管理する |
| `Result` | クリア／ゲームオーバーの表示、スコア表示、リスタート受付 |

`Boot` / `Preloader` は作らない（外部アセットなし、図形描画とテキストのみ）。

### 画面サイズ

- ゲーム画面は縦長の固定サイズ `CANVAS_W` × `CANVAS_H`（540×960）。Phaser の `Scale.FIT` + `CENTER_BOTH` で表示領域に収める（PC の横長画面では左右に余白が出る）
- 背景色は 1 色で塗る

### レイアウト方針（`Game`）

上から順に次の 3 領域。

1. **HUD（上部、高さ `HUD_H`）**: 左から「ウェーブ `n`/`WAVE_MAX`」「ライフ `n`」「コイン `n`」。その下に 1 行のメッセージ欄（設置失敗の理由などを表示する）
2. **盤面（中央）**: `GRID_COLS` × `GRID_ROWS` マス、1 マス `CELL` px。盤面は画面の左右中央に置き、上端は `BOARD_TOP`。マスの境界線を薄く描く
   - スタートマス `S` は最上段の中央列（列 `START_COL`、行 0）、ゴールマス `G` は最下段の中央列（列 `GOAL_COL`、行 `GRID_ROWS - 1`）。S と G はそれぞれ色で区別し、文字「S」「G」を描く
3. **操作パネル（下部、盤面の下端から画面下端まで）**: 1 段目に道具ボタン「壁（`WALL_COST`）」「砲台（`TURRET_COST`）」「売却」を横に 3 つ並べる。2 段目に横長の「開始」ボタン。ボタンには費用を併記する（例「壁 5」「砲台 25」）

### `Game` Scene の状態遷移

| フェーズ | 内容 | 次へのトリガー |
|----------|------|----------------|
| `build` | 設置・売却を受け付ける。最短経路のプレビューを描く。メッセージ欄の通常表示は、盤面に壁・砲台が 1 つもないとき「マスをタップして壁や砲台を置こう（置いたら開始）」、1 つ以上あるとき「ウェーブ `n` の準備（開始を押す）」（どのウェーブでも同じ規則。全部売れば前者に戻る） | 「開始」ボタンのタップ → `wave`（タップ時は経路を確定してフェーズを切り替えるだけ。出現タイマーは 0 から始まり、1 体目の出現を含むすべての進行は次の `update` から） |
| `wave` | 敵の出現・移動・砲台の攻撃を毎フレーム進める。経路プレビューは消す。メッセージ欄に「ウェーブ `n`」と表示 | (a) ライフが 0 → `ending`（ゲームオーバー） (b) そのウェーブの敵が全員出現済みかつ盤面の敵が 0 体 → 最終ウェーブなら `ending`（クリア）、そうでなければクリアボーナスを加算してウェーブ番号を +1 し `build` |
| `ending` | Scene 側のフェーズ。ロジックの更新を止め（ゲームは進まない）、道具ボタン・盤面・「開始」を含む `Game` の入力をすべて無視する（ボタンの光も出さない）。画面を `FADE_TIME` 秒で黒へ暗転する。判定が成立したフレームの出来事（最後の撃破、最後のゴール到達）は通常どおり演出し、再生中の演出（撃破の輪と文字、G とライフの赤、攻撃の線）は暗転中も時間どおり進める | 暗転の完了（タイマー） → `Result` |

- ゲーム開始時は `build`、ウェーブ番号 1、ライフ `LIVES_START`、コイン `COINS_START`、盤面は空（S・G 以外すべて空きマス）
- (a) と (b) が同じフレームで成立した場合（最後の敵がゴールしてライフ 0）は (a) ゲームオーバーを優先する
- `Result` への遷移は `ending` を経由する（上の表）。`Result` にはクリア／ゲームオーバーの別と、スコア計算に必要な値（撃破数・残りライフ・到達ウェーブ）を渡す

### レイアウト・遷移（`Result`）

- 画面中央に大きく「クリア！」または「ゲームオーバー」、その下に「スコア `n`」「撃破数 `n`」「到達ウェーブ `n`/`WAVE_MAX`」、最下部に「タップでもう一度」
- 画面のどこかをタップすると `Game` を最初から始める（前回の状態は一切引き継がない）
- `Result` に入ってから `RESULT_INPUT_DELAY` 秒間はタップを無視する（ウェーブ中の連打がそのままリスタートにならないように）。`Result` は `FADE_TIME` 秒かけて黒い画面から表示される（`FADE_TIME` < `RESULT_INPUT_DELAY` なので、表示し終わる前のタップは常に無視される）
- `Result` から `Game` を始め直すときはフェードを入れない（すぐに建設フェーズを表示する）

### 演出・UI

すべて見た目だけの演出で、ルール・数値・入力の受け付けには影響しない（演出の再生中も入力はふだんどおり受け付ける。例外は `ending` の間のみ）。長さ・大きさはパラメータ表の値を使う。

| # | きっかけ | 見た目 | 場所 |
|---|----------|--------|------|
| 1 | 建設フェーズで盤面に壁・砲台が 1 つもない | メッセージ欄の通常表示が案内文になる（状態遷移の表を参照） | HUD |
| 2 | 建設フェーズで「砲台」ツールを選んでいる間 | 盤面のすべての砲台に、中心から半径 `TURRET_RANGE` の半透明の円（塗り＋輪郭）を描く。ほかのツールを選んでいる間とウェーブ中は描かない | 盤面 |

| 6 | 最終ウェーブ以外のウェーブを終えて `build` に戻った | 盤面の中央に「ウェーブ `n` クリア！ +`WAVE_BONUS`」（`n` は終えたウェーブ番号）を `BANNER_TIME` 秒表示する。最後の 0.3 秒で薄くなって消える。表示中も盤面・ボタンの操作を受け付け、「開始」を押したらその時点で消す | 盤面中央 |

## ルール

### 盤面とマス

- 盤面の各マスは「空き」「壁」「砲台」のいずれか。S と G は常に空きで、何も置けない
- 敵が通れるのは「空き」マス（S・G を含む）のみ。壁と砲台はどちらも通れない
- 移動は上下左右の 4 方向のみ（斜め移動なし）

### 最短経路

- 経路は「G から各空きマスへの BFS 距離（歩数）」で決める。S から出発し、現在マスの隣接空きマスのうち G までの距離が 1 小さいマスへ進む、を G に着くまで繰り返した列が経路
- 距離が 1 小さい隣接マスが複数あるときは **下 → 左 → 右 → 上** の順で最初のものを選ぶ（毎回同じ経路になる）
- 経路は建設フェーズ中はプレビュー用に置くたび再計算し、`wave` 開始時に確定する。ウェーブ中は盤面が変わらないので経路も変わらない。そのウェーブの敵は全員同じ経路を歩く

### 設置

- 「壁」「砲台」選択中に盤面のマスをタップすると、次の順で判定する。最初に該当した理由で失敗し、盤面とコインは変わらない
  1. タップしたマスが S または G → 失敗（メッセージ「S と G には置けません」）
  2. タップしたマスが空きでない → 何もしない（メッセージなし）
  3. コインが費用未満 → 失敗（メッセージ「コインが足りません」）
  4. そのマスを塞ぐと S から G への経路がなくなる → 失敗（メッセージ「道をふさぐことはできません」）
  5. 上記以外 → 設置成功。コインから費用を引き、経路プレビューを再計算する。メッセージ欄を通常表示に戻す
- 失敗時はタップしたマスを赤く `INVALID_FLASH` 秒点滅させる
- 失敗メッセージが通常表示（フェーズの表示）に戻るのは **設置成功・売却成功・道具ボタンのタップ・開始** のときだけ。何も起きないタップ（埋まったマスへの設置、空きマス・S・G の売却、盤面外）ではメッセージを変えない

### 売却

- 「売却」選択中に壁・砲台のマスをタップすると、そのマスを空きに戻し、`floor(費用 × SELL_RATE)` のコインを得る。経路プレビューを再計算し、メッセージ欄を通常表示に戻す
- 空きマス・S・G をタップしたときは何もしない
- 売却で経路が塞がることはないので、経路の判定は不要

### 敵

- 敵は 1 種類。ウェーブ `w`（1 始まり）の敵は次の値を持つ
  - 体数: `ENEMY_COUNT_BASE + ENEMY_COUNT_STEP × (w − 1)`
  - 最大 HP: `ENEMY_HP_BASE + ENEMY_HP_STEP × (w − 1)`
  - 移動速度: `ENEMY_SPEED`（全ウェーブ共通）
- `wave` 開始の瞬間に 1 体目が出現し、以降 `SPAWN_INTERVAL` 秒ごとに 1 体ずつ出現する
- 敵は S マスの中心に出現し、確定した経路のマス中心を順にたどって一定速度で直線移動する（マスの角で曲がる）
- 敵が G マスの中心に着いたら盤面から消え、ライフが 1 減る（コインは入らない）。ライフは 0 未満にならない（同じフレームにライフより多くの敵が着いても 0 で止まる）
- 敵同士は重なってよい（衝突判定なし）
- 敵は丸で描き、HP が最大未満になったら頭上に HP バー（残り HP ÷ 最大 HP）を描く

### 砲台

- 砲台はマスの中心から半径 `TURRET_RANGE` px 以内（境界を含む）に中心がある敵を攻撃する
- 攻撃は即着弾（弾は飛ばさない）。1 回の攻撃で標的の HP が `TURRET_DAMAGE` 減り、砲台から標的へ `SHOT_FLASH` 秒だけ線を描く
- 攻撃間隔は `TURRET_INTERVAL` 秒。各砲台は「チャージ時間」（秒）を持ち、次の規則で攻撃する
  - `wave` 開始時点のチャージは `TURRET_INTERVAL`（全砲台が即攻撃可能）
  - 各フレーム（「1 フレームの処理順」の手順 4）で、砲台を **盤面の行優先の順（上の行から、同じ行では左から）** に 1 基ずつ、次の順で処理する（「先の砲台」はこの順で先に処理された砲台を指す）
    1. チャージに `dt`（`DT_MAX` で頭打ちにした後の値）を加える
    2. 「標的にできる敵」＝ 射程内にいて、盤面に残っていて、HP が 0 より大きい敵（同じフレームで先の砲台に HP 0 以下にされた敵は含まない）がいて、かつチャージが `TURRET_INTERVAL` 以上なら 1 回攻撃し、チャージから `TURRET_INTERVAL` を**引く**（0 に戻さない。超過分は次の攻撃に持ち越す）
    3. 攻撃しなかったフレーム（標的にできる敵がいない、またはチャージ不足）の最後に、チャージを `TURRET_INTERVAL` で頭打ちにする（待機中に攻撃を溜め込まない）
  - 1 フレームに攻撃するのは最大 1 回。`DT_MAX` < `TURRET_INTERVAL` を前提とする（この前提があるので、1 フレームで 2 回分のチャージが溜まることはない）
  - この規則により、射程内に敵がいる間はフレームレート（1 フレームの長さの揺れ）によらず、平均して `TURRET_INTERVAL` 秒に 1 回攻撃する。個々の攻撃の間隔はフレームの区切りに合わせて前後する（ちょうど `TURRET_INTERVAL` とは限らない）
- 標的は射程内の敵のうち **経路上で最もゴールに近い（残りの道のりが最短の）敵**。同じなら先に出現した敵
- HP が 0 以下になった敵はその場で消え、撃破数 +1、コイン +`KILL_REWARD`
- 同じフレームで先に攻撃した砲台によって HP が 0 以下になった敵は、後の砲台の標的にしない（後の砲台は射程内の残りの敵から標的を選ぶ）

### 1 フレームの処理順（`wave` 中）

1. 経過時間 `dt` を `DT_MAX` 秒で頭打ちにする（タブ復帰時などの大きな飛びを防ぐ）
2. 出現タイマーを進め、出現時刻に達した敵を出す（1 フレームで複数の出現時刻をまたいだときは、その分の敵をすべてこのフレームで S マスの中心に出す）。**出現したフレームでは敵は移動しない**（S の中心に置くだけで、出現時刻からの遅れ分を先に進める補正もしない）
3. 敵を移動する。G に着いた敵を消してライフを減らす
4. 砲台の攻撃（盤面に残っている敵だけが対象）
5. HP 0 以下の敵を消し、撃破数とコインを加算する
6. 状態遷移の判定（ゲームオーバー → ウェーブ終了の順）

したがって、同じフレームで G に着いた敵は撃破扱いにならない。

### コイン

- 開始時 `COINS_START`。撃破で +`KILL_REWARD`、ウェーブ終了（最終ウェーブ以外）で +`WAVE_BONUS`
- 上限なし。0 未満にはならない（費用未満のときは設置できない）

### 勝利条件・失敗条件

- **クリア**: ウェーブ `WAVE_MAX` の敵が全員出現済みで盤面の敵が 0 体になり、ライフが 1 以上残っている
- **ゲームオーバー**: ライフが 0 になった瞬間（ウェーブの途中でも即座に）

### スコア

- スコア = 撃破数 × `SCORE_PER_KILL` + （クリア時のみ）残りライフ × `SCORE_PER_LIFE`
- ゲームオーバー時は残りライフ分を加えない（ライフは 0 なので結果は同じ）
- スコアは `Result` にのみ表示する（プレイ中の HUD には出さない）。保存はしない

## 技術要件

- フレームワーク: Phaser 4.x（TypeScript）、Vite でビルド（静的サイト）
- lint: ESLint（エラー 0 件）
- テスト: Vitest（カバレッジ 90% 以上）
- 表示は `Graphics` とテキストのみで、外部画像・音声に依存しない
- パラメータ表の値は 1 つの定数モジュール（例 `src/game/logic/config.ts`）にまとめ、他の場所に数値を直書きしない
- ゲームロジックは Phaser に依存しない純粋関数／クラスとして `src/game/logic/` 配下に切り出し、単体テスト可能にする。最低限、次を純粋ロジックにする
  - 盤面（マスの状態、設置・売却の判定と結果、コインの増減）
  - BFS による距離計算と経路の決定、経路の有無の判定
  - ウェーブの値（体数・HP）の計算、出現タイマー
  - 敵の経路上の移動（位置と「残りの道のり」）、ゴール到達
  - 砲台の標的選択・攻撃間隔・ダメージ
  - 1 フレームの更新（上記「1 フレームの処理順」）とフェーズ遷移
  - スコア計算
- Scene はロジックの呼び出し、入力の受け渡し、描画のみを担当する。時間（`dt`）はロジックの更新関数へ引数で渡す（ロジック内で `Date.now()` や Phaser の時計を直接読まない）。乱数は使わない
- 盤面座標とマス座標の変換（タップ位置 → マス、マス → 中心座標）も純粋関数にしてテストする
- 演出（撃破の輪と文字、ゴール時の光、クリア表示、ボタンの光、射程円）はルールのロジックに混ぜない。ロジックは 1 フレームで起きた出来事（撃破した敵の位置、ゴールに着いた敵の数）を Scene が読める形で残し、Scene がそれを見て演出する。演出の残り時間の管理は純粋ロジックに切り出してテストしてよい（実装裁量）
- 撃破の文字・輪は `create` で `POPUP_MAX` 個ずつ作って使い回し、`update` の中で新しく生成しない
- 敵・線の描画オブジェクトは毎フレーム生成し直さない（1 つの `Graphics` を毎フレーム `clear` して描き直すか、オブジェクトを再利用する）
- 入力リスナーは `create` で 1 回だけ登録し、Scene の `shutdown` で解除する
- 状態は Scene のプロパティとロジックのオブジェクトで管理し、グローバル変数を使わない

## テスト観点

- マス座標変換: 盤面の四隅・境界ちょうどの座標、盤面外（上下左右）は「マスなし」
- BFS・経路: 空の盤面で S から G へまっすぐ下る経路（12 マス）、壁で迂回させたときの経路長、同距離の分岐で「下 → 左 → 右 → 上」の優先順が守られる、経路なしの判定
- 設置: 成功でコインが費用分減る、S・G への設置失敗、埋まったマスへの設置は何も起きない、コインがちょうど費用のとき成功・1 足りないとき失敗、経路を塞ぐ設置の失敗（盤面とコインが変わらない）、失敗理由の優先順（コイン不足かつ経路を塞ぐ場合は「コインが足りません」）
- 売却: 壁で `floor(5 × 0.5) = 2`、砲台で `floor(25 × 0.5) = 12` 戻る、空き・S・G の売却は何も起きない
- フェーズ: `build` 以外では設置・売却・開始が無視される、開始で `wave` になり経路が確定する
- ウェーブの値: ウェーブ 1 と `WAVE_MAX` の体数・HP
- 出現: 開始の瞬間に 1 体目、`SPAWN_INTERVAL` ちょうどで 2 体目、全員出たらそれ以上出ない、1 フレームで複数の出現時刻をまたぐと複数体が S に出る
- 敵の移動: 速度どおりに進む、マスの角で曲がる、G に着いたらライフ −1 で消える、`dt` が `DT_MAX` で頭打ちになる
- 砲台: 射程ちょうど（境界を含む）の敵を撃つ・射程 +1px の敵は撃たない、ゴールに最も近い敵を狙う、同じなら先に出現した敵、攻撃間隔（射程内に敵を置いた状態で `wave` 開始後に `dt` = 0.1 を与え続けると、1 フレーム目で撃ち（チャージ 0.6 → 0.1）、2〜4 フレーム目は撃たず、5 フレーム目で撃つ）、超過分の持ち越し（`dt` を 0.0166 と 0.0167 の交互で 1802 フレーム（合計 30.0033 秒）与え、その間ずっと標的にできる敵が射程内にいるとき、攻撃回数が `30 ÷ TURRET_INTERVAL` = 60 回以上になる。0 に戻す実装では 1 回あたり 31 フレーム必要になり 60 回に届かない。時刻を整数ミリ秒で扱う実装では `dt` を 16 ms と 17 ms の交互で 1850 フレーム（合計 30.525 秒）与え、持ち越しありで 61 回以上・0 に戻す実装で 61 回未満になることを確認する）、待機中の頭打ち（標的にできる敵がいない状態で `dt` = 0.1 を 30 フレーム（3 秒）与えたあと敵が射程に入ると、そのフレームで 1 回だけ撃ち、次のフレーム（`dt` = 0.1）では撃たない）、同じフレームで先の砲台が HP 0 にした敵しか射程内にいない砲台は撃たず、チャージは頭打ちになる、`wave` 開始時は即攻撃可能、HP 0 で撃破・コイン +`KILL_REWARD`
- 処理順: 同じフレームでゴールに着いた敵は撃破されない
- 遷移: 全員出現済みかつ敵 0 体でウェーブ終了とボーナス加算、最終ウェーブではボーナスなしでクリア、ライフ 0 でゲームオーバー、最後の敵のゴールでライフ 0 になったらゲームオーバー優先
- スコア: クリア時とゲームオーバー時の計算
- `ending`: Scene 側の処理なので単体テストの対象外。暗転中に道具ボタン・盤面・「開始」をタップしても何も変わらないことを連続スクリーンショットで確認する
- 案内文: 盤面が空のとき案内文、壁か砲台を 1 つ置くと「ウェーブ `n` の準備（開始を押す）」、全部売ると案内文に戻る、ウェーブ 2 以降でも同じ規則、失敗メッセージ表示中は失敗メッセージが優先
- 演出用の出来事: 撃破した敵の位置が 1 フレームの撃破数ぶん Scene に伝わる、G に着いた敵の数が伝わる、同じフレームで着いた敵は撃破として伝わらない、次のフレームには前のフレームの出来事が残らない
- 演出の時間管理（純粋ロジックにした場合）: 撃破の輪と文字が `POPUP_MAX` を超えたら最も古いものを再利用する、各演出が指定時間で終わる、ライフ表示の赤が次のゴールで数え直しになる
